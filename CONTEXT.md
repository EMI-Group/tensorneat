# TensorNEAT 0.2.0
## Intent
TensorNEAT is a NEAT / HyperNEAT neuroevolution library whose computation layer is the **EvoX Compiler (`evoxc`)** — no JAX and no PyTorch anywhere in `src/`.
The NEAT idea is unchanged: irregular network topologies are *tensorized* into fixed-shape arrays so a whole population of differently-shaped networks is evaluated at once, with the population on axis 0 of every tensor.
What changed is the engine: every generation is one `@evoxc.defn` graph, built once per shape (`evoxc.build`) and then run once per generation on a switchable backend, instead of being `jax.jit`/`vmap`-traced per call; the same graph runs on the CPU reference interpreter or on an accelerator (`device="rocm"`).
The library keeps its research identity (GECCO 2024 Best Paper, arXiv 2404.01817): batched gradient descent through evolved topologies, network visualization, and sympy formula / Python-code generation.
## Layout
- `src/tensorneat/` — the only installable package (setuptools src-layout); everything importable lives here.
- `test/` — pytest suite: `unit/`, `parity/` (vs a frozen legacy implementation), `integration/`, `backends/` (compiled backends, llvm-cpu and ROCm).
- `benchmarks/` — old-vs-new harness, the frozen pre-rewrite JAX implementation used as timing baseline and numerical oracle, and the committed measured reports (CPU, compiled-backend and accelerator).
- `examples/` — runnable scripts per problem family (`func_fit/`, `rl/`, `interpret_visualize/`).
- `docs/` — Sphinx autodoc site built strictly (`uv run --extra docs sphinx-build -W -b html docs docs/_build`, zero warnings), enforced by the `docs` job in `.github/workflows/ci.yaml` and by `fail_on_warning: true` in `.readthedocs.yaml`; `tutorials/` — `quickstart.ipynb` (current API) plus `legacy_jax/` (pre-rewrite notebooks, concepts only).
- `pyproject.toml` + `uv.lock` + `.python-version` — packaging, the locked environment, and the interpreter pin; `README.md` is the front page and must match the code.
## API Surface
- `from tensorneat import Pipeline, algorithm, genome, problem, common`; `tensorneat.__version__` is the installed distribution version.
- `Pipeline(algorithm, problem, seed=42, fitness_target=1, generation_limit=1000, backend="numpy", device=None, compile_options=None, is_save=False, save_dir=None, is_detailed=True, show_problem_details=False, pop_batch_size=None, host_payload=True)` → `setup()` (host-side setup graphs only, builds no generation graph), `step(state)`, `auto_run(state)`, `show(state, best)`.
- `device=` is `None` (host), a kind string (`"cpu"`, `"rocm"`, `"cuda"`) or an `evoxc.Device`; it is forwarded to `evoxc.build` and the runtime tensors are placed on it once after `setup`.
- `host_payload=True` copies the four gene arrays to host numpy on every `step`; `Pipeline(host_payload=False)` (or `step(state, host_payload=False)`) returns them as the backend left them, and `common.host_payload.materialize_payload` is the explicit converter.
- `algorithm.NEAT(...)`, `algorithm.HyperNEAT(substrate, neat)`, `genome.DefaultGenome/RecurrentGenome`, `problem.XOR/XOR3d/CustomFuncFit/CartPole/Pendulum/MountainCarContinuous`, `common.ACT/AGG/State`.
- A genome payload is a four-array record (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`) and is **batch-first**: `auto_run` returns `best` as a one-individual batch (`(1, max_nodes)`, …), which `show` and `genome.network_dict(state, best)` consume; bare rows are accepted by the host helpers and written one-genome-per-file by checkpointing.
- Configuration objects are constructor-level and host-side; every numerical operation is a batch-first kernel inside an `evoxc` graph.
## Environment (uv)
`uv` is the supported environment manager: `uv lock` then `uv sync` (add `--extra bench` for the parity oracle, `--extra iree` for the compiled backends, `--extra xla-rocm` for the PJRT plugin wheel, `--extra docs` for Sphinx), `uv run pytest`, `uv run python examples/func_fit/xor.py`.
`xla-rocm` is `jax-rocm7-pjrt==0.10.2` (the AMD plugin wheel; NVIDIA would retarget it to `jax-cuda12-pjrt`), tracked by the lock so `uv sync` keeps it — a hand-installed wheel is pruned.
`requires-python = ">=3.11"`; `.python-version` pins 3.12; `uv.lock` is committed and covers all 60 packages of the resolved set.
`evoxc` is resolved by `[tool.uv.sources]` from git tag `v0.1.1` because PyPI only ships 0.1.0, which predates the frontend work: the same-run recorded pair is an `evoxc` build of 0.30/0.53/0.80 s at XOR pop 100/500/1000 against 2.94/2.93/2.96 s of `jax.jit(...).lower().compile()` (`benchmarks/RESULTS.md`); the metadata floor is `evoxc >= 0.1.1`, which PyPI cannot satisfy, so a plain `pip install tensorneat` fails and the README's git-pinned `evoxc` plus `pip install --no-deps` recipe is the supported pip path.
The pinned tag predates the `evoxc` numpy-interpreter performance pass (per-block dispatch plans, a flat value store, dead-value release), which is delivered on the evoxc task branch and measured at 1.07–2.25× on the numpy leg in `benchmarks/PERF_NUMPY.md` pass 3; moving the pin needs an evoxc release and a regenerated `RESULTS.md` in the same change.
`--extra iree` installs `iree-base-compiler`/`iree-base-runtime` 3.13.x directly (not `evoxc[iree]`, whose pin is `>=3.11,<3.12`): 3.10/3.11 abort in the HIP HAL on any loop-carried `while`/`scan` and SIGSEGV `iree-compile` on a `while` nested in a `cond`, and 3.13 fixes both.
## Backends
`backend=` is forwarded verbatim to `evoxc.build`; `compile_options` is expanded into its `**options`; nothing ever silently falls back to another backend.
`"numpy"` is the default, the only leg with no optional dependency, and the fastest CPU leg: `iree` llvm-cpu is 1.5×/5.5×/6.6× slower per generation at pop 100/500/1000 with one 8.0–9.6 s `iree-compile` per static shape (`benchmarks/BACKENDS.md`, IREE 3.13).
`"iree"` lowers, compiles and runs one full generation of every shipped problem class (`XOR`, `XOR3d`, `CustomFuncFit`, `CartPole`, `Pendulum`, `MountainCarContinuous`) plus the `RecurrentGenome` and `HyperNEAT` paths, on llvm-cpu and — with `compile_options={"target_backends": ["rocm"]}` and `device="rocm"` — on the AMD Instinct MI300X (gfx942, ROCm 7.1).
`"xla"` drives a PJRT C API plugin `.so`; with the JAX ROCm plugin (`jax-rocm7-pjrt`, the only installable plugin on this box, no `jax` import involved) it is the fastest accelerator leg, 2.5–4.6× faster per generation than `iree` on the same device; evoxc discovers an installed `jax_plugins/*/*_plugin.so` automatically, and the pinned tag instead needs `EVOXC_PJRT_PLUGIN` or `compile_options["plugin_path"]`.
No CPU PJRT plugin is installable here, so `xla` is measured on `rocm` only; `"tvm"` is untested here.
Accelerator numbers (MI300X, seed 42, per generation): numpy 43.3 / 120.2 / 182.6 / 136.1 / 965.0 / 236.0 ms and xla 3.6 / 4.5 / 5.5 / 4.6 / 6.3 / 13.4 ms for `xor_p100` / `xor_p500` / `xor_p1000` / `xor3d_p500` / `custom_pagie_p500` / `cartpole_p100`, at a 2.1–2.7 s XLA and 8.0–9.0 s IREE one-off compile per shape (`benchmarks/GPU.md`).
## Performance
`benchmarks/RESULTS.md` is the generated full-matrix old-vs-new report, rendered only by `run_benchmark.py` from `results/authoritative.json`; its committed record was measured on the merged tree `63f0fc67` (3 repeats, seeds 42/43/44, 150 generations) and its verdict is **FAIL**.
That record's timings: the numpy interpreter is 2.59×/4.06× faster than the frozen JAX baseline on `xor_p500`/`xor_p1000`, 1.07× on `xor3d_p1000`, and slower on `xor_p100` (0.94×), `xor3d_p100` (0.68×), `xor3d_p500` (0.83×) and `custom_pagie_p500` (0.38×, 1258.04 vs 480.21 ms/gen); `cartpole_p100` is new-only at 307.16 ms/gen.
Its quality verdict fails only on `xor3d_p100` (−0.2500 against the JAX side's −0.0894), the constant-0.5 plateau where escaping is a per-seed lottery in both implementations.
`benchmarks/results/xor3d_quality_2026-11-04.md` is the narrower post-fix quality record (the xor3d and pagie cases, one repeat per seed) and is superseded by the matrix record's quality rows.
`benchmarks/GPU.md` is the accelerator evidence: every shipped case runs on the MI300X, the device wins per generation on all six (12–153× against the numpy leg), and the one-off compile amortises after 3–54 generations.
`benchmarks/BACKENDS.md` is the CPU compiled-backend evidence (IREE 3.13, llvm-cpu) and `benchmarks/PERF_NUMPY.md` records the hand-measured numpy passes (op count, tiled evaluate plus RL rollout hoist, and the evoxc interpreter dependency A/B) with their before/after pairs and reproduce commands.
Two structural defects were found and fixed earlier and remain load-bearing: a tiled func-fit evaluate fanned the schedule and payload to `P*S` rows and re-derived every per-pass static at `P*S` rows although all of it is sample-invariant (statics derive at `P` rows and expand, and a batch wider than the chunk budget is evaluated in row groups), and the RL rollout re-derived the genome-forward prelude on each of its `max_step` queries (a prepared-forward pair derives it once per generation).
The accelerator pass cut the A100-class cost drivers on device: one packed `(P+2,)` readout instead of three host round-trips, accelerator-only kernel formulations behind trace-time statics (`kernel_mode`, `distance_centre`, `distance_formulation`), no lazy speciation `cond` on an accelerator, a 4-relax-step `node_levels` group, a statically unrolled genome level sweep at `samples == 1`, and a device-aware evaluate chunk budget that makes Pagie's 250 000-row block one pass.
Remaining levers, measured: the padded gene geometry (`max_nodes`/`max_conns` multiply every per-pair op — Pagie would gain 2.7× at 20/40, but that is a workload change, not a fix), IREE's per-readback `hipHostMalloc`/`hipHostFree` pair (~57 µs per data-dependent loop exit; ~31 ms/generation on `cartpole_p100`) which only upstream can make reusable, the `max_depth` static on RL (CartPole 60.2 ms at 16 versus 42.0 at 8), and the unelevated evoxc pin above.
## Search Quality
`benchmarks/results/authoritative.json` (rendered in `benchmarks/RESULTS.md`, tree `63f0fc67`) is the current three-seed search-quality evidence for every case.
It holds the `-0.05` XOR3d tolerance on `xor3d_p500` (new −0.0000 against the JAX side's −0.1789) and on `xor3d_p1000` (both at the optimum), and the `-0.01` Pagie tolerance on `custom_pagie_p500` (−0.0066 against −0.0064).
`xor3d_p100` still misses the three-seed median (−0.2500 against −0.0894): at pop 100, leaving the constant-0.5 basin is a per-seed lottery in *both* implementations — the new side escapes on 13 of 20 seeds against the frozen oracle's 4 of 20 and seed 42 escapes inside the matrix protocol (generation 128), while seeds 43/44 do not escape inside the budget.
Two search contracts, both matching the frozen implementation: parent pairing pins elite slot *k* to its species' *k*-th ranked member (never the champion cloned into every elite slot), and the four structural gates are independent per individual and compose sequentially add-node → delete-node → add-conn → delete-conn.
`DefaultGenome` ships `conn_add=0.4`/`conn_delete=0.05` because the add gate is the one refused roughly half the time (duplicate/self/cycle refusals), which made equal declared probabilities thin the population; an explicitly constructed `DefaultMutation()` keeps NEAT-python's `0.2`/`0.2`.
Every allocated node and connection key stays inside `key_span`: a key outside the schedule's window is dropped from the phenotype without an error.
## Constraints
- `import tensorneat` must never import `jax`, `torch`, `brax`, `gymnax` or `mujoco` (a release-gate test enforces this); compiled backends are pulled in only by `evoxc.build(backend=...)`, and a PJRT plugin is a `.so` loaded over ctypes, never an import.
- All computation lives inside `@evoxc.defn` graphs or helpers called during an active trace; there is no eager mode — host code only orchestrates build/run/log.
- Shapes are static: population, `max_nodes`, `max_conns` are fixed at build time; a shape change forces a rebuild (the Pipeline caches one executable per shape signature, and the evaluate chunk budget is part of that signature).
- Device placement is explicit: the host-side `setup` graphs build and run on CPU (the device-selecting keys `device`/`target_backends` are stripped for that phase), the runtime tensors are placed once afterwards, and only the reported values (fitness, overflow, generation, and the payload when `host_payload=True`) come back to host. Nothing transfers implicitly, and a cross-kind move goes through host memory because `evoxc` refuses a payload-to-device copy.
- Accelerator kernel formulations are selected by trace-time statics and are bit-identical to the host route; the numpy leg and its per-generation cost are unchanged by them.
- Portability rules for every graph, from the StableHLO v1 exporter: rank ≤ 2 `scatter` (one prepared index block per scatter), no unsigned dtype in an exported generation graph (the tree's only `uint32` is `Genome.hash`'s digest, from a helper no generation graph calls), static dims, non-negative axes, and no op `evoxc.backends.stablehlo.ops.status()` reports as `deferred` (every name in `DEFERRED_OPS`, e.g. `erf`/`gelu`/`cholesky`/`svd`, plus every unmapped name, e.g. `cumsum`/`tril`/`triu`/`flip`/`solve`); never seed a `while`-carried value with a `scatter`.
- Control flow (`scan`/`cond`/`while_loop`) may nest inside an `evoxc.scan` body when the inner controller is a `cond`/mask over statically built branches (no host control flow on a traced value) and the numpy interpreter stays the reference; the shipped case is `algorithm/neat/_kernels.py::gated_row` inside its two speciation scans below `GATED_ROWS`. `vmap` is never applied over control flow — batch dimensions are written explicitly instead.
- `State` is an immutable host container for configuration, `evoxc` RNG keys and tensors; all randomness flows through `evoxc.random` stateless keys, so a `(seed, config, shape)` triple reproduces a run.
- NaN padding semantics of the pre-rewrite library are preserved (unconnected node value = `NaN`, `NaN` fitness = `-inf`), because `test/parity/` compares against the frozen implementation.
- Files stay under ~1000 lines; a directory's CONTEXT.md names any justified exception (currently `common/tensorization.py`, one cohesive schedule derivation, and the genome forward/prepared-pass test matrix).
- No silent error swallowing: configuration errors raise `tensorneat.common.errors.TensorNEATError`; trace/shape/backend errors propagate from `evoxc` unchanged.
- Dropped on purpose: the Brax/Gymnax/mujoco-playground RL environments required JAX; `problem.rl` ships three simulator-free evoxc-native replacements instead — `CartPole` (discrete), `Pendulum` (continuous torque), `MountainCarContinuous` (continuous force, one-time goal bonus).
## Test Strategy
`uv run pytest` from the repo root (`testpaths = ["test"]` in `pyproject.toml`); `test/` mirrors the source tree and the current full run with `uv sync --all-extras` is `1497 passed` (no failures, no skips) in ~101 s (`test/unit` 1313, `test/integration` 60, `test/backends` 46, `test/parity` 60 with `--extra bench`, `test/support` 9, and 9 release gates: 4 in `test/release_gate_no_jax.py` plus 5 in `test/test_release_gate_surface.py`).
`test/backends` runs real generations on IREE 3.13 llvm-cpu and on the ROCm device (the ROCm module skips when `/dev/kfd`, the HIP driver or a device is absent), and the marker guards make an absent `iree` extra loud.
`test/unit` runs on the numpy backend with no optional dependency and covers the accelerator formulations against the host route on cyclic, shallow and below-threshold payloads (with traced-IR proofs that the accelerator route builds no `cond` and no `where` loop), both speciation paths through the `GATED_ROWS` seam, the whole HyperNEAT subtree, and the benchmark harness's own fingerprint/protocol.
`test/integration` covers `ask`/`tell` hooks, determinism per seed, rebuild-on-shape-change, checkpoint round-trips, the `host_payload=False` opt-out plus `materialize_payload`, and the evaluate chunk budget as part of the shape signature.
`test/parity` needs `--extra bench` and compares kernels against `benchmarks/legacy_jax` within documented tolerances (rtol 1e-5 forward, 1e-4 gradients; 60 tests), with `test_oracle_integrity.py` pinning that the oracle is a separate implementation and that the directory stays 60 tests wide.
`test/support/` holds the shared host-side fixtures (`runner`, `payloads`, `oracle`, `functions_ref`) and `test_lazy.py`, which pins the lazy-import skip contract.
