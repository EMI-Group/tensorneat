# NEAT (`tensorneat.algorithm.neat`) — population cycle + species bookkeeping

## Intent
Everything in a NEAT generation that is neither network mathematics (genome) nor task evaluation (problem): the payload, the generation counter, speciation, stagnation, spawn allocation, parent pairing and the crossover/mutation dispatch.
`NEAT` (`neat.py`) is the algorithm the pipeline drives, `SpeciesController`/`SpeciesState` (`species.py`) own the species algebra, and `_distance.py` owns the compatibility-distance rows over one generation's digest.
Every kernel is batch-first over `P = pop_size` and compiled by `pipeline.py` into the single per-generation evoxc graph, so nothing branches on a traced value or reads the host.
One `Pipeline.step` dispatches 8 121 ops on the numpy leg at `xor_p500` (8 179 at `xor_p1000`): one digest, `2 · species_size` compatibility calls, `O(pop_size)` selection/crossover/mutation, and no `max_nodes × max_nodes` tensor anywhere.
Three host statics on the trace-time state pick the formulation, each read once at trace time: `distance_centre` (`"tiled"` on a bare `State`, else `"single"`), `kernel_mode` (`"host"` on a bare `State`, else `"accelerator"`) and the genome's `distance_formulation` (`"merge"`/`"index_free"`); a GPU-class device gets `accelerator`/`tiled`/`index_free` and the numpy pipeline `host`/`single`/`merge` (`pipeline.host_payload._formulation_statics`).

## API Surface
`NEAT.__init__(genome, pop_size, species_size=10, max_stagnation=15, species_elitism=2, spawn_number_change_rate=0.5, genome_elitism=2, survival_threshold=0.1, min_species_size=1, compatibility_threshold=2.0, species_fitness_func=evoxc.max, species_number_calculate_by="rank", pop_batch_size=None)` is API-compatible with the pre-rewrite library and calls `_keys.validate_key_space(genome)`, so `key_span <= max_nodes` fails here with a `TensorNEATError`.
`setup(state=None) -> State` requires `state.randkey`, registers `pop_size`, `pop` (`GenomeTensors`, axis 0 = individual), `generation` (0-d float32) and `species`, and advances `randkey`; it runs one init graph (`split(randkey)` → `genome.initialize` → species seeding) and must be called outside any trace.
`ask(state)` costs zero ops and returns `state.pop`; `transform`/`forward` delegate to the genome; `tell(state, fitness) -> State` runs the algebra below; `prepare_forward(..., samples=1)`/`forward_prepared` split `forward` so an RL rollout pays the prelude once (`Pipeline` queries through that pair, and `forward` has no in-tree call site); `show_details(state, fitness)` is the only host-side method; `num_inputs`/`num_outputs`/`pop_size` are read-only properties.
`SpeciesController.setup(state, first)` takes `first` as **one** `GenomeTensors` individual and makes slot 0 the single live species keyed `0` with `member_count[0] = pop_size`, centre `first`, `best_fitness = -inf`, `next_species_key = 1.0`; `update_species(state, fitness) -> (state, winner, loser, elite_mask)` owns the generation's first `evoxc.random.split`.
`speciate(state, distance_fn, pop=None)` accepts any `(state, centre_payload, pop) -> (P,)` or `(S, P)` callable and reads the population from `pop`, else the `"pop"` entry, else the four payload entries, else raises `TensorNEATError`; `_block_layout`/`_prefix_sum_exclusive` are test seams only (production calls the `_kernels` versions).
`DistanceRows(genome, digest, population, pop_size)` is created per generation inside `NEAT.tell`: `__call__(state, centre, pop=None)` accepts a centre batch of exactly `1` or `pop_size` and returns `(P,)`, raising `TensorNEATError` otherwise, and validates the digest's population axis against `pop_size`; `row` is the single-row form, `matrix` the explicit `(S, P)` table form.
`SpeciesState` is a frozen dataclass, one leaf per field, under `state.species`: the `(S,)` f32 `species_keys` (NaN = dead), `best_fitness`, `last_improved`, `member_count`, the `(P,)` f32 `idx2species` (NaN = unassigned, only inside `speciate`), the four split centre arrays sized `(S, max_nodes[, NA])` / `(S, max_conns[, CK|CA])` and 0-d f32 `next_species_key`.
Centres store the **four split payload arrays**, so `distance_fn` receives real `GenomeTensors`; every scalar field is float32 so NaN encodes a dead slot and `generation` writes into `last_improved` without a dtype change inside a scan carry.

## Generation Algebra (`NEAT.tell`)
1. Sanitise fitness: finite entries pass through, NaN and both infinities become `-inf` (`finite = abs(f) <= _finite_bound(dtype)` plus `select`, raising `TensorNEATError` unless the shape is `(pop_size,)`; the bound is `numpy.finfo(dtype).max` read at trace time, so no invalid arithmetic and no `RuntimeWarning` where `isnan(f - f)` would compute `inf - inf`).
2. `generation += 1` before the species update (legacy order), so stagnation is judged against the generation that produced the fitness being consumed.
3. `update_species` → species fitness, stagnation, descending sort, spawn allocation, parent pairs.
4. `_new_gene_keys(state, crossed.node_keys)` → `new_node_keys (P,)` and `new_conn_markers (P, 3)`.
5. Crossover: one `gather` per field for winner and loser, then batch-first `genome.execute_crossover(state, key, winners, losers)` (winner first).
6. Mutation: batch-first `genome.execute_mutation(state, key, crossed, new_node_keys, new_conn_markers)`, scan-chunked by `pop_batch_size`; the operator is genome-owned (`DefaultGenome` builds `DefaultMutation(0.1, 0.1, 0.4, 0.05)`, an explicit `DefaultMutation()` keeps 0.2/0.2).
7. Elitism: `select(elite_mask[:, None, …], crossover_children, mutated_children)` per field, one reshaped mask per field rank.
8. Speciation: one `genome.prepare_distance` digest, then `speciate(state, self._distance_rows(digest, population), population)`.
9. Commit `pop`, `randkey`, `generation`, `species`.

## Species Algebra
Membership is one primitive, `M[i, p] = idx2species[p] == species_keys[i]` of shape `(S, P)`; NaN compares False, so dead slots and unassigned rows never match.
Species fitness is `select(M[i], fitness, -inf)` then `species_fitness_func(..., axes=1)`, masking before the reduce so a member-less slot stays `-inf`; stagnation is `(f_s <= best_fitness) & (generation - last_improved > max_stagnation)`, disabled below the top `species_elitism` ranks, and a killed slot writes NaN into its float fields and `-inf` into its species fitness.
Sort is a stable ascending `argsort` plus the reversal permutation and one `gather` per field, so after the sort the slot index *is* the fitness rank.
Spawn in rank mode: `n = sum(valid)`, `rank_score = n - arange(S)`, `target = floor(rank_score / max((n+1)*n/2, 1) * pop_size)`; in fitness mode: `f' = f_live - min_live(f_live) + 1`, `target = floor(f' / sum_live(f') * pop_size)`, with a fresh slot's `-inf` best fitness `nan_to_num`-ed to weight `0`.
Both modes damp with `member_count + (target - member_count) * spawn_number_change_rate`, floor at `min_species_size`, force dead/NaN slots to `0.0`, cast to int32, then add the residual to the **first live slot** by one `scatter` so `sum(spawn) == pop_size` exactly.
Parent pairing ranks members by fitness descending, takes `survive_size = clamp(floor(survival_threshold * member_count), 1, max(min(member_count, pop_size), 1))` (a NaN `member_count` reads as `0`, so a dead slot still yields one parent), draws one `randint(key, (S, 2, P), 0, survive[:, None, None])` for father and mother and decides the winner in species space (ties to the father, `>=`).
Elite slot `k` of a block (`idx_in_block == k < genome_elitism`) pins **both** parents to that block's own `k`-th ranked member (`min(arange(P), live_members - 1)` as the rank index), so the top `genome_elitism` members survive unmutated as *distinct* individuals.
Block flattening: with exclusive prefix `E` of `spawn`, `loc(p)` is the **last** `i` with `E[i] <= p` (the count of qualifying `i` minus one) and `idx_in_block(p) = p - E[loc(p)]`, one `gather` at `flat = loc * P + idx_in_block` into the row-major `(S, P)` pair arrays; the count form needs no `spawn[i] > 0` term because `spawn >= 0` makes `E` monotone and `sum(spawn) == pop_size` makes that index a live block.
Scan 1 (centre reservation): per live slot `i`, `d_i` is the `(P,)` row `distance(centre_i, pop)` — behind one `cond` per iteration when the table is sparse, or read by `gather` from `matrix`'s pre-measured rows on the dense path — then `closest = argmin(select(unassigned, d_i, +inf))`, assign `idx2species[closest] = species_keys[i]`, re-elect `pop[closest]` as the centre and set its distance to `0`; a dead slot or an empty unassigned set writes nothing.
Scan 2 (member assignment): a live slot assigns every genome with `d < compatibility_threshold` and `(unassigned | d < current distance)`; a dead slot with anything unassigned creates a species keyed `next_species_key` seeded by the first unassigned genome.
Post-pass: leftovers adopt the last species key, slots created this generation get `best_fitness = -inf` / `last_improved = generation`, `member_count` is one masked compare-sum over `(S, P)`, and the centre tables are rebuilt once per scan as `select(mask[:, None…], gather(population.<field>, index_table, axis=0), scan_table)`, value-identical to scattering each centre row inside the iteration — which is why a scan records only its per-slot value and not the four centre tables.
Body sizes (dense, `"tiled"`, dispatches per iteration at `P=500`): scan-1 body 14, scan-2 body ~124, most of it its nested `measure_distance`.

## Search Quality (XOR3d / XOR, measured)
Config: `DefaultGenome(num_inputs=3 (XOR3d) / 2 (XOR), num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)`, `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, `backend="numpy"`, 150 generations; per-seed finals and the oracle comparison live in `../CONTEXT.md` (the authority).
The result this node must not lose: XOR3d pop 100 (seeds 0-19, shipped genome defaults) escapes **13/20** and targets **11/20** against the frozen oracle's 4/20 and 2/20 (Fisher two-sided p = 0.0095); XOR3d pop 500 / pop 1000 target 6/6 and 3/3.
Nothing here gates the pop-100 cell: species kill, spawn starvation, elite displacement, `max_in_degree = 4` (refusing 0.00-0.04 of fired add-conn gates), `max_depth = 16` against an observed maximum node level of 6-9, and an unsaturated output row are all measured non-binding.
The lever is genome-side and shipped: `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=0.4, conn_delete=0.05)`, an explicit `DefaultMutation()` keeping 0.2/0.2; at equal gates an add-conn is accepted about half as often as a delete-conn (duplicate, self, cycle and `max_in_degree` refusals), so an equal-gate operator sits at −0.14…−0.22 connections per individual per generation and its populations stay under-wired, while 0.4/0.05 moves that to +0.15 and lifts generation-150 density to 10.38 connections, output in-degree 2.59 and the multi-input-ancestor fraction to 0.82 (control 0.417) at an unchanged node count (8.19 vs 8.36).
Cloning the champion into every elite slot instead keeps a small population in one compatibility basin (1 live species every generation), where `benchmarks/legacy_jax` splits into 2 species at gen 3, 4 at gens 12–25 and 7 by gen 17.
The cell is not distance-gated (max pairwise distance reaches 2.4–2.5 with median 0.44–0.9, against a legacy gen-15 100×100 matrix of median 1.57 and max 2.79), and `survival_threshold` at 0.1 / 0.5 plus a `min(2, member_count)` survivor floor were measured and rejected: they move which seeds escape instead of removing the cell.

## Distance Rows
Both phases need one `(P,)` row per species slot and the population is measured `2 · species_size` times, so `NEAT.tell` digests it once (`genome.prepare_distance` sorts each gene family into a `DistanceDigest`, batch `P` on every population-indexed leaf) and `DistanceRows` turns centres into rows without re-sorting.
A call is `(state, centre, pop) -> (P,)`, the centre built by `_kernels.centre_payload(population, rows, pop_size, tiled)` from four 1-D rows — one rank-raising `evoxc.broadcast` per field when tiled, one `evoxc.reshape` to a leading axis of `1` otherwise — so one call is one `genome.measure_distance` call in both modes.
The mode is `_validation.distance_centre_mode(state)`, a plain host string resolved at trace time (absent means `"tiled"`, so a bare hand-built `State` keeps the population-shaped contract; anything else raises `TensorNEATError`); `Pipeline.setup` registers `"tiled"` on a GPU-class device and `"single"` otherwise, and the choice is not part of the executable-cache signature, so switching needs a rebuild.
Both modes ship because the costs sit on different resources: `"single"` selects the genome's dense key-table single-centre route, which wins on the numpy interpreter and loses on a GPU, where its per-call scatters run single-threaded (40 × 0.97 ms + 40 × 0.52 ms of device time per generation at `P = 500`; `## Measured Cost` holds the numpy pair); it is exact only while every gene key lies inside `[0, genome.key_span)`, which the bounded allocator keeps true, and the genome raises on host-resident data when it does not.
`__call__` is the production route (`compute_row` in both gated scan bodies and in every dense `assign_members` iteration) and is single-valued: batch `1` is tiled in `"tiled"` mode and measured as it stands in `"single"`, batch `pop_size` is measured row-wise in both, and a whole table goes through `matrix` by name — the dense scan 1 being `matrix`'s only caller.
Each slot's row is known before its iteration reads it, because every `scatter` in both scans writes its own slot only: scan 1's row for slot `i` is `distance(pre-scan centre i, pop)` and scan 2's for a **live** slot is `distance(post-scan-1 centre i, pop)`, so the dense path runs `rows1 = distance_fn.matrix(state, centre_table)` once before `evoxc.scan(reserve, …)` and each iteration reads `evoxc.gather(rows1, slot, axis=0)` — exactly the row it would have measured, since `arange(S)` visits each slot once; only a creating slot has a carry-dependent centre.
`matrix` measures those rows inside **one fixed-length `evoxc.scan`** on both spellings (`S` calls of one centre row on the host leg, `S // k` calls of `k` rows on the accelerator one), so nothing is measured at the top level of the graph and no `S * P` batch is ever formed.
The host body gathers centre row `slot` and makes one `measure_distance` call on `centre_payload(..., tiled)`, stacking `(S, P)`; the accelerator body gathers its group's `k` rows, merges them with `grouped.centre_batch` and makes one call against the `k`-times tiled digest `grouped.for_state` builds, returning the flat `(k * P,)` step value on purpose (a `(k, P)` `y` would become a rank-3 `scatter`), then `reshape`s to `(S - S % k, P)` and measures the `S % k` trailing rows singly.
`grouped.group_size` answers `k = 1` for every non-accelerator state (capping `k` at `GROUP_ROW_BUDGET // pop_size` and at the slot count), so the numpy graph is untouched and there the grouped route still loses on wall time (`## Measured Cost`).
Scan 2 keeps its in-scan measurement on both paths, and not for convenience: `_scan_accelerator.assign_step` seeds a creating slot with `pop[seed]`, where `seed` is the lowest index still unassigned *at that step*, so the centre and its distance row are mutually dependent and no static reordering of `k` centres exists; species are created in practice (seed 42, 10 generations: 0 / 0 / 1 / 0 … on the gated `xor_p100` cell, 0 / 5 / 10 / 4 / 0 … at `P = 500`, 1 / 10 / 8 / 0 … at `P = 1000`), and a second pre-measured table is the rejected route (+58 % wall, `## Measured Cost`).
**Sparse table** (`species_size * pop_size <= GATED_ROWS`): one `cond` per scan iteration wraps that row — predicate `live & any_pending` (scan 1) or `live | create` (scan 2), false branch a discarded zero row — and it pays off exactly while the table is sparse (an unconditional in-loop call costs 55.6 vs 30.1 ms of `speciate` at `P=100` and 211.0 vs 152.2 ms at `P=300`).
**Dense table**: scan 1's table is measured before the scan and each iteration reads its row with a `gather`, while scan 2 measures its selected centre per iteration, so the 40 compatibility kernels split 20 in `matrix` and 20 in scan 2's body; dispatch is `2 · species_size` calls (40 at `S = 20`) on the host path and in the `"single"` width, `ceil(species_size / k) + species_size` (30 at `S = 20`, `k = 2`) on the accelerator `"tiled"` path, plus one `prepare_distance`.
The `argmin_with_mask`/`fetch_first` sentinels are built once per generation so no scan body emits a `constant` op, and the dense path requires a `distance_fn` with `matrix` (`TensorNEATError` naming it otherwise) while the gated path works with any callable.
Bit-identity is a property of the genome kernel, which is row-independent (elementwise per-pair ops, per-row reductions over the gene axis, one sorted alignment per row), so in-scan and top-level rows are the same floats and both widths carry the same centre row.

## Accelerator Formulation of the Speciation Scans
On the box's MI300X a `xor_p500` generation is 19.6 ms of device time in 2 087 kernels, and the two scans contribute ~2.29 ms of it as ~120 single-workgroup dispatches: a dispatch costs a ~4.5 µs floor regardless of body size and an index-tracking reduction is much dearer than a plain reduce, so the levers there are dispatch count and plain reductions, not element volume.
`state.kernel_mode` picks the spelling (`speciate` reads it once through `is_accelerator(kernel_mode(state))`); the host spelling is the shipped one everywhere else, and both spellings keep the loop (`### The slot axis is not unrolled`).
The accelerator spelling is value-identical and removes three costs: the duplicated predicate reduction (`argmin_with_mask`/`fetch_first` already report "no candidate" through `I_INF`, so `claim`/`create` need no `reduce_max(mask)`, and the gated scan-1 `cond` predicate is a carried scalar counter seeded at `pop_size` and decremented by `claim`, because an iree-compile whose predicate reduces a `(P,)` value that is also an operand of the same dispatch SIGSEGVs in llvm-cpu's `GenericVectorization` as `evoxc.BackendError`).
Index tracking becomes plain reductions — scan 1 `best = reduce_min(select(pending, distances, +inf), axes=0)` then `closest_raw = reduce_min(select(pending & (distances == best), pop_index, I_INF), axes=0)` (int32, no `cast`), scan 2 `seed_raw = reduce_min(select(unassigned, pop_index, I_INF), axes=0)` — and the lowest index attaining the minimum is `argmin`'s tie order, so no `argmin`/`argmax` survives here.
Per-iteration `(S,)`-cell scatters go away because `evoxc.scan` already stacks its `y` per step: scan 1 returns `closest_raw`, scan 2 `seed_raw` and a rank-0 carried species-key counter, so the host bodies' **6 per-slot scatters per iteration pair** become none, and scan 2's created keys are rebuilt once after the scan as `select(create_mask, next_species_key + prefix_sum_exclusive(cast(create_mask, float32)), species_keys)`.

**Scan 1 reduces the whole pre-measured block, row-wise.** On the dense path `_block_min_index` masks the whole `(S, P)` table with the iteration's `pending`, takes `reduce_min(..., axes=1)`, matches `pending & (block == best)`, reduces `select(match, pop_index, I_INF)` along the same axis (int32) and reads its own row with one `gather(closest, slot)`, so the two per-iteration `(P,)`-axis-0 reductions — the dearest dispatches of the body at ~20.8 and ~18.9 µs of a one-workgroup kernel — become two `S`-workgroup reductions plus one 20-element gather; the gated path has no table to close over and keeps `_row_min_index` with its static op count unchanged.
Measured on the MI300X (interleaved fresh-process rounds, 10 generations at pop 500 and 8 at pop 1000, first step excluded): pop 500 reads **14.23 / 14.46 / 14.28 ms** per generation against the pre-change tree's **14.19 / 14.15 / 14.14 ms**, pop 1000 **16.84 / 16.76 ms** against **17.31 / 16.91 ms**; it ships because it is value-identical and de-serialises two reductions that grow with `pop_size`, not because the dispatch count moved.

### The slot axis is not unrolled
Running each phase's step once per static slot as ordinary SSA removes three loop regions (12 → 6 region entries) and the per-iteration scan scaffolding (`gather(xs)`, `reshape(y)`, `scatter(y)`, `add(counter)`, `less(counter)`) and pays for it in the static graph: 2 174 → 7 393 ops (`accelerator`/`single`), 2 114 → 6 793 (`accelerator`/`tiled`), `hal.executable.export` 296 → 531 / 314 → 590, `iree-compile` 5.8–6.0 s → 11.4–14.2 s per static shape (`gpu_measure` build 8.739 → 13.448 s at `xor_p500`, 9.034 → 13.548 s at `xor_p1000`, 13.169 → 18.281 s on `custom_pagie_p500`).
It buys 1 267 → 1 130 generation kernels and generation-kernel device time 8.06 → 6.83 ms, i.e. **no device-time win** against the loop form's 1 248 kernels / 6.792 ms, plus about 4 ms of wall per generation at `xor_p500` (14.3 → 9.7 ms in the recorded interleaved ladder, 13.1 → 9.0 ms under `gpu_measure`), which is host/launch overhead rather than kernel time.
At ~4 ms per generation against 5.6–6 s of one-off build the break-even is ≈1 400 generations, so the 150-generation protocol and every realistic run lose on it and the loop form ships.
The gated path is doubly excluded: its step body is an `evoxc.cond` over the four population field tables, and twenty of those at the top level fuse into one dispatch whose 26 operands exceed the ROCm/HIP HAL's 16-bindings cap, so the artifact compiles and then fails to load (`INVALID_ARGUMENT ... binding_flags count 26 exceeds maximum of 16`).

## Scan Patterns (why fixed-length scans are exact)
`evoxc` de-sugars `scan` into `while` + `gather`/`scatter`, so a trip count must be static and the carry must keep identical dtypes and shapes: both phases are `scan(f, carry, enp.arange(species_size))` with per-slot masks, never a data-dependent `while_loop`, and because every write is mask-then-single-`scatter` the legacy early-exit iterations are provably no-ops.
The `"host"` scans carry 7 packed values (`idx2species`, the running distance, the species keys plus `next_species_key` as one `(S+1,)` array, and two rank-1 per-slot tables), the `"accelerator"` ones 2 (scan 1: `assign`, `dist`, plus the rank-0 unassigned counter on the gated path) and 3, because its per-slot record is the scan's `y`; `matrix` is a third kind, trip count `species_size` or `species_size // k`, dummy carry, no table write.

## StableHLO Export Rules (binding for every kernel here)
Every graph here must survive `evoxc`'s StableHLO v1 exporter, because `backend=` is forwarded verbatim and a rejected op is a hard `evoxc.BackendError`, never a fallback; `scatter` is allowed only as rank-1 `axis=0` or a rank-2 row/column write (`axis` 0 or 1), and any wider operand raises `BackendError` naming the rank.
Neither speciation scan writes a gene table: the `"host"` spelling records its per-slot values with plain rank-1 `evoxc.scatter`, the `"accelerator"` spelling with the scan's `y`-stack writes, and each scan's centre rows are rebuilt afterwards with `gather` + `select`; a rank-3 per-slot row write would be flattened to a rank-2 `axis=0` row scatter and reshaped back, which is why the grouped `matrix` step keeps its `y` flat `(k * P,)`.
`_keys.first_free_keys` writes its occupancy cells with the rank-1 form on the flattened table (`flat = row * width + key`), because a `(P, max_nodes)` index block against a rank-2 table is neither a rank-1 scatter nor a rank-2 row write, and the out-of-span redirect happens in the index arithmetic, so no mask is needed at the scatter.
No `tril`/`triu`, no `flip`, no `cumsum`, no `iota`: static tables are baked with `static_i32`/`static_f32` (one `constant` op each, bit-identical because the entries are exact index/`0`/`1` values), so the gate matrix of `prefix_sum_exclusive` is `static_f32(np.tril(np.ones((S, S)), -1))` and the `(S, P)` block mask of `block_layout` is one broadcast comparison reduced by one `sum`.
Supported and in use: `gather` (single axis, static indices), `argsort`, `select`, `concatenate`, `constant`, `reshape`, `dot`, `argmax`/`argmin`, the `random_*` family and `while`/`if` regions; `argmin`/`argmax` appear only in the `"host"` spelling, the `"accelerator"` one using `reduce_min` plus a one-hot `equal` over `iota_i32(pop_size)`.
`scan` stacks its per-step outputs along a new leading axis, so both speciation scans return only their small per-step value and `matrix`'s scans return one row per step; a table whose rows are all written anyway is built by `concatenate` instead of a scatter (the generation-0 centre tables, `_kernels.first_centre_table`).
Unsigned integer dtypes are outside iree's declared dtype set, so a graph uses `int32`/`int64` only; the numpy interpreter accepts every rank, so a violation is invisible until `evoxc.lower(graph, backend="iree")`, which makes `## Export Audit` part of verification.

## Gene Keys & Padding
`_keys.node_keys_for_split(node_keys, key_span, max_nodes, base)` allocates the structural node key as a **wrapped per-individual spread** `max_nodes + (base + 1 + slot) mod (key_span - max_nodes)`, with `base = genome.max_node_key(state, node_keys)`.
The window `[max_nodes, key_span)` is the part of the dense key table no payload row can occupy, because a row holds at most `max_nodes` keys.
The wrap keeps the pre-rewrite per-individual monotone base plus the population-slot offset and exists because the unbounded `max_node_key + 1 + slot` formula outruns `key_span` (its `arange(P)` offset alone escapes a 150-key table from slot 100 up) while the schedule's dense key table silently drops an out-of-span key: the row exists in the payload but never reaches the phenotype, and no pipeline guard reports it.
A plain lowest-free policy is measurably worse, because the distance aligns node genes **by key** and charges non-homologous keys to the disjoint term, so compact keys inflate node homology and collapse speciation (XOR3d, `pop 500`, seed 42, 150 generations: final best `-0.25` with a species peak of 2–3, against `-8.76e-06`, target at generation 73 and a peak of 19–20 for the spread).
The spread candidate is tested exactly like the genome's `plan_add_node` alias guard (`reduce_max(equal(node_keys, candidate))`), so an allocation is never a key the payload owns and never outside `[0, key_span)`.
`first_free_keys(node_keys, key_span)` is the fallback — the **lowest key in `[0, key_span)` the individual's own rows do not hold** — and supplies the rows that already hold the spread candidate; it builds a `(P, key_span + 1)` occupancy table from one-element int32 constants and two broadcasts, redirects padded, negative and out-of-span keys to a permanently occupied trailing dump cell with one `select`, writes every real key with one rank-1 `scatter` on the flattened table and reads the answer with one `argmin`, 22 traced ops run unconditionally because its result is discarded on collision-free rows.
The composed allocator is 35 traced ops (the fallback's 22 plus 13 for the spread and the alias guard) plus `genome.max_node_key` (7), with no region and `remainder` exporting as `v1`; availability is static, because a row holds at most `max_nodes` keys and `key_span > max_nodes` is enforced by `_keys.validate_key_space`, so the window holds `key_span - max_nodes` keys (at least `max_conns` at the default bound) and a free key always exists.
The allocation is taken from the **crossover child** (`crossed.node_keys`), the payload the mutation actually receives, because a base derived from the pre-crossover parents can already be owned by the child and the alias guard would then silently refuse the split.
Uniqueness holds **within one individual's own keys** only: two individuals with the same occupied set get the same new key and the distance reads it as a homologue — the intended meaning of "both invented the same structural node", and what keeps keys spread instead of compact.
`new_conn_markers` continues from `state.pop.conn_keys` through `max_conn_marker` as `reshape(base_marker, (P, 1)) + arange(1, 3P + 1).reshape(P, 3)` when `conn_gene.uses_historical_marker`, else zeros; a `historical_marker` is a population-wide identity matched exactly by the distance kernel, never a table index, so it is not range tested, and gene alignment compares full key rows so a shared marker never yields a false homologue.
Validity is never inferred from packaging: this subtree calls `node_exists(node_keys)`, `conn_exists(conn_keys)` and `max_conn_marker` on the genome, whose helpers take only the key array and derive the padding sentinel themselves.

## Measured Cost (numpy, `DefaultGenome(50, 100)`, XOR, `species_size=20`, seed 42)
`benchmarks/PERF_NUMPY.md` is the committed record (pass 1 the op-count pass, pass 2 the tiled func-fit evaluate plus RL rollout hoist; 150-generation headline `xor_p500` 178.24 ms/generation · 228.6 MiB · 0.55 s build, `xor3d_p500` 183.22 · 237.2 MiB · 0.54 s).
The centre-width record is one interleaved same-session run (6 fresh-process rounds, one process per (mode, case) cell, 3 warmup + 20 timed `Pipeline.step` after the build step, `Pipeline(is_detailed=False)`, median of per-round medians) over `"tiled"`, `"single"` and the reference tree `91d579a`: `xor_p500` **159.43 / 112.73 / 115.81 ms**, `xor_p1000` **272.84 / 176.61 / 178.58 ms**, gated `xor_p100` 42.85 / 41.09 / 40.92 ms.
`"single"` reproduces the reference tree within noise (0.986× / 0.999× / 1.004× at `P = 500` / `1000` / `100`), `"tiled"` is 1.389× / 1.542× / 1.043× slower than `"single"`, at 218.7 versus 196.4 MiB peak RSS at `P = 500` and 348.5 versus 302.5 MiB at `P = 1000`, build 0.26–0.29 s on `p100` / 0.33–0.43 s on `p500`/`p1000`, `builds == 1` in every cell; `"tiled"` dispatches fewer ops everywhere and is still the slower leg, because the interpreter charges each op for the work it does and the row-wise merge's `(pop_size, 2 · max_conns)` intermediates are that volume — which is also why `"single"` cuts peak RSS.
**Grouped distance tables are a measured rejection on the numpy leg and ship on the accelerator one.** Against the merge route, `xor_p500` read 164.11 ms / 233.8 MiB / 7 592 dispatched ops with one centre per call against 155.23 ms / 253.2 MiB / 6 589 ops with two per call: −13 % dispatches for +8.3 % peak RSS and a bimodal wall time, 152–165 ms on the fast side and 196–253 ms in 7 of 13 fresh default-environment processes.
The slow mode is the allocator's, not the kernel's: with `MALLOC_MMAP_THRESHOLD_`/`MALLOC_TRIM_THRESHOLD_` forced to 1 GiB the grouped cell is stable at 152.2 / 152.2 ms against 158.9 / 162.1 ms, an intrinsic ~4 % win, but the 2× wider intermediates trip glibc's thresholds in about half of default-environment runs and numpy is the default leg — so `group_size` answers `k = 1` there.
`k = 4` loses outright (+15 % wall, +30.5 % peak RSS) and so does a second pre-measured table for scan 2 (+58 % wall at 258.96 ms / 274.0 MiB), because the `(rows, 2 · max_conns)` intermediates double at `k = 2` (273.8 MiB) and triple at `k = 4` (353.1 MiB) while the kernel is memory-bound there.
**Retention rule (measured, not inferred).** A kernel's live set is charged once per enclosing block — at the entry block for the rest of the generation, in a scan body once per iteration — so the in-scan table keeps one centre's transients alive where the top-level spelling keeps `S` of them: never hoist a kernel out of a `while`/`scan` without measuring peak RSS.
`breed` remains genome-bound (`genome.execute_mutation` 67 % of its IR ops, `genome.execute_crossover` 21 %, `update_species` 9 %, `neat.py` 1.4 %), and padded gene geometry dominates at `P=1000` (whole `Pipeline.step`: `max_nodes/max_conns` 50/100 → 506.0 ms, 20/40 → 192.2, 10/16 → 126.2).
`benchmarks/PERF_NUMPY.md` pass 1's same-session harness is 1.29× / 2.04× / 3.06× faster than the frozen JAX side at `P=100 / 500 / 1000`.

## Known Issues
Both host statics are part of the executable-cache signature (`host_payload._formulation_signature`), so switching either forces exactly one rebuild (`## Export Audit` holds the 24-cell lower/compile record).
Against the *declared* contract (51 / 109 / 157 ms per generation at `P=100 / 500 / 1000`, `benchmarks/RESULTS.md`) the committed pass-1 record reads 38.58 / 159.90 / 270.08 ms, while that record's measured frozen-JAX side is 38.99 / 295.33 / 807.30 ms.
What is left is genome-owned: the pair count `2 · species_size · pop_size` is irreducible (a created species takes the first unassigned genome as its centre, so its row depends on every earlier assignment; 40 000 pairs at `P=1000`), the padded gene geometry is a workload choice, and the merge's homologue sort — `2·M` key rows re-sorted once per centre — is what the dense single-centre route removes.
The allocator's census (`DefaultGenome(num_inputs=3, max_nodes=50, max_conns=100)` + `XOR3d`, `key_span=150`, seed 42, five `step`s at pop 100 and 500) reads 0 out-of-span node keys, 0 out-of-span connection endpoints and 0 duplicate node keys after every generation, against the unbounded `max_key + 1 + arange(P)` spelling whose first escape appears at generation 4; the wrapped candidate already belongs to the individual on at most 28 of 500 rows, so the fallback serves under 6 % of the population and that fallback table is the allocator's whole wall cost: +10 % / +4–8 % / +12–14 % at pop 100 / 500 / 1000.
`show_details` caches one counting executable per payload shape, reads every tensor through `to_numpy`, and a failure from it is recorded once per hook label in `Pipeline.detail_failures` instead of being swallowed or aborting the run; `next_species_key` must stay strictly greater than every live key (`setup` seeds it at `1.0`, slot 0 uses `0.0`), since a colliding counter silently merges two species' `member_count`.
`test/unit/algorithm/test_spawn.py` encodes `loc(p) = #{i : spawn[i] > 0 and E[i] <= p} - 1`, wrong for a live zero-spawn species in the middle of a table, so the oracle needs the "last qualifying block" form (cross-node item, `test/` is not writable from here).

## Constraints
No `jax`/`torch`/`numpy.random` import, since `import tensorneat` must stay free of them (release gate); `numpy` appears only as `numpy.finfo(dtype).max` in `_finite_bound`, a host-side scalar read.
No branching, `bool()`, `len()` or host reads on traced values; static Python `if`/`for` over constructor configuration is fine and unrolls at trace time.
No `.at[]`, no `cumsum` on the compute path (prefix sums are triangular `dot`), no `tril`/`triu`/`flip`/`iota`, no rank ≥ 3 `scatter`, no `where=`/`initial=`/`any`/`all`/`take`/`searchsorted`/`repeat`, no `vmap` over anything region-bearing, no `fori_loop`/`switch`.
Shapes are static (`P`, `S`, `max_nodes`, `max_conns`), so a shape change forces a rebuild; configuration validation raises `common.errors.TensorNEATError` with a named message while trace/shape/backend errors propagate unchanged and are never re-wrapped or silently fallen back.
State keys touched: `randkey`, `pop_size`, `pop`, `generation`, `species` and the host-only `distance_centre`/`kernel_mode` statics, plus the genome/problem keys documented above; `neat.py` (1026) is the documented ~1000-line exception named in `../CONTEXT.md`, and a further addition to `_kernels.py` (1000) belongs in `_scan_accelerator.py` or `_distance.py`.

## Known Risks (evoxc)
`evoxc.random.randint` needs a symbolic `high` that stays ≥ 1 at runtime, which `max(survive_size, 1)` guarantees; `evoxc.scatter` is replacement-only, so every "accumulate" update is restructured as reduce-then-scatter-once.
The one real iree hazard is seeding a `while`-carried value with a `scatter`, which SIGSEGVs `iree-compile` while exporting stays clean: seed with a one-hot `equal`/`logical_and`, and treat only `test/backends` as proof of portability.
The host spelling's five per-slot `while`-carried tables are not that case — integer/float per-slot tables, unchanged from `f5a1d0a2` and graph-for-graph identical — and those graphs compile and run on both targets (`## Export Audit`).
A batch-`1` centre selects the genome's dense single-centre route, whose per-call scatters a GPU executes single-threaded, so `state.distance_centre` stays `"tiled"` on a GPU-class device; the packed-carry convention is a shape-size decision, not a workaround for a live fault (9 loop-carried values compile in 6/6 fresh `evoxc.build` runs).

## Test Strategy
Tests live in the sibling `test/` tree (read-only from here): `test/unit/algorithm/` covers the spawn/selection/stagnation algebra, the block layout and the speciation scans on fixed payloads, `test/parity/algorithm/neat/` compares against `benchmarks/legacy_jax` (only the deliberate divergences allowed), and `test/integration/` evolves XOR to its target with a fixed seed and asserts run-to-run determinism.
Every kernel here must be a pure function of `(state, key)`: no dict-order dependence, no host RNG, no float→int conversion without an explicit mask; the sparse/dense switch and the `cond` placement are static trace-time choices, so a shape or gate regression shows up as a build error rather than as silent numerical drift.
The allocator is verified twice: `node_keys_for_split` against a host oracle of the same formula on every population the run produces, and end-to-end by the census above.
Distance rows and both centre widths are verified by whole-run bit-identity: 10 seed-42 generations at `P=100` (gated), `P=500` and `P=1000` (dense), 21 arrays per generation (the four `previous_pop` arrays, `fitnesses`, the four next-`pop` arrays, `randkey`, `generation` and all ten `SpeciesState` leaves) compared with `array_equal(equal_nan=True)` plus dtype and shape — **4 410 pairs, 0 mismatches** over 7 arm pairs × 3 populations, the shipped host arm equalling accelerator/`"tiled"`, accelerator/`"single"`, accelerator/`"tiled"` under `distance_formulation="index_free"` and both arms of the pre-revert tree `f5a1d0a2`.
The table's call width is observable at trace time by counting `distance.base.BaseDistance.measure` invocations and each centre's batch: one row per call on the host leg, `k` on the accelerator leg.
The numpy leg is pinned unchanged against `f5a1d0a2` (`kernel_mode="host"`, `distance_centre="single"`, `is_detailed=False`, build excluded, 6 interleaved fresh-process rounds, medians of per-round medians, 3 warmup + 20 timed `Pipeline.step`): 8 121 dispatches at `xor_p500` and 8 179 at `xor_p1000` with an identical per-op-name histogram, static graph 2 242 ops / 416 constants identical element-for-element modulo debug locations, peak RSS 191.3–191.7 MiB / 292.4–292.8 MiB, wall ratio 0.994× / 1.001×.
No test in the sibling `test/` tree selects `kernel_mode`, so the `"accelerator"` leg, its kept wins and the compile matrix are hand-run verifications: the accelerator path is the one this node cannot regress-detect on its own, and a committed test for it is wanted from the `test/` owner.

## Export Audit (how the StableHLO rules are verified)
The audit traces every graph TensorNEAT builds, classifies each op with `evoxc.backends.stablehlo.ops.status(op.name)` (`"v1"`/`"decompose"`/`"deferred"`, only the last a violation), checks every `scatter`'s operand rank and `axis`, and finishes with `evoxc.lower(graph, backend="iree")`.
Current result — 24 target-cells (pops 100 / 300 / 500 × `kernel_mode` `{host, accelerator}` × `distance_centre` `{single, tiled}`, `distance_formulation` left at the CPU default `merge`, which is why these counts differ from the production `index_free` census): **24/24 green**, `evoxc.lower` succeeding for llvm-cpu and rocm with a byte-identical `mlir_text` per cell, **0 deferred ops**, every `scatter` rank ≤ 2 (operand/index/update max rank 2, `axis=0`), no unsigned dtype, no two scatters sharing an index expression, and both `iree-compile` stages (`--compile-to=executable-configurations`, `--compile-to=executable-targets`) exiting 0 for both targets — 60/60 stage runs, no diagnostics.
Graph ops / `hal.executable.export` there: `p500` accelerator single **2 204 / 297**, accelerator tiled **2 181 / 348**, host single **2 242 / 318**, host tiled **2 182 / 334**; the gated cells read 2 177 / 2 117 (accelerator) against 2 236 / 2 176 (host) at `p100`/`p300`, and the `setup` graph is 74 ops with the allocator's 35 all `v1`.
The `"host"` spelling still seeds five `while`-carried per-slot tables with `scatter`s (scan 1's `closest_table`/`claim_table`, scan 2's `seed_table`/`created_mask` and its species-key table), unchanged from `f5a1d0a2` and graph-for-graph identical, and those graphs compile and run on both targets: the package rule against seeding a `while`-carried value with a `scatter` is about the boolean scatter seed in the mutation cycle kernel, not these integer/float per-slot tables.
