# NEAT (`tensorneat.algorithm.neat`) — population cycle + species bookkeeping

## Intent
Everything in a NEAT generation that is neither network mathematics (genome) nor task evaluation (problem): the population payload, the generation counter, speciation, stagnation, spawn allocation, parent pairing, and the crossover/mutation dispatch.
`NEAT` (`neat.py`) is the algorithm the pipeline drives; `SpeciesController` + `SpeciesState` (`species.py`) own the species algebra; `_distance.py` owns the compatibility-distance rows over one generation's population digest.
Every kernel here is batch-first over `P = pop_size` and compiled by `pipeline.py` into the single per-generation evoxc graph, so no function may branch on a traced value or read the host.
Current per-generation cost is recorded in `benchmarks/PERF_NUMPY.md` and under `## Measured Cost`: the padded gene axis multiplies every per-pair op, and both the interpreter's per-op overhead and the element volume of its intermediates feed what a generation costs.
One `xor_p500` generation executes 7 466 dispatched ops in `"tiled"` mode and 8 066 in `"single"` mode (3 817 / 3 877 on the gated `xor_p100` cell), the layer's own work being one population digest plus `2 · species_size` compatibility calls in `speciate` and `O(pop_size)` selection/crossover/mutation; it never materialises a `max_nodes × max_nodes` tensor (`## Executed-Op Inventory`, `## Distance Rows`).
The distance centre's width is a host mode on the trace-time state, `state.distance_centre` — `"tiled"` (the default on a bare `State`) or `"single"` — chosen per device and fixed for a session (`## Distance Rows`).

## Layout (six files, all near the ~1000-line baseline)
`species.py` — `SpeciesState` plus `SpeciesController`: the species algebra, each method delegating its tensor body to `_kernels.py`.
`_kernels.py` — plain graph helpers (no `@evoxc.defn`, no state): spawn allocation, block layout, parent pairing, membership, sort/prefix-sum primitives, the scalar/constant normalisers (`const`/`int_const`/`nan`/`neg_inf`/`pos_inf`/`scalar_f32`), the export-safe table primitives (`first_centre_table`, `static_i32`/`static_f32`), `centre_payload` (the one spelling of a centre row, tiled or single), `gated` (the static lazy-row gate) and the two speciation scans.
`_distance.py` — `DistanceRows`, the digest-backed `distance_fn` `speciate` consumes: one `measure_distance` call per centre, spelled `"tiled"` or `"single"` through `_kernels.centre_payload`, and the `(S, P)` table through `matrix`.
`_keys.py` — the bounded structural node-key allocator: `validate_key_space`, `node_keys_for_split`, `first_free_keys`; `## Gene Keys & Padding` holds its algebra.
`_validation.py` — host-side configuration validators shared with `neat.py` (`positive_int`, `non_negative_int`, `unit_interval`, `positive_float`), each raising `TensorNEATError` with the parameter name, plus the speciation distance-centre mode: `DISTANCE_CENTRE_KEY`/`DISTANCE_CENTRE_MODES` and `distance_centre_mode(state)`, which resolves `state.distance_centre` at trace time and raises `TensorNEATError` for anything outside `("tiled", "single")`.
`neat.py` — `_sanitize_fitness` and `NEAT`: setup, ask/transform/forward, the `tell` algebra, `_batched` chunking, host-side `show_details`.

## API Surface
`__init__.py` re-exports `NEAT`, `SpeciesController`, `SpeciesState`.

`NEAT(BaseAlgorithm)` — `neat.py`:
`__init__(genome, pop_size, species_size=10, max_stagnation=15, species_elitism=2, spawn_number_change_rate=0.5, genome_elitism=2, survival_threshold=0.1, min_species_size=1, compatibility_threshold=2.0, species_fitness_func=evoxc.max, species_number_calculate_by="rank", pop_batch_size=None)` — constructor kwargs are API-compatible with the pre-rewrite library.
`setup(state=None) -> State` requires `state.randkey` (`TensorNEATError` otherwise), registers `pop_size` (static int), `pop` (`GenomeTensors`, axis 0 = individual), `generation` (0-d float32) and `species`, and advances `randkey`.
`setup` is **host-side**: it builds and runs one small init graph (`split(randkey)` → `genome.initialize` → species seeding) and cannot be called inside an active trace.
`ask(state) -> GenomeTensors` (zero ops, returns `state.pop`); `transform(state, pop=None)` / `forward(state, transformed, inputs, pop=None)` delegate to the genome; `tell(state, fitness) -> State` runs the algebra below.
`Pipeline`'s compiled generation cycle calls `ask`, `transform`, `prepare_forward`/`forward_prepared` and `tell`; `ask` runs inside the generation graph on the registered payload and returns `state.pop` unchanged, while `forward` has no in-tree call site (`pipeline.py` queries through the prepared pair).
`prepare_forward(state, transformed, pop=None, samples=1)` / `forward_prepared(state, transformed, prepared, inputs)` are the same delegation split in two, calling `genome.prepare_pass` / `genome.forward_prepared` with the payload (`pop`, else `state.pop`) and `samples`; `forward` is their composition.
`show_details(state, fitness) -> None` is the only host-side member; `num_inputs`/`num_outputs`/`pop_size` are read-only properties (`pop_size` backed by `_pop_size`).
Private members: `_sanitize_fitness` and `_finite_bound` (module functions), `_seed_species(self, cfg, first)`, `_static_state(state)`, `_build_options(state)`, `_create_next_generation(state, winner, loser, elite_mask)`, `_new_gene_keys(state, node_keys)`, `_batched(kernel, key, *args)`, `_gene_counts(state, payload)`, `_gene_count_executable(state, payload)`, `_distance_rows(digest, population)`.
`__init__` also calls `_keys.validate_key_space(genome)`, so a genome with `key_span <= max_nodes` fails at construction with a `TensorNEATError` naming the mechanism.

`SpeciesController(StatefulBaseClass)` — `species.py`:
`setup(state, first) -> State` where `first` is **one** `GenomeTensors` individual (no population axis); slot 0 becomes the single live species keyed `0`, `member_count[0] = pop_size`, centre = `first`, `best_fitness = -inf`, `next_species_key = 1.0`.
`update_species(state, fitness) -> (state, winner (P,), loser (P,), elite_mask (P,))`; it owns the generation's first `evoxc.random.split` and stores the advanced key back into `state.randkey`.
`speciate(state, distance_fn, pop=None) -> State`; `distance_fn` is any callable `(state, centre_payload, pop) -> (P,)` or, for a centre payload of `species_size` rows, `(S, P)` — `_distance.DistanceRows` provides both forms; the population comes from `pop`, else from the `"pop"` state entry, else from the four split payload entries, else `TensorNEATError`.
Private: `_species_fitness`, `_stagnation`, `_cal_spawn_numbers_by_rank`, `_cal_spawn_numbers_by_fitness`, `_pair_parents(species_state, selection_key, spawn_number, fitness)`, `_block_layout(spawn_number) -> (loc, idx_in_block)`, `_membership`, static `_population(state, pop=None)`, static `_gather_species(species_state, order)`, static `_sort_desc_legacy(x, axis=-1)`, static `_prefix_sum_exclusive(values)`.
`_block_layout` and `_prefix_sum_exclusive` are test seams only: production calls `_kernels.block_layout` / `_kernels.prefix_sum_exclusive` (via `_pair_parents`/`_kernels.spawn_from_target`), so change the kernel, not these wrappers.
`_population` is a pass-through to `_kernels.read_population`, and `read_population`'s `SPLIT_POP_KEYS` (two-key-array) branch is unreachable from `NEAT`, which registers one four-array `GenomeTensors` payload under `POP_KEY`.
`_kernels.first_centre_table(species_size, row, fill, dtype)` (imported by `species.py` as `_first_centre_table`) builds a generation-0 centre table as `concatenate([reshape(row, (1,) + row.shape), constant fill block])`.
Module constant `SPAWN_MODES = ("rank", "fitness")`.

`DistanceRows(genome, digest, population, pop_size)` — `_distance.py`, created per generation inside `NEAT.tell`:
`__call__(state, centre, pop=None)` accepts a centre batch of exactly `1` or `pop_size` and returns `(P,)`; any other batch raises `TensorNEATError` naming it.
The centre width follows `state.distance_centre`: in `"tiled"` mode a batch-`1` centre is tiled to `pop_size` rows before the measurement, so every call carries a population-shaped centre whatever its caller sent, while in `"single"` mode both widths are measured as they stand (a batch-`1` centre selecting the genome's dense single-centre route).
It is the route `_kernels.speciate` uses (`distance_fn(state, centre_payload(...), payload_like(...))` from both `compute_row` bodies), and `_kernels.centre_payload(population, rows, pop_size, tiled)` is the one shared spelling of both widths — one rank-raising `evoxc.broadcast` per field when tiled, one `evoxc.reshape` per field otherwise.
`row(state, centre)` is the single-row form (one `measure_distance` call) and `matrix(state, centres)` the explicit by-name `(S, P)` whole-table form on both modes (one such call per centre row inside one fixed-length scan; `## Distance Rows` holds the mechanics) — `__call__` never dispatches to `matrix`, because a `species_size`-row table and a one-individual centre are indistinguishable when `species_size == 1`.
It validates that the digest's population axis and the measured population's static shapes match `pop_size` (`TensorNEATError` otherwise).

`SpeciesState` — frozen dataclass, one leaf per field, stored under `state.species`:
`species_keys (S,) f32` (NaN = dead slot), `best_fitness (S,) f32`, `last_improved (S,) f32`, `member_count (S,) f32`, `idx2species (P,) f32` (NaN = unassigned, only inside `speciate`), `center_node_keys (S, N) i32`, `center_node_attrs (S, N, NA) f32`, `center_conn_keys (S, E, CK) i32`, `center_conn_attrs (S, E, CA) f32`, `next_species_key` (0-d f32).
Centres store the **four split payload arrays** (payload reconciliation #2), not packed gene rows, so `distance_fn` receives real `GenomeTensors`.
Every scalar field is float32 so NaN encodes a dead slot and `generation` writes into `last_improved` without a dtype change inside a scan carry.

## Generation Algebra (`NEAT.tell`)
1. Sanitise fitness: finite entries pass through untouched, NaN and both infinities become `-inf`.
2. `generation += 1` before the species update (legacy order): stagnation is judged against the generation that produced the fitness being consumed.
3. `SpeciesController.update_species` → species fitness, stagnation, descending sort, spawn allocation, parent pairs.
4. `_new_gene_keys(state, crossed.node_keys)` → `new_node_keys (P,)` (each a wrapped-spread key in `[max_nodes, key_span)`, or the individual's lowest free key when the spread collides) and `new_conn_markers (P, 3)`.
5. Crossover: one `gather` per payload field for winner and loser, then batch-first `genome.execute_crossover(state, key, winners, losers)` (winner first — part of the contract).
6. Mutation: batch-first `genome.execute_mutation(state, key, crossed, new_node_keys, new_conn_markers)`, scan-chunked by `pop_batch_size`.
   The operator is genome-owned: `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(0.1, 0.1, 0.4, 0.05)` (`node_add, node_delete, conn_add, conn_delete`) when no operator is passed, while an explicit `DefaultMutation()` keeps NEAT-python's `0.2`/`0.2` connection gates; the node gates and the value stage stay at their defaults in both (`../../genome/operations/mutation/default.py`).
7. Elitism: `select(elite_mask[:, None, …], crossover_children, mutated_children)` per payload field, with one reshaped mask per distinct field rank.
8. Speciation against the new population: `digest = genome.prepare_distance(state, population)` (once per generation), then `SpeciesController.speciate(state, self._distance_rows(digest, population), population)`.
9. Commit `pop`, `randkey`, `generation`, `species`.

`_sanitize_fitness(fitness, pop_size)` implements the guard as `finite = abs(f) <= _finite_bound(dtype)` plus `select`, and raises `TensorNEATError` unless `fitness.shape == (pop_size,)`.
`_finite_bound(dtype)` is `numpy.finfo(dtype).max` read at trace time (a Python float, never an array), so the predicate needs no invalid arithmetic: NaN compares false, both infinities compare false, every finite float32 is `<= FLT_MAX`.
The `abs` spelling keeps the guard silent; an `isnan(f - f)` form would compute `inf - inf` and make the numpy backend emit one `RuntimeWarning: invalid value encountered in subtract` per generation for the same bits.

## Species Algebra
Membership is one primitive reused everywhere: `M[i, p] = idx2species[p] == species_keys[i]`, shape `(S, P)`; NaN compares False, so dead slots and unassigned rows never match.
Species fitness: `select(M[i], fitness, -inf)` then `species_fitness_func(..., axes=1)` — masking before the reduce keeps a member-less slot at `-inf` instead of NaN.
Stagnation: `improved = f_s > best_fitness`; `stagnant = (f_s <= best_fitness) & (generation - last_improved > max_stagnation)`, disabled when the species' fitness rank is below `species_elitism`; a killed slot writes NaN into `species_keys`/`best_fitness`/`last_improved`/`member_count` and `-inf` into its species fitness.
Sort: stable ascending `argsort` plus the reversal permutation `n - 1 - arange(n)` (`_sort_desc_legacy`), then one `gather` per field (`_gather_species`); after the sort the slot index *is* the fitness rank.
Spawn (rank mode): `n = sum(valid)`, `rank_score = n - arange(S)`, `denominator = max((n+1)*n/2, 1)`, `target = floor(rank_score/denominator * pop_size)`.
Spawn (fitness mode): `f' = f_live - min_live(f_live) + 1`, `rate = f' / sum_live(f')`, `target = floor(rate * pop_size)`; the `-inf` best fitness of a freshly created slot is `nan_to_num`-ed to weight `0`.
Spawn (both modes): `damped = member_count + (target - member_count) * spawn_number_change_rate`, floored at `min_species_size`, dead/NaN slots forced to `0.0`, cast to int32, then the residual added to the **first live slot** by one `scatter` so `sum(spawn) == pop_size` exactly.
Parent pairing: members ranked by fitness descending, `survive_size = clamp(floor(survival_threshold * member_count), 1, max(min(member_count, pop_size), 1))` (a NaN `member_count` reads as `0`, so a dead slot still yields one candidate parent), one `randint(key, (S, 2, P), 0, survive[:, None, None])` draw for father and mother, `flat_gather` of the ranking, winner decided in species space (ties to the father, `>=`).
Elite slot `k` of a block (`idx_in_block == k < genome_elitism`) pins **both** parents to that block's own `k`-th ranked member (`min(arange(P), live_members - 1)` as the rank index) — the legacy elementwise pin, so the top `genome_elitism` members survive unmutated as *distinct* individuals rather than as copies of the champion, and the `live_members - 1` clamp keeps an elite on the species' finite-fitness members where an unclamped rank could hand it a non-member or broken genome row.
Block flattening: with exclusive prefix `E` of `spawn`, `loc(p)` is the **last** `i` with `E[i] <= p` (the count of qualifying `i` minus one) and `idx_in_block(p) = p - E[loc(p)]`; parents are one `gather` at `flat = loc * P + idx_in_block` into the row-major `(S, P)` pair arrays.
The count form is exact and needs no `spawn[i] > 0` term: `spawn >= 0` makes `E` its running sum and therefore monotone non-decreasing, so the qualifying slots form a prefix of `[0, S)` and "count minus one" IS the last qualifying index, while `sum(spawn) == pop_size` (guaranteed by `spawn_from_target`'s residual correction) makes that index a live block because a zero-spawn block's exclusive prefix equals the end of the preceding live block.
Speciation, scan 1 (centre reservation): per live slot `i`, `d_i` is the `(P,)` row `distance(centre_i, pop)` — computed behind one `cond` per iteration when the table is sparse, and on the dense path read by `gather` from the rows `distance_fn.matrix` measured *before* the scan (see `## Distance Rows`) —, `closest = argmin(select(unassigned, d_i, +inf))`, then assign `idx2species[closest] = species_keys[i]`, re-elect `pop[closest]` as the centre and set its distance to `0`; a dead slot or an empty unassigned set writes nothing.
Speciation, scan 2 (member assignment): a live slot assigns every genome with `d < compatibility_threshold` and `(unassigned | d < current distance)`; a dead slot with anything still unassigned creates a species keyed `next_species_key` seeded by the first unassigned genome, then assigns the same way; an iteration with nothing to do writes nothing.
Each scan carries `assign`, `dist` and `keys_ext` plus its own two rank-1 per-slot tables, one single-element rank-1 `axis=0` `scatter` each — scan 1 records `closest_table (S,) int32` and `claim_table (S,) float32`, scan 2 records `seed_table (S,) int32` and `created_mask (S,) float32` — and **not** the four centre gene tables, because a slot's only centre write is `pop[closest]` (scan 1) or `pop[seed]` on a creating slot (scan 2).
The centre tables are rebuilt once after each scan as `select(mask[:, None…], gather(population.<field>, index_table, axis=0), scan_table)` (four gathers + four selects at top level, one reshaped mask per field rank), which is value-identical to scattering each centre row inside the iteration, leaves the dead rows' stale integers untouched and keeps the result bit-identical.
Both scans close over their graph-time constants (`I_INF`, `0`, `0.0`, `iota_i32(pop_size)`, the compatibility threshold and the gated false-branch zero row) instead of rebuilding them per iteration — one `constant` op each at the top level instead of one per slot.
Speciation post-pass: leftovers adopt the last species key, slots created this generation get `best_fitness = -inf` / `last_improved = generation`, and `member_count` is one masked compare-sum over `(S, P)`.
Body sizes (dense path, `"tiled"` centre, per-iteration executed dispatches at `P=500`): scan-1 body 14 and scan-2 body ~124, most of which is its nested `measure_distance` call.

## Search Quality (XOR3d / XOR, measured)
Config: `DefaultGenome(num_inputs=3 (XOR3d) / 2 (XOR), num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)`, `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, `XOR3d()` / `XOR()`, `backend="numpy"`, `fitness_target=-1e-9`, 150 generations, `Pipeline.setup` + a manual `step` loop.
The per-seed finals, the frozen-oracle comparison and the escape/target definitions live in `../CONTEXT.md` `## Search Quality` (the authority) and in `benchmarks/results/xor3d_quality_2026-11-04.md`.
The one result this node must not lose: XOR3d pop 100 (seeds 0-19, shipped genome defaults) escapes **13/20** and targets **11/20** against the frozen oracle's 4/20 and 2/20 (Fisher exact two-sided p = 0.0095), and XOR3d pop 500 / pop 1000 target 6/6 and 3/3.
Nothing in this node gates the pop-100 cell: species kill, spawn starvation, elite displacement, `max_in_degree = 4` (refusing only 0.00-0.04 of fired add-conn gates), `max_depth = 16` against an observed maximum node level of 6-9, and an unsaturated output row are measured non-binding.
The lever is genome-side and it is shipped: `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=0.4, conn_delete=0.05)` (`../../genome/operations/mutation/default.py::DEFAULT_GENOME_CONN_ADD`/`DEFAULT_GENOME_CONN_DELETE`), an explicit `DefaultMutation()` keeps 0.2/0.2, and `../../genome/operations/mutation/CONTEXT.md` `## Shipped connection gates` is the ledger.
Mechanism: at equal connection gates an add-conn is accepted about half as often as a delete-conn (duplicate, self-connection, cycle and `max_in_degree` refusals), so an equal-gate operator's structural steady state is -0.14…-0.22 connections per individual per generation and such populations stay under-wired; the shipped pair moves that to +0.15 and lifts generation-150 density to 10.38 connections, output in-degree 2.59 and the multi-input-ancestor fraction to 0.82 (control 0.417) at an unchanged node count (8.19 vs 8.36).
Parent pairing must hand each elite slot a **different** top member, not `genome_elitism` copies of the champion: cloning the champion into both elite slots keeps a small population in a single compatibility basin (1 live species every generation).
`benchmarks/legacy_jax` on the same config splits into 2 species at gen 3, 4 at gens 12–25 and 7 by gen 17.
The cell is not distance-gated: the population's max pairwise compatibility distance already reaches 2.4–2.5 with median 0.44–0.9, overlapping the legacy distribution (legacy gen-15 100×100 matrix: median 1.57, max 2.79), so no threshold change can open a basin the population is already outside of.
Raising `survival_threshold` to 0.1 or 0.5 and raising the survivor floor to `min(2, member_count)` were measured and rejected: they move which seeds escape instead of removing the cell, and the floor departs from the legacy `max(1, floor(thr · members))` count.
Weight-mutation frequency and the connection-gene law are genome-owned; their sweep and the rejections live in `../../genome/operations/mutation/CONTEXT.md`.

## Distance Rows (one digest per generation; one call per centre, two centre widths)
Both phases need one `(P,)` compatibility row per species slot, and the same population is measured `2 · species_size` times, so `NEAT.tell` digests it once: `genome.prepare_distance(state, pop)` sorts each gene family of the population into a `DistanceDigest` (batch `P` on every population-indexed leaf) and `DistanceRows` turns centres into rows against it without re-sorting the population.
Call shape: `(state, centre, pop) -> (P,)` with the centre built by `_kernels.centre_payload(population, rows, pop_size, tiled)` from four 1-D centre rows — one rank-raising `evoxc.broadcast` per field to `pop_size` identical rows when `tiled`, one `evoxc.reshape` per field to a leading axis of `1` otherwise — so one call is one `genome.measure_distance` call in both modes.
The mode is `state.distance_centre`, resolved at trace time by `_validation.distance_centre_mode` as a plain host string, never a traced value: an absent entry means `"tiled"`, so a bare hand-built `State` keeps the population-shaped contract, and any other value raises `TensorNEATError`.
`_kernels.speciate` computes `tiled = distance_centre_mode(state) == "tiled"` once at trace time and both `compute_row` bodies close over that static choice.
`Pipeline.setup` registers `"tiled"` on a GPU-class device and `"single"` otherwise; selection is host-side and is not part of the executable-cache signature, so one session runs one mode and switching needs a rebuild.
Both modes ship because the two costs sit on different resources: `"single"` selects the genome's dense key-table single-centre route, 112.73 / 176.61 ms per generation at `P = 500` / `1000` on the numpy interpreter against `"tiled"`'s 159.43 / 272.84 ms and 196.4 / 302.5 MiB peak RSS against 218.7 / 348.5 MiB, while on a GPU that route's per-call scatters run single-threaded — 40 × 0.97 ms + 40 × 0.52 ms of device time per generation at `P = 500`, i.e. 42.6 → 83.8 ms per generation, a 2× device-time regression — so a GPU-class device runs `"tiled"` and the numpy/CPU pipeline runs `"single"`.
The genome pairs the centre against the digest's `P` rows: `"single"` takes its **dense key-table single-centre route** (sort-free) when its static gate holds and broadcasts the centre internally otherwise, while `"tiled"` always takes the row-wise merge.
The dense route is exact only while every gene key lies inside `[0, genome.key_span)`; the algorithm's bounded structural-key allocator keeps it there (0 out-of-range keys over the measured runs), and the genome raises on host-resident data when it does not.
`measure_distance` also accepts a `k · P` batch against a `k`-times-tiled digest (the genome's `group_digest`, unwired here); `DistanceRows` never builds that width.
`__call__` is single-valued and is the production route (`compute_row` in both gated scan bodies and in every dense `assign_members` iteration): a batch of `1` is tiled to `pop_size` rows in `"tiled"` mode and measured as it stands in `"single"` mode, a batch of `pop_size` is measured row-wise as it stands in both, anything else raises, and a whole centre table is measured through `matrix` by name — the dense scan 1 is `matrix`'s only caller.
The row of a slot is known before the iteration reads it, because every `scatter` in both scans writes its own slot only: scan 1's row for slot `i` is `distance(pre-scan centre i, pop)`, and scan 2's row for a **live** slot is `distance(post-scan-1 centre i, pop)`. Only a slot that *creates* a species has a carry-dependent centre (`pop[seed]`, `seed` = first unassigned genome).
The dense path pre-measures **scan 1** outside the scan: `rows1 = distance_fn.matrix(state, centre_table)` runs once before `evoxc.scan(reserve, …)` and each iteration reads `evoxc.gather(rows1, slot, axis=0)`.
That is exactly the row the iteration would have measured, because scan 1's centre for slot `i` is the pre-scan centre row `i` (every `scatter` in `reserve` writes its own slot and `arange(S)` visits each once).
`matrix` measures those rows inside **one fixed-length `evoxc.scan`** over the `S` centre rows (body: gather centre row `slot` — a 1-D row — then one `genome.measure_distance` call on `centre_payload(..., tiled)`; output stacked to `(S, P)`), so the table is `S` calls of one centre row in the selected spelling and not one `S * P` batch.
Grouping several centres into one `measure_distance` call is a measured, unwired option: the genome's `group_digest`/`GroupedDigest` route accepts a `k · P` centre batch and is bit-identical, but it loses on numpy wall time in a common allocator mode (`## Measured Cost`), so this module keeps one call per centre.
The scan is a memory scope, not an arithmetic change: `evoxc`'s numpy interpreter pops a region's environment per iteration, so only one centre's transients are alive at a time and the kernel still stays out of the reservation `while` body.
Scan 2 keeps its in-scan measurement on both paths, because a slot that creates a species measures the carry-dependent `pop[seed]`; a second pre-measured table for it is the rejected route (+58 % wall time on the merge route, `## Measured Cost`).
The dense path therefore requires a `distance_fn` with a `matrix` method and raises `TensorNEATError` naming it otherwise; the gated path keeps working with any callable.
**Sparse table** (`gate` true, `species_size * pop_size <= GATED_ROWS`): one `cond` per scan iteration wraps that row — `gated_row(active, compute_row, operands)`, predicate `live & any_pending` (scan 1) or `live | create` (scan 2), false branch `enp.zeros((pop_size,), float32)` discarded by the iteration's own `claim` / `take` mask; the gate exists because an unconditional in-loop call costs 55.6 vs 30.1 ms of `speciate` at `P=100` and 211.0 vs 152.2 ms at `P=300`, i.e. the `if` regions pay off exactly while the table is sparse.
**Dense table** (`gate` false): scan 1's whole centre table is measured *before* the scan through `distance_fn.matrix` — one call per centre row, in the selected spelling — and each iteration reads its own row with a `gather`.
Scan 1 never runs the kernel in-loop; scan 2 measures its selected centre per iteration, so the generation's 40 compatibility kernels split 20 in `matrix` and 20 in scan 2's body.
Dispatch: one generation makes `2 · species_size` `measure_distance` calls (`S = 20` → 40) on both paths and in both modes, plus one `prepare_distance`.
The sentinels `argmin_with_mask` and `fetch_first` need (`+inf` filler and `I_INF` default) are built once per generation in `speciate` and passed as `filler=inf_f32` / `default=iinf` on both paths, so no scan body emits a `constant` op for them.
Bit-identity is a property of the genome kernel, not of this module: the compatibility kernel is row-independent (elementwise per-pair ops plus per-row reductions over the gene axis, one sorted alignment per row), so in-scan and top-level rows are the same floats and both widths carry the same centre row.

## Scan Patterns (why fixed-length scans are exact)
`evoxc` de-sugars `scan` into `while` + `gather`/`scatter`, so a trip count must be static and the carry must keep identical dtypes and shapes: both speciation phases are `scan(f, carry, enp.arange(species_size))` with per-slot masks, never a data-dependent `while_loop`.
The legacy early-exit conditions survive as masks, and because every write is mask-then-single-`scatter` the extra iterations are provably no-ops.
Carries are kept narrow and packed (`idx2species` and the running distance as two `(P,)` arrays; the species keys plus `next_species_key` as one `(S+1,)` array), which keeps the carry list short and every per-step op small.
Each scan therefore carries 7 values: those three plus its own two rank-1 per-slot tables, whose spelling and post-scan centre rebuild are in `## Species Algebra`.
`DistanceRows.matrix` is a third, unrelated kind of scan: its trip count is `species_size` and its carry is a one-element dummy, so it writes no table at all — only its stacked per-iteration `(P,)` rows. It exists purely to bound the interpreter's live set (see `## Distance Rows`); a static Python loop over the same centres is the faster-but-hungrier spelling.

## StableHLO Export Rules (binding for every kernel here)
Every graph this node contributes must survive `evoxc`'s StableHLO v1 exporter: `backend=` is forwarded verbatim by the pipeline, so `"iree"`/`"tvm"`/`"xla"` users lower these kernels and a rejected op is a hard `evoxc.BackendError`, never a fallback.
The v1 exporter accepts only the spellings below — a new kernel has to pick one of them:
- `scatter`: rank-1 `axis=0`, or a rank-2 row/column write (`axis` 0 or 1); any wider operand raises `BackendError` naming the rank.
  Neither speciation scan writes a gene table: scan 1 records `closest_table`/`claim_table` and scan 2 records `seed_table`/`created_mask` with plain rank-1 `evoxc.scatter`, and each scan's centre rows are rebuilt afterwards with `gather`+`select`.
  A rank-3 per-slot row write is spelled by flattening the trailing axes into one row length `R`, writing them as a rank-2 `axis=0` row scatter and reshaping back (a rank-2 table short-circuits to a plain `evoxc.scatter`); this package needs it nowhere, because both speciation scans record only rank-1 per-slot tables.
  `_keys.first_free_keys` (the allocator's fallback) writes its occupancy cells with the rank-1 form on the flattened table (`flat = row * width + key`, offsets from `common.tools.batch_offsets` plus one `reshape`), because a `(P, max_nodes)` index block against a rank-2 table is neither a rank-1 scatter nor a rank-2 row write; the out-of-span redirect happens in the index arithmetic (`select` to the dump column), so no mask is needed at the scatter.
- No `tril`/`triu`, no `flip`, no `cumsum`, no `iota` — deferred/unmapped in v1.
  Static tables are baked as graph constants with `static_i32`/`static_f32` (one `constant` op each, bit-identical because the entries are exact index/`0`/`1` values): the gate matrix of `prefix_sum_exclusive` is `static_f32(np.tril(np.ones((S, S)), -1))`, and the `(S, P)` block mask of `block_layout` is one broadcast comparison reduced by one `sum`.
- Supported and in use: `gather` (single axis, static indices), `argsort`, `select`, `concatenate`, `constant`, `reshape`, `dot`, `argmax`/`argmin`, the `random_*` family, and `while`/`if` regions.
- A table whose rows are all written anyway is not a scatter: the generation-0 centre tables are `concatenate([reshape(row, (1,) + row.shape), constant fill block])` (`_kernels.first_centre_table`, used by `SpeciesController.setup`), which also exports at rank 3.
- `scan` stacks its per-step *outputs* along a new leading axis, so returning a whole `(S, …)` table from a scan body becomes a rank-4 scatter inside the desugared `while`; both speciation scans therefore return only their small per-step value (`assign` in scan 1, `create` in scan 2), and `matrix`'s scan returns one `(P,)` row per step (stacked to `(S, P)` by the scan, no write at all).
- Unsigned integer dtypes (`uint32`/`uint64`) are outside iree's declared dtype set — a graph is expected to use `int32`/`int64` only (the sibling `genome`/`common` nodes own their remaining occurrences).
The numpy reference interpreter accepts every rank, so a violation is invisible until `evoxc.lower(graph, backend="iree")`; the audit in `## Export Audit` is part of verification, not an optional extra.

## Gene Keys & Padding
`_keys.node_keys_for_split(node_keys, key_span, max_nodes, base)` allocates the structural node key as a **wrapped per-individual spread**: `max_nodes + (base + 1 + slot) mod (key_span - max_nodes)`, where `base` is `genome.max_node_key(state, node_keys)`.
The window `[max_nodes, key_span)` is the part of the dense key table no payload row can occupy, because a row holds at most `max_nodes` keys.
The wrap keeps the pre-rewrite per-individual monotone base plus the population-slot offset, so different individuals and generations still get different keys, and exists because the unbounded `max_node_key + 1 + slot` formula outruns `key_span` (its `arange(P)` offset alone escapes a 150-key table from slot 100 up), while the schedule's dense key table silently drops an out-of-span key: the node row exists in the payload but never appears in the phenotype, and no pipeline guard reports it.
A plain lowest-free policy is not enough on its own, and it is measurably worse than the spread: the compatibility distance aligns node genes **by key** and charges non-homologous keys to the disjoint term, so compact keys inflate node homology across the population and collapse speciation (XOR3d, `pop 500`, seed 42, 150 generations: final best `-0.25` with a species peak of 2–3, against `-8.76e-06`, target at generation 73 and a peak of 19–20 for the spread).
The spread candidate is tested exactly like the genome's `plan_add_node` alias guard (`reduce_max(equal(node_keys, candidate))`), so an allocation is never a key the payload owns and never outside `[0, key_span)`.
`first_free_keys(node_keys, key_span)` is the fallback primitive — the **lowest key in `[0, key_span)` that the individual's own rows do not hold**, free by construction — and it supplies the rows that already hold the spread candidate.
`first_free_keys` builds a `(P, key_span + 1)` occupancy table from one-element int32 constants and two broadcasts (a `(P, key_span)` graph constant would be 600 kB at `P=1000`), redirects padded (`I_INF`), negative and out-of-span keys to the permanently occupied trailing **dump cell** with one `select`, writes every real key with one rank-1 `scatter` on the flattened table (`flat = row * width + key`, offsets from `common.tools.batch_offsets`), and reads the answer with one `argmin` — 22 traced ops per generation.
The composed allocator is 35 traced ops: the fallback's 22 plus 13 (four `constant`, `add`, `remainder`, `add`, `reshape`, `equal`, `cast`, `reduce_max`, `not_equal`, `select`), and `neat.py` adds `genome.max_node_key` (7 ops) — no region at all, `remainder` exporting as `v1`, and the graph still lowering to iree (`pop 500`: 0 deferred ops, `scatter` shapes `{(1, axis 0), (2, axis 0)}`).
The fallback runs unconditionally rather than behind a `cond`: its result is discarded on every collision-free row.
The availability proof is static: a row holds at most `max_nodes` keys, `key_span > max_nodes` is enforced by `_keys.validate_key_space` in `NEAT.__init__` (a `TensorNEATError` naming the mechanism otherwise), so the window holds `key_span - max_nodes` keys — `max_conns` of them at the default bound `max(max_nodes, num_inputs + num_outputs) + max_conns` — and a free key always exists.
`key_span` and `max_nodes` reach the allocator as genome statics; `base` is passed in, so `_keys.py` stays a plain graph helper with no `State`/genome wiring.
No overflow concern: `base` is at most `key_span - 1` and every key `genome.initialize` or this allocator writes is below `key_span`, so `base + 1 + slot` stays far inside int32, and a negative `base` cannot arise from a legal payload (`remainder` keeps the dividend's sign, keys start at `0`).
The allocation is taken from the **crossover child** (`crossed.node_keys`), the payload `genome.execute_mutation` actually receives: a base derived from the pre-crossover parents can already be owned by the child, and the genome's `plan_add_node` alias guard would then silently refuse the split.
Uniqueness is guaranteed **within one individual's own keys** only: keys are namespaced per individual, two individuals with the same occupied set receive the same new key, and the compatibility distance reads that shared key as a homologue — the intended meaning of "both invented the same structural node".
The window is only `key_span - max_nodes` keys wide, so with `pop_size` above that width different individuals regularly share a key; that sharing is the pre-rewrite behaviour, not a defect, and it is precisely what keeps the keys spread instead of compact.
`new_conn_markers` continues from `state.pop.conn_keys` through `max_conn_marker(state, conn_keys)`: `reshape(base_marker, (P, 1)) + arange(1, 3P + 1).reshape(P, 3)` when `conn_gene.uses_historical_marker`, else zeros, with the `+1` folded into the int32 `arange` and the `cast` on the genome maximum emitted only when its traced dtype is not already int32.
A `historical_marker` is a population-wide identity matched exactly by the distance kernel, never an index into the dense key table, so it is not range tested and does not share the silent-drop property; the three markers of one individual are distinct from each other, and node keys and connection markers live in different key columns, so a coincidence between an allocated node key and an allocated marker is meaningless.
Gene alignment compares full key rows (endpoints plus marker), so a marker two individuals share never yields a false homologue; the width `3` is a genome-level convention (one mutation call adds at most three connections per genome).
Validity is never inferred from packaging: this subtree calls `node_exists(node_keys)`, `conn_exists(conn_keys)` and `max_conn_marker` on the genome — the validity helpers take only the key array and derive the padding sentinel themselves.
Dead species slots are recognised by `isnan(species_keys)` alone; their centre rows hold stale integers because int32 cannot carry NaN, and no kernel reads a centre gated by that mask.

## Divergences from the Pre-Rewrite Baseline (deliberate fixes)
1. Zero-survivor division: the old `(p_idx < survive_size) / survive_size` probability vector divided by zero for a one-member species; `randint` with `high = max(survive_size, 1)` yields two identical parents instead (self-crossover is the identity).
2. NaN-poisoned reductions: `"fitness"`-mode `min`/`sum` mixed in the NaN `best_fitness` of dead slots; every reduction masks dead slots with `select` first.
3. NaN → int32 cast for `spawn_number`: dead and NaN slots are explicitly written to `0.0` before the cast instead of relying on cast semantics.
4. Configuration errors raise `TensorNEATError` instead of `assert`/`ValueError`.
5. Sort tie order is reproduced by a stable ascending `argsort` plus a reversal gather, because `argsort(descending=True)` breaks ties the other way.
6. Random streams differ by construction: one key per population kernel (drawing `(P, …)` randomness internally) instead of one key per genome, so parity tests compare kernels with fixed inputs and structural outcomes, not RNG bit-patterns.
7. The spawn residual goes to the first **live** slot instead of literally slot `0`: identical after the descending sort (live slots precede dead ones), but a hand-built unsorted table can no longer hand population slots to a dead species.

## Randomness Budget
`NEAT.setup` consumes one `evoxc.random.split` to separate the initialisation key from the key carried into generation 0 (setup only, once).
Per generation there are exactly two splits: `selection_key, rest = split(state.randkey)` inside `update_species` (parent selection only), then `cross_key, mut_key, next_randkey = split_n(rest, 3)` in `_create_next_generation` (crossover, mutation, next `randkey`).
Speciation and the distance digest draw no randomness at all, so neither the digest nor the scan that consumes it can move an RNG stream.
`pop_batch_size` chunking pre-splits the mutation key with `split_n(key, n_batches)` and passes the stacked `(n_batches,)` int64 array as the scan `xs`, so each step receives a valid rank-0 key.
Keys are rank-0 scalars, so a batched kernel takes one key and draws its own population-shaped randomness; chunked and unchunked runs therefore draw different streams and `pop_batch_size` is part of the reproducibility config.

`"single"` reproduces the reference tree within noise (0.986× / 0.999× / 1.004× at `P = 500` / `1000` / `100`), and `"tiled"` is 1.389× / 1.542× / 1.043× slower than `"single"` on the same cells.

The mechanism is element volume rather than per-op count: the numpy interpreter charges each op for the work it does, and the row-wise merge's `(pop_size, 2 · max_conns)` intermediates are that volume, which is also why `"single"` cuts peak RSS.
**Grouped distance tables are a measured rejection and stay unwired.** Measured against the merge route, `xor_p500` read 164.11 ms / 233.8 MiB / 7 592 dispatched ops with one centre per call, against 155.23 ms / 253.2 MiB / 6 589 ops when scan 1 groups two centres per call: −13 % dispatches for +8.3 % peak RSS and a bimodal wall time at process level — 152–165 ms (2–5 % below the ungrouped form) in the fast mode, 196–253 ms (30–45 % above it) in 7 of 13 fresh default-environment processes.
The slow mode is the allocator's, not the kernel's: with `MALLOC_MMAP_THRESHOLD_=1073741824 MALLOC_TRIM_THRESHOLD_=1073741824` the grouped cell is stable at 152.2 / 152.2 ms against 158.9 / 162.1 ms for the ungrouped one, an intrinsic ~4 % win, but the 2× wider `(2 · pop_size, 2 · max_conns)` intermediates trip glibc's mmap/trim threshold under the default environment in about half of runs, and numpy is the default and fastest leg.
The two other ways of wiring it lose outright on the dense cell: `k = 4` reads +15 % wall time and +30.5 % peak RSS at 6 004 ops, and pre-measuring a second table for scan 2 at `k = 2` reads +58 % wall time at 6 661 ops (258.96 ms / 274.0 MiB).
The mechanism is row width: `(rows, 2 · max_conns)` intermediates double at `k = 2` (273.8 MiB), triple at `k = 4` (353.1 MiB) and reach 593 / 753 MiB at `k = 10` / `k = 20`, while the kernel is memory-bound there, so at `k = 4` the per-op-name profile of one generation moves `argsort` 25.5 → 37.0 ms, `gather` 21.5 → 36.1 ms, `cast` 8.0 → 17.7 ms and `reshape` 4.3 → 8.9 ms as dispatches fall 8061 → 4885 against a 28 % wall-time increase.

**Retention rule (measured, not inferred).** A kernel's live set is charged once per enclosing block — at the entry block for the rest of the generation, in a scan body once per iteration — so the in-scan table keeps one centre's transients alive where the top-level spelling keeps `S` of them.

## Known Issues
This node contributes **no** deferred op and no rank>=3 `scatter`; `## Export Audit` holds the current counts for both speciation paths (`P=100`'s gated one and `P=500`'s dense one) in both centre widths.
`"single"`'s dense `measure` body scatters its owner and attribute tables instead of merging, so `xor_p500` carries 26 scatters in `"tiled"` mode against 42 in `"single"`, every one `axis=0` and rank ≤ 2.

## Constraints
No `jax`/`torch`/`numpy.random` import; `import tensorneat` must stay free of them (release gate). `numpy` appears only as `numpy.finfo(dtype).max` in `_finite_bound`, a host-side scalar read.
No branching, `bool()`, `len()` or host reads on traced values — static Python `if`/`for` over constructor configuration is fine and unrolls at trace time.
No `.at[]`, no `cumsum` on the compute path (prefix sums are triangular `dot`), no `tril`/`triu`/`flip`/`iota`, no rank>=3 `scatter` (flatten to a rank-2 row write or bake a static constant — see `## StableHLO Export Rules`), no `where=`/`initial=`/`any`/`all`/`take`/`searchsorted`/`repeat`, no `vmap` over anything region-bearing, no `fori_loop`/`switch`.
Shapes are static: `P`, `S`, `max_nodes`, `max_conns` are fixed at build time; a change forces a rebuild by the pipeline.
Errors: configuration validation raises `common.errors.TensorNEATError` with a named message; trace/shape/backend errors propagate unchanged and are never re-wrapped or silently fallen back.
State keys touched: `randkey`, `pop_size`, `pop`, `generation`, `species` and the host-only `distance_centre` mode, plus the genome/problem keys documented above — nothing else.
Files stay near the ~1000-line baseline: `neat.py` (1026) the population cycle, `_kernels.py` (999) the graph helpers, `species.py` (979) the species algebra, `_distance.py` (340) the digest-backed rows, `_keys.py` (325) the bounded key allocator, `_validation.py` (165) the host validators and the distance-centre mode.

## Known Risks
`evoxc.random.randint` needs a symbolic `high` that stays ≥ 1 at runtime — guaranteed by `max(survive_size, 1)`, which also removes the legacy NaN case.
`evoxc.scatter` is replacement-only, so every "accumulate" update is restructured as reduce-then-scatter-once (spawn residual, stale-write elimination in the speciation scans).
The packed-carry convention is a shape-size decision (narrow `(P,)`/`(S+1,)` carries), not a workaround for a live fault: the wide-carry codegen hazard does not reproduce (9 loop-carried values compile in 6/6 fresh `evoxc.build` runs).
The one real iree hazard is seeding a `while`-carried value with a `scatter`: that SIGSEGVs `iree-compile` 3.11 in the assembled generation graph while exporting and single-kernel compiles stay clean — seed with a one-hot `equal`/`logical_and` instead, and only `test/backends` proves portability.
A batch-`1` centre selects the genome's dense single-centre route, whose per-call scatters a GPU executes single-threaded — 40 × 0.97 ms + 40 × 0.52 ms of device time per generation at `P = 500`, i.e. 42.6 → 83.8 ms per generation — so `state.distance_centre` must stay `"tiled"` on a GPU-class device; the route itself legalizes on both `iree` targets (`## Known Issues`).
`evoxc.scan` pops a region's environment per iteration, which is the only reason the in-scan table is cheap: moving those calls back to the top level (or unrolling the scan) re-charges every transient to the entry block for the rest of the generation.
Reading a dead slot's centre rows would return stale integers, not NaN — always gate centre reads behind `isnan(species_keys)`.

## Test Strategy
Tests live in the sibling `test/` tree (read-only from here): `test/unit/algorithm/` covers the spawn/selection/stagnation algebra, the block layout and the speciation scans on fixed payloads.
`test/parity/algorithm/neat/` compares against `benchmarks/legacy_jax` on fixed gene payloads — identical selection/speciation outcomes for the deterministic steps, and only the divergences listed above allowed elsewhere.
`test/integration/` evolves XOR to its fitness target with a fixed seed and asserts run-to-run determinism for a `(seed, config, shape)` triple.
Every kernel here must be a pure function of `(state, key)`: no dict-order dependence, no host RNG, no float→int conversion without an explicit mask.
The key allocator is verified twice: `node_keys_for_split` against a host oracle of the same formula (wrapped spread, then the lowest-free fallback) on every population the run produces, through `evoxc.trace`/`evoxc.evaluate` on the numpy backend, and end-to-end by a per-generation census of a real `Pipeline` run that counts live node keys and connection endpoints outside `[0, key_span)` and duplicate node keys inside an individual — 0 of each at `pop 100` and `pop 500` over five generations.
Distance rows are verified by whole-run bit-identity: an `npz` dump of the fitness vector, the four payload arrays of the produced and the next population, all ten `SpeciesState` leaves, `randkey` and `generation` per generation, compared with `tobytes()` equality (padding NaNs make `np.array_equal` report self-vs-self differences) against the reference tree — 63 arrays per run at `P=500` and `P=1000` (3 generations each, the dense path) for the in-scan table, zero mismatches.
The table's call width is its contract: one `measure_distance` call per centre row, spelled by `state.distance_centre` through `_kernels.centre_payload` — a batch-`1` centre in `"single"` mode, a batch-`pop_size` one in `"tiled"` mode — observable at trace time by counting `tensorneat.genome.operations.distance.base.BaseDistance.measure` invocations and the batch of each centre; the grouped `k · P` route it must stay clear of is `tensorneat.genome.operations.distance.grouped`.
Both centre widths are verified by whole-run bit-identity: 10 seed-42 generations at `P=500` and `P=1000` plus 3 on the gated `P=100` cell (XOR, `max_nodes=50`, `max_conns=100`, `species_size=20`, `survival_threshold=0.01`) hash the four `previous_pop` arrays and the float32 fitness vector per generation (`dtype.str + repr(shape) + tobytes()` into sha256) and read the digests in `## Distance Rows`, identical for `"tiled"`, `"single"`, an absent `distance_centre` entry and the tiled-only reference tree, with both speciation paths running end to end (`P=100` gated, `P=500` / `1000` dense).
The sparse/dense switch and the `cond` placement are static trace-time choices, so a shape or gate regression shows up as a build error in `test/release_gate_no_jax.py`'s two-generation XOR run rather than as a silent numerical drift.

## Export Audit (how the StableHLO rules are verified)
Recipe, cheap and per-op: monkeypatch `evoxc.build` to also keep `evoxc.trace(fn, *specs)` for every graph TensorNEAT builds, then walk `graph.module.functions[*].region.blocks` recursively (`op.regions` included, skipping the result-less `return` op) and classify each op with `evoxc.backends.stablehlo.ops.status(op.name)` — it returns `"v1"` (direct emitter), `"decompose"` (emitted as an expansion) or `"deferred"` (the writer raises); only `"deferred"` is a violation. For `scatter` additionally check the operand rank and `op.attributes["axis"]` against the rank-1/rank-2 rule, and count the `while` regions to see the graph's shape. `op.location` gives the exact `file:line` of an offender, so a regression is attributable without reading diffs.
Finish with `evoxc.lower(graph, backend="iree")` on a box that has the iree packages; it fails fast on the first unsupported op and does not need a working end-to-end backend.
Current result: 0 deferred ops in both centre widths; `xor_p500` is 2 187 step-graph ops with 6 `while` regions and scatters `{(1, axis 0): 25, (2, axis 0): 1}` in `"tiled"` mode against 2 247 ops / 6 `while` / `{(1, axis 0): 33, (2, axis 0): 9}` in `"single"`, the gated `xor_p100` cell is 2 175 (`"tiled"`) / 2 235 (`"single"`) ops with 5 `while` + 4 `if` regions, and the `setup` graph is 74 ops; the allocator's 35 ops are all `v1` (`remainder` emits directly) and include only the fallback's single rank-1 axis-0 occupancy scatter.
`iree-compile --iree-hal-target-backends=rocm --iree-rocm-target=gfx942 --compile-to=executable-configurations` succeeds in every mode and reports 346 / 317 `hal.executable.export` at `P=500` and 333 / 318 at `P=100` (tiled / single) with identical llvm-cpu counts.
Full llvm-cpu vmfb compilation at `P=500` needs `--iree-llvmcpu-stack-allocation-limit=1048576` in every mode, including the tiled-only reference tree, because of the `stablehlo.sort` stack guard: the flag is mode-independent.
The same oracle runs in both spawn modes, and degenerate shapes are smoke-tested: `species_size` 1, 2, 3, 8.
