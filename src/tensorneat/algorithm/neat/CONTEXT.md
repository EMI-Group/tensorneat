# NEAT (`tensorneat.algorithm.neat`) — population cycle + species bookkeeping

## Intent
Everything in a NEAT generation that is neither network mathematics (genome) nor task evaluation (problem): the payload, the generation counter, speciation, stagnation, spawn allocation, parent pairing and the crossover/mutation dispatch.
`neat.py` drives the cycle, `species.py` owns the species algebra, `_kernels.py` the host-spelling graph helpers, `_scan_accelerator.py` the accelerator-spelling scan bodies, `_distance.py` the digest-backed distance rows and `_keys.py` the structural-key allocator.
Every kernel is batch-first over `P = pop_size` and compiled by `pipeline.py` into the single per-generation evoxc graph, so nothing branches on a traced value or reads the host.
One numpy `Pipeline.step` on this tree dispatches **7 592** ops at `xor_p500` (3 675 of them the 40 compatibility-distance calls) and **30 994** at `cartpole_p100`; the generation is one digest, `2 · species_size` compatibility calls and `O(pop_size)` selection/crossover/mutation.
Three host statics read once at trace time pick the formulation: `distance_centre` (`"tiled"` on a bare `State`, else `"single"`), `kernel_mode` (`"host"` on a bare `State`, else `"accelerator"`) and the genome's `distance_formulation` (`"merge"`/`"index_free"`); a GPU-class device gets `accelerator`/`tiled`/`index_free`, the numpy pipeline `host`/`single`/`merge` (`pipeline.host_payload._formulation_statics`).

## API Surface
`NEAT.__init__(genome, pop_size, species_size=10, max_stagnation=15, species_elitism=2, spawn_number_change_rate=0.5, genome_elitism=2, survival_threshold=0.1, min_species_size=1, compatibility_threshold=2.0, species_fitness_func=evoxc.max, species_number_calculate_by="rank", pop_batch_size=None)` is API-compatible with the pre-rewrite library and raises `TensorNEATError` from `_keys.validate_key_space(genome)` when `key_span <= max_nodes`, or when `pop_batch_size` does not divide `pop_size`.
`setup(state=None) -> State` requires `state.randkey`, registers `pop_size`, `pop` (`GenomeTensors`, axis 0 = individual), `generation` (0-d float32) and `species`, advances `randkey`, and runs one init graph (`split(randkey)` → `genome.initialize` → species seeding); it must be called outside any trace.
`ask(state)` costs zero ops and returns `state.pop`; `transform`/`forward` delegate to the genome; `tell(state, fitness) -> State` runs the algebra below; `prepare_forward(..., samples=1)`/`forward_prepared` split `forward` so a rollout pays the prelude once (`Pipeline` queries through that pair; `forward` has no in-tree call site); `show_details(state, fitness)` is the only host-side method.
`SpeciesController.__init__` validates host-side through `_validation.py`: `survival_threshold` in `(0, 1]`, `species_number_calculate_by` only `("rank", "fitness")`, `compatibility_threshold` finite and positive, `species_size * min_species_size <= pop_size`.
`SpeciesController.setup(state, first)` takes `first` as **one** `GenomeTensors` individual and makes slot 0 the single live species keyed `0` with `member_count[0] = pop_size`, centre `first`, `best_fitness = -inf`, `next_species_key = 1.0`; `update_species(state, fitness) -> (state, winner, loser, elite_mask)` owns the generation's first `evoxc.random.split`.
`speciate(state, distance_fn, pop=None)` accepts any `(state, centre_payload, pop) -> (P,)` callable and reads the population from `pop`, the `"pop"` entry or the four payload entries, raising otherwise; `_block_layout`/`_prefix_sum_exclusive` are test seams only (production calls the `_kernels` versions).
`DistanceRows(genome, digest, population, pop_size)` is built per generation inside `NEAT.tell` and validates both population axes; `__call__` takes a centre batch of `1` or `pop_size`, `row` is the single-row form and `matrix` the explicit `(K, P)` table form.
`SpeciesState` is a frozen dataclass under `state.species`: `(S,)` f32 `species_keys` (NaN = dead), `best_fitness`, `last_improved`, `member_count`, `(P,)` f32 `idx2species` (NaN = unassigned, only inside `speciate`), the four split centre arrays `(S, max_nodes[, NA])` / `(S, max_conns[, CK|CA])` and 0-d f32 `next_species_key`; all scalars are f32 so NaN encodes a dead slot and `generation` enters `last_improved` dtype-stable inside a scan carry.
File sizes: `neat.py` 1026 (the one documented ~1000-line exception; its cohesive split is the host diagnostics into a `_details.py`), `_kernels.py` 1000 and therefore at the limit, `species.py` 979, `_distance.py` 427, `_scan_accelerator.py` 416, `_keys.py` 325, `_validation.py` 165; a further addition to `_kernels.py` belongs in `_scan_accelerator.py` or `_distance.py`.

## Generation Algebra (`NEAT.tell`)
1. Sanitise fitness: NaN and both infinities become `-inf` (`abs(f) <= _finite_bound(dtype)` from `numpy.finfo(dtype).max`, plus `select`, so no invalid arithmetic and no `RuntimeWarning`), raising unless the shape is `(pop_size,)`.
2. `generation += 1` before the species update (legacy order), so stagnation is judged against the generation that produced the fitness being consumed.
3. `update_species` → species fitness, stagnation, descending sort, spawn allocation, parent pairs.
4. `_new_gene_keys(state, crossed.node_keys)` → `new_node_keys (P,)` and `new_conn_markers (P, 3)`.
5. Crossover: one `gather` per field for winner and loser, then batch-first `genome.execute_crossover(state, key, winners, losers)` (winner first).
6. Mutation: batch-first `genome.execute_mutation(state, key, crossed, new_node_keys, new_conn_markers)`, scan-chunked by `pop_batch_size`; the operator is genome-owned (`DefaultGenome` builds `DefaultMutation(0.1, 0.1, 0.4, 0.05)`, an explicit `DefaultMutation()` keeps 0.2/0.2).
7. Elitism: `select(elite_mask[:, None, …], crossover_children, mutated_children)` per field, one reshaped mask per field rank.
8. Speciation: one `genome.prepare_distance` digest, then `speciate(state, self._distance_rows(digest, population), population)`.
9. Commit `pop`, `randkey`, `generation`, `species`; exactly two `evoxc.random.split`s per generation feed parent selection, then crossover/mutation/the carried key.

## Species Algebra
Membership is one primitive, `M[i, p] = idx2species[p] == species_keys[i]` of shape `(S, P)`; NaN compares False, so dead slots and unassigned rows never match.
Species fitness is `select(M[i], fitness, -inf)` reduced by `species_fitness_func(..., axes=1)`, so a member-less slot stays `-inf`; stagnation is `(f_s <= best_fitness) & (generation - last_improved > max_stagnation)`, disabled for the top `species_elitism` ranked species, and a killed slot writes NaN into its float fields and `-inf` into its species fitness.
Sort is a stable ascending `argsort` plus the reversal permutation and one `gather` per field, so after the sort the slot index *is* the fitness rank.
Spawn in rank mode: `n = sum(valid)`, `rank_score = n - arange(S)`, `target = floor(rank_score / max((n+1)*n/2, 1) * pop_size)`; in fitness mode `f' = f_live - min_live(f_live) + 1`, `target = floor(f' / sum_live(f') * pop_size)`, a fresh slot's `-inf` best fitness `nan_to_num`-ed to weight `0`.
Both modes damp with `member_count + (target - member_count) * spawn_number_change_rate`, floor at `min_species_size`, zero the dead/NaN slots, cast to int32, then add the residual to the **first live slot** by one `scatter` so `sum(spawn) == pop_size` exactly.
Parent pairing takes `survive_size = clamp(floor(survival_threshold * member_count), 1, max(min(member_count, pop_size), 1))` (a NaN `member_count` reads as `0`), draws one `randint(key, (S, 2, P), 0, survive[:, None, None])` and decides the winner in species space (ties to the father, `>=`).
Elite slot `k` of a block (`idx_in_block == k < genome_elitism`) pins **both** parents to that block's own `k`-th ranked member (`min(arange(P), live_members - 1)` as the rank index), so the top `genome_elitism` members survive unmutated as *distinct* individuals; the champion is never cloned into every elite slot.
Block flattening: with exclusive prefix `E` of `spawn`, `loc(p)` is the **last** `i` with `E[i] <= p` and `idx_in_block(p) = p - E[loc(p)]`, one `gather` at `flat = loc * P + idx_in_block` into the row-major `(S, P)` pair arrays; no `spawn[i] > 0` term is needed because `spawn >= 0` makes `E` monotone and the total makes that index a live block.
Post-pass: leftovers with `isnan(idx2species)` adopt the last live species key (reachable only when the species cap is hit), created slots get `best_fitness = -inf` / `last_improved = generation`, and `member_count` is one masked compare-sum over `(S, P)`.

## Speciation Scans
`species.py::SpeciesController.speciate` is the host-facing wrapper (population resolution, `SpeciesState` rebuild) and delegates to `_kernels.speciate`, which selects the body set from `state.kernel_mode` at trace time (`common/schedule_accelerator.py::is_accelerator`).
`speciate(state, distance_fn, pop=None)` is two `evoxc.scan`s over `iota_i32(species_size)` with per-slot masks, so a fixed-length loop reproduces the legacy early-terminating `while_loop`: scan 1 (centre reservation) claims the nearest unassigned genome for each live slot and re-elects it as the centre, scan 2 (member assignment) assigns every genome within `compatibility_threshold` and materialises a created species on a dead slot while anything is still unassigned.
A slot writes only its own row and `arange(S)` visits each slot once, so a skipped iteration's record is the clamped `0` or the `I_INF` sentinel its mask discards, and the four centre tables are rebuilt once after each scan with `select(mask, gather(population.<field>, index_table, axis=0), scan_table)` instead of a row scatter per iteration.
`state.kernel_mode` picks one body set, so a graph contains one of them:
- host form (`_kernels.reserve`/`assign_members`): scan 1 carries `assign`, `dist`, `keys_ext (S+1,)` and two rank-1 per-slot tables, scan 2 carries `assign`, `dist`, `keys_ext` and two more — six per-slot scatters per iteration pair, write masks from `reduce_max(pending)`/`reduce_max(unassigned)`.
- accelerator form (`_scan_accelerator.reserve_step`/`assign_step`): scan 1 carries `(assign, dist)` plus the rank-0 int32 `remaining` counter on the gated path, scan 2 `(assign, dist, counter)` with `counter` the rank-0 float32 `next_species_key`; no per-slot table at all, because each step returns its record as the scan's stacked `y` (`closest`, then `seed`) and the created rows are rebuilt once after the scan from that `y` and the counter's final value.
It also drops the duplicated predicate reduction (`argmin_with_mask`/`fetch_first` already report "no candidate" through `I_INF`) and the index-tracking `argmin`/`argmax`: a minimising index is two plain `reduce_min`s, over the masked scores and then over the `pop_index` vector restricted to the attaining positions, which is argmin's own tie order.
Compile hazard, measured: a population-shaped `reduce_max(pop)` used as a scan `cond` predicate SIGSEGVs `iree-compile` on llvm-cpu (`GenericVectorization`); the rank-0 `remaining` counter is the working substitute, exact because scan 1 claims at most one row per iteration, so `pop_size - claims` *is* the unassigned count.
**Gate.** Below `GATED_ROWS = 6000` (`species_size * pop_size`) both scans keep the lazy per-slot row behind `evoxc.cond` (`_kernels.gated_row`, predicate `live & any_pending` for scan 1 and `live | create` for scan 2, false branch a discarded zero row): measured 2.3× faster at pop 100 and parity above ~pop 300, while an unconditional `cond` loses 26 % at pop 500.
Above the gate every slot is live, so scan 1's table is pre-measured by `distance_fn.matrix` and each iteration reads its own row with one `gather`; scan 2 measures its selected centre per iteration on both paths because a creating slot's centre is `pop[seed]`.
`gated_row` is the subtree's only nested control flow (`cond` inside a `scan` body): both branches are built statically, the predicate is a traced mask over statics, and the nested form is proven to compile on iree-llvm-cpu; `vmap` is never applied over control flow.
In the accelerator spelling the dense path reduces that pre-measured `(S, P)` block row-wise (`_block_min_index`: mask with the iteration's `pending`, `reduce_min(axes=1)` for the per-row minimum, the same index reduction along the same axis, one `gather` of its own row), turning two serialised one-workgroup `(P,)` reductions into two `S`-workgroup ones; the gated path has no table to close over and keeps `_row_min_index`.
Bit identity: each step's `y` is written once and a slot writes only its own row, so the stacked records rebuild the same write masks from the sentinel (`claimed = live & closest != I_INF`, `create = not live & seed != I_INF`); `reduce_min` plus a one-hot index equals `argmin`/`argmax` for finite candidates (which the compatibility kernel produces); created keys are `next_species_key + k` in slot order, exact in float32 below `2**24`.
Why scans at all: `evoxc` de-sugars `scan` to `while` + gather/scatter, so trip counts must be static to codegen and a data-dependent `while_loop` trip count does not run on iree CUDA/ROCm; the slot axis stays a scan because unrolling it triples the static graph and `iree-compile` build for no device-time win.

## Distance Rows
Both phases need one `(P,)` row per species slot and the population is measured `2 · species_size` times, so `NEAT.tell` digests it once (`genome.prepare_distance` sorts each gene family into a `DistanceDigest`, batch `P` on every population-indexed leaf) and `DistanceRows` turns centres into rows without re-sorting.
`_validation.distance_centre_mode(state)` resolves the centre width at trace time — absent means `"tiled"` (population-shaped), `"single"` is a leading axis of `1`, any other value raises — and `_kernels.centre_payload` spells it with one rank-raising `evoxc.broadcast` per field (tiled) or one `evoxc.reshape` (single).
`"single"` selects the genome's dense key-table single-centre route, which wins on the numpy interpreter and loses on a GPU, where its per-call scatters are lowered single-threaded; `"tiled"` selects the row-wise merge route.
`__call__` is the production route (`compute_row` in both gated scan bodies, `member_compute` in every dense scan-2 iteration) and is single-valued: batch `1` is tiled in `"tiled"` mode and measured as it stands in `"single"`, batch `pop_size` is measured row-wise in both, and a whole `(K, P)` table goes through `matrix` by name — the dense path's scan 1 is its only in-package caller, and the dense path requires a `distance_fn` with `matrix` (`TensorNEATError` naming it otherwise).
`matrix` measures its rows inside one fixed-length `evoxc.scan` on both spellings, so no `K * P` batch is ever formed and a region's environment is popped per iteration; it also wires the grouped leg.
Grouping needs `kernel_mode="accelerator"` **and** `distance_centre="tiled"`: `grouped.for_state(state, digest, species_size=K)` answers `k > 1` only for an accelerator state (capped at `ACCELERATOR_GROUP = 2`, at `GROUP_ROW_BUDGET // pop_size = 4096 // P` and at the slot count), and `matrix` takes the grouped branch only when the centre spelling is `"tiled"` too.
At `k = 2` one iteration gathers `k` centre rows, merges them with `grouped.centre_batch`, makes one `measure_distance` call against the `k`-times tiled digest and returns the flat `(k * P,)` step value (a `(k, P)` `y` would be a rank-3 write the exporter rejects); at most `K % k` trailing rows are then measured singly.
`k = 1` everywhere else, so the numpy pipeline traces exactly the ungrouped calls; and there the interpreter is charged by element volume, not dispatch, so the `k`-times wider `(k · P, 2 · max_conns)` intermediates cost more than the dispatches they save.

## StableHLO Export Rules (binding for every kernel here)
Every graph here must survive `evoxc`'s StableHLO v1 exporter, because `backend=` is forwarded verbatim and a rejected op is a hard `evoxc.BackendError`, never a fallback; `scatter` is allowed only as rank-1 `axis=0` or a rank-2 row/column write, and any wider operand raises `BackendError` naming the rank.
Neither speciation scan writes a gene table: the host spelling records per-slot values with plain rank-1 `evoxc.scatter`, the accelerator spelling with the scan's `y`-stack writes.
`_keys.first_free_keys` writes its occupancy cells with the rank-1 form on the flattened table, because a `(P, max_nodes)` index block against a rank-2 table is neither a rank-1 scatter nor a rank-2 row write.
No `tril`/`triu`/`flip`/`cumsum`/`iota`: static tables are baked with `static_i32`/`static_f32` (one `constant` op each), so the gate matrix of `prefix_sum_exclusive` is `static_f32(np.tril(np.ones((S, S)), -1))`.
`argmin`/`argmax` appear in the host spelling only; unsigned dtypes are outside iree's declared set, so a graph uses `int32`/`int64` only, and the numpy interpreter accepts every rank — a violation is invisible until `evoxc.lower(graph, backend="iree")`.
Verification is hand-run, never a committed test: classify every op with `evoxc.backends.stablehlo.ops.status(op.name)` (only `"deferred"` is a violation), check every `scatter`'s operand rank and `axis`, then `evoxc.lower(..., backend="iree")` plus both `iree-compile` stages.

## Gene Keys & Padding
`_keys.node_keys_for_split(node_keys, key_span, max_nodes, base)` allocates the structural node key as a **wrapped per-individual spread** `max_nodes + (base + 1 + slot) mod (key_span - max_nodes)`, with `base = genome.max_node_key(state, node_keys)`.
The window `[max_nodes, key_span)` is the part of the dense key table no payload row can occupy, since a row holds at most `max_nodes` keys; the wrap exists because the unbounded `max_node_key + 1 + slot` formula outruns `key_span`, and the schedule's dense key table silently drops an out-of-span key — the row stays in the payload, never reaches the phenotype, and no pipeline guard reports it.
The spread replaces a compact lowest-free policy, which measurably collapses speciation because the distance aligns node genes **by key** and charges non-homologous keys to the disjoint term.
The candidate is tested exactly like the genome's `plan_add_node` alias guard (`reduce_max(equal(node_keys, candidate))`), so an allocation is never a key the payload owns and never outside `[0, key_span)`.
`first_free_keys(node_keys, key_span)` is the fallback — the **lowest key in `[0, key_span)` the individual's own rows do not hold** — for the rows that already hold the spread candidate; it builds a `(P, key_span + 1)` occupancy table, redirects padded, negative and out-of-span keys to a permanently occupied dump cell, writes every real key with one rank-1 `scatter` and reads the answer with one `argmin`, run unconditionally because it is discarded on collision-free rows.
The composed allocator is 35 traced ops plus `genome.max_node_key` (7), with no region; availability is static, because `key_span > max_nodes` is enforced by `validate_key_space`.
The allocation comes from the **crossover child** (`crossed.node_keys`), the payload the mutation receives, because a base derived from the pre-crossover parents can already be owned by the child and the alias guard would then silently refuse the split; uniqueness holds within one individual's own keys only, so two individuals with the same occupied set get the same new key and the distance reads it as a homologue.
`new_conn_markers` continues from `state.pop.conn_keys` through `max_conn_marker` when `conn_gene.uses_historical_marker`, else zeros; a marker is an identity matched exactly by the distance kernel, never a table index, so it is not range tested.
Validity comes from the genome's `node_exists`, `conn_exists` and `max_conn_marker`, never from packaging.

## Measured Cost
`benchmarks/PERF_NUMPY.md` is the committed numpy protocol record; the per-generation numbers below were measured on this tree in this worktree (2026-11-06).
numpy backend, ms per generation: `xor_p100` 33.04, `xor_p500` 112.68, `xor_p1000` 177.43, `custom_pagie_p500` 847.13, `cartpole_p100` 248.70, with executed dispatches as in `## Intent`.
The numpy interpreter is charged ≈19–20 µs per dispatched op and by each op's element volume, so at these shapes **padded gene geometry and element volume are the levers, not dispatch count**; padded geometry at `P=1000` reads 506.0 ms at `max_nodes`/`max_conns` 50/100, 192.2 at 20/40 and 126.2 at 10/16, a workload change rather than a fix.
`"single"` versus `"tiled"` (centre-width A/B, pre-change tree, 6 interleaved fresh-process rounds): `"single"` reproduces that tree within noise (0.986×/0.999×/1.004× at `P=500`/`1000`/`100`), while `"tiled"` dispatches fewer ops and runs 1.39×/1.54× slower at `P=500`/`1000` at 218.7 against 196.4 MiB peak RSS — hence `"single"` on numpy.
The bounded key allocator costs +10 % / +4–8 % / +12–14 % at pop 100 / 500 / 1000, almost entirely the `(pop_size, key_span + 1)` free-key table built every generation although fewer than 6 % of rows ever need it.
iree+rocm on this tree (same session, one process per case): ms per generation `xor_p100` 17.42, `xor_p500` 13.24, `xor_p1000` 16.29, `custom_pagie_p500` 16.18, `cartpole_p100` 150.41, with a 7.2–8.0 s `iree-compile` build per static shape and ≈1.9 GiB peak RSS.
Cost laws on that leg: a generation costs `max(host submission, device)`; a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch; one `while` iteration costs ≈50 µs because the loop condition is read back to the host; `Tensor.to(cpu)` costs ≈47–60 µs per leaf regardless of size.
`breed` is genome-bound (the census attributed 67 % of its IR ops to `genome.execute_mutation`, 21 % to `execute_crossover`, 9 % to `update_species`); no committed artifact re-measures that census or the per-kernel tables on this tree — those live in `../../CONTEXT.md` `## Accelerator Status`.

## Search Quality (XOR3d / XOR, measured)
Config: `DefaultGenome(num_inputs=3 (XOR3d) / 2 (XOR), num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)`, `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, `backend="numpy"`, 150 generations; per-seed finals and the oracle comparison live in `../CONTEXT.md` (the authority).
The result this node must not lose: XOR3d pop 100 (seeds 0-19, shipped genome defaults) escapes **13/20** and targets **11/20** against the frozen oracle's 4/20 and 2/20 (Fisher two-sided p = 0.0095); XOR3d pop 500 / pop 1000 target 6/6 and 3/3.
Nothing here gates the pop-100 cell: species kill, spawn starvation, elite displacement, `max_in_degree = 4` (refusing 0.00-0.04 of fired add-conn gates), `max_depth = 16` against an observed maximum node level of 6-9, and an unsaturated output row are all measured non-binding.
The lever is genome-side and shipped: `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=0.4, conn_delete=0.05)` (an explicit `DefaultMutation()` keeps 0.2/0.2), because at equal gates an add-conn is accepted about half as often as a delete-conn and an equal-gate operator's steady state stays under-wired; the density record is in `../CONTEXT.md`.

## Known Issues
Both host statics are part of the executable-cache signature (`host_payload._formulation_signature`), so switching either forces exactly one rebuild.
What is left is genome-owned: the pair count `2 · species_size · pop_size` is irreducible (a created species takes the first unassigned genome as its centre, so its row depends on every earlier assignment), the padded gene geometry is a workload choice, and the merge's homologue sort — `2·M` key rows re-sorted once per centre — is what the dense single-centre route removes.
The allocator's census (XOR3d, `key_span=150`, seed 42, five `step`s at pop 100 and 500) reads 0 out-of-span node keys, 0 out-of-span connection endpoints and 0 duplicate node keys after every generation, and the fallback serves under 6 % of the population.
`show_details` caches one counting executable per payload shape, reads every tensor through `to_numpy`, and a failure from it is recorded once per hook label in `Pipeline.detail_failures` instead of being swallowed or aborting the run; `next_species_key` must stay strictly greater than every live key (`setup` seeds it at `1.0`, slot 0 uses `0.0`), since a colliding counter silently merges two species' `member_count`.
Crossover is live only for species with more than `1 / survival_threshold` members (200 at the example `0.01`): below that the survivor prefix is a single genome and every non-elite child is a mutated copy of it.
`Pipeline.setup` registers the centre spelling from the device kind — `"single"` on numpy, `"tiled"` on a GPU-class device — and the two agree bit for bit because the compatibility kernel is row-independent.

## Constraints
No `jax`/`torch`/`numpy.random` import, since `import tensorneat` must stay free of them (release gate); `numpy` appears only as `numpy.finfo(dtype).max` in `_finite_bound`, a host-side scalar read.
No branching, `bool()`, `len()` or host reads on traced values; static Python `if`/`for` over constructor configuration is fine and unrolls at trace time.
No `.at[]`, no `cumsum` on the compute path (prefix sums are triangular `dot`), no `tril`/`triu`/`flip`/`iota`, no rank ≥ 3 `scatter`, no `where=`/`initial=`/`any`/`all`/`take`/`searchsorted`/`repeat`, no `vmap` over anything region-bearing, no `fori_loop`/`switch`.
Shapes are static (`P`, `S`, `max_nodes`, `max_conns`), so a shape change forces a rebuild; configuration validation raises `common.errors.TensorNEATError` with a named message while trace/shape/backend errors propagate unchanged and are never re-wrapped or silently fallen back.
State keys touched: `randkey`, `pop_size`, `pop`, `generation`, `species` and the host-only `distance_centre`/`kernel_mode` statics, plus the genome/problem keys documented above.
evoxc hazards that shape this code: `random.randint` needs a symbolic `high` that stays ≥ 1 (`max(survive_size, 1)`), `scatter` is replacement-only (every "accumulate" update is restructured as reduce-then-scatter-once), and seeding a `while`-carried value with a `scatter` SIGSEGVs `iree-compile` while exporting cleanly — the host spelling's five `while`-carried per-slot tables are not that case and compile on both targets.
A batch-`1` centre selects the genome's dense single-centre route, whose per-call scatters a GPU executes single-threaded, so `state.distance_centre` stays `"tiled"` on a GPU-class device.

## Test Strategy
Tests live in the sibling `test/` tree (read-only from here): `test/unit/algorithm/` covers the spawn/selection/stagnation algebra, the block layout (against the documented "last qualifying block" oracle, with the count form pinned as a regression) and the speciation scans; `test/parity/algorithm/neat/` compares against `benchmarks/legacy_jax`; `test/integration/` evolves XOR to its target with a fixed seed and asserts run-to-run determinism.
Every kernel here must be a pure function of `(state, key)`: no dict-order dependence, no host RNG, no float→int conversion without an explicit mask; the sparse/dense switch and the `cond` placement are static trace-time choices, so a gate regression shows up as a build error rather than as silent numerical drift.
The allocator is verified twice: `node_keys_for_split` against a host oracle of the same formula on every population the run produces, and end-to-end by the census above.
Whole-run bit-identity is the acceptance test for both spellings and both centre widths: 10 seed-42 generations at `P=100` (gated), `P=500` and `P=1000` (dense), 21 arrays per generation compared with `array_equal(equal_nan=True)` plus dtype and shape; the call width is observable at trace time by counting `distance.base.BaseDistance.measure` invocations and each centre's batch (one row per call on the host leg, `k` on the grouped accelerator leg).
No test in the sibling `test/` tree selects `kernel_mode`, so the `"accelerator"` leg is a hand-run verification: this node cannot regress-detect it on its own, and a committed `test/backends` cell that builds a gated pop-100 graph in accelerator mode is the missing guard.
