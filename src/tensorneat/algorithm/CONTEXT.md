# Algorithm (`tensorneat.algorithm`)

## Intent
The evolutionary layer: it owns the population, the ask → transform → forward → tell generation cycle, speciation, parent selection, the crossover/mutation dispatch, and the HyperNEAT CPPN → substrate decode.
Everything here runs **inside an evoxc trace** — `pipeline.py` builds one graph per shape signature covering a whole generation — except the explicitly host-side helpers (`__init__`/`_validate` configuration checks, `setup`, `show_details`, substrate construction).
This layer owns no network mathematics: genomes own `transform/forward/grad/distance`, problems own `evaluate`, and the algorithm only shuffles whole populations at static shapes.
`__init__.py` is the package surface: it re-exports `BaseAlgorithm`, `NEAT`, `HyperNEAT` and `HyperNEATFeedForward` and `__all__` lists exactly those four names.
`NEAT(genome, pop_size, species_size=10, max_stagnation=15, species_elitism=2, spawn_number_change_rate=0.5, genome_elitism=2, survival_threshold=0.1, min_species_size=1, compatibility_threshold=2.0, species_fitness_func=evoxc.max, species_number_calculate_by="rank", pop_batch_size=None)` validates host-side only: `neat/_validation.py` (`positive_int`/`non_negative_int`/`unit_interval`/`positive_float`), `neat/_keys.py::validate_key_space` (`key_span > max_nodes`), the `pop_batch_size` divides-`pop_size` check and `SpeciesController.__init__` (`survival_threshold` in `(0, 1]`, `species_number_calculate_by` in `("rank", "fitness")` — there is no `"linear"` mode).
`NEAT` accepts **no** mutation-rate parameter; its genetic knobs are `survival_threshold`, `genome_elitism`, `min_species_size` and `spawn_number_change_rate`, and every structural/value probability belongs to the genome's `mutation` and gene objects.
`Pipeline`'s compiled cycle drives `ask → transform →` the `prepare_forward`/`forward_prepared` pair `→ tell`; `ask` runs inside the generation graph on the registered payload and every shipped `ask` returns `state.pop` unchanged, so it costs zero ops; `algorithm.forward` exists on the contract but has no in-tree call site.
Cost profile: one population digest plus `2 · species_size` compatibility rows in `speciate` — scan 1's whole table measured up front on the dense path inside one fixed-length `evoxc.scan` (`k = 2` centre rows per call on the accelerator leg), scan 2's measured in-loop — and `O(pop_size)` selection/crossover/mutation; no `max_nodes × max_nodes` tensor ever appears here.
`speciate` is the top term above pop 300 and it is per-pair bound: the pair count `2 · species_size · pop_size` is irreducible and one pair costs the genome's homologue resolution, so grouping centre rows halves dispatches on a launch-bound backend and never the pairs.

## Kernel Contract (binding for this subtree)
Batch-first: population is axis 0, always; a kernel is written once over the whole batch.
`vmap` is never used — evoxc refuses to vectorize region-bearing control flow — so the batch axis is spelled out explicitly.
Control flow (`evoxc.scan` / `evoxc.while_loop` / `evoxc.cond`) runs over static axes only: every loop has a static trip count and a branch set built at trace time.
An `evoxc.cond` may nest inside an `evoxc.scan` body when (a) its predicate is a traced mask over branches that are both built statically — a static Python decision lowered to a traced `cond`, never host control flow on a traced value, (b) the nested form has been proven to compile on `iree`-llvm-cpu, and (c) the numpy backend stays the reference.
The shipped instance is `_kernels.speciate`'s gated path: `gated_row` builds one `cond` per scan iteration inside both spellings' step bodies and both phases whenever `gated(species_size, pop_size)` holds (`species_size * pop_size <= GATED_ROWS = 6 000`).
Species loops are fixed-length `evoxc.scan`s over the static `species_size` axis with per-slot masks; no loop trip count is data-dependent.
`pop_batch_size` memory batching is an `evoxc.scan` over the batch axis of the mutation kernel only.
evoxc has no `.at[]`, no in-place mutation and no `cumsum`/`max(where=…)`/`sum(where=…)`/`any`/`all`/`take`/`searchsorted`/`repeat`: mask with `evoxc.select` before reducing, prefix-sum with `dot` against a static triangular ones matrix, and move data with flattened `evoxc.gather` / `evoxc.scatter`.
`evoxc.scatter` is replacement-only — an accumulating update is recomputed as "reduce first, scatter once".

## Device & Backend Placement
`NEAT._build_options(state)` is this subtree's only reader of `backend`/`device`/`compile_options`: it returns `{"backend": state.backend}` when registered (else `"numpy"`), adds `device` only when registered and not `None`, then expands `compile_options` last, so a `compile_options["device"]` entry would override the registered device.
`NEAT.setup` is the subtree's only setup-time `evoxc.build`/`evoxc.run`: a plain closure `_init_kernel` (no `@evoxc.defn` anywhere in this subtree) is built with `TensorSpec((), evoxc.int64)` and `**options`, then run on `state.randkey`.
`Pipeline.setup` registers `device=None` while `algorithm.setup`/`problem.setup` run, so that initialisation graph is built and run on CPU; the pipeline places the runtime tensors on the requested device afterwards (`Pipeline._place_state`) and does not call back into this subtree for it.
The initial payload is traced random output, never host data: `evoxc.random.split` → `genome.initialize` → `enp.full` → one `gather` for the first centre, with `SpeciesController.setup` filling the centre table from `enp` constants; the only host-numpy constants are `_kernels`' `const`/`int_const` scalar spellings, traced inside generation kernels.
`evoxc.run` performs no implicit device movement, so both run boundaries here rely on their caller: `state.randkey` in `setup` (cpu:0 by construction) and the `state.pop` leaves in `_gene_counts` must already live on `executable.device`.
`show_details` is the only host-materialising surface (`to_numpy`); the pipeline calls the hook with its `device=None` host view, so the counting graph is built on CPU, and its cache key is shape, dtype **and** resolved backend/device, so a device change can never reuse an executable loaded for another device.
Inside traced kernels every `.shape`/`.dtype`/`int(size)` read is static metadata; no `.to(...)`, `.numpy()` or host control flow on a traced value exists in this subtree.

## Formulation Statics (device-derived, graph-visible configuration)
`Pipeline.setup` derives three trace-time statics from the resolved device kind through `host_payload._formulation_statics` and registers them on the state as plain strings: `distance_centre` (`"tiled"` | `"single"`), `distance_formulation` (`"merge"` | `"index_free"`) and `kernel_mode` (`"host"` | `"accelerator"`).
A GPU-class kind (`rocm`, `hip`, `hips`, `cuda`, `vulkan`, `gpu`, compared case-insensitively) gets `("tiled", "index_free", "accelerator")`; every other kind and `None` gets `("single", "merge", "host")` — the numpy leg, value-identical and op-identical to the state that carried no statics.
They are never graph-boundary tensors: `Pipeline._static_config` drops the `_RUNTIME_KEYS` names (`pop`, `generation`, `species`, `randkey`) and every remaining `evoxc.Tensor`, so the three strings are captured by the generation kernel's closure.
The setup-time initialisation graph gets the same treatment through `NEAT._static_state`, which drops every `evoxc.Tensor` and forces `pop_size` into a tensor-free copy of the state — there is no separate `NEAT._static_config`.
Both statics passes are read off the **state**, which is why updating any of the three entries forces exactly one rebuild and leaves the other signature entries untouched.
They are part of `Pipeline._shape_signature` (`host_payload._formulation_signature`, defaulted to `"tiled"`/`"merge"`/`"host"` for a state no `setup` produced) next to the payload geometry, the substrate statics and the tiled-evaluate chunk budget, and `show_config()["pipeline"]` renders all three.
A missing entry is never an error: the kernels default to `"tiled"`/`"merge"`/`"host"` (`_validation.distance_centre_mode`, `common.schedule_accelerator.kernel_mode`, `genome/operations/distance/index_free.formulation_mode`), which is what a bare `State()` and every committed test get.
`distance_centre` selects the width of every speciation centre payload (`_distance.py`, `_kernels.py`); `kernel_mode` selects the speciation body set (`_kernels.speciate` → `_scan_accelerator`), the distance grouping (`grouped.group_size`) and the schedule's scatter-free formulation (`common/schedule_accelerator.py`); `distance_formulation` selects the genome's homologue resolution (the index-free equality table instead of the merge sort) and is read inside `genome/operations/distance`, not here.
Every accelerator formulation is bit-identical to the host route, generation for generation, and no committed test selects the statics — this subtree's own bit-identity evidence is a hand run.

## BaseAlgorithm Protocol (`base.py`)
`setup(self, state=None) -> State` registers the algorithm's tensors; `None` builds `State()` in the body because a `State()` default argument would be evaluated at import time and break `import tensorneat`.
`setup` runs after the genome's and the problem's `setup` on the same threaded `State`, and it is host-side: `NEAT.setup` builds and runs one `genome.initialize` graph, so it must never be called from inside an active trace.
`ask(state) -> pop` hands out the population to evaluate; for NEAT `pop` is the `genome.utils.GenomeTensors` payload (`node_keys (P, max_nodes)`, `node_attrs (P, max_nodes, NA)`, `conn_keys (P, max_conns, CK)`, `conn_attrs (P, max_conns, CA)`) and it costs zero ops.
`transform(state, pop) -> Transformed` decodes the **whole** population into one batch-first execution schedule (axis 0 = individual); the Pipeline never maps it per genome.
`forward(state, transformed, inputs) -> outputs` runs the decoded batch with `inputs (P, *input_shape)` and returns `(P, *output_shape)`.
`prepare_forward(state, transformed, pop=None, samples=1) -> prepared` derives one forward pass's loop-invariant operands and `forward_prepared(state, transformed, prepared, inputs) -> outputs` runs one query from them; `forward` is exactly the two of them back to back, bit for bit.
That pair's signature is **uniform** across algorithms (`pop=None`, `samples=1`, `samples` the static tiling factor of the `P * samples` queried rows), so the pipeline needs no arity adapter for it, unlike `forward`.
`NEAT.prepare_forward` takes the payload (`None` means `state.pop`) and forwards `samples` to `genome.prepare_pass`.
`HyperNEAT.prepare_forward` ignores `pop` — its payload is the substrate schedule inside `transformed` — and forwards `samples` to `hyper_genome.prepare_pass`, because the substrate schedule sits at `P` rows and a tiled query is the substrate genome's own sample axis; the CPPN query expansion happens once inside `HyperNEAT.transform`.
`host_payload._NetworkActFn` is the only consumer of the pair, and the problem layer queries through `act_fn.prepare(batch_rows)`: an RL rollout asks once per generation (`problem/rl/_common.py`) and the tiled func-fit evaluate once per chunk group (`host_payload._prepared_query`), so the prelude is paid once per batch shape instead of once per query.
`tell(state, fitness) -> State` consumes a `(P,)` fitness array (fitness is maximised) and returns the next-generation state.
`show_details(state, fitness) -> None` is the only other host-side method: it converts with `common.tools.to_numpy` and prints (evoxc has no `io_callback`, and `runtime_call` exists on the numpy backend only).
`num_inputs`, `num_outputs`, `pop_size` are static Python ints; `Pipeline` asserts the first two against `problem.input_shape[-1]` / `output_shape[-1]`.
`NEAT.transform`/`NEAT.forward` take an optional trailing `pop=` so a caller can forward a payload other than the one in `state`; `HyperNEAT` uses that for its `(P·Q)` CPPN query batch.

## State Layout
The algorithm registers exactly four keys on the shared `State`: `pop_size` (static Python int, so the batch-first `genome.initialize` can size axis 0), `pop` (one `genome.utils.GenomeTensors` payload, axis 0 = individual), `generation` (0-d float32 — kept float so it flows through `last_improved`) and `species`.
`randkey` is never registered here: `setup` only advances it, so `Pipeline.setup` must create it first with `evoxc.random.key(seed)` (`TensorNEATError` otherwise); a `(seed, config, shape)` triple then reproduces a run bit-for-bit.
`species` is a frozen dataclass `SpeciesState` (owned by `./neat`) with ten fields: `(species_size,)` float32 `species_keys`, `best_fitness`, `last_improved`, `member_count` (NaN = dead slot), `(pop_size,)` float32 `idx2species`, the four split payload arrays `center_node_keys (S, max_nodes) int`, `center_node_attrs (S, max_nodes, NA) float`, `center_conn_keys (S, max_conns, CK) int`, `center_conn_attrs (S, max_conns, CA) float`, and 0-d float32 `next_species_key`.
Dead species slots are addressed solely by the `isnan(species_keys)` mask; the centre gene rows of a dead slot hold stale integers that are never read, because the integer gene payload cannot carry NaN.
`generation` is incremented at the *start* of `tell`, so stagnation is evaluated against the generation that produced the fitness being consumed.

## NEAT Generation Algebra (`tell`)
1. Sanitize fitness: NaN and ±inf → `-inf`, so a broken topology can never win selection (`finite = abs(f) <= finfo(dtype).max`, no invalid arithmetic, hence no `RuntimeWarning`).
2. Species fitness = per-species maximum of member fitness, a masked reduce over the `(species_size, pop_size)` membership comparison `idx2species[None, :] == species_keys[:, None]`.
3. Stagnation: `stagnant = (f_species <= best_fitness) & (generation - last_improved > max_stagnation)`, disabled for the top `species_elitism` ranked species; a killed species is written to NaN / `-inf`.
4. Species sort by species fitness descending, applied to every `(species_size, …)` field with one gather over a permutation.
5. Spawn allocation: linear-rank (`"rank"`) or fitness-proportional (`"fitness"`), damped by `spawn_number_change_rate`, floored at `min_species_size`, integerised, then error-corrected so `sum(spawn) == pop_size` exactly — the residual is added to the **first live slot** by one `scatter`.
6. Parent selection per species: members sorted by fitness descending, survivors = `clamp(floor(survival_threshold * members), 1, min(members, pop_size))`, two parents drawn uniformly from the survivor prefix, elite slot `k` (`idx_in_block == k < genome_elitism`) pinned to its species' `k`-th ranked member clamped at `live_members - 1` — so the top `genome_elitism` **distinct** members survive unmutated — winner on ties (`fitness[first] >= fitness[second]`).
7. Block flattening: population slot `p` maps to species `loc(p)` = the **last** slot with `spawn[i] > 0 and exclusive_prefix[i] <= p`, with `idx_in_block(p) = p - exclusive_prefix[loc(p)]`, using a triangular-matmul prefix sum plus gather — never a host loop over species.
8. Winner/loser decided by fitness comparison; `genome.execute_crossover` then runs batch-first over the `(P, …)` pair, winner payload first.
9. Mutation takes `new_node_keys (P,)` from `_keys.node_keys_for_split`: the wrapped per-individual spread `max_nodes + (max_node_key + (1 + slot)) mod (key_span - max_nodes)`, replaced by the lowest free key in `[0, key_span)` on the rows where that candidate is already held — an allocated key is always inside the schedule's dense key table and never a key the individual owns.
   `new_conn_markers (P, 3)` keeps the monotone rule (zeros when the conn gene carries no `historical_marker`) and is bounded by nothing, because a marker is an exactly-matched identity and never a table index.
   The mutation runs batch-first, scan-chunked by `pop_batch_size`, with the allocation taken from the **crossover child** (`crossed.node_keys`) rather than the pre-crossover parents; see `./neat/CONTEXT.md` `## Gene Keys & Padding`.
10. Elite slots keep the unmutated crossover children.
11. Speciation: one `genome.prepare_distance(state, pop)` digest for the new population, then `speciate` rebuilds membership through `_distance.DistanceRows`; on the dense path scan 1's whole centre table is measured before the scan (`DistanceRows.matrix`, one centre per `measure_distance` call on the host leg and `k = 2` on the accelerator leg) and each iteration reads its row with `gather`, while scan 2 measures its selected centre per iteration.

## Speciation Without vmap-over-Control-Flow (`./neat/_kernels.py`, `./neat/_scan_accelerator.py`, wrapped by `./neat/species.py`)
`species.py::SpeciesController.speciate` is the host-facing wrapper (docstring, `pop` resolution, `SpeciesState` rebuild) and delegates to `_kernels.speciate`, which selects the body set from `state.kernel_mode` at trace time.
`speciate(state, distance_fn, pop=None)` is two `evoxc.scan`s over `evoxc.numpy.arange(species_size)` with per-slot masks, so a fixed-length loop reproduces the legacy early-terminating `while_loop`.
Neither scan carries a centre gene table: a slot writes only its own row and `arange(S)` visits each slot once, so the four tables are rebuilt once after each scan from a recorded `(source row, did-write)` pair (four `gather` + four `select`), and a non-writing slot's record is the clamped `0` or the `I_INF` sentinel its mask discards.
`idx2species`/`o2c` are the legacy names of the carried `assign`/`dist`; the carries are spelling-dependent, and the accelerator form carries no per-slot table at all — each step returns its record as the scan's stacked `y`, so the created rows are rebuilt once after the scan.
- host form: scan 1 carries `assign`, `dist`, `keys_ext (S+1,)`, `closest_table (S,)` and `claim_table (S,)`; scan 2 carries `assign`, `dist`, `keys_ext`, `seed_table (S,)` and `created_mask (S,)`.
- accelerator form: scan 1 carries `(assign, dist)` plus, on the gated path, the rank-0 int32 `remaining` counter (seeded at `pop_size`, decremented by `claim`) that replaces the host body's population-shaped `reduce_max(pending)` `cond` predicate; scan 2 carries `(assign, dist, counter)`, `counter` the rank-0 `next_species_key` advanced by one `select` per created slot.
- phase 1 (centre reservation): for each live slot `i`, take `d_i (P,)` (dense: `gather(rows1, i, axis=0)`; gated: one population-shaped call behind a per-iteration `cond`), then `closest` — the lowest index attaining the minimum of `select(unassigned, d_i, +inf)`, by `argmin_with_mask` on the host form and two plain `reduce_min`s on the accelerator form, `I_INF` when nothing is left to claim — assign `idx2species[closest] = species_keys[i]`, write `pop[closest]` as the new centre and set `o2c[closest] = 0`.
- phase 2 (member assignment): a live slot assigns every genome with `d < compatibility_threshold` and `unassigned or d < o2c`; a dead slot creates a species keyed `next_species_key` seeded by `seed = reduce_min(select(isnan(assign), pop_index, I_INF))` (`fetch_first` on the host form), then assigns the same way.
- both phases are guarded: an iteration with no unassigned genome, or with a dead slot in phase 1, performs no writes, so a fixed-length scan is equivalent to the legacy early-terminating `while_loop`.
- post-pass: still-unassigned genomes join the last species key, newly created slots get `best_fitness = -inf` / `last_improved = generation`, and `member_count` is a masked compare-sum `(species_size, pop_size)` reduce.
The rows come from `_distance.DistanceRows`, a per-generation digest-backed `distance_fn`: phase 1's centre for slot `i` is the pre-scan row `i`, while phase 2's live-slot centres are the post-scan-1 rows and a *creating* slot's centre is `pop[seed]`, a function of the earlier slots' distance rows — which is why scan 2 cannot be grouped and only scan 1's table does (`DistanceRows.matrix`, `k = 2` on the accelerator leg, one centre per call on the host leg).
Below `GATED_ROWS = 6000` (`species_size * pop_size`) both scans keep the lazy per-slot rows behind `evoxc.cond`, which is measurably cheaper there because most slots are dead; above the gate scan 1's pre-measured table wins because every slot is live and the table's own `evoxc.scan` keeps the compatibility kernel out of the reservation body at the cost of one centre's transients.
Compile hazard, measured: a population-shaped `reduce_max(pop)` used as a scan's `cond` predicate SIGSEGVs `iree-compile` on llvm-cpu (`GenericVectorization`); the rank-0 carried counter is the working substitute, and it is exact because scan 1 claims at most one row per iteration, so `pop_size - claims` *is* the unassigned count.
Unrolling the `species_size` slot axis into straight-line SSA was built and rejected: it removes 137 generation kernels for 0.6–2 ms of device time, but triples the static graph and `iree-compile` time and adds a one-off build worth ≈1 450 generations; `./neat/CONTEXT.md` `### The slot axis is not unrolled` holds the record, and the gated path is excluded twice over because twenty top-level `cond`s fuse into a dispatch whose 26 operands exceed the ROCm/HIP HAL's 16-binding cap.
Rationale for scans instead of the legacy data-dependent `while_loop`: evoxc de-sugars `scan` to `while` + gather/scatter, so trip counts must stay static to codegen on compiler backends, and iree aborts on wide `while` carries.

## Randomness Budget
Per generation the algorithm performs exactly two `evoxc.random.split`s, yielding three subkeys consumed in this order: parent selection, crossover, mutation — the advanced parent key is stored back into `state.randkey`.
Speciation (the digest, the matrix, the scans) draws no randomness, so batching the distance rows cannot move an RNG stream.
When `pop_batch_size` chunks a population kernel into a `scan`, the algorithm pre-splits `n_batches` keys with `evoxc.random.split_n` and passes the stacked `(n_batches,)` int64 array as the scan's `xs`, so each step receives a valid rank-0 key and draws its own population-shaped randomness inside the body.
Key-form is whatever `splitmix64` produces (rank-0 int64); nothing here assumes a JAX `PRNGKey`.
There is no `random.choice` and no probability vector: uniform parent rank slots come from `evoxc.random.randint` with a broadcast symbolic `high`, which is also the fix for the legacy zero-survivor division.

## Deliberate Divergences From the Legacy Oracle
1. `survive_size == 0` (a 1-member species) produced NaN probabilities and killed `random.choice`; `high = max(survive_size, 1)` yields two identical parents, and self-crossover is the identity.
2. `species_number_calculate_by="fitness"` poisoned `min`/`sum` with the NaN `best_fitness` of dead slots; every reduction masks dead slots first.
3. `HyperNEATNode` disagreed with the node-gene protocol (missing `valid_mask`, `aggregation` called with one argument, no declared option columns); it declares the two `int` option columns and an identity `combine`, so it runs through `BaseNode.forward` unchanged. See `./hyperneat`.
4. `spawn_number` relied on NaN → int32 cast semantics; dead slots are explicitly zeroed before the cast.
5. `HyperNEAT.__init__` validates `weight_threshold ∈ [0, 1)`, `max_weight > 0`, `activate_time >= 1`, the substrate's node-key block order and the CPPN arity, raising `TensorNEATError` instead of dividing by zero or broadcasting wrongly.
6. Sort tie-order stays bit-compatible with legacy by using a *stable ascending* `argsort` followed by an index reversal gather (evoxc `argsort(descending=True)` breaks ties the other way).
7. The spawn residual lands on the first **live** slot instead of literally slot `0`: identical after the descending species sort, but a hand-built unsorted table can no longer hand population slots to a dead species.
8. Random streams differ from the baseline by construction: one key per population kernel (drawing `(P, …)` randomness inside) instead of one key per genome, so parity compares kernels on fixed inputs, never RNG bit-patterns.

## Search Quality (numpy backend, measured)
The quality contract is `benchmarks/cases.py`: `DefaultGenome(num_inputs=3|2, num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)`, `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, `XOR3d()` / `XOR()`, 150 generations, no early stop, fitness = −mse.
"Escape" is some generation's best above −0.24, i.e. off the −0.25 constant-0.5 optimum of a sigmoid read-out for these non-linearly-separable tasks; "target" is some generation's best at or above −0.05.
The post-fix record is `benchmarks/results/xor3d_quality_2026-11-04.md`; the seeds 0-19 XOR3d sweep is recorded in `benchmarks/CONTEXT.md`.
XOR3d pop 100 (seeds 0-19) escapes on **13/20** and reaches the target on **11/20**, median escape generation 75; the frozen oracle on the same seeds escapes 4/20 and reaches the target 2/20 (Fisher exact two-sided p = 0.0095).
XOR3d pop 500 seeds 42-47 escapes 6/6 and reaches the target 6/6 with finals `-3.89e-15 / -1.22e-04 / -1.08e-11 / -2.48e-18 / -3.63e-37 / -4.14e-04`; pop 1000 seeds 42/43/44 reaches the target 3/3 with finals `-1.03e-10 / -4.44e-11 / -1.83e-24`.
XOR pop 100 seed 42 reaches its −0.1 target at generation 41 (final −1.64e-05) and XOR pop 500 seed 42 at generation 33 (final 0.0).
The lever for the pop-100 cell is genome-side and shipped: `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=0.4, conn_delete=0.05)` when no operator is passed (`genome/operations/mutation/default.py::DEFAULT_GENOME_CONN_ADD`/`DEFAULT_GENOME_CONN_DELETE`), while an explicit `DefaultMutation()` keeps NEAT-python's 0.2/0.2.
Mechanism: at equal connection gates an add-conn is accepted about half as often as a delete-conn (duplicate, self-connection, cycle and `max_in_degree` refusals), so an equal-gate operator's structural steady state is −0.14…−0.22 connections per individual per generation and such populations stay under-wired (5.93 connections / 4.34 hidden nodes at generation 150 against the oracle's 10.09 / 7.31); the escape hazard tracks the number of *structured* individuals.
The shipped 0.4/0.05 moves that steady state to +0.15 and lifts generation-150 density to 10.38 connections, output in-degree 2.59 and the multi-input-ancestor fraction to 0.82 (control 0.417) at an unchanged node count (8.19 vs 8.36): it buys wiring, not more nodes.
Rejected in the same sweep (XOR3d pop 100, seeds 0-19): a same-generation add-conn value-mutation exemption (4/20 escape, 0/20 target, Fisher p = 1.0), a milder 0.3/0.1 rebalance (7/20), that exemption stacked on the rebalance (7/20), `survival_threshold` 0.1/0.5, and a `min(2, members)` survivor floor; `../genome/CONTEXT.md` `## Rejected` and `../genome/operations/mutation/CONTEXT.md` hold the records.
Structural keys are bounded by construction: over 150-generation runs at pop 100, 500 and 1000 there are **0** node keys and **0** connection endpoints outside `[0, key_span)`, and the largest live key is `key_span - 1`.
The compatibility distance is not the gate: a fresh random population already spans 0.22–2.05 (median 0.93) against `compatibility_threshold = 2.0`, the same distribution as the frozen tree (median 0.90).
Evaluation is not implicated: hand-built payloads score bit-identically through `Pipeline.step` and a host numpy oracle, and all three input channels measurably move the output.

## Dependencies (cross-node contracts this subtree relies on)
`genome`: batch-first kernels `setup(state)`, `initialize(state, key, pop_size) -> GenomeTensors`, `transform(state, node_keys, conn_keys)`, `forward(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, inputs (P, …))`, `prepare_pass`/`forward_prepared`, `execute_crossover(state, key, winners, losers)` (winner payload first), `execute_mutation(state, key, payload, new_node_keys (P,), new_conn_markers (P, 3))`.
`genome` distance, two-phase: `prepare_distance(state, pop) -> DistanceDigest` (once per generation; an 8-leaf batch-first pytree that survives `State.register`) and `measure_distance(state, centre, digest) -> (P,)`, where `centre` may be batch-1 (the genome's dense single-centre route under `distance_centre="single"`, tiled to `pop_size` rows under `"tiled"`) or batch-`P` (row-wise) — any other centre batch is rejected; a `k · P` batch is accepted only against a `group_digest`-tiled digest, which `_distance.DistanceRows.matrix` builds through `grouped.for_state` on the accelerator leg and nothing else in this node does.
`genome.execute_distance` is still the documented single-pair contract but is no longer called from here.
`genome.utils.GenomeTensors` is the four-field payload namedtuple in declaration order `(node_keys, node_attrs, conn_keys, conn_attrs)`; `HyperNEAT` relies on that order for its `*payload` unpacking.
`genome` RNG: every kernel takes **one** `evoxc.random` key and draws population-shaped randomness inside (`random.uniform(key, (P, n_attrs))`), because an evoxc key is rank-0/2/4 and cannot be indexed dynamically.
`genome`: static attributes `num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `key_span`, `node_gene.length`, `conn_gene.length`, `conn_gene.uses_historical_marker`, plus key/validity helpers `node_exists(node_keys)`, `conn_exists(conn_keys)`, `max_node_key(state, pop_nodes)` and `max_conn_marker(state, pop_conns)` (one maximum **per individual**, `(P,) int32`) — the algorithm never inspects the padding encoding directly.
`genome`: `NEAT.genome` is read directly by `HyperNEAT._query_substrate`, which calls `genome.forward` on an expanded `(P·Q)` batch; `genome.forward` must therefore not assert `batch == pop_size`, and the decode takes `P` from the payload's own axis 0 so a one-individual `Pipeline.show` decode works.
`genome/gene`: `./hyperneat` synthesises the fixed substrate payload itself from the gene specs (`node_gene.key_width`/`attr_specs`, `conn_gene` spec); `conn_gene.forward` receives a `ConnOperands` bundle and genes read columns through `column_of(operands, name)`.
Gene payload encoding is genome-owned and opaque here — evoxc has **no bitcast/reinterpret op**, so how a float gene attribute travels inside an integer slot cannot be decided in this subtree.
`common`: `State` (immutable, evoxc-flattenable), `errors.TensorNEATError`/`ConfigError`, `StatefulBaseClass` (extended by `SpeciesController`), `functions.{ACT, AGG, apply_activation, apply_aggregation}` (`AGG` members take `(z, mask)`), `schedule_accelerator.{kernel_mode, is_accelerator}`, `tools.{rank_elements, fetch_first, argmin_with_mask, flat_gather, to_numpy}` in evoxc form.
`pipeline`: creates `randkey`, calls `setup` on the host, derives and registers the three formulation statics, drives `ask → transform → prepare_forward`/`forward_prepared` → `tell` and calls `show_details` on host-readable values.
`problem`: `evaluate(state, key, act_fn, transformed)` where `key` is one rank-0 evoxc key and `act_fn` is the prepared-pass pair; the problem owns the dataset tiling into the population axis and may call `act_fn.prepare(batch_rows)` once.

## Measured Cost
The committed numpy record is `benchmarks/PERF_NUMPY.md`; this section keeps the numbers that decide kernel shape and the cost laws behind them.
This tree, this session, numpy backend, 150 generations with 3 warmup, medians: **33.04** ms per generation on `xor_p100`, **112.68** on `xor_p500`, **177.43** on `xor_p1000`, **847.13** on `custom_pagie_p500`, **248.70** on `cartpole_p100`.
The same five cells on `backend="iree"`, `device="rocm"` cost **17.42 / 13.24 / 16.29 / 16.18 / 150.41** ms per generation in that order, at a 7.2–8.0 s one-off build per static shape and ≈1.9 GiB peak RSS.
Executed dispatches per generation on the numpy interpreter: `xor_p500` **7 592**, `cartpole_p100` **30 994**.
Count by wrapping `evoxc.backends.numpy.kernels.dispatch` and tallying `op.location`; region ops execute their body once per iteration and `evoxc.scan` peels step 0 at the enclosing level, so a fresh process reads lower (the forward level `while` runs `depth + 1` times) — always compare counts at the same generation.
The numpy interpreter charges ≈**19–20 µs per dispatched op**, so at population-sized tensors dispatch count is the lever; on a workload that tiles the population (func fit, a rollout) element volume is the lever instead, and the padded gene geometry (`max_nodes`/`max_conns`) is the largest single term.
On `iree`+rocm a generation costs **max(host submission, device)**: a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch (so kernel count is the lever there), one `while` iteration costs ≈50 µs because the loop condition is read back to the host, and `Tensor.to(cpu)` costs ≈47–60 µs per leaf regardless of size — which is why the pipeline packs its per-generation host return into one leaf.
Phase shares at `xor_p500`: `tell > speciate` is ≈75 % of the generation and `measure_distance` alone ≈48 % (`2 · species_size` population-shaped pairs at ≈92 dispatched ops per call), `tell > breed` ≈10 % (mutation dominates it, then crossover), `transform`/`evaluate`/`prepare_distance`/`tell`'s own algebra a few per cent each — attributed by source file and line range on an earlier census, so read them as shares, not counts.
The generation's distance work is `2 · species_size · pop_size` pairs, dispatched as 1 `prepare_distance` plus `2 · species_size` `measure_distance` calls on the host leg, and `ceil(species_size / k) + species_size` on the accelerator leg (`30` at `S = 20`, `k = 2`: scan 1 grouped, scan 2 ungrouped).
A kernel's live set is charged once per enclosing block: the numpy interpreter keeps every SSA result of a block alive until that block returns but pops a nested region's environment per iteration, so `matrix` measures inside a fixed-length scan — one centre's transients rather than `species_size` of them.
Measure peak RSS and build next to wall time for every hoist, and put a kernel inside a static loop region rather than duplicating it at the top level.
Grouping centre rows is the accelerator leg's route only: on the interpreter it does cut dispatches (7 592 → 6 589 at `k = 2`) but the 2× wider `(2 · pop_size, 2 · max_conns)` intermediates make the cell bimodally slower, so `grouped.group_size` answers `k = 1` for every non-accelerator state (capped at `ACCELERATOR_GROUP = 2`, at `GROUP_ROW_BUDGET // pop_size` and at the slot count) and the numpy pipeline traces exactly the calls it always traced.
The bounded structural-key allocator costs ~+4 / ~+8 / ~+33 ms per generation (+10 % / +5 % / +12 %) at pop 100 / 500 / 1000, almost entirely the `(pop_size, key_span + 1)` free-key table it needs for its collision fallback, even though fewer than 6 % of rows ever need that fallback.
In-node levers already applied, so do not re-derive them: one rank-raising `evoxc.broadcast` per field instead of the 4-op centre tiling, the four centre-row writes out of the `reserve` scan body, a rank-0 scan `y`, one `scalar_f32` spelling with the static fast path, `pair_parents`' hoisted constants with `trusted=True` `flat_gather`s, `block_layout`'s `sum(E[:, None] <= p, axis=0) - 1` (valid because `E` is monotone), and the `argmin_with_mask`/`fetch_first` sentinels hoisted out of both scan bodies.
The 51 / 109 / 157 ms per generation figures at pop 100 / 500 / 1000 are the *declared* contract in `benchmarks/RESULTS.md`, not a measurement; the measured frozen-JAX side in that same record is 38.99 / 295.33 / 807.30 ms.

## Known Issues
From pop ≈ 300 upward `speciate` is the dominant term of `tell` and it is per-pair bound: the pair count is irreducible (each phase needs its own genuinely different centres, and a created species takes the first unassigned genome as its centre, so its row depends on every earlier assignment), and `DefaultDistance`'s `find_homologous` still sorts `2·M` key rows per pair, so the same population genome is re-sorted once per centre — a genome-side centre-side prepare/sorted-row reuse is the next real lever and lies outside this subtree.
`genome/base.py::_iinf` materialises a full-size `I_INF` constant, so tracing warns `Embedding a tensor of … bytes as a graph constant` from pop 500 upward (genome-owned; a rank-0 sentinel plus broadcasting would avoid it).
`test/unit/algorithm/test_spawn.py` encodes `loc(p) = #{i : spawn[i] > 0 and E[i] <= p} - 1`; that count disagrees with `block_layout` for a live zero-spawn species in the middle of a table, so the oracle needs the "last qualifying block" form (cross-node item, `test/` is not writable from here).
`next_species_key` must stay strictly greater than every live key (`setup` seeds it at `1.0`, slot 0 uses `0.0`); a colliding counter silently merges two species' `member_count`.
The XOR3d pop-100 cell is the algorithm's tightest cell: no algorithm-side knob gates it (`max_in_degree = 4` refuses only 0.00–0.04 of fired add-conn gates, `max_depth = 16` sits above an observed maximum node level of 6–9, and species kill, spawn starvation, elite displacement and the output row are non-binding); the escape hazard tracks the number of *structured* individuals, and the measured lever for it is genome-side and shipped.
Crossover is live only for species with more than `1 / survival_threshold` members (200 at the example `0.01`): below that the survivor prefix is a single genome and every non-elite child is a mutated copy of it.
`SpeciesController._block_layout` and `_prefix_sum_exclusive` are maintained **test seams**: their only caller is `test/unit/algorithm/conftest.py::raw_kernel`, while production goes through `_kernels.block_layout`/`_kernels.prefix_sum_exclusive` (via `pair_parents`/`spawn_from_target`), so a behavioural change belongs in `_kernels.py`.
`_distance.DistanceRows.__call__` is the production distance route: `_kernels.speciate` calls it from its row bodies (`reserve_compute`/`member_compute`, gated or not) and so does `_scan_accelerator`'s `row_for_slot`/`row_for_centre`, while the dense scan 1 measures its whole table through `matrix`.
`evoxc.scan` peels step 0 at the enclosing level and traces its body again, so each scan body is traced twice: a probe of one `Pipeline.step` counted 4 `__call__` invocations on a gated cell (`pop_size=8`, `species_size=4`) and 2 on a dense cell (`pop_size=400`, `species_size=20`) alongside 1 `matrix`.
Unexercised from inside the package are `__call__`'s batch-`pop_size` branch (every call site builds a batch-`1` `centre_payload`), its batch-width rejection, `_check_population`'s payload rejection, and the tiling branch of whichever centre mode the state is not in.
`NEAT.__init__`'s `self.species_controller = self.species` is a deliberate public legacy-compat alias for the pre-rewrite attribute name: the same controller object, with no in-repo reader.
`show_details` is not free: it builds and caches one counting executable per payload shape (`_gene_count_executable`) and runs it every detailed generation; the pipeline's diagnostics wrapper prints a failure and records it once per hook label in `Pipeline.detail_failures` (out-of-node), so a broken detail printer never fails a run and is never lost without a record.

## Known Risks (evoxc)
`evoxc.scan` de-sugars to `while` + gather/scatter, so a wide carry trips iree's affinity analysis on CUDA/ROCm; the numpy backend is the reference and packed carries are the mitigation.
Data-dependent `while_loop` trip counts work on numpy and iree/llvm-cpu but not on iree CUDA/ROCm or tvm — the reason every loop in this subtree is fixed-length.
`cumsum` does not export on compiler backends, hence prefix sums are triangular matmuls.
`evoxc.constant` warns above 1 MiB, which bounds how large a substrate coordinate table may be before it must become an explicit pipeline input.
`evoxc` has no `io_callback`/print op, so all logging stays in `show_details` on the host side.
`DistanceRows`' tiling is a real copy (`broadcast_to` + `reshape`), so one population-shaped row materialises `pop_size` copies of that centre across every digest leaf — inside `matrix`'s scan this happens once per step and is released with the region, so the live set is one centre on the host leg and `k` centres on the grouped accelerator leg.

## Constraints
No `jax` / `torch` / `numpy.random` import anywhere in this subtree; `import tensorneat` must stay free of them (release gate).
No Python branching, `bool()`, `len()` or host reads on traced values; static Python `if`/`for` over constructor configuration is fine and unrolls at trace time.
Constructor validation raises `tensorneat.common.errors.TensorNEATError`; trace/shape/backend errors propagate unchanged and are never re-wrapped or silently fallen back.
Nothing here reads `state` fields it did not register, except the documented genome/problem keys and the three formulation statics.
One file is a deliberate, documented exception to the package's ~1000-line rule, kept un-split on purpose: `neat/neat.py` at 1026 (one generation's `tell`/breed algebra; the cohesive split, if ever taken, is its host diagnostics `show_details`/`_gene_counts`/`_gene_count_executable` into a `_details.py`).
The others sit at or inside the baseline and have no room left: `neat/_kernels.py` is exactly 1000, `neat/species.py` 979, `hyperneat/hyperneat.py` 930, `neat/_distance.py` 427, `neat/_scan_accelerator.py` 416, `neat/_keys.py` 325, `hyperneat/genes.py` 297, `neat/_validation.py` 165 — a new speciation helper belongs in `_scan_accelerator.py`/`_distance.py` rather than `_kernels.py`.

## Test Strategy
Tests live in the sibling `./../../test` tree (read-only from here), mirroring this subtree: `test/unit/algorithm/` for the spawn/selection/stagnation algebra on fixed keys and the speciation scans, `test/parity/algorithm/` for comparison against `benchmarks/legacy_jax` (the divergences above are the only allowed mismatches), `test/integration/` for a full XOR run reaching its fitness target with a reproducible seed.
Every kernel here must be deterministic given `(seed, state)`: no dict ordering, no host-side RNG, no float-to-int conversion without an explicit mask.
End-to-end verification is spread over three places: `test/release_gate_no_jax.py` resolves the two HyperNEAT dotted names through `PUBLIC_API` and evolves `NEAT + DefaultGenome + XOR` for two generations, `test/unit/algorithm/` carries the behavioural suites (`test_hyperneat.py`, `test_hyperneat_feedforward.py`, `test_hyperneat_e2e.py`, `test_hyperneat_weights.py`, `test_substrate.py` plus the shared `hyperneat_kernel.py`), and `test/integration/` runs the pipeline end to end.
The accelerator spellings (`kernel_mode="accelerator"`, `distance_centre="tiled"`, `distance_formulation="index_free"`) have no committed test: their bit-identity to the host route is a hand run, and a `test/backends` cell that builds a gated pop-100 graph in that mode is the missing regression guard.
The speciate rewrite is verified by whole-run bit-identity: per-generation `fitness_history`, the four payload arrays, all ten `SpeciesState` leaves, `randkey` and `generation` dumped to `npz` and compared with `tobytes()` equality (padding NaNs defeat `np.array_equal`) at pop 100 (lazy path), pop 500 and pop 1000 (dense path) — 144 arrays, zero mismatches.
Kernels are verified by building each one through `evoxc.build` on the numpy backend against hand-built tables: `speciate` full assignment, `sum(spawn) == pop_size` in both modes, survivor-prefix/elite pinning, stagnation kills and bit-identical repeat runs — all at `species_size * pop_size <= 6 000` (the biggest test cell is 1 000), so the dense `distance_fn.matrix` path never compiles in the suite and the pop 500/1000 bit-identity runs are hand runs, not tests.
