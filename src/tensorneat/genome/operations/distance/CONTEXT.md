# distance — compatibility distance: pair-wise, merge, index-free, dense single-centre, grouped k-centre

## Intent
Answer one question per parent pair, batch-first: how different are these two genomes?
It feeds speciation, so it is symmetric, exactly `0` at identity, `0` (never NaN) for an empty pair, and normalised by the larger gene count so pairs of different sizes stay comparable.
Speciation measures centre genomes against the whole population in two phases per generation, so the population side is packed and sorted **once** (the digest) and only the centre side is per-call work.
One arithmetic in five shapes, all ending in `DefaultDistance._scalar_distance`, which is what makes them bit-identical rather than merely close:
- the pair-wise `__call__` (two explicit parents; parity tests and callers holding both);
- `prepare` + `measure` **merge** (`digest.py`), the sort-based successor test and the contract all other shapes are measured against;
- `prepare` + `measure` **index-free** (`index_free.py`), an equality table instead of the sort, selected by `state.distance_formulation == "index_free"`;
- `measure` **dense single-centre** (`dense.py`), a key→gene scatter/gather for a batch-1 centre — the route the CPU pipeline takes;
- `measure` **grouped** (`grouped.py`) against `group_digest(digest, k)`: `k * P` centre rows in one call, the accelerator leg's shape.

## API Surface
`BaseDistance.__call__(state, genome, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, …, conn_attrs2) -> (P,) float32` validates both parents field by field (matching shapes, key rank 2 or 3, attribute rank 3, keys and attributes agreeing on `(P, M)`; a violation raises `ConfigError`) and returns node distance + connection distance.
`BaseDistance.prepare(state, genome, node_keys, node_attrs, conn_keys, conn_attrs, *, consts=None) -> DistanceDigest` runs once per generation and returns the reusable digest.
`BaseDistance.measure(state, genome, centre…, digest, *, consts=None) -> (R,) float32` takes a centre batch of `1` (broadcast, dense route when enabled) or `P` on a plain digest, and exactly `group * P` on a grouped one.
`BaseDistance._merge_both(pool, state, genome, payload, digest)` is the one spelling of the row-wise route (both families, one `evoxc.add`), shared by the plain and grouped paths.
`BaseDistance._measure_single_centre(pool, state, genome, payload, digest)` is the hook (`None` in the base class) and `_single_centre_enabled(genome)` its host twin (`False` in the base class, so `measure` can validate the dense precondition before any op is emitted).
`BaseDistance._measure_family(pool, state, gene, …)` is the per-family driver: `index_free.alignment(...)` then `distance_from_alignment(...)`; `gene_measure(...)` is the same body with a private pool and has **no in-library caller**.
`DefaultDistance(compatibility_disjoint=1.0, compatibility_weight=0.4, dense_single_centre=True)` — both weights finite and non-negative (`ConfigError` at construction); `dense_single_centre=False` forces the row-wise merge everywhere.
`DefaultDistance.gene_distance` (pair-wise alignment hook), `distance_from_rows` (its row-table spelling), `distance_from_alignment` (the aligned attribute gather), `_scalar_distance(cnt1, matched, cnt2, attribute_distance, pool, *, consts=None)`, `_tail_constants()`, `_single_centre_enabled`, `_measure_single_centre`.
`_scalar_distance` is `(non_homologous * compatibility_disjoint + attribute_distance * compatibility_weight) / max(cnt1, cnt2)`, with `non_homologous = cnt1 + cnt2 - 2 * matched` and the denominator floored at `1.0`, so an empty pair is `0.0` with no second `select` and `attribute_distance=None` (a zero-attribute family) drops the attribute term.

## Merge algebra (`digest.measure_alignment`)
A gene row folds into one `int64` composite, positionally and most significant first in base `_KEY_BASE = 2**31`: a node key is itself, an `(in_key, out_key)` connection key is `in * 2**31 + out`.
`2**31` is the whole non-negative `int32` key range, so the fold is injective for **every** legal key and never consults `key_span`; `key_span` (`S`) bounds only the dense table and the execution schedule, never an identity.
Digits need no per-column gate: `2**31` bounds every legal digit, and an absent row needs no special case because the payload contract makes every key column `I_INF`, which folds to the side's padding sentinel by construction.
The fold is unrolled `multiply`/`add` steps, never a weighted `reduce_sum` over the key axis (an innermost-axis integer reduction costs an order of magnitude more than the elementwise pair it replaces).
The **centre side of a multi-column key family folds with one `dot`**: `_pack_centre` contracts `cast(keys, int64) (R, M, 2)` against `fold_i64 (2, 1)` `[2**32, 2]`, so `k0 * 2**32 + k1 * 2` lands in 4 traced ops (cast, dot, reshape, `not_equal`) instead of 11.
That cast in front of the `dot` **stays**: a mixed-dtype `dot` traces and runs on numpy but is not exportable — the StableHLO writer forwards `dot` operand dtypes verbatim and emits an invalid `dot_general` with no `lower()`-time error, so only an actual export reveals it; `multiply` is the one op where mixed dtypes are safe (the elementwise writer inserts a `convert`), which is how the node family's single key column folds in one op.
Two folded columns are all an `int64` composite holds (`2 * 31 = 62` bits), so a gene with more columns (`OriginConn`'s `historical_marker`) folds its first two and **verifies** the rest row for row (`_key_row_matches` against `digest_key_cols`), keeping homology equal to full-tuple key-row equality.
The low bit of the sort key is the side tag (population `1`, centre `0`); each side's padding rows collapse onto their own sentinel: `_PAD_CENTRE = I_INF * _FOLD_HI + I_INF * _FOLD_LO = 2**63 - 2**32 - 4` and `_PAD_POPULATION = _PAD_CENTRE - 2`.
Defining the centre sentinel *as* the fold of an absent row is what lets the `dot` path skip its `select`; both sentinels are **even** and two apart, so no `(padding, padding)` and no `(padding, gene)` adjacency can pass the "differs by one, right neighbour population-tagged" test.
Injectivity plus the tag make a homologous pair exactly an adjacent `(centre, population)` pair whose composites differ by one, and the parity proves the neighbour is a real population gene.
The merge concatenates the **digest side first**, the centre second and one **trailing column** of `_PAD_CENTRE` third: a population gene's merged index *is* its digest row, the tail reads its row table straight off the successor, and every centre gene has a successor position in range — so the successor gather needs no `minimum` clamp and no in-range mask.
Sequence per family: `concatenate` to `(R, 2M + 1)`, one **stable** `argsort`, its inverse via a second **stable** `argsort` of the permutation, then two centre-width gathers (the successor's merged index and the composite it carries); nothing later is `2M`-wide.
The inverse permutation is the measured formulation: `argsort(order)` is two ops while scattering the ranks costs four to eight.
`evoxc.slice(x, start, limit)` takes **lengths**, not end indices, which is why the centre slice is `((0, count), (pop_size, count))`.
`stable=True` is a **performance** rule, not a tie rule: numpy's stable kind is timsort, so the already-ascending digest half is a detected run (the merge's two sorts 2.49 → 0.57 ms per `(1000, 200)` `int64` block at `M = 100`, the inverse permutation 1.05 → 0.29 ms) and the digest's own sort gains 15–17 % because a payload is a short real-gene run plus a long padding run.
No sort here has a meaningful tie — a homologous pair differs by one, real composites are unique inside a genome, and only padding rows compare equal (their attributes are `NaN` on both sides and they never pass the homology test) — and stability also pins tie order to input order and matches a compiled backend's count-mode `argsort`.
Sort cost is superlinear in **row width**, not element count: one `(500, 301)` `int64` `argsort` is dearer than `(500, 101)` + `(500, 201)` together, which is why fusing the two families' merges into one sort loses.

## Digest fields and the once-per-generation contract
`node_keys (P, N) int64` / `conn_keys (P, E) int64` — injective packed composites, ascending with the padding sentinel last; `node_attrs` / `conn_attrs (P, M, A) float32` — the attribute rows permuted into that same order, absent rows keeping their `NaN`.
`node_count` / `conn_count (P,) int32` — real genes per individual, the length of the valid prefix; `node_key_cols` / `conn_key_cols (P, M, K) int32` — key columns in the same order (the exact-match oracle for a key wider than `_FOLDED_KEYS`; a narrower key keeps the *unpermuted* table and nothing reads it).
`node_dense` / `conn_dense (P, M) int32` — the **star** slot (`select(real, slot, pad_i32)`, permuted into the digest's order) so `owner_at < count` alone is the dense route's homology mask; `node_real` / `conn_real (P, M) bool` — the in-range mask; `node_oor` / `conn_oor (P,) int64` — `count - reduce_sum(real)`, i.e. present genes whose key lies outside `[0, key_span)`, the dense precondition as a host-readable diagnostic (two traced ops per family, computed whether or not that route is enabled, and nothing branches on it in-graph).
`tail_counts (2, P) int32` — the two families' population counts stacked on a leading axis, `cnt2` of the dense route's tail, built once because that route traces the tail once for the pair; `enp.zeros((0, 0), int32)` when the dense gate is off.
`node_statics` / `conn_statics (MeasureStatics)` — the row-wise route's scaffolding, built once in `prepare_family` from one shared pool, which is why `measure` traces no `constant` and no index table of its own.
`node_layout` / `conn_layout (DenseLayout)` — the dense route's scaffolding, built in `prepare_family` only when the static gate holds (`dense = enabled(node_gene) and enabled(conn_gene)`, computed once in `BaseDistance.prepare`), so a merge-only configuration never materialises the two big table bases.
A gene family with no attribute column (`attr_specs = ()`) contributes an empty `(P, M, 0)` block: `_gather_rows` returns it unchanged (a zero-width row has exactly one permutation), `AttrStatics.base` is the `(0, 1)` placeholder, and the distance is the structural term alone.
`prepare` writes no RNG and touches no host memory, so a digest is valid for one generation and cacheable for the whole speciate pass; the centre is **never** prepared — `measure` packs its key rows itself (`_pack`, `_pack_centre`, `dense_rows(..., flat=True)`, or the index-free `_centre_composites`).
Nothing that does not depend on the centre may live in `measure`: every rank-0 scalar, every per-individual flat index block and every flat view of a population block travel in the digest, and a `measure` call left with value-dependent work only is the budget this node is measured by.
`NEAT.tell` calls `prepare_distance` exactly once per generation and reuses the digest for every centre of both speciation phases (`2 * species_size` rows; one `measure` call per row on the host leg, one per group of `k` in scan 1 on the accelerator leg).

## Dense single-centre route (`dense.py`)
A genome is a sparse table of `(key, gene)` rows and NEAT keys are small integers, so a **centre** scatters into a table indexed by the key itself and **gathers** at the population's own dense index: node slot `= node_key` (width `S + 1`), connection slot `= in_key * S + out_key` (width `S * S + 1`).
Two cells per table are not genes: the **dump** cell `width - 1` catches every centre row whose key is absent or outside `[0, S)`, and the **padding** cell `width` is never owned and is what a population gene with an unusable key reads; both start at the gene count (an impossible row index), so `owner_at < count` is the whole homology test and no out-of-range index reaches the backend.
Per family per call: one `concatenate` of the `(M, 1) float32` centre row index with the `(M, A)` attributes into one update block → **one** `scatter` into the merged `(width + 1, 1 + A) float32` table at `slot` → **one** `gather` of that table at the population's `dense` block → the owner column sliced and cast back to `int32` → `matched = owner_at < count`, ANDed with exact marker equality when the gene has columns past `_FOLDED_KEYS` → `gene.distance` against the attribute columns of the same gathered block → a flat `scatter` that reorders the per-population-gene distances into the **centre's own row order** → `reduce_sum`.
**One table, one scatter — a portability requirement, not a cost dodge.** `evoxc`'s StableHLO writer emits an `i32 → i64` `convert` of every `scatter`'s index operand, upstream IREE common-subexpressions two identical converts, and its StableHLO → Linalg conversion then wants `i32` indices and inserts two conflicting materialisations, so `iree-compile` dies on `failed to legalize unresolved source materialization from ('tensor<50x1xi64>') to ('tensor<50x1xi32>') that remained live after conversion`.
Measured on a scratch harness (`evoxc.scatter(zeros(W), idx, upd, axis=0)` graphs, `llvm-cpu`): one `scatter` compiles, three with three **distinct** index tensors compile, three sharing one index tensor fail, and a "distinct" index that canonicalises back (`add(idx, 0)`, `select(true, idx, idx)`) fails too, whatever the destination rank, width or index count.
A gene with trailing marker columns is therefore resolved by **gathering** the centre's own key rows at the owner index (`center_markers` = the centre's trailing key columns with the layout's `marker_pad` row appended, gathered at an index always in `[0, M]`), never by a marker table of its own, so each family emits exactly **two** scatters at different index expressions (the merged table at `slot`, the reorder buffer at a flat `(P*(M+1),)` index).
That reorder is the bit-identity requirement: the tail sums over the *centre's* rows in the centre's row order, exactly like the merge, so the float summation order is unchanged.
The marker-column `select` is a correctness requirement: a `(in_key, out_key)` slot says nothing about `historical_marker`, so a population edge sharing the endpoints with a different marker is not homologous and must not write its `|Δweight|` into that centre row.
Counts: `matched` from the in-range mask, `cnt1` from the centre's present rows (`key != I_INF`, the predicate the digest's `count` uses), `cnt2` from `digest.tail_counts`.
Duplicate key rows inside one genome are outside the payload contract; the dump redirect makes them a last-writer-wins scatter instead of a crash.
Static gate (`dense.enabled`, never a runtime branch): a family qualifies while its merged centre table fits `_DENSE_MAX_BYTES = 8 MiB` of float32 (`width * 4 * (1 + attr_width)`, the padding cell included) and the width stays inside `int32`; a trailing marker column costs no table cell.
`S = 150` (`max_nodes = 50`, `max_conns = 100`) gives `22 501` connection cells (≈0.2 MB); `S = 500` (≈2 MB) qualifies; `S = 2000` would need ≈72 MB and falls back to the merge, because the table grows with `S²` while the merge grows with the gene axis `M`.
**Both** families must qualify or neither does: a partially dense `measure` would have to broadcast the centre payload for the other family, and the row-wise merge is then the honest route.
The route is taken only for a batch-1 centre **and** only while `index_free.selected(state)` is false (that formulation must never enter the scatter-based route); when the gate fails, `measure` broadcasts the centre itself (`_broadcast_payload`, 12 ops) and runs the merge.
Precondition — gene keys inside `[0, key_span)`, validated on host data and reported as `node_oor`/`conn_oor`: an out-of-range key is **unmatched** here (exactly like `common.tensorization` drops it) while the merge still matches it, so `measure` validates whenever `_single_centre_enabled` holds and a leaf is host data (`_host_array` answers `None` for a `SymbolicTensor`, so a traced digest or centre is skipped silently).
The refusal names the family, the offending individuals or centre rows, `genome.key_span` and both remedies — keep every allocated structural key inside `[0, key_span)`, or construct `DefaultDistance(dense_single_centre=False)` — is pure NumPy with **zero** traced ops, and runs before the hook emits an op, which is what lets a host call answer `TensorNEATError` instead of a backend `TypeError`.
Inside a trace a value-dependent raise is impossible, so the guard is a host-call guarantee only; the live allocator (`algorithm/neat/_keys.py::node_keys_for_split`, which wraps every allocated key into `[max_nodes, key_span)`) keeps live payloads inside the window (`node_oor == conn_oor == 0` over eight cells × generations 0-39, worst present key 149 against `key_span = 150`).

## Index-free formulation (`index_free.py`)
`state.distance_formulation` picks how a centre gene finds its homologue in the already-prepared digest: `"merge"` (the sort-based successor test) or `"index_free"` (an `equal` table, no `argsort` at all).
The centre composites carry the **population** tag (`pack * 2 + 1`): rank-2 keys fold with `_pack(..., scale=tag_scale_i64)` + `_tagged(..., _TAG_POPULATION, pad_centre_i64, None, one_i64)` in four ops, rank-3 keys with width `>= _FOLDED_KEYS` fold with `_pack_centre` + `select(valid, add(composite, one_i64), pad_centre_i64)`.
So a homologue is **plain equality** — the comparison *is* the homology test — and the two sides cannot alias: real composites of both sides are odd and top out at `2**63 - 2**32 - 3`, while both padding sentinels are even (`_PAD_CENTRE = 2**63 - 2`, `_PAD_POPULATION = 2**63 - 4`), so an absent centre row equals no population composite and the population side needs **no presence mask** (the digest's `2M`-wide `valid` block is never read here, and `prepare_family` gained no constant, no table and no op for the switch).
Body per family: `table = equal(reshape(centre_tagged, (P, M, 1)), reshape(digest_keys, (P, 1, M)))` → `(P, M, M) bool` (`evoxc.equal` broadcasts a static pair, so the table costs two view reshapes and one compare), then `columns = enp.arange(0, count, int32)`, `no_match = pool.i32(count)`, `col = reduce_min(select(table, columns, no_match), axes=2)`, `homologous = less(col, no_match)` — "the first matching population column", which is the row the merge's successor test finds, and one reduction answers both the column and the mask so no second table-wide pass is paid.
`argmax` is deliberately avoided: it materialises a full `(P, M, M)` `int64` iota whose dispatch has no operands, so IREE's scheduling leaves it outside every `stream.async.execute` region and `iree-compile` fails the assembled graph with `'stream.async.dispatch' op : streamable op expected to be in an execution region` on both `llvm-cpu` and `rocm`, even though `ops.status("argmax")` reports `v1` and `lower()` sees nothing wrong.
A key width past `_FOLDED_KEYS` ANDs in exactly the merge's confirmation (`digest._key_row_matches` against the candidate digest row), so homology stays full-tuple key equality.
`rows = select(homologous, col, statics.zero_i32)`; the record is `AlignedGenes(rows, homologous, reduce_sum(valid, axes=1), reduce_sum(homologous, axes=1))` — same shapes and dtypes the merge returns (`count`/`matched` are `int64`, as a bool `reduce_sum` returns), so `distance_from_alignment` → `_scalar_distance` consumes it unchanged and the routes are bit-identical by construction.
Everything below the table is row-local, so a `GroupedDigest` (statics at `group * P` rows) and a broadcast batch-1 centre work with no special case.
Cost trade on the numpy reference interpreter (measured at `9b728405`): 84 marginal traced ops against the merge's 93 and **2.1–2.6×** the wall clock, because the `(P, M, M)` `equal`/`select`/`reduce_min` chain is an `M²` element pass (12.5 M bools for the connection family at pop 500) where the merge sorts `2M + 1` columns — so the route is the dispatch-bound leg's, never a CPU win, and the numpy default stays `"merge"`.
On a compiled/dispatch-bound target the same table is the win: `3 · R · M²` element touches per call against the merge's `≈ 405 M` (2 argsorts × 4 count-mode reduces × `(2M+1)²`), and 0 sorts against 8 reduction families.
**Duplicate key rows inside one genome are the one measurable divergence**, and they are outside the payload contract: with a centre carrying key `7` three times against one digest row the merge's successor test marks only the **last** duplicate homologous (`matched 3`) while the table marks **every** duplicate (`matched 5`, all pointing at the first matching column); duplicate rows on the population side agree. Matching the merge would cost a per-call tie-break op on the hot path, so it is documented rather than chased.

## Grouped route (`grouped.py`)
Every op of the merge, the aligned-attribute gather, `gene.distance` and the scalar tail is **row-local**, so a `(k * P, M)` centre against a `k`-times-tiled digest is exactly `k` separate `P`-row measurements in the same per-row float summation order; what hard-coded `P` was only the scaffolding (`offsets`, `offsets_plus_one`, `pad_column_i64`, `AttrStatics.base` and `attrs_rows`).
`group_digest(digest, k)` therefore does two things: it tiles each of the eight digest arrays with **one** `evoxc.concatenate((x,) * k, axis=0)` (`k == 1` returns the operand unchanged, zero ops), and it rebuilds both statics bundles with `layout.build_grouped_statics` at `rows = k * P`, reusing every rank-0 scalar, `fold_i64`, `zero_f32` and `tail` of the plain digest.
Row `j * P + p` of the result is `distance(centre row j * P + p, population individual p)`, so a caller hands over the `k` centre batches **concatenated on axis 0** in slot order and slices the `(k * P,)` answer back.
`measure` dispatches on `isinstance(digest, GroupedDigest)` straight to `_merge_both`: no dense route and no broadcast on that path; `validate_centre` raises `ConfigError` naming both shapes plus `group`/`pop_size` when the centre batch is not exactly `rows`, when the grouped digest's own leaves disagree, or when a rebuilt statics table is not shaped for `rows`.
`k` is chosen by `group_size`, the one place the decision is made: it answers **`1` unless `common.schedule_accelerator.is_accelerator(state.kernel_mode(state))`**, so the numpy/CPU leg is handed its plain digest unchanged and its dispatch count, wall time and peak RSS do not move; an accelerator state gets `max(1, min(ACCELERATOR_GROUP, GROUP_ROW_BUDGET // pop_size, species_size))`, i.e. `k = 2` up to pop 2048 and `k = 1` above it (`species_size = 1` degenerates to `1` too).
`for_state(state, digest, *, species_size=None) -> (digest, group)` returns the argument digest and `1` when `group == 1`, else `group_digest(digest, group)`, so `k = 1` is literally the plain path rather than a one-wide tiling; `centre_batch(payloads)` merges `k` one-individual centre payloads with one `concatenate` per field, and `group_size`/`for_state` are host-side (a non-`int`/non-positive `pop_size` or `species_size` raises `ConfigError`, the answer is a Python `int`), which keeps every seam a host branch and never a traced value.
The route **is** wired: `algorithm/neat/_distance.py::DistanceRows.matrix` groups the generation's digest with `for_state`, scans `K // k` groups instead of `K` rows, gathers each group's `k` centre rows, merges them with `centre_batch` and makes one `measure` call, rebuilding the `(K // k, k * P)` stack into `(K - K % k, P)` and measuring at most `K % k` trailing rows singly against the plain digest.
The scan body returns a rank-1 `(k * P,)` step on purpose: `evoxc.scan` stacks `y` into `(groups,) + y.shape`, and a `(k, P)` `y` would make that a **rank-3 axis-0 `scatter`**, which the StableHLO v1 exporter refuses outright (`BackendError: op 'scatter' on a rank-3 operand along axis 0 is not supported`).
The host leg is where the grouped form loses, which is why it is gated off there rather than unwired: on `xor_p500` `k = 2` cuts dispatched ops 7 592 → 6 589 (−13 %) but raises peak RSS 233.8 → 253.2 MiB (+19.4 MiB) because the 2× wider `(2P, 2M + 1)` merge intermediates stop fitting in cache, and its numpy wall time turns bimodal at process level — 152–165 ms in fast processes against 196–253 ms in 7 of 13 fresh default-environment processes, stable at 152 ms against 159–162 ms when glibc is forced onto brk with `MALLOC_MMAP_THRESHOLD_`/`MALLOC_TRIM_THRESHOLD_` raised.
`k = 4` reads +15 % wall / +30.5 % peak RSS and a second pre-measured centre table +58 % wall, so the trade is op count and call boundaries for allocator-sensitive memory, and a caller must measure its own arrangement rather than assume `k > 1` is a speed-up.
Bit identity holds: `tobytes()`-equal to `k` plain calls over pop 100/500/1000 × {`DefaultNode` + `DefaultConn`, `OriginNode` + `OriginConn`} × 10 evolved generations, and the generation-level digest gate matches grouped against plain at `P = 500` and `P = 1000`.
The grouped body's traced op count is the plain merge's and is independent of `k` (one body amortised over `k` centres), and a single grouped `k = 4` call is cheaper than the four plain calls it replaces (2.16 vs 4.00 ms at pop 100, 8.68 vs 9.52 ms at pop 500) — the kernel's arithmetic is not what holds the route back on the host leg.
`group_digest(k=1)` traces 16 ops and `group_digest(k=2/4/P)` 24 (identical at pop 100 and pop 500).

## Formulation statics (the device seam)
Three trace-time strings reach this node through `_static_config`'s closure, never as graph-boundary tensors: `distance_centre`, `distance_formulation` and `kernel_mode`.
`host_payload._formulation_statics` derives all three from one decision — whether the resolved device **kind** is GPU-class (`"rocm"`, `"hip"`, `"hips"`, `"cuda"`, `"vulkan"`, `"gpu"`, case-insensitive) — as `("tiled", "index_free", "accelerator")` for such a kind and `("single", "merge", "host")` for every other kind and `None`.
A state no `Pipeline.setup` produced resolves a **missing** entry the way the kernels do: `distance_centre` `"tiled"`, `distance_formulation` `"merge"`, `kernel_mode` `"host"` (a bare `State()` keeps the legacy contract).
All three are part of the executable-cache formulation signature (`host_payload._formulation_signature`), so changing one rebuilds exactly one executable and no other signature entry moves.
This node reads two of them: `index_free.formulation_mode`/`selected` for `distance_formulation` and `grouped.group_size` via `common.schedule_accelerator.kernel_mode`/`is_accelerator` for `kernel_mode`; both validate their value and raise `TensorNEATError` naming the accepted spellings (no silent fallback).
`distance_centre` is read only by the caller (`algorithm/neat/_validation.distance_centre_mode`) and by `host_payload`'s signature — but it decides which route this node runs: `"single"` hands `measure` a batch-1 centre (the dense route, i.e. the live CPU leg) and `"tiled"` a `pop_size`-row centre (the merge, or `index_free` on a GPU-class kind), so both centre widths must stay accepted.

## Cost law of this node
On the numpy reference interpreter one **dispatched op** costs ≈19–20 µs on rank-0/small operands (measured on this worktree, 2026-11-06), so op count is the budget for narrow passes and element width is the budget for the wide ones; `constant`, `reshape` and `arange` each cost a full op and evoxc never deduplicates constants.
A per-call body runs `2 * species_size` times per generation, so anything that does not depend on the centre belongs in `prepare` — the rejected alternative (a private `ConstantPool` and per-call `enp.arange`/`batch_offsets` inside `measure`) cost 536 rank-0 constant ops plus 320 index ops per generation.
A merge `measure` call is **sort-bound, not dispatch-bound**: the two `argsort`s plus their two `int32` casts are 27–30 % of the call, and every other op is an ordinary `(R, M)` pass at 5–90 µs; the dense route emits the same kinds of pass but no `(R, 2M + 1)` block, so nothing in it grows with the merged width.
Every `int64` block is element volume that shows up in the wall clock: `(P, 2M)` `int64` is 6.4 MB at `4P = 4000`, `max_conns = 100`, and the merge holds two of them plus the `int32` permutation — which is why the connection family costs twice the node family at the same op count and why the dense route wins on exactly that family.
`measure` holds one `(R, M, A)` temporary per call (plus one `(R, M + 1)` on the dense route) and a grouped call holds the same shapes at `k * P` rows, so a new full-size temporary in this path is a real regression even when it saves ops.
Traced op counts (static, independent of `P`): `measure` marginal **98** on the default batch-1 dense route and `prepare` **167**, as the shipped guard in `test/unit/genome/test_distance_digest.py` records (ceilings 120 / 210, `_count_ops` over every `entry_block` and region body); the merge body at a `P`-row centre traces 93 and the index-free body 84 (measured at `9b728405`), `execute_distance` (pair-wise, unchanged contract) 225.
`prepare` emits ~48 of its ops as `constant`s and `measure` emits none; `group_digest` emits none of its own either (it reuses the plain digest's scalars).
Per-call milliseconds measured on earlier trees (build excluded, one `prepare` + 6 × `measure`, marginal = `(total − prepare)/6`) put the batch-1 dense route at **2.2–2.4×** the speed of a `P`-row merge in the same session (1.35–1.47 ms against 3.10–3.32 ms at pop 500) — the ratio is the load-bearing number, never the absolute milliseconds.
Executed dispatches on the numpy leg of this worktree: `xor_p500` **7 592**, `cartpole_p100` **30 994**.
Per-generation wall time on this worktree (five shipped cases, numpy then rocm): `xor_p100` 33.04 / 17.42 ms, `xor_p500` 112.68 / 13.24 ms, `xor_p1000` 177.43 / 16.29 ms, `custom_pagie_p500` 847.13 / 16.18 ms, `cartpole_p100` 248.70 / 150.41 ms — i.e. 1.9× / 8.5× / 10.9× / 52× / 1.65× faster on the GPU-class leg the index-free + grouped formulation exists for.
On iree+rocm a **flat** graph pays ≈63 µs of fixed cost plus ≈2.2–2.5 µs per dispatch, a `while` iteration ≈50 µs of region overhead, and a `Tensor.to(cpu)` ≈47–60 µs per leaf, so above a few hundred kernels the lever on that leg is dispatch count, not arithmetic (measured this session).
The two laws are what the formulation switch is priced on: an `evoxc.scatter` lowers to one single-threaded workgroup at ~7–19 ns per destination cell on the device (why the dense route is a device-time regression there), and a count-mode `argsort` expands into `8 · E · R · E` element touches for `E = 2M + 1` (why the merge's per-call body carries 8 such reduction families and the index-free table's `3 · R · M²` replaces them).

## Bit-identity argument (five routes, one tail)
`__call__`/`gene_distance`, `prepare`+`measure` (merge), (index-free), (dense) and `prepare`+`group_digest`+`measure` differ only in how the homologue table is produced, and all five feed `_scalar_distance`.
For index-free: `homologous` is exactly "a population gene has this key tuple" (the table matches tagged composites, a marker column is confirmed by the same `_key_row_matches`), `rows` names the first matching population column, and the counts are the same `reduce_sum`s over the same masks, so the attribute rows and the float summation order are unchanged.
For dense: `matched` and the per-gene attribute distances are the *same multiset* as the merge's (a slot is shared exactly when the key tuples are equal) and the values are written back into the centre's own row order before the reduction — required because float addition is not associative.
For grouped: the tiled statics carry each group's own `p * stride` offsets and every op is row-local, so each row computes exactly what the corresponding plain call computes.
Duplicates inside one genome are the documented exception (see the index-free section); outside them the equivalence is `tobytes()`-exact, not approximate.

## Constraints
- **No unsigned dtype in a graph** — `iree`'s declared dtype set has none (`float16/float32/float64/int8/int16/int32/int64/bool`), so a `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the whole graph. Use same-width signed carriers: a range test is `logical_and(greater_equal(key, 0), less(key, S))` on `int32`, and the `>= 0` half is not decoration — a negative structural key must land in the dump slot exactly as `I_INF` does.
- Trace-time kernels only: no `jax`/`torch`/`numpy.random`, no `vmap`/`scan`/`while_loop`/`cond`, no Python loop over individuals or pairs, no eager NumPy on the compute path; nothing here is differentiable and nothing draws RNG, so repeated calls are bit-identical.
- Every static decision is a **host** value (gene geometry, `key_span`, `dense_single_centre`, the digest class, the three formulation strings); no traced value ever drives Python control flow, and a partially dense `measure` is impossible by construction.
- Never build an `O(M²)` per-pair comparison matrix (`(P, 100, 1) < (P, 1, 100)` is 3.3 ms and a `(P, 100, 100)` reduce 4.4 ms), except the index-free table; where such a table exists, read its column with `select` + `reduce_min`, **never `argmax`** (see the index-free section).
- Never let two `scatter`s in one graph share an index expression, and never use `evoxc.gather(..., axis=1)` on a rank-3 block (105–163 ms at `(P=1000, M=100)`); every row permutation is a flat gather on a `p * R + col` index block, and the one reorder scatter is raw because every index is already inside `[0, M]`.
- Mixed-dtype operands are allowed for **elementwise** ops only (`multiply`, `add`, `subtract`, `maximum`, `select` — the writer inserts the `convert`), never for `dot` or `concatenate`, whose operand dtypes it forwards verbatim.
- Never derive a composite radix from `key_span`: the fold uses `2**31` for injectivity, and the dense table derives its *slot* from `key_span` only because it is an address, not an identity.
- **Population-scaled seeds go through `genome.window.fill`, never `enp.zeros`/`enp.full`** (`DenseLayout.base (P·(M+1),)` and `DenseLayout.zeros (P,)` were the last such constants); only genuinely static tables (`key_span`-scaled, index `arange`s) and the dense layout's own `table`/`marker_pad` keep `enp.zeros`/`enp.full`.
- The attribute distance is masked/redirected so it never reads a non-homologous slot (a `NaN * 0` product would poison a sum), and int option columns contribute `!=` (one per changed option) rather than `|id1 - id2|` — that rule lives in `BaseGene.distance`.
- `attr_width == 0` is a supported configuration: `_gather_rows` returns the empty `(P, M, 0)` block unchanged, the attribute term is skipped, and every row stride built from an attribute width sits behind a static width branch (`enp.arange(0, n, 0)` is a `ZeroDivisionError` on the reference backend).
- Key tables are accepted as `(R, M)` or `(R, M, K)` via `alignment.key_rows`; rank-0 integer constants come from the pool because a Python literal widens an `int32` tensor to `int64`.
- Errors: a parent shape mismatch, a wrong key width, a digest built for another gene axis, or a centre batch the digest does not accept (plain: not `1`/`P`; grouped: not `group * P`) raise `ConfigError` (`TensorNEATError`); a host-resident leaf breaking the dense route's key precondition raises `TensorNEATError`; `evoxc` errors propagate unchanged.
- Files ≤ ~1000 lines: `base.py` 1000 (at the ceiling — a new body belongs in a new file and `base.py` gains only a switch), `digest.py` 953, `layout.py` 748, `default.py` 524, `grouped.py` 521, `dense.py` 380, `index_free.py` 363, `consts.py` 107.
- Each file is one job: `base.py` the two-phase drivers, `_merge_both`, the hook pair and the host-side key validation; `digest.py` the fold, the sentinels, the merge and the digest fields; `layout.py` every per-generation static and the table geometry; `default.py` the weights, the hooks and the one scalar tail; `dense.py`/`grouped.py`/`index_free.py` one route each; `consts.py` the pool.

## Test Strategy
`test/unit/genome/test_distance_digest.py` is the shipped regression spec for the digest pair: one module-scoped evolved population (seed-42 `Pipeline` XOR, `pop_size = 100`, `species_size = 5`, `max_nodes = 50`, `max_conns = 100`, 2 `step`s, both `DefaultDistance` variants), pinning `prepare` + `measure` `tobytes()`-equal to `execute_distance` on the batch-`P` centre, the batch-1 dense centre and the `dense_single_centre=False` merge, self-distance exactly `0` for every individual and `0` for an empty pair (never NaN), two independent digests measuring identically, the digest static contract (`node_count`/`conn_count` lead with the population axis, `tail_counts` equals the two counts, `node_oor`/`conn_oor` equal a host recount) with a `ConfigError` for a centre that disagrees with the digest, and the op budget (ceilings `MEASURE_OP_CEILING = 120` / `PREPARE_OP_CEILING = 210` against the measured 98 / 167).
One more test pins the payload invariant the `dot` fold relies on: an absent gene row carries `I_INF` in **every** key column, checked on a real evolved payload for both shipped key layouts (`DefaultConn`, `OriginConn`'s history column).
`test/unit/genome/test_distance.py` (15 tests) covers the pair-wise route, the self-distance and the sentinel/zero-attribute cases; `test/parity/test_distance.py` holds `execute_distance` exactly against the frozen legacy implementation and needs the `bench` extra.
**No committed test selects the accelerator leg**: neither `distance_formulation="index_free"`, nor `distance_centre="single"`/`"tiled"` beyond the pipeline default, nor `kernel_mode="accelerator"`, nor `group_digest` has a test here (`./test` is a sibling node), so the five accelerator formulations are gated by hand-run identity matrices only.
The evidence those matrices produced: index-free `tobytes()`-equal to the merge on 192 cells ({pop 100/500/1000} × {`DefaultNode` + `DefaultConn`, `OriginNode` + `OriginConn`} × generations 0-7 × {population-shaped centre, tiled row-0 broadcast, batch-1 centre, batch-1 dense), plus all-`I_INF` empty individuals, keys outside `[0, key_span)`, duplicate population rows and a zero-attribute conn gene); the marker-confirmation branch exercised on live payloads (586 prefix-only slots over 3 populations × 8 generations, 0 homologous on either route); grouped `tobytes()`-equal to `k` plain calls over 6 family/pop cells × 10 generations plus the generation-level digest gate; the dense route equal to the merge and to `execute_distance` over 1 500 centres / 750 000 rows.
A bad `distance_formulation` value raises `TensorNEATError` naming both accepted spellings, and a bare `State()` reads `"merge"`/`selected = False`.
The run-level gate for anything this node touches is 10 seed-42 `Pipeline.step` generations at `P = 500` and `P = 1000` with a sha256 per generation over `dtype.str + repr(shape) + tobytes()` of the four payload arrays plus `fitnesses`: `P=500` → `d43edd0d3c19fe8f6bb4a1001246c40faaf82bf431e95e3a12f6c9b4a3e4c96e`, `P=1000` → `caba83eeebe50e86941fb7997c184e59f4702388d0826d77401a68dcb166bd45` (the conventions live in `../CONTEXT.md`); index-free and grouped reproduce the same pair as the merge.
A performance claim is only accepted from an **interleaved two-process A/B** (a pristine `git archive` checkout against the working tree selected by `PYTHONPATH`, alternating fresh processes, `REPS >= 10` bodies per graph, medians over ≥6 rounds), because the box drifts ±30 % between sessions.
StableHLO portability gate: `evoxc.lower(graph, backend="iree").payload["mlir_text"]` plus `iree-compile --iree-input-type=stablehlo --iree-hal-target-backends=<llvm-cpu | rocm --iree-rocm-target=gfx942> --compile-to=executable-configurations`; the merge generation graph needs `--iree-llvmcpu-stack-allocation-limit=1048576` on llvm-cpu (`'func.func' op exceeded stack allocation limit of 32768 bytes … Got 40256 bytes`, a property of that graph and not of a change), the dense and index-free graphs need no flag.
Trace a bound method through a closure (`lambda *a: obj.method(state, *a)`) and build rank-0 RNG keys *inside* the trace (`evoxc.random.key(seed)`), because an `evoxc` key cannot cross the graph boundary as data.

## Known Issues / Notes for Agents
No open correctness or portability issue: `measure` on all five routes is `tobytes()`-identical to `execute_distance` on every in-contract payload, every graph's StableHLO export carries no deferred op and no unsigned dtype, and the merge, dense, index-free and grouped graphs all compile on llvm-cpu and rocm gfx942.
The route that holds the remaining CPU cost is the dense single-centre body itself, not the kernel choice: on that leg the per-call body is 22 dispatches, 6 of them serialised into a single workgroup (the four scatters plus the two rank-0-result counts), with 0 sorts and 0 matvecs, and its largest block is a 125 000-element `(500, 50, 5)` f32 gather index.
Two docstrings in this node still say the pipeline never selects the dense route because its centres are population-shaped (`base.py::measure`, `default.py::__init__`); on this tree the host leg registers `distance_centre="single"` and hands `measure` a batch-1 centre, so the dense route is the live CPU body — only the `"tiled"` (GPU-class) leg passes a population-shaped centre.
`grouped.py` and `index_free.py` have no autodoc stub in `docs/source/` (the stub rule is in `docs/CONTEXT.md`), and neither has a test (see `## Test Strategy`).
`match_rows`, `dense_slot` and `gene_measure` are kept-public entry points with no in-library caller; `gene_measure` starts its own `ConstantPool`, so a caller that already threads one should use `_measure_family`.
`base.py` and `digest.py` sit at the 1000-line ceiling: the next concern in either belongs in `layout.py`, `dense.py`, `grouped.py`, `index_free.py` or a new file.

## Cross-node needs (measured here, owned elsewhere)
`algorithm/neat/_distance.py` (`DistanceRows`) is where the remaining duplicated `constant` ops live: `prepare`/`measure` already accept a `consts=` pool and `measure` emits none of its own, while `prepare` emits ~48 once per generation — threading one pool per generation is worth ≲40 ops from this node.
`algorithm/` must keep structurally allocated keys below `genome.key_span` (or carry a raised span in the shape signature): that is what keeps the dense route exact and is the same fix that stops the execution schedule silently dropping evolved genes.
The accelerator leg's remaining per-call cost is dispatch count: the dense body's 22 dispatches and the merge's count-mode sort fan are what `index_free` + grouped `k = 2` replace, and any further win there needs the caller to group **both** speciation scans (scan 2 measures its selected centre per iteration).
`genome/gene/base.py` reads attribute columns with one kept-axis slice plus one reshape per column (~132 traced ops per generation at pop 500/1000), the largest remaining block inside `measure`.
