# distance — compatibility distance: pair-wise, merge, index-free, dense single-centre, grouped k-centre

## Intent
Answer one question per parent pair, batch-first: how different are these two genomes?
It feeds speciation, so it is symmetric, exactly `0` at identity, `0` (never NaN) for an empty pair, and normalised by the larger gene count.
Speciation measures centres against the whole population in two phases, so the population side is packed and sorted **once** (the digest) and only the centre side is per-call work.
One arithmetic in five shapes, all ending in `DefaultDistance._scalar_distance`, which is what makes them bit-identical rather than merely close:
- the pair-wise `__call__` (two explicit parents; parity tests);
- `prepare` + `measure` **merge** (`digest.py`), the sort-based successor test the other shapes are measured against;
- `prepare` + `measure` **index-free** (`index_free.py`), an equality table instead of the sort, selected by `state.distance_formulation == "index_free"`;
- `measure` **dense single-centre** (`dense.py`), a key→gene scatter/gather for a batch-1 centre — the route the CPU pipeline takes;
- `measure` **grouped** (`grouped.py`) against `group_digest(digest, k)`: `k * P` centre rows in one call, the accelerator leg's shape.

## API Surface
`BaseDistance.__call__(state, genome, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2…, conn_attrs2) -> (P,) float32` validates both parents field by field (matching shapes, key rank 2 or 3, attribute rank 3, keys and attributes agreeing on `(P, M)`; a violation raises `ConfigError`) and returns node + connection distance.
`prepare(state, genome, node_keys, node_attrs, conn_keys, conn_attrs, *, consts=None) -> DistanceDigest` runs once per generation; `measure(state, genome, centre…, digest, *, consts=None) -> (R,) float32` takes a centre batch of `1` (broadcast, dense route when enabled) or `P` on a plain digest and exactly `group * P` on a grouped one.
`_merge_both` is the one spelling of the row-wise route (both families, one `evoxc.add`) shared by the plain and grouped paths; `_measure_single_centre` is the dense hook (`None` in the base class) and `_single_centre_enabled` its host twin (`False` in the base class, so `measure` validates the dense precondition before emitting an op).
`_measure_family` is the per-family driver (`index_free.alignment(...)` then `distance_from_alignment(...)`), and `gene_measure` is that body with a private pool (no in-library caller).
`DefaultDistance(compatibility_disjoint=1.0, compatibility_weight=0.4, dense_single_centre=True)` — both weights finite and non-negative (`ConfigError` at construction) — exposes `gene_distance` (pair-wise alignment), `distance_from_rows`, `distance_from_alignment`, `_scalar_distance`, `_tail_constants` and the two dense hooks; `dense_single_centre=False` forces the row-wise merge everywhere.
`_scalar_distance(cnt1, matched, cnt2, attribute_distance, pool, *, consts=None)` is `(non_homologous * compatibility_disjoint + attribute_distance * compatibility_weight) / max(cnt1, cnt2)` with `non_homologous = cnt1 + cnt2 - 2 * matched` and the denominator floored at `1.0`, so an empty pair is `0.0` with no second `select`; `attribute_distance=None` (a zero-attribute family) drops the attribute term.
`digest.FamilyDigest` (9 fields), `digest.AlignedGenes(rows, homologous, count, matched)`, `digest.DistanceDigest` (19 fields, node family first); `field_names` is `self._fields` and `test/unit/genome/test_distance_digest.py` pins that literal order, so a new digest concern belongs in a **new** class (`GroupedDigest`), never a field.
`digest.prepare_family(state, gene, keys, attrs, *, key_span, consts=None, dense=False, tail=None)`, `digest.measure_alignment(gene, keys, digest_keys, digest_key_cols, *, statics=None, consts=None) -> AlignedGenes`, `digest._key_row_matches` (the marker confirmation the merge and index-free share), `digest.match_rows` (public, no caller).
Per-module surface (each name's role is in the Routing Table): `layout` holds `MeasureStatics`/`AttrStatics`/`DenseLayout` with `build_statics`/`build_attr_statics`/`build_grouped_statics`/`build`, `reorder`, `key_fold` and the geometry `_KEY_BASE`/`_FOLDED_KEYS`/`dense_width`/`dense_rows`/`dense_slot`; `dense` holds `enabled`/`measure_centre`/`FamilyTerms`/`_family_terms`/`_stack`/`_trailing_columns`/`_DENSE_MAX_BYTES = 8 MiB`; `grouped` holds `ACCELERATOR_GROUP = 2`/`GROUP_ROW_BUDGET = 4096`/`GroupedDigest`/`group_digest`/`group_size`/`for_state`/`centre_batch`/`validate_centre`/`validate_family`; `index_free` holds `DISTANCE_FORMULATION_KEY`/`DISTANCE_FORMULATION_MODES`/`formulation_mode`/`selected`/`alignment`/`resolve`.
`consts.ConstantPool` (`i32`/`i64`/`f32`) memoises rank-0 constants per **trace** — a `SymbolicTensor` belongs to one builder, so a pool is never module-global — keyed by `repr` so `-0.0` and `0.0` stay distinct, signed dtypes only.
`prepare`/`measure`/`group_digest`/`resolve` are **plain traced helpers**, never `@evoxc.defn` (a defn cannot call a defn), so the caller's graph owns them; a digest is a pytree of tensors and may be captured in a closure across a trace.

## Merge algebra (`digest.measure_alignment`)
A gene row folds into one `int64` composite, positionally and most significant first in base `_KEY_BASE = 2**31`: a node key is itself, an `(in_key, out_key)` connection key is `in * 2**31 + out`, unrolled as `multiply`/`add` steps rather than a weighted `reduce_sum` (an innermost-axis integer reduction costs an order of magnitude more than the elementwise pair).
`2**31` is the whole non-negative `int32` key range, so the fold is injective for **every** legal key and never consults `key_span` (`S` bounds only the dense table and the schedule, never an identity); digits need no per-column gate, and an absent row needs no special case because the payload contract makes every key column `I_INF`, which folds to the side's padding sentinel by construction.
The **centre side of a multi-column key family folds with one `dot`**: `_pack_centre` contracts `cast(keys, int64) (R, M, 2)` against `fold_i64 (2, 1)` `[2**32, 2]`, so `k0 * 2**32 + k1 * 2` lands in 4 traced ops (cast, dot, reshape, `not_equal`) instead of 11, and that cast **stays** because a mixed-dtype `dot` traces and runs on numpy but exports an invalid `dot_general` with no `lower()`-time error, while `multiply` is safe (the elementwise writer inserts a `convert`) — which is how the node family's single key column folds in one op.
Two folded columns are all an `int64` composite holds (`2 * 31 = 62` bits), so a gene with more columns (`OriginConn`'s `historical_marker`) folds its first two and **verifies** the rest row for row (`_key_row_matches` against `digest_key_cols`), keeping homology equal to full-tuple key-row equality.
The low bit of the sort key is the side tag (population `1`, centre `0`); each side's padding rows collapse onto their own even sentinel — `_PAD_CENTRE = I_INF * _FOLD_HI + I_INF * _FOLD_LO = 2**63 - 2**32 - 4` and `_PAD_POPULATION = _PAD_CENTRE - 2` — which lets the `dot` path skip its `select` and makes "differs by one, right neighbour population-tagged" a complete homology test, because no padding adjacency can pass it and the parity proves the neighbour is a real population gene.
The merge concatenates the **digest side first**, the centre second and one **trailing column** of `_PAD_CENTRE` third: a population gene's merged index *is* its digest row, the tail reads its row table off the successor, and every centre gene has a successor in range, so the successor gather needs no `minimum` clamp and no in-range mask.
Sequence per family: `concatenate` to `(R, 2M + 1)`, one **stable** `argsort`, its inverse via a second **stable** `argsort` of the permutation (two ops, where scattering the ranks costs four to eight), then two centre-width gathers; nothing later is `2M`-wide, and `evoxc.slice(x, start, limit)` takes **lengths**, which is why the centre slice is `((0, count), (pop_size, count))`.
`stable=True` is a **performance** rule, not a tie rule: numpy's stable kind is timsort, so the already-ascending digest half is a detected run (the merge's two sorts 2.49 → 0.57 ms per `(1000, 200)` `int64` block at `M = 100`, the inverse permutation 1.05 → 0.29 ms), and no sort here has a meaningful tie — a homologous pair differs by one, real composites are unique inside a genome, only padding rows compare equal — so stability also pins tie order to input order and matches a compiled backend's count-mode `argsort`.
Sort cost is superlinear in **row width**, which is why fusing the two families' merges into one sort loses.

## Digest fields and the once-per-generation contract
`node_keys (P, N) int64` / `conn_keys (P, E) int64` — injective packed composites, ascending with the padding sentinel last; `node_attrs` / `conn_attrs (P, M, A) float32` — the attribute rows permuted into that same order, absent rows keeping their `NaN`.
`node_count` / `conn_count (P,) int32` — real genes per individual, the length of the valid prefix; `node_key_cols` / `conn_key_cols (P, M, K) int32` — key columns in the same order (the exact-match oracle for a key wider than `_FOLDED_KEYS`; a narrower key keeps the *unpermuted* table and nothing reads it).
`node_dense` / `conn_dense (P, M) int32` — the **star** slot (`select(real, slot, pad_i32)`, permuted into the digest's order) so `owner_at < count` alone is the dense route's homology mask; `node_real` / `conn_real (P, M) bool` — the in-range mask.
`node_oor` / `conn_oor (P,) int64` — `count - reduce_sum(real)`, i.e. present genes whose key lies outside `[0, key_span)`, the dense precondition as a host-readable diagnostic: two traced ops per family, computed whether or not that route is enabled, and nothing branches on it in-graph.
`tail_counts (2, P) int32` — the two families' population counts stacked on a leading axis, `cnt2` of the dense route's tail, built once because that route traces the tail once for the pair (`enp.zeros((0, 0), int32)` when the dense gate is off).
`node_statics` / `conn_statics (MeasureStatics)` — the row-wise route's scaffolding, built once in `prepare_family` from one shared pool, which is why `measure` traces no `constant` and no index table of its own; `node_layout` / `conn_layout (DenseLayout)` — the dense route's, built only when `dense = enabled(node_gene) and enabled(conn_gene)` holds (decided once in `prepare`), so a merge-only configuration never materialises the two big table bases.
A gene family with no attribute column (`attr_specs = ()`) contributes an empty `(P, M, 0)` block: `_gather_rows` returns it unchanged (a zero-width row has exactly one permutation), `AttrStatics.base` is the `(0, 1)` placeholder, and the distance is the structural term alone.
`prepare` writes no RNG and touches no host memory, so a digest is valid for one generation and cacheable for the whole speciate pass; the centre is **never** prepared — `measure` packs its key rows itself (`_pack`, `_pack_centre`, `dense_rows(..., flat=True)`, or the index-free `_centre_composites`).
Nothing that does not depend on the centre may live in `measure`: every rank-0 scalar, every per-individual flat index block and every flat view of a population block travel in the digest.
`NEAT.tell` calls `prepare_distance` exactly once per generation and reuses the digest for every centre of both speciation phases (`2 * species_size` rows; one `measure` call per row on the host leg, one per group of `k` in scan 1 on the accelerator leg).

## Dense single-centre route (`dense.py`)
A genome is a sparse table of `(key, gene)` rows and NEAT keys are small integers, so a **centre** scatters into a table indexed by the key itself and **gathers** at the population's own dense index: node slot `= node_key` (width `S + 1`), connection slot `= in_key * S + out_key` (width `S * S + 1`).
Two cells per table are not genes: the **dump** cell `width - 1` catches every centre row whose key is absent or outside `[0, S)`, and the **padding** cell `width` is never owned and is what a population gene with an unusable key reads; both start at the gene count (an impossible row index), so `owner_at < count` is the whole homology test and no out-of-range index reaches the backend.
Per family per call: one `concatenate` of the `(M, 1) float32` centre row index with the `(M, A)` attributes into one update block → **one** `scatter` into the merged `(width + 1, 1 + A) float32` table at `slot` → **one** `gather` at the population's `dense` block → the owner column sliced and cast back to `int32` → `matched = owner_at < count`, ANDed with exact marker equality when the gene has columns past `_FOLDED_KEYS` → `gene.distance` against the attribute columns of the same gathered block → a flat `scatter` that reorders the per-population-gene distances into the **centre's own row order** → `reduce_sum`.
**One table, one scatter — a portability requirement, not a cost dodge.** `evoxc`'s StableHLO writer emits an `i32 → i64` `convert` of every `scatter`'s index operand, upstream IREE common-subexpressions two identical converts, and its StableHLO → Linalg conversion then wants `i32` indices and inserts two conflicting materialisations, so `iree-compile` dies on `failed to legalize unresolved source materialization from ('tensor<50x1xi64>') to ('tensor<50x1xi32>') that remained live after conversion` — one `scatter` compiles, three with three **distinct** index tensors compile, three sharing one index tensor fail, and a "distinct" index that canonicalises back (`add(idx, 0)`, `select(true, idx, idx)`) fails too, whatever the destination rank, width or index count.
A gene with trailing marker columns is therefore resolved by **gathering** the centre's own key rows at the owner index (`center_markers` = the centre's trailing key columns with the layout's `marker_pad` row appended, gathered at an index always in `[0, M]`), never by a marker table of its own, so each family emits exactly **two** scatters at different index expressions: the merged table at `slot` and the reorder buffer at a flat `(P*(M+1),)` index.
That reorder is the bit-identity requirement (the tail sums over the *centre's* rows in the centre's row order, exactly like the merge, because float addition is not associative), and the marker-column `select` is a correctness requirement (a `(in_key, out_key)` slot says nothing about `historical_marker`, so a population edge sharing the endpoints with a different marker is not homologous and must not write its `|Δweight|` there).
Counts: `matched` from the in-range mask, `cnt1` from the centre's present rows (`key != I_INF`, the predicate the digest's `count` uses), `cnt2` from `digest.tail_counts`; duplicate key rows inside one genome are outside the payload contract, and the dump redirect makes them a last-writer-wins scatter instead of a crash.
Static gate (`dense.enabled`, never a runtime branch): a family qualifies while its merged centre table fits `_DENSE_MAX_BYTES = 8 MiB` of float32 (`width * 4 * (1 + attr_width)`, padding cell included) and the width stays inside `int32`, and a trailing marker column costs no table cell because markers are gathered rather than tabulated; `S = 150` gives `22 501` connection cells (≈0.2 MB), `S = 500` (≈2 MB) qualifies, and a wider span falls back to the merge because the table grows with `S²` where the merge grows with the gene axis `M`.
**Both** families must qualify or neither does (a partially dense `measure` would have to broadcast the centre payload for the other family), the route is taken only for a batch-1 centre **and** only while `index_free.selected(state)` is false (that formulation must never enter the scatter-based route), and when the gate fails `measure` broadcasts the centre itself (`_broadcast_payload`, 12 ops) and runs the merge.
Precondition — gene keys inside `[0, key_span)`, validated on host data and reported as `node_oor`/`conn_oor`: an out-of-range key is **unmatched** here (exactly like `common.tensorization` drops it) while the merge still matches it, so `measure` validates whenever `_single_centre_enabled` holds and a leaf is host data (`_host_array` answers `None` for a `SymbolicTensor`, so a traced digest or centre is skipped silently).
The refusal names the family, the offending individuals or centre rows, `genome.key_span` and both remedies (keep every allocated structural key inside `[0, key_span)`, or construct `DefaultDistance(dense_single_centre=False)`), is pure NumPy with **zero** traced ops, and runs before the hook emits an op, so a host call answers `TensorNEATError` instead of a backend `TypeError`; inside a trace a value-dependent raise is impossible, so the guard is a host-call guarantee only.
The live allocator (`algorithm/neat/_keys.py::node_keys_for_split` wraps every allocated key into `[max_nodes, key_span)`) keeps live payloads inside the window: `node_oor == conn_oor == 0` over eight cells × generations 0-39, worst present key 149 against `key_span = 150`.

## Index-free formulation (`index_free.py`)
`state.distance_formulation` picks how a centre gene finds its homologue in the already-prepared digest: `"merge"` (the sort-based successor test) or `"index_free"` (an `equal` table, no `argsort` at all).
The centre composites carry the **population** tag (`pack * 2 + 1`): rank-2 keys fold with `_pack(..., scale=tag_scale_i64)` + `_tagged(..., _TAG_POPULATION, pad_centre_i64, None, one_i64)` in four ops, rank-3 keys with width `>= _FOLDED_KEYS` fold with `_pack_centre` + `select(valid, add(composite, one_i64), pad_centre_i64)`.
So a homologue is **plain equality** — the comparison *is* the homology test — and the two sides cannot alias: real composites of both sides are odd and top out at `2**63 - 2**32 - 3`, while both padding sentinels are even (`2**63 - 2` and `2**63 - 4`), so an absent centre row equals no population composite and the population side needs **no presence mask** (the digest's `2M`-wide `valid` block is never read here, and `prepare_family` gained no constant, no table and no op for the switch).
Body per family: `table = equal(reshape(centre_tagged, (P, M, 1)), reshape(digest_keys, (P, 1, M)))` → `(P, M, M) bool` (two view reshapes and one compare), then `columns = enp.arange(0, count, int32)`, `no_match = pool.i32(count)`, `col = reduce_min(select(table, columns, no_match), axes=2)`, `homologous = less(col, no_match)` — "the first matching population column", the row the merge's successor test finds, with one reduction answering both the column and the mask so no second table-wide pass is paid.
`argmax` is deliberately avoided: it materialises a full `(P, M, M)` `int64` iota whose dispatch has no operands, so IREE's scheduling leaves it outside every `stream.async.execute` region and `iree-compile` fails the assembled graph with `'stream.async.dispatch' op : streamable op expected to be in an execution region` on both `llvm-cpu` and `rocm`, even though `ops.status("argmax")` reports `v1` and `lower()` sees nothing wrong.
A key width past `_FOLDED_KEYS` ANDs in exactly the merge's confirmation (`digest._key_row_matches` against the candidate digest row), so homology stays full-tuple key equality.
`resolve` itself takes **no** `state`: the one host gate is `index_free.alignment(state, …)`'s `selected(state)`, which `BaseDistance._measure_family` calls, so only the `prepare` + `measure` pathway (`measure`, `gene_measure`) can reach this formulation — the pair-wise `BaseDistance.__call__` → `DefaultDistance.gene_distance` → `alignment.find_homologous` route reads no `distance_formulation` and always takes the host merge.
`rows = select(homologous, col, statics.zero_i32)`, and the record is `AlignedGenes(rows, homologous, reduce_sum(valid, axes=1), reduce_sum(homologous, axes=1))` — the shapes and dtypes the merge returns (`count`/`matched` are `int64`, as a bool `reduce_sum` returns) — and everything below the table is row-local, so `distance_from_alignment` → `_scalar_distance` consumes it unchanged while a `GroupedDigest` and a broadcast batch-1 centre keep working with no special case.
Cost trade on the numpy reference interpreter (measured at `9b728405`): 84 marginal traced ops against the merge's 93 but **2.1–2.6×** the wall clock, because the `(P, M, M)` `equal`/`select`/`reduce_min` chain is an `M²` element pass (12.5 M bools for the connection family at pop 500) where the merge sorts `2M + 1` columns; on a compiled/dispatch-bound target the same table is the win — `3 · R · M²` element touches per call against the merge's `≈ 405 M`, and 0 sorts against 8 reduction families — so the route is that leg's, never a CPU win, and the numpy default stays `"merge"`.
**Duplicate key rows inside one genome are the one measurable divergence**, and they are outside the payload contract: with a centre carrying key `7` three times against one digest row the merge's successor test marks only the **last** duplicate homologous (`matched 3`) while the table marks **every** duplicate (`matched 5`, all pointing at the first matching column); duplicate rows on the population side agree, and matching the merge would cost a per-call tie-break op on the hot path.

## Grouped route (`grouped.py`)
Every op of the merge, the aligned-attribute gather, `gene.distance` and the scalar tail is **row-local**, so a `(k * P, M)` centre against a `k`-times-tiled digest is exactly `k` separate `P`-row measurements in the same per-row float summation order; what hard-coded `P` was only the scaffolding (`offsets`, `offsets_plus_one`, `pad_column_i64`, `AttrStatics.base`, `attrs_rows`).
`group_digest(digest, k)` does two things: it tiles each of the eight digest arrays with **one** `evoxc.concatenate((x,) * k, axis=0)` (`k == 1` returns the operand unchanged, zero ops), and it rebuilds both statics bundles with `layout.build_grouped_statics` at `rows = k * P`, reusing every rank-0 scalar, `fold_i64`, `zero_f32` and `tail` of the plain digest; `group_digest(k=1)` traces 16 ops and `group_digest(k=2/4/P)` 24.
Row `j * P + p` of the result is `distance(centre row j * P + p, population individual p)`, so a caller hands over the `k` centre batches **concatenated on axis 0** in slot order and slices the `(k * P,)` answer back.
`measure` dispatches on `isinstance(digest, GroupedDigest)` straight to `_merge_both` (no dense route and no broadcast on that path), and `validate_centre` raises `ConfigError` naming both shapes plus `group`/`pop_size` when the centre batch is not exactly `rows`, when the grouped digest's own leaves disagree, or when a rebuilt statics table is not shaped for `rows`.
`k` is chosen by `group_size`, the one place the decision is made: it answers **`1` unless `common.schedule_accelerator.is_accelerator(state.kernel_mode(state))`**, so the numpy/CPU leg is handed its plain digest unchanged and its dispatch count, wall time and peak RSS do not move; an accelerator state gets `max(1, min(ACCELERATOR_GROUP, GROUP_ROW_BUDGET // pop_size, species_size))`, i.e. `k = 2` up to pop 2048 and `k = 1` above it (`species_size = 1` degenerates to `1` too).
`for_state` returns the argument digest and `1` when `group == 1`, else `group_digest(digest, group)`, so `k = 1` is literally the plain path rather than a one-wide tiling, while `centre_batch(payloads)` merges `k` one-individual centre payloads with one `concatenate` per field; both are host-side (a non-`int`/non-positive `pop_size` or `species_size` raises `ConfigError`, the answer is a Python `int`), which keeps every seam a host branch and never a traced value.
The route **is** wired: `algorithm/neat/_distance.py::DistanceRows.matrix` groups the generation's digest with `for_state`, scans `K // k` groups instead of `K` rows, gathers each group's `k` centre rows, merges them with `centre_batch` and makes one `measure` call, rebuilding the `(K // k, k * P)` stack into `(K - K % k, P)` and measuring at most `K % k` trailing rows singly against the plain digest.
The scan body returns a rank-1 `(k * P,)` step on purpose: `evoxc.scan` stacks `y` into `(groups,) + y.shape`, and a `(k, P)` `y` would make that a **rank-3 axis-0 `scatter`**, which the StableHLO v1 exporter refuses outright (`BackendError: op 'scatter' on a rank-3 operand along axis 0 is not supported`).
The host leg is where the grouped form loses, which is why it stays gated off there rather than unwired: on `xor_p500` `k = 2` cuts dispatched ops 7 592 → 6 589 (−13 %) but raises peak RSS 233.8 → 253.2 MiB (+19.4 MiB) because the 2× wider `(2P, 2M + 1)` merge intermediates stop fitting in cache, and its numpy wall time turns bimodal at process level — 152–165 ms in fast processes against 196–253 ms in 7 of 13 fresh default-environment processes, stable at 152 ms against 159–162 ms when glibc is forced onto brk with `MALLOC_MMAP_THRESHOLD_`/`MALLOC_TRIM_THRESHOLD_` raised.
`k = 4` reads +15 % wall / +30.5 % peak RSS and a second pre-measured centre table +58 % wall, so the trade is op count and call boundaries for allocator-sensitive memory, and a caller must measure its own arrangement rather than assume `k > 1` is a speed-up.
Bit identity holds on that argument rather than by measurement alone: the body's traced op count is the plain merge's and independent of `k`, and the result is `tobytes()`-equal to `k` plain calls over pop 100/500/1000 × {`DefaultNode` + `DefaultConn`, `OriginNode` + `OriginConn`} × 10 evolved generations, as is the generation-level digest gate at `P = 500` and `P = 1000`.

## Formulation statics (the device seam)
Three trace-time strings reach this node through `_static_config`'s closure, never as graph-boundary tensors: `distance_centre`, `distance_formulation` and `kernel_mode`.
`host_payload._formulation_statics` derives all three from one decision — whether the resolved device **kind** is GPU-class (`"rocm"`, `"hip"`, `"hips"`, `"cuda"`, `"vulkan"`, `"gpu"`, case-insensitive) — as `("tiled", "index_free", "accelerator")` for such a kind and `("single", "merge", "host")` for every other kind and `None`, a missing entry resolving the same way, and all three sit in the executable-cache signature (`host_payload._formulation_signature`), so changing one rebuilds exactly one executable.
This node reads two of them: `index_free.formulation_mode`/`selected` for `distance_formulation` and `grouped.group_size` via `common.schedule_accelerator.kernel_mode`/`is_accelerator` for `kernel_mode`; both validate their value and raise `TensorNEATError` naming the accepted spellings (no silent fallback).
`distance_centre` is read only by the caller (`algorithm/neat/_validation.distance_centre_mode`) and by `host_payload`'s signature, but it decides which route this node runs: `"single"` hands `measure` a batch-1 centre (the dense route, i.e. the live CPU leg) and `"tiled"` a `pop_size`-row centre (the merge, or `index_free` on a GPU-class kind), so both centre widths must stay accepted.

## Cost law of this node
On the numpy reference interpreter one **dispatched op** costs ≈19–20 µs on rank-0/small operands, so op count is the budget for narrow passes and element width the budget for the wide ones; `constant`, `reshape` and `arange` each cost a full op and evoxc never deduplicates constants.
A per-call body runs `2 * species_size` times per generation, so anything that does not depend on the centre belongs in `prepare` — the rejected alternative (a private `ConstantPool` plus per-call `enp.arange`/`batch_offsets` inside `measure`) cost 536 rank-0 constant ops and 320 index ops per generation.
A merge `measure` call is **sort-bound, not dispatch-bound**: the two `argsort`s plus their two `int32` casts are 27–30 % of the call and every other op is an ordinary `(R, M)` pass at 5–90 µs, while the dense route emits the same kinds of pass with no `(R, 2M + 1)` block, so nothing in it grows with the merged width.
Every `int64` block is element volume that reaches the wall clock: `(P, 2M)` `int64` is 6.4 MB at `4P = 4000`, `max_conns = 100`, and the merge holds two of them plus the `int32` permutation, which is why the connection family costs twice the node family at the same op count and why the dense route wins on exactly that family.
`measure` holds one `(R, M, A)` temporary per call (plus one `(R, M + 1)` on the dense route) and a grouped call holds those shapes at `k * P` rows, so a new full-size temporary here is a real regression even when it saves ops.
Traced op counts, static and independent of `P`: `measure` marginal **98** on the default batch-1 dense route and `prepare` **167**, as the shipped guard in `test/unit/genome/test_distance_digest.py` records (ceilings 120 / 210); the merge body at a `P`-row centre traces 93 and the index-free body 84 (measured at `9b728405`); `execute_distance` 225; `prepare` emits ~48 of its ops as `constant`s, `measure` none and `group_digest` none of its own either.
Executed dispatches on the numpy leg of this worktree: `xor_p500` **7 592**, `cartpole_p100` **30 994**.
Per-generation wall time on this worktree (numpy then rocm): `xor_p100` 33.04 / 17.42 ms, `xor_p500` 112.68 / 13.24 ms, `xor_p1000` 177.43 / 16.29 ms, `custom_pagie_p500` 847.13 / 16.18 ms, `cartpole_p100` 248.70 / 150.41 ms — 1.9× / 8.5× / 10.9× / 52× / 1.65× faster on the GPU-class leg the index-free + grouped formulation exists for.
On iree+rocm a **flat** graph pays ≈63 µs of fixed cost plus ≈2.2–2.5 µs per dispatch, a `while` iteration ≈50 µs of region overhead, and a `Tensor.to(cpu)` ≈47–60 µs per leaf, so above a few hundred kernels the lever there is dispatch count, not arithmetic — the same law the formulation switch is priced on, since an `evoxc.scatter` lowers to one single-threaded workgroup at ~7–19 ns per destination cell and a count-mode `argsort` expands into `8 · E · R · E` element touches for `E = 2M + 1`.

## Constraints
- **No unsigned dtype in a graph** — `iree`'s declared dtype set has none (`float16/float32/float64/int8/int16/int32/int64/bool`), so a `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the whole graph; use same-width signed carriers, and write a range test as `logical_and(greater_equal(key, 0), less(key, S))` because the `>= 0` half is not decoration — a negative structural key must land in the dump slot exactly as `I_INF` does.
- Trace-time kernels only: no `jax`/`torch`/`numpy.random`, no `vmap`/`scan`/`while_loop`/`cond`, no Python loop over individuals or pairs, no eager NumPy on the compute path; nothing here is differentiable and nothing draws RNG, so repeated calls are bit-identical.
- Every static decision is a **host** value (gene geometry, `key_span`, `dense_single_centre`, the digest class, the three formulation strings), no traced value drives Python control flow, and a partially dense `measure` is impossible by construction.
- Never build an `O(M²)` per-pair comparison matrix (`(P, 100, 1) < (P, 1, 100)` is 3.3 ms, a `(P, 100, 100)` reduce 4.4 ms) except the index-free table, and read any such table's column with `select` + `reduce_min`, **never `argmax`**.
- Never let two `scatter`s in one graph share an index expression, and never use `evoxc.gather(..., axis=1)` on a rank-3 block (105–163 ms at `(P=1000, M=100)`); every row permutation is a flat gather on a `p * R + col` index block, and the one reorder scatter is raw because every index is already inside `[0, M]`.
- Mixed-dtype operands are allowed for **elementwise** ops only (`multiply`, `add`, `subtract`, `maximum`, `select` — the writer inserts the `convert`), never for `dot` or `concatenate`, whose operand dtypes it forwards verbatim.
- Never derive a composite radix from `key_span`: the fold uses `2**31` for injectivity, and the dense table derives its *slot* from `key_span` only because that is an address, not an identity.
- **Population-scaled seeds go through `genome.window.fill`, never `enp.zeros`/`enp.full`**; only genuinely static tables (`key_span`-scaled, index `arange`s) and the dense layout's own `table`/`marker_pad` keep `enp.zeros`/`enp.full`.
- The attribute distance is masked/redirected so it never reads a non-homologous slot (a `NaN * 0` product would poison a sum), and int option columns contribute `!=` (one per changed option) rather than `|id1 - id2|` — that rule lives in `BaseGene.distance`.
- `attr_width == 0` is supported: `_gather_rows` returns the empty `(P, M, 0)` block unchanged, the attribute term is skipped, and every row stride built from an attribute width sits behind a static width branch (`enp.arange(0, n, 0)` is a `ZeroDivisionError` on the reference backend); key tables arrive as `(R, M)` or `(R, M, K)` via `alignment.key_rows`, and rank-0 integer constants come from the pool because a Python literal widens an `int32` tensor to `int64`.
- Errors: a parent shape mismatch, a wrong key width, a digest built for another gene axis, or a centre batch the digest does not accept (plain: not `1`/`P`; grouped: not `group * P`) raise `ConfigError` (`TensorNEATError`), a host-resident leaf breaking the dense key precondition raises `TensorNEATError`, and `evoxc` errors propagate unchanged.
- Files ≤ ~1000 lines, one job each: `base.py` 1000 (at the ceiling — a new body belongs in a new file and `base.py` gains only a switch), `digest.py` 953, `layout.py` 748, `default.py` 524, `grouped.py` 521, `dense.py` 380, `index_free.py` 363, `consts.py` 107.

## Test Strategy
`test/unit/genome/test_distance_digest.py` is the shipped regression spec: one module-scoped evolved population (seed-42 `Pipeline` XOR, `pop_size = 100`, `species_size = 5`, `max_nodes = 50`, `max_conns = 100`, 2 `step`s, both `DefaultDistance` variants) pinning `prepare` + `measure` `tobytes()`-equal to `execute_distance` on the batch-`P` centre, the batch-1 dense centre and the `dense_single_centre=False` merge, self-distance `0` and an empty pair `0`, two independent digests measuring identically, the `node_count`/`conn_count`/`tail_counts`/`node_oor` static contract with its `ConfigError`, and the op budget (`MEASURE_OP_CEILING = 120` / `PREPARE_OP_CEILING = 210` against the measured 98 / 167).
One more test pins the payload invariant the `dot` fold relies on: an absent gene row carries `I_INF` in **every** key column, checked on a real evolved payload for both shipped key layouts (`DefaultConn`, `OriginConn`'s history column).
`test/unit/genome/test_distance.py` covers the pair-wise route, the self-distance and the sentinel/zero-attribute cases; `test/parity/test_distance.py` holds `execute_distance` exactly against the frozen legacy implementation and needs the `bench` extra.
**No committed test selects the accelerator leg**: neither `distance_formulation="index_free"`, nor `distance_centre="single"`/`"tiled"` beyond the pipeline default, nor `kernel_mode="accelerator"`, nor `group_digest` has a test here (`./test` is a sibling node), so those formulations are gated by hand-run identity matrices only — index-free over 192 cells ({pop 100/500/1000} × two gene families × generations 0-7 × four centre shapes) plus out-of-span keys, duplicate population rows and a zero-attribute conn gene; grouped over 6 family/pop cells × 10 generations; dense over 1 500 centres.
A bad `distance_formulation` value raises `TensorNEATError` naming both accepted spellings, and a bare `State()` reads `"merge"`/`selected = False`.
The run-level gate for anything this node touches is the bit-exactness protocol of `../CONTEXT.md` (10 seed-42 `Pipeline.step` generations at `P = 500` and `P = 1000`, one sha256 per generation over `dtype.str + repr(shape) + tobytes()` of the four payload arrays plus `fitnesses`): `P=500` → `d43edd0d3c19fe8f6bb4a1001246c40faaf82bf431e95e3a12f6c9b4a3e4c96e`, `P=1000` → `caba83eeebe50e86941fb7997c184e59f4702388d0826d77401a68dcb166bd45`, and index-free and grouped reproduce the same pair as the merge.
A performance claim is only accepted from an **interleaved two-process A/B** (a pristine `git archive` checkout against the working tree selected by `PYTHONPATH`, alternating fresh processes, `REPS >= 10` bodies per graph, medians over ≥6 rounds), because the box drifts ±30 % between sessions.
StableHLO portability gate: `evoxc.lower(graph, backend="iree").payload["mlir_text"]` plus `iree-compile --iree-input-type=stablehlo --iree-hal-target-backends=<llvm-cpu | rocm --iree-rocm-target=gfx942> --compile-to=executable-configurations`; the merge generation graph needs `--iree-llvmcpu-stack-allocation-limit=1048576` on llvm-cpu (a property of that graph, not of a change), while the dense and index-free graphs need no flag.
Trace a bound method through a closure (`lambda *a: obj.method(state, *a)`) and build rank-0 RNG keys *inside* the trace (`evoxc.random.key(seed)`), because an `evoxc` key cannot cross the graph boundary as data.

## Known Issues / Notes for Agents
No open correctness or portability issue: `measure` on all five routes is `tobytes()`-identical to `execute_distance` on every in-contract payload, every graph's StableHLO export carries no deferred op and no unsigned dtype, and the merge, dense, index-free and grouped graphs all compile on llvm-cpu and rocm gfx942.
What holds the remaining CPU cost is the dense single-centre body, not the kernel choice: that body is 22 dispatches, 6 of them serialised into a single workgroup (the four scatters plus the two rank-0-result counts), 0 sorts, 0 matvecs, and its largest block is a 125 000-element `(500, 50, 5)` f32 gather index.
Two docstrings here still say the pipeline never selects the dense route because its centres are population-shaped (`base.py::measure`, `default.py::__init__`); the host leg registers `distance_centre="single"` and hands `measure` a batch-1 centre, so the dense route is the live CPU body and only the `"tiled"` (GPU-class) leg passes a population-shaped centre.
`grouped.py` and `index_free.py` have no autodoc stub in `docs/source/` (the stub rule is in `docs/CONTEXT.md`) and no committed test (see `## Test Strategy`).
`match_rows`, `dense_slot` and `gene_measure` are kept-public entry points with no in-library caller, and `gene_measure` starts its own `ConstantPool`, so a caller that already threads one should use `_measure_family`.
`base.py` and `digest.py` sit at the 1000-line ceiling: the next concern in either belongs in `layout.py`, `dense.py`, `grouped.py`, `index_free.py` or a new file.

## Cross-node needs (measured here, owned elsewhere)
`algorithm/neat/_distance.py` (`DistanceRows`) is where the remaining duplicated `constant` ops live: `prepare`/`measure` already accept a `consts=` pool and `measure` emits none of its own, so threading one pool per generation is worth ≲40 ops from this node.
`algorithm/` must keep structurally allocated keys below `genome.key_span` (or carry a raised span in the shape signature): that keeps the dense route exact and is the same fix that stops the execution schedule silently dropping evolved genes.
The accelerator leg's remaining per-call cost is dispatch count — the dense body's 22 dispatches and the merge's count-mode sort fan are what `index_free` + grouped `k = 2` replace — and any further win there needs the caller to group **both** speciation scans, since scan 2 measures its selected centre per iteration.
