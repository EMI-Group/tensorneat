# mutation — plan-based structural and value mutation, batch-first

## Intent
Turn one population-wide RNG key into an edited gene payload: four structural operations — add-node, delete-node, add-conn, delete-conn — each with its **own independent per-individual gate**, run in that fixed order, followed by attribute mutation of every existing gene.
`BaseMutation.__call__` splits the call key into `(structure_key, values_key)` and runs `mutate_structure` then `mutate_values`.
One call may apply up to **four** structural changes to one individual (at most one per operation) — the frozen legacy library's chaining, and the reason the stages compose sequentially instead of through one merged plan.
Nothing here allocates keys: `new_node_keys (P,)` and `new_conn_keys (P, 3)` arrive caller-allocated.
`algorithm/neat/_keys.py::node_keys_for_split` keeps every structural node key inside `[max_nodes, key_span)` with a `first_free_keys` fallback; `plan_add_node` re-validates the allocation and refuses a collision as a bit-exact no-op.

## Cost model
The reference backend is the evoxc numpy interpreter, where a dispatched op costs **≈19–20 µs** whatever its operands (a rank-0 constant, a `reshape`, a `slice` and a `broadcast` are each a whole op) plus its own array traffic.
- Rank-0 constants are real ops, so one distinct value per trace is hoisted into `EditContext` / `_StageContext` and shared by the stage that reads it.
- For recurrent `(P, tries, E)` slabs the **contiguous innermost** reduce is the cheap one (`axes=2` 0.82 ms against `axes=1` 1.65 ms at 2 M elements; `equal` 0.68 against 1.11), so do not transpose them.
- A `select` pays for the whole array while an indexed write pays only for its cells: two row writes on `conn_keys`+`conn_attrs` cost 8 ops / 1.00 ms as `select`s and 20 ops / 0.42 ms as one flat `scatter` (pop 500), so op count alone is not the budget.
- One `uniform`/`normal` on a rank-0 key costs 0.05–0.42 ms and is independent of the output shape; the kernel issues **13** of them (`masked_random_row` accounts for three) and draw-order bit-exactness forbids removing or reordering any.
- A compiled device pays a different law, measured on this worktree: iree+rocm ≈63 µs fixed per graph plus **≈2.2–2.5 µs per dispatch**, and one `while` iteration ≈157 µs when its predicate is device data (≈57 µs when the trip count is provably static) — dispatch count, not op count or arithmetic, is what dominates there (`## Cycle predicate`).

## Four-stage sequential composition
`mutate_structure` runs the four stages **in sequence**, one iteration of a Python `for index in range(_OPERATION_COUNT)` loop each.
Each stage rebuilds `EditContext` against the payload the previous stage produced (`_edit_context`), wraps it with the call's shared uniform bounds (`_stage_context`), plans exactly **one** operation (`_plan_operation`), turns that plan into one single-operation `Edit` (`_stage_edit`) and writes it with `plan.apply(..., write_nodes=..., clear_conn=...)`.
The static per-stage write flags are `_STAGE_WRITES = ((True, True), (True, True), (False, False), (False, True))`: add-node writes a node row and clears the consumed edge (slot 0), delete-node writes a node row and clears through slot 0 plus its detach mask, add-conn writes neither, delete-conn clears exactly one connection row.
Conflict rules are deliberate and match the legacy chaining: delete-node may delete the node add-node just created, delete-conn may consume an edge add-node or add-conn just created, and add-conn's duplicate / `max_in_degree` / cycle tests see the post-add-node and post-delete-node graph.
A stage that fires but whose candidate is refused (no candidate, duplicate edge, self-connection, cycle, capacity, `max_in_degree`, a colliding caller allocation) is a bit-exact no-op for that individual, and nothing is ever partially applied.
`plan.apply` is the one writer for all four stages: the node write is one row-index comparison broadcast over the attribute axis (a row equal to the array's own length matches nothing — no dump row, no flat index block), the clearing pass is one `select` per connection array merging slot 0 with the delete-node `drop` mask, and slots 1..n go through one flat `scatter` over the trailing dump cells (`_scatter_slots`), because a `select` per slot would pay whole-array traffic.
A stage whose `Edit` has zero scatter slots (delete-node, delete-conn) skips the scatter, and a stage that statically cannot write a node row or clear a connection row never traces those passes; the two node arrays share their row layout (one row comparison, broadcast), as do the two connection arrays (one stacked `(P, slots, 1)` row/validity block feeding both scatters).

## API Surface
`BaseMutation.__call__(state, genome, key, node_keys, node_attrs, conn_keys, conn_attrs, new_node_keys, new_conn_keys) -> GenomeTensors` — validates the two key shapes (`ConfigError`), then `mutate_structure` → `mutate_values`.
`BaseMutation.mutate_structure(...)` splits its key into `_OPERATION_COUNT + 1` (four operation keys in stage order, the gate key last), resolves the four gates once, and skips a stage wholesale when its probability is `0`.
`BaseMutation.mutate_values(...)` calls `genome.node_gene.mutate` / `genome.conn_gene.mutate` once each on the full `(P, N, NA)` / `(P, E, CA)` tables (one `split_n(key, 2)` inside), then re-masks with the padding pattern read *before* the mutation, so a padded row can never become finite and the key arrays are returned untouched.
`BaseMutation.structural_probabilities -> (node_add, node_delete, conn_add, conn_delete)` is the gate order a subclass supplies, and the extension points are the four plans: `plan_add_node(state, genome, key, context, node_keys, conn_keys, conn_attrs, new_node_keys, gate)`, `plan_delete_node(state, genome, key, context, node_keys, conn_keys, gate)`, `plan_add_conn(state, genome, key, context, node_keys, conn_keys, new_conn_keys, gate)`, `plan_delete_conn(state, genome, key, context, conn_keys, gate)`.
`_plan_operation` / `_stage_edit` are static Python `if` chains over the four stage numbers, so a stage traces only its own plan and its own single-operation `Edit`.
`plan.apply(edit, context, node_keys, node_attrs, conn_keys, conn_attrs, write_nodes=True, clear_conn=True)` — the two keyword flags are static specializations of the same machinery, and a `slots == 0` edit is supported (no scatter).
`_StageContext` wraps one stage's `EditContext` with the call's shared rank-0 `(low, high)` uniform bounds and delegates every other attribute read, so the plans keep reading `context.<field>` unchanged.
`DefaultMutation(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)` — each probability in `[0, 1]` else `ConfigError`; **these four are NEAT-python's values and are the operator's own defaults** (`DefaultMutation()` keeps them).
`default.py` also exports `DEFAULT_GENOME_CONN_ADD = 0.4` / `DEFAULT_GENOME_CONN_DELETE = 0.05` (module-level, not in `__all__`), which `genome/default.py` and `genome/recurrent.py` pass when their `mutation` argument is `None`, so a genome built without an explicit operator runs the rebalanced `(0.1, 0.1, 0.4, 0.05)` pair (`## Shipped connection gates`); `show_config()` renders the live operator's public attributes (`host_payload._object_config`), so `config.txt` records whichever pair the genome actually built.
`RecurrentMutation(*, p_recur=0.1, max_conn_tries=20, **kwargs)` overrides `plan_add_conn` only, so it inherits `plan_add_node` and the split validation.
`arrays.py` is the read-only flat-index toolkit: `first_row`/`random_row`/`masked_random_row` return a `(row, hit)` pair (no sentinel), `take_rows`/`take_block_at` gather row blocks from a static base index, `uniform_bounds` builds the shared rank-0 `(0.0, 1.0)` float32 pair, and `column_base`/`row_offsets`/`graph_constant`/`i32`/`flatten` build the static blocks; writing lives in `plan.apply`, so the module exports no writer, and `recurrent.py` imports `first_row`, `i32`, `row_offsets`, `take_rows` from it.
`degree.py` is the **public in-degree audit**: `in_degree(node_keys, conn_keys) -> (P, N) int32`, `max_in_degree(...) -> (P,) int32` and `violation(node_keys, conn_keys, limit) -> (P,) int32` (node rows strictly over `limit`), re-exported by `mutation/__init__.py`.
It is trace-time only, reads presence the way the write path does (`src key != I_INF`) and reports duplicate node keys as a union; it stays out of the generation path (its `(P, N, E)` intermediate is 15 traced ops / 0.3–2.1 ms at pop 100–1000), because operators enforce `max_in_degree` inline — so it has **no caller and no test** in the repo (a test gap, not a contract).

## Gate semantics (the load-bearing rule)
One `evoxc.random.uniform(gate_key, (4, P), low, high, dtype=float32)` draw per `mutate_structure` call, compared against a `(4, 1)` `float32` constant column of the four probabilities: `gate[i][p] = drawn[i, p] < p[i]`, so **each row is its own Bernoulli decision** and an individual may fire any subset of the four operations.
The rows are the operations in stage order `(node_add, node_delete, conn_add, conn_delete)`, and each gate is one axis-dropping `getitem` of the draw — four ops and no reshape.
Draw order is the reproducibility contract: `__call__` splits into `(structure_key, values_key)`, `mutate_structure` splits `structure_key` into five, stage `i` draws from `keys[i]` and the gate uses `keys[4]`.
`arrays.uniform_bounds()` is hoisted **once** per call and shared by every stage's draws; a Python float bound would embed one `float64` `constant` per draw, and `0.0`/`1.0` are exact in `float32`, so the draws are bit-identical.
At most one change **per operation per individual**, with no mutual exclusion; an individual whose gate is off writes the "no write" row and comes out bit-for-bit identical (`-0.0` and NaN included).
A probability of `0` is a true identity — the whole stage, its cycle predicate included, is elided at trace time; a probability of `1` always attempts (and can still be refused); `network_type` outside `{"feedforward", "recurrent"}` raises `ConfigError`.
Analytic at `DefaultMutation()`'s `(0.1, 0.1, 0.2, 0.2)`: `P(no gate) = 0.5184`, `P(exactly one) = 0.3744`, `P(any) = 0.4816`, `P(two or more) = 0.1072`; at the shipped genome pair `(0.1, 0.1, 0.4, 0.05)`: `0.4617 / 0.4347 / 0.5383 / 0.1036` — the measured attempt rates are in `## Known Issues`.

## Structural rules
- Add-node preserves the split topology: the consumed connection becomes `old_src -> new -> old_dst`, the new node takes `node_gene.new_identity_attrs`, the identity edge `conn_gene.new_identity_attrs` (weight `1`), the copy edge the consumed connection's recorded attributes, and both new edges take the *first two rows free before the delete*. It is refused when there is no candidate connection, no free node row, or fewer than two free connection rows.
- Add-node **validates the caller's allocation**: it refuses a split whose `new_node_keys` already appears in `node_keys` (a duplicate key would fold two rows onto one schedule slot) and one whose consumed edge points at a destination already at `genome.max_in_degree` incoming rows.
  The destination's post-write in-degree equals its pre-write count (the copy edge replaces the consumed row), so the second test is a no-op on every legal payload and the new node always ends with in-degree `1`; both fold into the plan's `ok` as one `(P, N)` equality and one `(P, E)` reduce (11 traced ops, no new rank-0 constant).
- Add-conn draws a source (inputs and outputs allowed) and a destination (inputs refused) from one `(P, 2, N)` mask block with `_fetch_two`'s single `argmax`, plus an "every slice has a candidate" test (`reduce_max` over the node axis, then `reduce_min` over the two slices) — a reduce over both axes would ask whether *every node row* is eligible and would refuse add-conn population-wide.
- Add-conn refuses an absent endpoint, a duplicate `(in_key, out_key)` pair, a destination already at `genome.max_in_degree` incoming edges, and — for `network_type == "feedforward"` — a cycle (`cycle.closes_cycle`), all against the payload add-node and delete-node left behind.
- Delete-node never names an input row (`0..num_inputs-1`) or an output row (`N-num_outputs..N-1`) and detaches every touching connection through the `Edit.drop` mask; delete-conn clears exactly one row.
- New rows always go to the first free row of the matching array; the `historical_marker` column is written only when `genome.conn_gene.uses_historical_marker`, and `new_conn_keys` columns stay `0` = add-node identity edge, `1` = add-node copy edge, `2` = add-conn edge.
- `RecurrentMutation.plan_add_conn`: one `(P, max_conn_tries, 2)` `randint` tableau plus one `(P, max_conn_tries)` `uniform` `p_recur` decision; acceptance = present endpoints & destination is not an input & not a duplicate & in-degree ok; the first accepted attempt wins by a reduce over the attempt axis (never `cond`), and **one** `closes_cycle` on the chosen edge then enforces the `p_recur` requirement. `max_conn_tries` bounds the tableau's element volume, not its op count.
- Padding never enters the recurrent confirmation slabs: a padded connection row is `I_INF` in *every* key column while an accepted candidate has two finite keys, so key equality alone excludes padded rows (the `exists` term still gates a candidate whose endpoint *is* `I_INF`).

## Cycle predicate (`cycle.py` + `cycle_accelerator.py`)
`closes_cycle(state, node_keys, conn_keys, src_keys, dst_keys, key_span)` answers "would `src -> dst` close a cycle?" as "is `src` reachable from `dst`", by one monotone frontier relaxation per formulation: a data-dependent `while_loop` on the host, a fixed-length loop of `node_count` hops on the accelerator leg.
`key_span` cannot be derived from any operand shape and is therefore the **6th positional argument** (both call sites pass `genome.key_span`); `state` is the 1st and selects the formulation.
Visibility is one host-side law, never a traced branch: every node key and every connection endpoint that must be visible lies in `[0, key_span)` — exactly the window the schedule's dense key table addresses — so an out-of-span key is invisible to the phenotype as well and the predicate treats it as a miss; `cycle._in_span` is the single spelling, shared by both formulations.
Duplicate node keys are supported: each formulation resolves keys through one *representative* row (which one is undefined), and because that map is injective on keys and every endpoint goes through it, reachability between the candidate's keys is the same for any representative choice.
The call site is **statically gated** on `genome.network_type == "feedforward" or self.p_recur > 0.0` (the acyclicity veto and the `p_recur` requirement are the only consumers) and traced once per call inside the add-conn stage; otherwise it runs on every generation where `conn_add > 0`, since the gate is a traced value.

### Host formulation (`cycle._closes_cycle_host`, default; the numpy route)
Key resolution is a **dense `key -> row` table** — the shape `common/tensorization.py::key_slot_table` builds: a `(P, key_span + 1) int32` table whose column `k` holds the row owning key `k`, plus a dump column.
It is built with **one flat rank-1 `scatter`** of `P·N` updates into a `(P·(key_span + 1),)` seed of the miss sentinel `node_count` (one element plus `broadcast_to`, never a materialised table), and read with **one flat rank-1 `gather`** at `cell + p·(key_span + 1)`, where `cell = select(in_range, key, key_span)` sends an out-of-span key to the dump cell; a lookup returns `(rows, hit)` with `hit = got != node_count` and `rows = minimum(got, node_count - 1)`, so a miss never names a live row.
Both endpoints of every existing edge plus both candidate endpoints are resolved in that one pass (`Q = 2E + 2`), so the predicate pays one table build and one gather.
The hop is a `scatter` on a **flat** `(P, N + 1) bool` frontier: `gather(frontier, src_flat)` → `scatter(frontier, select(live, dst_flat, dump_flat), live)` → `reduce_max(not_equal(grown, frontier))`; `select(edge_valid, src_flat, dump_flat)` folds a missing endpoint into the gather index once, outside the loop, so the dump column always reads `False` and the per-hop `logical_and` disappears.
The frontier only gains bits and the node count bounds it, so the loop carries `(frontier, growing)` and `growing` alone terminates it: no iteration counter, no hop cap.
The seed is a one-hot `equal(arange(width), dst_row) & dst_hit` — **an IREE release gate, not a style choice**: a boolean `scatter` as the `while_loop` init SIGSEGVs `iree-compile` (IREE 3.11, llvm-cpu) on the assembled generation graph while the same scatter inside the body and the same kernel standalone both compile, so only `pytest test/backends` catches a regression.
The final read is one flat gather at `src_row`, `logical_and`-ed with `src_hit`/`dst_hit`, so a self-loop on an existing node answers `True` from the seed alone.
Cost: **81 traced ops / 2 scatters**, 3.2 / 3.5 / 3.7 ms per call at pop 500 on generation-1/5/10 payloads; a `dot` hop against a dense `(P, N, N)` adjacency is decision-identical but slower and allocates a quadratic buffer (`## Rejected levers`).

### Accelerator formulation (`cycle_accelerator.closes_cycle_accelerator`)
`cycle_accelerator.kernel_mode(state)` reads `state.kernel_mode` — `"host"` when the entry is absent, `"accelerator"` the second accepted value, anything else a `TensorNEATError` — and `cycle.closes_cycle` is one static host branch on `selected(state)`, so a graph contains exactly one spelling and no traced value drives it.
The route exists because on a compiled device a `scatter` lowers to **one workgroup of one thread** (≈17–21 ns per update element on the box's MI300X), so the host route's table build and hop scatter are pure serialization where a reduction spreads over workgroups.
Key resolution is an **equality template** — the spelling `genome/operations/distance/index_free.py::resolve` uses: one broadcast `equal` of the masked `(P, Q, 1)` query keys against the `(P, 1, N)` visible node rows, then the *lowest* matching row (`reduce_min(select(match, arange(N), N), axes=2)`), `hit = lowest < N`, `rows = minimum(lowest, N - 1)`; no `scatter`, no `iota`/`argmax`.
Visibility is the dense table's, spelled as value masks (`_NO_QUERY = -1`, `_NO_NODE = -2`, both through `cycle._in_span`), so a padded or out-of-span key never matches a padded row and a miss lands on `N` exactly as `_rows_of`'s `hit`/clamp expects.
The hop is **scatter-free and data-dependent**: one `(P, N + 1) bool` carried tensor holds the reached set in columns `0..N-1` and the growth flag in column `N`, and the `while_loop`'s `cond` *is* that flag, so the loop runs until a hop grows nothing — the breadth-first closure from one source saturates within `N - 1` hops, and in practice in two or three.
The hop itself is `live = edge_valid & gather(reach, src_flat)`, `marked = reduce_max(live[:, :, None] & dst_onehot, axes=1)`, `grown = logical_or(current, marked)`, with `dst_onehot (P, E, N) bool`, `valid_flat (P·E,) bool` and `src_flat` hoisted; the destination one-hot is the only `O(P·E·N)` pass per hop, and `grew = any(grown != current)` is the next flag.
The seed and the read-back address the flat `(P, width)` carried tensor with the same stride-`width` row offsets, so the flag column is only ever read by `cond` and by the post-loop guard, and the read-back is one gather at the candidate source's row.
The counter rides **inside** the one carried value on purpose: an unused `while_loop` result makes `iree-compile` 3.13's `scf.while` canonicalization emit an illegal op for the assembled generation graph (`region branch point has 2 operands, but region successor needs 4 inputs`), and a separate `(reach, growing)` pair fails there even with the flag consumed, so the loop has exactly one result and the answer reads it.
The post-loop flag doubles as a convergence guard: it is `False` exactly when the last hop grew nothing (the loop only exits there), so `logical_not(settled)` refuses the mutation for a reach set that had not stabilized instead of admitting a cycle.
`evoxc.scan` cannot express this hop — it refuses a body with no stacked tensor output, and a stack would add a per-hop `scatter` plus a `(length, ...)` accumulator for the same static trip count.
Cost: **82 traced ops / 0 scatters** (against the host formulation's 81), paying one `O(P·E·N)` pass per hop instead of a serialized dispatch; the isolated-predicate device record (0.769 → 0.173 ms at pop 500, −77 %, and 1.425 → 0.282 ms at pop 1000, −80 %, against **2.859 ms** for the host formulation on the same device) is this body's, on the data-dependent hop loop.
A statically counted `node_count`-hop spelling of the same hop (bit-identical boolean, one readback fewer) is **rejected on measurement**: a whole generation costs 21.28 against 13.27 ms on `xor_p500`, 23.56 against 16.19 on `xor_p1000`, 24.16 against 16.13 on `custom_pagie_p500` and 69.01 against 60.16 on `cartpole_p100` (one session, seed 42, `iree-rocm`, warmup 2 + 5 timed generations), because these populations saturate in two or three hops and the counted loop pays the `O(P·E·N)` one-hot for all fifty.
On numpy the element volume is paid in full (isolated predicate 20.84 against 4.86 ms per call at pop 500; whole step 130.7 against 116.2 ms), which is why `"host"` is the default and `host_payload._formulation_statics` selects `"accelerator"` only for a GPU-class device kind.
The two formulations answer the same boolean: **240 011 comparisons, zero disagreements** across evolved generations at pop 100/500/1000 for `DefaultGenome`, `RecurrentGenome` and `OriginConn` plus 8 adversarial payloads, whole-generation bit-identity on numpy over 4 generations at pop 500, and both `evoxc.lower(..., backend="iree")` cleanly (0 deferred ops, no unsigned dtype).
Switching modes rebuilds exactly once: `kernel_mode` is registered by `Pipeline.setup`, part of the executable-cache formulation signature, and read host-side only; an `iree` generation differs from numpy only in last-ulp fitness, which is the backend's float fusion.

## Shipped connection gates (measured ledger)
`DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=DEFAULT_GENOME_CONN_ADD, conn_delete=DEFAULT_GENOME_CONN_DELETE)` = `(0.1, 0.1, 0.4, 0.05)` when no operator is passed, so every shipped end-to-end run evolves under the rebalanced connection pair while an explicit `DefaultMutation()` keeps NEAT-python's `(0.1, 0.1, 0.2, 0.2)`.
Ledger: XOR3d pop 100, seeds 0-19, 150 generations, numpy backend, one process per (arm, seed) in one session against an in-session control (escape = some generation best above −0.24; target = some generation best at or above −0.05).
| arm | gates `(node_add, node_delete, conn_add, conn_delete)` | escape | target | median escape gen | median final |
|---|---|---|---|---|---|
| control (`DefaultMutation()`) | 0.1/0.1/0.2/0.2 | 4/20 | 2/20 | 59.5 | −0.250 |
| **shipped** | 0.1/0.1/0.4/0.05 | **13/20** | **11/20** | 75.0 | −4.35e-02 |
| milder rebalance | 0.1/0.1/0.3/0.1 | 7/20 | 4/20 | 73.0 | −0.250 |
Fisher two-sided against the in-session control: shipped **p = 0.0095**, milder 0.48 — only the sharp pair clears the pre-registered bar (escape ≥ 8/20 and ≥ 2× the control, or p ≤ 0.05).
Composition, mean over seeds 0-19 at generation 150 (connections · present hidden · output in-degree): shipped 10.38 · 4.19 · 2.59, control 6.06 · 4.36 · 1.27.
Regression gates, same session, shipped law: XOR3d pop 500 seeds 42-47 escape and reach the target 6/6 (control 4/6, whose seed 43 stays flat), XOR3d pop 1000 seeds 42/43/44 3/3 (control 2/3), XOR pop 100 seed 42 target at generation 41 (final −1.64e-05, control 51) and XOR pop 500 seed 42 at generation 33 (final 0.0, control 32).
Mechanism: at equal connection gates add-conn is accepted about half as often as delete-conn (0.50 against 1.00 of fired gates), so the operator's own steady state is −0.14…−0.22 connections per individual per generation and the population stays under-wired; `0.4`/`0.05` moves that steady state to +0.15 and lifts the escape rate at equal node count (the two node gates stay at `0.1`, so the node-count trend is ≈0 net).

## Rejected levers (one law each; none is in the tree)
- **Add-node split heritability exemption** (restoring the split's rows after the value stage): +213 lines in `base.py`, a wash on the failing cell plus a per-seed regression on converging ones, and uncontrolled densification (4.0 connections / 2.1 hidden without it against 8.2 / 7.3 with it at generation 150) — so a neutral split stays unexempt and the value stage keeps mutating the rows the structural stages just wrote.
- **Weight-mutation-frequency sweep** (legacy 0.2/0.015, that law clipped to ±5, 0.5/0.05): no arm moves the pop-100 constant-0.5 attractor and the legacy law regresses cells that do converge — keep `DefaultConn`'s `0.8`/`0.1`.
- **Add-conn fresh-edge value-stage exemption** (a new edge keeps weight `0.0`): 4/20 escapes and 0/20 targets against the shipped 13/20 and 11/20, composition tracking the pre-rebalance control — inert capacity is not structured capacity.
- **A milder 0.3/0.1 gate pair**: 7/20 escapes, Fisher p = 0.48 against control, indistinguishable from noise.
- **A dense `dot` cycle hop** and **a per-key-family split of the accelerator resolution**: decision-identical but slower where they were measured (the first also allocates a quadratic buffer).
- **Collapsing the four stages into one merged plan**: legitimate only where the collapsed stages write provably disjoint rows, which the delete-conn/add-node and delete-node/add-node interactions are not.

## Constraints
- Trace-time kernel only: no `jax`/`torch`/`numpy.random`, no `vmap`/`scan`/`cond`, no Python loop over individuals (the stage loop is a static Python loop over four configurations), no eager NumPy; `sort`/`argsort` are legal (the mutation never enters the `grad` graph), and `cumsum` is a StableHLO v1 export deferral, so a prefix/suffix count has to be a static log2-doubling fold (no kernel here needs one).
- Randomness is one rank-0 key per call, split with `evoxc.random.split_n`; draws are batched over the population, never per individual, and the draw order is part of the contract (`## Test Strategy`).
- Each of the four stages rebuilds its own `EditContext`; that must not be hoisted into one context shared across stages, because a previous stage can move or clear a row.
- A row fetch returns `(row, hit)` rather than an `I_INF` index, so a gate is a plain `logical_and` chain and the empty-row index is `0` — never a sentinel `select` plus a rank-0 constant.
- Padded rows keep their sentinels in both arrays (`I_INF` keys, NaN attributes); no operator may pair an `I_INF` key with finite attributes or a finite key with NaN attributes.
- Capacity invariants are hard: `max_nodes`, `max_conns`, `max_in_degree`. `max_in_degree` is enforced at the write that could grow it (add-conn compares the destination's present row count against the limit, add-node refuses a colliding allocation and an already-over-limit destination), and the delete operations can only remove rows; a refused operation is a no-op for that individual, never a partially applied write.
- A device-specific formulation is a host-string branch, never a traced value: an unknown `kernel_mode` raises `TensorNEATError` naming both accepted values, and nothing falls back silently.
- Zero-width attribute tables (`attr_width == 0`) work: `_scatter_slots` early-returns on `width == 0` and the write path uses row-index selects, so nothing builds a `0`-stride arange.
- Errors: configuration problems raise `ConfigError` (`TensorNEATError`); `evoxc` shape/backend errors propagate unchanged.
- Rank-0 constants and static index blocks are built once per stage and shared, and population-scaled seeds stay one element plus `broadcast_to` (`window.fill`) instead of a materialised `(pop_size, …)` fill; `fill` is a real traced broadcast, so its shape must be exact where it feeds `reshape`/`scatter` while symmetric-broadcast consumers may grow it.
- Files ≤ ~1000 lines (this node's largest is `base.py` at 874); each file is one job, per the Routing Table.

## Known Issues
- **The four-gate reality** (20 000 individual-mutations, `DefaultMutation()` defaults, gate rows replayed from the kernel's own key split): gate histogram 0/1/2/3/4 firing operations = 51.16 / 38.01 / 9.74 / 1.05 / 0.045 % (any 48.84 %, ≥2 10.83 %, against the analytic 48.16 % / 10.72 %), and 5.12 % of individual-mutations apply ≥2 reconstructed operations on XOR (4.47 % on XOR3d) — one split writes three visible connection edits and a delete-node removes every edge touching its key, so the ≥2 count is not a per-gate count.
- **Per-operation accepted fire rate** (that operation at `1.0`, the rest `0.0`, visible payload diff): XOR pop-100 generation-10 payload add-node 95.0 %, delete-node 86.0 %, add-conn 54.6 %, delete-conn 95.0 %; XOR3d pop-100 stalled payload 89.0 / 69.0 / 52.8 / 89.0.
  The profile is a property of the payload, not of the gate design (add-conn measures 52.5 % on the frozen legacy tree), and 25.4 % of single-gate individuals produce no visible change — a refusal.
- **Value-stage churn**: 90.3 % of weight entries change per mutation call against 20.7 % in `benchmarks/legacy_jax`, with conditional mean `|Δw|` 0.232 against 0.186 (close distributions) — the difference is frequency, not step size, and it is where the two trees' payload divergence comes from.
- **`max_in_degree` never binds at pop 100**: with `K = 4` and a 3-input read-out the maximum per-destination present in-degree over the whole run is 2, so no `edge_overflow` occurs.
- Add-node does not preserve the network output (worst |Δoutput| 0.236) because `gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; that reproduces the pre-rewrite library's split semantics, so it is behaviour, not a defect.
- The value stage mutates the rows the structural stages just wrote (both split edges get fresh noise, an add-conn edge is perturbed off its `0.0` seed, a node delete-node cleared in the same call is not exempt), so "the split preserves output" only holds for `mutate_structure` in isolation.
- The frontier seed of the host route is an IREE safety constraint (a boolean `scatter` as the `while_loop` init SIGSEGVs `iree-compile` on the assembled graph), and the accelerator route's single packed `(P, N + 1) bool` carry (reached set plus growth flag) is the analogous `scf.while` constraint — one carried value, so no loop result goes unread; both compile standalone either way, so only `pytest test/backends` catches a regression.
- `RecurrentMutation`'s `closes_cycle` runs on the *chosen* attempt only: a must-cycle attempt that does not close a cycle is rejected instead of being skipped for a later attempt, which biases sampling slightly (fewer accepted recurrent edges) to keep `max_conn_tries` out of the op budget.
- `p_recur == 0` still splits the key into `attempt_key`/`recur_key` although no `p_recur` draw happens; removing the split would change `attempt_key` and therefore the draws, so it is not behaviour-neutral.
- The remaining reducible margin is the composition itself: `EditContext` is rebuilt four times, `_stage_edit`/`apply` run four times, and the cycle predicate is the largest single block (81 traced ops in the host formulation, 82 in the accelerator one). The node-write `select`s are at their floor — break-even against a `scatter` alternative, and sharing the row mask between the two node arrays is the only form that avoids a second comparison.

## Test Strategy
Status on this tree: `uv run pytest -o addopts="" -q` → **1497 passed** with `uv sync --all-extras` (`test/CONTEXT.md` records the count; `test/unit/genome` 154 of them with no optional extra, `test/parity` 60 with `bench`, `test/backends` 46 with `iree`).
Mutation has no `test/parity/` case (its draws differ from `jax.random` by construction), so parity covers the deterministic kernels only.
A change to this node is gated by **bit-identical mutation output on fixed inputs**: `execute_mutation` for `DefaultGenome`+`DefaultMutation` and `RecurrentGenome`+{`DefaultMutation`, `RecurrentMutation`} on a real seed-42 evolved payload with `evoxc.random.key(12345)`, `new_node_keys = arange(P) + 1000`, `new_conn_keys = arange(3P).reshape(P, 3) + 5000`, compared NaN-aware per leaf over ≥ 40 RNG keys and over configurations (each structural probability 0/1 in turn, saturated node and connection tables, `historical_marker` 3-column keys, `attr_width == 0` genes).
The run-level gate is the pipeline's bit-exactness protocol (10 generations at P=500 and P=1000, seed 42, one sha256 per generation over the four payload leaves and `fitnesses`, reference digests in `../../CONTEXT.md`); a digest mismatch with an unchanged trajectory shape is a kernel change, a different trajectory shape is a behavioural change.
The **capacity gate** is a soak: `Pipeline.step` on `OriginNode`/`OriginConn`, pop 500, `max_nodes` 16 and 50, `XOR3d`, for ≥ 250 generations over ≥ 20 seeds, asserting host-side after every generation that no destination key has more than `max_in_degree` present incoming rows (46 runs × 250 generations measured: zero violations, zero raises); `degree.in_degree`/`violation` express the same check in-graph and no shipped test drives them.
**Coverage gaps.** The gene value stage (`gene/blocks.py::mutate_attrs`/`init_attrs`/`crossover_attrs`) has no independent oracle (its distributions and per-column draw order are pinned only payload-level by `test_mutation.py`), `plan.apply`'s write-slot sharing is pinned only end-to-end, and the accelerator cycle formulation is pinned on the numpy leg by `test/unit/genome/test_accelerator_equivalence.py` plus the ad-hoc identity matrix above.
**StableHLO portability** (`evoxc.backends.stablehlo.export`, with every payload leaf passed as a `TensorSpec` and the rank-0 key built inside the trace): the four-stage mutation graph exports at **207 699 bytes / 2 143 op uses over 29 distinct ops** (12 `scatter`s and one `while` among them), passing the gate — no deferred op, no unsigned element type, every `dimension =` attribute non-negative.
Only `pytest test/backends` proves the assembled generation graph, since per-kernel compilation does not.
