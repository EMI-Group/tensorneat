# operations — batched genetic operators

## Intent
Mutation, crossover and compatibility distance as batch-first kernels over the split gene payload (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`), population on axis 0, every shape static at build time.
This node also owns the structural invariants that keep the execution schedule valid: `max_nodes`, `max_conns` and `genome.max_in_degree` are hard caps and a refused operation is a no-op for that individual, never a silent repair.
Operators never allocate RNG keys or structural keys: the algorithm draws `key` and allocates `new_node_keys`/`new_conn_keys`, so a `(seed, config, shape)` triple reproduces a run.

## Call contract (binding for `genome/base.py` and `algorithm/`)
- `BaseMutation.__call__(state, genome, key, node_keys, node_attrs, conn_keys, conn_attrs, new_node_keys (P,), new_conn_keys (P, 3) -> GenomeTensors` — validates the two key shapes (`ConfigError`), then `split_n(key, 2)` and runs the structural stage before the value stage.
- `new_conn_keys` columns: `0` = add-node identity edge, `1` = add-node copy edge, `2` = plain add-connection edge; each becomes the `historical_marker` when the conn gene declares one.
- `BaseCrossover.__call__(state, genome, key, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> GenomeTensors` — `genome1` is the fitter parent and keeps its keys; identical parent shapes are required (`ConfigError`).
- `BaseDistance.__call__(state, genome, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> (P,) float32` — the algorithm forms the pairs; distances are `0` for an empty pair and never NaN.
- Payload key ranks: node keys are `(P, N)` as `GenomeTensors` allocates them; `(P, N, 1)` is also accepted and returned verbatim. Connection keys are `(P, E, CK)`.
- `base.py` forwards as `self.mutation(state, self, key, *payload, new_node_keys, new_conn_keys)`, `self.crossover(state, self, key, *genome1, *genome2)` and `self.distance(state, self, *genome1, *genome2)`.
- The mutation operator reads only host statics off `genome`: `num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `max_in_degree`, `network_type`, `node_gene`, `conn_gene`, and the predicate `check_cycles(node_keys, conn_keys, src_keys, dst_keys)`.

## Mutation semantics
One `evoxc.random.uniform(key, (4, P))` draw decides the structural operation per individual, rows in the order `(node_add, node_delete, conn_add, conn_delete)`: the first row whose draw is below its probability wins and row `4` means "nothing".
At most one structural change therefore applies per individual per generation (the four helpers are mutually exclusive, not independent), and value mutation always runs afterwards.
Each private helper takes a trailing `(P,) bool` gate and is a batch-wide no-op where it is false; `select` returns the untouched row bit-for-bit, `-0.0` and NaN included, so a probability of `0` is the identity.
Add-node is the only output-preserving structural change: the chosen connection is deleted, the new node is written at `first_free_row(node_keys)` with `node_gene.new_identity_attrs`, an identity edge (`conn_gene.new_identity_attrs`, weight `1`) runs old source → new node and a copy edge (recorded original attributes) runs new node → old destination. It is refused when fewer than two connection rows are free *before* the delete.
Add-connection draws its two endpoints with one draw each and refuses an endpoint of `I_INF`, a duplicate `(in_key, out_key)` pair, a cycle when `network_type == "feedforward"` (`genome.check_cycles`), and a destination already at `max_in_degree` incoming edges.
Add-node validates the caller's allocation (11 traced ops, refusal a bit-exact no-op): it refuses a split whose allocated node key already appears in `node_keys` — a duplicate key folds two rows onto one schedule slot — and one whose consumed edge points at a destination already above `max_in_degree`; `algorithm/` derives those keys from the pre-crossover population, so the check is what keeps the invariant true at the node boundary.
`./mutation/degree.py` is the standalone diagnostic audit (`in_degree`, `max_in_degree`, `violation`) for soaks and future tests; `execute_mutation` never calls it.
Delete-node never names an input row (`0..num_inputs-1`) or an output row (`N-num_outputs..N-1`) and detaches every touching connection with `delete_conns_by_key`; delete-conn clears exactly one row.
`choose_node_key`/`choose_connection_key` take one draw per call and return the key *at the drawn row* together with that row, so key and row always agree, and `I_INF` everywhere when nothing is eligible.
`RecurrentMutation` replaces only the add-connection step: one `(P, max_conn_tries, 2)` `randint` tableau plus one `(P, max_conn_tries)` `uniform` `p_recur` decision, the first accepted attempt chosen with a reduce (no `cond`), and a `p_recur` hit makes "closes a cycle" a hard requirement; `p_recur=0` draws nothing and degenerates to `DefaultMutation`.
Its confirmation domain is the node's element-volume trap: the rejected version materialised six `(P, max_conn_tries, E)` slabs (~2 M elements each) and cost 72.5 ms at pop 1000 at 616 traced ops; the current version keeps two **bool** slabs and gathers on `(P·tries)` blocks, so it is 498 ops and 28.3 ms (pop 1000), 15.9 ms (500), 6.1 ms (100).
Structural resolution is plan-based: the four helpers only decide *what* to write (`plan.py`), one `select` per write slot applies it, and "no write" is the array's own row count — so a refused operation stays a bit-exact no-op without a dump row or a flat index block.
`execute_mutation` itself is **409 traced ops** for `DefaultMutation` (398 before the add-node allocation guard), **445** for `RecurrentMutation(p_recur=0.1)` and **325** for `p_recur=0` — one traced graph that already includes the gene-side `mutate`/`new_identity_attrs` calls.
`cycle.py`'s single `while_loop` replaced 49 unrolled hops (−15 ms), and a recurrent genome with `p_recur == 0` now elides the whole cycle region (423 → 325 ops, 31.2 → 14.2 ms at pop 1000, 2.2×) because its only two consumers are the feedforward veto and the `p_recur` requirement.

## Crossover semantics
`DefaultCrossover` always keeps parent 1's structure and recombines attributes only: a gene whose exact key-column tuple has a homologue in parent 2 is crossed per attribute by `gene.crossover`, one with no homologue keeps parent 1's attributes, and padded rows stay padded.
`alignment.find_homologous(keys1, keys2)` is the only aligner and serves both crossover and distance: one packed `int64` identity per key row (`row_identity`, sign-flipped so a signed `argsort` orders it like the unsigned pack) → one `argsort` of the concatenated `2M` identities → each gene's rank as `argsort(order)` → successor test "the element right after me is a parent-2 row with my identity" → `_confirm_rows` for key columns past the packed prefix. `O(M log M)`, never an `O(M^2)` scan, one batched kernel.

## Distance semantics
Two shapes of the same arithmetic: the pair-wise `__call__` (fitter/first parent pair per row) and the two-phase `prepare`/`measure` pair speciation uses, where the population side is sorted **once per generation** and each wide `measure` call only merges the centres against that digest.
Both routes end in the *same* scalar tail (`DefaultDistance.distance_from_alignment`, which re-spells the aligned rows as an `I_INF` row table and defers to the documented `distance_from_rows`), so they are bit-identical rather than merely close.
`gene_distance` (pair-wise) takes its homologue table from `alignment.find_homologous`; `measure` takes it from `digest.measure_alignment`, which returns `AlignedGenes(rows, homologous, count, matched)` so no consumer re-derives a mask or a count.
`execute_distance` measures **212 traced ops** at `5.83 / 10.04 ms` for pop 500 / 1000 on the generation-5 payload.
Per-call two-phase cost (medians, build excluded): `prepare` **167 ops** at `2.77 / 4.45 ms`, `measure` **98 ops** on the merge route (`2.91 / 5.20 ms`) and **102 ops** on the dense single-centre route (`1.08 / 2.06 ms`) for pop 500 / 1000.
The merge's 98 ops cost nearly 3× the dense route's 102 because the merge sorts and the dense route gathers: two `argsort`s per family over the `(P, 2M+1)` int64 composite block, which is element-bound work that op count does not show.
`measure`'s earlier ms win came from **sort semantics**: `argsort(..., stable=True)` is timsort in the numpy reference interpreter, which detects the digest half's existing ascending run, so the merge sort drops to roughly sorting the centre's own `M` values at zero extra ops (`stable=` is an attribute).
Every tensor `measure` needs that does not depend on the centre — rank-0 constants, the `(P, 1)` merge index blocks, the fold matrix, the padding column, the dense table geometry — is built once in `prepare` and carried in the digest, so the `measure` body emits **no** `constant` op and no static index arithmetic.
The generation's distance bucket is **3 222 executed ops** at pop 500 (`genome/gene` 970, whole generation 8 813), and `Pipeline.step` is `189.9 ms` median there and `450.1 ms` at pop 1000.
`measure` is dominated by those two sorts per family (the aligned-attribute tail is the rest of its ops), so the next lever is *route*, not formulation: the live call site tiles a batch-1 centre to `P` rows and therefore never reaches the sort-free dense route.
The merge algebra (injective `2**31` fold, digest-side-first concatenation so a population gene's merged index *is* its digest row, `argsort(order)` inverse, successor test against `composite + 1` with a trailing padding column instead of a clamp, `_confirm_rows` for a third key column) is stated in `./distance/CONTEXT.md`.
`ConstantPool` (`./distance/consts.py`) exists because `enp.full((), v, dtype)` emits one `constant` op per call and evoxc never deduplicates: a pool per trace took the distance files from **503 to 163** constant ops per generation, and hoisting the surviving constants into the digest removed the per-call ones entirely.
Non-homologous slots are zeroed **before** the attribute `reduce_sum` (a `NaN * 0` product would poison the sum), the attribute term uses `BaseGene.distance` (`|delta|` for float columns, `!=` for int option columns), and the empty-pair guard folds into `maximum(float32(max(cnt1, cnt2)), 1.0)` with one `divide` so no pair can be `inf`/NaN.
A **zero attribute width** (`attr_specs = ()`, an unweighted HyperNEAT/CPPN edge) is supported: `digest._gather_rows` returns the `(P, M, 0)` block unchanged (a zero-width row has exactly one permutation) and `distance_from_alignment` returns the structural disjoint/excess term alone, so `Pipeline.step` → `tell` no longer raises `ZeroDivisionError`; both guards are static Python branches, so the width ≥ 1 path keeps its exact op counts and bytes.

## Constraints
- No `jax`/`torch`/`numpy.random`; no `vmap`/`scan` over individuals; no Python loop over individuals — operators are already batched and never sit inside the `grad` graph, so `argsort` is legal here.
- `while_loop` is allowed only where it replaces a statically unbounded unroll of *identical* work: the cycle check uses one region, and its per-hop frontier stays flat (`(P*(N+1),)` with one trailing dump column) so a hop is four `O(E)` ops.
- Static Python `if` is used only for host configuration (probabilities, `network_type`, key width); every per-individual decision is a `select`/mask.
- evoxc's numpy backend raises on an out-of-range gather/scatter index, so every index is masked or clamped before it reaches the backend (`masked_flat_gather`/`masked_flat_scatter` from `common.tools`, or a caller-provided *in-range* index where the code already guarantees it).
- Rank-0 constants cost one traced op each and evoxc never deduplicates them: build each distinct value **once per trace** (a `ConstantPool`-style bundle threaded through the kernel, or the entry point's own bundle) rather than at every use site; a bare Python literal additionally promotes `int32`/`float32` to `int64`/`float64`, so the typed constant is still required.
- Configuration violations raise `ConfigError` (a `TensorNEATError` subclass) at construction time; `evoxc` errors are never caught or re-wrapped.
- Files ≤ ~1000 lines (`distance/digest.py` 930 is the largest, then `gene/base.py` 905, `mutation/base.py` 748, `distance/base.py` 720, `distance/layout.py` 649, `alignment.py` 483).
- `argsort` is called with `stable=True` wherever one input run is already ordered (the digest half of a merge) or where tie order must be pinned: stability is free, timsort detects the run, and it makes the reference interpreter agree with a compiled backend's count-mode tie order.
- Traced-op budget is the lever here, but element volume is close behind and it is what the clock pays at pop ≥ 500: the merge's `(P, 2M)` **int64** blocks are 6.4 MB each at `4P`/`max_conns=100`, which is why the conn family costs twice the node family at the same op count.
- Element-volume rules are layout-specific and measured, not guessed: an innermost-axis reduce over the `(P, N, K)` incoming window is 10-20× an ordinary op (fold the `K` slices), while for the `(P, max_conn_tries, E)` slabs of the recurrent add-connection the **contiguous innermost** axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms).
- `measure` holds one `(P, M, A)` and one `(P, 2M)` temporary per call and the digest four arrays per family; peak RSS at pop 1000 is ~2.1 GiB (pop 500: ~1.1 GiB), so a new full-size temporary in this path is a real regression even when it saves ops.
- **No unsigned dtype in a graph — `iree`'s declared dtype set has none** (`float16/float32/float64/int8/int16/int32/int64/bool`, `evoxc/backends/adapters/iree.py::_dtype_capabilities`), so one `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the whole graph. Use **same-width signed carriers**: two's-complement add/sub/shift/or/xor/cast and `equal` produce the identical bit pattern in `int32`/`int64`. The one thing that is *not* identical is **order**, so wherever a carried value is ordered rather than compared (`sort`/`argsort`/`<`/`reduce_max`), restore the unsigned order explicitly — that is `alignment._order_ready`, one `bitwise_xor` with the sign bit (`-2**63` as an `int64` constant, the only spelling `enp.full` accepts), a bijection that preserves equality exactly.
- **No op may be a StableHLO v1 export deferral**: `evoxc/backends/stablehlo/ops.py::DEFERRED_OPS` (plus anything unmapped) fails `evoxc.lower(..., backend="iree")` with `BackendError: op '<name>' ... is not supported in v1`. `cumsum` is deferred, so a prefix/suffix count is a log2-doubling fold of `pad` + `slice` + `add` (`mutation/cycle.py`), never `cumsum`; `erf`/`gelu`/`tril`/`flip`/`diagonal`/`cholesky`/`qr`/`svd`/`matrix_rank`/`matrix_exp` are the other names to avoid. `sort`, `argsort`, `gather`, `scatter`, `select`, `concatenate`, `pad`, `slice`, `reduce_(sum|max|min|prod)`, `dot`, comparisons, casts and the bitwise ops are all v1.

## Deviations from the pre-rewrite library (intentional)
- The four structural operations are mutually exclusive through one shared draw; the legacy build gated each of them with an independent uniform and could apply several per individual.
- `choose_node_key` takes the static row counts `num_inputs`/`num_outputs` (the legacy signature passed `input_idx`/`output_idx` lists); the four private mutation helpers take the trailing gate.
- Alignment is the packed-identity rank merge over `row_identity` (`_COLLISION_WINDOW`/`searchsorted`/hash-and-confirm no longer exist in any form): the parent tag lives in the low 2 bits of the `int64` sort key, so parent 1 sorts first inside a group of equal identities and the single `argsort` may run unstable; only key columns past the packed prefix are confirmed by `_confirm_rows`.
- Non-finite distance weights are rejected as well as negative ones, and `compatibility_disjoint`/`compatibility_weight` are validated at construction.

## Test Strategy
`test/unit/genome/test_mutation.py`, `test_crossover.py`, `test_distance.py` are real tests today (95 passing in `test/unit/genome`), and they are the acceptance specs for the contracts above.
`test/parity` (53 passing) holds the kernels against the frozen legacy implementation on identical genomes.
The behaviour-neutral gates used for every op-diet change in this node are fixed-input oracles rather than assertions: a real evolved seed-42 XOR population (pop 100, 2 steps) replayed through `execute_crossover`, `execute_distance`, `prepare_distance`, `measure_distance`, `execute_mutation` and `RecurrentGenome.execute_mutation` on captured input payloads, compared bytewise (NaN-aware for padding rows) against a frozen copy at `commit b18716e`; plus the wide `DistanceRows` path (4 tiled centres × P rows) against batch-1 `measure`, and the 5-generation seed-42 `fitness_history` against the same frozen run.
The exportability gate is the same shape: one script traces-and-runs `find_homologous` (key widths 1/2/3), `execute_mutation` (each operator), `execute_crossover`, `execute_distance`, `closes_cycle`, `prepare_distance`/`measure_distance` and three `Pipeline.step` calls on the captured payload, dumps the outputs to `npz`, and is run twice — once against a `git worktree add <tmp> <base>` checkout on `PYTHONPATH` and once against the working tree — with `.tobytes()` equality per array; a second script monkeypatches `evoxc.build`, walks every captured graph's `entry_block` and `op.regions`, and asserts no `uint*` dtype anywhere and `evoxc.backends.stablehlo.ops.status(op.name) != "deferred"` for every non-terminator op (`op.location` names the offender).
A mutation or alignment change must be trajectory-identical, so the fingerprint is the run, not the code: four payload arrays + the ten `SpeciesState` leaves + `randkey` per generation.
`find_homologous` is also checked against a pure-Python `{key tuple: row}` oracle at key widths 1/2/3, with shuffled parent-2 rows and an adversarial case whose packed prefixes match while the third column differs (`_confirm_rows` must reject it).
Trace a bound method through a closure (`lambda *a: obj.method(state, *a)`) and build rank-0 RNG keys *inside* the trace (`evoxc.random.key(seed)`), because an `evoxc` key cannot cross the graph boundary as data.

## Known Issues
- Five `test/unit/algorithm/` tests fail at `b18716e` and still do (algorithm node, not this one): four stale `xfail(strict=True)` cases in `test_neat_tell.py` and `test_speciation.py::test_centre_genes_keep_the_split_payload_contract` (which wants population-shaped centre payloads while `DistanceRows` sends batch-1 rows).
- **Add-node is not output-preserving**: `gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`, so the split node re-aggregates and re-activates (worst |Δoutput| 0.236, identical at `b18716e`). The fix belongs to the gene node (identity aggregation + identity activation).
- **Structural keys can exceed `genome.key_span`**: `algorithm/` allocates node keys as `max_node_key + 1 + arange(P)`, so a real pop-100 run reaches keys 225–249 while `key_span` is 150, and at pop 500 the allocator reaches 1 729–8 033 by generation 250 (at generation 53 of the reproducer, 494 of 500 allocated keys were outside the span); `common.tensorization.derive_schedule`'s dense key table then silently drops those genes without setting `edge_overflow`. Either the algorithm keeps keys below `key_span` or the pipeline's shape signature carries a raised one — genome/algorithm owners.
- The structural-key allocator is stale by one population: `algorithm/neat/neat.py::_new_gene_keys` derives `new_node_keys` from `state.pop` (the pre-crossover parents) while the payload mutated is the crossover child, so a child can already own the allocated key; `plan_add_node` refuses that split as a bit-exact no-op, and the allocation fix belongs to `algorithm/`.
- Remaining op blocks outside this node, measured: `genome/gene/base.py:50` reads each attribute column as kept-axis slice + reshape (**264 traced ops per generation**), `gene/*/mutate` ~65 ops, and `common/tools.py::fetch_random`/`fetch_first` still pay two sentinel `select`s each (`mutation/arrays.py`'s `(row, hit)` pair is the cheaper primitive).
- `test/support/oracle.py::schedule` still passes a `level=` keyword that `common.tensorization.Transformed` no longer declares (the field is `node_level`), so oracle-based forward checks cannot run until the test-support owner updates it.
- Hot spot: `distance/digest.py::measure_alignment` — 43 % of a `measure` call at pop 1000 is the conn family, and after `stable=True` it is **op bound** (~74 traced ops at ~80 µs each), not traffic bound. The measured alternatives: a `log2 M`-step gather binary search of each centre composite in the digest's sorted block is *correct* (verified against a Python oracle) but **refuted on speed** — 14.06 ms vs 8.60 ms per wide conn `measure` at pop 1000, 81 vs 41 ops; a scatter-derived inverse permutation is now behind on both ops (7 vs 2) and ms (1.05 vs 0.29) because the stable `argsort(order)` inverse is only 2 ops.
- Sort rule worth checking before any smaller `O(M log M)` formulation: `stable=True` (or `sort` instead of `argsort`) costs zero ops and, when one input run is already ordered, timsort removes most of the element volume.
- **This node's graphs are StableHLO-v1 clean; every remaining `backend="iree"` refusal is sibling-owned.** Auditing the two graphs a real `setup()`+`step()` builds (`DefaultGenome(2→1, max_nodes=12, sigmoid)` + `NEAT(pop_size=100, species_size=10, survival_threshold=0.01)` + `XOR()`, seed 42, 79 + 2357 traced ops) finds **0 unsigned sites and 0 deferred ops** from this subtree — after the three rewrites below. What still blocks `evoxc.lower(..., backend="iree")`: `algorithm/neat/species.py:295` (rank-3 operand scattered along axis 0), `algorithm/neat/_kernels.py:140` (`tril`) and `:295` (`flip`), and the `uint32` range test in `common/tensorization.py:179-180` + `common/tools.py:159`.
- Every kernel in this node now `lower`s, compiles and **runs** on `backend="iree"` against a real evolved payload: `find_homologous`, `execute_crossover`, `execute_distance` and `closes_cycle` are bit-identical to the numpy backend, `execute_mutation` is identical in both key arrays (structure, 0 differences) and differs in **91 of ~197 k** float attribute entries by ≤ 2.4e-7 (1 ulp). That is float arithmetic in the gene-side value mutation (`gene/blocks.py`), not RNG (evoxc's `uniform`/`randint` measured bit-exact between the backends) and not this node's rewrite; the numpy backend stays bit-identical, which is the contract.
- The exportability rewrites cost, measured pristine-versus-patched on the same box: `closes_cycle` 116 → 140 traced ops (+24 doubling ops, 8.26 → 8.60 ms at pop 1000, 4.17 → 4.30 at 500, 1.52 → 1.88 at 100); `find_homologous` +4 ops per call (`_order_ready`'s constant + xor), so `execute_distance` 219 → 227 ops and 3.04 → 3.26 ms at pop 100; `prepare_distance` 137 → 140 ops (+1 `greater_equal` +1 `logical_and` per key column, −1 `uint32` span constant, +1 pooled `int32` zero) and 1.241 → 1.340 ms. All three keep the numpy backend bit-identical (below).

## Routing Table
| Path | Responsibility |
|---|---|
| `./alignment.py` | The single shared homologue implementation: `find_homologous(keys1, keys2)` (packed-identity rank merge, consumed by crossover and distance alike), `row_identity`, `gather_attr_rows`, `key_rows` (rank-2/rank-3 key-table normaliser) and the private `_confirm_rows`/`_gather_rows`/`_flat_row_index`/`_pad_identity` helpers. |
| `./mutation/` | Structural (add/delete node, add/delete conn) and value mutation: `BaseMutation`, `DefaultMutation`, `RecurrentMutation`, plan/write resolution (`plan.py`), array editing (`arrays.py`), the one-region cycle check (`cycle.py`), and the diagnostic in-degree audit (`degree.py`). |
| `./crossover/` | Outcome-preserving attribute recombination over the shared homologue table: `BaseCrossover`, `DefaultCrossover` (alignment lives in `../alignment.py`). |
| `./distance/` | Compatibility distance (disjoint/excess + attribute term): `BaseDistance`, `DefaultDistance`, the two-phase digest (`digest.py`), the per-trace constant pool (`consts.py`), zero-width attribute tables included. |
