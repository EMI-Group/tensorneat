# operations — batched genetic operators
## Intent
Mutation, crossover and compatibility distance as batch-first kernels over the split gene payload (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`), population on axis 0, every shape static at build time.
This node also owns the structural invariants that keep the execution schedule valid: `max_nodes`, `max_conns` and `genome.max_in_degree` are hard caps and a refused operation is a no-op for that individual, never a silent repair.
Operators never allocate RNG keys or structural keys: the algorithm draws `key` and allocates `new_node_keys`/`new_conn_keys`, so a `(seed, config, shape)` triple reproduces a run.
It is the shared operator layer between `genome/` (which forwards into it) and the families `./mutation/`, `./crossover/` and `./distance/`, and it owns the one homologue implementation (`alignment.py` host / `alignment_accelerator.py` accelerator) that crossover and distance both consume.
## Call contract (binding for `genome/base.py` and `algorithm/`)
- `BaseMutation.__call__(state, genome, key, node_keys, node_attrs, conn_keys, conn_attrs, new_node_keys (P,), new_conn_keys (P, 3)) -> GenomeTensors` — validates the two key shapes (`ConfigError`), splits the key per stage and runs the structural stages before the value stage.
- `BaseCrossover.__call__(state, genome, key, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> GenomeTensors` — `genome1` is the fitter parent and keeps its keys; identical parent shapes are required (`ConfigError`).
- `BaseDistance.__call__(state, genome, node_keys1 … conn_attrs1, node_keys2 … conn_attrs2) -> (P,) float32` — no key argument; the algorithm forms the pairs, distances are `0` for an empty pair and never NaN.
- Key tables are node `(P, N)` (or `(P, N, 1)`) and connection `(P, E, CK)`; `alignment.key_rows` normalises them and any other rank raises `ConfigError`.
- `genome/base.py` forwards as `self.mutation(state, self, key, *payload, new_node_keys, new_conn_keys)`, `self.crossover(state, self, key, *genome1, *genome2)` and `self.distance(state, self, *genome1, *genome2)`, so the trace-time `state` — the only input that selects a formulation — reaches every operator.
- The mutation operator reads only host statics off `genome`: `num_inputs`, `num_outputs`, `max_in_degree`, `network_type`, `node_gene`, `conn_gene` (payload shapes carry `max_nodes`/`max_conns`); the cycle decision is `cycle.closes_cycle(node_keys, conn_keys, src_keys, dst_keys, key_span, state)`, reached only through the statically gated `network_type`/`p_recur` branches.
## Formulation seams (host | accelerator): one graph, one formulation
Three plain Python strings on the trace-time configuration `State` select every device-shaped route here; each is a host read inside a trace, never a traced value, so a graph holds exactly one spelling of each kernel, and all three sit in the executable-cache signature (`host_payload._formulation_signature`), so a flip rebuilds exactly once while the host spellings stay the shipped numpy bytes.
`kernel_mode` (`"host"` default | `"accelerator"`) is read by `alignment_accelerator.kernel_mode`/`selected` (`KERNEL_MODE_KEY`/`KERNEL_MODES`), by `mutation/cycle_accelerator.py`, and by `common.schedule_accelerator` for the schedule (outside this node); an unknown value raises `TensorNEATError` naming both spellings and nothing falls back silently.
`distance_formulation` (`"merge"` default | `"index_free"`) is read by `distance/index_free.formulation_mode`; only `BaseDistance._measure_family` consults it, so just the `prepare`/`measure` route switches while the pair-wise `__call__` → `gene_distance` → `find_homologous` route stays on the merge by construction.
`distance_centre` (`"tiled"` default | `"single"`) is **not** read in this node: `algorithm/neat/_validation.distance_centre_mode` owns it, `DistanceRows.row` tiles a batch-1 centre only in `"tiled"` mode, and `DistanceRows.matrix` groups only while the mode is `"tiled"`.
`host_payload._formulation_statics` derives all three from one decision — whether the resolved device kind is GPU-class — as `"tiled"`/`"index_free"`/`"accelerator"` for a GPU-class kind and `"single"`/`"merge"`/`"host"` for every other kind and `None`, which is what a bare `State()` yields.
## The equality-table idiom (all three accelerator modules)
"Which row of `keys2` carries this gene's key?" is answered on the compiled leg by one broadcast `equal` into a `(P, M, M)` boolean table plus `reduce_min(select(table, arange(M), M), axes=2)` — the *leftmost* match, with `col < M` reading "no match" because the miss filler `M` never wins a minimum: no sort, no permutation, no `scatter`; `argmax` is never used, because its `(P, M, M)` `int64` iota has no operands, so IREE leaves that dispatch outside every `stream.async.execute` region and `iree-compile` fails the assembled graph.
`alignment_accelerator.homologous_pair_accelerator` is that table over the key rows, `distance/index_free.resolve` over the digest keys (centre side tagged, so homology *is* plain equality) and `mutation/cycle_accelerator._key_resolver` over `(P, Q, 1)` candidate-edge keys; all three reuse `alignment`'s identifiers (`row_identity`, `_TAG_PARENT_2`, `_pad_identity`, `_confirm_rows`, `_scalar`) instead of restating the packing rule, so no formulation can disagree with the host route about what a homologue is.
## Alignment (host merge | accelerator table)
`alignment.homologous_pair(keys1, keys2, *, state=None)` is the only aligner and serves crossover and distance (`find_homologous` is its `I_INF`-marked reference form); the formulation is the static `state.kernel_mode`, branched once in `alignment._homologous`.
The host one — the default, and the only route the numpy interpreter takes — reduces each key row to one packed `int64` identity (`row_identity`: two 31-bit columns plus 2 tag bits, sign-flipped by `_order_ready` so a signed sort orders it like the unsigned pack), `argsort`s the concatenated `2M` identities **once**, and reads each gene's rank and successor position back with **one encoded `int32` `sort`** (`_successor_ranks`: `order[s] * 2**K + min(s + 1, 2M - 1)`, a bijection whose sorted position *is* the row) — `O(M log M)` per individual in one batched kernel, two sorts and two row gathers, **no `scatter`**, because the rank inversion is a value sort.
A gene has a homologue exactly when the element after it in sorted order is a parent-2 row with its identity, key columns past the packed prefix being confirmed by `_confirm_rows`; the parent tag lives in the key's low bits, so inside a group of equal identities parent 1 sorts first, the ordering never depends on stability, and the `argsort` runs unstable (4× faster there).
The accelerator table replaces both sorts with one `(P, M, M)` broadcast `equal` of `identity1 | tag` against `identity2`, `col = reduce_min(select(table, arange(M), M), axes=2)`, `found = col < M`, then the merge's own `_confirm_rows`, padding term and `select(present, col, 0)` redirect; both spellings are plain traced helpers (never `@evoxc.defn`) and `state=None` resolves to `"host"`, so a backend never sees both.
Both routes return `(rows (P, M) int32, present (P, M) bool)` with the row redirected to `0` where the mask is `False`; under the payload precondition (first two key columns unique within one parent) the identity is injective per parent, so the leftmost match **is** the merge's successor and the two records are bit-identical element by element.
Measured device cost (dispatch census of the assembled graph, `xor_p500`, rocm/gfx942, IREE 3.11): host **325** dispatches with `sort_500x100xi32`/`sort_500x200xi32` at one workgroup per row (2.03 + 0.28 ms of device time), accelerator **312** with both sorts absent on `rocm` and `llvm-cpu` and each table fused into one `linalg.generic` reduction (alignment alone is −17 net).
Measured numpy cost (`homologous_pair`, evolved-shaped payload, medians): node family `(500, 50)` host **46 ops / 2.05 ms** against **29 / 2.96 ms**, conn family `(500, 100)` host **60 / 4.66 ms** against **43 / 8.97 ms** — fewer ops but an `M²` pass plus a 10–20× innermost-axis `reduce_min`, which is why `"host"` stays the default.
## Operator semantics (per-family detail lives in the children)
Mutation is a batched *plan → apply* kernel run once per operation: one `evoxc.random.uniform(key, (4, P))` draw supplies four **independent** gates applied as sequential stages in legacy order, so at most one change lands per *operation* per individual, a false gate is a batch-wide bit-exact no-op, and a probability of `0` keeps that operation's chain out of the graph; value mutation runs last.
The cycle predicate is one `evoxc.while_loop` monotone frontier relaxation (never an unrolled hop relaxation) in two formulations: the host body resolves keys through a dense key→row table (one flat `scatter`) and reads the frontier with one flat `gather` (four `O(E)` ops per hop), the accelerator body uses an equality template plus `reduce_min` and a scatter-free `(P, N+1) bool` reached set, and both trace **81 ops**, two `scatter`s against none.
`DefaultCrossover` keeps parent 1's structure and recombines attributes only (homologous genes cross per attribute through `gene.crossover`, non-homologous ones keep parent 1's values, padding stays padded, `attr_width == 0` passes through) and exposes `find_homologous`/`align_gene_rows` (both `*, state=None`, both forwarding it into `../alignment.py`) plus `crossover_gene_attrs(state, gene, key, attrs1, aligned, attrs2)`, which pays one `gather_attr_rows` for the whole `(P, M, A)` block, one batched `gene.crossover` and one rank-3 `select` against the alignment's own mask.
Distance has two shapes of the same arithmetic — the pair-wise `__call__` and the two-phase `prepare`/`measure` — and both end in `DefaultDistance.distance_from_alignment`, so they are bit-identical rather than merely close; `measure` takes `dense` for a batch-1 centre (the live host leg, skipped under `index_free` because it is scatter-based), `index_free` on an accelerator state, the sort-based merge otherwise, and `_merge_both` for a `GroupedDigest`, with everything centre-independent carried in the once-per-generation digest.
A zero attribute width (`attr_specs = ()`, an unweighted HyperNEAT/CPPN edge) passes through the whole chain as a static branch, so `Pipeline.step` → `tell` cannot raise `ZeroDivisionError`.
## Cost law (measured on this tree, 2026-11-06)
Per-generation wall clock on the benchmark geometries (`../../benchmarks/cases.py`), numpy against iree+rocm ms: 33.04/17.42 (`xor_p100`), 112.68/13.24 (`xor_p500`), 177.43/16.29 (`xor_p1000`), 847.13/16.18 (`custom_pagie_p500`), 248.70/150.41 (`cartpole_p100`); dispatched ops on numpy 7 592 per `xor_p500` generation and 30 994 per `cartpole_p100` one (`genome/CONTEXT.md` repeats the same rows).
On the numpy interpreter one dispatched op costs ≈19–20 µs on population-shaped operands, so **op count is the budget for elementwise/gather/select/reshape work** while element volume decides the wide passes; `constant`, `reshape` and `arange` each cost a full op and evoxc never deduplicates constants, so a distinct value is built once per trace and threaded through (`ConstantPool`).
On the iree+rocm leg a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, one `while` iteration ≈50 µs and one `Tensor.to(cpu)` ≈47–60 µs per leaf, so a launch-bound graph is costed by dispatch count and `while` trips rather than element volume — the table/reduction formulations that lose on numpy win there, and the compiled leg beats numpy on the flat func-fit cases while losing on the rollout-heavy one.
The box drifts ±30 % between sessions: only a same-session A/B pair or a same-run old-vs-new ratio is load-bearing, never absolute milliseconds.
## Constraints
- No `jax`/`torch`/`numpy.random`; no `vmap`/`scan`/Python loop over individuals — operators are already batched and never sit inside the `grad` graph, so `argsort` is legal here.
- Static Python `if` covers host configuration only (probabilities, `network_type`, key width, the formulation statics) and every per-individual decision is a `select`/mask; a formulation is a host-string branch, never a traced value — an unknown value raises instead of falling back.
- evoxc's numpy backend raises on an out-of-range gather/scatter index, so every index is masked or clamped before it reaches the backend (`masked_flat_gather`/`masked_flat_scatter` from `common.tools`, or a caller-provided *in-range* index where the code already guarantees it).
- Configuration violations raise `ConfigError` (a `TensorNEATError` subclass) at construction time; `evoxc` errors are never caught or re-wrapped.
- **No unsigned dtype in a graph — `iree`'s declared dtype set has none** (`float16/float32/float64/int8/int16/int32/int64/bool`), so one `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the graph: use same-width signed carriers (two's-complement add/sub/shift/or/xor/cast and `equal` are bit-identical) and restore unsigned **order** wherever a value is ordered rather than compared — `alignment._order_ready`, one `bitwise_xor` with the sign bit (`-2**63` as an `int64` constant), preserves equality exactly.
- **No op may be a StableHLO v1 export deferral**: `evoxc/backends/stablehlo/ops.py::DEFERRED_OPS` (plus anything unmapped) fails `evoxc.lower(..., backend="iree")`, so `cumsum` is a log2-doubling fold of `pad` + `slice` + `add` and `erf`/`gelu`/`tril`/`flip`/`diagonal`/`cholesky`/`qr`/`svd` are the names to avoid; `sort`, `argsort`, `gather`, `scatter`, `select`, `concatenate`, `pad`, `slice`, the reduce/`dot`/comparison/cast/bitwise ops are all v1.
- Memory is part of the contract: `measure` holds one `(P, M, A)` and one `(P, 2M)` temporary per call plus the digest's four arrays per family, so a new full-size temporary there is a regression even when it saves ops (`distance/CONTEXT.md` holds the RSS figures).
- Files stay under ~1000 lines: `distance/base.py` sits exactly on it, `distance/digest.py` (953), `mutation/base.py` (874) and `alignment.py` (723) follow, everything else runs from 748 down to 26.
## Deviations from the pre-rewrite library (intentional)
- Alignment is exact key-tuple equality through the packed-identity merge, never row position or an innovation-number match, which is why `(genome1, genome2)` = (winner, loser) is order-sensitive by contract; the four plan functions take the trailing `(P,) bool` gate and delete-node reads `genome.num_inputs`/`genome.num_outputs` instead of the legacy `input_idx`/`output_idx` lists.
## Test Strategy
`test/unit/genome/test_mutation.py`, `test_crossover.py`, `test_distance.py` and `test_distance_digest.py` are the acceptance specs for the contracts above (`uv run pytest -o addopts="" -q test/unit/genome` → 154 passed on numpy, no optional extra), `test/parity/test_distance.py` holds `execute_distance` exactly against the frozen legacy implementation (no tolerance; 60 passed with the `bench` extra), and `find_homologous` is checked against a pure-Python `{key tuple: row}` oracle at key widths 1/2/3 with shuffled parent-2 rows.
The accelerator formulations have **no committed test** (`./test` is a sibling node): they are gated by an ad-hoc identity matrix that measured 0 mismatches on contract-conforming payloads (10 evolved generations at pop 100/500/1000, `RecurrentGenome` and an `OriginConn` mutation at pop 100, 18 cross/self parent pairs per configuration through both entry points, all-padded, padded-versus-real, out-of-span keys and a `historical_marker` clash) and by the generation gate — 10 seed-42 `Pipeline.step` generations on `xor_p500`/`xor_p1000` hashed per generation: `d43edd0d…e4c96e` (P=500) and `caba83ee…66bd45` (P=1000) in both modes, protocol and digests in `../CONTEXT.md`.
The missing regression guard is a `test/backends` cell that builds a gated pop-100 graph in accelerator mode; the cheapest close of the alignment gap is replaying that matrix inside `test/unit/genome/test_crossover.py` with `State().register(kernel_mode="accelerator")`.
**StableHLO portability** (`evoxc.backends.stablehlo.export`; procedure and the `TensorSpec` gotcha in `../CONTEXT.md`): the crossover graph exports at **33 373 bytes, 112 op uses over 6 distinct ops** (`broadcast_in_dim` 74, `compare` 20, `slice`/`gather` 6 each, `sort` 4, `concatenate` 2, no `scatter`) and passes; the generation, mutation and crossover graphs have been gated, the distance graphs (`execute_distance`, `prepare_distance`/`measure_distance`) are **not**.
The full suite on this tree (`uv sync --all-extras`): `uv run pytest -o addopts="" -q` → 1370 passed.
## Known Issues
- **This node's graphs are StableHLO-v1 clean, and the sibling-owned sites are clean too**: the two graphs a real `setup()`+`step()` builds (`DefaultGenome(2→1, max_nodes=12, sigmoid)` + `NEAT(pop_size=100, species_size=10)` + `XOR()`, seed 42, 79 + 2357 traced ops) carry 0 unsigned sites and 0 deferred ops, so the assembled graph lowers, compiles and runs on `backend="iree"`.
- Every kernel here `lower`s, compiles and **runs** on `backend="iree"` against a real evolved payload: `find_homologous`, `execute_crossover`, `execute_distance` and `closes_cycle` are bit-identical to numpy, and `execute_mutation` is identical in both key arrays while differing in **91 of ~197 k** float attribute entries by ≤ 2.4e-7 (1 ulp) — float arithmetic in the gene-side value mutation (`gene/blocks.py`), not RNG; numpy stays bit-identical, which is the contract.
- Per-kernel compilation proves nothing about the assembled generation graph: a boolean `scatter` as a `while_loop` initial value SIGSEGVs `iree-compile` in the generation graph although the same `closes_cycle` kernel compiles standalone, which is why that frontier seed is a one-hot `equal`/`logical_and` (`mutation/CONTEXT.md` holds the evidence).
- **Intra-parent duplicate key rows are the one place the formulations diverge, and the host merge is not self-consistent there either**: the merge reads the *unstable* `argsort` order inside a group of equal identities, while the accelerator table marks every duplicate that has a match and points at the leftmost matching row (`keys1` sharing key 7 twice gives host `present [0,1,0,0]` against accelerator `[1,1,0,0]`); `distance/index_free.py` makes the analogous choice, the payload contract forbids the case (first two key columns unique within one parent, guaranteed by `initialize` and `execute_mutation`'s duplicate refusal), and every evolved payload measured agrees exactly.
- Coverage gaps owned here: `mutation/degree.py` has no caller and no test, the three formulations and statics are gated only by hand-run identity matrices plus the generation digest, and the distance graphs are outside the StableHLO export gate; per-family hot spots and the op blocks outside this node (`gene/base.py::column`, `gene/*/mutate`, `common/tools.py::fetch_random`) sit in the children and in `genome/CONTEXT.md`.
## Call-site census (verified with `rg` over `src`, `test`, `examples`, `benchmarks`, `docs`, `tutorials` and every `CONTEXT.md`)
`mutation/degree.py` (`in_degree`/`max_in_degree`/`violation`) is exported and autodoc'd but **has no caller anywhere in the repo** — `execute_mutation` enforces the ceiling inline.
The live crossover path is `align_gene_rows` → `alignment.homologous_pair` (the only path `state.kernel_mode` switches there), while `alignment.find_homologous` is reached by `DefaultDistance.gene_distance` (via `BaseGenome.execute_distance`, which passes **no** state and so always takes the host formulation) and by `DefaultCrossover.find_homologous`, which only tests drive.
`distance/layout.py::dense_slot`, `distance/digest.py::match_rows` and `BaseDistance.gene_measure` are `__all__` members with no caller, `measure` → `_measure_family` is the live path, `DistanceDigest.field_names` is read only by `test/unit/genome/test_distance_digest.py`, and the grouped route's four helpers have exactly one caller, `algorithm/neat/_distance.py::DistanceRows.matrix`.
