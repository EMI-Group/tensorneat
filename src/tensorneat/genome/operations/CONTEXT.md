# operations — batched genetic operators

## Intent
Mutation, crossover and compatibility distance as batch-first kernels over the split gene payload (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`), population on axis 0, every shape static at build time.
This node also owns the structural invariants that keep the execution schedule valid: `max_nodes`, `max_conns` and `genome.max_in_degree` are hard caps and a refused operation is a no-op for that individual, never a silent repair.
Operators never allocate RNG keys or structural keys: the algorithm draws `key` and allocates `new_node_keys`/`new_conn_keys`, so a `(seed, config, shape)` triple reproduces a run.
It is the shared operator layer between `genome/` (which forwards into it) and the three families `./mutation/`, `./crossover/` and `./distance/`, and it owns the one homologue implementation (`alignment.py` host / `alignment_accelerator.py` accelerator) that crossover and distance both consume.

## Call contract (binding for `genome/base.py` and `algorithm/`)
- `BaseMutation.__call__(state, genome, key, node_keys, node_attrs, conn_keys, conn_attrs, new_node_keys (P,), new_conn_keys (P, 3)) -> GenomeTensors` — validates the two key shapes (`ConfigError`), then splits the key per stage and runs the structural stages before the value stage.
- `new_conn_keys` columns: `0` = add-node identity edge, `1` = add-node copy edge, `2` = plain add-connection edge; each becomes the `historical_marker` when the conn gene declares one.
- `BaseCrossover.__call__(state, genome, key, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> GenomeTensors` — `genome1` is the fitter parent and keeps its keys; identical parent shapes are required (`ConfigError`).
- `BaseDistance.__call__(state, genome, node_keys1 … conn_attrs1, node_keys2 … conn_attrs2) -> (P,) float32` — no key argument; the algorithm forms the pairs, distances are `0` for an empty pair and never NaN.
- Payload key ranks: node keys are `(P, N)` as `GenomeTensors` allocates them; `(P, N, 1)` is also accepted and returned verbatim. Connection keys are `(P, E, CK)`.
- `genome/base.py` forwards as `self.mutation(state, self, key, *payload, new_node_keys, new_conn_keys)`, `self.crossover(state, self, key, *genome1, *genome2)` and `self.distance(state, self, *genome1, *genome2)`; the trace-time `state` reaches every operator and is the only input that selects a formulation.
- The mutation operator reads only host statics off `genome`: `num_inputs`, `num_outputs`, `max_in_degree`, `network_type`, `node_gene`, `conn_gene` (the payload shapes carry `max_nodes`/`max_conns`); the cycle decision is `cycle.closes_cycle(node_keys, conn_keys, src_keys, dst_keys, key_span, state)`, reached only through the statically gated `network_type`/`p_recur` branches.

## Formulation seams (host | accelerator): one graph, one formulation
Three plain Python strings on the trace-time configuration `State` select every device-shaped route in this subtree; each is read on the host inside a trace and is never a traced value, so a graph contains exactly one spelling of each kernel.
`kernel_mode` (`"host"` default | `"accelerator"`) is read by `alignment_accelerator.kernel_mode`/`selected` (`KERNEL_MODE_KEY`/`KERNEL_MODES`), by `mutation/cycle_accelerator.py` for the cycle predicate, and by `common.schedule_accelerator` for the schedule (outside this node); an unknown value raises `TensorNEATError` naming both accepted spellings and nothing falls back silently.
`distance_formulation` (`"merge"` default | `"index_free"`) is read by `distance/index_free.formulation_mode`; only `BaseDistance._measure_family` consults it, so only the `prepare`/`measure` route can switch and the pair-wise `__call__` → `gene_distance` → `find_homologous` route stays on the merge by construction.
`distance_centre` (`"tiled"` default | `"single"`) is **not** read in this node: `algorithm/neat/_validation.distance_centre_mode` owns it, `DistanceRows.row` tiles a batch-1 centre only in `"tiled"` mode, and `DistanceRows.matrix` takes its grouped branch only while the mode is `"tiled"`.
`host_payload._formulation_statics` derives all three from one decision — whether the resolved device kind is GPU-class — as `"tiled"`/`"index_free"`/`"accelerator"` for a GPU-class kind and `"single"`/`"merge"`/`"host"` for every other kind and `None`, which is also what a bare `State()` yields.
All three sit in the executable-cache signature (`host_payload._formulation_signature`), so a flip rebuilds exactly once, and the host spellings are the shipped numpy bytes.

## The index-free equality-table idiom (all three accelerator modules)
"Which row of `keys2` carries this gene's key?" is answered on the compiled leg by one broadcast `equal` into a `(P, M, M)` boolean table plus `reduce_min(select(table, arange(M), M), axes=2)` — the *leftmost* matching row — with `col < M` reading back "no match" because the miss filler `M` can never win a minimum: no sort, no permutation, no `scatter`.
`argmax` is deliberately never used: it materialises a full `(P, M, M)` `int64` iota whose dispatch has no operands, so IREE scheduling leaves it outside every `stream.async.execute` region and `iree-compile` fails the assembled generation graph even though `ops.status` reports `v1`.
`alignment_accelerator.homologous_pair_accelerator` is that table over the key rows, `distance/index_free.resolve` the same table over the digest keys (centre side tagged, so homology *is* plain equality), and `mutation/cycle_accelerator._key_resolver` the same table over `(P, Q, 1)` query keys for the few lookups one candidate edge needs.
All three reuse `alignment`'s own identifiers (`row_identity`, `_TAG_PARENT_2`, `_pad_identity`, `_confirm_rows`, `_scalar`) rather than restating the packing rule, so no formulation can disagree with the host route about what a homologue is.

## Alignment (host merge | accelerator table)
`alignment.homologous_pair(keys1, keys2, *, state=None)` is the only aligner and serves both crossover and distance (`find_homologous` is its `I_INF`-marked reference form); the formulation is the trace-time static `state.kernel_mode`, branched once in `alignment._homologous`.
The host one — the default, and the only route the numpy reference interpreter takes — reduces each key row to one packed `int64` identity (`row_identity`: two 31-bit columns plus 2 tag bits, sign-flipped by `_order_ready` so a signed sort orders it like the unsigned pack), `argsort`s the concatenated `2M` identities **once**, reads each gene's rank and successor position back with **one encoded `int32` `sort`** (`_successor_ranks` encodes `order[s] * 2**K + min(s + 1, 2M - 1)`, a bijection whose sorted position *is* the row), tests "the element right after me is a parent-2 row with my identity", and confirms key columns past the packed prefix with `_confirm_rows`.
That is `O(M log M)` per individual in one batched kernel: two sorts, two row gathers, and **no `scatter` at all** — the rank inversion is a value sort, which is both cheaper on the reference interpreter and one portability rule fewer.
The parent tag lives in the low bits of the sort key, so inside a group of equal identities parent 1 sorts first and the ordering never depends on the sort being stable, which is why the `argsort` runs unstable (4× faster there).
The accelerator table replaces both sorts with one `(P, M, M)` broadcast `equal` of `identity1 | tag` against `identity2`, `col = reduce_min(select(table, arange(M), M), axes=2)`, `found = col < M`, then the merge's own `_confirm_rows`, padding term and `select(present, col, 0)` redirect.
Both routes return `(rows (P, M) int32, present (P, M) bool)` with the row redirected to `0` where the mask is `False`, so a consumer reads neither route differently; under the payload precondition (the first two key columns are unique within one parent) the identity is injective per parent, so the leftmost match **is** the merge's successor and the two records are bit-identical element by element.
`state=None` and any state without the entry resolve to `"host"`, and both spellings are plain traced helpers (never `@evoxc.defn`), so a backend never sees both.
Measured device cost (compile-time dispatch census of the assembled generation graph, `xor_p500` geometry, rocm/gfx942, IREE 3.11): host mode **325** dispatches, whose two alignment sorts are `sort_500x100xi32` and `sort_500x200xi32` at one workgroup per row — 64 000 threads, 2.03 + 0.28 ms of device time; accelerator mode **312**, both sorts absent on `rocm` and `llvm-cpu`, each family's table fused into one `linalg.generic` reduction dispatch (`reduction_500x100x100_i64xi64xi32xi32` at `[1000, 1, 1]` × 64 threads for the conn family, `reduction_500x50x50_i64xi64xi32xi32` at `[500, 1, 1]` × 64 for the node family).
That 325 → 312 delta also carries the `cycle_accelerator.py` switch the same entry selects; the alignment block alone is −17 net (22 dispatches removed, 5 added).
Measured numpy cost (`homologous_pair` isolated on an evolved-shaped payload, build excluded, medians): node family `(500, 50, K=1)` host **46 ops / 2.05 ms** against accelerator **29 ops / 2.96 ms**; conn family `(500, 100, K=2)` host **60 / 4.66 ms** against accelerator **43 / 8.97 ms** (P=1000: 60 / 3.70 ms against 43 / 20.57 ms).
Fewer ops but far more element volume — the table is 5 M booleans plus a 5 M-element `int32` `select` at conn geometry, and the innermost-axis `reduce_min` is the 10–20× shape `genome/CONTEXT.md` records — which is why `"host"` stays the default.

## Operator semantics (per-family detail lives in the children)
Mutation is a batched *plan → apply* kernel run once per operation: one `evoxc.random.uniform(key, (4, P))` draw supplies four **independent** gates in the order `(node_add, node_delete, conn_add, conn_delete)`, so one individual can receive several structural changes in one call, and the four stages run sequentially in legacy order so a later one sees the earlier one's writes.
At most one change applies per *operation* per individual per call, every private helper takes a trailing `(P,) bool` gate and is a batch-wide no-op where it is false (`select` returns the row bit-for-bit, `-0.0` and NaN included), a probability of `0` keeps that operation's whole chain out of the graph, and value mutation always runs afterwards.
Add-node writes the new node at the first free row with `node_gene.new_identity_attrs`, an identity edge (weight `1`) and a copy edge (recorded original attributes); it is refused when fewer than two connection rows are free before the delete, when the caller's allocated node key already appears in `node_keys`, or when the consumed edge points at a destination above `max_in_degree`.
A split is not output-preserving (`new_identity_attrs` keeps the aggregation/activation defaults, worst |Δoutput| 0.236, recorded in `genome/CONTEXT.md`), which matches the pre-rewrite library's split semantics and is therefore behaviour, not a defect.
Add-connection refuses an `I_INF` endpoint, a duplicate `(in_key, out_key)` pair, a cycle when `network_type == "feedforward"`, and a destination already at `max_in_degree`; both endpoints come from one pick over the stacked `present_node`/`targetable_node` masks and one flat gather, so each key and its row agree by construction.
Delete-node never names an input or output row and detaches every touching connection through the plan's `drop` mask; delete-conn clears exactly one row.
`RecurrentMutation` replaces only the add-connection step: one `(P, max_conn_tries, 2)` `randint` tableau plus one `(P, max_conn_tries)` `uniform` `p_recur` decision, the first accepted attempt chosen with a reduce (no `cond`), and a `p_recur` hit makes "closes a cycle" a hard requirement; `p_recur == 0` draws nothing, skips the whole cycle region (~106 traced ops) and degenerates to `DefaultMutation`.
The cycle predicate is one `evoxc.while_loop` monotone frontier relaxation, never an unrolled `max_nodes - 1` hop relaxation; the host body resolves keys through a dense key→row table (one flat `scatter`) and reads the frontier with one flat `gather`, so a hop is four `O(E)` ops, while the accelerator body resolves keys with an equality template plus `reduce_min` and carries a scatter-free `(P, N+1) bool` reached set — both **81 traced ops**, two `scatter`s against none (`mutation/CONTEXT.md` holds the device and numpy comparisons).
`DefaultCrossover` always keeps parent 1's structure and recombines attributes only: a gene whose exact key-column tuple has a homologue in parent 2 is crossed per attribute by `gene.crossover`, one without a homologue keeps parent 1's attributes, padded rows stay padded, and `gene.attr_width == 0` returns `attrs1` unchanged.
`DefaultCrossover` exposes `find_homologous(keys1, keys2, *, state=None)` and `align_gene_rows(keys1, keys2, *, state=None)` (both forwarding the state into `../alignment.py`) plus `crossover_gene_attrs(state, gene, key, attrs1, aligned, attrs2)`, which pays one `gather_attr_rows` for the whole `(P, M, A)` block, one batched `gene.crossover`, and one rank-3 `select` against the alignment's own mask.
Distance has two shapes of the same arithmetic — the pair-wise `__call__` and the two-phase `prepare`/`measure` pair speciation uses — and both end in the same scalar tail (`DefaultDistance.distance_from_alignment`), so they are bit-identical rather than merely close.
`measure`'s route is `dense` for a batch-1 centre (the live host leg, gated by `DefaultDistance(dense_single_centre=True)` and skipped under `index_free` because it is scatter-based), `index_free` on an accelerator state, and the sort-based merge otherwise; a `GroupedDigest` goes straight to the row-wise merge, and `ConstantPool` is the per-trace rank-0 constant bundle.
Everything centre-independent — rank-0 constants, merge index blocks, fold matrix, padding column, dense table geometry — is built once per generation in the digest, so `measure`'s body emits no `constant` op and no static index arithmetic.
A zero attribute width (`attr_specs = ()`, an unweighted HyperNEAT/CPPN edge) is supported through the whole chain: the attribute block passes through unchanged and the distance falls back to the structural disjoint/excess term, both as static Python branches, so `Pipeline.step` → `tell` cannot raise `ZeroDivisionError`.

## Cost law (measured on this tree, 2026-11-06)
Per-generation wall clock, one generation per case on the benchmark geometries (`../../benchmarks/cases.py`), numpy reference interpreter against iree+rocm:

| case | numpy ms/generation | iree+rocm ms/generation | numpy dispatched ops/generation |
|---|---|---|---|
| `xor_p100` | 33.04 | 17.42 | — |
| `xor_p500` | 112.68 | 13.24 | 7 592 |
| `xor_p1000` | 177.43 | 16.29 | — |
| `custom_pagie_p500` | 847.13 | 16.18 | — |
| `cartpole_p100` | 248.70 | 150.41 | 30 994 |

On the numpy interpreter one dispatched op costs ≈19–20 µs on population-shaped operands, so **op count is the budget for elementwise/gather/select/reshape work** and element volume decides the wide passes; `constant`, `reshape` and `arange` each cost a full op and evoxc never deduplicates constants, so a distinct value is built once per trace and threaded through (`ConstantPool`).
On the iree+rocm leg a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, one `while` iteration ≈50 µs and one `Tensor.to(cpu)` ≈47–60 µs per leaf, so a launch-bound graph is costed by dispatch count and `while` trips, not by element volume — which is why the tablet/reduction formulations that lose on numpy win there, and why the compiled leg beats numpy on the flat func-fit cases and loses on the rollout-heavy one.
The box drifts ±30 % between sessions: only a same-session A/B pair or a same-run old-vs-new ratio is load-bearing, never absolute milliseconds.

## Constraints
- No `jax`/`torch`/`numpy.random`; no `vmap`/`scan` over individuals; no Python loop over individuals — operators are already batched and never sit inside the `grad` graph, so `argsort` is legal here.
- `while_loop` is allowed only where it replaces a statically unbounded unroll of *identical* work (the cycle check), and its per-hop frontier stays flat with one trailing dump column so a hop is four `O(E)` ops.
- Static Python `if` is used only for host configuration (probabilities, `network_type`, key width, the formulation statics); every per-individual decision is a `select`/mask.
- **A device-specific formulation is a host-string branch, never a traced value**, and an unknown value raises rather than falling back — so a graph carries exactly one spelling of each kernel and the numpy/CPU default path is the shipped code byte for byte.
- evoxc's numpy backend raises on an out-of-range gather/scatter index, so every index is masked or clamped before it reaches the backend (`masked_flat_gather`/`masked_flat_scatter` from `common.tools`, or a caller-provided *in-range* index where the code already guarantees it).
- Rank-0 constants cost one traced op each and evoxc never deduplicates them: build each distinct value once per trace rather than at every use site, and remember a bare Python literal promotes `int32`/`float32` to `int64`/`float64`, so the typed constant is still required.
- Configuration violations raise `ConfigError` (a `TensorNEATError` subclass) at construction time; `evoxc` errors are never caught or re-wrapped.
- `argsort` is called with `stable=True` wherever one input run is already ordered (the digest half of a merge) or where tie order must be pinned: stability is free, timsort detects the run, and it makes the reference interpreter agree with a compiled backend's count-mode tie order.
- Traced-op budget is the lever, but element volume is what the clock pays at pop ≥ 500: the merge's `(P, 2M)` `int64` blocks are 6.4 MB each at `4P`/`max_conns=100`, which is why the conn family costs twice the node family at the same op count.
- Element-volume rules are layout-specific and measured, not guessed: an innermost-axis reduce over the `(P, N, K)` incoming window is 10–20× an ordinary op (fold the `K` slices), while for the `(P, max_conn_tries, E)` slabs of the recurrent add-connection the **contiguous innermost** axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms).
- `measure` holds one `(P, M, A)` and one `(P, 2M)` temporary per call and the digest four arrays per family; peak RSS at pop 1000 is ~2.1 GiB (pop 500: ~1.1 GiB), so a new full-size temporary in that path is a real regression even when it saves ops.
- **No unsigned dtype in a graph — `iree`'s declared dtype set has none** (`float16/float32/float64/int8/int16/int32/int64/bool`), so one `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the whole graph. Use **same-width signed carriers**: two's-complement add/sub/shift/or/xor/cast and `equal` produce the identical bit pattern. Only *order* differs, so wherever a carried value is ordered rather than compared (`sort`/`argsort`/`<`/`reduce_max`), restore the unsigned order explicitly — that is `alignment._order_ready`, one `bitwise_xor` with the sign bit (`-2**63` as an `int64` constant, the only spelling `enp.full` accepts), a bijection that preserves equality exactly.
- **No op may be a StableHLO v1 export deferral**: `evoxc/backends/stablehlo/ops.py::DEFERRED_OPS` (plus anything unmapped) fails `evoxc.lower(..., backend="iree")`. `cumsum` is deferred (`erf`/`gelu`/`tril`/`flip`/`diagonal`/`cholesky`/`qr`/`svd`/`matrix_rank`/`matrix_exp` are the other names to avoid), so a prefix/suffix count is a log2-doubling fold of `pad` + `slice` + `add`; `sort`, `argsort`, `gather`, `scatter`, `select`, `concatenate`, `pad`, `slice`, `reduce_(sum|max|min|prod)`, `dot`, comparisons, casts and the bitwise ops are all v1.
- Files stay under ~1000 lines: `distance/base.py` sits exactly on it and `distance/digest.py` (953), `mutation/base.py` (874) and `alignment.py` (723) are the next largest; everything else runs from 748 down to 26.

## Deviations from the pre-rewrite library (intentional)
- Alignment is exact key-tuple equality through the packed-identity merge, never row position or an innovation-number match, which is why `(genome1, genome2)` = (winner, loser) is order-sensitive by contract.
- The four plan functions (`plan_add_node`/`plan_delete_node`/`plan_add_conn`/`plan_delete_conn`) take the trailing `(P,) bool` gate, and delete-node reads the static row counts `genome.num_inputs`/`genome.num_outputs` instead of the legacy `input_idx`/`output_idx` lists.
- Non-finite distance weights are rejected as well as negative ones, and `compatibility_disjoint`/`compatibility_weight` are validated at construction.

## Test Strategy
`test/unit/genome/test_mutation.py`, `test_crossover.py`, `test_distance.py` and `test_distance_digest.py` are the acceptance specs for the contracts above (`uv run pytest -o addopts="" -q test/unit/genome` → 154 passed on numpy, no optional extra), and `test/parity/test_distance.py` holds `execute_distance` exactly against the frozen legacy implementation (a deterministic kernel, so no tolerance; 60 passed with the `bench` extra).
`find_homologous` is checked against a pure-Python `{key tuple: row}` oracle at key widths 1/2/3, with shuffled parent-2 rows and an adversarial case whose packed prefixes match while the third (`historical_marker`) column differs.
The accelerator formulations have **no committed test** (`./test` is a sibling node): they are gated by an ad-hoc identity matrix that measured **0 mismatches** on contract-conforming payloads — 10 evolved generations at pop 100/500/1000 for `DefaultGenome`, pop 100 for `RecurrentGenome` and pop 100 for an `OriginConn` mutation (the three-column `_confirm_rows` path), 18 cross/self parent pairs per configuration through both `homologous_pair` and `find_homologous`, plus all-padded, padded-versus-real, single-row, out-of-span keys and a `historical_marker` clash.
The generation-level gate is 10 seed-42 `Pipeline.step` generations on `xor_p500`/`xor_p1000` with a per-generation sha256 over the four `previous_pop` arrays and `fitnesses`: `d43edd0d…e4c96e` (P=500) and `caba83ee…66bd45` (P=1000) in both modes; the bit-exactness protocol and its reference digests live in `../CONTEXT.md`.
The missing regression guard is a `test/backends` cell that builds a gated pop-100 graph in accelerator mode, and the cheapest close of the alignment gap is replaying the matrix above inside `test/unit/genome/test_crossover.py` with `State().register(kernel_mode="accelerator")`.
For an op-diet change, the behaviour-neutral gate is a fixed-input oracle (a real evolved seed-42 XOR population replayed through `execute_crossover`, `execute_distance`, `prepare_distance`, `measure_distance` and compared bytewise, NaN-aware) plus the wide `DistanceRows` path (tiled centres × P rows) against batch-1 `measure`.
**StableHLO portability** (`evoxc.backends.stablehlo.export`; procedure and the `TensorSpec` gotcha in `../CONTEXT.md`): the crossover graph exports at **33 373 bytes, 112 op uses over 6 distinct ops** (`broadcast_in_dim` 74, `compare` 20, `slice` 6, `gather` 6, `sort` 4, `concatenate` 2, no `scatter`) and passes; the gate has been run on the generation, mutation and crossover graphs, and the distance graphs (`execute_distance`, `prepare_distance`/`measure_distance`) are **not** covered by it.
Trace a bound method through a closure (`lambda *a: obj.method(state, *a)`) and build rank-0 RNG keys *inside* the trace (`evoxc.random.key(seed)`), because an `evoxc` key cannot cross the graph boundary as data.
The full suite measured on this tree with `uv sync --all-extras`: `uv run pytest -o addopts="" -q` → 1370 passed.

## Known Issues
- **This node's graphs are StableHLO-v1 clean, and the sibling-owned sites are clean too**: auditing the two graphs a real `setup()`+`step()` builds (`DefaultGenome(2→1, max_nodes=12, sigmoid)` + `NEAT(pop_size=100, species_size=10, survival_threshold=0.01)` + `XOR()`, seed 42, 79 + 2357 traced ops) finds 0 unsigned sites and 0 deferred ops, so the assembled graph lowers, compiles and runs on `backend="iree"`.
- Every kernel here `lower`s, compiles and **runs** on `backend="iree"` against a real evolved payload: `find_homologous`, `execute_crossover`, `execute_distance` and `closes_cycle` are bit-identical to numpy, and `execute_mutation` is identical in both key arrays (structure, 0 differences) while differing in **91 of ~197 k** float attribute entries by ≤ 2.4e-7 (1 ulp) — float arithmetic in the gene-side value mutation (`gene/blocks.py`), not RNG (evoxc's `uniform`/`randint` measure bit-exact between backends); the numpy backend stays bit-identical, which is the contract.
- Per-kernel compilation proves nothing about the assembled generation graph, because `iree-compile` can still crash on the whole graph when every kernel lowers and runs standalone: the concrete case is a boolean `scatter` as a `while_loop` initial value, which SIGSEGVs `iree-compile` in the generation graph although the same `closes_cycle` kernel compiles standalone, which is why that frontier seed is a one-hot `equal`/`logical_and` (`mutation/CONTEXT.md` holds the evidence).
- **Intra-parent duplicate key rows are the one place the formulations diverge, and the host merge is not self-consistent there either**: the merge reads the *unstable* `argsort` order inside a group of equal identities, so which duplicate's successor a row becomes is a property of the sort implementation, while the accelerator table deterministically marks every duplicate that has a match and points at the leftmost matching row (`keys1` sharing key 7 twice gives host `present [0,1,0,0]` against accelerator `[1,1,0,0]`).
  `distance/index_free.py` makes the analogous choice (the table marks every duplicate, the merge only the last), the payload contract forbids the case (first two key columns unique within one parent, guaranteed by `initialize` and `execute_mutation`'s duplicate refusal), every evolved payload measured agrees exactly, and the divergence is documented rather than repaired.
- Coverage gaps owned here: `mutation/degree.py` has no caller and no test, the three accelerator formulations and the three statics are gated only by hand-run identity matrices plus the generation digest, and the distance graphs are outside the StableHLO export gate.
- `mutation/base.py`'s four-stage scaffold, `mutation/cycle.py`'s hop cost, the `distance` sort/route trade-offs and `crossover`'s `gene.crossover` share are the per-family hot spots; each is recorded in its own child's `## Measured cost` / `## Known Issues` and belongs there, not here.
- Op blocks outside this node worth a shared idiom: `gene/base.py::column` reads each attribute column as a kept-axis `slice` plus `reshape`, `gene/*/mutate` costs ~65 traced ops per call (`genome/CONTEXT.md`), and `common/tools.py::fetch_random`/`fetch_first` pay two sentinel `select`s each where `mutation/arrays.py`'s `(row, hit)` pair is the cheaper primitive.

## Call-site census (verified with `rg` over `src`, `test`, `examples`, `benchmarks`, `docs`, `tutorials` and every `CONTEXT.md`)
`mutation/degree.py` (`in_degree`/`max_in_degree`/`violation`) is exported by `mutation/__init__.py::__all__` and documented by its own autodoc stub, and **has no caller anywhere in the repo** — no kernel, no test, no example, no benchmark; `execute_mutation` enforces the ceiling inline instead, and the test that would close it asserts `violation(...) == 0` on an evolved payload before and after a mutation call.
`alignment.find_homologous` has callers in `src/`: the pair-wise distance route (`DefaultDistance.gene_distance`, reached through `BaseGenome.execute_distance`, which passes **no** state and therefore always takes the host formulation) and `DefaultCrossover.find_homologous`, which forwards `state` but which only tests drive; the live crossover path is `align_gene_rows` → `alignment.homologous_pair`, and it is the only path `state.kernel_mode` can switch for crossover.
`distance/layout.py::dense_slot`, `distance/digest.py::match_rows` and `distance/base.py::BaseDistance.gene_measure` are `__all__` members with no caller; `gene_measure` starts its own `ConstantPool()` (`distance/base.py:384`), so it can never share a generation's constants, and `measure` → `_measure_family` is the live path.
`DistanceDigest.field_names` is read only by `test/unit/genome/test_distance_digest.py`.
The grouped route's `group_digest`/`group_size`/`for_state`/`centre_batch` have exactly one caller, `algorithm/neat/_distance.py::DistanceRows.matrix`, and `DistanceRows.__call__`/`row` never group.
