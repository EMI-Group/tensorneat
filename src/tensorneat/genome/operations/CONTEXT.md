# operations — batched genetic operators

## Intent
Mutation, crossover and compatibility distance as batch-first kernels over the split gene payload (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`), population on axis 0, every shape static at build time.
This node also owns the structural invariants that keep the execution schedule valid: `max_nodes`, `max_conns` and `genome.max_in_degree` are hard caps and a refused operation is a no-op for that individual, never a silent repair.
Operators never allocate RNG keys or structural keys: the algorithm draws `key` and allocates `new_node_keys`/`new_conn_keys`, so a `(seed, config, shape)` triple reproduces a run.

## Call contract (binding for `genome/base.py` and `algorithm/`)
- `BaseMutation.__call__(state, genome, key, node_keys, node_attrs, conn_keys, conn_attrs, new_node_keys (P,), new_conn_keys (P, 3) -> GenomeTensors` — validates the two key shapes (`ConfigError`), then `split_n(key, 2)` and runs the structural stage before the value stage.
- `new_conn_keys` columns: `0` = add-node identity edge, `1` = add-node copy edge, `2` = plain add-connection edge; each becomes the `historical_marker` when the conn gene declares one.
- `BaseCrossover.__call__(state, genome, key, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> GenomeTensors` — `genome1` is the fitter parent and keeps its keys; identical parent shapes are required (`ConfigError`).
- `BaseDistance.__call__(state, genome, node_keys1, node_attrs1, conn_keys1, conn_attrs1, node_keys2, node_attrs2, conn_keys2, conn_attrs2) -> (P,) float32` — the algorithm forms the pairs; distances are `0` for an empty pair and never NaN.
- Payload key ranks: node keys are `(P, N)` as `GenomeTensors` allocates them; `(P, N, 1)` is also accepted and returned verbatim. Connection keys are `(P, E, CK)`.
- `base.py` forwards as `self.mutation(state, self, key, *payload, new_node_keys, new_conn_keys)`, `self.crossover(state, self, key, *genome1, *genome2)` and `self.distance(state, self, *genome1, *genome2)`.
- The mutation operator reads only host statics off `genome`: `num_inputs`, `num_outputs`, `max_in_degree`, `network_type`, `node_gene`, `conn_gene` (the payload shapes carry `max_nodes`/`max_conns`); the cycle decision is `cycle.closes_cycle(node_keys, conn_keys, src_keys, dst_keys)`, reached only through the statically gated `network_type`/`p_recur` branches.

## Mutation semantics
One `evoxc.random.uniform(key, (4, P))` draw supplies four **independent** gates, rows in the order `(node_add, node_delete, conn_add, conn_delete)`: row `i` fires where `drawn[i] < probability[i]`, so one individual can receive several structural changes in one call (the frozen legacy library's Bernoulli-per-operation law).
The four operations are applied as four sequential stages in legacy order — add-node, delete-node, add-conn, delete-conn — each rebuilding the `EditContext`, planning exactly one operation and writing it with `plan.apply`, so a later operation sees the earlier one's writes.
At most one change applies per *operation* per individual per call, and value mutation always runs afterwards.
Each private helper takes a trailing `(P,) bool` gate and is a batch-wide no-op where it is false; `select` returns the untouched row bit-for-bit, `-0.0` and NaN included, so a probability of `0` is the identity.
Add-node is the only structural change that writes a new node row: the chosen connection is deleted, the new node is written at the first free row of the `context.free_node` mask (`arrays.first_row`) with `node_gene.new_identity_attrs`, an identity edge (`conn_gene.new_identity_attrs`, weight `1`) runs old source → new node and a copy edge (recorded original attributes) runs new node → old destination. It is refused when fewer than two connection rows are free *before* the delete.
A split is not output-preserving: `new_identity_attrs` keeps `aggregation_default`/`activation_default`, so the new node re-aggregates and re-activates (worst |Δoutput| 0.236, recorded in `genome/CONTEXT.md` `## Known Issues`), which matches the pre-rewrite library's split semantics and is therefore behaviour, not a defect.
Add-connection draws its two endpoints with one draw each and refuses an endpoint of `I_INF`, a duplicate `(in_key, out_key)` pair, a cycle when `network_type == "feedforward"` (`cycle.closes_cycle`), and a destination already at `max_in_degree` incoming edges.
Add-node validates the caller's allocation (11 traced ops, refusal a bit-exact no-op): it refuses a split whose allocated node key already appears in `node_keys` — a duplicate key folds two rows onto one schedule slot — and one whose consumed edge points at a destination already above `max_in_degree`; `algorithm/neat/_keys.py::node_keys_for_split` allocates those keys from the mutated payload's own `max_node_key` inside the wrapped free window `[max_nodes, key_span)` with a lowest-free-key collision fallback, so an allocation is never a key the payload already owns and never outside `[0, key_span)`, and the guard stands as the node boundary's bit-exact refusal.
`./mutation/degree.py` is the standalone diagnostic audit (`in_degree`, `max_in_degree`, `violation`): `execute_mutation` enforces the ceiling inline and never calls it, and its exported-but-untested status is in `## Call-site census`.
Delete-node never names an input row (`0..num_inputs-1`) or an output row (`N-num_outputs..N-1`) and detaches every touching connection through the plan's `drop` mask (`plan.DeleteNodePlan.drop`); delete-conn clears exactly one row.
Both add-connection endpoints come from one `_fetch_two` pick over the stacked `context.present_node`/`context.targetable_node` masks and one flat gather on the chosen rows, so each key and its row agree by construction and neither endpoint can be `I_INF`.
`RecurrentMutation` replaces only the add-connection step: one `(P, max_conn_tries, 2)` `randint` tableau plus one `(P, max_conn_tries)` `uniform` `p_recur` decision, the first accepted attempt chosen with a reduce (no `cond`), and a `p_recur` hit makes "closes a cycle" a hard requirement; `p_recur=0` draws nothing and degenerates to `DefaultMutation`.
Its element-volume trap is materialising `(P, max_conn_tries, E)` slabs (~2 M elements each; six of them cost 72.5 ms at pop 1000 and 616 traced ops), so the kernel keeps two **bool** slabs and gathers on `(P·tries)` blocks: 498 traced ops and 28.3 ms at pop 1000, 15.9 ms at 500, 6.1 ms at 100.
Structural resolution is plan-based: the four helpers only decide *what* to write (`plan.py`), one `select` per write slot applies it, and "no write" is the array's own row count — so a refused operation stays a bit-exact no-op without a dump row or a flat index block.
`execute_mutation` is **578 traced ops** for `DefaultMutation` at pop 500 (96 shared scaffold + 137 add-node / 67 delete-node / 230 add-conn / 48 delete-conn, exactly additive), against 432 traced ops for a one-shared-gate formulation; the base's four-stage scaffold is described in `./mutation/CONTEXT.md`.
`cycle.py`'s single `while_loop` keeps a hop at four `O(E)` ops rather than one of 49 unrolled hops (15 ms saved per call at pop 1000), and a recurrent genome with `p_recur == 0` elides the whole cycle region because its only two consumers are the feedforward veto and the `p_recur` requirement (325 traced ops / 14.2 ms against 423 / 31.2 ms at pop 1000, 2.2×).
The traced-op counts and milliseconds in this section are this node's own measurements on the numpy reference interpreter, build excluded, one fresh process per population, on real evolved XOR payloads.

## Crossover semantics
`DefaultCrossover` always keeps parent 1's structure and recombines attributes only: a gene whose exact key-column tuple has a homologue in parent 2 is crossed per attribute by `gene.crossover`, one with no homologue keeps parent 1's attributes, and padded rows stay padded.
`alignment.homologous_pair(keys1, keys2, *, state=None)` is the only aligner and serves both crossover and distance (`find_homologous` is its `I_INF`-marked reference form); it has two formulations selected by the trace-time static `state.kernel_mode` (`## Alignment formulations` below).
The host one — the default, and the only route the numpy reference interpreter takes — is one packed `int64` identity per key row (`row_identity`, sign-flipped so a signed `argsort` orders it like the unsigned pack) → one `argsort` of the concatenated `2M` identities → each gene's rank as `argsort(order)` → successor test "the element right after me is a parent-2 row with my identity" → `_confirm_rows` for key columns past the packed prefix. `O(M log M)`, never an `O(M^2)` scan, one batched kernel.
`BaseCrossover.__call__` forwards its `state` into both `align_gene_rows(key1, key2, state=state)` calls, the symmetric spelling of `crossover_gene_attrs(state, ...)`; `state=None` — and any state without the entry — resolves to `"host"`, which is what the two-argument `find_homologous(keys1, keys2)` calls in `test/unit/genome/test_crossover.py` take.

## Alignment formulations (host merge | accelerator table)
Two spellings of the homologue table, both returning `(rows (P, M) int32, present (P, M) bool)` with the row redirected to `0` where the mask is `False`, so a consumer reads neither route differently.
The host merge (`./alignment.py`) is the shipped default and the one the numpy interpreter takes.
The accelerator table (`./alignment_accelerator.py`) is selected by `state.kernel_mode == "accelerator"`: `identity1 | tag` compared against `identity2` in one `(P, M, M)` broadcast `equal`, `col = reduce_min(select(table, arange(M), M), axes=2)` as the leftmost matching parent-2 row, `found = col < M`, then the merge's own `_confirm_rows` for a key wider than two columns and the merge's own padding term — **no sort, no permutation, no scatter**.
`alignment_accelerator.kernel_mode`/`selected` read the entry — `"host"` when `state` is `None` or the entry is absent, `"accelerator"` the second accepted value, anything else a `TensorNEATError` naming both — and `alignment._homologous` branches once on the host string, so a graph contains exactly one formulation.
The key and its two values are the package-wide `kernel_mode` contract: `./mutation/cycle_accelerator.py` reads the same entry for the cycle predicate, `host_payload._formulation_statics` registers `"accelerator"` for a GPU-class device kind and `"host"` otherwise, and `host_payload._formulation_signature` carries it in the executable-cache key, so switching modes rebuilds exactly once.
`find_homologous` forwards the state too, but its remaining compute caller — the pair-wise distance route `DefaultDistance.gene_distance` — passes none, so that route stays on the host formulation by construction; `measure` never touches `alignment` (it has its own digest and its own `distance_formulation` switch), and the distance kernels are untouched by this switch.
Measured device cost (ROCm/gfx942, IREE 3.11, `xor_p500` geometry, compile-time dispatch census of the assembled generation graph): host mode **325** dispatches, whose two alignment sorts are `sort_500x100xi32` and `sort_500x200xi32` at `workgroup_count [500, 1, 1]` × `workgroup_size [128, 1, 1]` — one workgroup per row, 64 000 threads, the recorded 2.03 + 0.28 ms of device time; accelerator mode **312** dispatches with **both sorts gone** on `rocm` and on `llvm-cpu`, each family's table fused into one `linalg.generic` reduction dispatch (`reduction_500x100x100_i64xi64xi32xi32` at `[1000, 1, 1]` × 64 threads for the conn family, `reduction_500x50x50_i64xi64xi32xi32` at `[500, 1, 1]` × 64 for the node family).
That 325 → 312 delta also contains the `mutation/cycle_accelerator.py` switch, which the same entry selects; the alignment block alone is −17 net (22 dispatches removed, 5 added) and the two `sort` symbols are absent from both target configurations.
Measured numpy cost (`homologous_pair` isolated on an evolved-shaped payload, build excluded, medians): node family `(500, 50, K=1)` host **46 ops / 2.05 ms** against accelerator **29 ops / 2.96 ms**; conn family `(500, 100, K=2)` host **60 ops / 4.66 ms** against accelerator **43 ops / 8.97 ms** (P=1000: 60 / 3.70 ms against 43 / 20.57 ms).
Fewer ops, much more element volume — the `(P, M, M)` table is 5 M booleans plus a 5 M-element int32 `select` at conn geometry and the innermost-axis `reduce_min` is the 10–20× shape `genome/CONTEXT.md` records — which is exactly why `"host"` stays the default.

## Distance semantics
Two shapes of the same arithmetic: the pair-wise `__call__` (fitter/first parent pair per row) and the two-phase `prepare`/`measure` pair speciation uses, where the population side is sorted **once per generation** and each wide `measure` call only merges the centres against that digest.
Both routes end in the *same* scalar tail (`DefaultDistance.distance_from_alignment`, which re-spells the aligned rows as an `I_INF` row table and defers to the documented `distance_from_rows`), so they are bit-identical rather than merely close.
`gene_distance` (pair-wise) takes its homologue table from `alignment.find_homologous`; `measure` takes it from `digest.measure_alignment`, which returns `AlignedGenes(rows, homologous, count, matched)` so no consumer re-derives a mask or a count.
`execute_distance` measures **212 traced ops** at `5.83 / 10.04 ms` for pop 500 / 1000 on the generation-5 payload.
Per-call two-phase cost (medians, build excluded): `prepare` **163 ops** at `2.63 / 4.13 ms`, `measure` **94 ops** on the merge route (`2.56–2.62 / 4.33–4.43 ms`) and **102 ops** on the dense single-centre route (`1.38 / 2.03 ms`) for pop 500 / 1000.
The merge's 94 ops still cost ~2× the dense route's 102 for the same reason: the merge sorts and the dense route gathers — two `argsort`s per family over the `(P, 2M+1)` int64 composite block are 27–30 % of the call, which is wall-clock work that op count does not show. Measure per-call time, not ops, before believing a change paid (`./distance/CONTEXT.md` holds the per-op budget).
`measure`'s cost is set by **sort semantics**: `argsort(..., stable=True)` is timsort in the numpy reference interpreter, which detects the digest half's existing ascending run, so the merge sort drops to roughly sorting the centre's own `M` values at zero extra ops (`stable=` is an attribute; the inverse permutation gains the same way, and the unstable kind measured 3.08 against 2.62 ms per call at pop 500).
Every tensor `measure` needs that does not depend on the centre — rank-0 constants, the `(P, 1)` merge index blocks, the `(P, 1)` attribute row base, the fold matrix, the padding column, the dense table geometry — is built once in `prepare` and carried in the digest, so the `measure` body emits **no** `constant` op and no static index arithmetic.
The generation's distance bucket is **3 538 executed ops** at pop 500 and the `Pipeline.step` median there is `177.8 ms` (this node's own measurement, consistent with the 178.24 ms `xor_p500` entry in `benchmarks/PERF_NUMPY.md`).
`measure` is dominated by those two sorts per family (the aligned-attribute tail is the rest of its ops), so the next lever is *route*, not formulation: the live call site tiles a batch-1 centre to `P` rows and therefore never reaches the sort-free dense route.
The body is at its dispatch floor — a narrow `(P, M)` pass costs 0.065–0.10 ms at pop 500 in-kernel (numpy's own work there is 2–5 µs), i.e. ~0.056 ms per executed op over the whole 94-op call — so a ≥5 % per-call win needs ≥5 ops removed and the two remaining micro-candidates together are ~2 %.
Both structural rewrites the op count invites are refuted in `./distance/CONTEXT.md::## Rejected`: an elementwise centre fold in place of the `dot` (2.8× slower) and one sort fused across both families (−7 ops but +10 % at pop 500, +15 % at pop 1000, because `argsort` cost is superlinear in row width).
The merge algebra (injective `2**31` fold, digest-side-first concatenation so a population gene's merged index *is* its digest row, `argsort(order)` inverse, successor test against `composite + 1` with a trailing padding column instead of a clamp, `_confirm_rows` for a third key column) is stated in `./distance/CONTEXT.md`.
`ConstantPool` (`./distance/consts.py`) exists because `enp.full((), v, dtype)` emits one `constant` op per call and evoxc never deduplicates: one pool per trace puts the distance files at **163** constant ops per generation (503 without pooling), and hoisting the surviving constants into the digest removes the per-call ones entirely.
Non-homologous slots are zeroed **before** the attribute `reduce_sum` (a `NaN * 0` product would poison the sum), the attribute term uses `BaseGene.distance` (`|delta|` for float columns, `!=` for int option columns), and the empty-pair guard folds into `maximum(float32(max(cnt1, cnt2)), 1.0)` with one `divide` so no pair can be `inf`/NaN.
A **zero attribute width** (`attr_specs = ()`, an unweighted HyperNEAT/CPPN edge) is supported: `digest._gather_rows` returns the `(P, M, 0)` block unchanged (a zero-width row has exactly one permutation) and `distance_from_alignment` returns the structural disjoint/excess term alone, so `Pipeline.step` → `tell` cannot raise `ZeroDivisionError`; both guards are static Python branches, so the width ≥ 1 path keeps its exact op counts and bytes.

## Constraints
- No `jax`/`torch`/`numpy.random`; no `vmap`/`scan` over individuals; no Python loop over individuals — operators are already batched and never sit inside the `grad` graph, so `argsort` is legal here.
- `while_loop` is allowed only where it replaces a statically unbounded unroll of *identical* work: the cycle check uses one region, and its per-hop frontier stays flat (`(P*(N+1),)` with one trailing dump column) so a hop is four `O(E)` ops.
- Static Python `if` is used only for host configuration (probabilities, `network_type`, key width); every per-individual decision is a `select`/mask.
- **A device-specific formulation is a host-string branch, never a traced value**: `state.kernel_mode` is read once per trace (`alignment_accelerator.kernel_mode`), `state=None` resolves to `"host"`, an unknown value raises `TensorNEATError` naming both accepted values, and nothing falls back silently — so a graph carries exactly one alignment formulation and the numpy/CPU default path is the host merge byte for byte.
- evoxc's numpy backend raises on an out-of-range gather/scatter index, so every index is masked or clamped before it reaches the backend (`masked_flat_gather`/`masked_flat_scatter` from `common.tools`, or a caller-provided *in-range* index where the code already guarantees it).
- Rank-0 constants cost one traced op each and evoxc never deduplicates them: build each distinct value **once per trace** (a `ConstantPool`-style bundle threaded through the kernel, or the entry point's own bundle) rather than at every use site; a bare Python literal additionally promotes `int32`/`float32` to `int64`/`float64`, so the typed constant is still required.
- Configuration violations raise `ConfigError` (a `TensorNEATError` subclass) at construction time; `evoxc` errors are never caught or re-wrapped.
- Files ≤ ~1000 lines (`distance/digest.py` 930 is the largest, then `gene/base.py` 912, `mutation/base.py` 874, `distance/base.py` 731, `alignment.py` 680, `distance/layout.py` 643).
- `argsort` is called with `stable=True` wherever one input run is already ordered (the digest half of a merge) or where tie order must be pinned: stability is free, timsort detects the run, and it makes the reference interpreter agree with a compiled backend's count-mode tie order.
- Traced-op budget is the lever here, but element volume is close behind and it is what the clock pays at pop ≥ 500: the merge's `(P, 2M)` **int64** blocks are 6.4 MB each at `4P`/`max_conns=100` (measured on this node), which is why the conn family costs twice the node family at the same op count.
- Element-volume rules are layout-specific and measured, not guessed: an innermost-axis reduce over the `(P, N, K)` incoming window is 10-20× an ordinary op (fold the `K` slices), while for the `(P, max_conn_tries, E)` slabs of the recurrent add-connection the **contiguous innermost** axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms).
- `measure` holds one `(P, M, A)` and one `(P, 2M)` temporary per call and the digest four arrays per family; peak RSS at pop 1000 is ~2.1 GiB (pop 500: ~1.1 GiB) measured on this node, so a new full-size temporary in this path is a real regression even when it saves ops.
- **No unsigned dtype in a graph — `iree`'s declared dtype set has none** (`float16/float32/float64/int8/int16/int32/int64/bool`, `evoxc/backends/adapters/iree.py::_dtype_capabilities`), so one `uint32`/`uint64` operand, result, constant or graph-boundary value makes that backend refuse the whole graph. Use **same-width signed carriers**: two's-complement add/sub/shift/or/xor/cast and `equal` produce the identical bit pattern in `int32`/`int64`. The one thing that is *not* identical is **order**, so wherever a carried value is ordered rather than compared (`sort`/`argsort`/`<`/`reduce_max`), restore the unsigned order explicitly — that is `alignment._order_ready`, one `bitwise_xor` with the sign bit (`-2**63` as an `int64` constant, the only spelling `enp.full` accepts), a bijection that preserves equality exactly.
- **No op may be a StableHLO v1 export deferral**: `evoxc/backends/stablehlo/ops.py::DEFERRED_OPS` (plus anything unmapped) fails `evoxc.lower(..., backend="iree")` with `BackendError: op '<name>' ... is not supported in v1`. `cumsum` is deferred, so a prefix/suffix count is a log2-doubling fold of `pad` + `slice` + `add` (`mutation/cycle.py`), never `cumsum`; `erf`/`gelu`/`tril`/`flip`/`diagonal`/`cholesky`/`qr`/`svd`/`matrix_rank`/`matrix_exp` are the other names to avoid. `sort`, `argsort`, `gather`, `scatter`, `select`, `concatenate`, `pad`, `slice`, `reduce_(sum|max|min|prod)`, `dot`, comparisons, casts and the bitwise ops are all v1.

## Deviations from the pre-rewrite library (intentional)
- The four plan functions (`plan_add_node`/`plan_delete_node`/`plan_add_conn`/`plan_delete_conn`) take the trailing `(P,) bool` gate, and delete-node reads the static row counts `genome.num_inputs`/`genome.num_outputs` instead of the legacy `input_idx`/`output_idx` lists.
- Alignment is the packed-identity rank merge over `row_identity`: the parent tag lives in the low 2 bits of the `int64` sort key, so parent 1 sorts first inside a group of equal identities and the single `argsort` may run unstable; only key columns past the packed prefix are confirmed by `_confirm_rows`.
- Non-finite distance weights are rejected as well as negative ones, and `compatibility_disjoint`/`compatibility_weight` are validated at construction.

## Test Strategy
`test/unit/genome/test_mutation.py`, `test_crossover.py`, `test_distance.py` and `test_distance_digest.py` are the acceptance specs for the contracts above (measured on this tree: `uv run pytest -o addopts="" -q test/unit/genome` → 154 passed on the numpy backend, no optional extra), and `test/parity/test_distance.py` holds `execute_distance` exactly against the frozen legacy implementation (a deterministic kernel, so no tolerance; `test/parity` measures 60 passed and needs the `bench` extra).
`find_homologous` is checked against a pure-Python `{key tuple: row}` oracle at key widths 1/2/3, with shuffled parent-2 rows and an adversarial case whose packed prefixes match while the third (`historical_marker`) column differs (`_confirm_rows` must reject it).
`_successor_ranks`'s encoded-rank inversion is pinned only behaviourally, through `test_crossover.py` (parent-1 structure, attribute provenance, sentinels, self-crossover identity), so an op-diet change to that helper is gated by the bit-exactness protocol of `../CONTEXT.md`, not by a direct oracle.
The behaviour-neutral gates for an op-diet change here are fixed-input oracles: a real evolved seed-42 XOR population (pop 100, 2 steps) replayed through `execute_crossover`, `execute_distance`, `prepare_distance` and `measure_distance` on captured input payloads, compared bytewise (NaN-aware for padding rows) against a reference checkout of the pre-change source, plus the wide `DistanceRows` path (4 tiled centres × P rows) against batch-1 `measure`.
The run-level gate for anything this subtree touches is that same bit-exactness protocol — 10 generations at P=500 and P=1000, seed 42, a sha256 per generation's five payload/fitness leaves, reference digests in `../CONTEXT.md`.
**StableHLO portability** (`evoxc.backends.stablehlo.export`; procedure and the `TensorSpec` gotcha in `../CONTEXT.md`): this node's own measurement has the crossover graph exporting at **33 373 bytes, 112 op uses over 6 distinct ops** — `broadcast_in_dim` 74, `compare` 20, `slice` 6, `gather` 6, `sort` 4, `concatenate` 2, no `scatter` — and passing the gate (no deferred op, no unsigned dtype, every `dimension =` attribute non-negative).
The gate has been run on the generation, mutation and crossover graphs; the distance graphs (`execute_distance`, `prepare_distance`/`measure_distance`) are not covered by it.
Trace a bound method through a closure (`lambda *a: obj.method(state, *a)`) and build rank-0 RNG keys *inside* the trace (`evoxc.random.key(seed)`), because an `evoxc` key cannot cross the graph boundary as data.
The full suite measured on this tree with `uv sync --all-extras`: `uv run pytest -o addopts="" -q` → 1370 passed.

## Known Issues
- Remaining op blocks outside this node: `gene/base.py::column` reads each attribute column as a kept-axis `slice` plus `reshape` (two view ops, the cheapest differentiable read evoxc 0.1.0 offers; `gene/CONTEXT.md` holds the per-call figures, ≈0.09 ms per read and 0.42 ms for the whole eight-read `BaseGene.distance` kernel at `(500, 50, 4)`), `gene/*/mutate` costs ~65 traced ops per call (`genome/CONTEXT.md`), and `common/tools.py::fetch_random`/`fetch_first` pay two sentinel `select`s each (`mutation/arrays.py`'s `(row, hit)` pair is the cheaper primitive).
- Hot spot: `distance/digest.py::measure_alignment` — 43 % of a `measure` call at pop 1000 is the conn family, and the call is **sort bound, not op bound**: the two `argsort`s plus their two `int32` casts are 27–30 % of its milliseconds while the other ~90 ops are ordinary `(P, M)` passes (the per-op budget is tabulated in `./distance/CONTEXT.md`). The measured alternatives: a `log2 M`-step gather binary search of each centre composite in the digest's sorted block is *correct* (verified against a Python oracle) but **refuted on speed** — 14.06 ms vs 8.60 ms per wide conn `measure` at pop 1000, 81 vs 41 ops; a scatter-derived inverse permutation is behind on both ops (7 vs 2) and ms (1.05 vs 0.29) because the stable `argsort(order)` inverse is only 2 ops.
- Layout rule measured here: a `(P, M, A)`-shaped `int32` index block costs 10–20× a contiguous arithmetic op (two-axis broadcast), so index in `(P, M)` and gather along axis 0 of a hoisted `(P * M, A)` row view — worth 4 ops and 0.13 / 0.6 ms per `measure` call at pop 500 / 1000.
- Sort rule worth checking before any smaller `O(M log M)` formulation: `stable=True` (or `sort` instead of `argsort`) costs zero ops and, when one input run is already ordered, timsort removes most of the element volume.
- **This node's graphs are StableHLO-v1 clean, and the sibling-owned sites are clean too.** Auditing the two graphs a real `setup()`+`step()` builds (`DefaultGenome(2→1, max_nodes=12, sigmoid)` + `NEAT(pop_size=100, species_size=10, survival_threshold=0.01)` + `XOR()`, seed 42, 79 + 2357 traced ops) finds **0 unsigned sites and 0 deferred ops** from this subtree; the graphs a real pipeline builds contain no unsigned dtype and no deferred op either (`common/CONTEXT.md`), so both lower, compile and run on `backend="iree"` (the assembled-graph gate is the `test/backends` entry below).
- Every kernel in this node `lower`s, compiles and **runs** on `backend="iree"` against a real evolved payload: `find_homologous`, `execute_crossover`, `execute_distance` and `closes_cycle` are bit-identical to the numpy backend, and `execute_mutation` is identical in both key arrays (structure, 0 differences) and differs in **91 of ~197 k** float attribute entries by ≤ 2.4e-7 (1 ulp).
  That residue is float arithmetic in the gene-side value mutation (`gene/blocks.py`), not RNG (evoxc's `uniform`/`randint` measured bit-exact between the backends) and not this node's formulation; the numpy backend stays bit-identical, which is the contract.
- Per-kernel compilation proves nothing about the assembled generation graph: the gate is `test/backends` (one XOR generation end to end on IREE 3.11 llvm-cpu; measured on this tree: `uv run pytest -o addopts="" -q test/backends` → 13 passed, 3 `iree` cases plus 10 marker-guard cases, needs the `iree` extra), because `iree-compile` can still crash on the whole graph when every kernel lowers and runs standalone.
  The concrete case is a boolean `scatter` as a `while_loop` initial value: it SIGSEGVs `iree-compile` in the generation graph although the same `closes_cycle` kernel compiles and runs standalone, which is why that frontier seed is a one-hot `equal`/`logical_and` (evidence and cost in `./mutation/CONTEXT.md`, cycle-predicate section).
- The v1-portable formulations cost, measured on this node by running the compared formulations side by side on the same box: `closes_cycle`'s log2-doubling suffix scan in place of `cumsum` costs 24 traced ops and 8.60 ms per call at pop 1000, 4.30 at 500, 1.88 at 100; `_order_ready` costs 4 traced ops per `find_homologous` call and `execute_distance` 3.26 ms at pop 100; `prepare_distance` measures 1.340 ms per call. All three keep the numpy backend bit-identical.

## Call-site census (verified with `rg` over `src`, `test`, `examples`, `benchmarks`, `docs`, `tutorials` and every `CONTEXT.md`)
`mutation/degree.py` (`in_degree`/`max_in_degree`/`violation`) is exported by `mutation/__init__.py::__all__` and documented by its own autodoc stub, and **has no caller anywhere in the repo** — no kernel, no test, no example, no benchmark; it is kept because it is exported and documented, not because a kernel needs it.
All three degree kernels are therefore untested (a test gap, not a contract): `test/unit/genome/test_mutation.py` re-derives in-degrees with its own host NumPy helper instead, and the test that would close it runs an evolved payload through `execute_mutation` and asserts `violation(...) == 0` on the payload before and after, beside the same payload's host re-count.
`alignment.find_homologous` is exported and documented **and has callers in `src/`**: the pair-wise distance route (`DefaultDistance.gene_distance`, reached through `BaseGenome.execute_distance`, which passes **no** state and therefore always takes the host formulation) and `crossover/default.py::DefaultCrossover.find_homologous`, which forwards `state` and which only two tests in `test/unit/genome/test_crossover.py` drive; the live crossover path is `align_gene_rows` → `alignment.homologous_pair`, the same table without the `I_INF` select, and it is the only path `state.kernel_mode` can switch.
`distance/layout.py::dense_slot` and `distance/digest.py::match_rows` are `__all__` members with no caller, and `distance/base.py::BaseDistance.gene_measure` has no caller either.
`BaseDistance.gene_measure` starts its own `ConstantPool()` (`distance/base.py:384`), so it cannot share a generation's constants; `measure` → `_measure_family` is the live path.
`DistanceDigest.field_names` is read only by `test/unit/genome/test_distance_digest.py`.
