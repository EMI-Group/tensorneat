# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors and evaluate a whole population of differently-shaped networks in one batch-first kernel.
This node owns the **gene payload** (key columns `int32`, attribute columns `float32`, padded rows), the **genetic operators** (mutation/crossover/distance) as batched kernels, the **forward algebra** over a precomputed schedule plus the exact gradient path beside it (`grad.py`), and the host-only entry points (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`); nothing here runs a host helper inside a trace.
It does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG` (`../common/functions/`); it consumes both.
Every kernel family here (value seed, read-out, schedule, homologue alignment, cycle predicate, distance) ships a **host** spelling and an **accelerator** spelling, chosen by one static host branch on the trace-time `State`; the host spelling is the numpy default and the accelerator spelling is the compiled-device leg.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers:
- `node_keys (P, max_nodes) int32` — node key per row; `I_INF` marks an absent row.
- `node_attrs (P, max_nodes, node_gene.attr_width) float32` — custom attrs; absent rows are NaN.
- `conn_keys (P, max_conns, conn_gene.key_width) int32` — `(in_key, out_key)` plus `historical_marker` when the conn gene declares it; `I_INF` marks an absent row.
- `conn_attrs (P, max_conns, conn_gene.attr_width) float32` — e.g. `weight`; absent rows are NaN.
There is **no bitcast** float↔int in evoxc, so a mixed-dtype row is impossible: the operators twiddle integer `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is supported (HyperNEAT/CPPN): every attr helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with an attribute distance of 0.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys are rows `max_nodes-num_outputs..max_nodes-1`, never deleted or moved — a *template*, never the read-out rule, because the schedule resolves `output_slot` and the forward reads that, while `get_input_idx()`/`get_output_idx()` describe the template only.
Hidden node keys are arbitrary and may move rows; compare keys, never row positions, for graph identity, and never mix sentinels: `I_INF` (`int32` max) for "no index", float NaN for "no value" and for "unconnected node value".
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds the host-side configuration (plus `output_transform`/`input_transform`/`init_hidden_layers`) and the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key and is part of the Pipeline's shape signature; a key outside `[0, S)` is *silently unmatched* by the schedule's key table, the node's one silent-failure mode, reachable only out of band because `algorithm/neat/_keys.py::node_keys_for_split` allocates inside the window and `validate_key_space` rejects `key_span <= max_nodes` at `NEAT` construction (widening the table is not a search lever: 150 → 2000 lifts the 2-input XOR `-0.25` plateau, XOR3d stays at `-0.25` even at 4000).
`DefaultGenome` carries **no** mutation-rate knobs — `__init__` takes the five statics plus `node_gene`/`conn_gene`/`mutation`/`crossover`/`distance`/`output_transform`/`input_transform`/`init_hidden_layers`/`max_in_degree`/`max_depth=16`/`key_span`, each `None` building a fresh default per instance — so the structural probabilities live on the operator: `DefaultMutation()`'s defaults stay NEAT-python's `(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)`, while `DefaultGenome`/`RecurrentGenome` build `(0.1, 0.1, 0.4, 0.05)` when `mutation is None`; value rates live on each gene's `attr_specs` (`DefaultConn` 0.8 mutate / 0.15 power / 0.1 replace; `DefaultNode` 0.2 / 0.15 / 0.015 within ±5; option replace 0.1), with no enabled/disable knob.
`S` is a *schedule* bound only, so homologue identity never derives a packing radix from it (`alignment.py`/`distance/digest.py` fold keys in base `2**31`, injective for the whole `int32` range) and homology is exact for keys far outside `[0, S)`.
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_values`, composed into `BaseGenome` as a mixin before `BaseGenomeHost`; every kernel accepts both the `GenomeTensors` payload and the positional four-array spelling, and `node_exists`/`conn_exists`/`max_node_key`/`max_conn_marker` are the thin in-graph helpers `algorithm/` calls.
- `initialize(state, key, pop_size)` — one rank-0 `evoxc.random` key per tensor with the batched output shape, so individual `i` gets an independent stream from one call; structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** and passed in as int32 tensors, and `_check_key_shapes` refuses any other dtype with a `TensorNEATError`.
- `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed` — schedule derivation delegated to `../common/tensorization.py`; the keyword-only overrides pin which keys count as inputs/outputs (how one genome derives a substrate executor's `inputs, outputs, hidden` schedule), `input_keys` must equal this genome's own `input_idx`, a host `output_keys` may be any `num_outputs`-long integer sequence, and the payload contract (`node_keys (P, max_nodes)`, `conn_keys (P, max_conns, key_width)`, agreeing leading dimensions) is checked first on `.shape` only, so it traces no op and a rank-1 `node_keys`/rank-2 `conn_keys` is reported as a per-individual row that needs a leading population axis.
- `forward(...)`, `prepare_pass(..., samples=1)`, `forward_prepared(state, transformed, prepared, inputs)` — `forward` is exactly prepare + forward_prepared; `_PreparedPass` holds the loop-invariant half (padding-safe `node_attrs`, `_StepStatics` with its node operands forced, the depth bound, the expanded `node_level`, the `_ReadOut`, the rank-0 level counter, the `SeedPad`; the expanded `update_mask` in the recurrent variant), `samples` must be a positive int, and an `inputs` batch that is not `pop_size * samples` raises `TensorNEATError`.
- `grad(...) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel: it traces its own graph and returns it, its body being `grad.build_grad(self, ...)`.
- `execute_mutation(state, key, genome, new_node_keys (P,), new_conn_keys (P,3))`, `execute_crossover(state, key, genome1, genome2)`, `execute_distance(state, genome1, genome2) -> (P,)` (pairwise over the pairs the algorithm forms), `prepare_distance(state, pop) -> DistanceDigest` (one digest per genome, **once per generation**) and `measure_distance(state, centre, digest) -> (P,)` (bit-identical to `execute_distance`, no re-sort; a batch-1 centre can take the dense key-table route, whose `[0, key_span)` precondition `distance/base.py::measure` validates on host data and which the live pipeline never reaches because `_kernels.py::single_payload` tiles the centre to `pop_size` rows).
- Host-only (NumPy in, Python out, never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`, `get_input_idx`, `get_output_idx`; the non-`sympy_func`/`visualize` ones live in `host.py::BaseGenomeHost`, `_split_payload` enforces batch-first for every compute entry point, and `network_dict`/`repr` take **one** individual through `host.py::_one_individual_payload` (the `(1, …)` batch `auto_run` returns or the bare checkpoint rows; slice recipe `GenomeTensors(*(a[i:i+1] for a in payload))`, there is no `payload.of(i)`).
- `hash` is **host-only numpy** (`(P,) np.uint32`), the xor-fold of `common.tools.hash_rows` over each gene family's key rows and its quantised attribute rows (`rint(attrs * HASH_QUANT_SCALE)`, NaN → `0`), folded across rows so padding hashes equal; it emits no evoxc op and no unsigned dtype, a `SymbolicTensor` payload is refused, and `HASH_QUANT_SCALE` (1e6) wraps past `|attr| ≈ 2147.48`, so it is a heuristic de-duplication key, never an identity test.
`GenomeTensors` is a namedtuple-like pytree of exactly the four payload arrays, always taken and returned by field.
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; the field table and the read-out authority live in `../tensorneat/CONTEXT.md` `## Kernel Contract`, and the field names are a binding contract.
This node reads `in_src`/`in_conn`/`in_valid (P, max_nodes, K)`, `node_level`/`node_exists`, `output_slot` and `edge_overflow`: `in_src` indexes `reshape(values, (P*max_nodes,))` and `in_conn` `reshape(conn_attrs, (P*max_conns,))`, `node_level` is the depth from an input node (`I_INF` on absent rows, zeros in the recurrent variant), and window slots are filled in increasing connection-row order, so a node's window ordering is canonical.
`BaseGenome.transform` passes the **derived** `acyclic` static (`self.network_type == "feedforward"`) as the 11th positional static of `common.tensorization.derive_schedule.fn` and `common.schedule_accelerator.kernel_mode(state)` as the trailing 12th, never a constructor kwarg.
With `acyclic=True` the cycle-detection relaxation, its in-graph test and the `evoxc.cond` fallback are not traced at all (280 traced `transform` ops); `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract, so a *cyclic* payload handed to a feedforward genome gets levels saturated at `max_nodes` and the loop clamps to `max_depth`.
## Formulation seams (host | accelerator)
Every seam is one static host branch on a trace-time `State` string, never a traced value, and every accelerator spelling is bit-identical to its host twin on the payloads compared, so both legs answer the same values generation for generation.
`Pipeline.setup` derives the three statics from the resolved device **kind**: a GPU-class kind registers `kernel_mode="accelerator"`, `distance_centre="tiled"`, `distance_formulation="index_free"`, every other kind and `None` register `"host"`/`"single"`/`"merge"`, and a state no `setup` produced resolves the way the kernels default (missing entry → the host formulation); the three are part of the cache signature, so a mode flip rebuilds exactly once, and on the numpy leg nothing moves because `"host"` selects the shipped spellings — byte-for-byte the pre-existing route.
`common/schedule_accelerator.py` is the one vocabulary reader for `kernel_mode` (`kernel_mode`/`resolve_mode`/`is_accelerator`, `KERNEL_MODES = ("host", "accelerator")`, missing entry → `"host"`, anything else `ConfigError`) and holds the two scatter-free schedule writes: `cumulative_indegree` for `edge_order`'s inverse-permutation `scatter` (75 000 serialised updates, 1.40 ms of a `xor_p500` generation) and `key_template` for `key_slot_table`'s dense `scatter` (25 000 updates, 0.55 ms), which resolves a duplicate cell to the same highest slot.
### Homologue alignment (`kernel_mode`)
`operations/alignment.py` is the host **packed-identity merge** shared with distance: one injective `int64` identity per key row (two 31-bit folds plus a 2-bit parent tag), one `argsort` of the concatenated parents, successor test, `_confirm_rows` for a third key column; crossover inverts the permutation with one encoded `int32` `sort` instead of two `scatter`s, and `homologous_pair` returns `(rows, present)` from that one merge.
`operations/alignment_accelerator.py::homologous_pair_accelerator` replaces the sort with one `(P, M, M)` broadcast `equal` plus `reduce_min` over a masked `arange` (leftmost matching parent-2 row) and reuses `_confirm_rows` — no sort, permutation or scatter, so it deletes the two bitonic alignment sorts (2.03 + 0.28 ms of device time) and fuses each family into one `linalg.generic` reduction, while numpy pays the table's element volume in full.
`find_homologous`/`homologous_pair(..., state=None)` delegate to `alignment._homologous`, which branches **once** on `alignment_accelerator.selected(state)`, so a graph holds one formulation; `crossover/base.py::__call__` and `crossover/default.py` forward `state`, while `DefaultDistance.gene_distance` passes none and always takes the host formulation (`./operations/CONTEXT.md` holds both legs' op/timing pairs).
### Cycle predicate (`kernel_mode`)
`operations/mutation/cycle.py::closes_cycle(state, node_keys, conn_keys, src_keys, dst_keys, key_span)` is the add-conn acyclicity veto: a cycle is closed exactly when `src` is reachable from `dst`, so it seeds a frontier at `dst` and grows it until it stops growing.
The host body resolves keys through a dense `key → row` table (one flat rank-1 `scatter`) and writes each hop into a flat `(P*(N+1),)` frontier with one `scatter`; `operations/mutation/cycle_accelerator.py` resolves keys with an equality template plus `reduce_min` and carries a scatter-free `(P, N+1) bool` reached set whose growth flag is packed as the last column.
Both bodies trace 81 ops and `cycle.py::_in_span` is the shared window law; `cycle_accelerator.kernel_mode`/`selected` read the same entry with the same default, and `closes_cycle` is one static branch on it, because the accelerator body is **0.173** ms per warmed call at `xor_p500` against the host body's **2.859** ms (0.282 against 1.425 at pop 1000) on a device while numpy prefers the host one (isolated predicate 20.84 against 4.86 ms).
A `RecurrentMutation` with `p_recur == 0` never traces the predicate; the feedforward path keeps it because an added connection there can close a cycle.
### Distance formulations (`distance_formulation`, `distance_centre`, grouped)
`operations/distance/` ships four `tobytes()`-identical spellings (on contract-conforming payloads, unique key rows), each gated by a static host read, with ledgers, per-route timings and the portability census in `./operations/distance/CONTEXT.md`:
- **merge** (`default.py`/`base.py` + `digest.py`) — the host default: sort-based successor test over the packed identities, 93 traced ops per `measure` call.
- **index_free** (`index_free.py`) — selected by `state.distance_formulation == "index_free"` (default `"merge"`, anything else `TensorNEATError`): the accelerator homologue resolution, no sort and no scatter, 84 traced ops, ≈18.8 M element touches per call against the merge route's ≈405 M on the device, at 2.1–2.6× the numpy wall clock.
- **dense** (`dense.py`) — the batch-1-centre key-table route, enabled by `DefaultDistance(dense_single_centre=True)`: 108 traced ops, 2.2–2.4× faster in wall than the tiled merge, and it cannot address a key outside `[0, key_span)`; `measure` skips it under `index_free`, because that route is scatter-based.
- **grouped** (`grouped.py`) — the k-centre form: `group_digest(digest, k)` tiles the digest and one `measure` call covers `k * P` centre rows with the plain merge body, whose 93 traced ops are independent of `k`.
`distance_centre` (`"tiled"`/`"single"`) names the centre batch width the speciation pass hands `measure`; only `measure` reads `distance_formulation`, while the pairwise route and digest construction stay on the host merge.
**Grouping is wired on the accelerator leg only**: `grouped.group_size` answers `k = 1` unless `is_accelerator(kernel_mode(state))`, so the numpy pipeline is handed its plain digest and its dispatch count, wall time and peak RSS do not move; on numpy the grouped form is a measured **loss** — −13 % dispatched ops (7 592 → 6 589) but peak RSS 233.8 → 253.2 MiB and wall time bimodal at 152–165 ms against 196–253 ms in 7 of 13 fresh processes (an allocator artefact: the 2× wider `(2P, 2*max_conns)` merge intermediates stop fitting in cache, so `argsort`/`gather`/`cast`/`reshape` cost more per pair than the dispatch they save), and `k = 4` reads +15 % wall / +30.5 % RSS — so it stays unwired there.
`grouped.group_size`/`for_state`/`centre_batch` are its host-side seam and `algorithm/neat/_distance.py::DistanceRows.matrix` its one caller (the accelerator leg only), gathering `k` centre rows per scan iteration and keeping the body result rank 1 because a rank-3 axis-0 `scatter` fails the StableHLO v1 export; on that leg it is a correctness- and portability-verified seam rather than a dispatch win yet (306 exports / 300 per generation against the ungrouped 282 / 276), because scan 2's per-slot `compute_row` calls stay ungrouped.
## Cost law (measured, numpy reference interpreter)
1. **An ordinary traced op pays its interpreter dispatch plus its own array traffic** — ≈19–20 µs per dispatched op on population-shaped kernels on this box, and the recorded per-generation pairs imply ≈15 µs/op at `xor_p500` (7 592 ops in 112.68 ms) and ≈8 µs/op at `cartpole_p100` (30 994 ops in 248.70 ms) because most of those ops are narrow — so op count is the budget for elementwise/gather/select/reshape work while element volume decides the wide passes and the reduces of rule 2.
2. **An innermost-axis reduction over a `(P, N, K)` tensor is 10–20× an ordinary op and does scale with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74 ms) against 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms against 1.06 ms for the slice-add fold.
Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked: more traced ops, far less time.
For the mutation slabs the opposite layout rule holds: in `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms; `gene/CONTEXT.md`).
## Forward algebra (feedforward)
`values (rows, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
That seed block is a `window.SeedPad` plan, built once per pass by `prepare_pass` as `window.seed_pad(kernel_mode(state), num_inputs, max_nodes, rows)` and spliced in by `window.seed_values(seed, pad)`, and the mode decides only the spelling: **host** keeps the NaN pad as a prepared `(rows, N-I)` block spliced with one `evoxc.concatenate` (one traced op, the numpy default), **accelerator** is a `SeedColumns` record — one `(N,) int32` column table repeating the last input column across the pad, one `evoxc.gather(seed, columns, axis=1)`, one baked `(1, N)` bool `keep` mask and a rank-0 `NaN` through `enp.where`, with no `(rows, N-I)` constant at all.
Both spellings are bit-identical (`-0.0` and NaN inputs included) and both return `seed` unchanged when `max_nodes == num_inputs`; the accelerator one exists because the concatenation of a dynamic block with a constant one lowers to a serialised `slow_memcpy` per policy query, while the gather+`where` fuses into one parallel elementwise dispatch (`## Compiled-device dispatch structure`).
Per pass: `_padding_safe_attrs` (`select` the attrs of **absent** rows to `0`, so option-index columns never reach the int cast as NaN, while a NaN *value* column of a live row still poisons), then `_hit_conn_attrs(transformed, conn_attrs, samples)` once (attributes are constant during a pass; its value-window gather index is **block-shaped** `(rows, N, K)` so `evoxc.gather` splices it directly), then one `evoxc.while_loop` over levels with `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)`.
Loop body (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level` (the `I_INF` padding already excludes absent rows, so no `node_exists` term): flatten + flat gather (**no fill** — a dead slot is clamped in range by `window._slot_index` and keeps that row's value), `live = present & (xv == xv)` (IEEE makes `x == x` False exactly on NaN), one `multiply` by the weight column, the per-option aggregation over `NodeOperands` masks + `combine` + activation (id `-1` = identity on output rows, because the final activation is `output_transform`), then `values = select(update_mask & any_slot(live), z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source, the legacy NaN poisoning reproduced exactly.
Cost is `O((depth+1) × max_nodes × K)` elementwise/reduce/gather work: real depth and real in-degree, never `max_depth` and never `max_nodes²`.
**The read-out is derived once per pass, never per level or per query**: `step._output_readout` builds `_ReadOut` (the flat gather index from `_slot_index`, its `present` mask, a rank-0 `NaN`, the `(rows, N)` geometry) and `step._output_row_mask` derives the `(P, N)` output mask from `output_slot` with one static `(1, N)` `arange` broadcast-compared per output column and folded with `logical_or`; a repeated query therefore pays only `reshape` + `gather` + `select`, and `_output_values` raises `TensorNEATError` when a prepared record's `(rows, N)` disagrees with `values`.
**Graph shape**: ≈67 entry ops + a **30-op level body** + a 1-op condition = **≈98 traced ops** per pass, independent of `P`, and the body runs `depth+1` times — measured **4 / 2 / 3** trips on the populations after 8 generations at P=100/500/1000, **3 / 3 / 3** at generation 5.
**Hoisting rule**: everything independent of the loop-carried `values`/`level` is derived **once per pass** (`_hit_conn_attrs`/`NodeOperands`/`prepare_pass` — the conn-attribute gather, the flat index's `minimum` clamp + `add` row offsets + `reshape`, the `present`/output-row masks, the option masks, the rank-0 `node_gene.prepare` builds, the `_ReadOut`, the level counter, the `SeedPad`), and **nothing wide may be computed per level unless a consumer reads it** — a dead-slot NaN fill after the value gather would be one `(P, N, K)` `select` per trip for values no consumer reads, while the narrow `logical_and` is bit-identical.
**Read set of one pass**: `in_conn`/`in_src`/`in_valid`, `output_slot`, `node_level`/`node_exists`, `node_keys` only in `_padding_safe_attrs`, `node_attrs`, `conn_attrs` once in the `_hit_conn_attrs` gather, and **`conn_keys` never** (an accepted-but-unused `forward` parameter); `src`, `dst`, `edge_valid`, `topo_key`, `input_slot` and `edge_overflow` are never read.
### Tiled batch (`P·S` rows): statics derived at `P`, expanded once
`step._sample_count(inputs, pop_size)` recovers the static `S = batch // P` inside `forward` and raises `TensorNEATError` when the batch is not a positive multiple of the population, so a tiled dataset is individual-major over the population axis.
`window.by_samples(x, samples, pop_size)` expands a `P`-row tensor to the tiled rows with `reshape` + `broadcast_to` + `reshape` (one copy per operand, flat order `p * S + j`) and is the identity for `S == 1` or a tensor without the population axis, so `_hit_conn_attrs`/`_StepStatics`/`prepare_pass` derive the conn gather, `present`, `output_rows`, `NodeOperands`, `node_level`, the read-out and the node masks at `P` rows and expand only the prepared leaves; only the flat value-window gather index is genuinely row-dependent (`evoxc.gather` is `np.take`), so `_slot_index(..., samples)` clamps at `P` rows, expands the clamped index and adds one baked `_row_offsets` constant.
`host_payload._prepared_query` passes the schedule and payload through unrepeated at `P` rows and only chunks (`EVAL_CHUNK_ROWS` = 12 500 tiled rows per forward), which is bit-identical because every forward op is row-local and the level loop's depth bound is a maximum a group can only under-shoot (`../host_payload.py` owns that budget and its measurements).
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python** (the level `while_loop` is feedforward-only), each tick re-injecting the inputs, computing every node from the previous tick's values (Jacobi), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than a `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a boolean *any*.
Its `evoxc.concatenate([inputs, values[:, I:]])` is not the seed shape above (both operands are dynamic, so it is a two-source copy rather than a dynamic-plus-constant `slow_memcpy`) and every alternative is worse: `gather` + `gather` + `select` is three dispatches for the same bytes, and a `scatter` into the input columns is one dispatch but one workgroup of one thread.
`sympy_func`/`visualize` are documented refusals (`TensorNEATError`: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, pointing at `network_dict()` / `DefaultGenome`).
## Gradient algebra
`grad` never differentiates the plain forward, so the forward's `while_loop` region and the schedule's `argsort`/`sort` never meet reverse-mode; three evoxc rules shape it: `evoxc.grad` requires a **single scalar output** (the loss is `sum(loss_fn(outputs))`, and per-individual gradients are unaffected because the population axis is independent), only float inputs are differentiable (an int32 *differentiated* argument is a hard `TransformError`), and `sort`/`argsort` have no AD rule, so the schedule must be derived outside the differentiated graph.
It differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`, because evoxc 0.1.0's `gather` VJP has put semantics (`## Known Issues`) and the window step's fan-out gathers under-accumulate: a per-individual `W (P, N, N)` weight matrix scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact, so these are the gradients of the plain forward (mean aggregation divides by `maximum(live_count, 1)`; values agree with `BaseGenome.forward` to 1e-6).
The plan (`W` cells, live matrix, level masks, read-out statics) is host-computed once per graph in `grad.dense_grad_plan`, and its read-out is a **static mask-and-reduce**, never a gather: per output column, one `(1, N)` `arange` compared with the baked `output_slot[:, j:j+1]`, non-output rows neutral-filled with `select` (never a `multiply`, so a `NaN` on a non-output row cannot poison the sum), the row axis summed, the columns concatenated and `NaN` written where `output_present` is false — bit-identical to `step.py::_output_values`; `dense_grad_plan` refuses a schedule whose `output_slot` names no output column (`ConfigError`).
## Operator algebra (ledgers and measurements in the children)
`execute_mutation` is a batched *plan → apply* kernel run **once per operation**: `_edit_context` builds the masks and flat index blocks for the payload that stage receives, the operation (`add_node`, `delete_node`, `add_conn`, `delete_conn`) resolves its candidates into a namedtuple plan (`mutation/plan.py`), and `plan.apply` writes it, so the four stages compose sequentially in legacy order and a later one sees the earlier one's writes; value mutation then runs as one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`), with draws kept per column because a `(…, A)`-wide draw costs ~9× a one-column draw.
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw, so one individual can receive up to four structural changes per call — at most one per operation; a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph, and refusals are bit-exact no-ops (duplicate connection, self-connection, a cycle, an add-node whose allocated key exists or whose destination is already at `max_in_degree`, capacity exhaustion).
The shipped pair `(0.1, 0.1, 0.4, 0.05)` raises P(any structural change) from 0.4816 to 0.5383 at an unchanged P(≥2) of ~0.104 against `DefaultMutation`'s 0.2/0.2; `./operations/mutation/CONTEXT.md` holds the gate histograms, the refusal split, the per-stage op ledger and every rejected alternative.
`BaseCrossover.__call__` takes parent 1's structure (`node_keys`/`conn_keys`) verbatim and recombines only float attributes, so argument order `(genome1, genome2)` = `(winner, loser)` is order-sensitive; inheritance is one `U[0,1)` block draw + `< 0.5` + `select`, the alignment primitive is `homologous_pair` via `align_gene_rows`, and unique first two key columns within a parent make homology a key-tuple question, never a row-position one (`./operations/crossover/CONTEXT.md`).
`execute_distance`, `prepare_distance` and `measure_distance` share the host merge: the digest concatenates the population's packed identities **first**, so a population gene's merged index *is* its digest row and the successor test needs no side tag; `distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants, each costs one op), and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push any destination past `K` is refused; soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings with zero violations.
- `max_depth` (`D`, default 16) is a **ceiling on the while-loop trip count**, not a cost multiplier: a node deeper than `D` is never visited and keeps its `NaN` value, and depth truncation is silent — it does **not** set `Transformed.overflow`, so the host must rebuild with a larger `D` on its own.
- `activate_time` (default 10) is the recurrent tick count, and `key_span` (`S`) is the silent-drop bound of the API section.
`Transformed.overflow` (the dropped-connection count) is the only host-visible diagnostic; nothing inside this node silently drops a connection or a node.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`), and no eager NumPy sits on the compute path — host helpers convert with `Tensor.numpy()` and never feed results back into a graph.
- Every kernel is already batched (no per-individual Python loop, no `vmap`/`vectorize`); the region ops are the forward's level `while_loop`, the cycle predicate's `while_loop` (both formulations) and the mutation add-conn attempt loop, none differentiable (`grad.py` owns that path).
- Shapes are static at trace time (`pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints), so a change forces a rebuild (the Pipeline caches per shape signature).
- Integer arithmetic: an `int32` tensor plus a Python literal promotes to `int64`, so index math stays in int32 tensors, and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`) — a full-size `I_INF` is a graph constant plus an op per use.
- Graph-op axes are non-negative static integers (`concatenate(..., axis=len(shape))`, never `axis=-1`), because the StableHLO exporter forwards the axis verbatim and rejects the negative form.
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors from evoxc propagate unchanged — never caught and re-wrapped.
- One window-reduce node step lives in `step.py::NodeStepMixin`, parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- File sizes stay under ~1000 lines and each file is one job: `base.py` (1005) is the node's only file above that guideline, `operations/distance/base.py` (1000) sits exactly on it, `grad.py` is 582, and the rest run down from `operations/distance/digest.py` (953) to `gene/node/origin.py` (61); the Routing Table states each file's responsibility.

## Compiled-device dispatch structure (level loop, ROCm/gfx942)
Counting recipe: build with `backend="iree"` and `device=None` (llvm-cpu load), take the target-independent text at `pipe._executable_for(state).backend_executable.artifact.payload["mlir_text"]`, run `iree-compile --iree-input-type=stablehlo --iree-hal-target-backends=rocm --iree-rocm-target=gfx942 --compile-to=executable-configurations` (pure CPU compile, iree-base-compiler 3.13), and count `stream.cmd.dispatch` per block of `util.func public @main`; the counts are device-independent for this target.
Per policy query at pop 100: the value-seed prelude is **3** dispatches under `kernel_mode="host"` and **2** under `"accelerator"`, and the level-loop body is **4** per trip host / **5** accelerator — identical for `cartpole_p100`, `pendulum_p100`, `mountaincar_p100` and `xor_p500` (which needs no loop and pays the query once per generation); the per-timestep totals those roll into belong to `../problem/rl/CONTEXT.md`.
The host body is one `(P, N)` `linalg.generic` (the `node_level == level` compare folded with the liveness mask), one wide `(P, N, K)` region (value gather, `multiply(weight)`, the K-fold, option-mask `select`, `combine`, activation, final `select(update, z, values)`), then two rank-0 `workgroup_size = [1,1,1]` dispatches holding `level + 1` and `level ≤ depth`; the `(P, N)` mask materialises because it is a multi-use operand, and `FormScalarDispatches` isolates each rank-0 compute behind a `compute_barrier.end`.
The `"accelerator"` formulation pays one dispatch more per trip: a second `(P, N)` `i32xf32xi32xf32 → f32` dispatch that the host formulation keeps inside the wide region — a fusion split produced by the schedule formulation's operand form in `../common/schedule_accelerator.py`, not by `_node_step`, which traces identically in both modes — so fusing it back is the one open per-trip cut on that leg.
The emitted floor is **4 host / 5 accelerator** per trip and every re-spelling tried costs the same or more: `stablehlo.reduce` for the K-sum or the `any_slot` fold gives 6 (both 11), a K-axis split by slicing gives 6, an inline liveness recompute is merged back by CSE, a per-row `remaining` probe or a `reduce_max` countdown gives 6, hoisting level 1 (or `k` levels) costs 4 for the straight-line level *and* raises the remaining body to 6 by breaking its two fusions, a carried `settled (P, N) i1` frontier is bit-identical but compiles to 8, and neither dispatch-creation fusion flag moves it.
Carrying the next condition as a third `while` value would give **3 host / 4 accelerator** per trip on a single-pass graph but cannot ship: a three-value carry in a level `while` nested inside a rollout `while` fails `iree-compile` with an upstream verifier error (`region branch point has 4 operands, but region successor needs 6 inputs`) while the emitted stablehlo is well formed.
Cost model on that leg (this tree): a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, one `while` iteration ≈50 µs, and one `Tensor.to(cpu)` ≈47–60 µs per leaf, so a launch-bound graph is costed by dispatch count and `while` trips, not by element volume.
The value seed is the one dispatch that leg saves per query: the host spelling (a prepared `(rows, N-I)` NaN block through one `evoxc.concatenate`) lowers to a `slow_memcpy` of the input block plus a constant-block fill and the loop-entry condition, while the accelerator `SeedColumns` spelling pays the gather and the masking `where` and no copy at all — one dispatch per policy query, i.e. 200 / 200 / 999 dispatches per generation for `CartPole` / `Pendulum` / `MountainCarContinuous`; the host spelling stays on the numpy leg because it is cheaper there (one traced op against two, and `evoxc.pad` would add an op below `EVAL_CHUNK_ROWS`).
## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select` over masks precomputed once per pass, so a non-total option (division by zero, `log/sqrt` of a possibly negative value) can poison gradients even where it is not selected.
- Random draws differ from the JAX build by construction, so parity with `benchmarks/legacy_jax` is asserted on kernels for given genomes (forward, grad, distance), not on RNG-dependent operator output.
- The forward's per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only (a pure "any", so identical); a future innermost-axis fold of a **float** reduce must check the non-numpy backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene: `weight_mutate_rate=0.8` / `weight_replace_rate=0.1` with no clip bounds, against the legacy `0.2` / `0.015` clipped to `±5` (0.8/0.1 are NEAT-python's own defaults) — 90.3 % of weight entries change per call against 20.7 % at a close `|Δweight|` distribution (conditional mean 0.232 vs 0.186), so the difference is frequency, not step size, and on evolved XOR3d populations the connection-gene attribute term of `execute_distance` reads ~0.05–0.06 here against ~0.01–0.02 in the legacy tree even though the distance kernel is numerically identical.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so a gather with duplicate indices silently keeps one contribution; no gradient may be taken through the window formulation until evoxc ships a scatter-add, and `grad.dense_grad_plan` therefore never gathers attributes — it reads the edge list (`conn_attrs[:, :, weight]`, `conn_exists`, `in_src`, `dst`) and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell, host-side NumPy over `Transformed` only.
`select`'s VJP does not reduce a broadcast operand — it hands a rank-0 constant the cotangent at the *output* shape, so one shared scalar used by two `select`s of different shapes raises `ShapeError: cannot broadcast incompatible dims …`.
`_node_step`, `_hit_conn_attrs`, `_output_readout` and `_gather_prepared` are the only plain-forward path and must keep their per-level op budget; `grad.py` serves `BaseGenome.grad` exclusively and refuses at graph-build time a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean`, a conn gene without a `weight` column, duplicate `(dst, src)` pairs and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal), and its finite-difference check (`max_nodes=8`, `max_conns=12`, `key_span=64`, central differences at `h=1e-2`) leaves a worst error of **4.96e-5** (`response`) and **3.77e-5** (conn weight), with padding rows, absent rows and non-weight columns at exactly `0`.
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236), which matches the pre-rewrite library's split semantics, so it is behaviour, not a defect.
**Origin families are not a learning defect** (`OriginNode`/`OriginConn` inherit everything but `crossover` and the conn gene's `historical_marker`), and a flat 0.25 MSE is a config/seed attractor of the search: the same task with `init_hidden_layers=(4,)` converges to 0.0031 MSE at generation 100.
**Compatibility distance matches the frozen implementation exactly**: `execute_distance` agrees with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` on all 4 950 pairs of converted XOR3d payloads, and mutation alone grows that distance identically in the two trees (median 0.90 → 1.12/1.10 after one call, → 1.82/1.75 after eight).
**`grad_from_payload`** (`BaseGenomeHost.grad_from_payload(state, payload, inputs, loss_fn, *, backend="numpy", device=None, compile_options=None)`) derives the schedule in a one-off executable (the `pipeline._schedule_of` recipe, duplicated rather than imported), calls `grad` for the graph, then lowers/compiles/loads/runs it and returns `(node_attr_grads, conn_attr_grads)` as numpy (52 live entries, max |analytic − central difference| 5.91e-5, all 36 NaN padding entries exactly `0`); its `loss_fn` operands must be Python scalars or `evoxc`/`enp` tensors (a numpy target array raises `TypeError`), the loss multiplies rather than `** 2`, and nothing in `src/` calls `grad` or `grad_from_payload`, so a `P > 1` population gradient is a documented user recipe, the graph is re-traced per call, and the loss *value* is never returned.
**Coverage gaps.** The gene value-mutation stage (`gene/blocks.py::mutate_attrs`/`init_attrs`/`crossover_attrs`) has no independent-oracle module, `operations/mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `operations/alignment.py::_successor_ranks`'s encoded-rank inversion only through `test_crossover.py`'s behavioural tests.
**Edge cases the suite does not exercise.** `P = 0` is refused upstream (`NEAT` validates `pop_size`), but the kernels answer it with `ZeroDivisionError` in `step._sample_count` and a zero-size `reduce_max` in `_depth_limit`; both `forward_prepared`s validate the batch *rows* but never `inputs.shape[1] == num_inputs`.
**Duplication worth folding.** `default.py::prepare_pass` and `recurrent.py::prepare_pass` repeat the eight-line `samples` validation verbatim, both `forward_prepared`s repeat the same `rows == pop_size * samples` check, and `window._i32`/`utils._i32`/`operations/mutation/arrays.py` carry three byte-identical copies.
**`import tensorneat` does pull `sympy`**: `host.py` claims the drawing/code-generation imports stay inside their bodies (and `visualize` does import `networkx`/`matplotlib` there), but `default.py` imports `sympy` at module scope for `sympy_func` and all three are hard runtime dependencies, so the release gate's import list (jax/torch/brax/gymnax/mujoco) is the only hygiene that holds.
## Outside this node (for the owners of `algorithm/`, `common/`, `problem/`)
1. **The reproduction bottleneck dominates newborn survival**: `algorithm/neat/_kernels.py::pair_parents` collapses every species to a single survivor below `2 / survival_threshold` members.
2. **`algorithm/neat/neat.py::_new_gene_keys` allocates `OriginConn`'s `historical_marker` per individual** although full-tuple homology is only meaningful for a population-wide marker (`65536*in + out`, 7.5–14.6 pp better at generation 100).
3. `../common/tensorization.py::node_levels` is 64 % of `transform` (three innermost-axis `reduce_max` per `while_loop` iteration), the largest remaining transform win; `../common/functions/`' reduces are innermost-axis over `(P, N, K)` and `act.py` emits one `select` per configured option per level, whose literals are the level body's remaining in-loop `constant` ops.
4. **Cheaper primitives `common/` should adopt**: `tools.py::fetch_random`/`fetch_first` pay two sentinel `select`s each (11/6 ops) against `operations/mutation/arrays.py`'s `(row, hit)` pair; `window.fill(shape, value)` is one element plus a broadcast (`gene/CONTEXT.md`); and `algorithm/hyperneat/hyperneat.py::forward_prepared` builds `enp.ones((batch, 1))` + `concatenate` per query for the substrate bias column, which belongs in `prepare_forward` as one prepared operand plus one `broadcast_to`.
5. **The environment step is the largest RL dispatch block** (`../problem/rl/`) and needs the shape this node's `SeedColumns` uses (a column `gather` plus a baked-mask `where` instead of a `concatenate` against a constant block), since those copies splice the observation/state block against constant or previously-materialised blocks.
6. **The accelerator leg's extra per-trip dispatch** belongs to the schedule formulation's operand form in `../common/schedule_accelerator.py`; fusing it back into the wide region is a 20 % per-trip cut on that leg.
## Test Strategy
`test/unit/genome/` runs on the numpy backend through `test/support/runner.py`, one module per contract (payload and `transform` validation, forward values and NaN poisoning, Jacobi ticks, finite differences and level order, mutation capacity and the four gates, key-tuple homology, distance bit-identity, host helpers, the prepared-pass read-out and the seed spellings); `test/parity/` compares the same kernels against the frozen `benchmarks/legacy_jax` implementation and needs the `bench` extra; `test/integration/` evolves XOR to target and pins determinism per seed.
**Bit-exactness gate** (the check any performance change here must pass): numpy backend, the ledger genome plus `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)` and `XOR()`, seed 42, 10 `Pipeline.step` calls, the four `previous_pop` leaves in field order then `fitnesses`, each leaf hashed as `dtype.str + repr(shape) + tobytes()`.
Two fold conventions circulate, both reproduce on this tree and are not interchangeable: a **running single sha256** over the concatenation of every generation's five leaves — `P=500` → `bca41966d9c949cbd2e58fd0a849edd3a51d86fa761219b8d3e9f417e3e30f6e`, `P=1000` → `3e7691819d46234822451a08103992027bef812152fd74aba3f56a9c64f88c76` — and **per-generation digests joined** — `P=500` → `d43edd0d3c19fe8f6bb4a1001246c40faaf82bf431e95e3a12f6c9b4a3e4c96e`, `P=1000` → `caba83eeebe50e86941fb7997c184e59f4702388d0826d77401a68dcb166bd45`; both pairs are identical under `kernel_mode="host"` and `"accelerator"`, so the two schedule formulations are bit-identical generation for generation on XOR, and both pin the shipped mutation law `(0.1, 0.1, 0.4, 0.05)` (at `DefaultMutation`'s 0.2/0.2 the same protocol gives `82f3cb…` / `763439…` under the running fold, so a mismatch with an unchanged gate law and trajectory shape is a kernel change).
Environment: Python 3.12.3, numpy 2.5.4, `evoxc` resolved by the lock from git tag `v0.1.1`; any library change moves the digests.
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over the module reached as `pipe._executable_for(state).backend_executable._module` is the *static* gate (no IREE needed) and catches every `DEFERRED_OPS`/dtype/axis/`scatter`-form violation at export time, while `pytest test/backends` (needs the `iree` extra) also catches `iree-compile` crashes a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value; a hand-built graph must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 RNG key as `evoxc.TensorSpec((), evoxc.int64)`), because a plain numpy array argument to `evoxc.build` is a static baked into the trace that exports a constant-only graph.
`RecurrentGenome` and the `grad` dense path do not share the level loop, so a change to `_node_step`/`window.py`/`prepare_pass` must re-check both.
No committed test selects an accelerator formulation: the four accelerator spellings and the `kernel_mode`/`distance_formulation` statics are gated by ad-hoc identity matrices and the generation-level digest gate only (`./test` is a sibling node), so a `test/backends` cell in accelerator mode is the missing regression guard.
