# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors, and evaluate a whole population of differently-shaped networks in one batch-first kernel.
This node owns exactly four things: (1) the **gene payload** (key columns in `int32`, attribute columns in `float32`, padded rows), (2) the **genetic operators** (mutation / crossover / distance) as batched kernels, (3) the **forward algebra** over a precomputed schedule plus the exact gradient path beside it (`grad.py`), and (4) host-only introspection, hashing and gradient orchestration (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`) — nothing here runs a host helper inside a trace.
It does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG` (`../common/functions/`); it consumes both.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers:
- `node_keys (P, max_nodes) int32` — node key per row; `I_INF` marks an absent row.
- `node_attrs (P, max_nodes, node_gene.attr_width) float32` — custom attrs; absent-node rows are NaN.
- `conn_keys (P, max_conns, conn_gene.key_width) int32` — `(in_key, out_key)` plus `historical_marker` when the conn gene declares it; `I_INF` marks an absent row.
- `conn_attrs (P, max_conns, conn_gene.attr_width) float32` — e.g. `weight`; absent rows are NaN.
`fixed_attrs` (key columns) stay integers and `custom_attrs` stay floats, because evoxc has **no bitcast** float↔int: the payload splits into a key array and an attr array, so genetic operators twiddle integer `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is supported (HyperNEAT/CPPN): every attr-table helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with a zero attribute distance.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys are rows `max_nodes-num_outputs..max_nodes-1`, rows never deleted or moved.
That layout is this genome's *template*, never the read-out rule: the schedule resolves the output keys to slots (`Transformed.output_slot`) and the forward reads those, so an inputs-outputs-hidden payload is read correctly while `get_input_idx()`/`get_output_idx()` describe only the template rows.
Hidden node keys are arbitrary and may move rows; compare keys (`node_keys`), never row positions, for graph identity.
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds the host-side configuration below (plus `output_transform`/`input_transform`/`init_hidden_layers`) and the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key into `[0, S)` and is part of the Pipeline's shape signature; a key outside it is *silently unmatched* by the schedule's dense key table, so the edge or node vanishes without setting `edge_overflow` (which only reports in-degree > `K`) — the node's one silent-failure mode.
`algorithm/neat/_keys.py::node_keys_for_split` keeps every structural key inside that window and `validate_key_space` rejects `key_span <= max_nodes` at `NEAT` construction; measured payloads at pop 100 XOR3d keep max key 134-149 over 150 generations at `S = 150`.
Raising `key_span` 150 → 2000 turns the 2-input `examples/func_fit/xor.py` from a flat `-0.25` into `-0.006` at generation 40 while XOR3d stays at `-0.25` even at `key_span=4000` (pop 100 and 500), so widening the table is not the XOR3d lever.
`DefaultGenome.__init__` takes no mutation rates: `(num_inputs, num_outputs, max_nodes=50, max_conns=100, node_gene/conn_gene/mutation/crossover/distance=None, output_transform/input_transform=None, init_hidden_layers=(), max_in_degree=None, max_depth=16, key_span=None)`, each `None` building a fresh default per instance.
The structural probabilities live on the `mutation` operator: `DefaultMutation`'s constructor defaults stay NEAT-python's `(0.2, 0.2, 0.1, 0.1)` for `(conn_add, conn_delete, node_add, node_delete)`, while the genomes build `DefaultMutation(conn_add=DEFAULT_GENOME_CONN_ADD, conn_delete=DEFAULT_GENOME_CONN_DELETE)` = `(0.1, 0.1, 0.4, 0.05)` when `mutation is None`.
The value rates live on each gene's `attr_specs` (`DefaultConn` weight 0.8 mutate / 0.15 power / 0.1 replace; `DefaultNode` bias and response 0.2/0.15/0.015 with ±5 bounds; option `replace_rate=0.1`); no enabled/disable knob exists.
`num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `max_in_degree`, `max_depth`, `key_span` are plain instance attributes (`base.py`), and `S` is a *schedule* bound only: homology folds keys in base `2**31` (`operations/alignment.py`, `distance/digest.py`), injective over `int32`.
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_values`: `_hit_conn_attrs` returns the loop-invariant `_StepStatics`, so a level pays only value-dependent ops.
- `initialize(state, key, pop_size) -> GenomeTensors` — `key` is a rank-0 `evoxc.random` key; randomness is drawn once per tensor with the batched output shape.
- `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed` — schedule derivation delegated to `../common/tensorization.py` in pure tensor ops; the keyword-only overrides pin which keys are inputs and outputs: `input_keys` must equal this genome's own `input_idx` (because `forward` seeds the inputs into rows `0..num_inputs-1`) and a host `output_keys` may be any `num_outputs`-long integer sequence.
The payload contract is checked first: `node_keys` must be `(P, max_nodes)`, `conn_keys` `(P, max_conns, key_width)`, their leading dims must agree, and in the four-array spelling each attribute array must lead with `node_keys.shape[0]`.
A violation raises `common.errors.TensorNEATError`: a rank-1 `node_keys` or rank-2 `conn_keys` is reported as a per-individual row needing a leading population axis (e.g. `node_keys[None, :]`), the message naming `Pipeline.auto_run`'s `(1, ...)` batch; the check reads `.shape` only (identical traced or host) and never compares a payload with `self.max_nodes`/`self.max_conns`.
`transform` passes the **derived** `acyclic` static (`self.network_type == "feedforward"`, the last of 11 positional statics to `derive_schedule.fn`), never a constructor kwarg, so the shape signature is unchanged; with `acyclic=True` the cycle-detection relaxation and its `evoxc.cond` fallback are not traced at all (280 traced ops, 10.54 ms at P=1000, bit-identical `Transformed`), while `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract.
- `forward(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, inputs) -> (P, num_outputs)` — trace-time kernel; `inputs` may carry any batch (`P·Q` substrate queries).
- `prepare_pass(state, transformed, node_*, conn_*, samples=1) -> Any` and `forward_prepared(state, transformed, prepared, inputs) -> (P, num_outputs)` — the same pass split into its loop-invariant operands (`_PreparedPass`) and its per-query half; `forward` is exactly prepare + forward_prepared, byte-identical; `prepare_pass` validates `samples` as a positive int and `forward_prepared` rejects an `inputs` batch that is not `pop_size * samples`.
- `grad(state, transformed, node_*, conn_*, inputs, loss_fn) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel: `grad.build_grad(self, ...)` traces its own graph and returns it for the Pipeline to cache/compile/run.
- `execute_mutation(state, key, genome, new_node_keys (P,), new_conn_keys (P,3)) -> GenomeTensors`; `execute_crossover(state, key, genome1, genome2) -> GenomeTensors`; `execute_distance(state, genome1, genome2) -> (P,)`.
- `prepare_distance(state, pop) -> DistanceDigest` — one digest per population genome, computed **once per generation**; `measure_distance(state, centre, digest) -> (P,)` measures one centre against the whole population with no re-sort and is **bit-identical** to `execute_distance` (verified on 5000 pairs and every `SpeciesState` leaf at pop 1000/500/100), so `algorithm/` prepares once and measures once per centre slot.
  A **batch-1** centre may take `DefaultDistance`'s dense key-table route, which addresses only keys inside `[0, key_span)`; `distance/base.py::measure` validates that on host data (the digest's `node_oor`/`conn_oor`, the centre's own out-of-range keys) and raises `TensorNEATError` (a traced digest is skipped: a value may not drive a traced raise).
- Host-only (NumPy in, Python out, never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`, `get_input_idx`, `get_output_idx`; all but `sympy_func`/`visualize` live in `host.py::BaseGenomeHost`.
- `network_dict` and `repr` take **one** individual in either documented spelling, normalised by `host.py::BaseGenomeHost._one_individual_payload`: the `(1, …)` batch (`Pipeline.auto_run`'s payload) or the bare checkpoint rows (`node_keys (N,)`, `node_attrs (N, A)`, `conn_keys (E, CK)`, `conn_attrs (E, CA)`); `None`, a non-four-field payload, a `P > 1` batch and fields that disagree about the spelling are refused (the `P > 1` message carries the slice recipe `GenomeTensors(*(a[i:i+1] for a in payload))`), so `Pipeline.show` and these two agree on what one genome is.
- `hash` is **host-only numpy** (`(P,) np.uint32`), the xor-fold of `common.tools.hash_rows` over each gene family's key rows and its quantised attribute rows (`rint(attrs * HASH_QUANT_SCALE)`, NaN → `0`); it emits no evoxc op and so no unsigned dtype, refuses a `SymbolicTensor` payload (in-graph gene identity is the key columns plus `evoxc.equal`), and is a heuristic de-duplication key only — it wraps past `|attr| ≈ 2147.48`.
`GenomeTensors` is a pytree of exactly the four payload arrays, always taken and returned by field; structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** as int32 tensors, not RNG draws, which `_check_key_shapes` enforces with a `TensorNEATError`.
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; field names are a binding contract with `common`:
- `in_src (P, max_nodes, K) int32` — flat index into `reshape(values, (P*max_nodes,))` of the source row of the k-th incoming edge of each node row; in range (0) where the slot is empty.
- `in_conn (P, max_nodes, K) int32` — flat index into `reshape(conn_attrs, (P*max_conns,))` of the same slot.
- `in_valid (P, max_nodes, K) bool` — True where that slot holds a real connection.
- `node_level (P, max_nodes) int32` — depth (longest path from an input node; inputs are 0), `I_INF` for absent rows; zeros in the recurrent variant.
- `node_exists (P, max_nodes) bool`, `overflow (P,) bool` — row validity and "some node's in-degree exceeded `K`"; `K`, `max_nodes` and `max_conns` are Python-int statics.
`K` is the genome's `max_in_degree`; slots are filled in increasing connection-row order so a node's window ordering is canonical and stable across runs.
## Cost law (measured, numpy reference backend)
Every number here is this node's own measurement on the numpy reference interpreter, one fixed payload per kernel, medians of repeated runs; two measured rules govern every kernel.
1. **An ordinary traced op pays ≈13 µs of interpreter dispatch plus its own array traffic** (`benchmarks/PERF_NUMPY.md` puts ~58–63 % of a generation in that fixed per-op cost), so op count is the budget for elementwise/gather/select/reshape work while element volume decides the wide passes and the innermost-axis reduces of rule 2.
2. **An innermost-axis reduction over a `(P, N, K)` tensor is 10–20× an ordinary op and does scale with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74 ms) versus 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms versus 1.06 ms for the slice-add fold (6.37 vs 3.49 ms at the tiled `4P=4000` batch).
Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked; the same law covers `common/functions/agg.py`'s `reduce_sum`/`count` and `gene/base.py::column` (a kept-axis slice + reshape is 2 view ops, a blocked pass pays 3× in element traffic for 8 ops — see `gene/CONTEXT.md`).
A third, layout rule governs the mutation slabs: for `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms), the opposite of the `(P, N, K)` window case.
## Forward algebra (feedforward)
`values (P, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
Step 0 (both genomes): `node_attrs = self._padding_safe_attrs(node_attrs, node_keys)` replaces the attrs of **absent** rows with `0` via `select`, so the option-index columns never reach the int cast as NaN; a NaN *value* column of a live row is untouched, so real corruption still poisons.
Step 1: one `evoxc.while_loop` over levels, `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)` — `node_level` is `I_INF` on absent/unreachable/cyclic rows so it is masked and clamped first.
Loop body (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level` (the schedule's `I_INF` padding already excludes absent rows, so no `node_exists` term):
1. `xv = _gather_prepared(values, flat_index)` — one flatten, one flat gather, **no fill**: a statically dead slot is clamped in range by `window._slot_index` and keeps that row's value.
2. `live = present & (xv == xv)` — two narrow ops; IEEE makes `x == x` False exactly on NaN, so this catches a live slot whose source row is still NaN while `present` excludes dead slots.
3. `msg = conn_gene.forward(statics.conn, xv)` — one `multiply` by the weight column; dead slots are neutral-filled by the aggregation before any reduce.
4. `z = node_gene.forward(...)`: per-option aggregation over masks precomputed in `NodeOperands`, `combine` (`bias + response * agg`), then the activation — id `-1` (identity) on output rows, because the final activation belongs to `output_transform`.
5. `update = update_mask & any_slot(live)`; `values = select(update, z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source: the legacy NaN poisoning, reproduced exactly.
The read-out is `self._output_values(...)`, so cost is `O((depth+1) × max_nodes × K)` in elementwise/reduce/gather ops only: work scales with real depth and real in-degree, never `max_depth` and never `max_nodes²`.
**Graph shape**: 67 entry ops + a **30-op level body** + a 1-op condition = **98 traced ops**, independent of `P`; the body runs `depth+1` times — measured **4 / 2 / 3** trips on the populations after 8 generations at P=100/500/1000 and **3 / 3 / 3** at generation 5.
**What is hoisted where** (the rule for future agents): everything independent of the loop-carried `values`/`level` — the conn-attribute gather, the value-window flat index (`minimum` clamp + `add` row offsets + `reshape`), the `present`/output-row masks and the rank-0 `node_gene.prepare` builds — is derived **once per pass** in `_hit_conn_attrs`/`NodeOperands`, so a level pays only `reshape` + `gather`, `equal` + `logical_and`, `multiply`, the aggregation (`select` fill + reduce + cascade), `combine` (2 ops), the activation (~5 ops + cascade), `any_slot` (8 ops), `logical_and` + `select` and `level + 1`.
**Nothing wide may be computed per level unless a consumer reads it**: a dead-slot NaN fill after the value gather would be one `(P, N, K)` `select` per trip for values no consumer reads, because the aggregation neutral-fills every slot of `live` before reducing.
**Read set of one feedforward pass**: `in_conn`/`in_src`/`in_valid`, `output_slot`, `node_level`/`node_exists` and the payload's `node_keys`/`node_attrs`/`conn_attrs` (**`conn_keys` never** — an accepted-but-unused parameter); `src`, `dst`, `edge_valid`, `topo_key`, `input_slot` and `edge_overflow` are never read (`grad.py::dense_grad_plan` reads `src`/`dst`/`edge_valid`), because the pass seeds the inputs into the invariant rows `0..I-1` and resolves the outputs through the schedule.
The recurrent forward drops `node_level` too and keys only on `node_exists` and `in_valid`.
`_hit_conn_attrs` sizes every static from the schedule's `P` rows and expands the prepared leaves once with `window.by_samples`; only the tiled value-window index is genuinely row-dependent (see `## Tiled batch`).
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python** (the level `while_loop` is feedforward-only).
Each tick re-injects the inputs into the input rows, computes every node from the previous tick's values (Jacobi/synchronous), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than a `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a boolean *any*.
`input_transform` is **not** applied by `RecurrentGenome` (legacy parity; HyperNEAT uses it as a CPPN).
`RecurrentGenome.sympy_func`/`visualize` are documented refusals: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, so both raise `TensorNEATError` pointing at `network_dict()` / `DefaultGenome`.
## Gradient algebra
`grad` never differentiates the plain forward, so the forward's `while_loop` region and the schedule's `argsort`/`sort` never meet reverse-mode. Three evoxc rules shape it:
- `evoxc.grad` requires a **single scalar output**, so the loss is scalarized as `sum(loss_fn(outputs))`; the population axis is independent, so per-individual gradients are unaffected.
- Only float inputs are differentiable: `node_attrs` and `conn_attrs` are the differentiated arguments; keys and the schedule are non-differentiated int inputs (an int32 *differentiated* argument is a hard `TransformError`).
- `sort`/`argsort` have no AD rule, so the schedule derivation must **not** be inside the differentiated graph — hence `grad` takes an already-derived `transformed` and returns its own graph.
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`), so padding rows gradient to exactly `0`.
`grad` therefore differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`: a per-individual `W (P, N, N)` scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and the live-slot gate `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact (mean is the same `dot` divided by `maximum(live_count, 1)`, values agree with `BaseGenome.forward` to 1e-6), so its gradients are the plain forward's.
`grad` returns an `evoxc.Graph` for the Pipeline to cache; the plan (`W` cells, live matrix, level masks, and the read-out statics `output_slot`/`output_present`/`output_rows`) is host-computed once per graph in `grad.dense_grad_plan`.
The dense read-out is a **static mask-and-reduce**, never a gather: per output column `j` it compares one `(1, N)` `arange` constant with the baked `output_slot[:, j:j+1]`, neutral-fills the non-output rows with `select` (never a `multiply`, so a `NaN` on a non-output row cannot poison the sum while a `NaN` output row still reads `NaN`), sums the row axis, concatenates the `O` columns and writes `NaN` where `output_present` is false — `2·O` elementwise/reduce ops plus one `concatenate` and one `select`, once per graph.
A gather read-out would need a `NaN`-cleaned copy of `values` (its VJP scatters into `multiply(x, 0)`, which a `NaN` row turns back into `NaN`) plus a second gather; the mask form reads exactly `values[p, output_slot[p, column]]`, bit-identical to the window read-out (`NaN` for an `I_INF` slot included) and row-layout-independent (checked on a tail-of-payload layout and a probe layout whose output slots are not the last rows).
Each `select` in the read-out gets its own rank-0 neutral; `dense_grad_plan` refuses a schedule whose `output_slot` names no output column (`ConfigError`).
## Mutation algebra
`execute_mutation` is a batched *plan → apply* kernel run **once per operation**: `_edit_context` builds the masks and flat index blocks for the payload that stage receives, the operation (`add_node`, `delete_node`, `add_conn`, `delete_conn`) resolves its candidates into a namedtuple plan (`mutation/plan.py`), and `plan.apply` writes it.
The four stages compose sequentially in legacy order add-node → delete-node → add-conn → delete-conn, each planning against the payload the previous stage produced, so a later operation sees the earlier one's writes (delete-conn may consume an edge a split created, delete-node may delete a node it just created, add-conn's duplicate/cycle/in-degree tests run on the post-stage graph).
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw (`drawn[i] < structural_probabilities[i]`), so one individual can receive up to four structural changes per call — at most one per operation — as the frozen legacy library chains them, and a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph.
Refusals are bit-exact no-ops: duplicate connection, self-connection, a cycle (one `while_loop` reachability relaxation over a flat `(P*(N+1),)` frontier with a dump column, `mutation/cycle.py`), an add-node whose allocated key already exists or whose split destination is already at `max_in_degree`, and capacity exhaustion.
`mutation/degree.py`'s `in_degree`/`max_in_degree`/`violation` (15/16/20 traced ops) is a standalone audit with no caller in `src/` and no test coverage; `execute_mutation` enforces `max_in_degree` inline.
`closes_cycle` is gated on the static configuration: a `RecurrentMutation` with `p_recur == 0` never traces it (324 traced ops at `p_recur=0` against 444 at `p_recur=0.1`, pop 1000), while the feedforward path always keeps it because an added connection there can close a cycle.
Its frontier is seeded by a one-hot `equal`/`logical_and`, **never** by a boolean `scatter`: a scatter whose result is the `while_loop` init SIGSEGVs `iree-compile` 3.11 llvm-cpu on the assembled generation graph while the same kernel compiles standalone, so only `pytest test/backends` catches a regression (`./operations/mutation/CONTEXT.md`).
Value mutation is one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`), with draws kept per column because a `(…, A)`-wide `evoxc.random` draw costs ~9× a one-column draw (this node's own measurement).
The four-stage composition executes 578 traced ops at pop 500 (`DefaultMutation`), 1.16× the shared-gate baseline's kernel time at pop 500 and 0.82× at pop 1000 while `Pipeline.step` (XOR pop 500 seed 42) stays flat within noise (median ratio 0.99); the per-stage op split is in `./operations/mutation/CONTEXT.md`.
Gate multiplicity over 20 000 individual-mutations at `(0.1, 0.1, 0.2, 0.2)` is 0/1/2/3/4 firing operations = 51.16/38.01/9.74/1.05/0.045 % (analytic P(any) 0.4816, P(>=2) 0.1072), and the shipped `(0.1, 0.1, 0.4, 0.05)` pair raises P(any) to 0.5383 at an unchanged P(>=2) of 0.1036, i.e. +5.7 pp of individuals changing structure per call; the realized acceptance rates, the refusal split and the joint-payload multiplicity are in `./operations/mutation/CONTEXT.md`.
Search-quality consequence of that balance (XOR3d, pop 100, seeds 0-19, 150 generations, numpy, fitness = −mse, target −0.05; **escape** = some generation best above −0.24, off the constant-0.5 attractor at −0.25): the shipped gates escape on **13/20** and reach the target on **11/20**, against **4/20** and **2/20** for the frozen `benchmarks/legacy_jax` tree on the same seeds and budget (Fisher two-sided p = 0.0095).
The gate histogram, the per-seed finals and every rejected alternative are in `algorithm/CONTEXT.md` `## Search Quality` and `./operations/mutation/CONTEXT.md`.
## Structural birth/death accounting (measured, `xor3d_p100`, pop 100, 150 generations, seeds 0-4 new / 0-2 frozen)
Realized per-operation acceptance on evolved payloads (isolated `execute_mutation`, all 150 generations) is add-node 0.99-1.00, delete-node 0.69-1.00, add-conn 0.39-0.65 and delete-conn 0.99-1.00, so the operators sit in **steady state and birth is not scarce** while nodes per individual rise and connections barely do.
`conn_delete` is therefore accepted about twice as often as `conn_add`, which sets the analytic steady state at ≈0 net nodes and −0.14…−0.22 net connections per individual per generation at equal gates, while the shipped `0.4`/`0.05` pair gives add 0.4 × ~0.50 ≈ +0.20 against delete 0.05 × ~1.00 = −0.05 — the balance that holds the wiring.
add-conn refusals are dominated by duplicate, self-connection and cycle, with `max_in_degree` (`K` = 4) refusing almost nothing and `max_depth` = 16 never binding (max `node_level` stays at 6-9), so neither static ceiling is the birth limit.
A forced split is fitness-median-neutral and lands on an input→output path, so the bottleneck is **inheritance, not birth**: only ~9-11 of 100 individuals per generation are structural copies of a previous individual, an injected newborn key survives to t=10 in ~1 % of cases, and 10-29 % of present hidden nodes have no path from an input while 10-21 % have no path to the output.
## Crossover algebra
`operations/alignment.py` is the one **packed-identity merge** shared with distance: each key row becomes an injective `int64` identity (two 31-bit folds plus a 2-bit parent tag so an *unstable* `argsort` is correct), the parents' identities are concatenated and sorted once, and a row is a homologue when its successor in sorted order carries its identity with the other parent's tag (a third `historical_marker` column is confirmed exactly).
Crossover inverts the permutation with one **encoded `int32` `sort`** (`alignment._successor_ranks`, 0.05 + 0.12 ms at pop 500) instead of two `scatter`s (0.42 ms), and `alignment.homologous_pair` returns `(rows, present)` from that one merge, so the "has a homologue" mask costs no extra `not_equal`/`select`.
The precondition is unique first two key columns within a parent (guaranteed by `initialize` and `execute_mutation`'s duplicate refusal): homology is by key tuple, never row position.
Argument order `(genome1, genome2)` = `(winner, loser)` is order-sensitive — parent 1 supplies the structure, only float attrs may come from parent 2 — and per-gene attribute inheritance is one `U[0,1)` block draw + `< 0.5` + `select` (`gene/blocks.py::crossover_attrs`), 13 traced ops; `./operations/crossover/CONTEXT.md` holds the ledger and the measured sort costs.
## Distance algebra
`execute_distance` (pairwise) and `prepare_distance`/`measure_distance` (digest) share that alignment: the digest concatenates the population's packed identities **first**, so a population gene's merged index *is* its digest row and the successor test needs no side tag; `stable=True` lets the reference interpreter's timsort detect the digest half's ascending run.
`distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants, each costs one op), the attribute term is a reduced sum over the aligned rows, and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
The routes, the op ledger and the rejected diet are in `./operations/distance/CONTEXT.md`; that file also holds the `measure` sort-bound split (two `argsort`s per family plus casts are 27–30 % of the call), the dense route's 106 ops costing 1.9–2.1× less than the merge's 93, and the grouped route's measured table.
`operations/distance/grouped.py::GroupedDigest` + `group_digest(digest, group)` measure `group * P` centre rows in ONE `measure` call against a `group`-times-tiled digest, with row `j * P + p` the distance of centre row `j * P + p` against population individual `p`.
The grouped result is bit-identical (`tobytes()`) to `group` separate `P`-row calls because every op of the merge, the aligned-attribute gather, `gene.distance` and the scalar tail is row-local; only the static scaffolding had to move from `P` to `group * P` rows.
`BaseGenome.prepare_distance`/`measure_distance` are unchanged: a `GroupedDigest` reaches `measure` through the existing `measure_distance(state, centre, grouped_digest)` wrapper, and a plain `P`-row or batch-1 centre behaves exactly as before.
`group_digest` is 24 traced ops at `group > 1` (one `concatenate` per tiled array plus the rebuilt tables) and 16 at `group == 1`; the grouped `measure` body is the plain merge body, so its traced op count is the plain one's and **independent of `group`** (94 on the pre-fold tree, 93 now).
The wall-clock caveat is honest: a single grouped `k=4` call measured 2.16 vs 4.00 ms against the four plain calls it replaces at pop 100 and 8.68 vs 9.52 ms at pop 500 (1.85× / 1.10×), but `prepare` + 5×grouped(4) versus `prepare` + 20×plain measured 22.62 vs 21.13 ms at pop 100 and 116.43 vs 105.63 ms at pop 500 (0.93× / 0.91×), because the interpreter retains every SSA result of a block and the merge is sort-bound with sort cost superlinear in row width; the grouped form buys op count and call boundaries rather than a numpy speed-up at these populations, and any speed claim must be measured at the live `algorithm/` call site.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push a destination past `K` is refused (`mutation/degree.py` is the same predicate standalone); soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings with zero violations.
- `max_depth` (`D`, default 16) is a **ceiling on the while-loop trip count**, not a cost multiplier: a node deeper than `D` is never visited and keeps its `NaN` value; truncation is silent (it does **not** set `Transformed.overflow`), so the host must rebuild with a larger `D`.
- `activate_time` (default 10) is the recurrent tick count.
`Transformed.overflow` is the only host-visible diagnostic; nothing inside this node silently drops a connection or a node.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`).
- No eager NumPy on the compute path; host helpers convert inputs with `Tensor.numpy()` and never feed results back into a graph.
- Every kernel is already batched: no per-individual Python loop and no `vmap`/`vectorize` over these kernels.
- The **only** region ops are the feedforward forward's level `while_loop` and the mutation cycle predicate's `while_loop`; neither may be differentiated (`grad.py` owns the differentiable path), and loop-invariant work belongs in `_StepStatics`/`_hit_conn_attrs`/`_edit_context`.
- Shapes are static at trace time: `pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints; a change forces a rebuild (the Pipeline caches per shape signature).
- Integer arithmetic: an `int32` tensor plus a Python literal promotes to `int64`, so index math stays in int32 tensors, and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`) — a full-size `I_INF` is a large graph constant plus an extra op per use.
- Graph-op axes are non-negative static integers (e.g. `concatenate(..., axis=len(shape))`, never `axis=-1`), because the StableHLO exporter forwards the axis verbatim as `dimension`.
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors from evoxc propagate unchanged.
- Shared machinery (one window-reduce node step) lives in `step.py::NodeStepMixin`, parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- File sizes stay under ~1000 lines, one job per file: `base.py` (1000), `step.py` (577), `window.py` (363), `host.py` (673), `grad.py` (581), `default.py` (711), `recurrent.py` (419), `gene/base.py` (861), `gene/blocks.py` (873), and in `operations/distance` `base.py` (993), `digest.py` (951), `layout.py` (725), `grouped.py` (373).

## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select` over masks precomputed once per pass (`option_masks`/`select_cascade`); a non-total option (division by zero, `log/sqrt` of a possibly negative value) can therefore poison gradients even where it is not selected.
- The forward's per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only (a pure "any"); a future innermost-axis fold of a **float** reduce must check the non-numpy backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene: `weight_mutate_rate=0.8` / `weight_replace_rate=0.1` and no clip bounds, against the legacy `0.2` / `0.015` clipped to `±5` (0.8/0.1 are NEAT-python's own defaults, so the legacy constants are the outlier).
  This node's own measurement (100 genomes × 3 conns, value mutation isolated): 90.3 % of weight entries change per call here against 20.7 % in `benchmarks/legacy_jax`, at a close `|Δweight|` distribution (conditional mean 0.232 vs 0.186, median 0.105 vs 0.130) — frequency, not step size; the consequence for speciation is a connection-gene attribute term of ~0.05–0.06 here against ~0.01–0.02 in the legacy tree on evolved XOR3d populations.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so any gather with duplicate indices silently keeps one contribution; no gradient may be taken through the window formulation until evoxc ships a scatter-add, and the defect is unfixed here on purpose.
`grad.dense_grad_plan` therefore never gathers attributes: it reads the edge list (`conn_attrs[:, :, weight]`, `conn_exists`, `in_src`, `dst`) and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell sliced off, host-side NumPy over `Transformed` only, one Python pass per compiled graph.
`select`'s VJP does not reduce a broadcast operand: it hands a rank-0 constant the cotangent at the *output* shape, so one shared scalar used by two `select`s of different shapes makes the reverse sweep raise `ShapeError: cannot broadcast incompatible dims …` — give each shape its own neutral constant.
`grad` refuses at graph-build time what the dense formulation cannot represent: a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean` (named by the `ConfigError`), a conn gene without a `weight` column, duplicate `(dst, src)` pairs, and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal).
Finite-difference check (2-input → 3-hidden → 1-output XOR genome, `max_nodes=8`, `max_conns=12`, `DefaultNode`/`DefaultConn`, `key_span=64`, central differences at `h=1e-2`): worst analytic-vs-FD error **4.96e-5** (node `response` column) and **3.77e-5** (conn weight); the int-encoded option columns and every padding row gradient to exactly `0`, no entry NaN/inf.
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236) — the pre-rewrite library's split semantics, so behaviour, not a defect.
**Origin families are not a learning defect**: `OriginNode`/`OriginConn` differ from the default families only in `crossover` (whole-gene copy) and, for the conn gene, the `historical_marker` column, and `OriginNode` + `DefaultConn` reproduces the default trajectory bit-for-bit at pop 100 (`gene/CONTEXT.md` has the per-family finals).
**Compatibility distance matches the frozen implementation exactly**: all 4 950 pairs at generations 1/3/10/30 (pop 100) agree with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` (float32 rounding), and mutation alone grows the distance identically in both trees (median 0.90 → 1.12/1.10 after one call, 1.82/1.75 after eight).
**Coverage gaps (current).** The gene value-mutation stage (`gene/blocks.py`) has no independent-oracle module, `operations/mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `operations/alignment.py::_successor_ranks` only through `test_crossover.py`; the oracle recipes are in `./operations/mutation/CONTEXT.md` `## Test Strategy`.
**The grouped distance route has no shipped unit test yet.** Its evidence is a `$TMPDIR` harness: a real evolved seed-42 XOR payload, 477 assertions, `DefaultDistance()` dense-on, `dense_single_centre=False`, `OriginConn` with three key columns and mixed markers, a zero-attribute connection gene, `group` in `{1, 2, 4, P}`, every group `np.array_equal` to the matching plain `P`-row call, plus `ConfigError` for a `P`/`3P`/`1`-row centre and for `group_digest(…, 0 / -1 / 2.0 / True)`; `grouped.py` has no `docs/source/` autodoc stub yet.
**`grad_from_payload` is the host entry point for gradient descent through evolved topologies.** `BaseGenomeHost.grad_from_payload(state, payload, inputs, loss_fn, *, backend="numpy", device=None, compile_options=None)` derives the schedule in a one-off executable (the `pipeline._schedule_of` recipe, duplicated), calls `grad`, then lowers/compiles/loads/runs the graph and returns `(node_attr_grads, conn_attr_grads)` as numpy.
It is verified end to end independently of `grad`'s own finite-difference test: `DefaultGenome(num_inputs=2, num_outputs=3, max_nodes=8, max_conns=12)`, `P = 2`, central differences through `forward` at `h = 1e-2` give **52 live entries, max |analytic − central difference| = 5.91e-5**, all 36 NaN padding entries gradient to exactly `0`, two calls are bit-identical, and a `P = 1` batch is a legitimate single-individual gradient.
Its `Notes:` record that `loss_fn`'s operands must be Python scalars or `evoxc`/`enp` tensors (a numpy target array raises `TypeError`) and that the loss multiplies rather than `** 2` (evoxc's `power` pullback emits an unconditional `log`); nothing in `src/` calls `grad` or `grad_from_payload`, so a `P > 1` population gradient is a documented user recipe, the graph is re-traced per call, and the loss *value* must be read from `forward` with the same `loss_fn`.
**Edge cases the suite does not exercise.** `P = 0` is refused upstream (`NEAT` validates `pop_size` through `positive_int`) but the kernels answer it with `ZeroDivisionError` in `_sample_count` (`step.py:223`) and a zero-size `reduce_max` in `_depth_limit`, not a `TensorNEATError`; `P = 1` is exercised end to end, and neither `forward_prepared` checks `inputs.shape[1] == num_inputs`, so a wrong input width surfaces as an evoxc shape error.
`visualize` imports `networkx`/`matplotlib` inside its body (both hard runtime dependencies), so a missing install is a raw `ImportError` rather than a configuration error; `sympy` is imported at module scope in `default.py:24`, so `import tensorneat` does pull the code-generation dependency contrary to `host.py`'s docstring.

## Tiled batch (`P·S` rows): statics are derived at `P` and expanded once
`NodeStepMixin._sample_count(inputs, pop_size)` recovers the static `S = batch // P` from the two shapes inside `forward` and raises `TensorNEATError` when the batch is not a positive multiple of the population, so a tiled dataset must be individual-major over the population axis.
`window.by_samples(x, samples, pop_size)` expands a `P`-row tensor to the tiled rows with `reshape` + `broadcast_to` + `reshape` (one copy per operand, flat order `p * S + j`), and is the identity for `S == 1` and for a tensor without the population axis.
`node_operands` refuses a second `forward` pass built from a different attribute tensor.
Only the flat value-window gather index is genuinely row-dependent: `evoxc.gather` is `np.take(arr, indices, axis)` with no per-leading-row semantics, so the index must carry the `(p·S+s)` row offset.
`window._slot_index(..., samples)` therefore clamps at the schedule's `P` rows, expands the clamped index, and adds one baked `_row_offsets(rows, row_len, rank)` constant (`p * row_len` at the tiled width) — one rows-scale `int32` `add` no expansion removes.
`_depth_limit` and the rest of the schedule geometry stay at `P` rows, and `default.py` expands `node_level` with `by_samples` for the per-level update mask.
`host_payload._prepared_query` passes the schedule and the payload through unrepeated at `P` rows and only chunks: at most `EVAL_CHUNK_ROWS` (12 500) tiled rows per forward — `EVAL_CHUNK_ROWS // S` individuals per chunk — slicing the `P`-row trees with `_slice_batch` and concatenating the group outputs in row order.
That chunking is bit-identical because every forward op is row-local and the one population-wide quantity, the level loop's depth bound, is a maximum a group can only under-shoot.
One static `samples` (= `S`) is recovered inside `forward` from the batch and the population, so no caller threads it and a direct caller (`Pipeline.show`, a unit test) stays at `samples=1`; the CPPN pass inside `HyperNEAT._query_substrate` keeps `samples=1` because `_expand_schedule`/`_expand_leaf` fuse the query axis into axis 0, while the *substrate* forward uses `samples` like any other.
`benchmarks/PERF_NUMPY.md` pass 2 records `custom_pagie_p500` (pop 500, `max_nodes=50`, `max_in_degree=4`, `CustomFuncFit(num_samples=500)`, so `P·S = 250 000` and `S = 500`) at the committed protocol (150 generations, 3 warmup, 3 repeats, numpy) as **833.81 ms per generation, 1361.4 MiB peak RSS and a 1.63 s build**, and its same-session A/B shows the chunk budget is load-bearing: the unbounded `P*S` block measured 3282 / 3315 ms per generation against 838 / 841 ms with `EVAL_CHUNK_ROWS`, at 4578 → 1315 MiB peak.
The XOR populations (`S = 4`) stay on the unchunked path, so the `P=500`/`P=1000` reference digests of `## Test Strategy` reproduce, and the `iree` smoke of `custom_pagie_p500` agrees with numpy to 2.38e-07 (float fusion).
Design (B), **not taken**: a real sample axis (`values (P,S,N)`, window `(P,S,N,K)`, statics `(P,1,…)`) would make the expansions 0-stride views, but it saves at most the `by_samples` copies, and `slice(..., strides=S)` is a new StableHLO/iree pattern.
Neither route touches the level loop's own element volume, `(depth + 1) × P·S × max_nodes × max_in_degree` elements per forward, so chunking and right-sizing `max_nodes`/`max_conns` remain the primary levers.

The check is bit-exact only when all 10 generations × 5 leaves at both populations reproduce those digests against another tree in two separate processes (reference source first on `sys.path`, `tensorneat.__file__` asserted under that root).
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over `pipe._executable_for(state).backend_executable._module` (`NumpyExecutable` keeps the lowered module as `_module`): the *static* gate, needs no IREE and catches every `DEFERRED_OPS` / dtype / axis / `scatter`-form violation at export time.
The real gate is `pytest test/backends` (needs `uv sync --extra iree`), which compiles and runs one XOR generation on IREE 3.11 llvm-cpu and also catches `iree-compile` crashes a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value.
This node's own measurement on a small payload (`pop_size=20`, `max_nodes=12`, `max_conns=24`, 2 inputs / 1 output): the generation graph exports at **732 200 bytes, 1 898 op uses over 13 distinct ops**, dominated by `broadcast_in_dim`, `compare`, `reduce` and `gather`; the mutation and crossover graphs pass the same gate with their own census (`./operations/mutation/CONTEXT.md`).
A hand-built graph for this check must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 RNG key as `evoxc.TensorSpec((), evoxc.int64)`): a plain numpy array argument to `evoxc.build` is a static baked into the trace, which exports a constant-only graph — `test/support/runner.py` builds the specs.
`RecurrentGenome` and the `grad` dense path are not covered by the level-loop machinery, so a change to `_node_step`/`window.py` must re-check both (they share the window step).
