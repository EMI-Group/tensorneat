# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors and evaluate a whole population of differently-shaped networks in one batch-first kernel.
Owns the **gene payload**, the **genetic operators** (mutation/crossover/distance) as batched kernels, the **forward algebra** over a precomputed schedule plus the exact gradient path (`grad.py`), and the host-only entry points (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`); no host helper runs inside a trace.
Does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG`; it consumes both.
Every kernel family here (value seed, read-out, schedule, alignment, cycle predicate, distance) ships a **host** spelling (numpy default) and an **accelerator** spelling (compiled-device leg), chosen by one static host branch on the trace-time `State`; both answer the same values.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers: `node_keys (P, max_nodes) int32` (`I_INF` on an absent row) with `node_attrs (P, max_nodes, node_gene.attr_width) float32`, and `conn_keys (P, max_conns, conn_gene.key_width) int32` (`(in_key, out_key)` plus `historical_marker` when the conn gene declares it, `I_INF` on an absent row) with `conn_attrs (P, max_conns, conn_gene.attr_width) float32` (e.g. `weight`); attr rows of absent genes are NaN.
evoxc has **no bitcast**, so a mixed-dtype row is impossible: the operators twiddle integer `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is supported (HyperNEAT/CPPN): every attr helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with an attribute distance of 0.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys `max_nodes-num_outputs..max_nodes-1`, never deleted or moved — a *template*, because the schedule resolves `output_slot` and the forward reads that, while `get_input_idx()`/`get_output_idx()` describe the template only.
Hidden keys are arbitrary and may move rows; compare keys, never row positions, and never mix sentinels: `I_INF` (`int32` max) = "no index", float NaN = "no value" and "unconnected node value".
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds the host-side configuration plus the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key and is part of the Pipeline's shape signature; a key outside `[0, S)` is *silently unmatched* by the schedule's key table — the node's one silent-failure mode, reachable only out of band because `algorithm/neat/_keys.py::node_keys_for_split` allocates inside the window and `validate_key_space` rejects `key_span <= max_nodes` at `NEAT` construction; `S` is a *schedule* bound only, so homology never derives a packing radix from it (`alignment.py`/`distance/digest.py` fold keys in base `2**31`).
`DefaultGenome` carries **no** mutation-rate knobs: `__init__` takes the five statics plus the gene/operator objects and `output_transform`/`input_transform`/`init_hidden_layers`/`max_in_degree`/`max_depth=16`/`key_span`, each `None` building a fresh default, so structural probabilities live on the operator (`DefaultMutation()` keeps NEAT-python's `(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)`, while `DefaultGenome`/`RecurrentGenome` build `(0.1, 0.1, 0.4, 0.05)` when `mutation is None`) and value rates live on each gene's `attr_specs` (`DefaultConn` 0.8 mutate / 0.15 power / 0.1 replace; `DefaultNode` 0.2 / 0.15 / 0.015 within ±5; option replace 0.1).
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_readout`/`_output_values`, composed into `BaseGenome` as a mixin before `BaseGenomeHost`; every kernel accepts both the `GenomeTensors` payload (a namedtuple-like pytree of exactly the four arrays) and the positional four-array spelling, and `node_exists`/`conn_exists`/`max_node_key`/`max_conn_marker` are the thin in-graph helpers `algorithm/` calls.
- `initialize(state, key, pop_size)` — one rank-0 `evoxc.random` key per tensor with the batched output shape; structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** as int32 tensors and `_check_key_shapes` refuses any other dtype.
- `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed` — derivation delegated to `../common/tensorization.py`; the keyword overrides pin which keys count as inputs/outputs (`input_keys` must equal this genome's own `input_idx`, a host `output_keys` may be any `num_outputs`-long sequence), and the payload contract (`node_keys (P, max_nodes)`, `conn_keys (P, max_conns, key_width)`, agreeing leading dims) is checked first on `.shape` only.
- `forward(...)`, `prepare_pass(..., samples=1)`, `forward_prepared(...)` — `forward` is exactly prepare + forward_prepared; `_PreparedPass` holds the loop-invariant half (padding-safe `node_attrs`, `_StepStatics` with node operands forced, the depth bound, the expanded `node_level`, the `_ReadOut`, the rank-0 level counter, the `SeedPad`; the expanded `update_mask` in the recurrent variant), `samples` must be a positive int, and an `inputs` batch that is not `pop_size * samples` raises `TensorNEATError`.
- `grad(...) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel; its body is `grad.build_grad(self, ...)`.
- `execute_mutation`, `execute_crossover`, `execute_distance(state, genome1, genome2) -> (P,)`, `prepare_distance(state, pop)` (one digest per genome, **once per generation**) and `measure_distance(state, centre, digest) -> (P,)` (bit-identical to `execute_distance`, no re-sort; its batch-1 dense key-table route needs `[0, key_span)` and the live pipeline never reaches it, because `_kernels.py::single_payload` tiles the centre to `pop_size` rows).
- Host-only (never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`, `get_input_idx`, `get_output_idx`; `_split_payload` enforces batch-first, and `network_dict`/`repr` take **one** individual through `host.py::_one_individual_payload` (the `(1, …)` batch `auto_run` returns or the bare checkpoint rows; slice recipe `GenomeTensors(*(a[i:i+1] for a in payload))`).
- `hash` is **host-only numpy** (`(P,) np.uint32`): the xor-fold of `common.tools.hash_rows` over each family's key rows and its quantised attribute rows (`rint(attrs * HASH_QUANT_SCALE)`, NaN → `0`), folded across rows so padding hashes equal; it emits no evoxc op, refuses a `SymbolicTensor` payload, and 1e6 wraps past `|attr| ≈ 2147.48`, so it is a de-duplication heuristic, never an identity test.
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; the field table and read-out authority live in `../tensorneat/CONTEXT.md` `## Kernel Contract` and the field names are binding.
Reads `in_src`/`in_conn`/`in_valid (P, max_nodes, K)`, `node_level`/`node_exists`, `output_slot`, `edge_overflow`: `in_src` indexes `reshape(values, (P*max_nodes,))`, `in_conn` `reshape(conn_attrs, (P*max_conns,))`, `node_level` is the depth from an input node (`I_INF` on absent rows, zeros in the recurrent variant), and window slots are filled in increasing connection-row order.
`BaseGenome.transform` passes the **derived** `acyclic` static (`self.network_type == "feedforward"`) as the 11th positional static of `derive_schedule.fn` and `common.schedule_accelerator.kernel_mode(state)` as the trailing 12th; with `acyclic=True` the cycle relaxation, its in-graph test and the `evoxc.cond` fallback are not traced at all (280 traced `transform` ops), while `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract, so a *cyclic* payload handed to a feedforward genome gets levels saturated at `max_nodes` and the loop clamps to `max_depth`.
## Formulation seams (host | accelerator)
Every seam is one static host branch on a trace-time `State` string, never a traced value, and every accelerator spelling is bit-identical to its host twin on the payloads compared.
`Pipeline.setup` derives the three statics from the resolved device **kind**: a GPU-class kind registers `kernel_mode="accelerator"`, `distance_centre="tiled"`, `distance_formulation="index_free"`; every other kind and `None` register `"host"`/`"single"`/`"merge"`, and a state no `setup` produced defaults to the host formulation.
They are part of the executable-cache signature, so a flip rebuilds exactly once, and on numpy nothing moves because `"host"` selects the shipped spellings byte-for-byte.
`common/schedule_accelerator.py` is the one vocabulary reader (`kernel_mode`/`resolve_mode`/`is_accelerator`, `KERNEL_MODES = ("host", "accelerator")`, missing → `"host"`, anything else `ConfigError`) and holds the two scatter-free schedule writes (`cumulative_indegree` for `edge_order`'s inverse-permutation `scatter`, `key_template` for `key_slot_table`'s dense `scatter`, both resolving a duplicate cell to the same highest slot).
**Level sweep** (`kernel_mode` + the tiling factor): `default.py::_level_loop` is the data-dependent `while_loop`, `default.py::_level_sweep` the statically unrolled `1 .. max_depth` sweep gated on `samples == 1` (see `## Forward algebra (feedforward)`); the recurrent genome has no level sweep at all, and `prepare_pass` skips `_depth_limit` under the sweep.
**Alignment** (`kernel_mode`): `operations/alignment.py` is the host **packed-identity merge** shared with distance (one injective `int64` identity per key row, one `argsort`, successor test, `_confirm_rows` for a third key column; crossover inverts the permutation with one encoded `int32` `sort` instead of two `scatter`s), while `operations/alignment_accelerator.py::homologous_pair_accelerator` swaps the sort for one `(P, M, M)` broadcast `equal` plus `reduce_min` over a masked `arange`; `find_homologous`/`homologous_pair(..., state=None)` delegate to `alignment._homologous`, which branches **once** on `alignment_accelerator.selected(state)` (`crossover/base.py::__call__` and `crossover/default.py` forward `state`; `DefaultDistance.gene_distance` passes none and stays on the host formulation).
**Cycle predicate** (`kernel_mode`): `operations/mutation/cycle.py::closes_cycle` vetoes an add-conn that closes a cycle — closed exactly when `src` is reachable from `dst`, so it seeds a frontier at `dst`; the host body resolves keys through a dense `key → row` table (one rank-1 `scatter`), writes each hop into a flat `(P*(N+1),)` frontier and stops when the frontier stops growing (81 traced ops), `operations/mutation/cycle_accelerator.py` swaps the table for an equality template plus `reduce_min` and carries one scatter-free `(P, N+1) bool` tensor — reached set plus growth flag — whose `cond` is that flag, so it hops until the closure stops growing (82 traced ops), and `cycle.py::_in_span` is the shared window law; on a device the accelerator body's **key resolution** measured **0.173** ms per warmed call at `xor_p500` against the host body's **2.859** ms, while numpy prefers the host one (20.84 against 4.86 ms), and a `RecurrentMutation` with `p_recur == 0` never traces it.
A statically counted `node_count`-hop variant of the same body (same boolean, no per-hop readback) is **rejected on measurement**: one generation costs 21.28 against 13.27 ms on `xor_p500`, 23.56 against 16.19 on `xor_p1000`, 24.16 against 16.13 on `custom_pagie_p500` and 69.01 against 60.16 on `cartpole_p100` (same session, seed 42, bit-identical fitness and build time), because these populations stabilize in two or three hops while the counted loop pays its `O(P·E·N)` destination one-hot for all `N = 50` — so the data-dependent exit stays the device spelling too.
**`operations/distance/`** ships four `tobytes()`-identical spellings on contract-conforming payloads, each gated by a static host read (ledgers in `./operations/distance/CONTEXT.md`): **merge** (the host default: sort-based successor test over packed identities, 93 traced ops per `measure`); **index_free** (`state.distance_formulation == "index_free"`, default `"merge"`, anything else `TensorNEATError` — no sort, no scatter, 84 traced ops, ≈18.8 M element touches per call against ≈405 M on the device, at 2.1–2.6× the numpy wall clock); **dense** (the batch-1-centre key table via `DefaultDistance(dense_single_centre=True)`, 108 traced ops, 2.2–2.4× faster in wall than the tiled merge, skipped under `index_free` because it is scatter-based); **grouped**.
`distance_centre` (`"tiled"`/`"single"`) names the centre batch width the speciation pass hands `measure`; only `measure` reads `distance_formulation`, while the pairwise route and digest construction stay on the host merge.
**Grouping is wired on the accelerator leg only**: `grouped.group_size` answers `k = 1` unless `is_accelerator(kernel_mode(state))`, so the numpy pipeline keeps its plain digest and its dispatch count, wall time and peak RSS do not move; on numpy the grouped form is a measured **loss** — −13 % dispatched ops (7 592 → 6 589) but peak RSS 233.8 → 253.2 MiB and wall time bimodal at 152–165 ms against 196–253 ms in 7 of 13 fresh processes (the 2× wider `(2P, 2*max_conns)` merge intermediates stop fitting in cache, so `argsort`/`gather`/`cast`/`reshape` cost more per pair than the dispatch they save), `k = 4` reading +15 % wall / +30.5 % RSS — so it stays unwired there.
`group_digest(digest, k)` tiles the digest so one `measure` call covers `k * P` centre rows with the plain merge body, whose 93 traced ops are independent of `k`; `grouped.group_size`/`for_state`/`centre_batch` are its host seam and `algorithm/neat/_distance.py::DistanceRows.matrix` its one caller, keeping the body result rank 1 because a rank-3 axis-0 `scatter` fails the StableHLO v1 export.
## Cost law (measured, numpy reference interpreter)
1. **An ordinary traced op pays its interpreter dispatch plus its own array traffic** — ≈19–20 µs per dispatched op on population-shaped kernels on this box, with the recorded pairs implying ≈15 µs/op at `xor_p500` (7 592 ops in 112.68 ms) and ≈8 µs/op at `cartpole_p100` (30 994 ops in 248.70 ms) because most of those ops are narrow — so op count is the budget for elementwise/gather/select/reshape work while element volume decides the wide passes and rule 2's reduces.
2. **An innermost-axis reduction over `(P, N, K)` is 10–20× an ordinary op and scales with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74) against 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms against 1.06 ms for the slice-add fold. Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked.
For the mutation slabs the opposite layout rule holds: in `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms; `gene/CONTEXT.md`).
## Forward algebra (feedforward)
`values (rows, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
**Seed splice.** That block is a `window.SeedPad` plan built once per pass by `prepare_pass` as `window.seed_pad(kernel_mode(state), num_inputs, max_nodes, rows)` and spliced by `window.seed_values(seed, pad)`; the mode decides only the spelling: **host** (numpy default) keeps the NaN pad as a prepared `(rows, N-I)` block spliced with one `evoxc.concatenate` (one traced op), while **accelerator** is a `SeedColumns` record — one `(N,) int32` column table repeating the last input column across the pad, one `evoxc.gather(seed, columns, axis=1)`, one baked `(1, N)` bool `keep` mask and a rank-0 `NaN` through `enp.where`, with no `(rows, N-I)` constant at all.
Both spellings are bit-identical (`-0.0` and NaN inputs included) and both return `seed` unchanged when `max_nodes == num_inputs`; the accelerator one exists because a dynamic block concatenated with a constant one lowers to a serialised `slow_memcpy` per policy query, while the gather+`where` fuses into one parallel elementwise dispatch.
**Per pass**: `_padding_safe_attrs` (`select` the attrs of **absent** rows to `0`, so option-index columns never reach the int cast as NaN while a NaN *value* column of a live row still poisons), then `_hit_conn_attrs(transformed, conn_attrs, samples)` once (its value-window gather index is **block-shaped** `(rows, N, K)` so `evoxc.gather` splices it directly), then one of the two level spellings of `_PreparedPass.sweep`.
**Level sweep** (`kernel_mode` **and** the tiling factor): `_level_loop` (host) is one `evoxc.while_loop` over `level = 1 .. limit` with `limit` = `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)`; `_level_sweep` (accelerator) is a Python loop unrolling the same `_node_step` over `level = 1 .. max_depth` with `update_mask = node_level == level`, and derives neither the bound nor the loop counter.
The gate is `sweep = is_accelerator(kernel_mode(state)) and samples == 1`: a `while` predicate over a device tensor costs a fresh pinned 1-byte host buffer, a D2H copy and event churn per trip on a compiled device (~157–263 µs against ~57 µs for a statically counted trip), so a **non-tiled** pass — a rollout, queried `max_step` times per generation — is where the unrolling pays; a **tiled** pass (`samples > 1`, a dataset spread over the population axis) is evaluated once per generation, so its readback is amortised, while an unrolled sweep would multiply its `P * samples` rows by `max_depth`.
Both spellings are bit-identical: level `0` (inputs) is never updated, absent/unreachable/cyclic rows carry `I_INF` in `node_level` and match no trip, a batch whose real depth is `d < max_depth` sees an all-`False` mask above `d` so `select(update, z, values)` returns `values` (NaN poisoning included), and a row deeper than `max_depth` is never visited either way.
**Loop body** (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level`: flatten + flat gather (**no fill** — a dead slot is clamped in range by `window._slot_index`), `live = present & (xv == xv)`, one `multiply` by the weight column, the per-option aggregation over `NodeOperands` masks + `combine` + activation (id `-1` = identity on output rows, because the final activation is `output_transform`), then `values = select(update_mask & any_slot(live), z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source.
Cost is `O((depth+1) × max_nodes × K)` elementwise/reduce/gather work on the host leg — real depth and real in-degree, never `max_depth` and never `max_nodes²` — and `O(max_depth × max_nodes × K)` on the accelerator sweep, where the unrolled ceiling is what removes the readbacks.
**The read-out is derived once per prepared pass, never per level or per query**: `step._output_readout(transformed, samples)` builds `_ReadOut` (the flat gather index from `_slot_index`, its `present` mask, one rank-0 `NaN`, the `(rows, N)` geometry) and `step._output_row_mask` derives the `(P, N)` output mask from `output_slot` with one static `(1, N)` `arange` broadcast-compared per output column and folded with `logical_or`; a query then pays only `reshape` + `gather` + `select`, so a pass costs one gather plus `O` mask comparisons and nothing per level, and `_output_values` raises `TensorNEATError` when a prepared record's geometry disagrees with `values`.
**Graph shape**: the host spelling is ≈67 entry ops + a **30-op level body** + a 1-op condition = **≈98 traced ops** per pass, independent of `P`, and the body runs `depth+1` times (measured **4 / 2 / 3** trips at P=100/500/1000 after 8 generations, **3 / 3 / 3** at generation 5); the accelerator sweep instead traces `max_depth` copies of the body and no region op at all (669 traced ops against 110 at `max_nodes=8`/`max_depth=16`), which is the build-side cost of the readback it removes.
**Hoisting rule**: everything independent of the loop-carried `values`/`level` is derived **once per pass**, and **nothing wide may be computed per level unless a consumer reads it** — a dead-slot NaN fill would be one `(P, N, K)` `select` per trip for values no consumer reads, while the narrow `logical_and` is bit-identical.
**Read set of one pass**: `in_conn`/`in_src`/`in_valid`, `output_slot`, `node_level`/`node_exists`, `node_keys` only in `_padding_safe_attrs`, `node_attrs`, `conn_attrs` once in the `_hit_conn_attrs` gather, and **`conn_keys` never**; `src`, `dst`, `edge_valid`, `topo_key`, `input_slot` and `edge_overflow` are never read.
### Tiled batch (`P·S` rows): statics derived at `P`, expanded once
`step._sample_count(inputs, pop_size)` recovers the static `S = batch // P` inside `forward` and raises `TensorNEATError` when the batch is not a positive multiple of the population, so a tiled dataset is individual-major over the population axis.
`window.by_samples(x, samples, pop_size)` expands a sample-invariant `P`-row tensor to the tiled rows with `reshape` + `broadcast_to` + `reshape` (one copy per operand, flat order `p * S + j`) and is the identity for `S == 1` or a tensor without the population axis, so `prepare_pass`/`_hit_conn_attrs`/`_StepStatics` derive the conn gather, `present`, `output_rows`, `NodeOperands`, `node_level`, the read-out and the node masks at `P` rows and expand only the prepared leaves.
Only the flat value-window gather index is genuinely row-dependent (`evoxc.gather` is `np.take`), so `_slot_index(..., samples)` clamps at `P` rows, expands the clamped index and adds one baked `_row_offsets` constant; `host_payload._prepared_query` passes schedule and payload through unrepeated at `P` rows and only chunks (`EVAL_CHUNK_ROWS` = 12 500 tiled rows per forward), bit-identical because every forward op is row-local and the depth bound is a maximum a group can only under-shoot.
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python**, each tick re-injecting the inputs, computing every node from the previous tick's values (Jacobi), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a boolean *any*.
Its `evoxc.concatenate([inputs, values[:, I:]])` is not the seed shape above (both operands are dynamic, so it is a two-source copy) and every alternative is worse: `gather` + `gather` + `select` is three dispatches for the same bytes, a `scatter` into the input columns one dispatch but one workgroup of one thread.
`sympy_func`/`visualize` are documented refusals (`TensorNEATError`: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, pointing at `network_dict()` / `DefaultGenome`).
## Gradient algebra
`grad` never differentiates the plain forward, so the level `while_loop` and the schedule's `argsort`/`sort` never meet reverse-mode; three evoxc rules shape it: `evoxc.grad` needs a **single scalar output** (the loss is `sum(loss_fn(outputs))`, and per-individual gradients are unaffected because the population axis is independent), only float inputs are differentiable (an int32 *differentiated* argument is a hard `TransformError`), and `sort`/`argsort` have no AD rule, so the schedule is derived outside the differentiated graph.
It differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`, because evoxc 0.1.0's `gather` VJP has put semantics: a per-individual `W (P, N, N)` weight matrix scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact, so these are the gradients of the plain forward (mean aggregation divides by `maximum(live_count, 1)`; values agree with `BaseGenome.forward` to 1e-6).
The plan (`W` cells, live matrix, level masks, read-out statics) is host-computed once per graph in `grad.dense_grad_plan`, and its read-out is a **static mask-and-reduce**, never a gather: per output column, one `(1, N)` `arange` compared with the baked `output_slot[:, j:j+1]`, non-output rows neutral-filled with `select` (never a `multiply`, so a `NaN` on a non-output row cannot poison the sum), the row axis summed, the columns concatenated and `NaN` written where `output_present` is false — bit-identical to `step.py::_output_values`; `dense_grad_plan` refuses a schedule whose `output_slot` names no output column (`ConfigError`).
## Operator algebra (ledgers and measurements in the children)
`execute_mutation` is a batched *plan → apply* kernel run **once per operation** (`_edit_context` builds the masks and flat index blocks, the operation resolves candidates into a plan in `mutation/plan.py`, `plan.apply` writes it), so the four stages compose sequentially in legacy order and a later one sees the earlier one's writes; value mutation is one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`) with draws kept per column.
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw (up to four structural changes per call, at most one per operation); a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph, and refusals are bit-exact no-ops (duplicate connection, self-connection, a cycle, an add-node whose key exists or whose destination is already at `max_in_degree`, capacity exhaustion).
The shipped pair `(0.1, 0.1, 0.4, 0.05)` raises P(any structural change) from 0.4816 to 0.5383 at an unchanged P(≥2) of ~0.104 against `DefaultMutation`'s 0.2/0.2; `./operations/mutation/CONTEXT.md` holds the histograms, refusal split and op ledger.
`BaseCrossover.__call__` takes parent 1's structure verbatim and recombines only float attributes, so `(genome1, genome2)` = `(winner, loser)` is order-sensitive, and unique first two key columns within a parent make homology a key-tuple question, never row-position (`./operations/crossover/CONTEXT.md`).
`execute_distance`, `prepare_distance` and `measure_distance` share the host merge: the digest concatenates the population's packed identities **first**, so a gene's merged index *is* its digest row and the successor test needs no side tag; `distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants), and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push any destination past `K` is refused; soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings with zero violations.
- `max_depth` (`D`, default 16) is a **ceiling on the level trips** — a deeper node is never visited and keeps its `NaN` value, and depth truncation does **not** set `Transformed.overflow`, so the host must rebuild with a larger `D`; on the accelerator sweep it is also a **cost multiplier** (`max_depth × body_ops` per query, measured 2.56 ms/generation per unrolled level at `cartpole_p100`), while on the host leg it is not.
- `activate_time` (default 10) is the recurrent tick count; `Transformed.overflow` (the dropped-connection count) is the only host-visible diagnostic, and `key_span` is the silent-drop bound of the API section.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`), and no eager NumPy sits on the compute path — host helpers convert with `Tensor.numpy()` and never feed results back.
- Every kernel is already batched (no per-individual loop, no `vmap`/`vectorize`); the region ops are the host leg's level `while_loop` (its accelerator spelling emits none), the cycle predicate's `while_loop` (a frontier-growth condition on the host, a static `node_count` trip count on the accelerator leg) and the mutation add-conn attempt loop, none differentiable.
- Shapes are static at trace time (`pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints), so a change forces a rebuild (the Pipeline caches per shape signature).
- An `int32` tensor plus a Python literal promotes to `int64`, so index math stays in int32 tensors and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`); graph-op axes are non-negative static integers (`axis=len(shape)`, never `axis=-1`).
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors propagate unchanged.
- One window-reduce node step lives in `step.py::NodeStepMixin`, parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- Files stay under ~1000 lines and each file is one job: `base.py` (1005) is the node's only file above that guideline, `operations/distance/base.py` (1000) sits exactly on it, `grad.py` is 582, and the rest run down from `operations/distance/digest.py` (953) to `gene/node/origin.py` (61).

## Compiled-device dispatch structure (level loop, ROCm/gfx942)
Counting recipe: build with `backend="iree"` and `device=None`, take `pipe._executable_for(state).backend_executable.artifact.payload["mlir_text"]`, run `iree-compile --iree-input-type=stablehlo --iree-hal-target-backends=rocm --iree-rocm-target=gfx942 --compile-to=executable-configurations` (pure CPU compile), and count `stream.cmd.dispatch` per block of `util.func public @main`.
Per policy query at pop 100: the value-seed prelude is **3** dispatches under `kernel_mode="host"` and **2** under `"accelerator"`; the level-loop body is **4** per trip host / **5** accelerator, identical for `cartpole_p100`, `pendulum_p100`, `mountaincar_p100` and `xor_p500` (which needs no loop and pays the query once per generation).
The host body is one `(P, N)` `linalg.generic` (the `node_level == level` compare folded with the liveness mask), one wide `(P, N, K)` region (value gather, `multiply(weight)`, K-fold, option-mask `select`, `combine`, activation, final `select`), then two rank-0 `workgroup_size = [1,1,1]` dispatches holding `level + 1` and `level ≤ depth`; the `"accelerator"` formulation pays one dispatch more per trip (a second `(P, N)` float dispatch the host formulation keeps inside the wide region), a fusion split produced by the schedule formulation's operands in `../common/schedule_accelerator.py`, so fusing it back is the one open per-trip cut on that leg.
The floor is **4 host / 5 accelerator** per trip and every re-spelling costs the same or more (`stablehlo.reduce` for the K-sum or the `any_slot` fold 6, a K-axis split by slicing 6, a carried `settled` frontier 8, hoisting levels 6, a third `while` carry 3/4 but it fails `iree-compile` upstream inside a rollout `while`).
Under `_level_sweep` the two rank-0 counter dispatches per trip are gone (the level is a Python int), so an unrolled level is the `(P, N)` compare-plus-mask and the wide `(P, N, K)` region; the measured marginal 12.8 µs per level per query implies that pair still splits into ≈5 dispatches once ~60 fused ops per iteration are exceeded, which is the per-level cut left on that leg.
An unrolled level body counts **4 dispatches** at `cartpole_p100` (`max_depth` 4 / 8 / 16 → TOTAL 416 / 432 / 464, all counted with `iree-compile --compile-to=executable-configurations` for gfx942, CPU-only): the value-window `gather`, the wide `live = present & (xv == xv)`, the wide message-plus-neutral-fill region, and one level-specific narrow group carrying the fold, `combine`, the activation and the `update` select.
Removing the wide `live` mask's **second** consumer (`any_slot(live)` → `any_slot(present)`) measures **3** per level, but it is not semantics-preserving: a node whose only present slots point at `NaN` sources would be updated to its bias instead of keeping `NaN`.
A prepared `(P, N, N)` bool incidence replacing that fold — `any_live = reduce_max(incoming & nan_mask, axes=2)`, one `(P, N, K, 1)` `in_src == arange(N)` ANDed with `in_valid` and reduced over `K`, derived once per pass in `_hit_conn_attrs` — measures **7** per level (TOTAL 432 / 460 at `max_depth` 4 / 8) while *lowering* one level's traced ops from 38 to 34, because the `(P, N, N)` compare-AND and its source-axis reduce are 12× the window's element count and do not fuse into the narrow group.
Every exact spelling of "any live incoming slot" therefore carries either that `N²` tensor or a second wide `(P, N, K)` derivation, so **4 per level is the floor for this structure** and the remaining cut has to come from the gather or the message region, not from the liveness predicate.
Replacing the static slice fold with a real reduction (`reduce_sum` for the K-sum, `reduce_max` for `any_slot`) — the one shape that lets a wide producer fuse into the fold — moves the `max_depth` 4 sweep block from 23 to 21 dispatches (TOTAL 416 → 415), not the 4 a per-level fusion would need, and it is unshippable regardless: the reduction's association order is not the numpy fold's, so the accelerator leg would stop matching the reference.
`max_depth` is the dominant config term on the rollout leg and the largest lever left there: `cartpole_p100` measures **32.38 / 41.96 / 60.15 ms** per generation at `max_depth` 4 / 8 / 16 (same session, warmup 2 + 5 timed generations, seed 42), i.e. ≈2.3 ms per unrolled level ≈ 11.7 µs per level per query, against a floor of ≈21 ms fixed plus 200 × 57 µs for the rollout itself.
The evolved population never uses the ceiling: over 30 generations at the shipped `max_depth=16` the CartPole depth histogram is 2332 individuals at depth 1, 645 at 2, 21 at 3 and 2 at 4 with nothing deeper (per-generation maximum 1–4, mean 2.33, computed host-side from the payload keys). So `max_depth=4` is lossless on that workload and 1.86× faster and `max_depth=8` is 1.43× faster, while the default stays 16 because the ceiling is exactly what keeps a deeper evolved network from silently losing its value to `NaN` — shrinking it is a caller decision, not a library one.
Cost model on that leg: a flat graph pays ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, one `while` iteration ≈50 µs, and one `Tensor.to(cpu)` ≈47–60 µs per leaf, so a launch-bound graph is costed by dispatch count and `while` trips, not element volume; the seed trick saves exactly one dispatch per policy query (200 / 200 / 999 per generation for `CartPole` / `Pendulum` / `MountainCarContinuous`).
## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select` over per-pass masks, so a non-total option (division by zero, `log/sqrt` of a possibly negative value) can poison gradients even where it is not selected.
- Random draws differ from the JAX build by construction, so parity with `benchmarks/legacy_jax` is kernel-level for given genomes, never trajectory-level; the per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only, so a future innermost-axis fold of a **float** reduce must check the other backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene (`0.8` / `0.1` with no clip bounds against `0.2` / `0.015` clipped to `±5`; 0.8/0.1 are NEAT-python's own defaults) — 90.3 % of weight entries change per call against 20.7 % at a close `|Δweight|` distribution, which makes the connection-gene attribute term of `execute_distance` read ~0.05–0.06 here against ~0.01–0.02 there.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so a gather with duplicate indices silently keeps one contribution; no gradient may be taken through the window formulation until evoxc ships a scatter-add, and `grad.dense_grad_plan` therefore never gathers attributes — it reads the edge list and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell, host-side NumPy over `Transformed` only.
`select`'s VJP does not reduce a broadcast operand — it hands a rank-0 constant the cotangent at the *output* shape, so one shared scalar used by two `select`s of different shapes raises `ShapeError: cannot broadcast incompatible dims …`.
`_node_step`, `_hit_conn_attrs`, `_output_readout` and `_gather_prepared` are the only plain-forward path and must keep their per-level op budget; `grad.py` serves `BaseGenome.grad` exclusively and refuses at build time a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean`, a conn gene without a `weight` column, duplicate `(dst, src)` pairs and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal); its finite-difference check (`max_nodes=8`, `max_conns=12`, `key_span=64`, `h=1e-2`) leaves a worst error of **4.96e-5** (`response`) and **3.77e-5** (conn weight), with padding rows and non-weight columns at exactly `0`.
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236) and **origin families are not a learning defect** (a flat 0.25 MSE is a config/seed attractor: the same task with `init_hidden_layers=(4,)` reaches 0.0031 MSE at generation 100); both match the pre-rewrite library's semantics, so they are behaviour.
**Compatibility distance matches the frozen implementation exactly**: `execute_distance` agrees with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` on all 4 950 pairs of converted XOR3d payloads, and mutation alone grows that distance identically in both trees (median 0.90 → 1.12/1.10 after one call, → 1.82/1.75 after eight).
**`grad_from_payload`** (`host.py`) derives the schedule in a one-off executable, calls `grad`, then lowers/compiles/loads/runs it and returns `(node_attr_grads, conn_attr_grads)` as numpy (52 live entries, max |analytic − central difference| 5.91e-5, all 36 NaN padding entries exactly `0`); its `loss_fn` operands must be `evoxc`/`enp` tensors or Python scalars, and nothing in `src/` calls `grad`.
**Coverage gaps.** `gene/blocks.py`'s value-mutation stage has no independent-oracle module, `mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `alignment.py::_successor_ranks`'s encoded-rank inversion only through `test_crossover.py`; `P = 0` (refused upstream by `NEAT`) raises `ZeroDivisionError` in `step._sample_count` and a zero-size `reduce_max` in `_depth_limit`, and both `forward_prepared`s check batch rows but never `inputs.shape[1] == num_inputs`.
**Duplication worth folding.** `default.py::prepare_pass` and `recurrent.py::prepare_pass` repeat the eight-line `samples` validation verbatim, both `forward_prepared`s repeat the `rows == pop_size * samples` check, and `window._i32`/`utils._i32`/`operations/mutation/arrays.py` carry three byte-identical copies.
**`import tensorneat` does pull `sympy`** (`default.py` imports it at module scope for `sympy_func`; `networkx`/`matplotlib` are hard dependencies too), so the release gate's import list (jax/torch/brax/gymnax/mujoco) is the only hygiene that holds.
## Outside this node (for the owners of `algorithm/`, `common/`, `problem/`)
1. **The reproduction bottleneck dominates newborn survival**: `algorithm/neat/_kernels.py::pair_parents` collapses every species to a single survivor below `2 / survival_threshold` members.
2. **`algorithm/neat/neat.py::_new_gene_keys` allocates `OriginConn`'s `historical_marker` per individual** although full-tuple homology is only meaningful for a population-wide marker (`65536*in + out`, 7.5–14.6 pp better at generation 100).
3. `../common/tensorization.py::node_levels` is 64 % of `transform` (three innermost-axis `reduce_max` per `while_loop` iteration), the largest remaining transform win; `act.py` emits one `select` per option per level.
4. **Cheaper primitives `common/` should adopt**: `tools.py::fetch_random`/`fetch_first` pay two sentinel `select`s each against `mutation/arrays.py`'s `(row, hit)` pair; `window.fill(shape, value)` is one element plus a broadcast; `hyperneat.py::forward_prepared` builds `enp.ones((batch, 1))` + `concatenate` per query for the substrate bias column, which belongs in `prepare_forward`.
5. **The environment step is the largest RL dispatch block** (`../problem/rl/`) and needs the shape this node's `SeedColumns` uses (a column `gather` plus a baked-mask `where`).
6. **The accelerator leg's extra per-trip dispatch** belongs to `../common/schedule_accelerator.py`; fusing it back is a 20 % per-trip cut there.
## Test Strategy
`test/unit/genome/` runs on numpy through `test/support/runner.py`, one module per contract (payload and `transform` validation, forward values and NaN poisoning, Jacobi ticks, finite differences, mutation capacity and the four gates, key-tuple homology, distance bit-identity, host helpers, the prepared read-out and the seed spellings); `test/parity/` compares the same kernels against `benchmarks/legacy_jax` and needs the `bench` extra; `test/integration/` evolves XOR to target and pins determinism per seed.
**Bit-exactness gate** (required of any performance change here): numpy backend, the ledger genome plus `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)` and `XOR()`, seed 42, 10 `Pipeline.step` calls, the four `previous_pop` leaves in field order then `fitnesses`, each leaf hashed as `dtype.str + repr(shape) + tobytes()`; two conventions circulate, both green on this tree and not interchangeable — a **running single sha256** over the concatenated five leaves (`P=500` → `bca41966d9c949cbd2e58fd0a849edd3a51d86fa761219b8d3e9f417e3e30f6e`, `P=1000` → `3e7691819d46234822451a08103992027bef812152fd74aba3f56a9c64f88c76`) and **per-generation digests joined** (`P=500` → `d43edd0d3c19fe8f6bb4a1001246c40faaf82bf431e95e3a12f6c9b4a3e4c96e`, `P=1000` → `caba83eeebe50e86941fb7997c184e59f4702388d0826d77401a68dcb166bd45`); both pairs are identical under `kernel_mode="host"` and `"accelerator"` and both pin the shipped mutation law `(0.1, 0.1, 0.4, 0.05)` (0.2/0.2 gives `82f3cb…` / `763439…`). Environment: Python 3.12.3, numpy 2.5.4, `evoxc` from git tag `v0.1.1`.
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over `pipe._executable_for(state).backend_executable._module` catches every `DEFERRED_OPS`/dtype/axis/`scatter`-form violation at export time without IREE, while `pytest test/backends` (the `iree` extra) also catches `iree-compile` crashes a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value; a hand-built graph must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 key as `evoxc.TensorSpec((), evoxc.int64)`).
`RecurrentGenome` and the `grad` dense path do not share the level loop, so a change to `_node_step`/`window.py`/`prepare_pass` must re-check both, and no committed test selects an accelerator formulation — the five accelerator spellings (schedule writes, cycle predicate, alignment, distance grouping/centre, level sweep) and the three statics are gated by ad-hoc identity matrices and the generation-level digest gate only, so a `test/backends` cell in accelerator mode is the missing regression guard.
The level sweep's own guard is cheapest as a numpy unit test: build one payload per regime (`samples=1` with hidden nodes and an unconnected subtree, `samples=4` tiled) and compare `forward_prepared` under a `kernel_mode="accelerator"` state with the host-state result bitwise — the two spellings are eager on the interpreter, so the comparison needs no device; the hand verification at `231249da` covered depth 6, a NaN subtree, a network deeper than `max_depth` and a tiled batch, plus a three-generation `Pipeline` run in all three state modes, all bit-identical.
