# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors, and evaluate a whole population of differently-shaped networks in one batch-first kernel.
This node owns exactly four things: (1) the **gene payload** (key columns in `int32`, attribute columns in `float32`, padded rows), (2) the **genetic operators** (mutation / crossover / distance) as batched kernels, (3) the **forward algebra** over a precomputed execution schedule plus the exact gradient path beside it (`grad.py`), and (4) host-only introspection (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`).
It does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG` (`../common/functions/`); it consumes both.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers:
- `node_keys (P, max_nodes) int32` — node key per row; `I_INF` marks an absent row.
- `node_attrs (P, max_nodes, node_gene.attr_width) float32` — custom attrs; rows for absent nodes are NaN.
- `conn_keys (P, max_conns, conn_gene.key_width) int32` — `(in_key, out_key)` plus `historical_marker` when the conn gene declares it; `I_INF` marks an absent row.
- `conn_attrs (P, max_conns, conn_gene.attr_width) float32` — e.g. `weight`; absent rows are NaN.
`fixed_attrs` (key columns) are integers and stay integers; `custom_attrs` are floats and stay floats.
There is **no bitcast** float↔int in evoxc, so a single mixed-dtype row is impossible: the payload is split into a key array and an attr array, and this split is why genetic operators are integer-index twiddling over `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is a supported configuration (HyperNEAT/CPPN): every attr-table helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with an attribute distance of 0.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys are rows `max_nodes-num_outputs..max_nodes-1`; those rows are never deleted or moved, so `get_input_idx()`/`get_output_idx()` are usable as *row indices*.
Hidden node keys are arbitrary and may move rows; always compare keys (`node_keys`), never row positions, for graph identity.
Padding sentinels never mix: `I_INF` (`int32` max) for "no index", float NaN for "no value" and for "unconnected node value".
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds host-side configuration (`num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `max_in_degree`, `max_depth`, `key_span`, transforms, `init_hidden_layers`) and the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key: keys must lie in `[0, S)`, a caller allocating larger keys must raise it, and `S` is part of the Pipeline's shape signature.
A key outside `[0, S)` is *silently unmatched* by the schedule's dense key table: the edge or node becomes invisible without setting `edge_overflow` (which only reports in-degree > `K`), which is this node's one silent-failure mode — a caller that allocates structural keys (the algorithm) must keep them below `S` and raise `key_span` in the shape signature instead.
Measured cost of violating it (seed 42, XOR, `survival_threshold=0.01`): at `pop 500 / max_nodes 16` (`S=116`) 90 % of the keys the allocator would hand to the next add-node mutation lie outside `[0, S)`, and the evaluated population already hides 2.5 % of nodes / 4.9 % of connections, while `edge_overflow` stays 0 throughout.
Raising `key_span` from 150 to 2000 turns the 2-input `examples/func_fit/xor.py` from a flat `-0.25` (constant-0.5 read-out) into `-0.006` at generation 40 — 2-input only: XOR3d stays at `-0.25` with `key_span=4000` at pop 100 and pop 500, and the stalled pop-100 seed-42 genome holds no key >= 150, so an out-of-range allocator is not the cause of that plateau.
A *bounded* structural-key allocator (algorithm side) remains the durable fix for the 2-input case; widening this table is not.
`DefaultGenome`/`RecurrentGenome` accept `key_span=` explicitly (last keyword before super) so `algorithm/` can raise it past the default for its own structural-key allocation.
`DefaultGenome` carries **no** mutation-rate knobs: its `__init__` is `(num_inputs, num_outputs, max_nodes=50, max_conns=100, node_gene=None, conn_gene=None, mutation=None, crossover=None, distance=None, output_transform=None, input_transform=None, init_hidden_layers=(), max_in_degree=None, max_depth=16, key_span=None)` and each `None` builds a fresh `DefaultNode()`/`DefaultConn()`/`DefaultMutation()`/`DefaultCrossover()`/`DefaultDistance()` per instance.
The structural probabilities therefore live on the `mutation` operator (`DefaultMutation(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)`) and the value rates on each gene's `attr_specs` (`DefaultConn(weight_mutate_rate=0.8, weight_mutate_power=0.15, weight_replace_rate=0.1)`; `DefaultNode` bias/response `mutate_rate=0.2`, `mutate_power=0.15`, `replace_rate=0.015`, `init_std` 1.0/0.0 with ±5 bounds, aggregation/activation `replace_rate=0.1`); no enabled/disable knob exists.
`num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `max_in_degree`, `max_depth`, `key_span` are plain instance attributes set in `base.py::BaseGenome.__init__` — no property accessors exist in this node.
`S` is a *schedule* bound only: structural keys can exceed it, so genome-side homologue identity never derives a packing radix from it (`operations/alignment.py`/`operations/distance/digest.py` fold keys in base `2**31`, which is injective for the whole `int32` range) — homology is exact for keys far outside `[0, S)`.
`node_exists`, `conn_exists`, `max_node_key`, `max_conn_marker` are the thin in-graph helpers `algorithm/` calls; `execute_mutation`/`execute_crossover`/`execute_distance`/`transform` accept both the `GenomeTensors` payload and the positional four-array spelling.
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_values`, composed into `BaseGenome` as a mixin before `BaseGenomeHost`; `_hit_conn_attrs` returns a `_StepStatics` bundle (gathered conn attributes, the value-window gather index, the `present` and output-row masks, `NodeOperands`) because node/conn attributes are constant during a pass, so a level pays only value-dependent ops.
- `initialize(state, key, pop_size) -> GenomeTensors` — `key` is a rank-0 `evoxc.random` key and randomness is drawn once per tensor with the batched output shape, so individual `i` gets an independent stream from one call.
- `transform(state, node_keys, conn_keys) -> Transformed` — schedule derivation, delegated to `../common/tensorization.py`; pure tensor ops, no host round-trip.
The payload contract is checked before anything is derived: `node_keys` must be `(P, max_nodes)`, `conn_keys` `(P, max_conns, key_width)`, their leading dimensions must agree, and (four-array spelling) each attribute array must lead with `node_keys.shape[0]` (`node_attrs (P, max_nodes, NA)`, `conn_attrs (P, max_conns, CA)`).
A violation raises `common.errors.TensorNEATError`; a rank-1 `node_keys` or rank-2 `conn_keys` is reported as a per-individual row that needs a leading population axis (e.g. `node_keys[None, :]`), and the message says `Pipeline.auto_run` returns a `(1, ...)` batch, so slicing one individual out must keep that axis.
The validation reads `.shape` only (identical on a traced `evoxc.SymbolicTensor` and a host array), so it traces no op and behaves the same inside `evoxc.trace`, and it never compares a payload's sizes with `self.max_nodes`/`self.max_conns`: a differently configured genome legitimately receives an off-signature payload, and only one call's internal agreement is a contract.
It passes the **derived** `acyclic` static (`self.network_type == "feedforward"`, the last of 11 positional statics to `derive_schedule.fn`), never a constructor kwarg, so the shape signature and `_static_state` are unchanged.
With `acyclic=True` the cycle-detection relaxation, its in-graph test and the `evoxc.cond` fallback are not traced at all (`transform` 390 → 280 traced ops, 16.25 → 10.54 ms at P=1000, bit-identical `Transformed`); `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract, so a *cyclic* payload handed to a feedforward genome gets levels saturated at `max_nodes` and the loop clamps to `max_depth` (no test hands one there).
- `forward(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, inputs) -> (P, num_outputs)` — trace-time kernel; `inputs` may carry any batch (`P·Q` substrate queries), verified equal to `Q` independent `P`-sized passes for both the feedforward and the recurrent genome.
- `grad(state, transformed, node_*, conn_*, inputs, loss_fn) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel: it traces its own graph and returns it for the Pipeline to cache/compile/run, and its body is `grad.build_grad(self, ...)`; every call returns a **distinct** graph (the caller caches).
- `execute_mutation(state, key, genome, new_node_keys (P,), new_conn_keys (P,3)) -> GenomeTensors`
- `execute_crossover(state, key, genome1, genome2) -> GenomeTensors`
- `execute_distance(state, genome1, genome2) -> (P,)` — pairwise, batched over pairs; the algorithm forms the pairs.
- `prepare_distance(state, pop) -> DistanceDigest` — one digest per population genome, computed **once per generation** (packed sorted key rows, attribute rows permuted into that order, gene counts and every per-call static); `measure_distance(state, centre, digest) -> (P,)` measures one centre against the whole population with no re-sort and is **bit-identical** to `execute_distance` (verified on 5000 pairs and every `SpeciesState` leaf at pop 1000/500/100). That is how `algorithm/` speciates: `prepare` once, `measure` once per centre slot (cost table below).
- Host-only (NumPy in, Python out, never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `get_input_idx`, `get_output_idx` — the non-`sympy_func`/`visualize` ones live in `host.py::BaseGenomeHost` and take **one** individual: `_individual` raises `TensorNEATError`, telling the caller to slice first (`GenomeTensors(*(a[i:i+1] for a in payload))`; there is no `payload.of(i)`).
`GenomeTensors` is a namedtuple-like pytree of exactly the four payload arrays; every kernel takes and returns it by field, never by column offsets.
Structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** (globally unique across the population) and passed in as int32 tensors — they are not RNG draws.
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; field names are a binding contract with `common`:
- `in_src (P, max_nodes, K) int32` — flat index into `reshape(values, (P*max_nodes,))` of the source row of the k-th incoming edge of each node row; in range (0) where the slot is empty.
- `in_conn (P, max_nodes, K) int32` — flat index into `reshape(conn_attrs, (P*max_conns,))` of the same slot.
- `in_valid (P, max_nodes, K) bool` — True where that slot holds a real connection.
- `node_level (P, max_nodes) int32` — depth (longest path from an input node; inputs are 0), `I_INF` for absent rows; zeros in the recurrent variant.
- `node_exists (P, max_nodes) bool`, `overflow (P,) bool` — row validity, and "some node's in-degree exceeded `K`".
- static metadata `K`, `max_nodes`, `max_conns` as Python ints.
`K` is the genome's `max_in_degree`; slots are filled in increasing connection-row order so a node's window ordering is canonical and stable across runs.
## Cost law (measured, numpy reference backend)
Two rules govern every kernel here; both were measured, not assumed.
1. **An ordinary traced op costs ≈80 µs at `P=1000` regardless of element count**, so op count is the budget for elementwise/gather/select/reshape work.
2. **An innermost-axis reduction over a `(P, N, K)` tensor is 10–20× an ordinary op and does scale with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74 ms), versus 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms versus 1.06 ms for the slice-add fold (6.37 vs 3.49 ms at the tiled `4P=4000` batch).
Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked — more traced ops, far less time.
The same law applies to `common/functions/agg.py`'s `reduce_sum`/`count` over the window axis and to `gene/base.py::column` (a kept-axis slice + reshape is 2 view ops; `BaseGene.distance` subtracts the aligned attribute blocks once and reads one width-1 view per float column — 17 ops / 0.24 ms per node-gene call at `(500, 50, 4)` against 27 / 0.30 for a read-both-parents form, cutting `gene/` to 962 executed ops per pop-500 generation; a fully blocked pass with a static kind mask and a last-axis `reduce_sum` is 8 ops but 0.73 ms, 3× — element traffic, not op count, decides that kernel).
A third, layout rule matters for the mutation slabs: for `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms), the opposite of the `(P, N, K)` window case.
## Forward algebra (feedforward)
`values (P, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
Step 0 (both genomes): `node_attrs = self._padding_safe_attrs(node_attrs, node_keys)` replaces the attrs of **absent** rows with `0` via `select`, so the option-index columns (`activation`, `aggregation`) never reach the int cast as NaN; a NaN *value* column of a live row is untouched, so real corruption still poisons.
Step 1: `hit_conn_attrs = self._hit_conn_attrs(transformed, conn_attrs)` once (attributes are constant during a pass); the value-window gather index it builds is **block-shaped** `(P, N, K)` so `evoxc.gather` splices it directly (no reshape back).
Step 2: one `evoxc.while_loop` over levels, `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)` — `node_level` is `I_INF` on absent/unreachable/cyclic rows so it is masked and clamped first.
Loop body (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level` (the schedule's `I_INF` padding already excludes absent rows, so no `node_exists` term):
1. `xv = _gather_prepared(values, flat_index)` — one flatten, one flat gather, **no fill**: a statically dead slot is clamped to an in-range row by `window._slot_index` and keeps that row's value.
2. `live = present & (xv == xv)` — two narrow ops; IEEE makes `x == x` False exactly on NaN, so this catches a live slot whose source row is still NaN while `present` excludes the dead slots.
3. `msg = conn_gene.forward(statics.conn, xv)` — one `multiply` by the weight column; dead slots are neutral-filled by the aggregation before any reduce, and live slots pass through exactly.
4. `z = node_gene.forward(...)`: per-option aggregation over masks precomputed in `NodeOperands`, `combine` (`bias + response * agg`), then the activation — id `-1` (identity) on output rows, because the final activation belongs to `output_transform`.
5. `update = update_mask & any_slot(live)`; `values = select(update, z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source: the legacy NaN poisoning, reproduced exactly.
Read out `gather(values, output_idx, axis=1) -> (P, num_outputs)`, then `output_transform`.
Cost is `O((depth+1) × max_nodes × K)` with only elementwise/reduce/gather ops: work scales with real depth and real in-degree, never `max_depth` and never `max_nodes²`.
**Graph shape**: 67 entry ops + a **30-op level body** + a 1-op condition = **98 traced ops**, independent of `P`; the body runs `depth+1` times — measured **4 / 2 / 3** trips on the populations after 8 generations at P=100/500/1000 and **3 / 3 / 3** at generation 5, i.e. the per-level work dominates and the header is amortised.
**What is hoisted where** (the rule a future agent must follow): everything that does not depend on the loop-carried `values`/`level` is derived **once per pass** in `_hit_conn_attrs`/`NodeOperands` — the conn-attribute gather, the value-window flat index (`minimum` clamp + `add` row offsets + `reshape`), the `present` and output-row masks, and the option masks/rank-0 zero `node_gene.prepare` builds.
A level therefore pays only value-dependent work: `reshape` + `gather`, `equal` + `logical_and`, `multiply`, the aggregation (`select` neutral fill + reduce + `select` cascade), `combine` (2 ops), the activation (~5 ops + `select` cascade), `any_slot` (8 ops), `logical_and` + `select` for the update, and `level + 1`.
**Nothing wide may be computed per level unless a consumer reads it**: a dead-slot NaN fill after the value gather would be a `(P, N, K)` `select` per trip (0.30 ms of a 12.8 ms pass at 4P=2000) for values no consumer reads — the aggregation neutral-fills every slot of `live` before reducing — so it is one narrow `logical_and`, bit-identical because no dead slot reaches a reduce and `live` stays exactly `present & ~isnan(gathered)`.
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python** (the recurrent path keeps its tick loop; the level `while_loop` is feedforward-only).
Each tick: re-inject `input_transform`-free inputs into the input rows, compute every node from the previous tick's values (Jacobi/synchronous), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than a `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a predicate that is a boolean *any*.
`input_transform` is **not** applied by `RecurrentGenome` (legacy parity; HyperNEAT uses it as a CPPN).
`RecurrentGenome.sympy_func`/`visualize` are documented refusals: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, so both raise `TensorNEATError` naming that reason and pointing at `network_dict()` / `DefaultGenome` (never a bare `NotImplementedError` stub).
## Gradient algebra
`grad` never differentiates the plain forward, so the forward's `while_loop` region and the schedule's `argsort`/`sort` never meet reverse-mode. Three evoxc rules shape the API:
- `evoxc.grad` requires a **single scalar output**, so the loss is scalarized as `sum(loss_fn(outputs))`; per-individual gradients are unaffected because the population axis is independent.
- Only float inputs are differentiable: `node_attrs` and `conn_attrs` are the differentiated arguments; keys and the schedule are non-differentiated int inputs (an int32 *differentiated* argument is a hard `TransformError`).
- `sort`/`argsort` have no AD rule, so the schedule derivation must **not** be inside the differentiated graph — this is why `grad` takes an already-derived `transformed` and returns its own graph.
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`), so padding rows gradient to exactly `0`.
Why a second formulation exists: evoxc 0.1.0 derives a `gather` VJP with *put* semantics, so the fan-out gathers of the window step under-accumulate and the gradient is wrong wherever a node feeds several edges.
`grad` therefore differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`: a per-individual `W (P, N, N)` weight matrix scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and the live-slot gate `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact, so the gradients are the gradients of the plain forward (sum aggregation is `dot`, mean is the same `dot` divided by `maximum(live_count, 1)`; values agree with `BaseGenome.forward` to 1e-6).
`grad` still returns an `evoxc.Graph` for the Pipeline to cache; the plan (`W` cells, live matrix, level masks) is host-computed once per graph in `grad.dense_grad_plan`, and the measured cost is **273 traced ops**, 1.93 ms at pop 100 and 2.53 ms at pop 500 (build 21 / 27 ms), one fresh graph per call.
## Mutation algebra
`execute_mutation` is a batched *plan → apply* kernel run **once per operation**: `_edit_context` builds the masks and flat index blocks for the payload that stage receives, the operation (`add_node`, `delete_node`, `add_conn`, `delete_conn`) resolves its candidates into a namedtuple plan (`mutation/plan.py`), and `plan.apply` writes it.
The four stages compose sequentially in legacy order add-node → delete-node → add-conn → delete-conn, each planning against the payload the previous stage produced, so a later operation sees the earlier one's writes (delete-conn may consume an edge a split just created, delete-node may delete a node it just created, add-conn's duplicate/cycle/in-degree tests run on the post-stage graph).
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw (`drawn[i] < structural_probabilities[i]`), so one individual can receive up to four structural changes per call — at most one per operation — exactly as the frozen legacy library chains them; a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph.
Refusals are bit-exact no-ops: duplicate connection, self-connection, a cycle (one `while_loop` reachability relaxation over a flat `(P*(N+1),)` frontier with a dump column, `mutation/cycle.py`), an add-node whose allocated key already exists, an add-node whose split destination is already at `max_in_degree`, and capacity exhaustion.
`mutation/degree.py` exports `in_degree`/`max_in_degree`/`violation` (15 traced ops) as a standalone audit; `execute_mutation` never calls it (verified by monkey-patching it to raise) and enforces `max_in_degree` inline instead.
`closes_cycle` is gated on the static configuration: a `RecurrentMutation` with `p_recur == 0` never traces it (`RecurrentMutation` pop 1000: 324 ops / 18.0 ms at `p_recur=0`, 444 / 25.8 at `p_recur=0.1`), while the feedforward path always keeps it (an added connection there can close a cycle).
Its frontier is seeded by a one-hot `equal`/`logical_and`, **never** by a boolean `scatter`: a scatter whose result is the `while_loop` init SIGSEGVs `iree-compile` 3.11 llvm-cpu on the assembled generation graph while the same kernel compiles standalone, so only `pytest test/backends` catches a regression (`./operations/mutation/CONTEXT.md` holds the evidence).
Value mutation is one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`), with the draws kept per column — a `(…, A)`-wide `evoxc.random` draw costs ~9× a one-column draw, so per-column draws plus block-wide combining ops is the cheaper shape.
Measured cost of the four-stage form (numpy, `DefaultMutation`, pop 500): **578 traced ops** against 432 for the shared-gate baseline (96 shared scaffold + 137 add-node / 67 delete-node / 230 add-conn, 121 of them the cycle predicate / 48 delete-conn, exactly additive), 1.16× the baseline's kernel time at pop 500 and 0.82× at pop 1000, while `Pipeline.step` at XOR pop 500 seed 42 is flat within noise (median ratio 0.99); `./operations/mutation/CONTEXT.md` holds the ledger.
Gate multiplicity over 20 000 individual-mutations at the shipped `0.1/0.1/0.2/0.2`: 0/1/2/3/4 firing operations = 51.16/38.01/9.74/1.05/0.045 % (analytic P(any) 0.4816, P(>=2) 0.1072).
Per-operation acceptance on an evolved payload is add-node 95 %, delete-node 86 %, add-conn 54.6 % (over **1000 RNG draws** on that payload, against **52.5 %** for the frozen legacy tree on identical payloads; a single-draw estimate was a sampling artifact and must not be quoted), delete-conn 95 %; the joint payload diff shows >= 2 visible structural changes on 5.12 % of XOR and 4.47 % of XOR3d mutations, a split writing three connection edits, so that is not a per-gate count.
Search-quality profile at the shipped defaults (XOR3d benchmark config: `DefaultGenome(num_inputs=3, num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)` + `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, numpy backend): pop 100 (seeds 42-47) has **0/6** seeds escape the -0.05 target within 150 generations (best final -0.249999, seed 43; all six flat at -0.25) and **2/6** within 400 — seed 42 -1.822294e-02, seed 43 -2.563953e-10, seed 44 partial at -1.260456e-01, seeds 45-47 flat; pop 500 (seeds 42-47) has **3/6** escape within 150 generations; at pop 1000 seeds 42 and 44 converge within 150 generations while seed 43 does not.
Spot-checked final best fitness after 150 generations, seeds 42/43/44: pop 500 **-8.759811e-06 / -0.25 / -4.135456e-07**; pop 1000 **-9.067872e-14 / -0.25 / -6.149132e-09**.
The frozen legacy tree reaches -0.0278 / -0.1224 / -0.0894 on seeds 42/43/44 at 150 generations, so the pop-100 plateau is a search-dynamics wall on both trees, not structural-mutation multiplicity.
The independent gates still restore diversity — 1 → 7 live species by generation 6, against 1 live species for all 150 generations of the shared-gate tree — and seed 42 leaves the constant-0.5 plateau (−0.1594 at generation 149, mse 0.018 by generation 213), while the 150-generation median stays −0.25.
The frozen legacy value-mutation law (`weight_mutate_rate=0.2`, `weight_replace_rate=0.015`, `weight_mutate_power=0.15`, clip ±5) measured host-side on top of this kernel *worsens* both probed seeds (−0.25 flat on 42 and 44 at 150 generations), and adding the ±5 clip to the shipped defaults changes nothing (bit-identical finals), so the shipped `DefaultConn` defaults stay.
A frequency sweep (XOR3d pop 100, seeds 42-47, 150 generations, escapes vs the -0.05 target) gives **1/6** at the shipped `0.8`/`0.1` measured on the population that carried the add-node split heritability exemption — the same family whose pop-100 arm measured 1/6 — while the shipped rates measure **0/6** on this tree over the same seeds and budget; the legacy `0.2`/`0.015` gives **0/6**, that law plus a `±5` clip **0/6** (bit-identical finals to the unclipped run: the clip never binds, maximum `|w|` 3.8) and `0.5`/`0.05` **0/6**, while the legacy law flattens both converging cells (pop 1000 seed 42 and pop 500 seed 43 stay at −0.25) — so no alternative setting exceeds the shipped rates' own 0/6, the `DefaultConn` defaults stay, and the pop-100 constant-0.5 attractor is not gated by weight-mutation frequency.

## Crossover algebra
`operations/alignment.py` is the one **packed-identity merge** shared with distance: each key row becomes an injective `int64` identity (two 31-bit folds plus a 2-bit parent tag so an *unstable* `argsort` is correct), the parents' identities are concatenated, `argsort` once, the inverse permutation gives each row its rank, and a row is a homologue when its successor in sorted order carries its identity with the other parent's tag (a third `historical_marker` column is confirmed exactly).
Crossover inverts the permutation with one **encoded `int32` `sort`** (`alignment._successor_ranks`, 0.05 + 0.12 ms at pop 500) instead of two `scatter`s (0.42 ms), and `alignment.homologous_pair` returns `(rows, present)` from that one merge, so the "has a homologue" mask costs no extra `not_equal`/`select`.
The precondition is unique first two key columns within a parent (guaranteed by `initialize` and `execute_mutation`'s duplicate refusal): homology is by key tuple, never row position.
Argument order `(genome1, genome2)` = `(winner, loser)` is order-sensitive — parent 1 supplies the structure, only float attrs may come from parent 2 — and per-gene attribute inheritance is one `U[0,1)` block draw + `< 0.5` + `select` (`gene/blocks.py::crossover_attrs`), the per-entry Bernoulli(0.5) in 13 traced ops instead of 8; `./operations/crossover/CONTEXT.md` holds the ledger and the measured sort costs.
## Distance algebra
`execute_distance` (pairwise) and `prepare_distance`/`measure_distance` (digest) share the same alignment: the digest concatenates the population's packed identities **first**, so a population gene's merged index *is* its digest row and the successor test needs no side tag; `stable=True` lets the reference interpreter's timsort detect the digest half's ascending run.
`distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants, each costs one op), the attribute term is a reduced sum over the aligned rows, and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
The routes, the op ledger and the rejected diet are in `./operations/distance/CONTEXT.md`; that file also holds the `measure` sort-bound split (two `argsort`s per family plus casts are 27–30 % of the call) and why the dense route's 106 ops cost 1.9–2.1× less than the merge's 94.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push any destination past `K` is refused (`mutation/degree.py` is the same predicate as a standalone assertion); soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings: zero violations, worst payload in-degree exactly `K`.
- `max_depth` (`D`, default 16) is a **ceiling on the while-loop trip count**, not a cost multiplier: a node deeper than `D` is never visited and keeps its `NaN` value. Depth truncation is silent — it does **not** set `Transformed.overflow` (only the dropped-connection count does) — so the host must rebuild with a larger `D` on its own.
- `activate_time` (default 10) is the recurrent tick count.
- `key_span` (`S`): see the API section — a key outside `[0, S)` is dropped **silently** by the schedule, the one invariant the genome cannot enforce for its caller.
`Transformed.overflow` is the only host-visible diagnostic; nothing inside this node silently drops a connection or a node.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`).
- No eager NumPy on the compute path; the host helpers (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`) convert inputs with `Tensor.numpy()` and never feed results back into a graph.
- Every kernel is already batched: no per-individual Python loop and no `vmap`/`vectorize` over these kernels.
- The **only** region op in this node is the feedforward forward's level `while_loop` (default.py) plus the mutation cycle predicate's `while_loop`; neither may be differentiated (`grad.py` owns the differentiable path), and anything added inside a region pays the region overhead too, so loop-invariant work belongs in `_StepStatics`/`_hit_conn_attrs`/`_edit_context`.
- Shapes are static at trace time: `pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints; a change forces a rebuild (the Pipeline caches per shape signature).
- Integer arithmetic: an `int32` tensor plus a Python literal promotes to `int64` in evoxc, so index math stays in int32 tensors, and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`) — a full-size `I_INF` is a large graph constant plus an extra op per use.
- Graph-op axes are written as non-negative static integers (e.g. `concatenate(..., axis=len(shape))`, never `axis=-1`) because the StableHLO exporter forwards the axis verbatim as `dimension` and StableHLO requires it non-negative, so the `iree` backend rejects the negative form at compile time.
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors from evoxc propagate unchanged — never caught and re-wrapped.
- Shared machinery (one window-reduce node step) lives in `step.py::NodeStepMixin` and is parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- File sizes: `base.py` (979) is one job — configuration, payload construction, the schedule entry point, the `forward`/`grad` declarations and the operator entry points; `step.py` (450) holds the shared in-graph payload machinery; the per-pass window helpers live in `window.py` (316), introspection in `host.py` (348), the exact gradient path in `grad.py` (501), the gene helpers in `gene/base.py` (912) + `gene/blocks.py` (873).

The `measure` body emits **no** `constant` op: the per-call rank-0 constants, index blocks and attribute row base are built once in `prepare` and carried in the digest.
## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select`, over masks precomputed once per pass in `NodeOperands` (`option_masks`/`select_cascade`); a non-total option (division by zero, `log/sqrt` of a possibly negative value) can therefore poison gradients even where it is not selected.
- Random draws differ from the JAX build by construction (`evoxc.random` vs `jax.random`), so parity with `benchmarks/legacy_jax` is asserted on kernels for given genomes (forward, grad, distance), not on RNG-dependent operator output.
- The forward's per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only (a pure "any", so identical); any future innermost-axis fold of a **float** reduce must check the non-numpy backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene: `weight_mutate_rate=0.8` / `weight_replace_rate=0.1` and no clip bounds here, against the legacy `0.2` / `0.015` clipped to `±5` (0.8/0.1 are NEAT-python's own defaults, so the legacy constants are the outlier).
  Measured on one population (100 genomes × 3 conns, value mutation isolated): 90.3 % of weight entries change per call here against 20.7 % in `benchmarks/legacy_jax`, with conditional mean `|Δweight|` 0.232 vs 0.186 (median 0.105 vs 0.130, p99 2.45 vs 2.12) — a close distribution, so the difference is frequency, not step size.
  Consequence for speciation: on evolved XOR3d populations the connection-gene attribute term of `execute_distance` is ~0.05–0.06 here against ~0.01–0.02 in the legacy tree, so the two trees' payloads diverge in different proportions (attribute drift here, structural divergence there) even though the distance kernel is numerically identical.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so any gather with duplicate indices silently keeps one contribution instead of accumulating them.
Gradient algebra above explains the consequence: no gradient may be taken through the window formulation until evoxc ships a scatter-add, and the defect is unfixed here on purpose.
`grad.dense_grad_plan` therefore never gathers attributes: it reads the edge list (`conn_attrs[:, :, weight]`, `conn_exists`, `in_src`, `dst`) and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell (`N*N`) sliced off afterwards; the plan is host-side NumPy over `Transformed` only, so it costs one Python pass per compiled graph and nothing per generation.
`_node_step`, `_hit_conn_attrs` and `_gather_prepared` remain the only plain-forward path and must keep their per-level op budget; the exact path in `grad.py` is used exclusively by `BaseGenome.grad`.
`grad` refuses at graph-build time what the dense formulation cannot represent: a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean` (the `ConfigError` names the offending option), a conn gene without a `weight` column, duplicate `(dst, src)` pairs, and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal) — all five refusals live in `grad.dense_grad_plan`.
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`) and cleaned at the output (`select(isnan(g), 0, g)`), so padding rows, absent rows and non-weight attribute columns (option ids, historical markers) gradient to exactly `0`.
Finite-difference check (2-input → 3-hidden → 1-output XOR genome, `max_nodes=8`, `max_conns=12`, `DefaultNode`/`DefaultConn`, `key_span=64`, central differences at `h=1e-2`): worst analytic-vs-FD error **4.96e-5** (node `response` column) and **3.77e-5** (conn weight); the int-encoded option columns and every padding row gradient to exactly `0`, no entry NaN/inf.
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236): this matches the pre-rewrite library's split semantics, so it is behaviour, not a defect — changing it would change the search dynamics.
**Origin families are not a learning defect.** `OriginNode`/`OriginConn` inherit everything from the default families except `crossover` (whole-gene copy) and, for the conn gene, the `historical_marker` column.
With the current elite pin the connection gene's whole-gene copy is live from generation 1 (`OriginConn` diverges from `DefaultConn` there at pop 100 on seed-7 XOR), while `OriginNode` + `DefaultConn` reproduces the default trajectory bit-for-bit at that population; measured 100-generation XOR (seed 7, pop 300, `max_nodes=50`): `OriginNode+OriginConn` 0.0189 MSE, `OriginNode+DefaultConn` 0.0, `DefaultNode+DefaultConn` 1.7e-5, all well under 0.05.
A flat 0.25 MSE (every output = 0.5) that appears across runs is a **config/seed attractor of the search**, not a gene bug: in the literal `examples/func_fit/xor_origin.py` (XOR3d, `species_size=10`, pop 500, `max_nodes=16`) it hits the *default* family 4/8 seeds, `OriginNode+OriginConn` 5/8, `OriginConn` 3/8, `OriginNode` 0/8.
Neither the `key_span` allocator overflow above (measured not causal on XOR3d) nor a forward-path bug is a cause: the same task with `init_hidden_layers=(4,)` converges to 0.0031 MSE at generation 100, so the wall is search dynamics, not the phenotype.
**Compatibility distance matches the frozen implementation exactly.** On converted payloads (fresh and evolved XOR3d populations, all 4 950 pairs at generations 1/3/10/30, pop 100) `execute_distance` agrees with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` (float32 rounding), and both trees measure the same fresh-population distribution (median 0.90–0.93, mean 0.92–0.94, max 2.04; 4 nodes / 3 conns each), so a different species count is never a kernel-scale difference.
Mutation alone (no selection) also grows that distance identically in the two trees: median 0.90 → 1.12/1.10 after one call and → 1.82/1.75 after eight, with matching per-operation structural success rates at `p=0.5` (add-node 0.54 vs 0.50, delete-conn 0.47 vs 0.40; add-conn and delete-node are 0 on a 4-node/3-conn genome in both).
The structural gate law now matches the legacy tree (four independent Bernoullis composed sequentially), so the realised any-change rate is 0.4816 (multiplicity record in `## Mutation algebra` above); the remaining per-operation gap is refusal-driven, not draw-driven (add-conn is accepted on 54.6 % of fired gates here against 52.5 % legacy on identical payloads, 1000 draws each).
**Coverage gaps (current).** The gene value-mutation stage (`gene/blocks.py::mutate_attrs`/`init_attrs`/`crossover_attrs`) has no independent-oracle module: its legacy distributions, its NaN-liveness/re-draw rule, its per-column draw order and its clip windows are pinned only payload-level by `test_mutation.py`.
`operations/mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `operations/alignment.py::_successor_ranks`'s encoded-rank inversion only through `test_crossover.py`'s behavioural tests.
The exact oracle recipes that close the gene stage and the write path are recorded in `./operations/mutation/CONTEXT.md`; a change to either helper is gated meanwhile by the bit-exactness protocol of `## Test Strategy`.

## Outside this node (measured, for the owners of `algorithm/` and `common/`)
1. **`algorithm/neat/neat.py::_new_gene_keys` allocates structural node keys from the pre-crossover population** (`max_node_key + 1 + slot`, slot < P) and therefore outruns `key_span` within ~10 generations (81 % of *allocated* keys outside `[0, S)` at pop 200/`max_nodes=50`; the pop-500 and `key_span`-raise measurements are in `## Genome API`), and the schedule drops those genes silently; it also produces duplicate-key collisions, which this node refuses at the plan level.
2. **`algorithm/neat/_kernels.py::pair_parents`'s `survive = clamp(floor(survival_threshold · member_count), 1, …)`** collapses every species to a single survivor below `2 / survival_threshold` members (200 at `0.01`, every example config), which is why one-parent blocks dominate at small populations; a `min(2, member_count)` lower bound was measured and rejected (no trajectory effect), and the elementwise elite pin in the same module makes a species' top-2 members distinct.
3. **`algorithm/neat/neat.py::_new_gene_keys` allocates `OriginConn`'s `historical_marker` per individual**, while full-tuple homology is only meaningful for a population-wide marker (`65536*in + out`), which measures 7.5–14.6 pp better at generation 100.
4. **The live call site never reaches the dense single-centre route.** `algorithm/neat/_kernels.py::single_payload` tiles a batch-1 centre to `pop_size` identical rows before `measure_distance`, so `measure` takes the merge route (94 ops / 2.39 ms at pop 500, 4.33 ms at pop 1000) instead of the batch-1 dense one (102 ops / 1.35 ms, 2.02 ms at pop 1000); `_broadcast_payload` (12 ops) replaces the caller's 16-op tiling when the dense route's static gate fails. Passing the batch-1 centre is worth ~480 executed ops and ~50 ms per generation at pop 500 (~120 ms at pop 1000), is bit-identical on a tiled centre, and becomes exact for every payload only together with the `key_span` bound of item 1 (the dense table cannot address keys outside `[0, key_span)`, the merge matches them) — the only ≥5 % lever left in this call path, a one-line change in `algorithm/`.
5. `../common/tensorization.py::node_levels` is 64 % of `transform` (three innermost-axis `reduce_max` per `while_loop` iteration); folding them the `window.any_slot` way and dropping the `reach` relaxation for a feedforward genome (static `acyclic=True`, −27 % of the whole transform) are the largest remaining transform wins.
6. `../common/functions/agg.py`'s `sum`/`mean`/`max`/`min`/`product` and `count` are innermost-axis reduces over `(P, N, K)` (a `K`-slice fold measured −20 % of `forward(P)`, bit-identical on numpy); `act.py` still emits the sigmoid body plus one `select` per configured option per level.

The check is bit-exact only when all 10 generations × 5 leaves at both populations reproduce those digests; a change is compared against another tree with two separate processes, the reference source first on `sys.path` with `tensorneat.__file__` asserted under that root.
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over the module reached as `pipe._executable_for(state).backend_executable._module` (`evoxc.backends.numpy.NumpyExecutable` keeps the lowered module as `_module`).
It is the *static* portability gate: it needs no IREE and catches every `DEFERRED_OPS` / dtype / axis / `scatter`-form violation at export time.
The real gate is `pytest test/backends` (needs the `evoxc[iree]` extra), which compiles and runs one XOR generation on IREE 3.11 llvm-cpu: it also catches `iree-compile` crashes that a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value.
Measured on a small payload (`pop_size=20`, `max_nodes=12`, `max_conns=24`, 2 inputs / 1 output: `node_keys (20,12) int32`, `node_attrs (20,12,4) f32`, `conn_keys (20,24,2) int32`, `conn_attrs (20,24,1) f32`): the generation graph exports at **732 200 bytes, 1 898 op uses over 13 distinct ops**, dominated by `broadcast_in_dim` 968, `compare` 442, `reduce` 140 and `gather` 139 (then `slice`, `concatenate`, `scatter`, `transpose`, `sort`, `pad`, `while`, `dot_general`, `if`).
The mutation and crossover graphs pass the same gate with their own census (`./operations/mutation/CONTEXT.md`, `./operations/CONTEXT.md`).
Outcomes on all of them: no `DEFERRED_OPS` op, no unsigned dtype (`ui8/16/32/64`), every `dimension =` attribute non-negative, every `stablehlo.scatter` carrying one of the two permitted `scatter_dimension_numbers` (rank-1 axis-0: `update_window_dims = []`, `inserted_window_dims = [0]`, `scatter_dims_to_operand_dims = [0]`, `index_vector_dim = 1`; rank-2 row/column write: `update_window_dims = [1]` with the rest alike), and only `f32`/`f64`/`i1`/`i8`/`i32`/`i64` element types.
A hand-built graph for this check must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 RNG key as `evoxc.TensorSpec((), evoxc.int64)`): a plain numpy array argument to `evoxc.build` is a static baked into the trace, which exports a constant-only graph — `test/support/runner.py` builds the specs for the suite.
`RecurrentGenome` and the `grad` dense path are not covered by the level-loop machinery, so a change to `_node_step`/`window.py` must re-check both (they share the window step).
