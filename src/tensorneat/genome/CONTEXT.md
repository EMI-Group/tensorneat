# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors, and evaluate a whole population of differently-shaped networks in one batch-first kernel.
This node owns exactly four things: (1) the **gene payload** (key columns in `int32`, attribute columns in `float32`, padded rows), (2) the **genetic operators** (mutation / crossover / distance) as batched kernels, (3) the **forward algebra** over a precomputed schedule plus the exact gradient path beside it (`grad.py`), and (4) host-only introspection, hashing and gradient orchestration (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`) — nothing in this node runs a host helper inside a trace.
It does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG` (`../common/functions/`); it consumes both.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers:
- `node_keys (P, max_nodes) int32` — node key per row; `I_INF` marks an absent row.
- `node_attrs (P, max_nodes, node_gene.attr_width) float32` — custom attrs; rows for absent nodes are NaN.
- `conn_keys (P, max_conns, conn_gene.key_width) int32` — `(in_key, out_key)` plus `historical_marker` when the conn gene declares it; `I_INF` marks an absent row.
- `conn_attrs (P, max_conns, conn_gene.attr_width) float32` — e.g. `weight`; absent rows are NaN.
`fixed_attrs` (key columns) are integers and stay integers; `custom_attrs` are floats and stay floats.
There is **no bitcast** float↔int in evoxc, so a single mixed-dtype row is impossible: the payload is split into a key array and an attr array, which is why genetic operators twiddle integer `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is a supported configuration (HyperNEAT/CPPN): every attr-table helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with an attribute distance of 0.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys are rows `max_nodes-num_outputs..max_nodes-1`, rows that are never deleted or moved.
That layout is this genome's *template*, never the read-out rule: the schedule resolves the output keys to slots (`Transformed.output_slot`) and the forward reads those, so a payload ordered inputs, outputs, hidden (a substrate executor) is read correctly, while `get_input_idx()`/`get_output_idx()` describe only the template rows.
Hidden node keys are arbitrary and may move rows; always compare keys (`node_keys`), never row positions, for graph identity.
Padding sentinels never mix: `I_INF` (`int32` max) for "no index", float NaN for "no value" and for "unconnected node value".
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds the host-side configuration listed below (plus `output_transform`/`input_transform`/`init_hidden_layers`) and the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key: keys must lie in `[0, S)`, a caller allocating larger keys must raise it, and `S` is part of the Pipeline's shape signature.
A key outside `[0, S)` is *silently unmatched* by the schedule's dense key table: the edge or node becomes invisible without setting `edge_overflow` (which only reports in-degree > `K`), which is this node's one silent-failure mode, so a caller that allocates structural keys must keep them below `S` and raise `key_span` in the shape signature instead.
`algorithm/neat/_keys.py::node_keys_for_split` keeps every structural key inside that window (a per-individual spread wrapped into `[max_nodes, key_span)`, with `first_free_keys` as collision fallback) and `validate_key_space` rejects `key_span <= max_nodes` at `NEAT` construction; measured payloads at pop 100 XOR3d keep max key 134-149 over 150 generations with `S = 150`, so the silent-drop path is reachable only from an out-of-band caller.
Raising `key_span` from 150 to 2000 turns the 2-input `examples/func_fit/xor.py` from a flat `-0.25` (constant-0.5 read-out) into `-0.006` at generation 40, 2-input only: XOR3d stays at `-0.25` with `key_span=4000` at pop 100 and pop 500, so widening the table is not the XOR3d lever.
`DefaultGenome`/`RecurrentGenome` accept `key_span=` explicitly (last keyword before super) for that purpose.
`DefaultGenome` carries **no** mutation-rate knobs: its `__init__` is `(num_inputs, num_outputs, max_nodes=50, max_conns=100, node_gene=None, conn_gene=None, mutation=None, crossover=None, distance=None, output_transform=None, input_transform=None, init_hidden_layers=(), max_in_degree=None, max_depth=16, key_span=None)` and each `None` builds a fresh `DefaultNode()`/`DefaultConn()`/`DefaultMutation()`/`DefaultCrossover()`/`DefaultDistance()` per instance.
The structural probabilities therefore live on the `mutation` operator: `DefaultMutation`'s own constructor defaults stay NEAT-python's `(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)`, while `DefaultGenome`/`RecurrentGenome` build `DefaultMutation(conn_add=DEFAULT_GENOME_CONN_ADD, conn_delete=DEFAULT_GENOME_CONN_DELETE)` = `(0.1, 0.1, 0.4, 0.05)` when `mutation is None` (`operations/mutation/default.py` exports the two constants, not in `__all__`), so the population default is the rebalanced connection pair and an explicit `DefaultMutation()` keeps the constructor pair.
The value rates live on each gene's `attr_specs` (`DefaultConn(weight_mutate_rate=0.8, weight_mutate_power=0.15, weight_replace_rate=0.1)`; `DefaultNode` bias/response `mutate_rate=0.2`, `mutate_power=0.15`, `replace_rate=0.015`, `init_std` 1.0/0.0 with ±5 bounds, aggregation/activation `replace_rate=0.1`); no enabled/disable knob exists.
`num_inputs`, `num_outputs`, `max_nodes`, `max_conns`, `max_in_degree`, `max_depth` and `key_span` are plain instance attributes set in `base.py::BaseGenome.__init__` — no property accessors exist in this node.
`S` is a *schedule* bound only, so genome-side homologue identity never derives a packing radix from it (`operations/alignment.py`/`operations/distance/digest.py` fold keys in base `2**31`, injective for the whole `int32` range), and homology is exact for keys far outside `[0, S)`.
`node_exists`, `conn_exists`, `max_node_key` and `max_conn_marker` are the thin in-graph helpers `algorithm/` calls, and the kernels accept both the `GenomeTensors` payload and the positional four-array spelling.
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_values`, composed into `BaseGenome` as a mixin before `BaseGenomeHost`; `_hit_conn_attrs` returns a `_StepStatics` bundle (gathered conn attributes, the value-window gather index, the `present` and output-row masks, `NodeOperands`) because node/conn attributes are constant during a pass, so a level pays only value-dependent ops.
`_output_row_mask(transformed)` derives the `(P, N)` output-row mask from `transformed.output_slot` with one static `(1, N)` `arange` constant broadcast-compared against each output column and folded with `logical_or`: no `scatter`, no row-position assumption, derived once per pass.
`_output_values(transformed, values, output_transform)` reads the outputs out of the node values: it clamps/fans `output_slot` with `window._slot_index`, gathers it in one `_gather_prepared`, writes `NaN` where a slot is `I_INF`, and applies `output_transform`.
- `initialize(state, key, pop_size) -> GenomeTensors` — `key` is a rank-0 `evoxc.random` key and randomness is drawn once per tensor with the batched output shape, so individual `i` gets an independent stream from one call.
- `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed` — schedule derivation, delegated to `../common/tensorization.py`; pure tensor ops, no host round-trip.
  The two keyword-only key overrides pin which keys the schedule treats as the network's inputs and outputs, which is what lets one genome derive a substrate executor's `inputs, outputs, hidden` schedule (`output_slot` then names the substrate output neurons); `input_keys` must equal this genome's own `input_idx`, because `forward` seeds the inputs into rows `0..num_inputs-1`, while a host `output_keys` may be any `num_outputs`-long integer sequence.
The payload contract is checked before anything is derived: `node_keys` must be `(P, max_nodes)`, `conn_keys` `(P, max_conns, key_width)`, their leading dimensions must agree, and in the four-array spelling each attribute array must lead with `node_keys.shape[0]`.
A violation raises `common.errors.TensorNEATError`; a rank-1 `node_keys` or rank-2 `conn_keys` is reported as a per-individual row that needs a leading population axis (e.g. `node_keys[None, :]`), and the message says `Pipeline.auto_run` returns a `(1, ...)` batch, so slicing one individual out must keep that axis.
The validation reads `.shape` only (identical on a traced `evoxc.SymbolicTensor` and a host array), so it traces no op and behaves the same inside `evoxc.trace`; it never compares a payload's sizes with `self.max_nodes`/`self.max_conns`, because a differently configured genome legitimately receives an off-signature payload and only one call's internal agreement is a contract.
`transform` passes the **derived** `acyclic` static (`self.network_type == "feedforward"`, the last of 11 positional statics to `derive_schedule.fn`), never a constructor kwarg, so the shape signature and `_static_state` are unchanged.
With `acyclic=True` the cycle-detection relaxation, its in-graph test and the `evoxc.cond` fallback are not traced at all (280 traced `transform` ops, 10.54 ms at P=1000, bit-identical `Transformed`); `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract, so a *cyclic* payload handed to a feedforward genome gets levels saturated at `max_nodes` and the loop clamps to `max_depth` (no test hands one there).
- `forward(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, inputs) -> (P, num_outputs)` — trace-time kernel; `inputs` may carry any batch (`P·Q` substrate queries), verified equal to `Q` independent `P`-sized passes for both the feedforward and the recurrent genome.
- `prepare_pass(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, samples=1) -> Any` and `forward_prepared(state, transformed, prepared, inputs) -> (P, num_outputs)` — the same pass split into its loop-invariant operands (`_PreparedPass`: padding-safe `node_attrs`, `_StepStatics` with its node operands forced, the depth bound / expanded `node_level`, or the recurrent expanded `update_mask`) and its per-query half; `forward` is exactly prepare + forward_prepared, byte-identical to it, and a rollout loop prepares once per payload and calls `forward_prepared` per timestep.
`prepare_pass` validates `samples` as a positive int and `forward_prepared` rejects an `inputs` batch that is not `pop_size * samples` (`TensorNEATError`).
- `grad(state, transformed, node_*, conn_*, inputs, loss_fn) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel: it traces its own graph and returns it for the Pipeline to cache/compile/run, and its body is `grad.build_grad(self, ...)`; every call returns a **distinct** graph (the caller caches).
- `execute_mutation(state, key, genome, new_node_keys (P,), new_conn_keys (P,3)) -> GenomeTensors`
- `execute_crossover(state, key, genome1, genome2) -> GenomeTensors`
- `execute_distance(state, genome1, genome2) -> (P,)` — pairwise, batched over pairs; the algorithm forms the pairs.
- `prepare_distance(state, pop) -> DistanceDigest` — one digest per population genome, computed **once per generation** (packed sorted key rows, attribute rows permuted into that order, gene counts and every per-call static); `measure_distance(state, centre, digest) -> (P,)` measures one centre against the whole population with no re-sort and is **bit-identical** to `execute_distance` (verified on 5000 pairs and every `SpeciesState` leaf at pop 1000/500/100), so `algorithm/` does `prepare` once and `measure` once per centre slot (cost table below).
  A **batch-1** centre may take `DefaultDistance`'s dense key-table route, which addresses only keys inside `[0, key_span)`; `distance/base.py::measure` validates that precondition on host-resident data (the digest's `node_oor`/`conn_oor` and the centre's own out-of-range keys) and raises `TensorNEATError` naming the key space and the remedies, while a traced digest is skipped because a value may not drive a traced raise — the pipeline is unaffected because `algorithm/neat/_kernels.py::single_payload` tiles the centre to `pop_size` rows (merge route, exact for any key).
- Host-only (NumPy in, Python out, never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`, `get_input_idx`, `get_output_idx` — the non-`sympy_func`/`visualize` ones live in `host.py::BaseGenomeHost`.
- `network_dict` and `repr` take **one** individual in either documented spelling, normalised by `host.py::BaseGenomeHost._one_individual_payload`: the `(1, …)` batch (`Pipeline.auto_run`'s payload, both `examples/interpret_visualize` scripts build one with `initialize(state, key, 1)`) or the bare per-individual rows a checkpoint stores (`node_keys (N,)`, `node_attrs (N, A)`, `conn_keys (E, CK)`, `conn_attrs (E, CA)`).
  The same helper refuses `None`, a non-four-field payload, a `P > 1` batch (with the slice recipe) and fields that disagree about the spelling, so the two public helpers (`Pipeline.show` via `host_payload._one_individual` and these two) agree on what one genome is.
  `_split_payload` (`base.py`) still enforces batch-first for every compute entry point.
  A `P > 1` batch raises `ConfigError` telling the caller to slice (`GenomeTensors(*(a[i:i+1] for a in payload))`; there is no `payload.of(i)`).
- `hash` is **host-only numpy** (`(P,) np.uint32`), the xor-fold of `common.tools.hash_rows` over each gene family's key rows and its quantised attribute rows (`rint(attrs * HASH_QUANT_SCALE)`, NaN → `0`), folded across rows so padding that sits on other rows hashes equal.
  It emits no evoxc op and therefore no unsigned dtype, and a payload whose leaves are `SymbolicTensor`s is refused with a `TensorNEATError` naming that: in-graph gene identity is the key columns plus `evoxc.equal`.
  `HASH_QUANT_SCALE` (1e6) reaches the `int32` range at `|attr| ≈ 2147.48` and wraps beyond it, so the hash is a heuristic de-duplication key, never an identity test anywhere.
`GenomeTensors` is a namedtuple-like pytree of exactly the four payload arrays, always taken and returned by field.
Structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** (globally unique across the population) and passed in as int32 tensors — they are not RNG draws.
`_check_key_shapes` (`base.py`) refuses any other dtype with a `TensorNEATError` naming the tensor and the required `int32` (a cast would be a traced op for a host-side contract violation), so a widened or float key tensor cannot reach `enp.stack`/`scatter`.
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; field names are a binding contract with `common`:
- `in_src (P, max_nodes, K) int32` — flat index into `reshape(values, (P*max_nodes,))` of the source row of the k-th incoming edge of each node row; in range (0) where the slot is empty.
- `in_conn (P, max_nodes, K) int32` — flat index into `reshape(conn_attrs, (P*max_conns,))` of the same slot.
- `in_valid (P, max_nodes, K) bool` — True where that slot holds a real connection.
- `node_level (P, max_nodes) int32` — depth (longest path from an input node; inputs are 0), `I_INF` for absent rows; zeros in the recurrent variant.
- `node_exists (P, max_nodes) bool`, `overflow (P,) bool` — row validity, and "some node's in-degree exceeded `K`"; `K`, `max_nodes` and `max_conns` are Python-int statics.
`K` is the genome's `max_in_degree`; slots are filled in increasing connection-row order so a node's window ordering is canonical and stable across runs.
## Cost law (measured, numpy reference backend)
Every number in this section is this node's own measurement on the numpy reference interpreter, one fixed payload per kernel, medians of repeated runs.
Two rules govern every kernel here.
Both were measured, not assumed.
1. **An ordinary traced op pays ≈13 µs of interpreter dispatch plus its own array traffic** (`benchmarks/PERF_NUMPY.md` attributes ~58–63 % of a generation to that fixed per-op cost), so op count is the budget for elementwise/gather/select/reshape work while element volume decides the wide passes and the innermost-axis reduces of rule 2.
2. **An innermost-axis reduction over a `(P, N, K)` tensor is 10–20× an ordinary op and does scale with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74 ms), versus 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms versus 1.06 ms for the slice-add fold (6.37 vs 3.49 ms at the tiled `4P=4000` batch).
Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked — more traced ops, far less time.
The same law applies to `common/functions/agg.py`'s `reduce_sum`/`count` over the window axis and to `gene/base.py::column`, where a kept-axis slice + reshape is 2 view ops and a fully blocked pass pays 3× in element traffic for 8 ops; `gene/CONTEXT.md` holds the column-read measurements.
A third, layout rule matters for the mutation slabs: for `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms), the opposite of the `(P, N, K)` window case.
## Forward algebra (feedforward)
`values (P, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
Step 0 (both genomes): `node_attrs = self._padding_safe_attrs(node_attrs, node_keys)` replaces the attrs of **absent** rows with `0` via `select`, so the option-index columns (`activation`, `aggregation`) never reach the int cast as NaN; a NaN *value* column of a live row is untouched, so real corruption still poisons.
Step 1: `hit_conn_attrs = self._hit_conn_attrs(transformed, conn_attrs, samples)` once (attributes are constant during a pass); the value-window gather index it builds is **block-shaped** `(rows, N, K)` — the schedule's `P` rows, or the tiled `P·S` rows when a problem tiles a dataset — so `evoxc.gather` splices it directly (no reshape back).
Step 2: one `evoxc.while_loop` over levels, `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)` — `node_level` is `I_INF` on absent/unreachable/cyclic rows so it is masked and clamped first.
Loop body (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level` (the schedule's `I_INF` padding already excludes absent rows, so no `node_exists` term):
1. `xv = _gather_prepared(values, flat_index)` — one flatten, one flat gather, **no fill**: a statically dead slot is clamped to an in-range row by `window._slot_index` and keeps that row's value.
2. `live = present & (xv == xv)` — two narrow ops; IEEE makes `x == x` False exactly on NaN, so this catches a live slot whose source row is still NaN while `present` excludes the dead slots.
3. `msg = conn_gene.forward(statics.conn, xv)` — one `multiply` by the weight column; dead slots are neutral-filled by the aggregation before any reduce, and live slots pass through exactly.
4. `z = node_gene.forward(...)`: per-option aggregation over masks precomputed in `NodeOperands`, `combine` (`bias + response * agg`), then the activation — id `-1` (identity) on output rows, because the final activation belongs to `output_transform`.
5. `update = update_mask & any_slot(live)`; `values = select(update, z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source: the legacy NaN poisoning, reproduced exactly.
Read out `gather(values, output_idx, axis=1) -> (P, num_outputs)`, then `output_transform`.
Cost is `O((depth+1) × max_nodes × K)` with only elementwise/reduce/gather ops: work scales with real depth and real in-degree, never `max_depth` and never `max_nodes²`.
**Graph shape**: 67 entry ops + a **30-op level body** + a 1-op condition = **98 traced ops**, independent of `P`; the body runs `depth+1` times — measured **4 / 2 / 3** trips on the populations after 8 generations at P=100/500/1000 and **3 / 3 / 3** at generation 5, i.e. the per-level work dominates and the header is amortised.
**What is hoisted where** (the rule a future agent must follow): everything that does not depend on the loop-carried `values`/`level` is derived **once per pass** in `_hit_conn_attrs`/`NodeOperands` — the conn-attribute gather, the value-window flat index (`minimum` clamp + `add` row offsets + `reshape`), the `present`/output-row masks and the option masks plus the rank-0 `node_gene.prepare` builds.
A level therefore pays only value-dependent work: `reshape` + `gather`, `equal` + `logical_and`, `multiply`, the aggregation (`select` neutral fill + reduce + `select` cascade), `combine` (2 ops), the activation (~5 ops + `select` cascade), `any_slot` (8 ops), `logical_and` + `select` for the update, and `level + 1`.
**Nothing wide may be computed per level unless a consumer reads it**: a dead-slot NaN fill after the value gather would be one `(P, N, K)` `select` per trip for values no consumer reads, because the aggregation neutral-fills every slot of `live` before reducing; the narrow `logical_and` is bit-identical since no dead slot reaches a reduce and the `present &` term keeps `live` exactly `present & ~isnan(gathered)`.
**Read set of one feedforward pass**: `in_conn`/`in_src`/`in_valid` (`step.py::_hit_conn_attrs`), `node_level` and `node_exists` (`default.py::_depth_limit`); `src`, `dst`, `edge_valid`, `topo_key`, `input_slot`, `output_slot` and `edge_overflow` are never read (`grad.py::dense_grad_plan` reads the first three, the slot tables have no reader in `src/`, `edge_overflow` is host-only), because the pass uses the row invariant (inputs `0..I-1`, outputs `N-O..N-1`).
The recurrent forward drops `node_level` too and keys only on `node_exists` and `in_valid` (`recurrent.py::forward`).
Payload reads: `node_keys` only in `_padding_safe_attrs` (`step.py`), `node_attrs` once as one wide `select` plus per-column views in `node_gene.prepare` (`gene/node/base.py`), `conn_attrs` once in the `_hit_conn_attrs` gather (`step.py`), and **`conn_keys` never** — it is an accepted-but-unused `forward` parameter (`default.py::forward`).
`_hit_conn_attrs` sizes every static from the *schedule's* row count (`transformed.in_conn.shape[0]`, i.e. `P`), so a `P·S`-tiled pass derives the conn gather, the padded node attrs, `present`, `output_rows` and the option masks once and expands each with `window.by_samples` — one copy per operand instead of a re-derivation at `P·S` rows (see `## Tiled batch`).
The one operand it derives at the tiled width is the flat value-window index, whose baked `p * row_len` offsets make it genuinely row-dependent.
`fill`/`_iinf` (one element, `window.py`) and `_output_row_mask`'s `(N,)` flag plus broadcast (`step.py`) stay row-count independent.
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python** (the recurrent path keeps its tick loop; the level `while_loop` is feedforward-only).
Each tick: re-inject `input_transform`-free inputs into the input rows, compute every node from the previous tick's values (Jacobi/synchronous), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than a `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a predicate that is a boolean *any*.
`input_transform` is **not** applied by `RecurrentGenome` (legacy parity; HyperNEAT uses it as a CPPN).
`RecurrentGenome.sympy_func`/`visualize` are documented refusals: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, so both raise `TensorNEATError` naming that reason and pointing at `network_dict()` / `DefaultGenome` (never a bare `NotImplementedError` stub).
## Gradient algebra
`grad` never differentiates the plain forward, so the forward's `while_loop` region and the schedule's `argsort`/`sort` never meet reverse-mode. Three evoxc rules shape it:
- `evoxc.grad` requires a **single scalar output**, so the loss is scalarized as `sum(loss_fn(outputs))`; per-individual gradients are unaffected because the population axis is independent.
- Only float inputs are differentiable: `node_attrs` and `conn_attrs` are the differentiated arguments; keys and the schedule are non-differentiated int inputs (an int32 *differentiated* argument is a hard `TransformError`).
- `sort`/`argsort` have no AD rule, so the schedule derivation must **not** be inside the differentiated graph — this is why `grad` takes an already-derived `transformed` and returns its own graph.
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`), so padding rows gradient to exactly `0`.
The second formulation exists because evoxc 0.1.0's `gather` VJP has put semantics (`## Known Issues`), so the fan-out gathers of the window step under-accumulate.
`grad` therefore differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`: a per-individual `W (P, N, N)` weight matrix scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and the live-slot gate `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact, so the gradients are the gradients of the plain forward (sum aggregation is `dot`, mean is the same `dot` divided by `maximum(live_count, 1)`; values agree with `BaseGenome.forward` to 1e-6).
`grad` returns an `evoxc.Graph` for the Pipeline to cache; the plan (`W` cells, live matrix, level masks) is host-computed once per graph in `grad.dense_grad_plan`, and this node's own measured cost is **273 traced ops**, 1.93 ms at pop 100 and 2.53 ms at pop 500 (build 21 / 27 ms).
## Mutation algebra
`execute_mutation` is a batched *plan → apply* kernel run **once per operation**: `_edit_context` builds the masks and flat index blocks for the payload that stage receives, the operation (`add_node`, `delete_node`, `add_conn`, `delete_conn`) resolves its candidates into a namedtuple plan (`mutation/plan.py`), and `plan.apply` writes it.
The four stages compose sequentially in legacy order add-node → delete-node → add-conn → delete-conn, each planning against the payload the previous stage produced, so a later operation sees the earlier one's writes (delete-conn may consume an edge a split just created, delete-node may delete a node it just created, add-conn's duplicate/cycle/in-degree tests run on the post-stage graph).
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw (`drawn[i] < structural_probabilities[i]`), so one individual can receive up to four structural changes per call — at most one per operation — exactly as the frozen legacy library chains them; a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph.
Refusals are bit-exact no-ops: duplicate connection, self-connection, a cycle (one `while_loop` reachability relaxation over a flat `(P*(N+1),)` frontier with a dump column, `mutation/cycle.py`), an add-node whose allocated key already exists or whose split destination is already at `max_in_degree`, and capacity exhaustion.
`mutation/degree.py` exports `in_degree`/`max_in_degree`/`violation` (15/16/20 traced ops) as a public standalone audit with no caller in `src/` — `execute_mutation` enforces `max_in_degree` inline instead — and no test coverage.
`closes_cycle` is gated on the static configuration: a `RecurrentMutation` with `p_recur == 0` never traces it (324 traced ops at `p_recur=0` against 444 at `p_recur=0.1`, pop 1000), while the feedforward path always keeps it because an added connection there can close a cycle.
Its frontier is seeded by a one-hot `equal`/`logical_and`, **never** by a boolean `scatter`: a scatter whose result is the `while_loop` init SIGSEGVs `iree-compile` 3.11 llvm-cpu on the assembled generation graph while the same kernel compiles standalone, so only `pytest test/backends` catches a regression (`./operations/mutation/CONTEXT.md` holds the evidence).
Value mutation is one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`), with the draws kept per column because a `(…, A)`-wide `evoxc.random` draw costs ~9× a one-column draw (this node's own measurement).
The four-stage composition executes 578 traced ops at pop 500 (`DefaultMutation`, this node's own measurement), 1.16× the shared-gate baseline's kernel time at pop 500 and 0.82× at pop 1000 while `Pipeline.step` (XOR pop 500 seed 42) stays flat within noise (median ratio 0.99); the per-stage op split is in `./operations/mutation/CONTEXT.md`.
Gate multiplicity over 20 000 individual-mutations at `(0.1, 0.1, 0.2, 0.2)` is 0/1/2/3/4 firing operations = 51.16/38.01/9.74/1.05/0.045 % (analytic P(any) 0.4816, P(>=2) 0.1072), and the shipped genome pair `(0.1, 0.1, 0.4, 0.05)` raises P(any) to 0.5383 at an unchanged P(>=2) of 0.1036, i.e. +5.7 pp of individuals changing structure per call; the realized acceptance rates, the refusal split and the joint-payload multiplicity are in `./operations/mutation/CONTEXT.md`.
Search-quality consequence of that balance (XOR3d, pop 100, seeds 0-19, 150 generations, numpy, fitness = −mse, target −0.05; **escape** = some generation best above −0.24, i.e. off the constant-0.5 attractor at −0.25): the shipped gates escape on **13/20** and reach the target on **11/20**, against **4/20** and **2/20** for the frozen `benchmarks/legacy_jax` tree on the same seeds and budget (Fisher two-sided p = 0.0095).
The gate histogram, the acceptance rates, the per-seed finals, the XOR and pop-500/pop-1000 cells and every rejected alternative are recorded in `algorithm/CONTEXT.md` `## Search Quality` and `./operations/mutation/CONTEXT.md`.
## Structural birth/death accounting (measured, `xor3d_p100`, pop 100, 150 generations, seeds 0-4 new / 0-2 frozen)
The structural operators sit in **steady state and birth is not scarce**: realized per-operation acceptance on evolved payloads (isolated `execute_mutation`, all 150 generations) is add-node 0.99-1.00, delete-node 0.69-1.00, add-conn 0.39-0.65 and delete-conn 0.99-1.00, while nodes per individual rise and connections barely do, so surplus nodes stay weakly wired.
`conn_delete` is therefore accepted about twice as often as `conn_add`, which sets the analytic steady state at ≈0 net nodes and −0.14…−0.22 net connections per individual per generation at equal gates, while the shipped `0.4`/`0.05` pair gives add 0.4 × ~0.50 ≈ +0.20 against delete 0.05 × ~1.00 = −0.05 — the balance that holds the wiring.
add-conn refusals are dominated by duplicate, self-connection and cycle, with `max_in_degree` (`K` = 4) refusing almost nothing and `max_depth` = 16 never binding (max `node_level` stays at 6-9), so neither static ceiling is the birth limit.
A forced split is fitness-median-neutral and lands on an input→output path, so the bottleneck is **inheritance, not birth**: only ~9-11 of 100 individuals per generation are structural copies of a previous individual, an injected newborn key survives to t=10 in ~1 % of cases, and 10-29 % of present hidden nodes have no path from an input while 10-21 % have no path to the output.
The composition and acceptance records and the operator-configuration arm behind the shipped gate pair live in `./operations/mutation/CONTEXT.md`.
## Crossover algebra
`operations/alignment.py` is the one **packed-identity merge** shared with distance: each key row becomes an injective `int64` identity (two 31-bit folds plus a 2-bit parent tag so an *unstable* `argsort` is correct), the parents' identities are concatenated and sorted once, the inverse permutation gives each row its rank, and a row is a homologue when its successor in sorted order carries its identity with the other parent's tag (a third `historical_marker` column is confirmed exactly).
Crossover inverts the permutation with one **encoded `int32` `sort`** (`alignment._successor_ranks`, 0.05 + 0.12 ms at pop 500) instead of two `scatter`s (0.42 ms), and `alignment.homologous_pair` returns `(rows, present)` from that one merge, so the "has a homologue" mask costs no extra `not_equal`/`select`.
The precondition is unique first two key columns within a parent (guaranteed by `initialize` and `execute_mutation`'s duplicate refusal): homology is by key tuple, never row position.
Argument order `(genome1, genome2)` = `(winner, loser)` is order-sensitive — parent 1 supplies the structure, only float attrs may come from parent 2 — and per-gene attribute inheritance is one `U[0,1)` block draw + `< 0.5` + `select` (`gene/blocks.py::crossover_attrs`), the per-entry Bernoulli(0.5) in 13 traced ops; `./operations/crossover/CONTEXT.md` holds the ledger and the measured sort costs.
## Distance algebra
`execute_distance` (pairwise) and `prepare_distance`/`measure_distance` (digest) share that alignment: the digest concatenates the population's packed identities **first**, so a population gene's merged index *is* its digest row and the successor test needs no side tag; `stable=True` lets the reference interpreter's timsort detect the digest half's ascending run.
`distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants, each costs one op), the attribute term is a reduced sum over the aligned rows, and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
The routes, the op ledger and the rejected diet are in `./operations/distance/CONTEXT.md`; that file also holds the `measure` sort-bound split (two `argsort`s per family plus casts are 27–30 % of the call) and why the dense route's 106 ops cost 1.9–2.1× less than the merge's 94.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push any destination past `K` is refused (`mutation/degree.py` is the same predicate as a standalone assertion); soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings with zero violations.
- `max_depth` (`D`, default 16) is a **ceiling on the while-loop trip count**, not a cost multiplier: a node deeper than `D` is never visited and keeps its `NaN` value. Depth truncation is silent — it does **not** set `Transformed.overflow` (only the dropped-connection count does) — so the host must rebuild with a larger `D` on its own.
- `activate_time` (default 10) is the recurrent tick count.
- `key_span` (`S`): see the API section — a key outside `[0, S)` is dropped **silently** by the schedule, the one invariant the genome cannot enforce for its caller.
`Transformed.overflow` is the only host-visible diagnostic; nothing inside this node silently drops a connection or a node.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`).
- No eager NumPy on the compute path; the host helpers convert inputs with `Tensor.numpy()` and never feed results back into a graph.
- Every kernel is already batched: no per-individual Python loop and no `vmap`/`vectorize` over these kernels.
- The **only** region op in this node is the feedforward forward's level `while_loop` (default.py) plus the mutation cycle predicate's `while_loop`; neither may be differentiated (`grad.py` owns the differentiable path), and anything added inside a region pays the region overhead too, so loop-invariant work belongs in `_StepStatics`/`_hit_conn_attrs`/`_edit_context`.
- Shapes are static at trace time: `pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints; a change forces a rebuild (the Pipeline caches per shape signature).
- Integer arithmetic: an `int32` tensor plus a Python literal promotes to `int64` in evoxc, so index math stays in int32 tensors, and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`) — a full-size `I_INF` is a large graph constant plus an extra op per use.
- Graph-op axes are non-negative static integers (e.g. `concatenate(..., axis=len(shape))`, never `axis=-1`), because the StableHLO exporter forwards the axis verbatim as `dimension` and rejects the negative form at compile time.
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors from evoxc propagate unchanged — never caught and re-wrapped.
- Shared machinery (one window-reduce node step) lives in `step.py::NodeStepMixin` and is parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- File sizes stay under ~1000 lines and each file is one job: `base.py` (998), `step.py` (524), `window.py` (363), `host.py` (673), `grad.py` (501), `default.py` (710), `gene/base.py` (861) + `gene/blocks.py` (873); the Routing Table states each file's responsibility.

## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select`, over masks precomputed once per pass in `NodeOperands` (`option_masks`/`select_cascade`); a non-total option (division by zero, `log/sqrt` of a possibly negative value) can therefore poison gradients even where it is not selected.
- Random draws differ from the JAX build by construction (`evoxc.random` vs `jax.random`), so parity with `benchmarks/legacy_jax` is asserted on kernels for given genomes (forward, grad, distance), not on RNG-dependent operator output.
- The forward's per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only (a pure "any", so identical); a future innermost-axis fold of a **float** reduce must check the non-numpy backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene: `weight_mutate_rate=0.8` / `weight_replace_rate=0.1` and no clip bounds here, against the legacy `0.2` / `0.015` clipped to `±5` (0.8/0.1 are NEAT-python's own defaults, so the legacy constants are the outlier).
  This node's own measurement (100 genomes × 3 conns, value mutation isolated): 90.3 % of weight entries change per call here against 20.7 % in `benchmarks/legacy_jax`, at a close `|Δweight|` distribution (conditional mean 0.232 vs 0.186, median 0.105 vs 0.130), so the difference is frequency, not step size.
  Consequence for speciation: on evolved XOR3d populations the connection-gene attribute term of `execute_distance` is ~0.05–0.06 here against ~0.01–0.02 in the legacy tree, so the two trees' payloads diverge in different proportions (attribute drift here, structural divergence there) even though the distance kernel is numerically identical.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so any gather with duplicate indices silently keeps one contribution instead of accumulating them.
No gradient may be taken through the window formulation until evoxc ships a scatter-add, and the defect is unfixed here on purpose.
`grad.dense_grad_plan` therefore never gathers attributes: it reads the edge list (`conn_attrs[:, :, weight]`, `conn_exists`, `in_src`, `dst`) and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell sliced off afterwards, host-side NumPy over `Transformed` only, so it costs one Python pass per compiled graph.
`_node_step`, `_hit_conn_attrs` and `_gather_prepared` remain the only plain-forward path and must keep their per-level op budget; `grad.py` serves `BaseGenome.grad` exclusively.
`grad` refuses at graph-build time what the dense formulation cannot represent: a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean` (the `ConfigError` names the option), a conn gene without a `weight` column, duplicate `(dst, src)` pairs, and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal).
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`) and cleaned at the output (`select(isnan(g), 0, g)`), so padding rows, absent rows and non-weight columns gradient to exactly `0`.
Finite-difference check (2-input → 3-hidden → 1-output XOR genome, `max_nodes=8`, `max_conns=12`, `DefaultNode`/`DefaultConn`, `key_span=64`, central differences at `h=1e-2`): worst analytic-vs-FD error **4.96e-5** (node `response` column) and **3.77e-5** (conn weight); the int-encoded option columns and every padding row gradient to exactly `0`, no entry NaN/inf.
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236): this matches the pre-rewrite library's split semantics, so it is behaviour, not a defect — changing it would change the search dynamics.
**Origin families are not a learning defect.** `OriginNode`/`OriginConn` inherit everything from the default families except `crossover` (whole-gene copy) and, for the conn gene, the `historical_marker` column; with the current elite pin the conn gene's whole-gene copy is live from generation 1, while `OriginNode` + `DefaultConn` reproduces the default trajectory bit-for-bit at pop 100, and the per-family finals are in `gene/CONTEXT.md` `## Known Issues`.
A flat 0.25 MSE (every output = 0.5) that appears across runs is a **config/seed attractor of the search**, not a gene bug, and neither the `key_span` allocator above (measured not causal on XOR3d) nor a forward-path bug is a cause: the same task with `init_hidden_layers=(4,)` converges to 0.0031 MSE at generation 100, so the wall is search dynamics, not the phenotype.
**Compatibility distance matches the frozen implementation exactly.** On converted payloads (fresh and evolved XOR3d populations, all 4 950 pairs at generations 1/3/10/30, pop 100) `execute_distance` agrees with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` (float32 rounding), and both trees measure the same fresh-population distance distribution, so a different species count is never a kernel-scale difference.
Mutation alone (no selection) also grows that distance identically in the two trees (median 0.90 → 1.12/1.10 after one call and → 1.82/1.75 after eight), with matching per-operation structural success rates at `p=0.5`.
The structural gate law matches the legacy tree (four independent Bernoullis composed sequentially), so the realised any-change rate is 0.4816 at `(0.1, 0.1, 0.2, 0.2)` and 0.5383 at the shipped `(0.1, 0.1, 0.4, 0.05)` (`## Mutation algebra` above); the remaining per-operation gap is refusal-driven, not draw-driven.
**Coverage gaps (current).** The gene value-mutation stage (`gene/blocks.py::mutate_attrs`/`init_attrs`/`crossover_attrs`) has no independent-oracle module, `operations/mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `operations/alignment.py::_successor_ranks`'s encoded-rank inversion only through `test_crossover.py`'s behavioural tests.
The oracle recipes that close them, and the bit-exactness gate a change must pass meanwhile, are in `./operations/mutation/CONTEXT.md` `## Test Strategy`.
**`grad_from_payload` is the host entry point for gradient descent through evolved topologies.** `BaseGenomeHost.grad_from_payload(state, payload, inputs, loss_fn, *, backend="numpy", device=None, compile_options=None)` derives the schedule in a one-off executable (the `pipeline._schedule_of` recipe, duplicated rather than imported), calls `grad` for the graph, then lowers/compiles/loads/runs it and returns `(node_attr_grads, conn_attr_grads)` as numpy.
It is verified end to end independently of `grad`'s own finite-difference test: `DefaultGenome(num_inputs=2, num_outputs=3, max_nodes=8, max_conns=12)`, `P = 2`, central differences through `forward` at `h = 1e-2` give **52 live entries, max |analytic − central difference| = 5.91e-5**, all 36 NaN padding entries gradient to exactly `0`, two calls are bit-identical, and a `P = 1` batch is a legitimate single-individual gradient.
Two traced-operand constraints cost a debugging round if unstated and are in its `Notes:` — `loss_fn`'s operands must be Python scalars or `evoxc`/`enp` tensors (a numpy target array raises `TypeError: unsupported operand type ndarray`), and the loss multiplies rather than `** 2` (evoxc's `power` pullback emits an unconditional `log`).
Still true and unchanged: nothing in `src/` (`Pipeline`, `algorithm/`) calls `grad` or `grad_from_payload`, and no example script exists, so a `P > 1` population gradient is a documented user recipe rather than a library feature; the graph is re-traced per call, so a repeated use must cache the returned arrays or its own graph, and the loss *value* is never returned (read it from `forward` with the same `loss_fn`).
**Edge cases the suite does not exercise.** `P = 0` is refused upstream (`NEAT` validates `pop_size` through `positive_int`) but the kernels answer it with `ZeroDivisionError` in `_sample_count` (`step.py:223`, `divmod(batch, pop_size)`) and a zero-size `reduce_max` in `_depth_limit`, not a `TensorNEATError`; `P = 1` is exercised end to end.
`DefaultGenome.forward_prepared` and `RecurrentGenome.forward_prepared` validate the batch *rows* but never `inputs.shape[1] == num_inputs`, so a wrong input width surfaces as an evoxc shape error rather than a configuration error.
**Duplication worth folding.** `default.py::prepare_pass` and `recurrent.py::prepare_pass` repeat the eight-line `samples` validation verbatim, and both `forward_prepared`s repeat the same `rows == pop_size * samples` check — both belong in `step.py::NodeStepMixin`.
`window._i32` (`window.py:76`) and `utils._i32` (`utils.py:68`) are byte-identical (a third copy is in `operations/mutation/arrays.py`).
`visualize` imports `networkx`/`matplotlib` inside its body, but both are hard runtime dependencies of `pyproject.toml`, so a missing install surfaces as a raw `ImportError` rather than a configuration error; `sympy` is imported at module scope in `default.py:24`, so `import tensorneat` does pull the code-generation dependency, contrary to `host.py`'s docstring.

## Outside this node (measured, for the owners of `algorithm/` and `common/`)
1. **The reproduction bottleneck dominates newborn survival.** `algorithm/neat/_kernels.py::pair_parents` collapses every species to a single survivor below `2 / survival_threshold` members, which is why only ~9-11 of 100 individuals per generation are structural copies of a previous individual; every structural-operator measurement in this node is conditional on that (`algorithm/CONTEXT.md`).
2. **`algorithm/neat/neat.py::_new_gene_keys` allocates `OriginConn`'s `historical_marker` per individual**, while full-tuple homology is only meaningful for a population-wide marker (`65536*in + out`), which measures 7.5–14.6 pp better at generation 100.
3. **The live call site never reaches the dense single-centre route.** `algorithm/neat/_kernels.py::single_payload` tiles a batch-1 centre to `pop_size` rows before `measure_distance`, so `measure` takes the merge route (94 ops / 2.39 ms at pop 500, 4.33 ms at pop 1000) instead of the batch-1 dense one (102 ops / 1.35 ms, 2.02 ms at pop 1000), which is bit-identical on a tiled centre and exact for every payload only with a bound on every allocated key (the dense table cannot address keys outside `[0, key_span)`, the merge matches them) — the only ≥5 % lever left in this call path (`algorithm/CONTEXT.md`).
4. `../common/tensorization.py::node_levels` is 64 % of `transform` (three innermost-axis `reduce_max` per `while_loop` iteration), so folding them the `window.any_slot` way is the largest remaining transform win.
5. `../common/functions/agg.py`'s `sum`/`mean`/`max`/`min`/`product` and `count` are innermost-axis reduces over `(P, N, K)`, and `act.py` emits the sigmoid body plus one `select` per configured option per level.
6. `../common/tools.py::fetch_random`/`fetch_first` pay two sentinel `select`s each (11/6 ops); `operations/mutation/arrays.py`'s `(row, hit)` primitive is the cheaper pair `common` should adopt.
7. **Graph constants are one element plus a broadcast.** `window.fill(shape, value)` is `enp.broadcast_to(enp.full((1,)*rank, value), shape)`, every population-scaled fill in this node goes through it (`forward`'s NaN seed, the recurrent `values` block, `grad.dense_forward`'s seeds, `execute_mutation`'s sentinels/identity/zero rows, `gene/blocks.py::column_constant`, `base.py`'s padding seeds), and a `(1, max_nodes)`-shaped mask or a genuinely static table keeps its `enp.full`.
The baked-constant table, the largest single constant, the `Graph.save` sizes, the `grad` build-time pair and the parameter-table A/B live in `gene/CONTEXT.md` `## Graph constants (measured)`.
`Pipeline.build_seconds` is 0.271 / 0.328 / 0.480 s at pop 100/500/1000, and the one-element-plus-broadcast form left every kernel's wall clock unchanged beyond drift.
`transform`'s remaining baked constants (a `(P, 201)` int32 table in two copies) live in `../common/tensorization.py` — outside this node, reported upward.

## Tiled batch (`P·S` rows): statics are derived at `P` and expanded once
`NodeStepMixin._sample_count(inputs, pop_size)` recovers the static `S = batch // P` from the two shapes inside `forward` and raises `TensorNEATError` when the batch is not a positive multiple of the population, so a tiled dataset must be individual-major over the population axis.
`window.by_samples(x, samples, pop_size)` expands a `P`-row tensor to the tiled rows with `reshape` + `broadcast_to` + `reshape` (one copy per operand, flat order `p * S + j`), and is the identity for `S == 1` and for a tensor without the population axis.
`_hit_conn_attrs`/`_StepStatics` derive the conn-attribute gather, its cleaned `weight` column, `present`, `output_rows` and `NodeOperands` at the schedule's `P` rows and expand only the prepared leaves, so the per-sample-identical operands cost one copy each instead of a re-derivation at `P·S` rows; `node_operands` refuses a second `forward` pass built from a different attribute tensor.
Only the flat value-window gather index is genuinely row-dependent: `evoxc.gather` is `np.take(arr, indices, axis)` (`evoxc/backends/numpy/kernels/indexing.py::_gather`) with `infer_gather`'s `x.shape[:axis] + indices.shape + x.shape[axis+1:]`, i.e. a whole-block index into one axis with no per-leading-row semantics, so the index must carry the `(p·S+s)` row offset.
`window._slot_index(..., samples)` therefore clamps at the schedule's `P` rows, expands the clamped index, and adds one baked `_row_offsets(rows, row_len, rank)` constant (`p * row_len` at the tiled width) — one rows-scale `int32` `add` no expansion removes, because a `broadcast_to` index view cannot address a per-row window.
`_depth_limit` and the rest of the schedule geometry stay at `P` rows, and `default.py` expands `node_level` with `by_samples` for the per-level update mask.
`host_payload._prepared_query` passes the schedule and the payload through unrepeated at `P` rows and only chunks: it evaluates at most `EVAL_CHUNK_ROWS` (12 500) tiled rows per forward — `EVAL_CHUNK_ROWS // S` individuals per chunk — slicing the `P`-row trees with `_slice_batch` and concatenating the group outputs in row order.
That chunking is bit-identical because every forward op is row-local and the one population-wide quantity, the level loop's depth bound, is a maximum a group can only under-shoot.
One static `samples` (= `S`) is recovered inside `forward` from the batch and the population, so no caller threads it and a direct caller (`Pipeline.show`, a unit test) stays at `samples=1`; the CPPN pass inside `HyperNEAT._query_substrate` keeps `samples=1` because `_expand_schedule`/`_expand_leaf` fuse the query axis into axis 0 before that forward runs, while the *substrate* forward uses `samples` like any other.
`benchmarks/PERF_NUMPY.md` pass 2 records `custom_pagie_p500` (pop 500, `max_nodes=50`, `max_in_degree=4`, `CustomFuncFit(num_samples=500)`, so `P·S = 250 000` and `S = 500`) at the committed protocol (150 generations, 3 warmup, 3 repeats, numpy) as **833.81 ms per generation, 1361.4 MiB peak RSS and a 1.63 s build**, and its own same-session A/B shows the chunk budget is load-bearing: the unbounded `P*S` block measured 3282 / 3315 ms per generation against 838 / 841 ms with `EVAL_CHUNK_ROWS`, at 4578 → 1315 MiB peak.
The XOR populations (`S = 4`) stay on the unchunked path, so the `P=500`/`P=1000` reference digests of `## Test Strategy` reproduce, and the `iree` smoke of `custom_pagie_p500` agrees with numpy to 2.38e-07 (float fusion).
Design (B), **not taken**: a real sample axis (`values (P,S,N)`, window `(P,S,N,K)`, statics `(P,1,…)`) would make the expansions 0-stride views and leave only the index `add`, but it saves at most the `by_samples` copies and moves the window step to `(P,1,N)` across `step.py`/`window.py`/`default.py`/`recurrent.py`/`gene/node/base.py`.
Rejected: fetching the representative rows with `slice(..., strides=S)`, because a non-unit-`strides` slice is a new StableHLO/iree pattern.
Neither route touches the level loop's own element volume, `(depth + 1) × P·S × max_nodes × max_in_degree` elements per forward, so chunking and right-sizing `max_nodes`/`max_conns` remain the primary levers and this expansion is second-order.

`test/integration/` evolves XOR to target on the numpy backend and pins determinism per seed; `test/release_gate_no_jax.py` asserts that `import tensorneat` pulls in no `jax`/`torch`.

**Bit-exactness gate (the check any performance change to this node must pass).** numpy backend, `DefaultGenome(num_inputs=2, num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)` + `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)` + `XOR()`, seed 42, 10 `Pipeline.step` calls, run-level sha256 over `dtype.str + repr(shape) + tobytes()` of each generation's four payload leaves then `fitnesses`, at `P=500` and `P=1000`.
Reference digests of that run — one chained sha256, per generation feeding `to_numpy` of the four `previous_pop` leaves in field order (`node_keys`, `node_attrs`, `conn_keys`, `conn_attrs`) then `fitnesses`, each as `dtype.str + repr(shape) + tobytes()`: `P=500` → `bca41966d9c949cbd2e58fd0a849edd3a51d86fa761219b8d3e9f417e3e30f6e`, `P=1000` → `3e7691819d46234822451a08103992027bef812152fd74aba3f56a9c64f88c76`.
These pin the shipped genome mutation law `(node_add, node_delete, conn_add, conn_delete) = (0.1, 0.1, 0.4, 0.05)`; the same protocol at `(0.1, 0.1, 0.2, 0.2)` (`DefaultMutation`'s own constructor defaults) reproduces `P=500` → `82f3cb1c3c3bfd35a24195d97f239e0801cbf7dc1b7220d4cd0973b6a9d25639` and `P=1000` → `763439a2b324a6263142521eb43229cbe5d120754c4ea1c570a57b80a91e09f6`, so a digest mismatch with an unchanged gate law is a kernel change and either pair is a valid reference for its own law.
Both reproduce in two separate fresh processes on this tree, and exactly this leaf order and composition is required — a different order or a missing `fitnesses` leaf reproduces neither digest.
Environment the digests were taken in, because any library change moves them: Python 3.12.3, numpy 2.5.4, `evoxc` resolved by the lock from git tag `v0.1.1` (whose metadata reports version 0.1.0).
A digest mismatch with an unchanged fitness-trajectory shape is a kernel change, a different trajectory shape is a behavioural change.
The check is bit-exact only when all 10 generations × 5 leaves at both populations reproduce those digests; a change is compared against another tree with two separate processes, the reference source first on `sys.path` with `tensorneat.__file__` asserted under that root.
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over the module reached as `pipe._executable_for(state).backend_executable._module` (`evoxc.backends.numpy.NumpyExecutable` keeps the lowered module as `_module`); it is the *static* gate, needs no IREE and catches every `DEFERRED_OPS` / dtype / axis / `scatter`-form violation at export time.
The real gate is `pytest test/backends` (needs the `iree` extra, `uv sync --extra iree`), which compiles and runs one XOR generation on IREE 3.11 llvm-cpu and also catches `iree-compile` crashes a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value.
This node's own measurement on a small payload (`pop_size=20`, `max_nodes=12`, `max_conns=24`, 2 inputs / 1 output: `node_keys (20,12) int32`, `node_attrs (20,12,4) f32`, `conn_keys (20,24,2) int32`, `conn_attrs (20,24,1) f32`): the generation graph exports at **732 200 bytes, 1 898 op uses over 13 distinct ops**, dominated by `broadcast_in_dim`, `compare`, `reduce` and `gather`.
The mutation and crossover graphs pass the same gate with their own census (`./operations/mutation/CONTEXT.md`, `./operations/CONTEXT.md`).
Outcomes on all of them: no `DEFERRED_OPS` op, no unsigned dtype (`ui8/16/32/64`), every `dimension =` attribute non-negative, every `stablehlo.scatter` carrying one of the two permitted `scatter_dimension_numbers` (rank-1 axis-0, or the rank-2 row/column write), and only `f32`/`f64`/`i1`/`i8`/`i32`/`i64` element types.
A hand-built graph for this check must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 RNG key as `evoxc.TensorSpec((), evoxc.int64)`): a plain numpy array argument to `evoxc.build` is a static baked into the trace, which exports a constant-only graph — `test/support/runner.py` builds the specs for the suite.
`RecurrentGenome` and the `grad` dense path are not covered by the level-loop machinery, so a change to `_node_step`/`window.py` must re-check both (they share the window step).
