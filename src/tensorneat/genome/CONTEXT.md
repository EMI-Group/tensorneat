# genome — gene payloads, genetic operators, and the network forward/grad algebra
## Intent
Turn a NEAT individual into fixed-shape `int32`/`float32` evoxc tensors, and evaluate a whole population of differently-shaped networks in one batch-first kernel.
This node owns four things: the **gene payload** (key columns in `int32`, attribute columns in `float32`, padded rows), the **genetic operators** (mutation / crossover / distance) as batched kernels, the **forward algebra** over a precomputed schedule plus the exact gradient path beside it (`grad.py`), and host-only introspection, hashing and gradient orchestration (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`) — nothing here runs a host helper inside a trace.
It does not own the schedule derivation (`../common/tensorization.py`) nor `ACT`/`AGG` (`../common/functions/`); it consumes both.
The schedule, homologue-alignment, cycle-predicate and distance kernels each ship a **host** spelling and an **accelerator** spelling, chosen by a static host branch on the trace-time `State`; the host spelling is the numpy default and the accelerator spelling is the compiled-device leg.
## Gene payload (binding)
Two arrays per gene type, batch-first, static shapes, no NaN in integers:
- `node_keys (P, max_nodes) int32` — node key per row; `I_INF` marks an absent row.
- `node_attrs (P, max_nodes, node_gene.attr_width) float32` — custom attrs; rows for absent nodes are NaN.
- `conn_keys (P, max_conns, conn_gene.key_width) int32` — `(in_key, out_key)` plus `historical_marker` when the conn gene declares it; `I_INF` marks an absent row.
- `conn_attrs (P, max_conns, conn_gene.attr_width) float32` — e.g. `weight`; absent rows are NaN.
`fixed_attrs` (key columns) stay integers and `custom_attrs` stay floats: there is **no bitcast** float↔int in evoxc, so a mixed-dtype row is impossible and the operators twiddle integer `*_keys` while only `*_attrs` does float arithmetic.
`attr_width == 0` is supported (HyperNEAT/CPPN): every attr helper is width-aware (`gene/base.py::has_attr`, `column_of(..., default)`, `blocks.*` early-return), a `(P, E, 0)` array flows through `execute_mutation`/`execute_crossover` unchanged, and the distance kernels return the structural term with an attribute distance of 0.
Key/row invariant: `initialize` writes nodes in key order, so input keys are rows `0..num_inputs-1` and output keys are rows `max_nodes-num_outputs..max_nodes-1`, rows that are never deleted or moved.
That layout is this genome's *template*, never the read-out rule: the schedule resolves the output keys to slots (`Transformed.output_slot`) and the forward reads those, so a payload ordered inputs, outputs, hidden (a substrate executor) is read correctly, while `get_input_idx()`/`get_output_idx()` describe only the template rows.
Hidden node keys are arbitrary and may move rows; always compare keys, never row positions, for graph identity, and never mix sentinels: `I_INF` (`int32` max) for "no index", float NaN for "no value" and for "unconnected node value".
## Genome API (batch-first, population on axis 0)
`BaseGenome` holds the host-side configuration (plus `output_transform`/`input_transform`/`init_hidden_layers`) and the gene/operator objects; nothing on the compute path reads `State`.
`key_span` (`S`, default `max(max_nodes, num_inputs + num_outputs) + max_conns`) bounds every node key and is part of the Pipeline's shape signature; a key outside `[0, S)` is *silently unmatched* by the schedule's dense key table (the edge or node becomes invisible without setting `edge_overflow`, which only reports in-degree > `K`) — this node's one silent-failure mode.
`algorithm/neat/_keys.py::node_keys_for_split` keeps every structural key inside that window (a per-individual spread wrapped into `[max_nodes, key_span)`, with `first_free_keys` as collision fallback) and `validate_key_space` rejects `key_span <= max_nodes` at `NEAT` construction, so the silent-drop path is reachable only from an out-of-band caller.
Raising `key_span` from 150 to 2000 turns the 2-input `examples/func_fit/xor.py` from a flat `-0.25` (constant-0.5 read-out) into `-0.006` at generation 40, 2-input only: XOR3d stays at `-0.25` with `key_span=4000` at pop 100 and pop 500, so widening the table is not the XOR3d lever.
`DefaultGenome` carries **no** mutation-rate knobs — its `__init__` takes the five statics plus `node_gene`/`conn_gene`/`mutation`/`crossover`/`distance`/`output_transform`/`input_transform`/`init_hidden_layers`/`max_in_degree`/`max_depth=16`/`key_span`, and each `None` builds a fresh default gene/operator per instance — so the structural probabilities live on the `mutation` operator: `DefaultMutation`'s constructor defaults stay NEAT-python's `(conn_add=0.2, conn_delete=0.2, node_add=0.1, node_delete=0.1)`, while `DefaultGenome`/`RecurrentGenome` build `(0.1, 0.1, 0.4, 0.05)` when `mutation is None`.
The value rates live on each gene's `attr_specs` (`DefaultConn` 0.8 mutate / 0.15 power / 0.1 replace; `DefaultNode` bias and response 0.2 / 0.15 / 0.015 within ±5, aggregation and activation replace 0.1); no enabled/disable knob exists, and the statics are plain instance attributes with no property accessors.
`S` is a *schedule* bound only, so homologue identity never derives a packing radix from it (`operations/alignment.py`/`operations/distance/digest.py` fold keys in base `2**31`, injective for the whole `int32` range) and homology is exact for keys far outside `[0, S)`.
The shared window step is `step.NodeStepMixin`'s `_hit_conn_attrs` + `_node_step` + `_output_values`, composed into `BaseGenome` as a mixin before `BaseGenomeHost`; every kernel accepts both the `GenomeTensors` payload and the positional four-array spelling, and `node_exists`/`conn_exists`/`max_node_key`/`max_conn_marker` are the thin in-graph helpers `algorithm/` calls.
The read-out derives its `step._ReadOut` (gather index, `present` mask, rank-0 `NaN` fill, `(rows, max_nodes)` geometry) once per pass, so a repeated query pays `reshape` + `gather` + `select` instead of an eleven-op derivation (`cartpole_p100` 33 270 → 31 081 executed ops), and a prepared record whose geometry disagrees with `values` raises `TensorNEATError`; `_output_row_mask` derives the `(P, N)` output mask from `output_slot` with one static `(1, N)` `arange` broadcast-compared per output column and folded with `logical_or`.
- `initialize(state, key, pop_size) -> GenomeTensors` — `key` is a rank-0 `evoxc.random` key and randomness is drawn once per tensor with the batched output shape, so individual `i` gets an independent stream from one call.
- `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed` — schedule derivation delegated to `../common/tensorization.py`; pure tensor ops, no host round-trip.
  The keyword-only key overrides pin which keys the schedule treats as inputs and outputs (how one genome derives a substrate executor's `inputs, outputs, hidden` schedule); `input_keys` must equal this genome's own `input_idx`, while a host `output_keys` may be any `num_outputs`-long integer sequence.
  The payload contract is checked first (`node_keys (P, max_nodes)`, `conn_keys (P, max_conns, key_width)`, agreeing leading dimensions, each attribute array leading with `node_keys.shape[0]`): a violation raises `TensorNEATError`, a rank-1 `node_keys` or rank-2 `conn_keys` is reported as a per-individual row that needs a leading population axis, and the check reads `.shape` only, so it traces no op and never compares against `self.max_nodes`/`self.max_conns`.
- `forward(...) -> (P, num_outputs)` — trace-time kernel; `inputs` may carry any batch (`P·Q` substrate queries), verified equal to `Q` independent `P`-sized passes for both genomes.
- `prepare_pass(..., samples=1)` and `forward_prepared(state, transformed, prepared, inputs) -> (P, num_outputs)` — the same pass split into its loop-invariant operands (`_PreparedPass`: padding-safe `node_attrs`, `_StepStatics` with its node operands forced, the depth bound / expanded `node_level`, or the recurrent expanded `update_mask`) and its per-query half; `forward` is exactly prepare + forward_prepared, `samples` must be a positive int, and an `inputs` batch that is not `pop_size * samples` raises `TensorNEATError`.
- `grad(state, transformed, node_*, conn_*, inputs, loss_fn) -> evoxc.Graph` — **graph factory** (like `evoxc.grad`), not a trace-time kernel: it traces its own graph and returns it for the caller to cache/compile/run, and its body is `grad.build_grad(self, ...)`.
- `execute_mutation(state, key, genome, new_node_keys (P,), new_conn_keys (P,3)) -> GenomeTensors`, `execute_crossover(state, key, genome1, genome2) -> GenomeTensors`, `execute_distance(state, genome1, genome2) -> (P,)` (pairwise, batched over pairs; the algorithm forms the pairs).
- `prepare_distance(state, pop) -> DistanceDigest` — one digest per population genome, computed **once per generation** (packed sorted key rows, attribute rows permuted into that order, gene counts and every per-call static); `measure_distance(state, centre, digest) -> (P,)` measures one centre against the whole population with no re-sort and is **bit-identical** to `execute_distance`.
  A **batch-1** centre can take the dense key-table route, which addresses only keys inside `[0, key_span)`; `distance/base.py::measure` validates that precondition on host-resident data and raises `TensorNEATError` naming the key space and the remedies, while a traced digest is skipped because a value may not drive a traced raise — the pipeline stays on the merge route because `algorithm/neat/_kernels.py::single_payload` tiles the centre to `pop_size` rows, which is exact for any key.
- Host-only (NumPy in, Python out, never traced): `network_dict`, `sympy_func`, `visualize`, `repr`, `hash`, `grad_from_payload`, `get_input_idx`, `get_output_idx` — the non-`sympy_func`/`visualize` ones live in `host.py::BaseGenomeHost`, and `_split_payload` (`base.py`) enforces batch-first for every compute entry point.
  `network_dict` and `repr` take **one** individual, normalised by `host.py::BaseGenomeHost._one_individual_payload`: the `(1, …)` batch `Pipeline.auto_run` returns or the bare per-individual rows a checkpoint stores, refusing `None`, a non-four-field payload, a `P > 1` batch (with the slice recipe `GenomeTensors(*(a[i:i+1] for a in payload))`; there is no `payload.of(i)`) and fields that disagree about the spelling.
- `hash` is **host-only numpy** (`(P,) np.uint32`), the xor-fold of `common.tools.hash_rows` over each gene family's key rows and its quantised attribute rows (`rint(attrs * HASH_QUANT_SCALE)`, NaN → `0`), folded across rows so padding on other rows hashes equal; it emits no evoxc op and therefore no unsigned dtype, a payload of `SymbolicTensor`s is refused with a `TensorNEATError`, and `HASH_QUANT_SCALE` (1e6) wraps past `|attr| ≈ 2147.48`, so the digest is a heuristic de-duplication key, never an identity test.
`GenomeTensors` is a namedtuple-like pytree of exactly the four payload arrays, always taken and returned by field.
Structural mutation keys (`new_node_keys`, `new_conn_keys`) are **allocated by the caller** (globally unique across the population) and passed in as int32 tensors — not RNG draws; `_check_key_shapes` (`base.py`) refuses any other dtype with a `TensorNEATError` naming the tensor and the required `int32` (a cast would be a traced op for a host-side contract violation).
## Execution schedule (`Transformed`, owned by `../common/tensorization.py`)
Per-population, batch-first, static shapes; the field table and the read-out authority live in `../tensorneat/CONTEXT.md` `## Kernel Contract`, and the field names are a binding contract.
This node reads `in_src`/`in_conn`/`in_valid (P, max_nodes, K)`, `node_level`/`node_exists`, `output_slot` and `edge_overflow`, and three details of that contract are load-bearing here: `in_src` is a flat index into `reshape(values, (P*max_nodes,))` and `in_conn` into `reshape(conn_attrs, (P*max_conns,))`; `node_level` is the depth from an input node (inputs 0, `I_INF` on absent rows, zeros in the recurrent variant); and window slots are filled in increasing connection-row order, so a node's window ordering is canonical and stable across runs.
`K`, `max_nodes` and `max_conns` are Python-int statics, and `edge_overflow (P,)` counts the connections that did not fit `K`.
### Schedule formulation (`transform` statics)
`BaseGenome.transform` passes the **derived** `acyclic` static (`self.network_type == "feedforward"`) as the 11th positional static of `common.tensorization.derive_schedule.fn` and `common.schedule_accelerator.kernel_mode(state)` as the trailing 12th static, never a constructor kwarg.
`kernel_mode` owns the vocabulary: `"host"` (the default, what `state=None` and a state without the entry resolve to) traces the dense key→slot table and the entry-order inversion, `"accelerator"` traces the scatter-free key resolution and in-degree count, and any other value raises `TensorNEATError`.
Both spellings return the same `Transformed` on every payload comparison tried (genomes `DefaultGenome`/`RecurrentGenome`/`BiasNode`/`OriginConn`, pops 100/500/1000, `max_in_degree` ∈ {own, 2, 1}, with and without `edge_overflow > 0`).
`Pipeline.setup` registers the device-derived value, the entry is part of the executable-cache formulation signature `(distance_centre, distance_formulation, kernel_mode)`, and `base.py::transform` is its only genome-side reader, so a mode change rebuilds exactly once.
With `acyclic=True` the cycle-detection relaxation, its in-graph test and the `evoxc.cond` fallback are not traced at all (280 traced `transform` ops); `RecurrentGenome` keeps `False` and its `level == I_INF`-on-a-cycle contract, so a *cyclic* payload handed to a feedforward genome gets levels saturated at `max_nodes` and the loop clamps to `max_depth`.
## Formulation seams (host | accelerator)
`common.schedule_accelerator.kernel_mode` is the one vocabulary reader for `kernel_mode`; `distance/index_free.py` reads the same entry for `distance_formulation` and `distance/grouped.py::group_size` for the grouped centre width, so every seam is a static host branch and no traced value drives a formulation switch.
### Homologue alignment (`kernel_mode`)
`operations/alignment.py` is the host **packed-identity merge** shared with distance: each key row becomes an injective `int64` identity (two 31-bit folds plus a 2-bit parent tag so an *unstable* `argsort` is correct), the parents' identities are concatenated and sorted once, and a row is a homologue when its successor in sorted order carries its identity with the other parent's tag (a third `historical_marker` column is confirmed exactly).
Crossover inverts the permutation with one **encoded `int32` `sort`** (`alignment._successor_ranks`, 0.05 + 0.12 ms at pop 500) instead of two `scatter`s (0.42 ms), and `alignment.homologous_pair` returns `(rows, present)` from that one merge, so the "has a homologue" mask costs no extra `not_equal`/`select`.
`operations/alignment_accelerator.py` is the accelerator **comparison table**: `identity1 | tag` compared against `identity2` in one `(P, M, M)` broadcast `equal`, `col = reduce_min(select(table, arange(M), M), axes=2)` as the leftmost matching parent-2 row, `found = col < M`, then the merge's own `_confirm_rows` (a key wider than two columns) and padding term — no sort, no permutation, no scatter.
`find_homologous(keys1, keys2, *, state=None)` and `homologous_pair(keys1, keys2, *, state=None)` both delegate to `alignment._homologous`, which branches **once** on `alignment_accelerator.selected(state)`, so a graph holds exactly one formulation; `crossover/base.py::__call__` and `crossover/default.py` forward their `state`, but the pair-wise route `DefaultDistance.gene_distance` passes none and so stays on the host formulation.
The host spelling is the default because the comparison table is element volume the numpy interpreter pays in full: node family `(500, 50, K=1)` host 46 ops / 2.05 ms against accelerator 29 ops / 2.96 ms, conn family `(500, 100, K=2)` host 60 / 4.66 against accelerator 43 / 8.97 (P=1000: 60 / 3.70 against 43 / 20.57).
On a compiled device the trade reverses: the table removes the two bitonic alignment sorts (`sort_500x200xi32`/`sort_500x100xi32`, 2.03 + 0.28 ms of device time, one workgroup per row) and fuses each family's table into one `linalg.generic` reduction dispatch.
### Cycle predicate (`kernel_mode`)
`operations/mutation/cycle.py::closes_cycle(state, node_keys, conn_keys, src_keys, dst_keys, key_span)` is the acyclicity veto the add-conn stage calls: a cycle is closed exactly when `src` is reachable from `dst` in the existing graph, so the predicate seeds a frontier at `dst` and grows it until it stops growing.
The host body `cycle.py::_closes_cycle_host` resolves keys through a dense `key → row` table (one flat rank-1 `scatter` per call) and writes each hop into a flat `(P*(N+1),)` frontier with one `scatter`.
`operations/mutation/cycle_accelerator.py::closes_cycle_accelerator` resolves keys with an equality template (one broadcast `equal` against the node row axis, then the lowest matching row via `reduce_min(select(match, arange(N), N), axes=2)`) and carries a scatter-free `(P, N+1) bool` reached set marked by a broadcast reduction, its growth flag packed as the last column.
`cycle_accelerator.kernel_mode`/`selected` read the same `state.kernel_mode` entry with the same `"host"` default and `TensorNEATError` on anything else, and `closes_cycle` is one static host branch on it; `cycle.py::_in_span` is the shared window law both routes use, so an `I_INF`/out-of-span node row and an out-of-span query are masked identically.
Both bodies trace 81 ops, the host body carrying 2 scatters and the accelerator body none: measured per warmed call at `xor_p500` the accelerator body is **0.173** ms at pop 500 against the host body's **2.859** ms (0.282 against 1.425 at pop 1000), while on numpy the accelerator route is the slower one (isolated predicate 20.84 against 4.86 ms), which is why it exists only for a compiled device.
A `RecurrentMutation` with `p_recur == 0` never traces the predicate; the feedforward path keeps it because an added connection there can close a cycle.
### Distance formulations (`distance_formulation`, `distance_centre`, grouped)
`operations/distance/` ships four spellings of the same arithmetic, all `tobytes()`-identical on contract-conforming payloads (unique key rows) and all gated by a static host read:
- **merge** (`default.py`/`base.py` + `digest.py`) — the host default: sort-based successor test over the packed identities, 93 traced ops per `measure` call.
- **index_free** (`index_free.py`) — the accelerator homologue resolution, selected by `state.distance_formulation == "index_free"` (default `"merge"`, anything else `TensorNEATError`): one `(P, M, M)` `equal` plus `select`/`reduce_min`/gather/reduce, no sort and no scatter, 84 traced ops, ≈18.8 M element touches per call against the merge route's ≈405 M on the device, at 2.1–2.6× the numpy wall clock.
- **dense** (`dense.py`) — the batch-1-centre key-table route, enabled by `DefaultDistance(dense_single_centre=True)`: 108 traced ops and 2.2–2.4× faster in wall than the tiled merge, and it cannot address a key outside `[0, key_span)`.
- **grouped** (`grouped.py`) — the k-centre form: `group_digest(digest, k)` tiles the digest and one `measure` call covers `k * P` centre rows with the plain merge body, whose 93 traced ops are independent of `k`; `group_size` answers `k = 2` only for a GPU-class `kernel_mode` (`ACCELERATOR_GROUP`/`GROUP_ROW_BUDGET`) and `k = 1` everywhere else, so the numpy leg is byte-for-byte the ungrouped path.
`grouped.group_size`/`for_state`/`centre_batch` are the host-side seam of that form, and `algorithm/neat/_distance.py::DistanceRows.matrix` is its one caller (the accelerator leg only), gathering `k` centre rows per scan iteration and keeping the body result rank 1 because a rank-3 axis-0 `scatter` fails the StableHLO v1 export.
`distance_centre` (`"tiled"`/`"single"`) names the centre batch width the speciation pass hands `measure`; only `measure` reads `distance_formulation`, while the pairwise route and the digest construction stay on the host merge.
## Cost law (measured, numpy reference backend)
Two rules govern every kernel here, both measured rather than assumed.
1. **An ordinary traced op pays ≈13 µs of interpreter dispatch plus its own array traffic** (`benchmarks/PERF_NUMPY.md` attributes ~58–63 % of a generation to that fixed per-op cost), so op count is the budget for elementwise/gather/select/reshape work while element volume decides the wide passes and the innermost-axis reduces of rule 2.
2. **An innermost-axis reduction over a `(P, N, K)` tensor is 10–20× an ordinary op and does scale with elements**: `np.max((1000,50,4) int32, axis=2)` = 1.00 ms (bool 0.74 ms) against 0.093 ms with the window on axis 1 and 0.167 ms for an unrolled `maximum`/`logical_or` fold of the 4 slices; `np.sum` = 1.50 ms against 1.06 ms for the slice-add fold (6.37 vs 3.49 ms at the tiled `4P=4000` batch).
Hence `window.any_slot` (`K` slices + `K-1` logical ops, `_WINDOW_FOLD_LIMIT = 8`) replaces `reduce_max(mask, -1)` wherever "any live slot" is asked — more traced ops, far less time.
A third, layout rule matters for the mutation slabs: for `(P, tries, E)` blocks the *contiguous innermost* axis is the cheap one (`axes=2` 0.82 ms vs transposed 1.65 ms), the opposite of the `(P, N, K)` window case; `gene/CONTEXT.md` holds the column-read measurements.
## Forward algebra (feedforward)
`values (P, max_nodes) float32`, all NaN except the input rows, which hold `input_transform(inputs)`.
Step 0 (both genomes): `node_attrs = self._padding_safe_attrs(node_attrs, node_keys)` replaces the attrs of **absent** rows with `0` via `select`, so the option-index columns (`activation`, `aggregation`) never reach the int cast as NaN; a NaN *value* column of a live row is untouched, so real corruption still poisons.
Step 1: `hit_conn_attrs = self._hit_conn_attrs(transformed, conn_attrs, samples)` once (attributes are constant during a pass); the value-window gather index it builds is **block-shaped** `(rows, N, K)` — the schedule's `P` rows, or the tiled `P·S` rows when a problem tiles a dataset — so `evoxc.gather` splices it directly.
Step 2: one `evoxc.while_loop` over levels, `_depth_limit(transformed)` = `min(max_depth, max over existing rows of node_level, 1)` — `node_level` is `I_INF` on absent/unreachable/cyclic rows so it is masked and clamped first.
Loop body (`level` carried, starts at 1) is one `_node_step` with `update_mask = node_level == level` (the schedule's `I_INF` padding already excludes absent rows, so no `node_exists` term):
1. `xv = _gather_prepared(values, flat_index)` — one flatten, one flat gather, **no fill**: a statically dead slot is clamped to an in-range row by `window._slot_index` and keeps that row's value.
2. `live = present & (xv == xv)` — two narrow ops; IEEE makes `x == x` False exactly on NaN, so this catches a live slot whose source row is still NaN while `present` excludes the dead slots.
3. `msg = conn_gene.forward(statics.conn, xv)` — one `multiply` by the weight column; dead slots are neutral-filled by the aggregation before any reduce, and live slots pass through exactly.
4. `z = node_gene.forward(...)`: per-option aggregation over masks precomputed in `NodeOperands`, `combine` (`bias + response * agg`), then the activation — id `-1` (identity) on output rows, because the final activation belongs to `output_transform`.
5. `update = update_mask & any_slot(live)`; `values = select(update, z, values)` — a node with no live incoming edge keeps NaN and its descendants lose their only live source: the legacy NaN poisoning, reproduced exactly.
Read out via `_output_values`: one flat gather at `transformed.output_slot` (clamped) with `NaN` for an `I_INF` slot, then `output_transform`; cost is `O((depth+1) × max_nodes × K)` with only elementwise/reduce/gather ops, so work scales with real depth and real in-degree, never `max_depth` and never `max_nodes²`.
**Graph shape**: 67 entry ops + a **30-op level body** + a 1-op condition = **98 traced ops**, independent of `P`; the body runs `depth+1` times — measured **4 / 2 / 3** trips on the populations after 8 generations at P=100/500/1000 and **3 / 3 / 3** at generation 5.
**What is hoisted where** (the rule a future agent must follow): everything independent of the loop-carried `values`/`level` is derived **once per pass** in `_hit_conn_attrs`/`NodeOperands` — the conn-attribute gather, the value-window flat index (`minimum` clamp + `add` row offsets + `reshape`), the `present`/output-row masks, the option masks and the rank-0 `node_gene.prepare` builds — so a level pays only value-dependent work: `reshape` + `gather`, `equal` + `logical_and`, `multiply`, the aggregation, `combine`, the activation, `any_slot`, the update `select` and `level + 1`.
**Nothing wide may be computed per level unless a consumer reads it**: a dead-slot NaN fill after the value gather would be one `(P, N, K)` `select` per trip for values no consumer reads, because the aggregation neutral-fills every slot of `live` before reducing; the narrow `logical_and` is bit-identical.
**Read set of one pass**: `in_conn`/`in_src`/`in_valid`, `output_slot` (`_hit_conn_attrs` derives the output-row mask from it, `_output_values` reads it out), `node_level`/`node_exists` (`default.py::_depth_limit`), `node_keys` only in `_padding_safe_attrs`, `node_attrs` once as one wide `select` plus per-column views, `conn_attrs` once in the `_hit_conn_attrs` gather, and **`conn_keys` never** (an accepted-but-unused `forward` parameter); `src`, `dst`, `edge_valid`, `topo_key`, `input_slot` and `edge_overflow` are never read, because the pass seeds the inputs into the invariant rows `0..I-1` and resolves the outputs through the schedule.
## Forward algebra (recurrent)
Same window machinery, no levels: unroll `activate_time` ticks in **Python** (the recurrent path keeps its tick loop; the level `while_loop` is feedforward-only).
Each tick re-injects `input_transform`-free inputs into the input rows, computes every node from the previous tick's values (Jacobi/synchronous), then `values = select(node_exists & any_slot(in_valid), z, values)` — `any_slot` rather than a `count > 0`, which would be an innermost-axis `reduce_sum` per tick for a predicate that is a boolean *any*.
`sympy_func`/`visualize` are documented refusals (`TensorNEATError`: a cyclic network has no finite closed form and the layered layout assumes a depth-ordered DAG, pointing at `network_dict()` / `DefaultGenome`).
## Gradient algebra
`grad` never differentiates the plain forward, so the forward's `while_loop` region and the schedule's `argsort`/`sort` never meet reverse-mode; three evoxc rules shape it: `evoxc.grad` requires a **single scalar output** (the loss is scalarized as `sum(loss_fn(outputs))`, and per-individual gradients are unaffected because the population axis is independent), only float inputs are differentiable (`node_attrs`/`conn_attrs`; keys and the schedule are non-differentiated ints, and an int32 *differentiated* argument is a hard `TransformError`), and `sort`/`argsort` have no AD rule, so the schedule must be derived outside the differentiated graph.
Attribute gradients are masked at the graph input (`select(exists & ~isnan(a), a, 0)`), so padding rows gradient to exactly `0`.
`grad` therefore differentiates a mathematically identical **dense** pass built beside the plain one in `grad.py`, because evoxc 0.1.0's `gather` VJP has put semantics (`## Known Issues`) and the window step's fan-out gathers under-accumulate: a per-individual `W (P, N, N)` weight matrix scattered from the conn-gene `weight` column (unique `(dst, src)` cells, `0` elsewhere), `agg = dot(W, xs)` per level, and the live-slot gate `live_count = dot(live_matrix, ~isnan(values))` — `dot`'s VJP is exact, so the gradients are the gradients of the plain forward (sum aggregation is `dot`, mean is the same `dot` divided by `maximum(live_count, 1)`; values agree with `BaseGenome.forward` to 1e-6).
The plan (`W` cells, live matrix, level masks, and the read-out statics `output_slot`/`output_present`/`output_rows`) is host-computed once per graph in `grad.dense_grad_plan`.
The dense read-out is a **static mask-and-reduce**, never a gather: for each output column `j` it compares one `(1, N)` `arange` constant with the baked `output_slot[:, j:j+1]`, neutral-fills the non-output rows of `values` with `select` (never a `multiply`, so a `NaN` on a non-output row cannot poison the sum while a `NaN` output row still reads `NaN`), sums the row axis, concatenates the `O` columns and writes `NaN` where `output_present` is false.
It reads exactly `values[p, output_slot[p, column]]`, bit-identical to `step.py::_output_values` (`NaN` for an `I_INF` slot included), and needs neither the `NaN`-cleaned copy nor the second gather a gather read-out would (its VJP scatters into `multiply(x, 0)`); `dense_grad_plan` refuses a schedule whose `output_slot` names no output column (`ConfigError`), because a zero-width read-out has nothing to differentiate.
## Mutation algebra
`execute_mutation` is a batched *plan → apply* kernel run **once per operation**: `_edit_context` builds the masks and flat index blocks for the payload that stage receives, the operation (`add_node`, `delete_node`, `add_conn`, `delete_conn`) resolves its candidates into a namedtuple plan (`mutation/plan.py`), and `plan.apply` writes it.
The four stages compose sequentially in legacy order add-node → delete-node → add-conn → delete-conn, each planning against the payload the previous stage produced, so a later operation sees the earlier one's writes.
Each operation is gated by its **own** `(P,) bool` from one shared `(4, P)` `evoxc.random.uniform` draw (`drawn[i] < structural_probabilities[i]`), so one individual can receive up to four structural changes per call — at most one per operation; a probability of `0` keeps that operation's whole chain (including the cycle predicate) out of the graph.
Refusals are bit-exact no-ops: duplicate connection, self-connection, a cycle, an add-node whose allocated key already exists or whose split destination is already at `max_in_degree`, and capacity exhaustion.
Value mutation is one gate/`select`/`clip` cascade over the whole `(*shape, A)` attribute block (`gene/blocks.py`), with the draws kept per column because a `(…, A)`-wide `evoxc.random` draw costs ~9× a one-column draw.
The four-stage composition executes **536 traced ops** at pop 500 (`DefaultMutation`) and measures 18.3 ms per call there; `mutation/degree.py` exports `in_degree`/`max_in_degree`/`violation` as a public standalone audit with no caller in `src/`, because `execute_mutation` enforces `max_in_degree` inline.
Gate multiplicity over 20 000 individual-mutations at `(0.1, 0.1, 0.2, 0.2)` is 0/1/2/3/4 firing operations = 51.16/38.01/9.74/1.05/0.045 %, and the shipped genome pair `(0.1, 0.1, 0.4, 0.05)` raises P(any) from 0.4816 to 0.5383 at an unchanged P(>=2) of ~0.104; `./operations/mutation/CONTEXT.md` holds the histograms, the refusal split, the per-stage op ledger, the search-quality arm and every rejected alternative.
## Crossover algebra
`BaseCrossover.__call__` takes parent 1's structure (`node_keys`/`conn_keys`) verbatim and recombines only float attributes; argument order `(genome1, genome2)` = `(winner, loser)` is order-sensitive.
Per-gene attribute inheritance is one `U[0,1)` block draw + `< 0.5` + `select` (`gene/blocks.py::crossover_attrs`), the per-entry Bernoulli(0.5) in 13 traced ops, and the alignment primitive is `homologous_pair` via `align_gene_rows` (`## Formulation seams`).
The precondition is unique first two key columns within a parent (guaranteed by `initialize` and `execute_mutation`'s duplicate refusal): homology is by key tuple, never row position; `execute_crossover` traces 142 ops and measures 5.3–5.4 ms at pop 500 / 10.2–10.3 ms at pop 1000 (`./operations/crossover/CONTEXT.md` holds its op ledger and rejected diets).
## Distance algebra
`execute_distance` (pairwise), `prepare_distance` and `measure_distance` share the host merge: the digest concatenates the population's packed identities **first**, so a population gene's merged index *is* its digest row and the successor test needs no side tag; `stable=True` lets the reference interpreter's timsort detect the digest half's ascending run.
`distance/consts.py` threads one `ConstantPool` through the graph (evoxc never dedupes rank-0 constants, each costs one op), the attribute term is a reduced sum over the aligned rows, and `measure_distance` is bit-identical to `execute_distance` on every pair and on all ten `SpeciesState` leaves of every generation.
The four spellings and their selectors are in `## Formulation seams`; `./operations/distance/CONTEXT.md` holds the per-call op ledger, the per-route timings and every rejected diet.
## Static invariants (performance knobs, never silent)
- `max_in_degree` (`K`, default `max(initial in-degree, 4)`): enforced by `execute_mutation` at the *written* payload state — an added connection or an add-node split that would push any destination past `K` is refused; soaked over ≈12 700 generations across 20 seeds and two `max_nodes` settings with zero violations.
- `max_depth` (`D`, default 16) is a **ceiling on the while-loop trip count**, not a cost multiplier: a node deeper than `D` is never visited and keeps its `NaN` value, and depth truncation is silent — it does **not** set `Transformed.overflow` (only the dropped-connection count does), so the host must rebuild with a larger `D` on its own.
- `activate_time` (default 10) is the recurrent tick count.
- `key_span` (`S`): see the API section — a key outside `[0, S)` is dropped **silently** by the schedule, the one invariant the genome cannot enforce for its caller.
`Transformed.overflow` is the only host-visible diagnostic; nothing inside this node silently drops a connection or a node.
## Constraints
- No `jax`/`torch` import anywhere in this node; all tensor math is evoxc ops (`enp`, `evoxc.gather/scatter/select/slice/reduce_*/dot`, `evoxc.random`), and no eager NumPy sits on the compute path — the host helpers convert with `Tensor.numpy()` and never feed results back into a graph.
- Every kernel is already batched: no per-individual Python loop and no `vmap`/`vectorize` over these kernels.
- The region ops in this node are the feedforward forward's level `while_loop` (default.py), the mutation cycle predicate's `while_loop` (both formulations) and the mutation add-conn attempt loop; none may be differentiated (`grad.py` owns the differentiable path), and loop-invariant work belongs in `_StepStatics`/`_hit_conn_attrs`/`_edit_context`.
- Shapes are static at trace time: `pop_size`, `max_nodes`, `max_conns`, `K`, `D` are Python ints; a change forces a rebuild (the Pipeline caches per shape signature).
- Integer arithmetic: an `int32` tensor plus a Python literal promotes to `int64` in evoxc, so index math stays in int32 tensors, and every sentinel/level index is a **rank-0** constant (`window._iinf`, `enp.full((), ...)`) — a full-size `I_INF` is a large graph constant plus an extra op per use.
- Graph-op axes are non-negative static integers (e.g. `concatenate(..., axis=len(shape))`, never `axis=-1`), because the StableHLO exporter forwards the axis verbatim as `dimension` and rejects the negative form at compile time.
- Errors: configuration violations raise `../common/errors.TensorNEATError` (and `ConfigError`/`ShapeBoundError`); tensor/backend errors from evoxc propagate unchanged — never caught and re-wrapped.
- Shared machinery (one window-reduce node step) lives in `step.py::NodeStepMixin` and is parameterized by the update mask, never duplicated between `default.py` and `recurrent.py`.
- File sizes stay under ~1000 lines and each file is one job: `base.py` (1005) is the node's only file above that guideline, `operations/distance/base.py` (1000) sits exactly on it, and the rest run down from `operations/distance/digest.py` (953) to `operations/alignment_accelerator.py` (221); the Routing Table states each file's responsibility.

## Compiled-device dispatch structure (level loop body, ROCm/gfx942)
Counting recipe: build with `backend="iree"` and `device=None` (llvm-cpu load), take the target-independent text at `pipe._executable_for(state).backend_executable.artifact.payload["mlir_text"]`, run `iree-compile --iree-input-type=stablehlo --iree-hal-target-backends=rocm --iree-rocm-target=gfx942 --compile-to=executable-configurations`, and count `stream.cmd.dispatch` per block of `util.func public @main` (the counts are device-independent for the rocm target).
`iree-compile --compile-to=executable-configurations` (IREE 3.13) on the `cartpole_p100` graph puts the level loop in one self-branching stream block of **4 dispatches per trip in the `kernel_mode="host"` formulation and 5 in the `"accelerator"` one** (identical for `pendulum_p100`, `mountaincar_p100` and `xor_p500`; the `speciate` scan block in the same function is 8): one two-result `linalg.generic` over `(d0,d1,d2)` holding `gather` + `x == x` + `and(present,·)` + `multiply(weight)` + neutral `select` (the whole gather/mask/window-fill chain fuses), a second `linalg.generic` over `(d0,d1,d2)` holding the K-fold `add`, the option-mask `select`, `combine`, the activation and the final `select(update, z, values)`, then two rank-0 `workgroup_size = [1,1,1]` dispatches holding `level + 1` (the loop-carried counter) and `level < depth` (the `while` condition).
The first boundary is a `tensor.extract_slice` with a constant K offset: the consumer reads the producer's `(P,N,K)` result through four `(1,1,1)`-offset views, and `ElementwiseOpFusion` fuses identity/projected-permutation maps only, so the two tensors stay in separate regions; the second boundary is `FormScalarDispatches` isolating each rank-0 compute into a 0-d `linalg.generic`, with a `compute_barrier.end` on the carried counter that blocks the condition from joining it.
Measured on that graph (whole-`@main` dispatch total in parentheses): rewriting the K-sum or the `any_slot` fold as `stablehlo.reduce` gives **6** per trip (433), both gives **11** (437), a K-axis split built by slicing the K-wide operands gives **6** (433) because each sliced chain becomes its own region, `--iree-dispatch-creation-fuse-multi-use` leaves **4**, and `--iree-dispatch-creation-enable-aggressive-fusion` leaves **4** while the graph total falls 430 → 352.
So no op reordering inside `_node_step` reaches 2 per trip: the emitted shape's floor is 4, 3 needs the window operands materialised as `K` separate `(P,N)` tensors (no constant-offset slice between producer and consumer), and 2 additionally needs the counter gone — a carried `settled (P,N) i1` frontier (`ready = present & ¬settled & all existing sources settled`, `update = ready & any_slot(live)`, `settled' = settled | ready`, condition `any(ready)`) replaces both the counter and the `(P,N)` `node_level == level` broadcast with one elementwise forward plus one rank-0 reduce.
The per-query prelude is 3 dispatches: a strided copy of the input block into `values[:, :I]`, a copy of a constant NaN block into `values[:, I:]`, and the loop-entry rank-0 condition; seeding `values` with one column-index `select` generic instead of two copies removes one of the three.

## Deviations from the pre-rewrite library (intentional)
- `activation == -1` means **identity** everywhere; the legacy `lax.switch(-1, ...)` clamped to the last option, so `BiasNode` split nodes silently used the wrong activation.
- Activation/aggregation options are evaluated for **all** configured options and selected with `select`, over masks precomputed once per pass in `NodeOperands` (`option_masks`/`select_cascade`); a non-total option (division by zero, `log/sqrt` of a possibly negative value) can therefore poison gradients even where it is not selected.
- Random draws differ from the JAX build by construction (`evoxc.random` vs `jax.random`), so parity with `benchmarks/legacy_jax` is asserted on kernels for given genomes (forward, grad, distance), not on RNG-dependent operator output.
- The forward's per-level `any_slot` fold changes the *order* of the `reduce_max`-equivalent for bool masks only (a pure "any", so identical); a future innermost-axis fold of a **float** reduce must check the non-numpy backends' summation order first.
- The perturb and replacement candidates of a float value column share one standard-normal sample; the gate is exclusive, so each mutated entry's marginal law is unchanged.
- `DefaultConn` mutates weights far more often than the frozen legacy gene: `weight_mutate_rate=0.8` / `weight_replace_rate=0.1` and no clip bounds here, against the legacy `0.2` / `0.015` clipped to `±5` (0.8/0.1 are NEAT-python's own defaults, so the legacy constants are the outlier) — 90.3 % of weight entries change per call against 20.7 %, at a close `|Δweight|` distribution (conditional mean 0.232 vs 0.186), so the difference is frequency, not step size.
  On evolved XOR3d populations that makes the connection-gene attribute term of `execute_distance` ~0.05–0.06 here against ~0.01–0.02 in the legacy tree, so the two trees' payloads diverge in different proportions even though the distance kernel is numerically identical.
## Known Issues / Notes for Agents
**evoxc 0.1.0 `gather` VJP has put semantics** (`evoxc/transforms/rules.py`: `g_x = scatter(zeros_like(x), idx, ct)`), so a gather with duplicate indices silently keeps one contribution instead of accumulating them; no gradient may be taken through the window formulation until evoxc ships a scatter-add, and `grad.dense_grad_plan` therefore never gathers attributes — it reads the edge list (`conn_attrs[:, :, weight]`, `conn_exists`, `in_src`, `dst`) and scatters into unique cells whose flat index carries a per-individual stride (`p * (N*N + 1)`) plus one dump cell, host-side NumPy over `Transformed` only.
`select`'s VJP does not reduce a broadcast operand — it hands a rank-0 constant the cotangent at the *output* shape, so one shared scalar used by two `select`s of different shapes raises `ShapeError: cannot broadcast incompatible dims …`.
`_node_step`, `_hit_conn_attrs` and `_gather_prepared` remain the only plain-forward path and must keep their per-level op budget; `grad.py` serves `BaseGenome.grad` exclusively and refuses at graph-build time a non-`"feedforward"` genome, `aggregation_options` other than a single `AGG.sum`/`AGG.mean`, a conn gene without a `weight` column, duplicate `(dst, src)` pairs and edges with no incoming-window slot (`ShapeBoundError`, a `max_in_degree` rebuild signal).
Attribute gradients are masked at the graph input and cleaned at the output, so padding rows, absent rows and non-weight columns gradient to exactly `0`; the finite-difference check (`max_nodes=8`, `max_conns=12`, `key_span=64`, central differences at `h=1e-2`) leaves a worst error of **4.96e-5** (`response`) and **3.77e-5** (conn weight).
**Add-node is not output-preserving** (`gene/node/default.py::new_identity_attrs` keeps `aggregation_default`/`activation_default`; worst |Δoutput| 0.236), which matches the pre-rewrite library's split semantics, so it is behaviour, not a defect.
**Origin families are not a learning defect** (`OriginNode`/`OriginConn` inherit everything but `crossover` and the conn gene's `historical_marker`), and a flat 0.25 MSE is a config/seed attractor of the search: the same task with `init_hidden_layers=(4,)` converges to 0.0031 MSE at generation 100.
**Compatibility distance matches the frozen implementation exactly**: `execute_distance` agrees with `tensorneat_legacy`'s `DefaultDistance` to `max |Δ| 2.4e-7` on all 4 950 pairs of converted XOR3d payloads, and mutation alone grows that distance identically in the two trees (median 0.90 → 1.12/1.10 after one call, → 1.82/1.75 after eight).
**Coverage gaps.** The gene value-mutation stage (`gene/blocks.py::mutate_attrs`/`init_attrs`/`crossover_attrs`) has no independent-oracle module, `operations/mutation/plan.py::apply`'s write-slot sharing is pinned only end-to-end by `test_mutation.py`, and `operations/alignment.py::_successor_ranks`'s encoded-rank inversion only through `test_crossover.py`'s behavioural tests.
No committed test selects an accelerator formulation: the four accelerator spellings and the `kernel_mode`/`distance_formulation` statics are gated by ad-hoc identity matrices and the generation-level digest gate only (`./test` is a sibling node), so a `test/backends` cell in accelerator mode is the missing regression guard.
**`grad_from_payload` is the host entry point for gradient descent through evolved topologies**: `BaseGenomeHost.grad_from_payload(state, payload, inputs, loss_fn, *, backend="numpy", device=None, compile_options=None)` derives the schedule in a one-off executable (the `pipeline._schedule_of` recipe, duplicated rather than imported), calls `grad` for the graph, then lowers/compiles/loads/runs it and returns `(node_attr_grads, conn_attr_grads)` as numpy, verified independently of `grad`'s finite-difference test (52 live entries, max |analytic − central difference| 5.91e-5, all 36 NaN padding entries exactly `0`).
`loss_fn`'s operands must be Python scalars or `evoxc`/`enp` tensors (a numpy target array raises `TypeError`) and the loss multiplies rather than `** 2`; nothing in `src/` calls `grad` or `grad_from_payload`, so a `P > 1` population gradient is a documented user recipe, the graph is re-traced per call, and the loss *value* is never returned.
**Edge cases the suite does not exercise.** `P = 0` is refused upstream (`NEAT` validates `pop_size`), but the kernels answer it with `ZeroDivisionError` in `_sample_count` (`step.py:223`) and a zero-size `reduce_max` in `_depth_limit`; both `forward_prepared`s validate the batch *rows* but never `inputs.shape[1] == num_inputs`.
**Duplication worth folding.** `default.py::prepare_pass` and `recurrent.py::prepare_pass` repeat the eight-line `samples` validation verbatim, both `forward_prepared`s repeat the same `rows == pop_size * samples` check, and `window._i32`/`utils._i32`/`operations/mutation/arrays.py` carry three byte-identical copies.
`visualize` imports `networkx`/`matplotlib` inside its body although both are hard runtime dependencies, and `sympy` is imported at module scope in `default.py:24`, so `import tensorneat` does pull the code-generation dependency.

## Tiled batch (`P·S` rows): statics are derived at `P` and expanded once
`NodeStepMixin._sample_count(inputs, pop_size)` recovers the static `S = batch // P` inside `forward` and raises `TensorNEATError` when the batch is not a positive multiple of the population, so a tiled dataset is individual-major over the population axis.
`window.by_samples(x, samples, pop_size)` expands a `P`-row tensor to the tiled rows with `reshape` + `broadcast_to` + `reshape` (one copy per operand, flat order `p * S + j`) and is the identity for `S == 1` or a tensor without the population axis, so `_hit_conn_attrs`/`_StepStatics` derive the conn gather, `present`, `output_rows` and `NodeOperands` at `P` rows and expand only the prepared leaves.
Only the flat value-window gather index is genuinely row-dependent (`evoxc.gather` is `np.take(arr, indices, axis)`): `window._slot_index(..., samples)` clamps at `P` rows, expands the clamped index and adds one baked `_row_offsets` constant — one rows-scale `int32` `add` no expansion removes.
`host_payload._prepared_query` passes the schedule and payload through unrepeated at `P` rows and only chunks (`EVAL_CHUNK_ROWS` = 12 500 tiled rows per forward), which is bit-identical because every forward op is row-local and the level loop's depth bound is a maximum a group can only under-shoot; pass 2 records `custom_pagie_p500` (`P·S = 250 000`) at **833.81 ms per generation, 1361.4 MiB peak, 1.63 s build** and the chunk budget as load-bearing (unbounded `P*S` 3282 / 3315 ms per generation against 838 / 841 ms, 4578 → 1315 MiB peak), while the XOR populations (`S = 4`) stay unchunked.

Two fold conventions circulate and both reproduce on this tree; they are not interchangeable:
- a **running single sha256** over the concatenation of every generation's five leaves — `P=500` → `bca41966d9c949cbd2e58fd0a849edd3a51d86fa761219b8d3e9f417e3e30f6e`, `P=1000` → `3e7691819d46234822451a08103992027bef812152fd74aba3f56a9c64f88c76`.
- **per-generation digests joined** (one sha256 per generation over its five leaves, the ten hex digests concatenated and hashed once) — `P=500` → `d43edd0d3c19fe8f6bb4a1001246c40faaf82bf431e95e3a12f6c9b4a3e4c96e`, `P=1000` → `caba83eeebe50e86941fb7997c184e59f4702388d0826d77401a68dcb166bd45`.
Both pin the shipped mutation law `(node_add, node_delete, conn_add, conn_delete) = (0.1, 0.1, 0.4, 0.05)`; the same protocol at `DefaultMutation`'s constructor defaults `(0.1, 0.1, 0.2, 0.2)` gives a different pair (`82f3cb…` / `763439…` under the running fold), so a mismatch with an unchanged gate law and trajectory shape is a kernel change.
Environment: Python 3.12.3, numpy 2.5.4, `evoxc` resolved by the lock from git tag `v0.1.1`; any library change moves the digests.
**StableHLO portability gate** — `evoxc.backends.stablehlo.export(module)` over the module reached as `pipe._executable_for(state).backend_executable._module` is the *static* gate: no IREE needed, and it catches every `DEFERRED_OPS`/dtype/axis/`scatter`-form violation at export time, while `pytest test/backends` (needs the `iree` extra) also catches `iree-compile` crashes a clean export cannot see, e.g. a boolean `scatter` as a `while_loop` initial value.
A hand-built graph for the export check must pass **every payload leaf as `evoxc.TensorSpec(shape, dtype)`** (the rank-0 RNG key as `evoxc.TensorSpec((), evoxc.int64)`), because a plain numpy array argument to `evoxc.build` is a static baked into the trace that exports a constant-only graph; `test/support/runner.py` builds the specs.
`RecurrentGenome` and the `grad` dense path do not share the level loop, so a change to `_node_step`/`window.py` must re-check both.
