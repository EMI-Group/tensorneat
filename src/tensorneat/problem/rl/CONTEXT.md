# rl — reinforcement-learning problems on evoxc

## Intent
Score a genome by the return of a batched episode rollout, with the environment dynamics written as evoxc ops instead of a JAX simulator.
Three environments ship: the discrete `CartPole` and the continuous classic-control tasks `Pendulum` and `MountainCarContinuous`.
Each one is the recipe for a user-defined environment: one step kernel and one `while_loop` per file, no registry and no simulator dependency.

## API Surface
- `cartpole.py: CartPole(BaseProblem)` — `__init__(max_step=500, repeat_times=1, gravity=9.8, masscart=1.0, masspole=0.1, length=0.5, force_mag=10.0, dt=0.02, x_threshold=2.4, theta_threshold=12.0, reset_scale=0.05, fitness_target=None)`; every knob is host-validated and raises `TensorNEATError`.
- `pendulum.py: Pendulum(BaseProblem)` — `__init__(max_step=200, repeat_times=1, gravity=10.0, mass=1.0, length=1.0, max_speed=8.0, max_torque=2.0, dt=0.05, fitness_target=None)`; every physics knob is strictly positive and finite, and `fitness_target > 0` raises because every reward is `-cost <= 0`.
- `mountaincar.py: MountainCarContinuous(BaseProblem)` — `__init__(max_step=999, repeat_times=1, min_position=-1.2, max_position=0.6, max_speed=0.07, goal_position=0.45, goal_velocity=0.0, power=0.0015, gravity=0.0025, fitness_target=None)`; unreachable geometry (`min_position >= max_position`, a `goal_position` outside the clipped track, `goal_velocity > max_speed`) and `fitness_target > ATTAINABLE_CEILING` (`93.0`, exported in `__all__`) raise.
- `_common.py` — the helpers all three draw from: `to_numpy`, the owner-prefixed validators `require_positive_int`/`require_finite`/`require_positive`/`require_non_negative` (messages `<Owner>: <name> must be ...`), and the three **traced** helpers `horizon_cond(consts, step_index=3)` (the fixed-horizon loop trip condition), `returns_of(total, pop_size, repeat_times)` (`(B,) -> (P, R)`) and `prepared_query(act_fn, batch)` (`act_fn.prepare` once per rollout, a genome-free callable passing through unchanged), inlined into the caller's graph like `problem.base.finalize_fitness`.
  `horizon_cond` reads `consts.horizon` at the carry's counter slot — `3` for the four-leaf carry all three share, `1` for `Pendulum`'s packed `(row, step)` carry — and is the single place the "static horizon, never 'any episode still alive'" rule lives.
  Both float validators layer on `require_finite`, so a non-numeric knob (a string, a list, `None`) and a non-finite one (`NaN`/`±inf`) both raise `TensorNEATError`, never a bare `TypeError`/`ValueError`; the module carries no dynamics, no `@evoxc.defn` and no module-scope `enp` call.
- Shapes: `CartPole` `(4,)` = `(x, x_dot, theta, theta_dot)` → `(2,)` two logits (`out[1] > out[0]` pushes right); `Pendulum` `(2,)` = `(theta, theta_dot)` → `(1,)` one torque logit; `MountainCarContinuous` `(2,)` = `(position, velocity)` → `(1,)` one action logit.
- Both continuous problems own the action squashing (`u = max_torque*tanh(logit)`, `a = tanh(logit)`), so a genome used with them leaves `output_transform` unset (identity).
- Formulation gate: `Pendulum` traces exactly one of two carries, picked on the host from the trace-time static `state.kernel_mode` (`common.schedule_accelerator.kernel_mode(state)`: `"host"` on the numpy leg, `"accelerator"` on a GPU-class device); `CartPole` and `MountainCarContinuous` consult no mode.
- `fitness_target` is validation-only: `None` skips the check, a non-finite value or one above the environment's attained ceiling (`max_step`, `0`, `93.0`) raises, and the attribute is stored as given.
- `evaluate(state, keys, act_fn, transformed) -> (P,)` maximizes fitness: the mean over `repeat_times` of the episode return, `finalize_fitness`-ed last; all three environments skip that grouping and mean at `repeat_times == 1` (a host-static branch, never a branch on a traced value), where the episode return already is the individual's fitness and the `returns_of` reshape plus the mean would be two ops on the identity.
- `show(state, key, act_fn, transformed)`: host-side, one individual, its own graph over the single rank-0 key (`evoxc.build` + `evoxc.run`) built with `**problem.base.build_options(state)`, one printed line per repeat plus the mean; an unusable backend raises rather than falling back.
- Beyond the shared `_rollout`/`_loop_body`/`_constants` skeleton and the `_common.horizon_cond` trip condition each file only adds its own step algebra and the `_terminated` rank-1 test façade.

## Algebra

### Shared shape (all three)
`B = P * repeat_times` with `P = static_batch_size(transformed)`, **individual-major**: row `p * R + r` is repeat `r` of individual `p`, so `P = 4, R = 1` and `P = 2, R = 2` draw the same four initial states from one key and produce identical per-episode returns.
Initial states come from **one** `evoxc.random.uniform` off the single rank-0 key, which is never threaded through the loop and never replaced by `np.random`; the trip count is always static (`step < horizon`), never "while any episode is alive".
That trip condition is `_common.horizon_cond(consts)` at the shared four-leaf carry's counter slot `3`, and `horizon_cond(consts, 1)` for `Pendulum`'s packed `(row, step)` carry.
The return accumulator rides in the carry and the loop emits no output, because an `evoxc.scan` would carry a `(max_step, B)` stack and scatter one row per iteration.
`returns_of` is the only place the `(P, R)` layout is assumed, and a rollout prepares its policy query once with `_common.prepared_query(act_fn, batch)`, so the genome's loop-invariant pass operands are derived once per generation.

### CartPole (`cartpole.py`)
Classic Gym `CartPole-v1` with Euler integration: `dt=0.02`, `g=9.8`, `masscart=1.0`, `masspole=0.1`, half-pole `length=0.5`, `force_mag=10`, dead when `|x| > 2.4` or `|theta| > 12deg` (`= 0.2095 rad`), reset `U(-0.05, 0.05)^4`.
One `evoxc.while_loop` over `max_step` timesteps with carry `(obs (B,4), alive (B,), total (B,), step ())`: "push right" iff `out[1] > out[0]` via `enp.split` + `enp.greater` (a tie pushes left); `total += alive` **before** the transition (the failing step still scores, as in Gym); then one fused Euler op `next_obs = obs + dt * (x_dot, xacc, theta_dot, thetaacc)`.
Death is read off that same row against a `(1, 4)` constant `(x_threshold, +inf, deg2rad(theta_threshold), +inf)`: `dead = max(greater(|next_obs|, threshold_row), axis=1)` — three ops, `abs`, a broadcast `greater` and a bool `reduce_max` — over a bracketed per-column limit whose velocity columns can never fail, and `|obs_j| > t` is exactly `|x'| > 2.4 | |theta'| > 12deg`.
The bool fold is NaN-honest on its own terms: a genuinely `NaN` observation compares false against every limit, so the row is reported alive, and a velocity column that overflowed to `+inf` compares false against its own `+inf` limit, so it can never fail.
The alternative slack spelling — `greater(reduce_max(|obs| - threshold), 0)` — reaches the same two answers only incidentally (`greater(NaN, 0)` is false, `inf - inf` is a `NaN` slack) and costs one op per timestep more, so the bool fold is the shipped form.
The state is frozen after death via `enp.where(enp.expand_dims(alive, 1), next_obs, obs)` — no `cond`, every carried dtype/shape constant across iterations — and because episodes are frozen an individual's return is its survival time, so `max_step` is the fitness ceiling and `fitness_target` must be `<= max_step`.
The alive mask is retired with **one** op, `enp.where(dead, consts.false, alive)` against the bundle's rank-0 bool `false` (`enp.zeros((), dtype=evoxc.bool_)`, the same spelling `MountainCarContinuous` uses for its terminal flag), where `logical_and(alive, logical_not(dead))` cost two.
NaN: a NaN logit acts as push-left inside the rollout (`enp.greater` is false against NaN) but `_nan_rows` (`evoxc.isnan` of the row sum, NaN being absorbing under addition) selects a NaN into `total`, so any individual whose policy ever emitted a NaN logit gets a NaN fitness → `-inf`.
**Step formulation (one, unconditional, no `kernel_mode` gate).** The row is never split into four columns nor concatenated back, because each such column costs a serialised `slow_memcpy` dispatch through the step's scratch buffer: the two angular variables come from static one-lane `evoxc.slice`es, and the derivative row is assembled by rotating the observation with the baked `(1, 0, 3, 2)` lane index (`evoxc.gather` axis 1, so lanes 0/2 receive the row's own `x_dot`/`theta_dot`) and overwriting lanes 1/3 with `xacc`/`thetaacc` via `enp.where` against two baked `(1, 4)` single-lane boolean rows.
Physics, rotation and both selections compile into one elementwise region, and since the selections only *discard* lanes a NaN cannot leak between them.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Read statically, never by running a device: count `stream.cmd.dispatch` per `cf` block of `util.func public @main` in the generation graph's StableHLO compiled to `executable-configurations` for rocm/gfx942 (a pure CPU compile, iree-base-compiler 3.13).
Reference geometry `pop 100`, `species_size=20`, `survival_threshold=0.01`, `max_nodes=50`, `max_conns=100`, seed 42; one timestep is `^bb5` (the genome's per-query prelude) + `^bb7`·L (its level body) + `^bb8` (this node's step).
`CartPole` costs **21 dispatches per timestep** at `L = 3` (`^bb5` 3 + `^bb7` 4 + `^bb8` **6**), i.e. **4 200** rollout dispatches per generation at `max_step=200`, in a graph of **446** static sites.
`^bb8`'s 6: the genome's logit read-out materialised inside the step, one fused row region (slices, physics, rotation, lane selects, Euler add, force select, reward chain), the bool death fold (which absorbs its own `abs` + `greater` into its `reduce`, so the fold's op count does not move this block's dispatch count), the NaN row sum with its `i1` compare, and the freeze select — a floor, because a reduction cannot fuse into another iteration space, the `i1` compare feeds the fused region, and `alive`/`reward` are loop-carried values written first.
numpy control: 30 591 executed IR ops per generation (one per timestep from the bool death fold), with no change outside build noise in wall time or peak RSS; the `iree`+`rocm` leg builds (8.6–8.9 s), runs bit-identically to the numpy leg generation for generation, and pays the same dispatch census (446 static sites, `^bb5` 3 / `^bb7` 4 / `^bb8` 6).

### Pendulum (`pendulum.py`)
Gym `Pendulum-v1`, where `theta=0` is **upright**, so the cost is smallest exactly at the unstable equilibrium.
Per timestep, all on the pre-transition state: `u = max_torque * tanh(logit)`; `cost = angle_normalize(theta)**2 + 0.1*theta_dot**2 + 0.001*u**2`; `theta_dot' = clip(theta_dot + (3g/(2l)*sin(theta) + 3/(m*l**2)*u) * dt, -max_speed, max_speed)` — the clip comes **before** the angle update; `theta' = theta + theta_dot'*dt`; `total -= cost`.
`gravity_term = 3*gravity/(2*length)` and `torque_term = 3/(mass*length**2)` are precomputed host-side so the body never divides, and the host oracle must use the same precomputed float32 values; `angle_normalize(x) = x - two_pi*floor((x + pi)/two_pi)`, the floor-mod spelling of Gym's `((x + pi) % (2*pi)) - pi`.
Reset: one `U(-1, 1)` block of shape `(B, 2)` scaled by the baked `(1, 2)` float32 row `reset_scale = [pi, max_speed]` in one elementwise multiply (`theta = raw_0*pi`, `theta_dot = raw_1*max_speed`, so the draw is bit-identical to the per-column spelling), then split into the two carry leaves.
No termination and no alive mask: every episode is scored over the whole horizon, so the return is in `[-max_step*max_cost, 0]` (per-step cost at most `pi**2 + 0.1*max_speed**2 + 0.001*max_torque**2 = 16.2736`) and `fitness_target` may only be `<= 0`.
The host carry `(theta (B,1), theta_dot (B,1), total (B,1), step ())` of `kernel_mode == "host"` (the numpy leg and the byte-identical base kernel) keeps three float leaves at the cost's own rank, so a step needs no `slice`/`reshape`; the policy's observation row is **one elementwise select** against the baked `(1, 2)` boolean `obs_columns = [True, False]`, which fuses into the observation producer.
The accelerator carry `(row (B,3), step ())` of `kernel_mode == "accelerator"` holds `row = (theta, theta_dot, total)` as one float root, assembled by `row * keep_dims + next_speed * speed_row - cost * total_dim` against three baked `(1, 3)` rows (`keep_dims = [[1,0,1]]`, `speed_row = [[dt,1,0]]`, `total_dim = [[0,0,1]]`), bit-identical to the host step for finite values.
Its observation row is the leading `(B, 2)` `ops.slice` of the carried row instead of a select, and a NaN cost also drags the `theta` column to NaN (`NaN * 0`), which the fitness never reads.
NaN: `tanh(NaN)` → `0.001*u**2` is NaN → `cost` is NaN → the accumulator is NaN → `-inf`; no NaN census is needed, and a non-terminating episode keeps every NaN it sees.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Counted with the method and geometry of the CartPole subsection at `L = 3`.
Host mode: `^bb5` 4 + `^bb7` 4 + `^bb8` **3** = **19** dispatches per timestep (**3 800** per generation at `max_step=200`), in a graph of **445** static sites.
Accelerator mode: `^bb5` **3** + `^bb7` **5** + `^bb8` **3** = **21** dispatches per timestep (**4 200** per generation), in a graph of **414** static sites; the same packed carry without the per-query win is 4 + 5 + 3 = **22** on **415** sites, which is the count to compare the accelerator leg against, never the host mode's 19 (the genome's level body is one dispatch wider per trip there).
The packed step body alone reaches **1** dispatch (3 for the three-leaf host carry) in a standalone rollout graph, but the assembled generation graph re-materialises its column slices as one `slow_memcpy` each, so `^bb8` is 3 in both modes and the surviving win is the per-query prelude.
Gate: assembling the packed row costs the numpy interpreter **+805** executed ops on the generation after setup (27 055 → 27 860) and buys no dispatch in the assembled graph, so the packing stays behind `kernel_mode` and a host-mode graph is byte-for-byte the shipped kernel (27 391 ops, identical fitness).

### MountainCarContinuous (`mountaincar.py`)
Gym `MountainCarContinuous-v0` in exact Gym order on the pre-transition state: `a = tanh(logit)` (the **pre-clip** action, what Gym charges the penalty on); `force = clip(a, -1, 1)` (a no-op because `|tanh| <= 1`, kept for faithfulness); `velocity' = velocity + force*power - gravity*cos(3*position)`; `velocity' = clip(velocity', -max_speed, max_speed)`; `position' = clip(position + velocity', min_position, max_position)`; `velocity' = 0` where `position' == min_position and velocity' < 0` (exact equality, because `clip` returns the bound verbatim); `done = position' >= goal_position and velocity' >= goal_velocity`; `reward = (100 if done else 0) - 0.1*a**2`.
The goal test is folded into `_transition` and comes back rank-1 via one `enp.reshape`, so no `(B, 1)` operand meets the `(B,)` accumulator.
Reset: one `U(-1, 1)` draw of shape `(B, 1)` rescaled to `U(-0.6, -0.4)` (centre `-0.5`, half-width `0.1`, from `_RESET_LOW`/`_RESET_HIGH`) plus an exact zero velocity column, joined by `_stack_state`.
**Termination differs from CartPole**: `done` is a *success*, the terminal transition pays the `100` bonus once and the `0.1*a**2` penalty on it too, and afterwards the state is frozen **and no further reward is accumulated** — the accumulator is masked by the **pre-step** alive flag, because the frozen post-goal state still satisfies `done` and an unmasked bonus would be re-awarded every remaining timestep; the mask is retired with one `enp.where(done, consts.false, alive)` (`consts.false` being the bundle's rank-0 in-trace bool), not a `logical_not` feeding a `logical_and`.
Row assembly law: `_advance` splits the `(B, 2)` row, runs `_transition` on the two `(B, 1)` columns, and rejoins them with `_stack_state` — `enp.where(consts.position_column, position, velocity)` over the `(1, 2)` boolean `[True, False]`, numerically identical to an `enp.concatenate` but one elementwise op that fuses with its consumer.
That baked-mask `where` is the node's row-assembly law (the sibling `genome/window.py` seed splice uses the same one), and `_terminated` stays the rank-1 façade over `_goal_mask` for host-side tests.
Return bounds `[-(0.1*max_step), 100]` nominally, but `100` is not attainable: the bonus is paid once while `0.1*a**2` is charged on every scoring step of the climb, so `ATTAINABLE_CEILING = 93.0` is the highest admitted `fitness_target`.
Derivation: the per-step velocity gain is at most `power + gravity = 0.004` (full force with `cos(3*position) = -1`), so reaching the `max_speed = 0.07` clip from rest takes at least `ceil(0.07/0.004) = 18` scored steps, and the shortest travel from the highest reset position (`-0.4`) to `goal_position = 0.45` is `0.85`, i.e. at least `ceil(0.85/0.07) = 13` more at up to `0.1` penalty each; a real climb is ~106 steps and the best reaching policy measured here (bang-bang `a = sign(velocity)`, `P = 8`) returns `90.8` (min `89.1`) at both 999 and 200 steps.
NaN: `tanh(NaN)` → the `0.1*a**2` penalty is NaN → the live step's reward is NaN → the accumulator follows → `-inf`; `enp.clip` is `minimum(maximum(x, lo), hi)` and both ops propagate NaN, so the clip never folds the poison away, while a NaN arriving *after* the goal is genuinely dropped because accumulation stops.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Counted with the method and geometry of the CartPole subsection, `max_step=999`, `L = 3`; this environment consults no `kernel_mode` and traces one formulation on every leg.
**19 dispatches per timestep**: `^bb5` 3 + `^bb7` 4 + `^bb8` **4**, i.e. **18 981** rollout dispatches per generation, in a graph of **443** static sites.
`^bb8`'s 4: one `(B, 1)`-domain region holding the read-out gather, its `I_INF`→NaN guard, `tanh` and `_transition`'s whole physics; `total'` (bonus, penalty, pre-step alive mask, accumulation); `alive'`; and `obs'` (`_stack_state`'s baked select plus the freeze).
That is a floor of 4 — one dispatch per carried tensor (`obs (B,2)`, `alive (B,)`, `total (B,)`) plus one for the physics region, a multi-use producer (`math.cos` and the read-out gather are not clonable) whose cheap comparisons are cloned into every consumer region (the goal predicate reappears three times although `done` is computed once).
3 would need the carried set down to two tensors: `alive` is not recoverable from `obs` (the freeze keeps the pre-terminal observation), and the carry shape with rank-1 `alive`/`total` is pinned by `test/unit/problem/test_mountaincar.py` and `_common.returns_of`.
The per-iteration overhead costs **0** dispatches (the trip condition and counter increment are host-level `arith` ops), and dropping `clip(tanh, ±1)` would change the documented Gym-order physics while moving no dispatch.

## Constraints
- Every arithmetic constant is an in-trace `enp.full((), value)` (float32) built **once per rollout, outside the loop** in the environment's `NamedTuple` bundle (plus the int32 `one_step`/`horizon`); a Python float literal would become f64 on the stablehlo path and break iree type unification.
- `enp.full` fills a scalar only, so a row constant (`threshold_row`, `perm_idx`, the two lane masks, `obs_columns`, `position_column`, `reset_scale`, the three packed rows) is an `evoxc.constant(evoxc.from_numpy(...))` baked once per rollout — data, never arithmetic, so it introduces no float64 constant.
- Row assembly is one baked-mask `enp.where`, never an `enp.concatenate` of columns, and column reads are static one-lane `evoxc.slice`es or a baked lane rotation: a `concatenate`/split costs one serialised `slow_memcpy` dispatch per column on iree.
- `evoxc.remainder` is **not** portable (floormod on numpy, fmod on iree) and `enp` has neither `floor` nor `remainder`; `angle_normalize` uses `evoxc.floor`, which is bit-identical on both.
- Use non-negative axes (`axis=1`) in `split`/`concatenate`, broadcast rank-1 masks with `enp.expand_dims` (a traced tensor has no `__getitem__`), and keep loop values rank-1 (`enp.reshape`) so no `(B,1)` operand meets a `(B,)` accumulator.
- Physics algebra is fixed op-for-op in all three: precomputing reciprocals (`1/total_mass`, `1/(2*l)`, …) or reassociating the float32 arithmetic changes which step a chaotic trajectory dies or reaches the goal on, so returns would stop matching the host-numpy oracles in `test/unit/problem/`.
- Control flow makes all three environments numpy / iree-llvm-cpu / xla only (TVM rejects `while`/`if`/gather/scatter) and the failure must surface as `evoxc.BackendError`, never a fallback.
- `show` and every report graph are host-side and built with `**problem.base.build_options(state)`; reporting is finite-safe, so no report may convert a return with `int()`/`round()` or test it against a bound without `math.isfinite` first — `CartPole` prints `survived n/a (NaN return)`, `MountainCarContinuous` prints `goal n/a (NaN return)`, `Pendulum` prints `nan`.
- Every numeric knob and every `fitness_target` goes through a `_common` validator, so a configuration error is always `TensorNEATError` with a `<Owner>: <name> must be ...` message, never a bare `TypeError`/`ValueError`.
- Files <= ~1000 lines (`cartpole.py` 730, `mountaincar.py` 835, `pendulum.py` 960, `_common.py` 253).
- `L` (the level loop's trip count) is a **runtime** value — the population's own depth — so a per-timestep total moves by the level trip's width per `L`: instrumenting `Interpreter._run_block` over 20 `CartPole` generations reads `L` 2 at the generation after setup, 3 at the median and 4 at the deepest.

## Measured cost
On the numpy interpreter at the reference geometry (`pop 100`, `max_step=200`, seed 42) one `cartpole_p100` generation executes **30 591** dispatched ops and costs **≈97 ms** (median of ten interleaved `benchmarks/gpu_measure.py run --case cartpole_p100 --target numpy --warmup 2 --generations 5` runs, 2026-11-07 session, build 0.26 s).
The box drifts ±30 % between sessions, so only a same-session pair is load-bearing; the `iree`+`rocm` leg of the same protocol was recorded at **61.9** ms per generation (build 9.0 s, 1.9 GiB RSS) on an earlier tree, and on this one it is **bimodal per process** at ≈61 ms and ≈87 ms across fresh processes in both directions, so no cell of it is a wall-time regression signal (its static dispatch census is what pins the leg).
The compiled leg's cost law is `max(host submission, device)`: a flat graph is ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, a `while` iteration adds ≈157 µs when its predicate is device data against ≈57 µs when its trip count is provably static (a counter against a constant, no early-exit flag), and `Tensor.to(cpu)` is ≈47–60 µs per leaf; a flat-graph numpy interpreter measurement reads ≈19–20 µs per dispatched op, so op count is the lever on either leg.
The rollout `while_loop` is the provably-static case — its condition is the counter against the constant `max_step` — so `cartpole_p100` pays 200 × ≈57 µs ≈ 11.4 ms of loop boundaries per generation, and the genome's level loop inside it is the statically unrolled `max_depth` sweep on that leg (`genome/default.py::_level_sweep`, accelerator-only and only when `samples == 1`), which makes `max_depth` the cell's dominant config term (32.38 / 41.96 / 60.15 ms at `max_depth` 4 / 8 / 16).
Both legs are linear in the horizon with no quadratic term and nearly flat in the population (10× the population costs ≈1.07–1.09× at 200 steps; 10× the horizon costs ≈2.5× Pendulum / ≈5× MountainCar).
The rollout component alone (`evaluate` traced with a genome-free toy policy) is 3.4–10.0× cheaper on iree-llvm-cpu than on numpy, at a ≈0.65–0.70 s one-off build per shape.
Per-timestep op budget (`cartpole_p100`, `L = 2` on the generation after setup, 135 ops per timestep): **78** are the genome level body (39 × 2 trips), **6** its level `while` condition, **2** the rollout `while` condition, and **49** the rollout body, of which **43** are this node's force/dynamics/reward/alive update (the other 6 are the logit read-out and NaN handling the prepared pass contributes); ≈87 % of a generation's ops run inside the rollout region.
The prepared pass hoists the 58-op per-query prelude (`_padding_safe_attrs`, `_hit_conn_attrs`' `(P,N,K,CA)` gather, `_slot_index`, `_output_row_mask`, `_depth_limit`, the NaN seed) once per generation and derives it for `B = P * R` rows while the schedule and payload stay at `P`, so `repeat_times > 1` pays the genome's sample expansion (`genome/window.py::by_samples`) once and `R=1` makes it the identity.
Pipeline level (`pop_batch_size` unset, one generation per `step`, numpy): the genome `transform` + `forward` inside `act_fn` is 80–90 % of a generation's evaluate share and this node's rollout is the rest — 6–18 % of it for `CartPole`, 9.9 % for a six-node-hidden `Pendulum`, 17.5 % for `MountainCarContinuous` — so a continuous-control generation is genome-forward-bound, not rollout-bound (`../CONTEXT.md` holds the per-cell rows).
Numeric agreement (`P=100`, one key, same toy policies): iree vs numpy per-individual fitness differs only by float32 rounding (`max_rel` 1.2e-6 Pendulum 200 steps, 4.1e-7 MountainCar 200, 1.8e-6 MountainCar 999), and against a host-numpy **float32** transcription of the documented recurrence fed the graph's own initial states both continuous environments are bit-identical (`max_abs = 0`).
Cross-backend fitness is therefore reproducible to float32 rounding but never bitwise, and no test may assert cross-backend trajectory equality.

### Per-timestep op inventory (traced on the numpy interpreter, current tree)
Environment-only bodies traced with a one-op stub policy at `P=100` (the structure is horizon-independent): `CartPole` **44** ops per timestep, `Pendulum` **27** (host carry) / **31** (accelerator carry), `MountainCarContinuous` **36**, on top of a once-per-rollout entry block of 22 / 18 (21) / 24 `constant` ops built by `_constants`.
`cartpole_p100` (pop 100, `max_step=200`, seed 42) executes **30 591** ops per generation, attributed per block: genome level body **15 600** (51.0 %, 400 trips = 2 per timestep at the population's depth 1), rollout body **9 800** (32.0 %, 49 ops × 200, of which the environment is 43), genome level condition 1 200, rollout condition 402, whole-generation entry block **1 586** (5.2 %, including the ≈55-op prepared pass, hoisted into the entry block and paid once per generation).
The rollout region is therefore ≈87 % of a generation; the environment share is 27/105 and 36/114 for Pendulum and MountainCar.
Three `constant` ops execute per genome level trip (1 200 ops, 3.9 % of the generation) and are created inside the level body rather than in the prepared pass (sibling genome node).
`repeat_times` widens tensors, never the dispatch sequence: `R=1/2/4` at pop 100 costs 30 591 / 30 632 / 30 632 executed ops and ≈101 / 135 / 193 ms per generation (one sample each, this session), because `B = P·R ≤ 800` stays under the 12 500-row CPU chunk budget, so a rollout keeps ONE prepared pass and one query per timestep; `R = 1` is the only cell that also skips `evaluate`'s `returns_of` reshape and mean (2 ops), and the skip is now shared by all three environments.
`benchmarks/gpu_measure.py run --case cartpole_p100` reads numpy **97.4** ms/generation (median of ten interleaved runs, build 0.26 s) and the recorded `iree`+`rocm` leg of the same protocol **61.9** ms (build 9.0 s, 1.9 GiB RSS); the horizon slope is 0.407 ms per timestep plus ≈17 ms fixed per generation on numpy and 0.262 ms plus ≈9 ms on rocm at `max_depth=16`.

## Notes for Agents
- Dead in `src/`: `_terminated` (`cartpole.py`, `mountaincar.py`) has no caller outside `test/unit/problem`; the constant bundles carry no unread field (`_CartPoleConstants` holds no `masscart`, only the derived `total_mass`, because the validated constructor attribute feeds it host-side).
- **`evoxc.remainder` is not backend-consistent**: floor-mod on numpy but `fmod` on stablehlo/iree, which inflated an `angle_normalize` Pendulum cost 2.4× on iree while numpy looked perfect — worth an upstream report.
- **MountainCarContinuous's reward is deceptive**: `a -> 0` returns exactly `0`, an aggressive constant policy `-0.1*max_step`, and only a bang-bang energy-pumping policy reaches the goal (`a = sign(velocity)` at `P=8` returns **90.8**, min 89.1, at both 999 and 200 steps, which proves the `100` bonus is paid exactly once).
  NEAT nonetheless converges to the idle policy (12–20 generations at `pop=100`, `max_step` 200/300/999, with and without `init_hidden_layers=(6,)`, all ending at `-0.007 … -0.0`) — task semantics, so target `≈-0.5` for a demo that terminates or budget far more generations for the bonus.
- **Pendulum needs a hidden layer to learn quickly**: at `pop=100`, `species_size=10`, `max_step=200`, `init_hidden_layers=()` plateaus at `-527` (best of 40 generations, seed 42), while `init_hidden_layers=(6,)` reaches `-300` at generation 5 of 20 (training max `-271.30`, 2.7–2.9 s wall) for ≈2× the genome forward; `examples/rl/CONTEXT.md` holds both shipped demo configurations.
- CartPole's `_loop_body` insertion order is load-bearing: `_nan_rows` selects the NaN into `total` **before** `alive` is updated, so a poison arriving on the step an episode dies still lands.
- Environment-body micro-optimisations are worth ~1 %: the one-op alive mask is taken (see the CartPole algebra), and the next op would fold the death test from `abs/subtract/reduce_max/greater` into `abs/greater/reduce_max`, which needs a bool `reduce_max` the stablehlo exporter may not take — so it stays unshipped.
- The unrolled level sweep, not the environment, is the accelerator lever: on iree+rocm `cartpole_p100` costs **31.2 / 33.4 / 42.4 / 64.8** ms per generation at `max_depth` 2 / 4 / 8 / 16 (≈10.9 µs per unrolled level per timestep), so bounding the level loop by the batch's real depth (1–2 here) removes about half of the 64.8 ms (sibling genome node's `genome/default.py::_level_sweep`); after that, ≈57 µs of the remaining ≈110 µs per timestep is the rollout `while` boundary and only ~6 of its ~9 dispatches are the environment.
- The reset/carry skeleton is the only generic code each environment still spells itself; the trip condition is `_common.horizon_cond` and dynamics stay per environment by the module rule.
- `_common.py` validators take the **owner name first** (`require_positive_int("Pendulum", "max_step", value)`) so the `<Owner>: <name> must be ...` text is uniform; a non-numeric or non-finite knob reports `must be a finite number`, a finite out-of-range one `must be positive`/`must be non-negative`.
- The reference oracle for the two continuous environments is a float32 host transcription in `test/unit/problem/` (test-agent owned); ordering a test can break: Pendulum clips velocity before the angle update, MountainCar charges the penalty on the **pre-clip** action and resets velocity at the min position by exact float equality, and the bonus is masked by the pre-step alive flag.
- `backend="iree"` runs a full `Pipeline` end to end (`test/backends/test_iree_pipeline.py`), so the component measurements above are not a pipeline verdict; `benchmarks/BACKENDS.md` holds the llvm-cpu ratios and the per-shape `iree-compile` cost.
