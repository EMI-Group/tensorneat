# rl — reinforcement-learning problems on evoxc

## Intent
Score a genome by the return of a batched episode rollout, with the environment dynamics written as evoxc ops instead of a JAX simulator.
Three environments ship: the discrete `CartPole` and the continuous classic-control tasks `Pendulum` and `MountainCarContinuous`.
Each one is the reference recipe for a user-defined environment: no registry, no simulator dependency, just a step kernel and one `while_loop`, one file per environment.

## API Surface
- `cartpole.py: CartPole(BaseProblem)` — `__init__(max_step=500, repeat_times=1, gravity=9.8, masscart=1.0, masspole=0.1, length=0.5, force_mag=10.0, dt=0.02, x_threshold=2.4, theta_threshold=12.0, reset_scale=0.05, fitness_target=None)`; every knob is host-validated and raises `TensorNEATError`.
- `pendulum.py: Pendulum(BaseProblem)` — `__init__(max_step=200, repeat_times=1, gravity=10.0, mass=1.0, length=1.0, max_speed=8.0, max_torque=2.0, dt=0.05, fitness_target=None)`; every physics knob is strictly positive and finite, and `fitness_target > 0` raises because every reward is `-cost <= 0`.
- `mountaincar.py: MountainCarContinuous(BaseProblem)` — `__init__(max_step=999, repeat_times=1, min_position=-1.2, max_position=0.6, max_speed=0.07, goal_position=0.45, goal_velocity=0.0, power=0.0015, gravity=0.0025, fitness_target=None)`; unreachable geometry (`min_position >= max_position`, a `goal_position` outside the clipped track, `goal_velocity > max_speed`) and `fitness_target > ATTAINABLE_CEILING` (`93.0`, exported in `__all__`) raise.
- `_common.py` — the host helpers all three draw from: `to_numpy`, the owner-prefixed validators `require_positive_int`/`require_finite`/`require_positive`/`require_non_negative` (messages `<Owner>: <name> must be ...`), and `returns_of(total, pop_size, repeat_times)` plus `prepared_query(act_fn, batch)`, the last two **traced** and inlined into the caller's graph like `problem.base.finalize_fitness`.
  The two float validators layer on `require_finite`, so a non-numeric knob (a string, a list, `None`) and a non-finite one (`NaN`/`±inf`) both raise `TensorNEATError`, never a bare `TypeError`/`ValueError`; it carries no dynamics, no `@evoxc.defn` and no module-scope `enp` call, so adding an environment never edits it.
- Shapes: `CartPole` `(4,)` = `(x, x_dot, theta, theta_dot)` → `(2,)` two logits (`out[1] > out[0]` pushes right); `Pendulum` `(2,)` = `(theta, theta_dot)` → `(1,)` one torque logit; `MountainCarContinuous` `(2,)` = `(position, velocity)` → `(1,)` one action logit.
- Both continuous problems own the action squashing (`u = max_torque*tanh(logit)`, `a = tanh(logit)`), so a genome used with them leaves `output_transform` unset (identity).
- Formulation gate: `Pendulum` traces exactly one of two carries, picked on the host from the trace-time static `state.kernel_mode` (`common.schedule_accelerator.kernel_mode(state)`: `"host"` on the numpy leg, `"accelerator"` on a GPU-class device); `CartPole` and `MountainCarContinuous` consult no mode.
- `fitness_target` is validation-only: `None` skips the check, a non-finite value or one above the environment's attained ceiling (`max_step`, `0`, `93.0`) raises, and the attribute is stored as given.
- `evaluate(state, keys, act_fn, transformed) -> (P,)` maximizes fitness: the mean over `repeat_times` of the episode return, `finalize_fitness`-ed last.
- `show(state, key, act_fn, transformed)`: host-side, one individual, its own graph over the single rank-0 key (`evoxc.build` + `evoxc.run`), one printed line per repeat plus the mean, built with `**problem.base.build_options(state)` so it runs on the registered backend/device/compile options and an unusable backend raises rather than falling back.
- Beyond the shared `_rollout`/`_loop_cond`/`_loop_body`/`_constants` skeleton — `CartPole`: `_advance`, `_death_mask`, `_terminated`, `_force_from_logits`, `_nan_rows`; `Pendulum`: `_packed_rollout`, `_reset`, `_loop_body_packed`, `_advance`, `_advance_rows`, `_transition_rows`, `_angle_normalize`; `MountainCarContinuous`: `_reset`, `_action_from_logits`, `_advance`, `_transition`, `_stack_state`, `_goal_mask`, `_terminated`.

## Algebra

### Shared shape (all three)
`B = P * repeat_times` with `P = static_batch_size(transformed)`, **individual-major**: row `p * R + r` is repeat `r` of individual `p`, so `P = 4, R = 1` and `P = 2, R = 2` draw the same four initial states from one key and produce identical per-episode returns.
Initial states come from **one** `evoxc.random.uniform` off the single rank-0 key, which is never threaded through the loop and never replaced by `np.random`; the trip count is always static (`step < horizon`), never "while any episode is alive".
The return accumulator rides in the carry and the loop emits no output, because an `evoxc.scan` would carry a `(max_step, B)` stack and scatter one row per iteration.
`returns_of` is the only place the `(P, R)` layout is assumed, and a rollout prepares its policy query once with `_common.prepared_query(act_fn, batch)`, so the genome's loop-invariant pass operands are derived once per generation (a genome-free callable exposes no `prepare` and passes through unchanged).

### CartPole (`cartpole.py`)
Classic Gym `CartPole-v1` with Euler integration: `dt=0.02`, `g=9.8`, `masscart=1.0`, `masspole=0.1`, half-pole `length=0.5`, `force_mag=10`, dead when `|x| > 2.4` or `|theta| > 12deg` (`= 0.2095 rad`), reset `U(-0.05, 0.05)^4`.
One `evoxc.while_loop` over `max_step` timesteps with carry `(obs (B,4), alive (B,), total (B,), step ())`: "push right" iff `out[1] > out[0]` (a tie pushes left, matching `argmax` index 0) via `enp.split` + `enp.greater`; `total += alive` **before** the transition (the failing step still scores, as in Gym); then one fused Euler op `next_obs = obs + dt * (x_dot, xacc, theta_dot, thetaacc)` from the documented `temp`/`thetaacc`/`xacc` algebra.
Death is read off that same row against a `(1, 4)` constant `(x_threshold, +inf, theta_threshold, +inf)`: `dead = greater(max(|next_obs| - threshold_row, axis=1), 0)`, a bracketed per-column limit whose velocity columns can never fail, and `|obs_j| - t > 0` is exactly `|obs_j| > t` in IEEE, so it equals `|x'| > 2.4 | |theta'| > 12deg`.
The state is frozen after death via `enp.where(enp.expand_dims(alive, 1), next_obs, obs)` — no `cond`, every carried dtype/shape constant across iterations — and because episodes are frozen an individual's return is its survival time, so `max_step` is the fitness ceiling and `fitness_target` must be `<= max_step`.
NaN: a NaN logit acts as push-left inside the rollout (`enp.greater` is false against NaN) but `_nan_rows` (`evoxc.isnan` of the row sum, NaN being absorbing under addition) selects a NaN into `total`, so any individual whose policy ever emitted a NaN logit gets a NaN fitness → `-inf`.
**Step formulation (one, unconditional, no `kernel_mode` gate).** The row is never split into four columns and never concatenated back, because each such column costs a serialised `slow_memcpy` dispatch through the step's scratch buffer: the two angular variables come from static one-lane `evoxc.slice`es (no index tensor, no baked constant), and the derivative row is assembled by rotating the observation with the baked `(1, 0, 3, 2)` lane index (`evoxc.gather` axis 1, so lanes 0/2 receive the row's own `x_dot`/`theta_dot`) and overwriting lanes 1/3 with `xacc`/`thetaacc` via `enp.where` against two baked `(1, 4)` single-lane boolean rows.
Physics, rotation and both selections compile into one elementwise region, and since the selections only *discard* lanes a NaN cannot leak between them.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Read statically, never by running a device: count `stream.cmd.dispatch` per `cf` block of `util.func public @main` in the generation graph's StableHLO compiled to `executable-configurations` for rocm/gfx942 (a pure CPU compile, iree-base-compiler 3.13).
Reference geometry `pop 100`, `species_size=20`, `survival_threshold=0.01`, `max_nodes=50`, `max_conns=100`, seed 42; one timestep is `^bb5` (the genome's per-query prelude) + `^bb7`·L (its level body) + `^bb8` (this node's step).
`CartPole` costs **21 dispatches per timestep** at `L = 3` (`^bb5` 3 + `^bb7` 4 + `^bb8` **6**), i.e. **4 200** rollout dispatches per generation at `max_step=200`, in a graph of **446** static sites.
`^bb8`'s 6: the genome's logit read-out materialised inside the step, one fused row region (slices, physics, rotation, lane selects, Euler add, force select and reward chain), the death fold, the NaN row sum, its `i1` compare and the freeze select — the floor, because a reduction broadcasts into its own iteration space and cannot fuse, the `i1` compare materialises because its result feeds the fused region, and `alive`/`reward` cannot join that region because they are loop-carried values written first.
numpy control: 30 994 executed IR ops per generation (the three baked row-assembly constants add 3) and no wall-time or peak-RSS change — 248.70 ms per generation.

### Pendulum (`pendulum.py`)
Gym `Pendulum-v1`, where `theta=0` is **upright**, so the cost is smallest exactly at the unstable equilibrium.
Per timestep, all on the pre-transition state: `u = max_torque * tanh(logit)`; `cost = angle_normalize(theta)**2 + 0.1*theta_dot**2 + 0.001*u**2`; `theta_dot' = clip(theta_dot + (3g/(2l)*sin(theta) + 3/(m*l**2)*u) * dt, -max_speed, max_speed)` — the clip comes **before** the angle update; `theta' = theta + theta_dot'*dt`; `total -= cost`.
`gravity_term = 3*gravity/(2*length)` and `torque_term = 3/(mass*length**2)` are precomputed host-side so the body never divides, and the host oracle must use the same precomputed float32 values; `angle_normalize(x) = x - two_pi*floor((x + pi)/two_pi)`, the floor-mod spelling of Gym's `((x + pi) % (2*pi)) - pi`.
Reset: one `U(-1, 1)` block of shape `(B, 2)` scaled by the baked `(1, 2)` float32 row `reset_scale = [pi, max_speed]` in one elementwise multiply (`theta = raw_0*pi`, `theta_dot = raw_1*max_speed`, each element `raw * scale` with the operand the per-column spelling used, so the draw is bit-identical), then split into the two carry leaves.
No termination and no alive mask: every episode is scored over the whole horizon, so the return is in `[-max_step*max_cost, 0]` (per-step cost at most `pi**2 + 0.1*max_speed**2 + 0.001*max_torque**2 = 16.2736`) and `fitness_target` may only be `<= 0`.
The host carry `(theta (B,1), theta_dot (B,1), total (B,1), step ())` of `kernel_mode == "host"` (the numpy leg and the byte-identical base kernel) keeps three float leaves at the cost's own rank, so a step needs no `slice`/`reshape`; the policy's observation row is **one elementwise select** against the baked `(1, 2)` boolean `obs_columns = [True, False]`, which fuses into the observation producer where an `enp.concatenate` of the two columns lowers to one strided copy (one dispatch) per column.
The accelerator carry `(row (B,3), step ())` of `kernel_mode == "accelerator"` holds `row = (theta, theta_dot, total)` as one float root, assembled by the single affine expression `row * keep_dims + next_speed * speed_row - cost * total_dim` against three baked `(1, 3)` rows (`keep_dims = [[1,0,1]]`, `speed_row = [[dt,1,0]]`, `total_dim = [[0,0,1]]`), so column 0 is literally `theta + next_speed*dt`, column 1 `next_speed` and column 2 `total - cost` — bit-identical to the host step for finite values.
Its observation row is the leading `(B, 2)` `ops.slice` of the carried row instead of a select, so the per-query region is one dispatch narrower; a NaN cost also drags the `theta` column to NaN (`NaN * 0`), which the fitness never reads.
Both formulations flatten `total` to `(B,)` once after the loop, and the baked rows are Constants built once per rollout, outside the loop.
NaN: `tanh(NaN)` → `0.001*u**2` is NaN → `cost` is NaN → the accumulator is NaN → `-inf`; no NaN census is needed, and a non-terminating episode keeps every NaN it sees.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Counted with the method and geometry of the CartPole subsection at `L = 3`.
Host mode: `^bb5` 4 + `^bb7` 4 + `^bb8` **3** = **19** dispatches per timestep (**3 800** per generation at `max_step=200`), in a graph of **445** static sites.
Accelerator mode: `^bb5` **3** + `^bb7` **5** + `^bb8` **3** = **21** dispatches per timestep (**4 200** per generation), in a graph of **414** static sites; the same packed carry without the per-query win is 4 + 5 + 3 = **22** on **415** sites, which is the count to compare the accelerator leg against, never the host mode's 19 (the genome's level body is one dispatch wider per trip there).
The packed step body alone reaches **1** dispatch (3 for the three-leaf host carry) in a standalone rollout graph, but the assembled generation graph re-materialises its column slices as one `slow_memcpy` each, so `^bb8` is 3 in both modes and the surviving win is the per-query prelude.
Gate: assembling the packed row costs the numpy interpreter **+805** executed ops on the generation after setup (27 055 → 27 860, ~+1.9 % averaged over 20 timed generations) and buys no dispatch in the assembled graph, so the packing stays behind `kernel_mode` and a host-mode graph is byte-for-byte the shipped kernel (27 391 ops, identical per-step op list, identical fitness).

### MountainCarContinuous (`mountaincar.py`)
Gym `MountainCarContinuous-v0` in exact Gym order on the pre-transition state: `a = tanh(logit)` (the **pre-clip** action, what Gym charges the penalty on); `force = clip(a, -1, 1)` (a no-op because `|tanh| <= 1`, kept for faithfulness); `velocity' = velocity + force*power - gravity*cos(3*position)`; `velocity' = clip(velocity', -max_speed, max_speed)`; `position' = clip(position + velocity', min_position, max_position)`; `velocity' = 0` where `position' == min_position and velocity' < 0` (exact equality, because `clip` returns the bound verbatim); `done = position' >= goal_position and velocity' >= goal_velocity`; `reward = (100 if done else 0) - 0.1*a**2`.
The goal test is folded into `_transition` (the transition already holds `position'`/`velocity'`) and comes back rank-1 via one `enp.reshape`, so no `(B, 1)` operand ever meets the `(B,)` accumulator.
Reset: one `U(-1, 1)` draw of shape `(B, 1)` rescaled to `U(-0.6, -0.4)` (centre `-0.5`, half-width `0.1`, from `_RESET_LOW`/`_RESET_HIGH`) plus an exact zero velocity column, joined by `_stack_state`.
**Termination differs from CartPole**: `done` is a *success*, the terminal transition pays the `100` bonus once and the `0.1*a**2` penalty on it too, and afterwards the state is frozen **and no further reward is accumulated** — the accumulator is masked by the **pre-step** alive flag, because the frozen post-goal state still satisfies `done` and an unmasked bonus would be re-awarded every remaining timestep; the mask is retired with one `enp.where(done, consts.false, alive)` (`consts.false` being the bundle's rank-0 in-trace bool), not a `logical_not` feeding a `logical_and`.
Row assembly law: `_advance` splits the `(B, 2)` row, runs `_transition` on the two `(B, 1)` columns, and rejoins them with `_stack_state` — `enp.where(consts.position_column, position, velocity)` over the `(1, 2)` boolean `[True, False]`, numerically identical to `enp.concatenate((position, velocity), axis=1)` but one elementwise op in the row's own domain that fuses with its consumer, where a `concatenate` forms one strided copy (one dispatch) per column on iree.
That baked-mask `where` is the node's row-assembly law (the sibling `genome/window.py` seed splice uses the same one), and `_terminated` stays the rank-1 façade over `_goal_mask` for host-side introspection and tests.
Return bounds `[-(0.1*max_step), 100]` nominally, but `100` is not attainable: the bonus is paid once while `0.1*a**2` is charged on every scoring step of the climb, so `ATTAINABLE_CEILING = 93.0` is the highest admitted `fitness_target`.
Derivation: the per-step velocity gain is at most `power + gravity = 0.004` (full force with `cos(3*position) = -1`), so reaching the `max_speed = 0.07` clip from rest takes at least `ceil(0.07/0.004) = 18` scored steps, and the shortest travel from the highest reset position (`-0.4`) to `goal_position = 0.45` is `0.85`, i.e. at least `ceil(0.85/0.07) = 13` more scored steps at up to `0.1` penalty each; a real climb is ~106 steps and the best reaching policy measured on this box (bang-bang `a = sign(velocity)`, `P = 8`) returns `90.8` (min `89.1`) at both 999 and 200 steps.
A structurally minimal climb needs 31 scoring steps, so a target below the ceiling can still be out of reach on a short horizon — a constructor-docstring caveat, not a rejection.
NaN: `tanh(NaN)` → the `0.1*a**2` penalty is NaN → the live step's reward is NaN → the accumulator follows → `-inf`; `enp.clip` is `minimum(maximum(x, lo), hi)` and both ops propagate NaN, so the clip never folds the poison away, while a NaN arriving *after* the goal is genuinely dropped because accumulation stops.

#### IREE dispatch budget of the step block (measured statically, CPU only)
Counted with the method and geometry of the CartPole subsection, `max_step=999`, `L = 3`; this environment consults no `kernel_mode` and traces one formulation on every leg.
**19 dispatches per timestep**: `^bb5` 3 + `^bb7` 4 + `^bb8` **4**, i.e. **18 981** rollout dispatches per generation, in a graph of **443** static sites.
`^bb8`'s 4: one `(B, 1)`-domain region holding the read-out gather, its `I_INF`→NaN guard, `tanh` and `_transition`'s whole physics; `total'` (bonus, penalty, pre-step alive mask, accumulation); `alive'`; and `obs'` (`_stack_state`'s baked select plus the freeze).
That is a floor of 4 — one dispatch per carried tensor (`obs (B,2)`, `alive (B,)`, `total (B,)`) plus one for the physics region, a multi-use producer (`math.cos` and the read-out gather are not clonable) whose cheap comparisons are cloned into every consumer region, so the goal predicate reappears three times although the trace computes `done` once.
3 would need the carried set down to two tensors, and `alive` is not recoverable from `obs` (the freeze keeps the pre-terminal observation), while the `(obs, alive, total, index)` carry with rank-1 `alive`/`total` is pinned by `test/unit/problem/test_mountaincar.py` and `_common.returns_of`.
The per-iteration overhead around the step costs **0** dispatches (the trip condition and the counter increment are host-level `arith` ops), and dropping the `clip(tanh, ±1)` would be numerically a no-op but changes the documented Gym-order physics while moving no dispatch, so it stays.

## Constraints
- Every arithmetic constant is an in-trace `enp.full((), value)` (float32) built **once per rollout, outside the loop** in the environment's `NamedTuple` bundle (plus the int32 `one_step`/`horizon`); a Python float literal would become f64 on the stablehlo path and break iree type unification.
- `enp.full` fills a scalar only, so a row constant (`threshold_row`, `perm_idx`, the two lane masks, `obs_columns`, `position_column`, `reset_scale`, the three packed rows) is an `evoxc.constant(evoxc.from_numpy(...))` baked once per rollout — data, never arithmetic, so it introduces no float64 constant.
- Row assembly is one baked-mask `enp.where`, never an `enp.concatenate` of columns, and column reads are static one-lane `evoxc.slice`es or a baked lane rotation: a `concatenate`/split costs one serialised `slow_memcpy` dispatch per column on iree.
- `evoxc.remainder` is **not** portable (floormod on numpy, fmod on iree) and `enp` has neither `floor` nor `remainder`; `angle_normalize` uses `evoxc.floor`, which is bit-identical on both.
- Use non-negative axes (`axis=1`) in `split`/`concatenate`, broadcast rank-1 masks with `enp.expand_dims` (a traced tensor has no `__getitem__`), and keep loop values rank-1 (`enp.reshape`) so no `(B,1)` operand meets a `(B,)` accumulator.
- Physics algebra is fixed op-for-op in all three: precomputing reciprocals (`1/total_mass`, `1/(2*l)`, …) or reassociating the float32 arithmetic changes which step a chaotic trajectory dies or reaches the goal on, so returns would stop matching the host-numpy oracles in `test/unit/problem/`.
- Control flow makes all three environments numpy / iree-llvm-cpu / xla only (TVM rejects `while`/`if`/gather/scatter) and the failure must surface as `evoxc.BackendError`, never a fallback.
- `show` and every report graph are host-side and built with `**problem.base.build_options(state)`; reporting is finite-safe, so no report may convert a return with `int()`/`round()` or test it against a bound without `math.isfinite` first — `CartPole` prints `survived n/a (NaN return)`, `MountainCarContinuous` prints `goal n/a (NaN return)`, `Pendulum` prints `nan`.
- Every numeric knob and every `fitness_target` goes through a `_common` validator, so a configuration error is always `TensorNEATError` with a `<Owner>: <name> must be ...` message, never a bare `TypeError`/`ValueError`.
- Adding an environment means a step helper + a `while_loop` + the same finish step, in one file per environment; a shared helper belongs in `_common.py` only if it is generic (no dynamics, no module-scope `enp` call).
- Files <= ~1000 lines (`cartpole.py` 744, `mountaincar.py` 849, `pendulum.py` 980, `_common.py` 214).
- Per-timestep IREE dispatch inventory at `L = 3`: `CartPole` 3 + 4·L + 6 = **21** (446 sites), `Pendulum` 4 + 4·L + 3 = **19** host / 3 + 5·L + 3 = **21** accelerator (445 / 414 sites), `MountainCarContinuous` 3 + 4·L + 4 = **19** (443 sites); the genome's `^bb5`/`^bb7` are the sibling genome node's, so this node's own budget is `^bb8` 6 / 3 / 4.
  `L` is a **runtime** value (the population's own depth): instrumenting `Interpreter._run_block` over 20 `CartPole` generations reads `L` 2 at the generation after setup, 3 at the median and 4 at the deepest.

## Measured cost
On this worktree (2026-11-06, reference geometry): one `cartpole_p100` generation costs **248.70 ms** on the numpy interpreter and executes **30 994** dispatched ops, and the same cell on `backend="iree"`, `device="rocm"` costs **150.41 ms** per generation.
The compiled leg's cost law is `max(host submission, device)`: a flat graph is ≈63 µs fixed plus ≈2.2–2.5 µs per dispatch, one `while` iteration adds ≈50 µs because its condition is read back to the host, and `Tensor.to(cpu)` is ≈47–60 µs per leaf; a flat-graph numpy interpreter measurement reads ≈19–20 µs per dispatched op, so op count is the lever on either leg.
Both legs are linear in the horizon with no quadratic term and nearly flat in the population (10× the population costs ≈1.07–1.09× at 200 steps; 10× the horizon costs ≈2.5× Pendulum / ≈5× MountainCar).
The rollout component alone (`evaluate` traced with a genome-free toy policy) is 3.4–10.0× cheaper on iree-llvm-cpu than on numpy (a ≈0.65–0.70 s one-off build per shape), while a full compiled pipeline stays launch-bound on llvm-cpu (237.9 ms median step, 7.8–8.0 s build per shape).
Per-timestep op budget (`cartpole_p100`, `L = 2` on the generation after setup): ~80 ops are the genome forward (the level loop's 76, the level `while`, and the three NaN-seed constant/broadcast ops `forward_prepared` emits per query), 5 are the two loop conditions plus the output read-out, and the rest is this node's force/dynamics/reward/carry update; 88 % of a generation's ops run inside the rollout region, and leaf kernel bodies are ≈42 % of the wall time against ≈58 % interpreter per-op work.
The prepared pass hoists a 58-op per-query prelude (`_padding_safe_attrs`, `_hit_conn_attrs`' `(P,N,K,CA)` gather, `_slot_index`, `_output_row_mask`, `_depth_limit`, the NaN seed) once per generation, and `repeat_times > 1` is its tiled-sample case: the pass is derived for `B = P * R` rows while the schedule and the payload stay at `P`, so the genome's sample expansion (`genome/window.py::by_samples`) is paid once and is the identity at `R=1`.
Pipeline level (`pop_batch_size` unset, one generation per `step`, numpy): the genome `transform` + `forward` inside `act_fn` is 80–90 % of a generation's evaluate share and this node's rollout is the rest — 6–18 % of it for `CartPole`, 9.9 % for a six-node-hidden `Pendulum`, 17.5 % for `MountainCarContinuous` — so a continuous-control generation is genome-forward-bound, not rollout-bound (`../CONTEXT.md` holds the per-cell rows).
Numeric agreement (`P=100`, one key, same toy policies): iree vs numpy per-individual fitness differs only by float32 rounding (`max_rel` 1.2e-6 Pendulum 200 steps, 4.1e-7 MountainCar 200, 1.8e-6 MountainCar 999), and against a host-numpy **float32** transcription of the documented recurrence fed the graph's own initial states both continuous environments are bit-identical (`max_abs = 0`) at `max_step` 60, 200 and 999.
Cross-backend fitness is therefore reproducible to float32 rounding but never bitwise, and no test may assert cross-backend trajectory equality.

## Notes for Agents
- `CartPole.show` computes the survival length only for a finite return (`math.isfinite`), so a NaN-poisoned policy prints `survived n/a (NaN return), return nan` instead of raising from a bare `int(round(...))`; the final-state and mean-return lines print `nan` too.
- Dead in `src/`: `_CartPoleConstants.masscart` is built but never read (only the derived `total_mass` is), and `_terminated` (`cartpole.py`, `mountaincar.py`) has no caller outside `test/unit/problem`.
- Duplication: the three `show` methods repeat one ~45-line skeleton (`TensorSpec` → `report` closure over `_rollout(..., 1)` → `build`/`run` → `to_numpy` → per-repeat print), and the three `_rollout`s repeat `consts → batch → prepared_query → reset → init → while_loop → return`; they differ only in carry arity, constant bundle and printed lines.
- **`evoxc.remainder` is not backend-consistent**: numpy implements floor-mod while `stablehlo.remainder` (and hence `iree`) is `fmod`, so an `angle_normalize` written with it wraps `-3pi` to `-3pi` instead of `-pi` on iree and inflates the cost by 2.4× while numpy looks perfect; the floor form is bit-identical on both, and the mismatch (`evoxc/ops/elementwise.py` documents "sign of the dividend") is worth an upstream report.
- **MountainCarContinuous's reward is deceptive**: `a -> 0` (any small-weight policy) returns exactly `0`, an aggressive constant policy returns `-0.1*max_step`, and only a bang-bang energy-pumping policy reaches the goal (`a = sign(velocity)` at `P=8` returns **90.8**, min 89.1, at both 999 and 200 steps — which also proves the `100` bonus is paid exactly once).
  NEAT nonetheless converges to the idle policy: `pop=100`, `species_size=10`, 12–20 generations, `max_step` 200/300/999, with and without `init_hidden_layers=(6,)`, all ended at `-0.007 … -0.0` and never the goal bonus — task semantics, so pick a target near `-0.5` for a demo that terminates or budget far more generations for the bonus.
- **Pendulum needs a hidden layer to learn quickly**: `pop=100`, `species_size=10`, `max_step=200`, `init_hidden_layers=()` plateaus at `-527` (best of 40 generations, seed 42), while `init_hidden_layers=(6,)` reaches the `-300` target at generation 5 of 20 with a training max of `-271.30` in 2.7–2.9 s wall, for ≈2× the genome forward (see `examples/rl/CONTEXT.md` for both shipped demo configurations, which end at generation 5 / the 10-generation limit with `show` reporting `-595.12` and `-0.00` respectively).
- `MountainCarContinuous.show` reports the goal as `return > 0` rather than `return >= 100 - eps`, since a solving episode returns ≈89–91 (hence `ATTAINABLE_CEILING = 93.0`); a non-finite return compares false, so the indicator reads `goal n/a (NaN return)` with the return still printed.
- CartPole specifics worth not re-deriving: the `_loop_body` insertion order is load-bearing (`_nan_rows` selects the NaN into `total` **before** `alive` is updated, so a poison arriving on the step an episode dies still lands); `evoxc.scan` is **not** export-blocked on iree for this kernel (its output is rank-1), `while_loop` is simply the cheaper form because it drops the stack.
- `_common.py` validators take the **owner name first** (`require_positive_int("Pendulum", "max_step", value)`) so the message shape matches `CartPole`'s original text exactly; a non-numeric or non-finite knob reports `"{owner}: {name} must be a finite number, got {value!r}"`, while a finite out-of-range one keeps the pinned `must be positive`/`must be non-negative` text.
- This node's reference oracle for the two continuous environments is a float32 host transcription (in `test/unit/problem/`, owned by the test agent); ordering decisions a test can break: the Pendulum clip happens before the angle update, the MountainCar penalty uses the **pre-clip** action, the min-position velocity reset uses exact float equality, and the bonus is masked by the pre-step alive flag.
- `backend="iree"` runs a full `Pipeline` end to end (`test/backends/test_iree_pipeline.py` drives `Pipeline(backend="iree")` through `setup` plus two `step`s), so the measurements above are a component record, not a pipeline verdict (`benchmarks/BACKENDS.md` holds the llvm-cpu ratios and the per-shape `iree-compile` cost).
