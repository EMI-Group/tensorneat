# tensorneat/common — host primitives, batched tensor helpers, the tensorization engine, ACT/AGG registries, sympy codegen

## Intent
Framework-wide foundation: the immutable `State` container, the error hierarchy, the batched flat gather/scatter helpers every kernel is built from, the **execution schedule** turning a ragged evolved topology into static-shape arrays (host and accelerator formulations of its two writes, selected at trace time by `kernel_mode`), the ACT/AGG registries and host-side sympy code generation.
Nothing here imports `genome`, `algorithm`, `problem` or `pipeline` — this node is the bottom of the package dependency DAG.

## Dtype & sentinel contract (binding for genome / algorithm / problem)
The payload is **split by dtype**: `node_keys (P, max_nodes) int32`, `node_attrs (P, max_nodes, A) float32`, `conn_keys (P, max_conns, 2..3) int32` (`(in_key, out_key)` first, optional historical marker third), `conn_attrs (P, max_conns, W) float32`.
Absent key rows are `I_INF`, absent attribute values `NaN` (the pre-rewrite NaN padding survives in the attribute arrays: `isnan(attrs[..., 0])` means "row unused").
Keys are `int32` in `[0, KEY_MAX)` with `KEY_MAX = 2**24`; a key outside that range, or two nodes with the same key, is a caller bug (`ConfigError`).
One integer sentinel only: `I_INF = 2147483647` (`int32` max) = "no index / unmatched / unavailable", in integer arrays only, never mixed with `NaN` in one array.
evoxc has **no bitcast op** (`cast` is numeric only), so a mixed-dtype gene row is impossible and the payload is split; keys stay `int32` so absence is exact and `key_span` really is a key-magnitude bound.
Int-valued genes (activation/aggregation option positions) therefore live in the float attributes, stay integral and are cast with `cast(..., int32)`; in-graph gene identity uses the **key columns** with `equal`, never a row hash.
`derive_schedule` accepts **either** key spelling: `int32` with `I_INF` padding (canonical — the payload and every kernel) or `float32` with `NaN` padding (the pre-rewrite/parity spelling `test/support/oracle.py` uses); a trace-time `if` on a static dtype (`_key_present`): `keys != I_INF` for integer keys, `isfinite(keys) & (keys < KEY_MAX)` for float keys.
**Graph dtypes are signed only** (iree's set is float16/32/64, int8/16/32/64, bool): no `uint*` in any operand, result or constant — use a same-width signed carrier and flip the sign where unsigned order matters (`tools.hash_rows` is the one exception, host-only numpy, never traced).
So a range test `key ∈ [0, key_span)` is two signed comparisons in the key's own dtype, one op more than a `cast(keys, uint32)` comparison that cannot be lowered to iree.

## Execution schedule contract (`Transformed`)
`tensorization.derive_schedule(...)` is one `@evoxc.defn` graph; its output is a pytree of arrays only (**no Python statics inside** — every static fact is implied by a shape or a dtype).
Runtime inputs, batch-first: `node_keys (P, N)`, `conn_in (P, C)`/`conn_out (P, C)` endpoint keys of the same dtype and padding, plus the batchless `input_keys (I,)`/`output_keys (O,)`.
Statics are positional-or-keyword (`evoxc.build` mirrors a positional call): `pop_size P`, `max_nodes N`, `max_conns C`, `max_in_degree K`, `key_span S` — the Pipeline's shape signature and therefore the executable-cache key — plus trailing `acyclic=False` (caller assertion that the population holds no cycle) and `kernel_mode="host"` (the formulation static).
Fields, all batch-first, in `Transformed` (a `typing.NamedTuple`, twelve leaves in this order):

| field | shape | dtype | meaning |
|---|---|---|---|
| `src` / `dst` | `(P, C)` | int32 | source / destination node slot of a connection row; `I_INF` = absent row or unmatched key |
| `edge_valid` | `(P, C)` | bool | real conn row AND both endpoints matched |
| `in_conn` | `(P, N, K)` | int32 | conn row index of the k-th incoming edge of node `i`; `I_INF` padding |
| `in_src` | `(P, N, K)` | int32 | source slot of that edge; `I_INF` in the same positions |
| `in_valid` | `(P, N, K)` | bool | that window slot holds a live edge |
| `node_level` | `(P, N)` | int32 | longest-path depth from the inputs (inputs = 0); `I_INF` = absent, unreachable or on/after a live cycle |
| `node_exists` | `(P, N)` | bool | the node row is present |
| `topo_key` | `(P, N)` | int32 | `node_level * N + slot`, a total order for a topological sweep; `I_INF` where the level is |
| `input_slot` / `output_slot` | `(P, I)` / `(P, O)` | int32 | node slot holding input `j` / output `j` in the pinned key order; `I_INF` if unmatched |
| `edge_overflow` | `(P,)` | int32 | valid edges dropped because their in-group rank reached `K` |

`level`/`overflow` are read-only properties (`level` → `node_level`, `overflow` → `edge_overflow > 0`) kept for the pre-rewrite callers and the numpy oracle; new kernels use the stored names.
`Transformed` is a plain `typing.NamedTuple` with **no `evoxc.register_pytree_node` call** (only `State` registers, in `state.py`): evoxc's namedtuple branch flattens it to exactly those leaves in field order, so `tree_map`/`tree_leaves`/`host_payload._slice_batch` never visit the properties; `test/unit/common/test_tensorization.py::DOCUMENTED_FIELDS`/`DOCUMENTED_DTYPES` pin the order and dtypes.
Invariances: `in_conn`/`in_src`/`in_valid` mark the same positions and a node's columns `0..d-1` are dense; every `edge_valid` row appears exactly once in the window unless its in-group rank reached `K` (counted in `edge_overflow`); a node with `in_valid[..., 0] == False` has no incoming edge; `reduce_max(node_level)` bounds the execution loop and levels `0, 1, ...` are a valid topological order with independent nodes per level; `src`/`dst` are *slots within one genome's own arrays*, never innovation numbers.
`edge_overflow > 0` means the schedule is lossy for that genome — host code must rebuild with a larger `max_in_degree` (or raise `ShapeBoundError`); kernels never silently drop edges.

## Derivation recipe (validated field by field against `test/support/oracle.py::schedule`)
1. dense key→slot table `(P, S+1) int32` (trailing column = write dump), one flat scatter over the node keys (`key_slot_table`, **host formulation only**; the accelerator route resolves keys by equality instead).
2. `src`/`dst` = gathers from that resolver with sanitized keys (`absent -> 0`, clamped to `[0, S-1]`); `edge_valid = row present & hit`; `node_exists` from the node key column.
3. `edge_order` — **one** stable `argsort` of the combined `(edge key 2*dst, node key 2*slot + 1)` array, in the narrowest signed carrier that holds its `2N + 2` sentinel (`int8` up to N=62, `int16` up to N=16382, else `int32`); its **output** cast once to `int32` is `order` (position → entry id, entries `< C` being connection rows in `(dst, connection index)` order).
4. `cc[i]` = valid edges with destination `<= i`, computed as `inv[C + i] - i` (one `(P, C + N)` scatter, host) or by counting that predicate (`cumulative_indegree`, accelerator); `start[i] = cc[i-1]` (0 at `i = 0`), `deg[i] = cc[i] - start[i]`, and node `i`'s in-edges sit at positions `start[i] + i + k` for `k < deg[i]`.
5. `in_conn`/`in_src` = two gathers at that `(P, N, K)` block, masked to `I_INF` where `k >= deg[i]`; `edge_overflow = reduce_sum(max(deg - K, 0))` (data, not an exception); `in_valid = in_conn != I_INF`.
6. `node_level` = `while_loop` longest-path relaxation over the `(P, N, K)` table, inputs pinned to 0, narrowest carrier dtype: the default runs the level-only relaxation (cap `N`) and tests **in-graph** with `evoxc.cond` whether any valid edge violates `level[dst] > level[src]` (no violation ⇔ acyclic, answer exact; else the two-relaxation fallback, cap `2N`, reports every node on/after a live cycle as `I_INF`), while `acyclic=True` returns the level-only answer and drops both.
   The trip predicate is formulation-dependent: `"host"` stops at the fixpoint (`step < cap and changed`, `changed` a loop-carried `reduce_max`), `"accelerator"` carries no flag and runs all `cap` trips on `step < cap` alone — bit-identical because both bodies are idempotent at their fixpoint; `_cycle_violation`'s `cond` stays data-dependent on purpose (its branch is a whole second campaign).
7. `topo_key = node_level * N + slot` (`I_INF` where the level is) and the `input_slot`/`output_slot` gathers are then free.

Cost `O(P * (S + C log C + N*K*D))` with `D` = max depth, i.e. edge-proportional except the `N*K` padding and the one-off `key_span` table; **no `cumsum`, no unsigned dtype, no scatter-with-reduce, no `max_nodes**2` matrix**.
`transform` runs once per generation: `derive_schedule` is ~3–5 % of one `Pipeline.step` (XOR, pop 500–1000) and `node_levels` ~40–45 % of it at the real `(500, 50, 4)` window, so schedule-local work moves a generation by ~1 %.
A change here needs a field-by-field diff against the implementation it replaces (feed-forward, cyclic, in-degree > `K`, absent nodes, unmatched keys, both key spellings, both `acyclic` settings): the suites do not pin bit-exactness of every field.

## `node_levels` loop trips, measured (numpy interpreter, `benchmarks/cases.py` geometry, seed 42, 20 generations)
The fast campaign's body executions are exactly `max_over_population(node_level) + 1`: `D+1` in all 80 measured generations of `xor_p100`/`xor_p500`/`xor3d_p500`/`custom_pagie_p500`, never `D+2`, and the loop's final `step` carried value equals the trip count.
Trips stay at 2–7 against the `max_nodes = 50` cap (`xor_p100` median 4 max 5, `xor_p500` 6/6, `xor3d_p500` 6/7, `custom_pagie_p500` 4/5) because those populations carry only 3–9 live nodes and 2–10 live connections of the 50/100 slots.
The cycle-detecting fallback is not traced at all on the shipped `DefaultGenome` path (`BaseGenome.transform` passes `acyclic = network_type == "feedforward"`), so neither `_cycle_violation` nor the `2*max_nodes` campaign costs anything there; on `RecurrentGenome` (`acyclic=False`) the fast campaign saturates its `max_nodes = 50` cap every generation and `_cycle_violation` fires on 19 of 20 generations, the fallback then running exactly `2*max_nodes = 100` trips (no early exit: `reach` grows until the cap).
One iteration costs 24 dispatched ops — 21 of the 22 traced body ops plus 3 in the 4-op condition region (`constant`/`less`/`logical_and`) — so a generation is `24 * trips + 3` dispatches (147 at 6 trips, 123 at 5): 2.6 % of `xor_p100`'s 5 591 dispatches, 1.8 % of `xor_p500`/`xor3d_p500`'s 8 189, 1.0 % of `custom_pagie_p500`'s 12 674.
The body's op count scales with `max_in_degree` (22 traced ops at `K = 4`, 46 at `K = 16`) because the window fold is one `slice`/`maximum` pair per slot.
Accelerator consequence (157 µs per data-dependent-condition iteration against 57 µs per host-counted one, `benchmarks/spikes/rocm/CONTEXT.md`): dropping `changed` freezes the trip count at `max_nodes`, turning 0.6–0.9 ms of loop cost into 2.85 ms on every shallow feed-forward case (+1.9 to +2.2 ms per generation, ~+14–21 % of the 10.5/13.6 ms ungated ROCm `xor_p100`/`xor_p500` walls) — a loss — while on the `RecurrentGenome` path it is a win (150 iterations at 157 µs = 23.6 ms against 8.6 ms static, −15 ms per generation).
Break-even is `cap < 2.75 * trips_today`, i.e. a static cap near `max_depth = 16`, not `max_nodes = 50`; such a change stays on the accelerator leg, so the numpy graph keeps `changed` and these bit-exact trip counts.
`node_levels` is this node's **only** control flow: the `evoxc.cond` mention in `functions/agg.py` is prose about why the aggregation dispatch is a `select` cascade, and `functions/` picks fold-vs-reduce on a trace-time `if` over the static window width.

## The schedule's two writes and their two formulations (`kernel_mode`)
`derive_schedule` makes exactly two table writes: `key_slot_table`'s dense key→slot scatter (`P*N` updates) and `edge_order`'s inverse permutation (a `(P, C + N)` flat scatter yielding `cc`); `incoming_table` writes nothing — it gathers its `(P, N, K)` window out of the sort permutation.
On a compiled backend a write is the expensive shape: `evoxc` lowers every `scatter` to **one workgroup of one thread**, measured at 17–21 ns per *update* element independent of destination width, while `gather`, elementwise ops and reductions spread over the whole grid. At `xor_p500` the two writes are 75 000 and 25 000 serialised cells, 1.40 ms and 0.55 ms of the generation.
`schedule_accelerator.py` is the scatter-free spelling of both, selected by the static host string `state.kernel_mode` through `schedule_accelerator.kernel_mode(state)` (`KERNEL_MODE_KEY`); `"host"` is what a state without the entry gets, `("host", "accelerator")` is the whole vocabulary (`KERNEL_MODES`), anything else raises `ConfigError` at trace time.
`key_template(node_cells, node_visible, rows)` replaces the dense table: one broadcast `equal` of the `(P, L, 1)` query cells against the `(P, 1, N)` node cells, `select(match, slot_of_row, -1)`, `reduce_max` over the node axis; invisible node rows become `_NO_NODE` (-2), invisible queries `_NO_QUERY` (-1), a miss answers `I_INF`.
`cumulative_indegree(dst, edge_valid, max_nodes)` replaces the inverse permutation: `edge_valid & (dst <= iota)` over a `(P, C, N)` table reduced over the edge axis to `cc (P, N) int32` — the same number the host form reads out of `inv[C + i] - i`, so `edge_overflow` and every window position agree.
Bit identity, not near-equality: both routes consume the same sanitized `int32` cells (`tensorization._key_indices`), so they cannot disagree about which keys are visible; the dense table's flat write leaves the **highest** slot at a cell two node rows name (also covering two `float32` keys truncating to one integer cell) and `reduce_max` returns that same slot; `cc` is a count in both routes (108 field-by-field `Transformed` comparisons and ten seed-42 generations hash identically in both modes).
The switch is a host `if` on a static string, never on a traced value, so a graph holds one formulation; the `argsort` stays in both, because `order` is what `incoming_table` gathers through.
On the numpy interpreter the accelerator formulation is the **slower** one (`xor_p500` 117.39 → 134.33 ms per generation, +14.4 %, at the same dispatched-op count) because it trades a serialised write for an `(P, L, N)` element volume numpy pays in full; `"host"` stays the default and `Pipeline.setup` asks for `"accelerator"` only on a GPU-class device kind (`host_payload._formulation_statics`).
Neither formulation needs a `cumsum` (a StableHLO export deferral), an unsigned dtype, or (in accelerator mode) any scatter, and `iree-compile` succeeds in both modes on `llvm-cpu` and `rocm`/`gfx942`.

## Forward-side contract (consumed by `genome`)
Per level `l = 0 .. reduce_max(node_level)`: `mask = in_valid & ~isnan(gathered source value)` (the legacy `conn_exists & src_valid`); gather each conn gene attribute from the flattened `(P, C*attrs)` payload with `tools.masked_flat_gather` at `in_conn`, and the source values at `in_src`; `z = functions.agg.apply_aggregation(contribs, mask, agg_ids)` (a static `K`-plane fold, never a `reduce_*`); `new = functions.act.apply_activation(z, act_ids)`; `vals = select((node_level == l) & valid_count > 0, new, vals)` with `valid_count = reduce_sum(in_valid, -1)`.
The per-node `valid_count` guard matters: a node whose incoming edges are all invalid keeps `NaN` (legacy behaviour relied on `lax.cond(has_valid, ...)`).
Kernels must never index outside `[0, size)` — evoxc's numpy backend **raises** where JAX clamped, so clamping plus masking is mandatory (`trusted=True` stays opt-in, only where the range is proven).
The mandatory `select(mask, z, 0.0)` on `(P, N, K)` cannot become a masked multiply (a dead slot may hold `NaN`/`±inf`, whose product with `0` is `NaN`), so the aggregation passes remain the term to attack on a level.

## API Surface
### `state.py`
`State(**kwargs)` — immutable host container over a dict; `register/update/remove` return new `State`s (raising on duplicate/missing keys); `__getattr__` raises `StateKeyError`, `__getitem__` the plain `KeyError`; `save`/`load` pickle it; `tree_flatten`/`tree_unflatten` + `evoxc.register_pytree_node` let it cross a graph boundary.
`StateKeyError(AttributeError, KeyError)` is the one dual-base exception here: `AttributeError` is what `copy.deepcopy`'s instance probe and `hasattr`/`getattr(state, name, default)` need, and what `Pipeline._shape_signature`'s `getattr(state, "pop", None)` probe needs to reach its documented `TensorNEATError`; `KeyError` keeps the legacy `except KeyError` around `state.pop_size` in `genome/base.py::_resolve_pop_size` (`copy.copy`/`pickle` were never a reason).
The price: `hasattr(state, "typo")` answers `False` instead of propagating, so a typo is loud only at a bare read, an explicit `except`, or `state["typo"]` (plain `KeyError`); writing a new key is refused by `__setattr__`.
`StatefulBaseClass` (`stateful_class.py`) — `setup(state) -> State` plus a generic `show_config(registered_objects=None)` that nothing calls.

### `errors.py`
`TensorNEATError(Exception)` root; subclasses `ConfigError` (a user value violates the contract: non-positive statics, duplicate/out-of-`KEY_MAX` keys, mismatched input/output counts, a registry miss), `ShapeBoundError` (a static bound was exceeded: `max_in_degree`, `key_span`, `max_conns`), `GraphError` (cycle where feedforward is required, missing input/output node). Backend/shape errors from evoxc are **never** re-wrapped; only validation raises these, on the host before a graph is traced.

### `tools.py`
Sentinels `I_INF`, `KEY_MAX`; flat-index plumbing `batch_offsets(pop_size, row_len)`, `prepare_flat_index(x, idx, present=None, fallback=0, trusted=False)` (the reusable `(P, n)` flat index block), `flat_gather_prepared(x, flat_idx, shape)`, `flat_scatter_prepared(x, flat_idx, updates)`, `flat_gather(x, idx, trusted=False)`, `masked_flat_gather(x, idx, mask=None, fill=nan, trusted=False)`, `flat_scatter(x, idx, updates, trusted=False)`, `masked_flat_scatter(x, idx, updates, mask, trusted=False)` (dump-slot routing); selection `fetch_first(mask, default=I_INF)`, `fetch_random(key, mask, default=I_INF)`, `rank_elements(x, reverse=False)`, `argmin_with_mask(arr, mask, *, filler=None, default=None)`; standalone `mutate_float(...)`/`mutate_int(key, val, options, replace_rate)` (the genome path is `genome/gene/blocks.py::mutate_attrs`; evoxc has no `random.choice`, so an option set is gathered at `randint`); `to_numpy(tensor)`; `hash_rows(rows)` — host-only numpy xor-mix over a row's bytes, folded over the numpy payload by `genome/host.py::BaseGenomeHost.hash`; the package has no in-graph hashing op (evoxc has no bitcast).
`to_numpy` is the single explicit device-to-host step (logging, checkpointing, the read-back of `Pipeline._place_state`'s cross-device hop): an `ndarray` returns unchanged, a device tensor (`.device.kind != "cpu"`) transfers with `Tensor.to(Device("cpu", 0))` first, and `evoxc.Tensor` deliberately has **no** `__array__`.
Every flat-index helper takes `trusted=False`, whose escape guard (`select` + comparisons + redirect select) makes the backend **raise** on an out-of-range index instead of reading a neighbouring row; `trusted=True` skips it only where every index is *proved* inside `[0, R)`, never on unbounded data.

### Hoistable sentinels (`tools._sentinel_constant`)
Every sentinel is a rank-0 `constant` **op**, not a bare Python scalar, because a bare scalar is weakly promoted and changes the `select`'s result dtype (`_scalar_constant` owns that rationale); evoxc has no constant CSE, so two identical sentinels are two ops.
That op is charged per call, so a helper inside a `scan`/`cond`/`while_loop` body pays it once per iteration. `_sentinel_constant(value, fallback, dtype)` makes it hoistable: `None` builds `fallback`, a Python/NumPy number builds a rank-0 constant of `dtype`, any other object is returned **verbatim** (no cast, no reshape).
A supplied constant whose dtype differs from `dtype` raises `ConfigError` at trace time — `evoxc.select` promotes silently, so a `float64` filler would widen the `argmin` input and an `int64` default would change the returned index dtype.
`fetch_first(mask, default=I_INF)` takes an optional pre-built `int32` constant for `default`; `argmin_with_mask(arr, mask, *, filler=None, default=None)` takes them for the masking `+inf` (of `arr.dtype`) and the `I_INF` "no candidate" index; `None` keeps the one-shot spelling op for op, and "unset" and "no candidate" read the same `I_INF`.
Measured (numpy, one small `scan` body calling both): one-shot 3 `constant` dispatches per iteration, hoisted 0, bit-identical outputs. The intended hoister is `algorithm/neat/_kernels.py::speciate` (≈60 dispatches per generation at `species_size=20`); no hoistable spelling exists for `prepare_flat_index` (up to three constants) or `fetch_random`, and `batch_offsets` is the cheapest to hoist caller-side.

### `tensorization.py`
`Transformed`; `derive_schedule(...)`; `edge_order(dst, edge_valid, max_nodes, max_conns, kernel_mode="host") -> (order, cc)`; the private `_key_resolver(node_keys, key_span, kernel_mode)` is the **one selection point** of the key-resolution formulation (dense table built lazily for `"host"`, none for `"accelerator"`), and both routes are addressed by `_key_indices`'s sanitized `int32` cells so they cannot disagree about which keys are visible.
Individually testable steps: `key_slot_table(node_keys, key_span) -> (P, S+1) int32` (trailing dump column, one `masked_flat_scatter`), `slot_lookup`/`_slot_of` (sanitized index, gather, `I_INF` on a miss), `edge_order`, `incoming_table(order, cc, src, max_nodes, max_in_degree) -> (in_conn, in_src, edge_overflow)` (two gathers at the `start[i] + i + k` block, `trusted=True` bounded by `inv[C + i] - 1 <= C + N - 1`), `node_levels(in_conn, in_src, input_slot, max_nodes, acyclic=False, edges=None, kernel_mode="host")` where `edges` is the `(src, dst, edge_valid)` triple the cycle test needs (`ConfigError` when `acyclic=False` and it is missing) and the new trailing static is the same formulation switch `derive_schedule` already resolved (`ConfigError` on a value outside `KERNEL_MODES`).
Also `validate_schedule(transformed)` (host-side invariant checker, called by the unit tests and `genome/grad.py::build_grad`) and the trace-time helpers `_key_indices`, `_key_present`, `_narrow_int`, `_node_slots`, `_iinf_like`, `_carrier`, `_cycle_violation`, `_pinned_mask`; the narrow carriers are a contract detail, not a knob (smallest `int8`/`int16`/`int32` holding every reachable value *and* its "after everything" sentinel, cast back to `int32`).

### `schedule_accelerator.py`
`__all__` is exactly `KERNEL_MODE_KEY`, `KERNEL_MODES`, `cumulative_indegree`, `is_accelerator`, `kernel_mode`, `key_template`, `resolve_mode`; `_DEFAULT_KERNEL_MODE = "host"` is the private fallback, `_NO_QUERY = -1`/`_NO_NODE = -2` the two masked cells.
`kernel_mode(state) -> str` is the plain attribute read every kernel uses (`getattr(state, KERNEL_MODE_KEY, "host")`, no graph op, identical inside and outside a trace); `resolve_mode(mode) -> str` is the one validation (`ConfigError` on anything else, so a typo fails loudly instead of silently selecting the other route); `is_accelerator(mode) -> bool` the comparison helper.
`key_template(node_cells, node_visible, rows)` returns a callable `resolve(query_cells, query_visible) -> slots (P, L) int32` with exactly `_slot_of`'s contract (`I_INF` on a miss); it validates every shape pair at trace time and materialises one `(P, L, N)` compare/select/reduce table — no scatter, no permutation, no `iota`.
`cumulative_indegree(dst, edge_valid, max_nodes) -> cc (P, N) int32` validates `max_nodes` via `_positive_static` and `edge_valid` against `dst`'s shape; `I_INF` destinations fail `<= i` and are masked by `edge_valid` too, and `cc <= C`, so `int32` cannot overflow.
`common.__init__` re-exports **only** `kernel_mode` from this module; `tensorization` imports `cumulative_indegree`/`is_accelerator`/`key_template`/`resolve_mode` directly, and `genome/base.py::transform` passes `kernel_mode(state)` as `derive_schedule`'s trailing static, so a real run traces whichever formulation the state names (the entry is in the executable-cache formulation signature, so a mode change rebuilds exactly once).

### `functions/`
Exports exactly `ACT`, `AGG`, `FunctionManager`, `apply_activation(z, act_ids, act_fns=ACT_FUNCS)`, `apply_aggregation(values, mask, agg_ids, agg_fns=AGG_FUNCS)`: 12 activations and 6 aggregations in a fixed, parity-critical order; activations are elementwise, aggregations reduce the last axis of a `(P, N, K)` contribution tensor with neutral padding and are `NaN`-aware through `mask`; `ACT.name_of`/`AGG.name_of` are the reverse lookups. `functions/CONTEXT.md` owns the dispatcher recipes.

### `host_graph.py`
Host-only, pure Python (stdlib + `errors.GraphError`, deliberately backend-free — it keeps its own `_I_INF` literal rather than importing `tools`, which pulls in `evoxc`), never traced: `decode_graph(nodes, conns, node_attrs=1, conn_attrs=2)` → `(dict[int, tuple[float, ...]], set[tuple[int, int]])`; `topological_sort(nodes, conns)` → `(topo_order, topo_layers)` (Kahn, layers ascending, `GraphError` on a cycle); `find_useful_nodes(nodes, conns, output_idx)` → `set[int]`; `check_cycles(...)` → `bool`; `node_depth(nodes, conns, input_idx)` → `dict[int, int]`, which must equal `Transformed.node_level` for a well-formed feedforward genome.
`common.__init__` re-exports `decode_graph`, `topological_sort`, `find_useful_nodes`; `host_graph.__all__` also lists `check_cycles` and `node_depth`.

### `sympy_tools.py`
Host-only (`re` + `sympy` + a deferred `numpy` import): `analysis_nodes_exprs`, `round_expr`, `replace_variable_names`, `to_latex_code`, `to_python_code` — the 8-tuple contract of `Genome.sympy_func`, taken **unpacked** (`to_latex_code(*genome.sympy_func(state, network))`), where `symbols`/`topo_order` key by node **keys**, `nodes_exprs`/`output_exprs` by sympy Symbols and `forward_func` is for signature compatibility only.
`to_python_code` emits module-level source, never a `def` (`import numpy as np`, a header binding the caller's array `i`, `h = np.zeros(hidden_cnt)`, `o = np.zeros(...)`, one assignment per useful node, a closed-form `# o[k] = ...` block); `_NumPySourcePrinter` (a `NumPyPrinter`) makes it callable, folding `Max`/`Min` to right-nested `np.maximum`/`np.minimum`, `Piecewise` to an eager `np.where` chain (correct because every shipped branch is total) and an unregistered `sp.Function` by class name (`SympyClip` -> `np.clip`, `ConfigError` when NumPy lacks it).
All 18 per-option snippets exec and match their kernel to ≤2.5e-7 absolute, the one divergence being `exp` (its emitted `np.clip(z, -10, 10)` against the unclipped kernel beyond ±10); `round_expr` never collapses a real constant to zero, so `LOG_EPS`/`INV_EPS` (1e-7) survive as `1.0e-7` while `123456789/10**9` renders `0.123457` at `precision=6`.
Per-option runnability is hand-verified only; not re-exported by `common.__init__`.

## evoxc idioms, cost laws and gotchas
- `@evoxc.defn` + `evoxc.build(fn, *TensorSpec, backend=..., device=...)`; the numpy reference interpreter is the default and is enough for `test/unit`. An `@evoxc.defn` object is not callable: use `.fn` (tests bind it with `functools.partial`) or `evoxc.build` the `Defn` itself.
- `evoxc.numpy as enp` for in-graph constants (`enp.zeros/ones/full/arange`), `evoxc.constant(evoxc.tensor(ndarray))` for host data; dtypes come from `evoxc.int32/float32/...`, **not** from `enp`.
- `gather(x, idx, axis)`/`scatter(x, idx, upd, axis)` **replace** the indexed axis (not `take_along_axis`), so per-row indexing goes through the flattened helpers (`flat = row * R + col`); `P*R` must stay inside `int32`, `scatter` is set-only, and reductions have no `where=`/`initial=` (pad with the neutral element first).
- **`argsort(kind="stable")` has a radix fast path for `int8`/`int16` and a slow general path for `int32`/`int64`**: `(1000, 250)` costs 7.4 ms as `int32`, 1.0 ms as `int16`, 0.62 ms as `int8`, so anything sorted is keyed in the narrowest dtype that fits its range *including* the sentinel; the output is int64 and its inverse permutation is a `flat_scatter` of `arange(n)`.
- `evoxc.cond` accepts a `while_loop` in each branch on the numpy backend (both traced, one executed), so "fast path + expensive fallback" is expressible in-graph; control-flow bodies keep fixed shapes/dtypes, the condition is a scalar tensor, and no `vmap` may be applied over them.
- No `broadcast_to` on `evoxc` (use `enp.broadcast_to`), no `searchsorted`, no `choice`, no `bitcast`, no `where` (it is `evoxc.select(pred, on_true, on_false)`); `evoxc.slice(x, start, lengths)` takes per-axis tuples.
- Cost laws measured on this box (this tree): one dispatched op costs ≈19–20 µs on the numpy interpreter at population-sized tensors, so at these shapes **executed op count is the lever**; a flat graph on iree+rocm pays ≈63 µs fixed + ≈2.2–2.5 µs per dispatch, a `while` iteration costs **≈157 µs when its predicate is device data vs ≈57 µs when it is a counter against a static constant** (both saturated by a 20–60-op body), and `Tensor.to(cpu)` a fixed ≈47–60 µs per leaf regardless of size.
- Executed dispatches per generation on this tree (numpy, `kernels.dispatch` monkeypatched): `xor_p500` 7 592, `cartpole_p100` 30 994; `derive_schedule` alone is ≈650 of the former.
- **Executed-op count is not a proxy for wall time at this level**: a value- and work-identical 17-op trim of the derivation tail (faster in isolation, 6.66 → 6.47 ms) cost +34 % of one `Pipeline.step` at pop 1000, non-linear in `P` — measure `Pipeline.step` end to end in fresh interleaved processes before landing a "free" removal. Build once and time `evoxc.run` only (one cell per **fresh process**; a second executable skews later cells up to 25 %) and report a paired ratio, since absolute milliseconds move ~30 % between sessions.
- `node_levels` is at its op floor: `reduce_max` over `K` instead of the pairwise fold is 1.52× worse, two relaxation sub-steps per trip 1.21× worse (and not value-identical on a cyclic payload), dropping the per-trip `(P, N)` dump-column `concatenate` 1.17× worse; dense max-plus, one-hot prefix counting and static unrolling are all slower, and per-member `cond` is inexpressible.
- The accelerator leg's static trip count is a **trade, not a free win**: it removes the ≈157 µs per-iteration readback but runs `max_nodes` trips of the fast campaign whatever the settled depth (measured `xor`-geometry payloads: 20 host trips for a depth-18 random population, so 50 fixed trips only pays from ~18 settled iterations up, and a shallow depth-5 population loses ~2 ms); the fallback campaign is the clear win (host 102 trips × 157 µs against 100 × 57 µs). Measured at `N = 50, K = 4`, bodies are 19 (fast) / 39 (fallback) dispatches on the host leg against 17 / 35 on the accelerator leg, and executed dispatches for the same payload go 322 → 428 (no cycle) and 1 078 → 1 036 (with a cycle, the body trim paying for the extra trips).

## Scatter portability on `backend="iree"` (IREE 3.11/3.13)
**One index value feeds exactly one scatter.** `evoxc`'s StableHLO writer emits a flat write (`tools.flat_scatter_prepared`, `tools.masked_flat_scatter`) as a rank-1 axis-0 scalar-window scatter; IREE lowers it to `iree_linalg_ext.scatter`, whose `ins` wants the index tensor collapsed to rank 1, and performs that collapse inside `iree-stablehlo-to-iree-input` as an `unrealized_conversion_cast`.
When the same index SSA value (an explicitly shared block *or* two expressions IREE's CSE merges) feeds a **second** scatter, that materialization stays live and the pass aborts: `failed to legalize unresolved materialization from ('tensor<nx1xi32>') to ('tensor<nxi32>') that remained live after conversion`, at the second scatter's source location. One scatter with the same shapes compiles at any size, so the emitted form is fine — this is contextual, not a bad spelling.
Consequences: the **host** formulation of the schedule needs exactly **two** scatters, each through its own index expression (`key_slot_table`'s table, `edge_order`'s inverse permutation), the **accelerator** formulation needs none, and `incoming_table` writes nothing in either mode; a caller that must fill several payloads in the same cells uses one wider buffer and one call.
Minimal reproducer: `P, R, N = 4, 68, 32`; `block = tools.prepare_flat_index(x, idx, trusted=True)`; both `tools.flat_scatter_prepared(x, block, u1)` and `(..., u2)` abort with that message (`tensor<128x1xi64>` → `tensor<128x1xi32>`); with only the first call it compiles.

## Constraints
- No `jax`/`torch`/`numpy.random` in graph code; randomness is `evoxc.random` stateless keys (`key(seed)`, `split`, `randint`, `uniform`, `normal`, `permutation`).
- Files ≤ ~1000 lines; shared math lives here, never duplicated in `genome`/`algorithm`.
- Declared size exceptions: `tensorization.py` (1076 lines — one responsibility, deriving the schedule including which formulation a graph is traced with, with the recipe/contract/measurement record next to the kernels) and `schedule_accelerator.py` (278 lines — the accelerator spellings of the two writes, so `tensorization.py` stays one job; their measured record lives here, not in code comments); condense prose before adding code.
- One rule has one owner inside this node: `tools` owns `_positive_static`, `_scalar_constant`, `_sentinel_constant` and `to_numpy` (which `tensorization._host_array` converts through); `schedule_accelerator` owns the `kernel_mode` vocabulary and the two accelerator formulations, which `tensorization` imports and never re-implements.
- Nothing in this node imports from `genome`, `algorithm`, `problem`, `pipeline`, `benchmarks` or `test`.
- Every public function carries a napoleon docstring stating shapes, dtypes, sentinels and the invariances it relies on.
- Errors: validation raises `errors.TensorNEATError` subclasses on the host, at configuration/build time, before a graph is traced; in-graph overflow is reported as data (`edge_overflow`), never silenced.

## Known Gaps / Open Decisions
- Host-side graph walks use `host_graph.py`: `topological_sort`/`find_useful_nodes` are what `genome/default.py::network_dict` calls, `node_depth` what `algorithm/hyperneat` calls; the in-graph mutation cycle test is `genome/operations/mutation/cycle.py::closes_cycle`.
- The pre-rewrite helper names are gone and must not be re-introduced by consumers: `attach_with_inf` → `masked_flat_gather`; `hash_array` → `hash_rows` (host-only).
- **The v1 StableHLO op table is the portability gate.** `stablehlo.ops.status` reports `cumsum`, `erf`, `gelu`, `tril` and `flip` as `deferred` (numpy interpreter only — hence the `cc` counting trick instead of `cumsum`), and `scatter` is v1 but rejects a rank ≥ 3 operand, which is why every write goes through the rank-1/2 flat-index helpers; `argsort`/`gather`/`select`/`while`/`if`/`pad`/`tile`/`dot`/`random_*` have no such caveat. With the signed-dtype rule that is the whole checklist: the `setup` and `step` graphs a real pipeline builds carry no unsigned dtype and no deferred op and both lower on `backend="iree"`.
- `key_span S` is a static bound on key magnitude: keys must stay compact (hidden-node key compaction on mutation) or the table grows; `S` is part of the shape signature.
- The default genome's forward pass unrolls `max_depth = 16` level steps for every population, even a three-node network, so a per-level saving is multiplied by 16; unrolling on the real depth (or a level `while_loop`) is a genome-side change.

## Notes for Agents
Every one of the 12 ACT and 6 AGG options is a real evoxc kernel with a validated sympy counterpart (`FunctionManager` checks the pairing at import) — no placeholder, no `NotImplementedError`; `clip` is absent from both tables on purpose, and the only surface a caller loses is `FunctionManager.add_func`/`update_sympy` (custom options are per-genome tuples now).
An empty population is *rejected*, not handled: `_positive_static` raises `ConfigError` for `pop_size == 0` in `derive_schedule`/`batch_offsets`, so `P >= 1` is the supported range and `P == 1` (the checkpoint/best-genome spelling) goes through every helper unchanged.
`test/unit/common/*` is the runnable kernel suite here, with `test/support/oracle.py` the independent numpy schedule oracle (it rebuilds the shipped field set including `node_level`/`node_exists`/`in_valid`, so it is the field-by-field reference a schedule change is diffed against) and `test/support/functions_ref.py` the ACT/AGG oracle; `test/test_release_gate_surface.py` pins the importable surface, and `pytest` finds `src/` and `test/support` through `test/conftest.py`.
The accelerator route has **no committed test**: no `test/` cell selects `kernel_mode="accelerator"` (nor `distance_centre`/`distance_formulation`), because `./test` is a sibling node — the bit-identity, numpy A/B and `iree-compile` gates here are hand-run verifications, and a `test/backends` cell building a gated pop-100 graph in accelerator mode is the missing regression guard.
That gap now covers a formulation *difference*, not only a spelling one: the accelerator leg's `node_levels` carries no fixpoint flag and trips a static count, so the guard should also pin every `Transformed` field against the host leg on a cyclic payload (the fallback campaign) and assert the two `while` conditions are counter-vs-constant.
