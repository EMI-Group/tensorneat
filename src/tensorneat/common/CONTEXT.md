# tensorneat/common — host primitives, batched tensor helpers, the tensorization engine, ACT/AGG registries, sympy codegen

## Intent
Framework-wide foundation: the immutable `State` container, the error hierarchy, the batched flat gather/scatter helpers every kernel is built from, the **execution schedule** that turns a ragged evolved topology into static-shape arrays (with a host and an accelerator formulation of each of its two writes, selected at trace time by `kernel_mode`), the ACT/AGG registries and host-side sympy code generation.
Nothing here imports `genome`, `algorithm`, `problem` or `pipeline` — this node is the bottom of the package dependency DAG.

## Dtype & sentinel contract (binding for genome / algorithm / problem)
The gene payload is **split by dtype**: `node_keys (P, max_nodes) int32`, `node_attrs (P, max_nodes, A) float32`, `conn_keys (P, max_conns, 2..3) int32` (`(in_key, out_key)` first, an optional historical marker third), `conn_attrs (P, max_conns, W) float32`.
Absent key rows are `I_INF`; absent attribute values are `NaN` — the pre-rewrite NaN padding survives in the attribute arrays (`isnan(attrs[..., 0])` means "row unused"), while key arrays use the integer sentinel.
Keys are `int32` in `[0, KEY_MAX)` with `KEY_MAX = 2**24`; a key outside that range, or two nodes with the same key, is a caller bug (`ConfigError`).
One integer sentinel only: `I_INF = 2147483647` (`int32` max) = "no index / unmatched / unavailable", in integer arrays only, never mixed with `NaN` in one array.
Rationale: evoxc has **no bitcast op** (`cast` is numeric only), so a mixed-dtype gene row is impossible and the payload is split; keys stay `int32` so absence is an exact comparison and `key_span` really is a key-magnitude bound.
Consequences: int-valued genes (activation/aggregation option positions) live in the float attribute columns, stay integral-valued and are cast with `cast(..., int32)` before use; in-graph gene identity uses the **key columns** with `equal`, never a hash of the row.
`tensorization.derive_schedule` accepts **either** key spelling: `int32` with `I_INF` padding (canonical — what the payload and every kernel pass) or `float32` with `NaN` padding (the pre-rewrite/parity spelling `test/support/oracle.py` uses); the dispatch is a trace-time `if` on a static dtype (`_key_present`): `keys != I_INF` for integer keys, `isfinite(keys) & (keys < KEY_MAX)` for float keys.
**Graph dtypes are signed only**: no `uint8/uint16/uint32/uint64` in any operand, result or constant of a graph this package builds, because iree's declared set is float16/32/64, int8/16/32/64 and bool; use a same-width **signed** carrier and flip the sign explicitly where unsigned order matters. `tools.hash_rows` is the one deliberate exception (host-only numpy, never traced).
Consequence for range tests: `key ∈ [0, key_span)` is two signed comparisons in the key's own dtype, one op more than a `cast(keys, uint32)` comparison that cannot be lowered to iree.

## Execution schedule contract (`Transformed`)
`tensorization.derive_schedule(...)` is one `@evoxc.defn` graph; its output is a pytree of arrays only (**no Python statics inside** — every static fact is implied by a shape or a dtype).
Runtime inputs, batch-first (population on axis 0): `node_keys (P, N)` node key column (`I_INF`/`NaN` = absent row), `conn_in (P, C)`/`conn_out (P, C)` endpoint keys of the same dtype and padding, plus the batchless `input_keys (I,)`/`output_keys (O,)` key vectors.
Statics are positional-or-keyword (`evoxc.build` mirrors a positional call, `functools.partial(fn, **statics)` also works): `pop_size P`, `max_nodes N`, `max_conns C`, `max_in_degree K`, `key_span S` — the Pipeline's shape signature and therefore the executable-cache key — plus trailing `acyclic=False` (caller assertion that the population holds no cycle; a build-time knob, not part of the shape signature) and `kernel_mode="host"` (the formulation static).
Fields, all batch-first, in `Transformed` (a `typing.NamedTuple`, twelve leaves in this order):

| field | shape | dtype | meaning |
|---|---|---|---|
| `src` | `(P, C)` | int32 | source node slot of each connection row; `I_INF` = absent row or unmatched key |
| `dst` | `(P, C)` | int32 | destination node slot; `I_INF` likewise |
| `edge_valid` | `(P, C)` | bool | real conn row AND both endpoints matched |
| `in_conn` | `(P, N, K)` | int32 | conn row index of the k-th incoming edge of node `i`; `I_INF` padding |
| `in_src` | `(P, N, K)` | int32 | source slot of that edge; `I_INF` in the same positions |
| `in_valid` | `(P, N, K)` | bool | that window slot holds a live edge (`in_conn != I_INF`) |
| `node_level` | `(P, N)` | int32 | longest-path depth from the inputs (inputs = 0); `I_INF` = absent, unreachable or on/after a live cycle |
| `node_exists` | `(P, N)` | bool | the node row is present |
| `topo_key` | `(P, N)` | int32 | `node_level * N + slot`, a cheap total order for a topological sweep; `I_INF` where `node_level` is |
| `input_slot` | `(P, I)` | int32 | node slot holding input `j` (in `input_keys` order); `I_INF` if unmatched |
| `output_slot` | `(P, O)` | int32 | node slot holding output `j` (in `output_keys` order); `I_INF` if unmatched |
| `edge_overflow` | `(P,)` | int32 | number of valid edges dropped because their in-group rank reached `K` |

`level`/`overflow` are read-only properties (`level` → `node_level`, `overflow` → `edge_overflow > 0`) kept for the pre-rewrite host callers and the numpy oracle; new kernels use the stored field names.
`Transformed` is a plain `typing.NamedTuple` with **no `evoxc.register_pytree_node` call** (only `State` registers, in `state.py`): evoxc's namedtuple branch flattens it to exactly those 12 leaves in field order, so `tree_map`/`tree_leaves`/`host_payload._slice_batch` never visit the properties. `test/unit/common/test_tensorization.py::DOCUMENTED_FIELDS`/`DOCUMENTED_DTYPES` pin the order and dtypes.
Invariances the consumers may rely on:
- `in_conn`, `in_src` and `in_valid` mark the same positions, and a node's columns `0..d-1` are dense (a column is padded iff it is past that node's in-degree).
- For every `(p, c)` with `edge_valid[p, c]`, exactly one `(p, i, k)` has `in_conn[p, i, k] == c` and `in_src[p, i, k] == src[p, c]`; dropped edges (rank `>= K`) are the only exceptions, counted in `edge_overflow`.
- A node with `in_valid[p, i, 0] == False` has no incoming edge (input nodes, or isolated nodes).
- `reduce_max(node_level)` bounds the execution loop; executing level `0, 1, ...` is a valid topological order, and nodes of one level are independent.
- `src`/`dst` are *slots within one genome's own arrays*, never innovation numbers, so the schedule never reflects population member identity.
- `edge_overflow > 0` means the schedule is lossy for that genome — host code must rebuild with a larger `max_in_degree` (or raise `ShapeBoundError`); kernels never silently drop edges.

## Derivation recipe (validated field by field against `test/support/oracle.py::schedule`)
1. dense key→slot table `(P, S+1) int32` (trailing column = write dump), one flat scatter over the node keys (`key_slot_table`, **host formulation only**; the accelerator route resolves keys by equality instead).
2. `src`/`dst` = gathers from that resolver with sanitized keys (`absent -> 0`, clamped to `[0, S-1]`), then `edge_valid = row present & hit`; `node_exists` comes from the node key column.
3. `edge_order` — **one** stable `argsort` of the combined `(edge key 2*dst, node key 2*slot + 1)` array, in the narrowest signed carrier that holds its `2N + 2` sentinel (`int8` up to N=62, `int16` up to N=16382, else `int32`); the argsort **output** cast once to `int32` is `order` (position → entry id, entries `< C` being connection rows in `(dst, connection index)` order).
4. `cc[i]` = the number of valid edges whose destination slot is `<= i`, computed as `inv[C + i] - i` (one `(P, C + N)` scatter, host) or by counting the same predicate (`cumulative_indegree`, accelerator); `start[i] = cc[i-1]` (0 for `i = 0`), `deg[i] = cc[i] - start[i]`, and node `i`'s in-edges sit at sorted positions `start[i] + i + k` for `k < deg[i]`.
5. `in_conn`/`in_src` = two gathers at that `(P, N, K)` index block (`in_conn = order[start[i] + i + k]`, `in_src = src[in_conn]`), masked to `I_INF` where `k >= deg[i]`; `edge_overflow = reduce_sum(max(deg - K, 0))` (data, not an exception); `in_valid = in_conn != I_INF`.
6. `node_level` = `while_loop` longest-path relaxation over the `(P, N, K)` table, inputs pinned to 0, in the narrowest carrier dtype: the default runs the level-only relaxation (cap `N`), then decides **in-graph** with `evoxc.cond` whether any valid edge violates `level[dst] > level[src]` — no violation ⇔ acyclic and the level-only answer is exact; a violation runs the two-relaxation machinery (`level` + `reach`, cap `2N`, snapshot at `N`) that reports every node on/after a live cycle as `I_INF`. `acyclic=True` returns the level-only answer and drops both.
7. `topo_key = node_level * N + slot` (`I_INF` where the level is) and the `input_slot`/`output_slot` gathers are then free.
Cost: `O(P * (S + C log C + N*K*D))` with `D` = max depth, i.e. edge-proportional except for the `N*K` padding and the one-off `key_span` table; **no `cumsum`, no unsigned dtype, no scatter-with-reduce, no `max_nodes**2` matrix**.
`transform` runs once per generation, so its cost amortises: `derive_schedule` is ~3–5 % of one `Pipeline.step` (XOR, pop 500–1000) and `node_levels` ~40–45 % of `derive_schedule` at the real `(500, 50, 4)` window, i.e. schedule-local micro-optimisation moves a generation by ~1 %.
A performance change here still needs a field-by-field diff against the implementation it replaces (feed-forward, cyclic, in-degree > `K`, absent nodes, unmatched keys, both key spellings, both `acyclic` settings), because the suites do not pin bit-exactness of every `Transformed` field.

## The schedule's two writes and their two formulations (`kernel_mode`)
`derive_schedule` makes exactly two table writes: `key_slot_table`'s dense `(P, key_span + 1) int32` key→slot scatter (`P*N` updates) and `edge_order`'s inverse permutation (a `(P, C + N)` flat scatter yielding `cc`); `incoming_table` writes nothing — it gathers its `(P, N, K)` window out of the sort permutation `order`/`cc`.
On a compiled backend a write is the expensive shape: `evoxc` lowers every `scatter` to **one workgroup of one thread**, measured at 17–21 ns per *update* element independent of the destination width, while `gather`, elementwise ops and reductions spread over the whole grid. At `xor_p500` the two writes are 75 000 and 25 000 serialised cells, 1.40 ms and 0.55 ms of the generation (≈1.95 ms together).
`schedule_accelerator.py` is the scatter-free spelling of both, selected by the static host string `state.kernel_mode` through `schedule_accelerator.kernel_mode(state)` (`KERNEL_MODE_KEY`); `"host"` is what a state without the entry gets, `("host", "accelerator")` is the whole vocabulary (`KERNEL_MODES`), and any other value raises `ConfigError` at trace time, before a graph exists.
`key_template(node_cells, node_visible, rows)` replaces the dense table: one broadcast `equal` of the `(P, L, 1)` query cells against the `(P, 1, N)` node cells, `select(match, slot_of_row, -1)`, `reduce_max` over the node axis; invisible node rows are rewritten to `_NO_NODE` (-2), invisible queries to `_NO_QUERY` (-1), and a miss answers `I_INF`.
`cumulative_indegree(dst, edge_valid, max_nodes)` replaces the inverse permutation: `edge_valid & (dst <= iota)` over a `(P, C, N)` table, reduced over the edge axis to `cc (P, N) int32` — the same number the host form reads out of `inv[C + i] - i`, so `edge_overflow` and every window position agree.
Bit identity, not near-equality: both routes are fed the same sanitized `int32` cells (`tensorization._key_indices`), so they cannot disagree about which keys are visible; the dense table's flat write leaves the **highest** slot at a cell two node rows name (which also covers two `float32` keys truncating to one integer cell) and `reduce_max` returns that same highest slot; `cc` is a count in both routes. Verified over 108 field-by-field `Transformed` comparisons (four genome types × pops 100/500/1000 × three evolved payloads × `max_in_degree` ∈ {own, 2, 1}; 67 with `edge_overflow > 0`) and ten seed-42 `Pipeline.step` generations hashing identically in both modes at P=500 and P=1000.
The switch is a host `if` on a static string, never on a traced value, so a graph holds exactly one formulation; the `argsort` stays in both, because `order` is what `incoming_table` gathers its window out of.
On the numpy interpreter the accelerator formulation is the **slower** one — `xor_p500` 117.39 → 134.33 ms per generation (+14.4 %), 190.9 → 225.5 MiB peak RSS at the same dispatched-op count — because it trades a serialised write for an `(P, L, N)` element volume numpy pays in full; `"host"` therefore stays the default and `Pipeline.setup` asks for `"accelerator"` only on a GPU-class device kind (via `host_payload._formulation_statics`).
Neither formulation needs a `cumsum` (a StableHLO export deferral), an unsigned dtype, or (in accelerator mode) any scatter at all, and `iree-compile` succeeds in both modes on `llvm-cpu` and `rocm`/`gfx942`.
Rejected spellings, do not re-derive: materialise `order` from a Hillis-Steele prefix over `key_span` (needs `cumsum`, `log2(key_span)` dispatches per resolve, and `order` is still required); narrow the table's carrier or destination (destination width is irrelevant to the ns/cell law, a 16-bit carrier measured worse); resolve keys with `argmax` instead of `reduce_max` + `select` (the int64 `argmax` result materialises an `iota` outside the execution region — the ROCm failure `genome/operations/distance/index_free.py` records).

## Forward-side contract (consumed by `genome`)
Per level `l = 0 .. reduce_max(node_level)`: `mask = in_valid & ~isnan(gathered source value)` (the legacy `conn_exists & src_valid`); gather each conn gene attribute from the flattened `(P, C*attrs)` payload with `tools.masked_flat_gather` at `in_conn`, and the source values at `in_src`; `z = functions.agg.apply_aggregation(contribs, mask, agg_ids)` (a static `K`-plane fold, never a `reduce_*`); `new = functions.act.apply_activation(z, act_ids)`; `vals = select((node_level == l) & valid_count > 0, new, vals)` with `valid_count = reduce_sum(in_valid, -1)`.
The per-node `valid_count` guard matters: a node whose incoming edges are all invalid keeps `NaN` (legacy behaviour relied on `lax.cond(has_valid, ...)`).
Kernels must never index outside `[0, size)` — evoxc's numpy backend **raises** on out-of-range gather/scatter where JAX clamped, so clamping plus masking is mandatory, not an optimisation (`trusted=True` stays opt-in and only where the range is proven).
The mandatory `select(mask, z, 0.0)` on `(P, N, K)` cannot become a masked multiply (a dead slot may hold `NaN` or `±inf`, whose product with `0` is `NaN`), so the aggregation passes — not the dispatch — remain the term to attack on a level.

## API Surface
### `state.py`
`State(**kwargs)` — immutable host container over a dict; `register/update/remove` return new `State`s (raising on duplicate/missing keys); `__getattr__` raises `StateKeyError`, `__getitem__` the plain `KeyError`; `save`/`load` pickle it; `tree_flatten`/`tree_unflatten` + `evoxc.register_pytree_node` let it cross a graph boundary.
`StateKeyError(AttributeError, KeyError)` is the one dual-base exception in the package: `AttributeError` is what `copy.deepcopy`'s instance probe and `hasattr`/`getattr(state, name, default)` need, and what `Pipeline._shape_signature`'s `getattr(state, "pop", None)` probe needs to reach its documented `TensorNEATError` instead of a `KeyError`; `KeyError` keeps the legacy `except KeyError` around `state.pop_size` in `genome/base.py::_resolve_pop_size` (`copy.copy`/`pickle` were never a reason — CPython resolves `__copy__`/`__reduce_ex__` on the type).
The price of the dual base is that `hasattr(state, "typo")` answers `False` instead of propagating, so a typo is loud only at a bare `state.typo` read, an explicit `except`, or `state["typo"]` (plain `KeyError`); writing a new key is still refused by `__setattr__` with `AttributeError("State is immutable")`.
`StatefulBaseClass` (`stateful_class.py`) — `setup(state) -> State`, plus a generic `show_config(registered_objects=None) -> dict` that nothing calls (`Pipeline.show_config` renders through `host_payload._object_config`).

### `errors.py`
`TensorNEATError(Exception)` root; subclasses `ConfigError` (a user-supplied value violates the contract: non-positive statics, duplicate/out-of-`KEY_MAX` keys, mismatched input/output counts, a registry miss), `ShapeBoundError` (a static schedule bound was exceeded: `max_in_degree`, `key_span`, `max_conns`), `GraphError` (cycle where feedforward is required, missing input/output node). Backend/shape errors from evoxc are **never** re-wrapped; only validation raises these, on the host before a graph is traced.

### `tools.py`
Sentinels `I_INF`, `KEY_MAX`; flat-index plumbing `batch_offsets(pop_size, row_len)`, `prepare_flat_index(x, idx, present=None, fallback=0, trusted=False)` (the `(P, n)` flat index block, reusable across calls), `flat_gather_prepared(x, flat_idx, shape)`, `flat_scatter_prepared(x, flat_idx, updates)`, `flat_gather(x, idx, trusted=False)`, `masked_flat_gather(x, idx, mask=None, fill=nan, trusted=False)`, `flat_scatter(x, idx, updates, trusted=False)`, `masked_flat_scatter(x, idx, updates, mask, trusted=False)` (dump-slot routing); selection helpers `fetch_first(mask, default=I_INF)`, `fetch_random(key, mask, default=I_INF)`, `rank_elements(x, reverse=False)`, `argmin_with_mask(arr, mask, *, filler=None, default=None)`; standalone mutation kernels `mutate_float(key, val, init_mean, init_std, mutate_power, mutate_rate, replace_rate)` and `mutate_int(key, val, options, replace_rate)` (the genome path is `genome/gene/blocks.py::mutate_attrs`; evoxc has no `random.choice`, so an option set is gathered at `randint`); `to_numpy(tensor)`; `hash_rows(rows)` — host-only numpy xor-mix over a row's bytes (`view(np.uint32)`), the host twin of `genome/gene/base.py::hash_int32`.
`to_numpy` is the single explicit device-to-host step every logging/checkpoint path uses and the read-back of `Pipeline._place_state`'s cross-device host hop: an `ndarray` comes back unchanged, a device tensor (`.device.kind != "cpu"`) is first transferred with `Tensor.to(Device("cpu", 0))`, then a callable `.numpy()` is called, else `np.asarray`; `evoxc.Tensor` deliberately has **no** `__array__`, and the CPU path never copies.
Every flat-index helper takes `trusted=False`: the default emits the escape guard (`select` + `less`/`greater_equal`/`logical_or` + redirect select) that makes the backend **raise** on an out-of-range index instead of reading a neighbouring row; `trusted=True` skips it only for a caller that has *proved* every index lies inside `[0, R)`, never on unbounded data.

### Hoistable sentinels (`tools._sentinel_constant`)
Every sentinel is a rank-0 `constant` **op**, not a bare Python scalar, because a bare scalar is weakly promoted and changes the `select`'s result dtype (`_scalar_constant` owns that rationale); evoxc has no constant CSE, so two identical sentinels are two ops.
That op is charged per call, so a helper called inside a `scan`/`cond`/`while_loop` body pays it once per iteration. `_sentinel_constant(value, fallback, dtype)` is the single resolver that makes it hoistable: `None` builds `fallback`, a Python/NumPy number builds a rank-0 constant of `dtype`, and any other object is returned **verbatim** (no cast, no reshape).
A supplied constant whose dtype differs from `dtype` raises `ConfigError` at trace time — `evoxc.select` promotes silently instead of rejecting, so without this check a `float64` filler would widen the `argmin` input and an `int64` default would change the returned index's dtype.
`fetch_first(mask, default=I_INF)` takes an optional pre-built `int32` constant for `default`; `argmin_with_mask(arr, mask, *, filler=None, default=None)` takes them for the masking `+inf` (of `arr.dtype`) and the `I_INF` "no candidate" index; `None` keeps the one-shot spelling op for op, and "unset" and "no candidate" read the same `I_INF`.
Measured (numpy backend, one small `scan` body calling both helpers, `kernels.dispatch` counted): the one-shot spelling costs 3 `constant` dispatches per iteration, the hoisted spelling 0, with bit-identical outputs. The intended hoister is `algorithm/neat/_kernels.py::speciate` (≈60 dispatches per generation at `species_size=20`), which `tools.py` cannot hoist from here.
No hoistable spelling exists for `prepare_flat_index` (up to three constants: the `fallback`, the `pop_size * row_len` redirect and `batch_offsets`' `enp.arange`), hence for the `masked_flat_gather`/`flat_gather`/`flat_scatter`/`masked_flat_scatter` built on it, or for `fetch_random`; `batch_offsets` is the cheapest to hoist caller-side (one `enp.arange` + `reshape`, built once and added in), and `genome/operations/alignment.py` plus `algorithm/neat/_keys.py` already call it both ways.

### `tensorization.py`
`Transformed` `NamedTuple`; `derive_schedule(node_keys, conn_in, conn_out, input_keys, output_keys, pop_size, max_nodes, max_conns, max_in_degree, key_span, acyclic=False, kernel_mode="host")` (`@evoxc.defn`); `edge_order(dst, edge_valid, max_nodes, max_conns, kernel_mode="host") -> (order, cc)`; the private `_key_resolver(node_keys, key_span, kernel_mode)` is the **one selection point** of the key-resolution formulation (it builds the dense table lazily for `"host"` and derives no table for `"accelerator"`), and both routes are addressed by `_key_indices`'s sanitized `int32` cells so they cannot disagree about which keys are visible.
Individually testable steps: `key_slot_table(node_keys, key_span) -> (P, S+1) int32` (trailing dump column, one `masked_flat_scatter`, `trusted=True`), `slot_lookup(table, keys, key_span)`/`_slot_of` (sanitized index, gather, `I_INF` on a miss), `edge_order`, `incoming_table(order, cc, src, max_nodes, max_in_degree) -> (in_conn, in_src, edge_overflow)` (two gathers at the `start[i] + i + k` block, `trusted=True` bounded by `inv[C + i] - 1 <= C + N - 1`), `node_levels(in_conn, in_src, input_slot, max_nodes, acyclic=False, edges=None)` where `edges` is the `(src, dst, edge_valid)` triple the cycle test needs (`ConfigError` when `acyclic=False` and it is missing).
Also `validate_schedule(transformed)` (host-side invariant checker, called by the unit tests and by `genome/grad.py::build_grad`) and the trace-time helpers `_key_indices`, `_key_present`, `_narrow_int`, `_node_slots`, `_iinf_like`, `_carrier`, `_cycle_violation`, `_pinned_mask`.
The narrow carriers are a contract detail, not a knob: the level relaxation and both sort keys use the smallest of `int8`/`int16`/`int32` that provably holds every reachable value *and* its "after everything" sentinel (a real value inside the dtype, never `I_INF`), with the thresholds documented next to each builder; results are cast back to `int32` on the way out.

### `schedule_accelerator.py`
`__all__` is exactly `KERNEL_MODE_KEY`, `KERNEL_MODES`, `cumulative_indegree`, `is_accelerator`, `kernel_mode`, `key_template`, `resolve_mode`; `_DEFAULT_KERNEL_MODE = "host"` is the private fallback and `_NO_QUERY = -1`/`_NO_NODE = -2` are the two masked cells.
`kernel_mode(state) -> str` is the plain attribute read every kernel uses (`getattr(state, KERNEL_MODE_KEY, "host")` semantics, no graph op, identical inside and outside a trace); `resolve_mode(mode) -> str` is the one validation (`ConfigError` on anything else, so a typo fails loudly instead of silently selecting the other route); `is_accelerator(mode) -> bool` is the comparison helper.
`key_template(node_cells, node_visible, rows)` returns a callable `resolve(query_cells, query_visible) -> slots (P, L) int32` with exactly `_slot_of`'s contract (`I_INF` on a miss); it validates every shape pair at trace time and materialises one `(P, L, N)` compare/select/reduce table — no scatter, no permutation, no `iota`.
`cumulative_indegree(dst, edge_valid, max_nodes) -> cc (P, N) int32` validates `max_nodes` via `_positive_static` and `edge_valid` against `dst`'s shape; `I_INF` destinations fail `<= i` and are masked by `edge_valid` too, and `cc <= C`, so `int32` cannot overflow.
`common.__init__` re-exports **only** `kernel_mode` from this module; the rest is reached as `tensorneat.common.schedule_accelerator.<name>` (`tensorization` imports `cumulative_indegree`/`is_accelerator`/`key_template`/`resolve_mode` directly), and `genome/base.py::transform` passes `kernel_mode(state)` as `derive_schedule`'s trailing static, so a real run traces whichever formulation the state names (the entry is part of the executable-cache formulation signature, so a mode change rebuilds exactly once).

### `functions/`
Exports exactly `ACT`, `AGG`, `FunctionManager`, `apply_activation(z, act_ids, act_fns=ACT_FUNCS)`, `apply_aggregation(values, mask, agg_ids, agg_fns=AGG_FUNCS)`: 12 activations and 6 aggregations in a fixed, parity-critical order; activations are elementwise, aggregations reduce the last axis of a `(P, N, K)` contribution tensor with neutral padding and are `NaN`-aware through `mask`; `ACT.name_of`/`AGG.name_of` are the reverse lookups. `functions/CONTEXT.md` owns the dispatcher recipes (one `_Window` memo per call, its per-literal constant memo, the `has_valid` guard emitted only when some option is not `zero_on_empty`).

### `host_graph.py`
Host-only, pure Python (stdlib + `errors.GraphError`, deliberately backend-free: it keeps its own `_I_INF` literal rather than importing `tools`, which pulls in `evoxc`), never traced: `decode_graph(nodes, conns, node_attrs=1, conn_attrs=2)` → `(dict[int, tuple[float, ...]], set[tuple[int, int]])`; `topological_sort(nodes, conns)` → `(topo_order, topo_layers)` (Kahn, layers ascending, `GraphError` on a cycle); `find_useful_nodes(nodes, conns, output_idx)` → `set[int]`; `check_cycles(nodes, conns, from_idx, to_idx)` → `bool`; `node_depth(nodes, conns, input_idx)` → `dict[int, int]`, which must equal `Transformed.node_level` for a well-formed feedforward genome.
`common.__init__` re-exports `decode_graph`, `topological_sort` and `find_useful_nodes`; `host_graph.__all__` also lists `check_cycles` and `node_depth` (the in-graph mutation cycle test is `genome/operations/mutation/cycle.py::closes_cycle`).

### `sympy_tools.py`
Host-only (`re` + `sympy` + a `numpy` import deferred to the printer, no evoxc): `analysis_nodes_exprs`, `round_expr`, `replace_variable_names`, `to_latex_code`, `to_python_code` — the 8-tuple contract of `Genome.sympy_func` is unchanged from the pre-rewrite library, and both renderers take it **unpacked** (`to_latex_code(*genome.sympy_func(state, network))`): `symbols`/`topo_order` key by node **keys**, `nodes_exprs`/`output_exprs` by sympy Symbols, `forward_func` is accepted for signature compatibility only.
`to_python_code` emits module-level source, never a `def`: `import numpy as np`, a `#     <symbol> -> i[<position>]` binding header, `h = np.zeros(hidden_cnt)` (only with hidden nodes), `o = np.zeros(len(output_exprs) or output_cnt)`, one assignment per useful node and a trailing `# o[k] = ...` closed-form block; `_NumPySourcePrinter` (a `NumPyPrinter` subclass) is what makes it callable — `Max`/`Min` fold to right-nested `np.maximum`/`np.minimum`, `Abs` to `np.abs`, `Piecewise` to a right-nested eager `np.where` chain (correct because every shipped branch is total), any unregistered `sp.Function` by class name (`SympyClip` -> `np.clip`) with `ConfigError` when NumPy has no such callable, and `numpy.` normalised to `np.` because sympy keeps its known-function tables on the class.
Every shipped ACT/AGG option renders executable source and all 18 per-option snippets exec and match their kernel to ≤2.5e-7 absolute over negative/zero/positive inputs; the one divergence is `exp`, whose emitted `np.clip(z, -10, 10)` differs from the unclipped kernel beyond ±10 (the divergence `functions/CONTEXT.md` records). `round_expr` never collapses a real constant to zero, so `LOG_EPS`/`INV_EPS` (1e-7) survive as `1.0e-7` while `123456789/10**9` still renders `0.123457` at `precision=6`.
`analysis_nodes_exprs` counts `input_cnt` over keys *starting with* `i` and `genome.sympy_func` names only the raw input symbol `i<k>` that way, so `input_cnt == I` and the `topo_order[input_cnt:]` slice is correct for a standard genome whose inputs sort first; `to_python_code`'s empty-`input_symbols` fallback comes from the pre-substitution expressions, so production (which always passes a non-empty vector) never takes it.
Both renderers are legacy-derived (`benchmarks/legacy_jax/tensorneat_legacy/common/sympy_tools.py`) and have one unit test (`test/unit/common/test_functions.py::test_to_python_code_emits_runnable_source_for_a_hand_built_expression`), which pins the emitted text and execs it; per-option runnability and the `round_expr` guard are hand-verified only. Not re-exported by `common.__init__` (only `Genome.sympy_func` imports it, directly).

## evoxc idioms, cost laws and gotchas
- `@evoxc.defn` + `evoxc.build(fn, *TensorSpec, backend=..., device=...)`; the numpy reference interpreter is the default and is enough for `test/unit`.
- `evoxc.numpy as enp` for in-graph constants (`enp.zeros/ones/full/arange`), `evoxc.constant(evoxc.tensor(ndarray))` for host data; dtypes come from `evoxc.int32/float32/...`, **not** from `enp`.
- `gather(x, idx, axis)`/`scatter(x, idx, upd, axis)` **replace** the indexed axis (they are not `take_along_axis`), so per-row indexing goes through the flattened helpers (`flat = row * R + col`); `P*R` must stay inside `int32`.
- `scatter` is set-only (no add/max modes) and reductions have no `where=`/`initial=`: masked reduction pads with the neutral element (`0`, `-inf`, `+inf`, `1`) first.
- `argsort` returns int64; its inverse permutation is a `flat_scatter` of `arange(n)`; `stable=True` is required for tie-breaking (group ranks).
- **`argsort(kind="stable")` has a radix fast path for `int8`/`int16` and a slow general path for `int32`/`int64`**: `(1000, 250)` costs 7.4 ms as `int32`, 1.0 ms as `int16`, 0.62 ms as `int8`, so anything sorted here is keyed in the narrowest dtype that fits its range *including* the sentinel.
- `evoxc.cond` accepts a `while_loop` in each branch on the numpy backend (both traced, one executed), so a "fast path + expensive fallback" decision is expressible in-graph; control-flow bodies keep fixed shapes/dtypes, the condition is a scalar tensor, and no `vmap` may be applied over them.
- No `broadcast_to` on `evoxc` (use `enp.broadcast_to`), no `searchsorted`, no `choice`, no `bitcast`, no `where` (it is `evoxc.select(pred, on_true, on_false)`); `evoxc.slice(x, start, lengths)` takes per-axis tuples, and `reshape`/`transpose` are the only other structural ops needed here.
- An `@evoxc.defn` object is not callable: use `.fn` (the tests bind it with `functools.partial`) or `evoxc.build` the `Defn` itself.
- Cost laws measured on this box (this tree): one dispatched op costs ≈19–20 µs on the numpy interpreter at population-sized tensors, so at these shapes **executed op count is the lever**; a flat graph on iree+rocm pays ≈63 µs fixed + ≈2.2–2.5 µs per dispatch, one `while` iteration ≈50 µs (the condition is read back to the host), and `Tensor.to(cpu)` a fixed ≈47–60 µs per leaf regardless of size.
- Executed dispatches per generation on this tree (numpy, `kernels.dispatch` monkeypatched): `xor_p500` 7 592, `cartpole_p100` 30 994; `derive_schedule` alone is ≈650 of the former.
- **Executed-op count is not a proxy for wall time at this level**: a value- and work-identical 17-op trim of the derivation tail (faster in isolation, 6.66 → 6.47 ms) cost +34 % of one `Pipeline.step` at pop 1000, non-linear in `P`, so measure `Pipeline.step` end to end in fresh interleaved processes before landing a "free" removal.
- `node_levels` is at its op floor: `reduce_max` over the `K` axis instead of the pairwise fold is 1.52× worse, two relaxation sub-steps per trip 1.21× worse (and not value-identical on a cyclic payload), dropping the per-trip `(P, N)` dump-column `concatenate` 1.17× worse; dense max-plus, one-hot prefix counting, static unrolling and per-member `cond` are all rejected (the last is inexpressible).
- Test a variant of a kernel without touching the file: `exec` `textwrap.dedent(inspect.getsource(fn))` with one textual substitution into `dict(vars(module))`, then diff `build_defn` output against the unmodified function on arrays from a real `Transformed`, variants interleaved.
- Timing anything here: build once and time `evoxc.run` only (`run_defn` per iteration times the build), one cell per **fresh process** (a second executable in the same process skews later cells up to 25 %), and report a paired ratio against the previous implementation — absolute milliseconds move ~30 % between sessions on this box.

## Scatter portability on `backend="iree"` (IREE 3.11/3.13)
**One index value feeds exactly one scatter.** That is the whole rule.
`evoxc`'s StableHLO writer emits a flat write (`tools.flat_scatter_prepared`, `tools.masked_flat_scatter`) as a rank-1 axis-0 scalar-window scatter (operand `tensor<Rxi32>`, indices `tensor<nx1xi64>`, updates `tensor<nxi32>`); IREE lowers it to `iree_linalg_ext.scatter`, whose `ins` wants the index tensor collapsed to rank 1, and performs that collapse inside `iree-stablehlo-to-iree-input` as an `unrealized_conversion_cast`.
When the same index SSA value (an explicitly shared block *or* two expressions IREE's CSE merges) feeds a **second** scatter, that materialization stays live and the pass aborts: `failed to legalize unresolved materialization from ('tensor<nx1xi32>') to ('tensor<nxi32>') that remained live after conversion`, reported at the second scatter's source location. One scatter with the same shapes compiles in ~0.25 s at any size, so the emitted form is fine — this is contextual, not a bad op spelling; the rank-2 row form (operand `(R, 1)`, indices `(n, 1)`) fails identically, and operand shape, width, i32-vs-i64 indices and `while`/`if`/`sort` regions are irrelevant (bisected by deleting ops: removing *either* shared-index scatter compiles the whole module, as does a distinct index expression).
Consequences: the **host** formulation of the schedule needs exactly **two** scatters, each through its own index expression (`key_slot_table`'s table and `edge_order`'s inverse permutation), the **accelerator** formulation needs none, and `incoming_table` writes nothing in either mode; a caller that must fill several payloads in the same cells uses one call over a buffer wide enough to hold them, never two `flat_scatter_prepared` calls with one block.
Minimal reproducer: `P, R, N = 4, 68, 32`; `block = tools.prepare_flat_index(x, idx, trusted=True)`; `tools.flat_scatter_prepared(x, block, u1)` **and** `tools.flat_scatter_prepared(x, block, u2)` → `failed to legalize unresolved materialization from ('tensor<128x1xi64>') to ('tensor<128x1xi32>')`; with only the first call it compiles.

## Constraints
- No `jax`/`torch`/`numpy.random` in graph code; randomness is `evoxc.random` stateless keys (`key(seed)`, `split`, `randint`, `uniform`, `normal`, `permutation`).
- Files ≤ ~1000 lines; shared math lives here, never duplicated in `genome`/`algorithm`.
- Declared size exceptions: `tensorization.py` (1057 lines — one responsibility, deriving the schedule including which of its two formulations a graph is traced with, with the recipe/contract/measurement record next to the kernels, because splitting it would separate the recipe from the code) and `schedule_accelerator.py` (278 lines — the accelerator spellings of the two writes, so `tensorization.py` stays one job; their measured record lives in this document, not in code comments); condense prose before adding code.
- One rule has one owner inside this node: `tools` owns `_positive_static`, `_scalar_constant`, `_sentinel_constant` and `to_numpy` (which `tensorization._host_array` converts through), imported and never re-written; `schedule_accelerator` owns the `kernel_mode` vocabulary (`KERNEL_MODE_KEY`, `KERNEL_MODES`, `_DEFAULT_KERNEL_MODE`, `kernel_mode`, `resolve_mode`, `is_accelerator`) and the two accelerator formulations, which `tensorization` imports and never re-implements.
- Nothing in this node imports from `genome`, `algorithm`, `problem`, `pipeline`, `benchmarks` or `test`.
- Every public function carries a napoleon docstring stating shapes, dtypes, sentinels and the invariances it relies on.
- Errors: validation raises `errors.TensorNEATError` subclasses on the host, at configuration/build time, before a graph is traced; in-graph overflow is reported as data (`edge_overflow`), never silenced.

## Known Gaps / Open Decisions
- Host-side graph walks use `host_graph.py`: `topological_sort`/`find_useful_nodes` are what `genome/default.py::network_dict` calls, `node_depth` what `algorithm/hyperneat` calls.
- The pre-rewrite helper names are gone and must not be re-introduced by consumers: `attach_with_inf` → `masked_flat_gather`; `hash_array` → `hash_rows` (host-only).
- **The v1 StableHLO op table is the portability gate.** `stablehlo.ops.status` reports `cumsum`, `erf`, `gelu`, `tril` and `flip` as `deferred` (numpy interpreter only — hence the `cc` counting trick instead of `cumsum`), and `scatter` is v1 but rejects a rank ≥ 3 operand, which is why every write goes through the rank-1/2 flat-index helpers; `argsort`/`sort`/`gather`/`select`/`while`/`if`/`pad`/`tile`/`dot`/`random_*` have no such caveat. With the signed-dtype rule that is the whole checklist: the `setup` and `step` graphs a real pipeline builds carry no unsigned dtype and no deferred op, and both lower on `backend="iree"`.
- `key_span S` is a static bound on key magnitude: keys must stay compact (hidden-node key compaction on mutation) or the table grows; `S` is part of the shape signature and a build rebuilds on overflow.
- `agg.maxabs` pays `tools.flat_gather`'s guard chain (`less`/`greater_equal`/`logical_or`/`select` plus a `(P, 1)` `arange` constant) even though an `argmax` result is provably inside `[0, K)`: `trusted=True` exists but `functions/` cannot bound `K` itself, and `maxabs` is not an option of the default genome, so the default XOR path never pays it.
- The step graph of a pop-1000 pipeline emits no large-constant warning: the largest baked constant is `edge_order`'s `(P, C + N)` `int32` zeros seed for the inverse permutation (600 000 B at `N=50 C=100 P=1000`), below evoxc's 1 048 576 B threshold, and the window padding is a rank-0 `I_INF` constant broadcast by `select`.
- `incoming_table` is where numpy pays for ROCm: its two `(P, N, K)` gathers cost slightly more than the scatter they replaced (1.18 → 1.37 ms at pop 500, 2.22 → 2.45 at pop 1000 on a real evolved payload), cancelled by `edge_order` no longer deriving `rank`; net `derive_schedule` is ±0.15 ms and the end-to-end paired A/B is −0.4 % with 17 fewer dispatches, −3 % peak RSS and a bit-identical trajectory.
- The default genome's forward pass unrolls `max_depth = 16` level steps for every population, even a three-node network, so a per-level saving is multiplied by 16; unrolling on the real depth (or a level `while_loop`) is a genome-side change (`genome/` owns it).

## Notes for Agents
Every one of the 12 ACT and 6 AGG options is a real evoxc kernel with a validated sympy counterpart (`FunctionManager` checks the pairing at import) — no placeholder, no `NotImplementedError`; `clip` is absent from both tables on purpose, and the only surface a caller loses is `FunctionManager.add_func`/`update_sympy` (custom options are per-genome tuples now).
An empty population is *rejected*, not handled: `_positive_static` raises `ConfigError` for `pop_size == 0` in `derive_schedule`/`batch_offsets`, so `P >= 1` is the supported range and `P == 1` (the checkpoint/best-genome spelling) goes through every helper unchanged.
`test/unit/common/*` is the runnable kernel suite here, with `test/support/oracle.py` the independent numpy schedule oracle (it rebuilds the shipped field set including `node_level`/`node_exists`/`in_valid`, so it is the field-by-field reference a schedule change is diffed against) and `test/support/functions_ref.py` the ACT/AGG oracle; `test/test_release_gate_surface.py` pins the importable surface.
`import tensorneat` works from an installed checkout (`uv pip install --python .venv/bin/python -e . --no-deps`) and pulls in no `jax`/`torch`/`brax`/`gymnax`/`mujoco`; a bare-checkout environment is `uv venv .venv && uv pip install --python .venv/bin/python evoxc numpy sympy networkx matplotlib pytest && uv pip install --python .venv/bin/python -e . --no-deps`, and `pytest` finds `src/` and `test/support` through `test/conftest.py`.
The accelerator route has **no committed test**: no `test/` cell selects `kernel_mode="accelerator"` (nor `distance_centre`/`distance_formulation`), because `./test` is a sibling node — the bit-identity, numpy A/B and `iree-compile` gates in this document are hand-run verifications, and a `test/backends` cell that builds a gated pop-100 graph in accelerator mode is the missing regression guard.
