# tensorneat — package architecture

## Intent
This package is the NEAT/HyperNEAT toolchain built on the EvoX Compiler (`evoxc`), replacing the pre-rewrite JAX implementation module for module.
It owns three things only: (1) **tensorization** of variable topology into fixed-shape arrays, (2) the **kernel contract** shared by genome / algorithm / problem, and (3) the **compile site** (`pipeline.py`) that turns one generation into a single evoxc executable.

## Kernel Contract (binding for all child nodes)
**Batch-first.** The population is axis 0 and every shape is static at build time.
Kernels are written already batched; `evoxc.vmap` is never applied to a kernel.
Control flow may nest inside an `evoxc.scan` body when the inner controller is a `cond`/mask over statically built branches (no host control flow on a traced value), the nested form has been proven to compile on iree-llvm-cpu, and the numpy interpreter stays the reference — the shipped case is `algorithm/neat/_kernels.py::gated_row` inside its two speciation scans below `GATED_ROWS`.
**Split gene payload.** `evoxc` has no bitcast/reinterpret op, so a mixed-dtype gene row is impossible: `node_keys (P,max_nodes) int32` + `node_attrs (P,max_nodes,A) float32`, `conn_keys (P,max_conns,2..3) int32` + `conn_attrs (P,max_conns,W) float32`. Absent rows are `I_INF` in key arrays and NaN in attr arrays. Mutation therefore twiddles int keys and float attrs separately.
**Execution schedule.** `Genome.transform(state, *arrays, input_keys=None, output_keys=None)` accepts the four-array payload (or the two key arrays) and returns the `Transformed` pytree defined in `./common/CONTEXT.md` (authority: that table, not this one) — `in_src`/`in_conn`/`in_valid (P,N,K)`, `node_level`/`node_exists`, `input_slot`/`output_slot`, `edge_overflow (P,)`.
`input_keys`/`output_keys` override the pinned key vectors (length `num_inputs`/`num_outputs`, int32; `None` = the genome's own `input_idx`/`output_idx`), which is how `HyperNEAT.transform` passes the substrate's keys `0..I-1` / `I..I+O-1`.
`output_slot` is the read-out authority: `genome/step.py` gathers the network outputs at `output_slot` and derives the per-row output-activation mask from it, so a payload whose block order is not the `DefaultGenome` template (HyperNEAT's substrate is inputs, outputs, hidden) reads its real output neurons and never applies the output transform to a hidden one.
`input_slot` only pins the levels: every shipped forward seeds the first `num_inputs` payload rows with the inputs, and HyperNEAT's substrate input keys are `0..I-1` by validation.
`common/tensorization.py::derive_schedule` derives it **inside the graph** at cost `O(P·(C log C + N·K·D))` — never the legacy `max_nodes²` matrix.
**Edge proportionality.** A forward pass touches work proportional to real connections and depth (`(depth+1) × max_nodes × K` elementwise/reduce/gather ops), never `max_nodes²` and never `max_depth`.
**Genome.** `initialize(state, key, pop_size)` (pop_size is static; evoxc keys are rank-0 so randomness is one key plus batched output shapes); `transform(state, *arrays, input_keys=None, output_keys=None) -> Transformed`; `forward(state, transformed, node_keys, node_attrs, conn_keys, conn_attrs, inputs (P,*in)) -> (P,*out)` reads its outputs at `transformed.output_slot` (NaN for an `I_INF` slot) and applies the output transform there; `grad(...) -> (loss (P,), (grad_attrs, ...))` built by `evoxc.grad` over the float attrs only (the `sort`-derived schedule has no AD rule); `execute_mutation/crossover/distance`; and the digest pair `prepare_distance`/`measure_distance` that `speciate` consumes.
The feedforward forward is one `evoxc.while_loop` over topological levels; the recurrent one unrolls its `activate_time` ticks in Python.
Host-only helpers (`network_dict`, `sympy_func`, `visualize`, `repr`, `hash`) stay pure Python and never enter a graph; `Genome.hash` is host-only numpy (`genome/host.py::BaseGenomeHost.hash` folds `common.tools.hash_rows` over the numpy payload — the `uint32` xor-mix — and refuses a traced payload because evoxc has no bitcast), and it has no production caller.
**Algorithm.** `ask(state) -> payload`, `transform(state, pop=None)`, `forward(state, transformed, inputs, pop=None)`, `tell(state, fitness) -> State`, `num_inputs`, `num_outputs`, `pop_size`, plus the host-only `show_details`.
**Problem.** `evaluate(state, key, act_fn, transformed) -> fitness (P,)` executed inside the active trace; **`key` is a single rank-0 evoxc key** (there is no batched key type), `act_fn` maps `(P*S, *input_shape)` to `(P*S, *output_shape)`, and `input_shape`/`output_shape` are **per-sample**. Datasets and rollouts are tiled into the population axis inside the graph; NaN fitness becomes `-inf` as the last op of every problem. `evaluate` is a plain helper, never `@evoxc.defn` (a defn cannot call another defn).
**Formulation statics.** Three plain Python strings on the trace-time configuration `State` — `distance_centre` (`"single"` | `"tiled"`), `distance_formulation` (`"merge"` | `"index_free"`), `kernel_mode` (`"host"` | `"accelerator"`) — select which spelling of a kernel a graph is traced with; they are read on the host, never as traced values, so a graph contains exactly one formulation and no backend ever sees both. `Pipeline.setup` derives them from the device kind and registers them; a missing entry means `"single"`/`"merge"`/`"host"`, which is what a bare `State()` yields.
**Randomness.** `evoxc.random` stateless keys only; no `numpy.random`/`jax.random` anywhere on the compute path. Draw order intentionally differs from the legacy library, so parity is kernel-level on identical inputs, never trajectory-level.
**State.** Immutable host container (`State.register/update/remove/registered_keys` + pytree registration) holding configuration, evoxc keys and tensors.

## Contract Reconciliations (authoritative; resolves the divergences found in Phase 1)
1. **Gene payload is split and integer-keyed**: `node_keys (P,max_nodes) int32` (`I_INF` padding), `node_attrs (P,max_nodes,A) float32`, `conn_keys (P,max_conns,2) int32` (`I_INF` padding; a third column only when the conn gene uses `historical_marker`), `conn_attrs (P,max_conns,W) float32` (NaN padding). Keys are never floats; `host_graph`/`tensorization` detect absence with `key != I_INF`.
2. **Payload arity is four arrays**, bundled as `genome.utils.GenomeTensors`: `initialize(state, key, pop_size)`, `transform(state, payload)`, `forward(state, transformed, payload, inputs)`, `execute_*(state, key, payload, ...)`. `BaseAlgorithm.forward(state, transformed, payload, inputs)` therefore takes the payload too, and `SpeciesState` centers store the split payload (never packed ints).
3. **`Transformed` authority is `common/tensorization.py`**: fields `src, dst, edge_valid, in_conn, in_src, in_valid, level, node_level, topo_key, input_slot, output_slot, node_exists, edge_overflow`, where `in_valid (P,N,K)` marks a live window slot, `node_level (P,N) int32` is the topological level (authority for `level`), and `edge_overflow (P,)` counts connections that did not fit the static `K`.
4. **Public names**: `common.tensorization.derive_schedule` (no `build_schedule` alias); **all static arguments are positional** (evoxc cannot pass keyword-only statics to `build`, so no `functools.partial` dance at call sites); `common.host_graph.{decode_graph, topological_sort, find_useful_nodes, node_depth, check_cycles}` and `common.__init__` re-exports the first three; `ACT.name_of`/`AGG.name_of` replace `get_func_name`; `common.tools.to_numpy(tensor)` is the host-side array accessor.
5. **No default `State()` in signatures**: `setup(self, state=None)` builds `State()` in the body (a default argument would run at class-definition time and break `import tensorneat`).
6. **Genome helper surface used by `algorithm/`**: `node_exists`, `conn_exists`, `max_node_key`, `max_conn_marker`, `conn_gene.uses_historical_marker`, plus statics `num_inputs/num_outputs/max_nodes/max_conns/max_in_degree`; `node_gene.from_attrs`/`conn_gene.from_attrs` are the public split-payload assembly helpers (`attrs=None` = the zero row) and have no call site anywhere in `src/`.
7. **Three RL environments ship, each validating `fitness_target` against its own return ceiling at construction** and each reaching `-inf` for a NaN-poisoned genome: **`CartPole`** (ceiling `max_step`, return = survival time) demotes NaN logits with an explicit `evoxc.isnan` census, while **`Pendulum`** (ceiling `0`, negated cumulative cost) and **`MountainCarContinuous`** (ceiling `100`, the one-time goal bonus) are poisoned *implicitly* through their action penalty — `tanh(NaN)` is NaN, so `0.001*u**2` and `0.1*a**2` respectively carry the NaN into the return. Every shipped problem ends with `problem.base.finalize_fitness`, the single NaN → `-inf` gate.

## API Surface (as implemented)
`tensorneat.Pipeline`, `tensorneat.algorithm.{BaseAlgorithm,NEAT,HyperNEAT,HyperNEATFeedForward}`, `tensorneat.genome.{DefaultGenome,RecurrentGenome,DefaultNode,BiasNode,OriginNode,DefaultConn,OriginConn,...}`, `tensorneat.problem.{XOR,XOR3d,CustomFuncFit,FuncFit,CartPole,MountainCarContinuous,Pendulum}`, `tensorneat.common.{ACT,AGG,State,TensorNEATError}`.
`tensorneat.algorithm` re-exports `BaseAlgorithm`, `NEAT`, `HyperNEAT` and `HyperNEATFeedForward` (the last from `tensorneat.algorithm.hyperneat`) with exactly those four names in `__all__`, pinned by `test/unit/algorithm/test_exports.py`.
`Pipeline(algorithm, problem, seed=42, fitness_target=1, generation_limit=1000, backend="numpy", device=None, compile_options=None, is_save=False, save_dir=None, is_detailed=True, show_problem_details=False, pop_batch_size=None, host_payload=True)` — host-only construction, no graph built and nothing printed until the first `step`.
`setup(state=None) -> State` registers `randkey`, `backend`/`device`/`compile_options`, the three formulation statics, the algorithm's payload/species and the problem's data, resets the run's history and, with `is_save`, writes `config.txt` and the `log.txt` header.
`step(state, host_payload=None) -> (state, previous_pop, fitnesses)` is the single compile site and one compiled-graph run; fitness is **last**, a host `numpy` `(P,)` float32 array, and `step` prints nothing.
`previous_pop` is a `GenomeTensors` of the population that produced those fitnesses: four host numpy arrays when `host_payload` is in effect (the constructor's `True` default, or a per-call override), otherwise **whatever the backend left** — numpy on the reference interpreter, device-resident `evoxc.Tensor` leaves on a device backend — so no copy is paid; `host_payload.materialize_payload` is the converter a caller (or a reporting path) uses on such a payload.
The generation graph returns the fitness vector and the two host-side scalars (the incremented generation and the schedule's overflow maximum) as **one packed `(P + 2,)` block**, so a generation pays one device-to-host copy for all three; `step` keeps the generation on `_host_generation` for the report and raises on a non-zero overflow before returning anything.
`auto_run(state) -> (state, best_genome)` loops on the host until `fitness_target` or `generation_limit`, owning all output, logging, checkpointing and early stop; it asks `step` for the payload only when the loop can consume it (`self.host_payload`, `is_save`, `is_detailed` or `show_problem_details`).
`_analyse` materialises the payload only on the generations that need it — a new best, a checkpoint, the problem's `show_details` hook — and a reporting path handed `None` raises a `TensorNEATError` naming the `host_payload` flag instead of reporting nothing.
The stop test and the reported statistics/best use `host_payload._finite_fitness`, which maps `NaN`/`±inf` to `-inf`, so a non-finite fitness from a custom problem never satisfies `fitness_target` and never becomes `best_fitness`.
`show(state, best)` prints one genome's behaviour through the problem's host-side `show` (schedule derived once, network re-baked as `evoxc.constant`), and `show_config() -> dict` is the deterministic, JSON-serialisable description of the run (the genome section names the mutation gates, the gene attribute laws, the crossover/distance classes and `input_transform`/`output_transform`, never a memory address); the search law is read off the algorithm and falls back to the inner `neat`'s species controller, so a `HyperNEAT` wrapper records `species_size`/`survival_threshold`/`max_stagnation`/`compatibility_threshold` exactly like `NEAT`; the `pipeline` section records `device`, `backend`, `compile_options`, `host_payload` and the three formulation statics.
`best_genome` is spelled **batch-first** everywhere: a one-individual batch — `node_keys (1, max_nodes)`, `node_attrs (1, max_nodes, A)`, `conn_keys (1, max_conns, key_width)`, `conn_attrs (1, max_conns, W)` — i.e. exactly `state.pop` at `P = 1`; `None` when no generation produced a finite fitness.
`auto_run`/`_analyse` store the selected individual with its leading axis added back, and `show` accepts that batch as well as the bare rows a checkpoint stores: `host_payload._one_individual` accepts **only** the one-individual batch or those bare per-individual rows, and rejects a `P > 1` payload **and** a missing/`None` payload with a `TensorNEATError` naming both accepted spellings (never a bare `TypeError`, never the population-axis message); a genuine disagreement between the four arrays' leading axes still raises the population-axis message.
`Pipeline._constant_act_fn` therefore bakes its payload **as given** — `self._analyse` hands it the whole population the diagnostics hook receives, `show` hands it the one individual `_one_individual` normalised.
`tensorneat.__version__` is `importlib.metadata.version("tensorneat")` with a `PackageNotFoundError` fallback to `"0.0.0"`; it imports nothing that reaches a backend.
Host-visible attributes: `fitness_history` (list of `(generation, max_fitness)`), `best_fitness`, `best_genome`, `detail_failures` (first failure per diagnostics-hook label, see `_details`), `shape_signature`, `build_seconds`, `builds`, `_executables`, `save_dir`, and the device-derived formulation statics `distance_centre`/`distance_formulation`/`kernel_mode` (also registered on the state by `setup`).
`setup` registers the three statics as plain strings derived from one decision — whether the resolved device **kind** is GPU-class (`"rocm"`, `"hip"`, `"hips"`, `"cuda"`, `"vulkan"`, `"gpu"`, compared case-insensitively) — made once by `host_payload._formulation_statics`: a GPU-class kind gets `"tiled"`/`"index_free"`/`"accelerator"`, every other kind and `None` get `"single"`/`"merge"`/`"host"`.
The kernel side treats a **missing** state entry as `"single"`/`"merge"`/`"host"` (the legacy contract), which is what a bare `State()` yields; `host_payload._formulation_signature` defaults the same way.
All three reach the graph through `_static_config`'s closure like every other non-tensor entry, never as graph-boundary tensors, and all three are rendered in `show_config()["pipeline"]`.
Fitness is maximized; NaN or infinite fitness is mapped to `-inf` before selection so broken topologies cannot win.
No `problem.jitable` flag exists: whether a graph compiles is the backend's business and `evoxc.BackendError` propagates.

## Compile Site
One `evoxc` graph per shape signature covers `split randkey → ask → transform → problem.evaluate(eval_key, act_fn) → tell`, so a generation is one `evoxc.run` plus host bookkeeping.
The graph boundary carries **tensors only** (the four payload arrays, `generation`, `randkey`, the `SpeciesState` leaves) and returns `randkey`, `generation`, the four payload arrays, the species leaves and then ONE packed `(P + 2,)` block (`fitness`, `generation`, the eval-phase maximum `edge_overflow`); the tensor-free configuration `State` is baked through the closure (`Pipeline._static_config` drops every tensor and every `_RUNTIME_KEYS` entry, the `NEAT._static_state` pattern), so no concrete tensor is ever captured by a trace.
The `act_fn` handed to a problem is a `host_payload._NetworkActFn` over the already-transformed schedule: `act_fn(inputs)` is one query and `act_fn.prepare(batch_rows)` derives the pass once (chunk groups prepared at trace time) for a problem that queries the same batch shape many times.
A rollout is the case that path exists for: `cartpole_p100` (200 policy queries per generation) executes 30 994 dispatches per generation through `prepare`, and the prepared pass pays its read-out once (one gather plus `O` mask comparisons, never per level) instead of once per query.
Both paths pass the schedule and the payload on at their native `P` rows together with the tiled `(P * S, ...)` inputs (a problem tiles a dataset or a rollout batch **individual-major**), and the genome recovers `S` from the two static shapes itself (`NodeStepMixin._sample_count`) and expands its own sample-invariant operands (`genome/window.py::by_samples`); `algorithm.prepare_forward`/`algorithm.forward_prepared` are uniform across `NEAT` (which takes the payload) and `HyperNEAT` (whose payload is its substrate schedule), so `pipeline.py` carries no forward adapter of its own.
The generation graph calls `algorithm.ask`: after registering the state's payload on `current` (whose `pop` is the graph's own tensor argument) the kernel takes `pop = algorithm.ask(current)` and hands that to `transform` and to the problem's `evaluate`, so an algorithm overriding `ask` is honoured instead of bypassed. Every shipped `ask` returns `state.pop` unchanged (zero ops), so the returned `previous_pop` *is* the population that produced `fitnesses`; `tell` receives `current`, so `next_state.pop` is bred from the argument payload and an `ask` that returns a different population must document that its evaluated phenotype is not the one reported/checkpointed.

## Caching Policy
The signature is `(pop_size, max_nodes, max_conns, max_in_degree, max_depth, key_span)`, followed by `host_payload._substrate_signature(algorithm)`'s entries `(nodes_cnt, conns_cnt, num_inputs, num_outputs, activate_time, nodes.shape, conn_index.shape, query_coors.shape, weight_threshold, max_weight)` when the algorithm wraps a fixed substrate (and `()` otherwise), by `host_payload._formulation_signature(state)`'s `(distance_centre, distance_formulation, kernel_mode)` statics, and last by `host_payload.eval_chunk_rows(self._device_kind(), max_nodes)` — the chunk budget is unrolled into the graph at trace time, so a CPU build is never reused on a device leg (or the other way round).
`_executable_for` keeps one `evoxc.Executable` per signature in `_executables` and rebuilds only when the signature changes, so a replaced substrate, a device/mode change or a different chunk budget can never reuse a stale executable.
The statics are read off the **state** (the graph's statics come from `_static_config(state)`), so updating any entry forces exactly one rebuild and leaves every other signature entry untouched; a repeated `step` on an unchanged state reuses the cached executable (`builds` stays at 1).
A second pipeline with a different `max_nodes` is a second entry and a second build; the build is timed into `build_seconds` and counted in `builds`, and `auto_run` pays it before its first generation.

## Overflow Policy
A non-zero `Transformed.edge_overflow` means the schedule dropped connections, so `step` raises `TensorNEATError` naming the count, the population and `max_in_degree` instead of evaluating a lossy phenotype.
The check is host-side on the maximum the generation graph returns inside its packed `(P + 2,)` block: a traced value never drives Python control flow.
`max_in_degree` is a **genome** static, so the pipeline cannot widen it silently — the caller rebuilds the genome, and a lossy schedule is never used.

## Key Discipline
`Pipeline.setup` creates the one root key (`evoxc.random.key(seed)`); `NEAT.setup` then splits it once inside the init graph so `init_key` draws the whole population's attributes and the other half is carried into generation 0.
Exactly one `evoxc.random.split` happens at the pipeline boundary per generation: `eval_key` goes to the problem and the advanced key goes to `tell`, which advances it again before the generation returns.
`step` stores that returned key on the new state, so one `step` is exactly one generation of key advance and `(seed, config, shape)` reproduces a run.

## Checkpoint Layout (`is_save=True`, written by `setup`/`auto_run`)
`config.txt` — `json.dumps(show_config(), indent=4)`, a deterministic description of the run: `host_payload._object_config` names each gene/operator by its class path plus its public primitive attributes (the mutation gates `conn_add`/`conn_delete`/`node_add`/`node_delete`, the gene attribute laws, the crossover/distance classes) and renders callables such as `input_transform`/`output_transform` by their qualified name, so two identical runs write identical bytes and no memory address ever reaches the file.
`log.txt` — header `Generation,Max,Min,Mean,Std,Cost Time`, then one row per generation.
`genomes/<generation>.npz` and `genomes/best_genome.npz` — `node_keys`, `node_attrs`, `conn_keys`, `conn_attrs` and `fitness`, one individual per file: the batch-first payload flattened (no population axis). The four arrays round-trip to a payload `show`/`network_dict` accept (bare rows) and re-score to the recorded fitness; the `fitness` entry must be dropped first, because `_one_individual` requires exactly four fields (`dict(np.load(path))` has five and is rejected).
`best_genome.npz` is omitted when no generation produced a finite fitness; a bare `step` loop writes no files (`auto_run`/`_analyse` is the writer, and it materialises a device-resident payload through `materialize_payload` before writing).

## Measured Cost
The cost laws of this tree, measured in one session (2026-11-06) on one box: the numpy reference interpreter charges **≈19–20 µs per dispatched op** (op count is the lever at population-sized tensors, element volume once a problem tiles the population); on `iree`+`rocm` a generation costs **`max(host submission, device)`**, a flat graph pays **≈63 µs fixed + ≈2.2–2.5 µs per dispatch**, **one `while` iteration costs ≈50 µs** because the loop condition is read back to the host, and **`Tensor.to(cpu)` costs a fixed ≈47–60 µs per leaf** regardless of its size.
The box drifts ±30 % between sessions, so a same-session pair is the load-bearing number, never the absolute milliseconds.

Per-generation medians on this tree (same session, one process per cell):

| case | numpy | `backend="iree"`, `device="rocm"` |
| --- | --- | --- |
| xor_p100 | 33.04 ms | 17.42 ms |
| xor_p500 | 112.68 ms | 13.24 ms |
| xor_p1000 | 177.43 ms | 16.29 ms |
| custom_pagie_p500 | 847.13 ms | 16.18 ms |
| cartpole_p100 | 248.70 ms | 150.41 ms |

The ROCm leg builds **7.2–8.0 s per static shape** and peaks at **≈1.9 GiB** of RSS; it now beats the numpy interpreter on every measured cell, so `"numpy"` stays the default because it needs no optional dependency and is the portability reference, not because it is the fastest leg.
`"iree"` on llvm-cpu remains slower per generation than the interpreter (the measured table, protocol and per-gate record are in `benchmarks/BACKENDS.md`); `"xla"` needs a user-supplied PJRT C API plugin (`EVOXC_PJRT_PLUGIN`) and `"tvm"` is untested.
Executed ops per generation on this tree, counted on the numpy interpreter with a monkeypatched `evoxc.backends.numpy.kernels.dispatch`: `xor_p500` **7 592** (of which the 40 compatibility-distance calls are 3 675, 48 %) and `cartpole_p100` **30 994**.
Those counts exclude the `output_slot` read-out, which adds one gather plus `O` mask comparisons once per pass and never per level.
`benchmarks/PERF_NUMPY.md` is the hand-maintained numpy cost record (two passes, each with its own protocol, before/after pair, peak RSS, build time and reproduce commands) and the reference for any numpy A/B whose tree is not this one.
`benchmarks/RESULTS.md` is the *generated* old-vs-new harness report, rendered only by `benchmarks/run_benchmark.py` from `benchmarks/results/authoritative.json`; it was measured after the op-count pass and before the tiled-evaluate/RL-rollout-hoist and accelerator passes, so its new-side rows are never the current cost, its committed verdict is `FAIL` for the tree it measured, and only a full harness re-run may replace it.
The two structural fixes those passes made are recorded as laws: a tiled func-fit evaluate must derive every sample-invariant static at `P` rows and expand, never at `P*S` rows, and a rollout must derive its genome-forward prelude once per generation (`prepare`) rather than once per policy query.
The genome ships a grouped form of the distance kernel — `genome/operations/distance/grouped.py::group_digest` + `GroupedDigest`, one `measure` call on a `k*P`-row centre, bit-identical to `k` plain calls — and `algorithm/neat/_distance.py::DistanceRows.matrix` wires it **on the accelerator leg only** (`grouped.group_size` answers `k = 2` under `kernel_mode="accelerator"` and `1` everywhere else, so the numpy graph is untouched). On numpy it is a measured loss: it cuts dispatched ops 7 592 → 6 589 (−13 %) while peak RSS rises 233.8 → 253.2 MiB and wall time turns bimodal at process level (152–165 ms fast against 196–253 ms, in 7 of 13 fresh default-environment processes; stable at 152 vs 159–162 ms only when glibc is forced onto brk), because the 2× wider `(2P, 2 * max_conns)` merge intermediates stop fitting in cache; `k = 4` reads +15 % wall / +30.5 % RSS.
So on numpy **op count is not the lever — padded gene geometry and element volume are**, and the grouped route is only an option for a dispatch-bound backend.
`speciate` is still the largest phase on the interpreter — two fixed-length scans over `species_size` slots, one population-shaped distance row per slot — followed by the mutation/crossover chain and `transform`; the digest is paid once per generation (`prepare_distance`) and the rows are measured `species_size * 2` times, and the pair count `species_size * 2 * pop_size` is irreducible under NEAT's assignment semantics.
The forward level loop is a `while` whose body is 5 real IR ops (`gather`, `select`, `scatter`, `not_equal`, `reduce_max`), run `depth + 1` times.

## Network-Evaluation Cost When a Problem Tiles the Population (func-fit)
`act_fn` receives the whole tiled batch: a problem tiles its dataset or rollout over the population axis, so the network is asked for `P * S` rows while the schedule and the payload stay at their native `P` rows.
`Genome.forward` recovers the static factor `S = batch // P` (`NodeStepMixin._sample_count`) and expands only its own sample-invariant operands once (`genome/window.py::by_samples`), so a `(250000, 50, 4)` = 191 MiB float32 window per level is paid by the *values*, never by the schedule: at generation 3 the networks carry ≈3 real nodes of 50 and ≈2 real connections of 100 (1.3 % live slots), so the padding dominates the element volume.
`host_payload._prepared_query` therefore only regroups, at the budget `host_payload.eval_chunk_rows(device_kind, max_nodes)`: **`EVAL_CHUNK_ROWS` = 12 500 rows on the CPU interpreter** (a cache/live-set bound; the group loop is unrolled at trace time, so 20 groups are 20 copies of the forward's dispatch sequence) and, on a non-CPU device, **`max(12 500, DEVICE_EVAL_CHUNK_BYTES // (4 · max_nodes))`** with `DEVICE_EVAL_CHUNK_BYTES` = 1 GiB, because a device's cost is dispatch-sequence length rather than live set.
A 250 000-row func-fit block is therefore 20 groups of 25 individuals on CPU and **one unchunked pass** on a device (≈5.37 M rows at `max_nodes=50`); the group outputs are concatenated in row order, which is bit-identical because every forward op is row-local and the level loop's depth bound is a per-batch maximum, and a smaller block (`S=4` XOR, the RL cases at `repeat_times=1`) takes the single unchunked call.
The budget is a host-side static: it is part of `Pipeline._shape_signature`, read at trace time, so a monkeypatched budget reaches both legs.
The budget is load-bearing: the unbounded `P*S` block it replaced measured 3282 / 3315 ms per generation against 838 / 841 ms with the CPU budget in a same-session A/B, at 4578 → 1315 MiB peak RSS (`benchmarks/PERF_NUMPY.md` pass 2).
The trees a group slices are **declared population-major** (the genome `Transformed` and the four-array payload both put the population on axis 0, and `HyperNEAT`'s `SubstrateSchedule` holds the substrate schedule plus its `(P, N)`/`(P, Q, ...)` payload, all population-major), and `_slice_batch` enforces that declaration: every non-scalar leaf must carry `pop_size` on axis 0 and a leaf whose leading dimension differs raises `TensorNEATError` instead of being silently shared or mis-sliced.
What still dominates is the level loop's own element volume, `(depth + 1) × P·S × max_nodes × max_in_degree`, plus the one tiled `add` of the flat window index that cannot be a `P`-row derivation (the gather index bakes the absolute row offset); `gather` (numpy `take`) and `select` (numpy `where`) run at 0.6–0.8 GB/s on 50M-element index arrays against ≈10 GB/s for `multiply`.
Right-sizing the genome geometry beats every kernel tweak on this path: `max_nodes`/`max_conns` 50/100 → 20/40 is 2.7× and → 12/24 is 4.4×, but that changes the evolved workload, so it is a caller decision, not a fix.
Memory is set by the interpreter's per-block live set: it retains every SSA result of a block until that block returns, and the chunk loop is unrolled Python, so each chunk's entry-block intermediates stay alive until the generation returns; the peak therefore tracks the chunk budget rather than `S` and is not linear in the dataset size.
A real memory win over that needs the chunk loop as an `evoxc.scan`, which nests control flow around the forward's level `while_loop` — the portability rule forbids it until `test/backends` can prove it, so it stays out.

## Search Quality (current, measured on the numpy backend)
The quality contract for the search layer is `benchmarks/cases.py`'s XOR family: `DefaultGenome(num_inputs=2|3, num_outputs=1, max_nodes=50, max_conns=100, output_transform=ACT.sigmoid)` + `NEAT(pop_size=P, species_size=20, survival_threshold=0.01)`, 150 generations, no early stop, fitness = −mse.
A genome built without an explicit `mutation` operator ships an unbalanced connection-gate pair, `conn_add=0.4` against `conn_delete=0.05` (`genome/operations/mutation/default.py::DEFAULT_GENOME_CONN_ADD`/`DEFAULT_GENOME_CONN_DELETE`); `DefaultMutation()`'s own defaults stay NEAT-python's 0.2/0.2, so an explicitly constructed operator is unchanged.
XOR converges: pop 100 seed 42 reaches its target at generation 41 (final −1.64e-05) and pop 500 seed 42 at generation 33 (final 0.0).
XOR3d pop 100 escapes the constant-0.5 basin on **13 of seeds 0-19** and reaches the −0.05 target on **11** (median escape generation 75), against the frozen oracle's 4 and 2 on the same seeds (Fisher p = 0.0095).
XOR3d pop 500 reaches target on **6 of seeds 42-47** and pop 1000 on **3 of 3** of seeds 42/43/44 (3-seed median −4.44e-11); the per-seed tables live in `algorithm/CONTEXT.md`.
The mechanism is connection-gate balance, not node birth: `add_conn` is accepted about half as often as `delete_conn` at equal rates (duplicate, self-connection, cycle and `max_in_degree` refusals), so the 0.2/0.2 pair sat at an operator steady state of −0.14…−0.22 connections per individual per generation and populations stayed under-wired; at 0.4/0.05 the same cell reaches 10.38 connections, output in-degree 2.59 and a 0.82 multi-input-ancestor fraction at generation 150, with the node count unchanged and no previously converging cell regressed.
On the probed seeds the first escape was a weight-only move on pre-existing topology in 13 of 14 cases, so the escape is a weight-space lottery that pays out in proportion to how many structured individuals the population can hold.
`custom_pagie_p500` seed 42 reaches −0.0103 at 150 generations against the −0.01 target and the legacy −0.0064, a slow climb that runs out of budget rather than a plateau.
Rejected as the pop-100 lever: weight-mutation frequency, a same-generation add-conn value exemption, a milder 0.3/0.1 gate pair and a `min(2, members)` survivor floor — `genome/operations/mutation/CONTEXT.md` and `algorithm/CONTEXT.md` hold the records.
Evaluation is not implicated: hand-built payloads score bit-identically through `Pipeline.step` and a host numpy oracle, and all three input channels measurably move the output.
Two structural contracts keep the search from silently losing genes: every allocated structural key lies inside `[0, key_span)` (`algorithm/neat/_keys.py`; `key_span <= max_nodes` raises at `NEAT` construction) and every structural operation is gated independently (`genome/operations/mutation`).
`algorithm/neat/_kernels.py::pair_parents` pins elite slot k of a species block to that block's rank-k member, so a species never clones its champion into both elite slots.

## Device Placement
`Pipeline(..., device=...)` accepts a kind string (`"cpu"`, `"cuda"`, `"rocm"`) or an `evoxc.Device`; `Pipeline._placement_device` resolves it (`None` stays `None`, a string becomes `evoxc.Device(kind)`, a `Device` is returned unchanged) and is the only spelling the placement helpers use.
`Pipeline.setup` keeps the setup-time graphs on CPU: it registers `device=None` for `algorithm.setup`/`problem.setup`, so `NEAT.setup`'s initialisation graph and the problem's setup never see a device/`randkey` mismatch (`evoxc.run` transfers nothing across devices).
`Pipeline._host_build_options` drops only the device-targeting `compile_options` keys (`"device"`, `"target_backends"`) for that phase, because a CPU setup graph cannot execute an artifact compiled for the accelerator; every other option key (`iree_compile_args`, `iree_runtime_args`, flags, `opt_level`, ...) is forwarded unchanged.
After `problem.setup` the real `device` **and** the caller's real `compile_options` are registered, and `Pipeline._place_state` moves the runtime tensors once, through `evoxc.tree_map` over exactly `_RUNTIME_KEYS` (`pop`, `generation`, `species`, `randkey`) — never the whole `State`, which also holds configuration objects.
A same-kind placement is `Tensor.to(device)` (`self` on the tensor's own device); a cross-kind placement goes through the host, because the runtime tensors `algorithm.setup` returns are payload-backed and `evoxc` refuses a payload-to-device transfer, so the leaf is read back with `to_numpy` and re-uploaded as `evoxc.from_numpy(...).to(device)`.
That host hop makes the array C-contiguous only when it is not already, so a rank-0 `randkey`/`generation` keeps its scalar shape (`np.ascontiguousarray` would promote it to `(1,)`, which `evoxc.random.split` rejects).
Placement is idempotent and `device="cpu"` is identity for every tensor, so the default numpy path is byte-identical and allocates nothing; `device=None` skips the placement pass entirely and returns the identical state.
Every later `step` runs the cached executable at `_build_options()`, which forwards the state's real `device` to `evoxc.build`, and the graph outputs stay device-resident: `new_state` is rebuilt from them, so a generation copies only the packed `(P + 2,)` host block and — when the loop asked for it — the four payload arrays.
`common.tools.to_numpy` is the single explicit device-to-host step: a tensor whose `.device.kind != "cpu"` is transferred with `Tensor.to(Device("cpu", 0))` before `.numpy()`, while a CPU tensor or an ndarray is never copied; that transfer costs a fixed ≈47–60 µs per leaf regardless of size, which is why the three host scalars travel packed and why `Pipeline(host_payload=False)` exists.
Host-reporting graphs run on the CPU side-channel: `Pipeline._host_view(state)` returns a `device=None` view with its runtime tensors on `cpu:0`, and `_schedule_of`, `_constant_act_fn`, `show` and both `show_details` calls in `_analyse` take that view, because `evoxc.from_numpy`/`evoxc.constant` are CPU-only and a per-generation report must not pay a fresh compile on the requested device.
`_analyse`'s numeric path (`_finite_fitness`, `np.asarray`, `_save_generation`, `_save_best`) reads only the host `fitnesses` and the payload it materialises, never a device tensor it was not given.
A device that cannot be reached raises `evoxc`'s own error (`DeviceError`, or the transfer provider's import/`TypeError`): nothing falls back to CPU.
`evoxc` has no `device_put`/`to_device`: `evoxc.Device(kind, index)` plus `Tensor.to(device)` is the only transfer API, and `evoxc.run` requires every leaf to be already on `executable.device`.
`test/unit/test_pipeline_device.py` pins this layer on CPU with no GPU: device resolution, the stripped setup options, identity placement for `None`/`cpu`, a cross-kind upload through a registered fake provider (rank-0 preserved, contiguous host tensor, values round-trip), the host view, `to_numpy`'s explicit D2H branch, and bit-identical `device="cpu"` vs `device=None` runs.

## Accelerator Status (ROCm / MI300X)
A full generation graph runs on ROCm: `Pipeline(..., backend="iree", device="rocm", compile_options={"target_backends": ["rocm"]})` sets up on CPU, places `pop`/`randkey`/`generation`/species on `Device("rocm", 0)`, builds a generation graph in 7.2–8.0 s and runs every shipped case end to end — no `DeviceError` anywhere, and the per-generation numbers are the ROCm column of `## Measured Cost`.
What dominates there is the **dispatch floor, not arithmetic**: one dispatch costs ≈2.2–2.5 µs however little work it does, plus a ≈63 µs fixed per-graph charge, so above a few hundred kernels the lever is dispatch count; a `while`/`scan` region boundary additionally pays a ≈50 µs host round trip per iteration, which is why an unrolled graph of the same device time can beat a loop (`algorithm/neat/CONTEXT.md` holds the rejection that follows from it).
The kernel-level law behind the formulations: an `evoxc` `scatter` lowers to **one workgroup of one thread**, at 17–21 ns per update element and independent of the destination width, while `gather`, elementwise ops and reductions spread over the whole grid.
Three device-shaped routes are selected by the statics described under `## Caching Policy` on a GPU-class device kind, and every one is bit-identical to the host route, generation for generation:

| route | module | selection |
| --- | --- | --- |
| schedule writes without their scatter (`cumulative_indegree` for `cc`, `key_template` for the key→slot table) | `common/schedule_accelerator.py` | `kernel_mode` |
| cycle hop without a scatter (equality template + windowed hop) | `genome/operations/mutation/cycle_accelerator.py` | `kernel_mode` |
| homologue table as one `(P,M,M)` equality table instead of the sort merge | `genome/operations/distance/index_free.py` | `distance_formulation` |
| homologue alignment as comparison-rank over `(P,M,M)` (no `argsort`) | `genome/operations/alignment_accelerator.py` | `kernel_mode` |
| one `measure` call per `k = 2` centre slots (scan 1 only; `k > 1` requires `"tiled"` mode and the accelerator leg) | `genome/operations/distance/grouped.py` | `kernel_mode` + `distance_centre` |
| speciation slot axis reduced row-wise as one `(S,P)` block (scan 2's seed stays the residual per-slot reduction) | `algorithm/neat/_scan_accelerator.py` | `kernel_mode` and `distance_centre` |
| seed block spliced by one gather plus a baked `where` mask instead of a `concatenate` | `genome/window.py::seed_pad`/`seed_values` | `kernel_mode` |
| prepared-pass read-out gathered once per pass (`_ReadOut`/`_output_readout`) | `genome/step.py` | every leg (one gather + `O` mask comparisons) |
| RL step bodies: CartPole's Euler row assembled with baked lanes (`^bb8` 6 dispatches, 21 per timestep at depth 3), Pendulum's packed `(row, step)` carry (21 accelerator against 19 host per timestep), MountainCar's 4-dispatch floor (19 per timestep) | `problem/rl/*.py` | CartPole and MountainCar unconditional, Pendulum on `kernel_mode` |

No committed test selects `kernel_mode`/`distance_centre`/`distance_formulation`, so every route in that table is a hand-run verification (bit-identity checked field by field and generation by generation); a `test/backends` cell that builds a gated pop-100 graph in accelerator mode is the missing regression guard.
No ROCm row belongs in `benchmarks/RESULTS.md` until the harness measures this leg; the record for it is this section plus `benchmarks/gpu_measure.py` and the per-formulation records under `algorithm/`, `genome/` and `problem/`.
The HIP `while`/`scan` abort that blocked this leg on `iree-base-runtime` 3.11 is fixed in 3.13; `benchmarks/spikes/rocm/repro_minimal.py` and that directory's ladder remain its reproducer.

## Constraints
- `import tensorneat` must not import `jax`, `torch`, `brax`, `gymnax`, `mujoco` (release-gate test); optional backends are pulled in only by `evoxc.build(backend=...)`.
- evoxc idioms are mandatory: `@evoxc.defn` graph entry points, plain helpers otherwise, `evoxc.numpy as enp` for tensor creation (float literals become f64 constants otherwise), `evoxc.random` for keys, `evoxc.constant` only for genuinely static data, non-negative axes in `concatenate`/`split`.
- No eager fallback: if a backend cannot compile a kernel the error propagates; we never quietly compute on the host.
- NaN padding semantics of the pre-rewrite library are preserved (`test/parity/` depends on them); `select` chains stand in for `lax.switch`.
- Errors: user/config validation raises `common.errors.TensorNEATError` (and its subclasses); tensor/backend errors are never caught and re-wrapped.
- The formulation statics are trace-time Python strings read off the configuration `State`: never a traced value, never a graph-boundary tensor, and an unknown value raises rather than falling back silently.
- A new kernel with a device-specific spelling goes beside its host spelling in its own module behind one of the three statics, stays bit-identical to it, and leaves the host path untouched — a route that only wins on a compiled backend must not change the numpy graph.
- Files ≤ ~1000 lines; shared math lives in `common/`, never duplicated per genome/algorithm. Declared exceptions: `common/tensorization.py` (1057, one cohesive schedule derivation including both formulations), `algorithm/neat/neat.py` (1026, `tell` plus the diagnostics that belong beside it) and `genome/base.py` (1005, the kernel contract every genome subclass shares).
- The numpy interpreter keeps every SSA result of a block alive until that block returns, so a kernel's live set is charged once per enclosing block: never hoist a kernel out of a `while`/`scan` without measuring peak RSS (hoisting the 20 speciation rows was 28 % faster and 1.7× the memory; measuring them inside one `evoxc.scan` is 40 % faster and below the starting memory).
- Never seed a `while`-carried value with a `scatter`: it SIGSEGVs `iree-compile` in the assembled graph while exporting cleanly; seed with a one-hot `equal`/`logical_and`, and treat only `test/backends` as proof of portability.
- `pipeline.py` (1390 lines) is one job — the single compile site, the device-placement helpers (`_placement_device`/`_host_build_options`/`_place_state`/`_host_view`) and the design, caching, overflow and measured-cost documentation that belongs next to them; the host-side payload/fitness/config helpers live in `./host_payload.py` (900 lines, including the device-kind → formulation rule and the chunk budget), so the pair keeps to the documented ~1000-line exception.
- `Pipeline._details` is reporting-only by contract: a failing `show_details` hook (algorithm or problem) is printed and its `(type, message)` recorded once per label in `Pipeline.detail_failures`, and the evolution loop continues — a broken printer never aborts a run, and it never disappears without a record.
