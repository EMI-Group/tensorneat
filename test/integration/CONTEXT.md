# ./test/integration — whole-`Pipeline` runs on the numpy backend

## Intent
Prove the *assembled* library rather than its kernels: a `Pipeline` built from the documented public API evolves XOR, reproduces itself from `(seed, config, shapes)`, survives a shape change, leaves a loadable checkpoint, decodes a HyperNEAT substrate, and never lets a diagnostics or non-finite-fitness path corrupt a run.
Sixty tests across fourteen modules drive the real `Pipeline` (`setup` → `step` / `auto_run`) on the numpy reference interpreter and assert on what the pipeline returns, prints or writes, never on an intermediate kernel.
No `jax`/`torch`, no network, no GPU, no wall-clock assertions: a run is judged by generations, fitness, payload shapes and compile counts.
Every module carries `pytestmark = [pytest.mark.slow]`; `pytest -m slow` selects the directory, the default gate leaves it out.

## Current state: every test runs, and a regression fails
`src/tensorneat/pipeline.py` is the evoxc compile site, so `conftest.py::missing_evoxc_pipeline_features(tn)` returns an empty list and the suite runs.
The probe is structural, never hardcoded: it inspects `inspect.signature(tn.Pipeline.__init__)` for the four documented compile kwargs (`PIPELINE_COMPILE_KWARGS = ("backend", "device", "compile_options", "is_detailed")`), checks whether the loaded `tensorneat.pipeline` module binds `jax`/`jnp`, and scans that module's source file for a top-level `import jax` (it never imports jax to find out).
`require_evoxc_pipeline` now **raises `AssertionError`** naming every missing feature, and the autouse `_evoxc_pipeline_required` fixture applies it to every test: losing a compile keyword or re-binding `jax` turns the directory red with a clear message instead of green with silent skips.
The suite has no skip channel of its own: `support.lazy.require` propagates every error by default — a `NotImplementedError` from this tree is a defect, not a skip — and only the opt-in `allow_pending=True` (which `./conftest.py` never passes) turns a `NotImplementedError` raised inside `src/tensorneat` into a named skip; no test body uses `skip`/`skipif`/`xfail`.
`test_shape_rebuild.py`'s compile-observability probe follows the same rule: if the first step makes no observable `evoxc.build/build_cached/lower/compile` call it now `pytest.fail`s, naming the compile-site contract.
No module imports `tensorneat` or a `support` module at module scope: `tn`, `payloads` and `runner` are `support.lazy.require` fixtures, and only `numpy`/`json`/`pytest` plus `from integration.conftest import …` appear at module scope.

## How a test builds and drives a `Pipeline`
`./conftest.py` owns the single XOR configuration, `TINY_CONFIG`, grouped by the object that owns each knob: genome `num_inputs=2, num_outputs=1, max_nodes=8, max_conns=16, max_in_degree=4, max_depth=8, output_transform="sigmoid"`, `NEAT(pop_size=16, species_size=4)`, `XOR(error_method="mse")`, `Pipeline(seed=0, fitness_target=-0.01, generation_limit=60, backend="numpy", device=None, compile_options=None, is_save=False, save_dir=None, is_detailed=True, show_problem_details=False)`.
`tiny_pipeline(**overrides)` returns that `Pipeline` **configured but not run**; an unknown knob raises `TypeError`, and `output_transform` is either an `ACT` registry name (`"sigmoid"`), a callable, or `None`.
`fitness_target=-0.01` on XOR's negated `mse` means "mean squared error ≤ 0.01"; tests that need a fixed-length run pass `fitness_target=1.0`, which XOR can never reach, so exactly `generation_limit` generations are consumed.
`run_pipeline(pipeline)` is `setup()` + `auto_run()` and returns `(state, best)` — `auto_run`'s documented pair, nothing derived.
`step_once(pipeline, state)` runs one `pipeline.step` and returns `(state, (P,) fitness)`, validating the documented step contract: a tuple whose `[0]` is the new state and whose `[-1]` is a length-`pipeline.pop_size` floating array (`step`'s middle element is `previous_pop`, the host payload that produced the fitness).
`step_loop(pipeline, state, generations=None, target=None)` drives `step_once` for a fixed count (or until `max(fitness) >= target`) and returns `(state, [max_fitness_per_generation])` — the trajectory oracle, read from what the pipeline reports rather than from an undocumented history attribute.
`state.pop` is a `genome.utils.GenomeTensors` (`node_keys (P,N) int32`, `node_attrs (P,N,4) float32`, `conn_keys (P,C,2) int32`, `conn_attrs (P,C,1) float32`); `state.generation` is a 0-d float32 evoxc tensor and must be read as `int(to_numpy(state.generation))`.

## Requirements this suite imposes on `pipeline.py` (cross-node)
`Pipeline.step` must return a tuple with the new `State` first and the `(pop_size,)` fitness last; `step_once` rejects anything else with a message quoting that contract.
`Pipeline.auto_run` must return `(state, best_genome)` with the best a P=1 batched `GenomeTensors` padded to the static signature, must report `None` when no generation produced a finite fitness, and must record the run's best fitness so the checkpoint and the re-score agree.
`Pipeline` must expose `pop_size`, `builds`, `shape_signature` and `detail_failures`, and must keep `State` keys `pop`, `generation`, `randkey` (`NEAT.setup`/`tell` own them).
`Pipeline.show` must accept `auto_run`'s batch-first `best_genome` unchanged and the same genome as bare per-individual rows, print the problem's report and return `None`; a `None` (missing) payload must raise `common.TensorNEATError` naming the accepted spellings, never a bare `TypeError`.
`show_problem_details=True` must call `problem.show_details(state, randkey, act_fn, schedule)` and `algorithm.show_details(state, fitness)` once per generation; a failing hook must be printed, recorded first-per-label in `detail_failures`, and must not abort the run.
The generation kernel must call `algorithm.ask(current)` and use its result for `transform`/`evaluate` (the shipped `ask` returns `state.pop` unchanged, zero ops); `tell`, `previous_pop` and checkpoints stay on `state.pop`, which is the documented reporting mismatch.
`auto_run`'s early stop must compare `host_payload._finite_fitness`'s view, so `+inf`/`NaN` from a custom problem can never satisfy `fitness_target` and `-inf` is the only non-finite value selection sees.
`Pipeline.show_config` must fall back from a wrapper algorithm to `algorithm.neat.species`, and the checkpoint's `config.txt` must be exactly `json.dumps(show_config(), indent=4)`.
`Pipeline._shape_signature` must append `host_payload._substrate_signature(algorithm)` for a substrate-owning wrapper, so replacing the algorithm with a different substrate geometry is a new executable; mutating `algorithm.substrate` in place with different counts is unsupported (`hyper_genome` is sized at construction), so the test constructs a fresh algorithm.
`host_payload._slice_batch` must reject a non-scalar leaf whose leading dimension is not `pop_size`; a forced-chunk run must be bit-identical to the unchunked one for both `NEAT` and `HyperNEAT`.
The compile site must reach the compiler through `evoxc.build`, `build_cached`, `lower` or `compile`; otherwise `test_a_second_generation_of_the_same_shape_does_not_compile_again` fails, naming exactly that requirement.
`is_save` must keep the legacy layout (`config.txt` as `json.dumps(show_config(), indent=4)`, the `LOG_COLUMNS` header, one appended line per generation, per-generation and best-genome npz files), and `best_genome.npz` must store `node_keys`/`node_attrs`/`conn_keys`/`conn_attrs` plus a scalar `fitness`, because the payload has no bitcast and cannot be packed into a mixed-dtype `nodes`/`conns` pair.
`pipeline.fitness_history` is optional: `fitness_history()` falls back to `<save_dir>/log.txt`, which `is_save=True` always writes.

## Budget
Measured on this machine: `pytest test/integration -o addopts="" -q` is **60 passed in 28.2 s** (with every extra installed; `pytest -m slow` adds the release gate's XOR run).
`test_xor_run::test_auto_run_reaches_the_xor_fitness_target` dominates (`pop_size=100`, up to 250 generations, one compile per shape).
Every other module runs 1–10 generations at `pop_size≤16`; the HyperNEAT modules run pop 4 for two generations each (a second or two per test) and the three evolving cases of `./test_show_best.py` spend one generation each.
The convergence budget is calibrated from the legacy curve in `benchmarks/RESULTS.md` (`pop_size=100` reached `mse ≤ 0.1` at generation 77 and `mse ≈ 0.0099` by generation 150); the evoxc rewrite reaches its target inside the configured budget on this machine.

## Known issues / uncertainty
The convergence budget is the legacy-calibrated one; the evoxc run reaches the target inside it, so it stays headroom rather than a measured floor.
`test_step_advances_one_generation_and_reports_one_fitness_per_individual` assumes the fitness returned by `step` belongs to the population the step consumed (`state_before.pop`); a pipeline that returned post-`tell` fitness instead would fail it loudly.
`test_the_best_fitness_is_non_decreasing_across_generations` rests on NEAT's per-species elitism preserving the population maximum; if species spawn allocation can drop the elite, this is the assertion to revisit (it is not weakened).
`state.generation` is asserted to reach exactly `generation_limit` on fixed-length runs and `1` after a single step; a different counter base would surface there.
Nothing in this directory can observe the pipeline's per-shape cache object itself — only the compile counts and `Pipeline.builds`/`shape_signature`; the off-shape "must raise" contract is not testable from outside a cached executable.
On the numpy backend `state.pop` leaves are `evoxc.Tensor` wrappers, so `np.array_equal` on two raw payloads compares object arrays and returns False; every payload assertion unwraps with `runner.to_numpy` (or `common.tools.to_numpy`) first, and the identity assertions compare the wrappers themselves.
The chunk budget is reachable with no device attached by monkeypatching `host_payload.EVAL_CHUNK_ROWS`, so the device branch's own window arithmetic (`DEVICE_EVAL_CHUNK_BYTES // (4 * max(1, max_nodes))`) is only table-tested and never run on hardware.
`Pipeline` surface never exercised end-to-end here: a non-`None` `device` beyond `device="cpu"`'s `setup()` and last-signature element (no step runs with a device; `pipeline.py:477-478`), `compile_options` and any `backend` other than `"numpy"` (only `../backends`, skipped without the iree extra), `pop_batch_size` (`tiny_pipeline` does not forward it), the default timestamped `save_dir`, and every `pipeline.py` error path except `show(state, None)` (`_validate_arity`, the missing-`pop` guard, the `edge_overflow` raise, the `pop_batch_size` mismatch, the species-leaf change).
`test_checkpoint.py` checks `config.txt` only as a non-empty JSON mapping; the HyperNEAT module compares the species-law keys, but the XOR run's values are not compared with the configuration that produced them.
`GOLDEN` (`test_rl_golden.py`) is a recording of this tree's own output, not an independent oracle: its magic numbers must be re-recorded on any intended search/RNG change.
The HyperNEAT coverage uses a deliberately tiny CPPN (`max_nodes=12`, `max_conns=24`) and six func-fit samples, so it pins the wiring (decode, substrate signature, checkpoint, `network_dict`) rather than search quality.

## Conventions
Every test has a real body; the directory has no skip channel — `support.lazy.require` propagates by default and skips only an opt-in `allow_pending=True` `NotImplementedError` raised inside `src/tensorneat`, which no fixture here passes — and no test body calls `skip`/`skipif`/`xfail`.
The structural probes (`require_evoxc_pipeline`, the shape-rebuild compile probe) fail loudly instead of skipping, because on this tree the evoxc compile site is the code under test.
Assertions are never weakened to get green: a genuine `src/` defect is reported (or pinned with `xfail(strict=True)` and a one-line reason), never hidden behind a tolerance or a skip.
Shapes stay small (`pop_size` 8/16 for XOR, 4 for HyperNEAT, `max_nodes ≤ 16`), checkpoint tests always pass `save_dir=tmp_path`, and `log.txt`'s `Cost Time` column is parsed but never asserted on.
Files stay under ~1000 lines (largest: `./conftest.py` at 889); one test module per documented behaviour area, module basenames unique across the tree.

## Constraints
`../src/tensorneat`, `../../benchmarks` and `../../pyproject.toml` are read-only inputs: a defect or contract gap found from here goes into the report to the parent, never into this directory's diff.
`pytest`'s prepend import mode names a test module by bare basename, so `./__init__.py` namespaces this directory as `integration.*`; do not delete it.
No new dependency, no `import jax`, no network, no GPU, `backend="numpy"` everywhere.
