# ./unit/genome — payload, forward/grad and operator suites for the genome subtree

## Intent
Prove that each genome kernel computes what its docstring promises, on the reference numpy backend, with no optional dependency.
The assertions are about *invariants* and hand-written oracles, never about the implementation's own intermediate state: closed-form values on analytically chosen networks, `support.oracle` rollouts on the tedious topologies, and set/count algebra for the stochastic operators.
Nothing skips and nothing is `xfail`: the suite is a verifier, not a spec (`git log` has the spec era).
Several modules pin a guard that a naive implementation would pass by accident: `test_forward.py` activates hidden rows but not output rows, `test_recurrent.py` contrasts a live sibling against a starved one, `test_level_order.py` relabels a genome so row order disagrees with level order, and `test_mutation_weight.py` derives the perturbation magnitude from `weight_mutate_power` instead of asserting "it changed".
The device-gated accelerator spellings are pinned the same way: `test_forward_accelerator.py` (the `prepare_pass` level sweep) and `test_accelerator_equivalence.py` (`closes_cycle`, `homologous_pair`) hold each `kernel_mode="accelerator"` leg to the host leg exactly and prove the route on the traced IR, because equal output is also what a leg that ran twice would produce.

## Layout
180 collected cases in 16 modules (15 test modules + `conftest.py`): `test_payload.py` 15, `test_forward.py` 20, `test_forward_accelerator.py` 11, `test_prepared_operands.py` 5, `test_recurrent.py` 19, `test_grad.py` 20, `test_mutation.py` 16, `test_mutation_weight.py` 9, `test_crossover.py` 10, `test_distance.py` 15, `test_distance_digest.py` 9, `test_accelerator_equivalence.py` 10, `test_host_helpers.py` 12, `test_level_order.py` 4, `test_transform_validation.py` 5, and `conftest.py` (no tests).
`test_payload.py` — `initialize` four-array layout/dtypes/sentinels (an absent row is `I_INF` in every key column and `NaN` in every attribute column, present keys are unique, ascending and inside `[0, key_span)`, and the initial dense `input → output` wiring is a pinned edge set), the input/output row-key invariant, `setup` chaining order and state immutability, the three constructor rejections, `transform` equal to `support.oracle.schedule` field by field and accepted by `common.validate_schedule`, and `edge_overflow` on a too-small `max_in_degree`.
`test_forward.py` — closed-form level composition on a 13-row chain (every intermediate read out through a probe output row), output rows unactivated while hidden rows are, activation `-1` = identity, both transforms by composition, bypassed node inert, unconnected node + descendants NaN, padded rows inert, population axis a pure batch axis, random DAGs vs the oracle, the `max_depth` tail bound; and the split of the pass: `forward` equals `prepare_pass` + `forward_prepared` bit for bit on both families at `samples` 1 and 4, a `(P * S, I)` tiled batch repeats each individual's own network on its own rows, a query batch that is not `pop_size * samples` and a batch that is not a positive multiple of `P` are each rejected with `TensorNEATError`.
`test_level_order.py` — the schedule reads levels from the *keys*, not the row index: an isomorphic relabel of the probe chain (hidden rows `2..6` mirrored to `6..2`, so all four hidden-to-hidden joints point from a higher row to a lower one) yields `node_level` that un-permutes to the canonical literal, `forward` output and `grad` bit-identical to the row-ordered run (`.tobytes()`), and three closed-form gradient entries; the smaller `0 -> 2 -> 1 -> out` variant pins that a lower-row consumer reads the higher-row source's *previous-level* value from its declared incoming window.
`test_recurrent.py` — Jacobi ticks via closed-form orbits, input re-injection per tick, `input_transform` never applied, `output_transform` once after the last tick, NaN starvation across ticks, ring vs the oracle, `activate_time` = tick count, `activate_time` validation.
`test_grad.py` — `grad` returns an `evoxc.Graph` whose loss was traced (not called on an ndarray), determinism, shapes/dtypes, conn-weight and node-attribute gradients vs central finite differences, closed-form bias-only network, `NaN`/padding never poisons, padded rows gradient to exactly 0, `sum(loss)` scalarization leaves per-individual gradients unchanged; and the host-only `grad_from_payload` wrapper: central differences at `P == 1` and at `P == 3` with distinct members (plus `tobytes()` equality with the `transform` + `grad` pair, and pairwise-distinct per-member rows so a batch-axis broadcast fails), padding gradients exactly `0` on a payload with absent rows, and its three documented refusals (bare rows, a wrong `inputs` row count, a traced payload leaf).
`test_mutation.py` — probability validation, identity at zero, capacity (`max_nodes`/`max_conns`/`max_in_degree`), caller-allocated `new_node_keys`/`new_conn_keys` honoured and refused when not `int32` or not the documented `(P,)`/`(P, 3)` shapes, key uniqueness and sentinels intact, untouched rows bit-identical, one change per operation type on four independent per-individual gates (one individual may both gain and lose a node, the four stages composing sequentially), no duplicate edge, no cycle in a feedforward genome, `add_node` splits one edge, `delete_node` never touches input/output rows.
`test_mutation_weight.py` — the value-mutation law: with `weight_mutate_rate=1.0`/`weight_replace_rate=0.0` the delta is `assert_array_equal`-exact proportional to `weight_mutate_power` across five powers on one base (a fresh draw per power fails), the noise is base-independent to within float32 rounding, `rate=0` is byte-identical, `replace_rate=1` redraws every present weight to the init mean, `replace_rate=0.5` reaches exactly `{base, init_mean}`, the perturb branch wins where both arms fire, both candidates are affine in *one* shared standard-normal sample, `0.5/0.5` reaches only the init mean or the perturb law, and the key columns are never touched.
`test_crossover.py` — parent 1 keeps the structure, offspring keys ⊆ parent 1, aligned attributes are one of the two parents' (never a blend), non-homologous genes keep parent-1 attributes, padding preserved, shapes/dtypes, self-crossover bit-identity, `find_homologous` exact on the key tuple (including `historical_marker`) and `I_INF` for absent genes, and `gene/blocks.py::crossover_attrs` driven directly: with every parent cell distinct, every offspring cell is one parent's cell *at that cell* (no neighbour-row gather), columns mix in both directions, all four columns take both parents and row patterns vary (no whole-gene pick).
`test_distance.py` — configuration validation, zero at identity, symmetry, monotonicity in non-homologous genes, attribute weighting exact, one per changed int option, empty pair `0` not NaN, batched == pairwise, determinism; and `measure_distance`'s key-span contract: the dense single-centre route refuses a centre node key at `key_span`, a centre conn key `-1`, and a population digest whose `node_oor`/`conn_oor` recorded an unaddressable key (each message naming the family, the individual, the span and `DefaultDistance(dense_single_centre=False)`), while the row-wise merge route accepts the same payload and returns `execute_distance`'s bytes (non-zero for the poisoned individuals), and both routes agree on a clean payload.
`test_distance_digest.py` — on a seed-42 pop-100 XOR payload two `step`s deep, `execute_distance` (the pair kernel) is reproduced bit for bit (`tobytes()`, never `array_equal`) by the shipped single-centre digest, the batch-1 dense-centre fast path and `DefaultDistance(dense_single_centre=False)`'s row-wise merge; zero at identity and for an empty pair, two independently traced digests measuring identically, the digest's static contract (the literal 19-name field tuple) plus `ConfigError` on a centre whose shapes disagree, `I_INF` in every key column of a padding row, out-of-range keys counted per family in `node_oor`/`conn_oor` without counting padding, and the traced-IR ceilings `MEASURE_OP_CEILING` 120 (marginal over `prepare`) / `PREPARE_OP_CEILING` 210.
`test_host_helpers.py` — `network_dict` structure/renumbering (and the renumbering fixed point: a payload that already carries the renumbered keys walks unchanged), `network_dict`/`repr` accepting the `(1, …)` batch and the bare per-individual rows identically while refusing `P > 1` with a `TensorNEATError` that names the population and the exact slicing expression, `repr` exact rendering, `hash` (host-only numpy: `uint32`, deterministic, sensitive to a topology, a weight, a node bias and a node activation id, invariant under row permutation, independent per individual, and refusing a traced payload), `sympy_func`'s 8-tuple plus one exact formula, `visualize` under `Agg` + `tmp_path` with a `networkx.draw` spy, and the recurrent `sympy_func`/`visualize` refusal being `TensorNEATError`.
`test_transform_validation.py` — `transform` rejects a per-individual node row, a `conn_keys` without a population axis and mismatched population sizes with `TensorNEATError`, and accepts both batched spellings.
`test_forward_accelerator.py` — the `_static_sweep(state, samples)` gate of `prepare_pass`, whose three statics are `kernel_mode == "accelerator"`, `samples == 1` and a backend outside `_SWEEP_UNSAFE_BACKENDS` (`("xla",)`): the unrolled `_level_sweep` against the host `_level_loop` exactly (`NaN`-aware equality, no tolerance) on a shallow chain also checked against a float64 closed form, on a chain deeper than `max_depth` (both stay `NaN`), on a topology whose node is bypassed and on an unconnected node whose `NaN` crosses two hops into the read-out; a `samples == 4` tiled batch equal to the host loop and repeating each individual's `samples == 1` result (the individual-major tiling); the whole gate as a state table (`xla` and `" XLA "` → loop, `iree`/`numpy`/`None`/no entry → sweep, tiled or host → loop); and the traced IR that proves the routes (`while`/`reduce_max` 0/0 on the accelerator `samples == 1` sweep against 1/1 on the host, on the tiled accelerator batch and on the `xla` state, with the unroll costing more ops than the loop) plus the three backend spellings returning one array, so excluding `xla` from the sweep is a cost decision and not an accuracy one.
`test_prepared_operands.py` — the operands `prepare_pass` hoists, both to the numpy comparison: `_PreparedPass.level_masks` equal to `equal(node_level, level)` per level (in the same graph and host-side, one mask per `max_depth` level, the masks partitioning exactly the reachable rows with levels `1 .. max_depth` and the tail levels all-`False`), the sweep really *reading* them (a mask tuple rotated by one level or cleared makes the read-out all-`NaN` while the real pass equals `forward`), `_takes_scalars` as the signature rule, and the prepared-scalar activation path bit-identical to a scalar-less literal kernel (the literal side is the test-local `_literal_sigmoid`, which declares no `scalars` and keeps the old one-argument call shape — every shipped `act`/`agg` option now declares `scalars`, `sigmoid` and all six `agg` kernels included, so none of them can play that role any more), with **no** `constant` op in the scalars-aware route's level body (its full graph matches its own `prepare_pass` prelude) and strictly fewer in the whole graph (measured on the chain geometry: 28 against 36). A missing mapping key still falls back to the option's own literal exactly.
`test_accelerator_equivalence.py` — the two device-gated kernel spellings against the host route: `closes_cycle` on accept-and-refuse matrices (forward and back edges, self-loops on live and absent keys, a duplicate edge, every documented degenerate candidate — `I_INF` endpoint, absent key, key outside `[0, key_span)`, negative key — per-individual candidates, a `P = 2` payload whose individuals carry different graphs, and the recurrent ring) and `homologous_pair` on the key-pair matrix (`rows` and `present` asserted separately and exactly: identical, disjoint and partially overlapping parents, padded parent-2 rows, an empty pair, a batch of three populations, a three-column `OriginConn` key taking the `_confirm_rows` path), plus the route proofs (host `closes_cycle` carries `scatter`, host `homologous_pair` carries `sort`/`argsort`, the accelerator legs neither), an unknown `kernel_mode` refused by both entry points, and one documented non-equality case pinned per leg (a duplicate key row inside one parent: the accelerator marks both, the host merge picks one).
`conftest.py` — the five lazily resolved modules (`genome`, `common`, `payloads`, `oracle`, `runner`), the four graph-glue fixtures (`run_kernel`, `run_transform`, `run_forward`, `run_prepared`) and the module-scoped `evoxc.Executable` cache they share.

## Known test gaps
`RecurrentMutation` (`../../../src/tensorneat/genome/operations/mutation/recurrent.py`) has no reference in `test/`: `p_recur`/`max_conn_tries` validation, the cycle-forcing accept filter and the candidate-tableau path are unverified, and `RecurrentGenome` defaults to `DefaultMutation`, so nothing exercises it implicitly.
`OriginNode.crossover` and `OriginConn.crossover`/`get_historical_marker` are never executed: `OriginConn` appears only as a three-column key layout, and every crossover assertion runs the per-attribute `DefaultNode`/`DefaultConn` path.
`BiasNode`'s host hooks (`repr`, `to_dict`, `sympy_func`) and its `new_identity_attrs` are never called; its only use is the CartPole golden run, which asserts fitness/population hashes.
`max_conn_marker`'s `uses_historical_marker` branch is dead in the suite: the algorithm tests build `DefaultConn`, so a marker-carrying genome inside `NEAT.tell` is untested.
`window.any_slot`'s wide-window fallback (`width > _WINDOW_FOLD_LIMIT`) is untested — every genome here uses `max_in_degree <= 5`.
`in_degree`/`max_in_degree`/`violation` (`operations/mutation/degree.py`, re-exported from `operations.mutation`) have no caller in `src/` and no test.
The `AGG.mean` divide in the dense pass (`grad.py:421`) is still unexercised: the aggregation test pins only the *refusal* of a multi-option node gene, so a dense pass that ignored the `1/in_degree` factor would pass every gradient test.
No grad test configures `input_transform`/`output_transform` or a network deeper than `max_depth`, so a dense pass that dropped a transform or over-ran the depth bound passes.
`test_recurrent.py::test_raw_inputs_are_reinjected_on_every_tick` cannot fail for its claim: no `in_valid` window covers an input row, so hoisting the re-injection out of the tick loop yields the same read-out.
Deleting a connection is pinned only by "some edge went away": which edge a delete drops (and whether the choice is uniform over the present connections) has no oracle.
`test_crossover.py` writes the *same* genes for every row of the population axis in its `_payload` cases, so those tests cannot detect a cross-individual alignment collapse (the new `crossover_attrs` test does vary rows, and `test_distance.py`/`test_distance_digest.py` vary pairs).
The two `(child == parent2).any()` assertions in `test_crossover.py` are draw-based and coupled to the internal RNG consumption order; a legitimate change to `BaseCrossover`'s key split can flip them.
Connection-gene attribute values are never mapping-checked on homozygous rows (only the lonely row is), and `crossover.find_homologous` — the function the tests pin exactly — is not the function `__call__` uses (`align_gene_rows` → `alignment.homologous_pair`).
The digest's bit-identity rests on a *shared* scalar tail (`_scalar_distance`) and the same gene hook, so it proves alignment agreement only, not the formula.
The node family's float attribute term (`|delta|` over bias/response) has no numeric oracle; only the connection weight and the activation int column are pinned.
`test_distance_is_deterministic` replays one cached executable, not two independent builds.
`measure_distance`'s key-span guard is a *host* guard: inside a trace every field is a `SymbolicTensor`, `_host_array` returns `None`, and the dense route then measures the unaddressable key as if it were absent instead of raising, so only the host entry point (`test_distance.py`) pins the refusal.
`grad` has no accelerator case: it builds its own dense graph and never uses the level sweep, so an accelerator gradient route would be untested if one ever appears.
`prepare_pass`/`forward_prepared` under `kernel_mode="accelerator"` are exercised only through `forward`, never called as the split pair the host leg is pinned on.
`test_forward_accelerator.py` covers the tile sizes 1 and 4 only; any other `samples` (including 0 and 2) is untested, and the backend axis is pinned as a host-side table (`xla`/`iree`/`numpy`/absent) — no compiled leg runs it, and no `xla` execution exists anywhere in the suite because the sweep SIGSEGVs the process on that leg.
The homologue kernels' `K = 1` key width is not exercised — the kernel requires rank-3 keys, so two-column and three-column keys are the only widths tested — and the largest homologue batch is three populations.

## Conventions
Inputs are `scope="module"` fixtures resolved through `support.lazy.require`, so no module-scope `tensorneat`/`support` import; `pytest`, `numpy` and (in `test_payload.py`) `evoxc.random` are the only module-scope imports.
Every graph runs through `support.runner`'s fixtures; `runner.run_defn(closure, *args)` is the escape hatch for a kernel that takes no `state` (`g.hash`, `find_homologous`) and for passing a `DistanceDigest` as a payload-neighbour argument (`run_kernel(g.measure_distance, state, *centre.args(), digest)`).
Every op count quoted here — the `test_distance_digest.py` ceilings and the route proofs of the two accelerator modules — comes from the shared walker `../ir_ops.py` (`count_ops`/`count_graph_ops`/`op_names`), never from a module-local recursion: it descends `op.regions` → `region.blocks` and skips each block's `"return"` terminator unless a whole histogram is compared.
`run_kernel`/`run_transform`/`run_forward`/`run_prepared` reuse one compiled `evoxc.Executable` per `(genome identity, state identity, kernel or graph name, argument shapes and dtypes)`; a different genome/state object, a different static value or a different shape/dtype rebuilds.
The key keeps the genome and state objects alive (`_Identity`, never a bare `id()`) and keys frozen scalars by value, so an address is never recycled into a false hit and `pop_size=3` never reuses the `pop_size=4` graph.
`genome.grad` graphs are never cached — `runner.run_graph` retraces per call — and `grad_from_payload` builds and compiles its own two executables per call, so its tests keep to a handful of calls.
A call the conftest cannot classify (a mutable-container static, a callee that is not a bound method) rebuilds every time.
`genome.transform` is the only source of a `Transformed`: tests never name a schedule field, so a rename cannot silently pass.
A `Transformed` is passed field by field and rebuilt inside the traced closure — the shared runner treats only top-level array leaves as data, so a namedtuple argument would be baked as a static (see `conftest.py`).
A payload's `max_nodes`/`max_conns` must match the genome's statics: `output_slot`/`input_slot` come from the genome's key lists while the read-out takes the last `num_outputs` rows, so a capacity-comparison test builds one genome per capacity.
A node with no live incoming edge is *starved*, not contagious: the aggregation neutral-fills dead slots, so NaN spreads only by a consumer losing its every live source (this is what `test_recurrent.py`'s control chain pins).
Shapes stay small (`pop <= 4`, `max_nodes <= 13`) except in `test_distance_digest.py`, whose fixtures evolve a pop-100, `max_nodes` 50, `max_conns` 100 XOR population for two steps so the gene rows carry mutation-produced structure, and in `test_accelerator_equivalence.py`, which batches pop-8 chain and pop-4 ring payloads plus a three-population homologue batch; the backend is always `"numpy"` and there is no `jax`/`torch`, no network, no GPU.
Randomness comes only from the repo-level `rng`/`evoxc_key` fixtures (seeded from the node id), never the global numpy state; a stochastic operator is pinned with probabilities of exactly `0.0`/`1.0` and with set/exact-value laws, not with a lucky draw.

## Constraints
A test may not edit `../../../src`, `../../../benchmarks` or `pyproject.toml`; a defect or a doc conflict found here goes into the report to the parent.
Whole node: 180 passed in ≈12 s on the numpy backend, with about one `evoxc.build` per forward/recurrent/prepared/level-order/accelerator case — the floor, since each such test legitimately builds a fresh genome+state and `grad` graphs are never cached.
`test_forward.py` (1136 lines), `test_grad.py` (1063) and `test_mutation.py` (1050) are the three declared exceptions to the ~1000-line guideline: each is one cohesive concern sharing module-local helpers (`test_forward.py` the forward/prepared matrix; `test_grad.py` the differentiated pass plus its host-only wrapper; `test_mutation.py` the four structural gates' invariants), and splitting them would duplicate those helpers; split by family if any grows past ~1200 lines.
`test_host_helpers.py`'s `visualize` test asserts `matplotlib`/`networkx` are absent from `sys.modules` before the call, so it is order-sensitive within one process; pytest runs each module once, so this never bites in a normal run.
The guard in `test/unit/conftest.py` is the test-side counterpart of `test/release_gate_no_jax.py`: it freezes a session baseline at session start and records every import statement of `jax`/`jaxlib`/`torch`/`brax`/`gymnax`/`mujoco`, attributed to the file that executed it.
It therefore catches any import of an optional framework executed from `test/unit/**`, whether at module scope or inside a test body.
It excuses the imports originating in `src/` or in `pytest.importorskip`.
No test here carries a `slow` marker, including `test_distance_digest.py`'s pop-100, two-generation XOR fixture, so the whole node runs in the default gate (`pytest -m "not parity and not slow"`).

## Notes for Agents
`hash` is a **host-only numpy fold** (`src/tensorneat/genome/host.py`), not an in-graph kernel: it returns a plain `numpy.uint32` array from a `(P, …)` batch-first payload and raises `TensorNEATError` on a traced `SymbolicTensor`; call it as `g.hash(genome.GenomeTensors(*payload.args()))`.
`network_dict`/`repr`/`sympy_func`/`visualize` take `state` and ONE individual in either spelling — a `(1, max_nodes)` batch or the bare rows — and raise a `ConfigError` (a `TensorNEATError`) on a `P > 1` batch.
`grad_from_payload` is batch-first only (bare rows are refused), returns `(node_grad, conn_grad)` numpy arrays mirroring the attribute tensors, and traces + compiles a fresh graph on every call.
`grad`'s loss should be written `residual * residual`: evoxc's `power` pullback emits `log(base)` regardless of exponent, so `residual ** 2` warns on negative residuals.
`ABI` note for a digest argument: pass a `DistanceDigest` as a plain positional argument to `run_kernel`/`run_defn` (its leaves become data); closing over a host digest inside the traced closure bakes numpy arrays into the trace and raises `TypeError: unsupported operand type ndarray`.
Two support-layer changes would be welcome and are out of this node's scope: `runner.run_built(executable, *args)` (the run-only entry point the executable cache needs, so the cache can move into `test/support/` and serve the other unit suites) and public `runner.is_data`/`runner.split_args` (the cache currently mirrors the private split so its key can never be coarser than the `TensorSpec` that reaches `build`).
