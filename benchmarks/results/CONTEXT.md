# results — generated run records
## Intent
Hold the machine-readable output of `../run_benchmark.py` — per-run `RunResult` records plus aggregated rows and the protocol/environment snapshot — so each committed report can be re-rendered without re-running the benchmark.
Four records are committed evidence and stay in git: `authoritative.json`, `threads1.json`, `iree.json` and `xor3d_quality_2026-11-04.json`.
Every other `*.json` here (the default `latest.json` and anything else) is scratch output, git-ignored and safe to delete.
`authoritative.json`/`../RESULTS.md` are the pre-fix full-matrix record and its report: `RESULTS.md`'s quality rows predate the search-quality fix, its timing rows are post-pass-1 and pre-pass-2, and `xor3d_quality_2026-11-04.json` is the current search-quality evidence.
Nothing here is authored by hand: records are only ever written by the harness, and a report is regenerated by re-running the CLI, never by editing a record.
## API Surface
- `authoritative.json` — the default-thread matrix: both implementations, `numpy` new-side backend, all 8 cases (`cartpole_p100` is new-only), 150 timed generations after 3 warmups, 3 repeats (`seed + r` = 42/43/44), `--threads 0`, 45 runs all `ok`; generated `2026-11-04T19:01:27+00:00`, document fingerprint git `ebeaf1f8d07e` (the per-run worker environments recorded `95701646e5ee`), jax `0.10.2`, verdict `FAIL` on both sub-verdicts (timing loses on `xor3d_p100`/`xor3d_p500`/`xor3d_p1000`/`custom_pagie_p500`, quality on `xor3d_p100`/`xor3d_p500`/`custom_pagie_p500`); renders `../RESULTS.md`.
- `threads1.json` — the thread-bound sensitivity run: both implementations, XOR family (pop 100/500/1000), 150 timed generations after 3 warmups, 2 repeats (`42/43`), `--threads 1`, 12 runs all `ok`; generated `2026-11-02T06:31:32+00:00` at git `89f6200d6bba`, jax `0.12.0.1`, verdict `FAIL`; renders `../THREADS.md`.
- `iree.json` — the IREE attempt: `--impl new --backend iree --cases all --generations 2 --warmup 1 --repeats 1`, 8/8 rows `error` in `Pipeline.setup` on the rank-3 axis-0 scatter export gate; renders `../iree.md` with verdict `INCOMPLETE`.
- `xor3d_quality_2026-11-04.json` — the post-fix search-quality measurement: both implementations, new side on the `numpy` backend, cases `xor3d_p100`/`xor3d_p500`/`xor3d_p1000`/`custom_pagie_p500`, 150 timed generations after 3 warmups, 3 repeats (`seed + r` = 42/43/44), `--threads 0`; written together with its rendered `xor3d_quality_2026-11-04.md` via `--json` + `--out` (passing only `--json` would re-render `../RESULTS.md`), and it leaves `authoritative.json`/`../RESULTS.md` untouched as the pre-fix full-matrix record.
- `latest.json` — the git-ignored default `--json` path; scratch output that no committed report is rendered from.
- Schema `tensorneat-bench/1` for all of them, documented in `../harness/CONTEXT.md`.
## Constraints
- `.gitignore` ignores `*.json` and re-includes exactly the four committed records; never drop a re-include while the report rendered from that record stays in git.
- Never edit a JSON record to make a report look better: regenerate it by running the benchmark, and iterate report text with `--render-from-json`.
- Keep this directory free of caches and venvs — it is evidence output only.
