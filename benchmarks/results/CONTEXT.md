# results — generated run records
## Intent
Hold the machine-readable output of `../run_benchmark.py` — per-run `RunResult` records plus aggregated rows and the protocol/environment snapshot — and of `../gpu_measure.py` (one accelerator record per matrix session), so each committed report can be re-rendered without re-running the benchmark.
Eleven records are committed evidence and stay in git: `authoritative.json`, `threads1.json`, `iree.json`, `xor3d_quality_2026-11-04.json`, `gpu_rocm_2026-11-05.json`, `gpu_rocm_xla_2026-11-06.json`, `gpu_rocm_xla_2026-11-07.json`, `gpu_rocm_xla_2026-11-07_grouped.json`, `jax_rocm_2026-11-07.json`, `forward_jax_rocm_2026-11-07.json` and `forward.json`.
Every other `*.json` here (the default `latest.json` and anything else) is scratch output, git-ignored and safe to delete.
Nothing here is authored by hand: a record is only ever written by its producer (`../run_benchmark.py`, `../gpu_measure.py` or `../forward_measure.py`), and a report is regenerated by re-running that producer's CLI, never by editing a record.

## Constraints
- `.gitignore` ignores `*.json` and re-includes exactly the eleven committed records, each by an explicit `!<name>` line (the newest is `!gpu_rocm_xla_2026-11-07_grouped.json`); never drop a re-include while the report rendered from that record stays in git.
- Never edit a JSON record to make a report look better: regenerate it by re-running its producer (`../run_benchmark.py`, `../gpu_measure.py matrix` or `../forward_measure.py matrix`), and iterate report text with `--render-from-json` / `render`.
- `--persist-note` (on the harness side) is the only sanctioned write to an existing record and may touch `meta.report_note` alone: it re-reads the file and refuses to render if anything outside `meta` moved, so `runs`/`aggregated`/`verdict` and every measured number stay byte-identical.
- A record's `meta.report_note` is its own scope line, so every committed report renders the note its record stores — `../RESULTS.md`'s names tree `63f0fc67` and the 2026-11-06 session.
- A committed accelerator record must carry the plugin's identity whenever it measured an `xla` target: a number measured against a different `.so` is a different experiment.
- A committed accelerator record that measured an `xla` target must also carry the `XLA_FLAGS` value its rows ran with, once in `meta.xla_flags` and per row in `record["xla_flags"]` (`null` on a non-`xla` row): a number measured under a different command-buffer setting is a different experiment, and a record written before that key existed cannot be compared with one that has it.
- The records keep the recording host's absolute paths (`meta` interpreter/`out_path`, `iree.json`'s traceback paths, the plugin path on the newer accelerator records); the report scrubs them at render time, the evidence file does not — so never hand-scrub a record either.
- Keep this directory free of caches and venvs — it is evidence output only.
